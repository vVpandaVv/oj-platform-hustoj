# Edu Games

OJ Platform에 교육 게임, 연습 활동, 개인·팀 순위와 학습 통계를 추가하는 WordPress 플러그인입니다.

## 실행 환경

- WordPress 6.6 이상, PHP 8.1 이상
- OJ Platform `2.0.0-dev.30` 이상, Addon API v1
- 로컬 PHP: `D:\php\php.exe`
- 플레이 권한: `edu_games_play`, 관리 권한: `edu_games_manage` (플랫폼의 권한 매핑 사용)

### 1.6.7 라이트·다크 화면 모드

- 게임·허브·순위의 페이지 응답에 다크 모드 지원을 선언합니다. 플랫폼이 밝은 화면으로 강제하던 원인을 제거하며, 이전 Addon API에서는 기존 HTML 응답으로 돌아갑니다.
- 13종 게임과 집중 화면의 배경·본문·보조 문구·점수판·입력·카드·순위 조작을 플랫폼 색상 토큰에 연결했습니다. 플랫폼의 라이트·다크·시스템 선택을 따르고, 진행 중 전환에도 점수·입력·선택을 초기화하지 않습니다.
- 그래프 축·눈금·격자 색도 화면 모드 변경 시 갱신합니다. 사진, 16색 픽셀 값과 팔레트, 손글씨 표본의 원래 색은 학습 자료이므로 바꾸지 않습니다. 필터 반전은 사용하지 않습니다.
- 플랫폼 화면 모드 기능은 OJ Platform 2.1.0 이상에서 제공됩니다. 별도 게임 설정이나 데이터 이전은 필요하지 않습니다. 플랫폼 색상 토큰이 없는 일반 삽입 환경에서는 기존 밝은 색상으로 표시합니다.
- 검증: `PLAY_THEME_ONLY=1`로 `node tests/browser-play.cjs`를 실행하면 실제 플랫폼 CSS·모드 선택 스크립트를 사용해 13종의 노트북·휴대폰 화면, 시스템 설정, 집중 화면, 그래프와 픽셀 색 보존을 검사합니다.

### 1.6.6 Safari 카드 표시와 화면 맞춤 보완

- 카드 뒤집기는 3D 뒷면 합성 대신 2D 접힘 애니메이션과 명시적인 앞·뒷면 표시를 사용합니다. 오답 뒤 닫힘, 정답 매칭, 대기 중 재시작, 동작 줄이기 설정은 유지합니다. 카드판 크기 감지는 너비가 바뀔 때만 다음 프레임에 열 수를 조정해 WebKit의 ResizeObserver 반복 알림을 피합니다.
- 이진수 게임은 크기 변경 때 입력칸을 재생성하지 않고 위치만 갱신합니다. 연습 알림 제거 등 게임판 갱신 시에도 입력 포커스와 커서 위치를 유지합니다. 키워드 레인의 긴 단어는 양쪽 가장자리 안에 표시합니다.
- 결측값의 많은 관측값·긴 계산식, 문자코드 복원 입력칸, 시각화의 계산 영역을 좁은 집중 화면에 맞춰 조정합니다. 자료·사진·필수 조작은 유지하고 점수·시간·저장 규칙은 변경하지 않습니다.
- 검증: `PLAY_BROWSER=webkit`으로 `tests/browser-play.cjs`와 `tests/device-matching.cjs`를 실행할 수 있습니다. `PLAY_VIEWPORT_ONLY=1`은 13종의 노트북·휴대폰·iPad 세로/가로 배치와 주요 판정 화면을, `PLAY_FIT_ONLY=1`은 화면 전환 뒤 입력·그리기·제출 동작을 검사합니다. 카드 검사는 실제 터치 이벤트와 회전 후 오답 복구도 포함합니다.
- 로컬 검사는 Chromium 및 Playwright WebKit 26.5 기준입니다. 보고된 iPadOS 26.6 Safari 실기기는 직접 검사하지 않았으며, WebKit 검사를 Safari 실기기 검증으로 간주하지 않습니다.

### 1.6.5 장치 카드 오답 뒤집기 수정

- 카드판을 매번 새로 만들던 처리를 바꿔, 같은 카드 요소에서 앞면·뒷면을 전환합니다. 오답 두 장은 잠시 공개한 뒤 닫히는 애니메이션을 마치고 다음 선택을 받습니다.
- 닫힌 카드의 사진·설명은 제거하고, 오답 대기 중 다시 시작하면 이전 타이머를 취소합니다. 동작 줄이기 설정에서도 카드가 정상적으로 닫힙니다.
- 일반·집중 화면과 노트북·휴대폰 크기에서 오답 후 재선택·정답 매칭·재시작을 확인합니다. 사진 전체가 보이는 배치도 유지합니다.

### 1.6.3 장치 카드 사진 잘림 수정

- 카드 앞면은 분류 라벨의 공간을 확보한 뒤 남은 높이를 사진에 배정합니다. 사진은 원래 비율을 유지해 전체가 보이며, 집중 화면에서 카드 높이가 줄어도 카드 밖으로 밀려나지 않습니다.
- 일반 화면·집중 화면의 12·16·20·24장 배치를 노트북·휴대폰·태블릿 크기에서 검사합니다. 모든 장치 사진의 표시 영역과 라벨이 카드 안에 들어가는지 확인하며, 집중 화면의 스크롤 방지 배치도 유지합니다.

### 1.6.1 화면 높이에 맞춘 집중 화면

- 게임 시작 시 점수·게임판·필수 조작만 남기는 집중 화면으로 전환합니다. 상단 모니터 버튼으로도 열 수 있고, X 또는 Esc로 원래 페이지로 돌아옵니다. 이미지 제작·복원은 모니터 버튼으로 엽니다.
- 브라우저 전체 화면 권한을 요구하지 않습니다. 실제 게임 노드를 이동하므로 선택·입력·점수를 유지하며, 나가기는 일시 정지가 아닙니다. 순위 버튼은 집중 화면을 닫고 기록을 엽니다.
- 이진수 8줄의 표시와 위치 계산을 함께 조정하고, 카드 단계·픽셀 격자·타이핑·낙하 단어·데이터 및 AI 조작판에 높이별 배치를 적용합니다. 좁은 카드의 설명은 카드 아래 공통 설명 영역에 그대로 표시합니다.
- 결과 확인은 조작판 옆 또는 아래의 제한된 영역으로 배치합니다. 상세 비교는 별도 펼침 영역에서 확인할 수 있습니다. 매우 작은 창·화면 확대에서는 내용을 잘라내지 않고 집중 화면 안의 스크롤을 허용합니다.
- 검증: `PLAY_VIEWPORT_ONLY=1`로 `node tests/browser-play.cjs` 실행. 일반 노트북(1280×720)과 휴대폰(390×844), 최대 카드·이진수 줄·기억 표본, 그래프 5종 및 판정 화면을 확인합니다. 실제 운영 테마의 추가 CSS는 별도 확인 대상입니다.

### 1.6.0 공통 인터페이스와 순위 기록 관리

- 13종의 게임에 밝은 흰색·회색 바탕, 시스템 서체, 파란 주요 버튼, 같은 점수 표시 형식을 적용합니다. 최대 1120px 너비와 가운데 정렬을 공유하며, 학습에 필요한 게임판·사진·색상·조작은 유지합니다.
- 허브 돌아가기와 접힌 순위 영역을 통일했습니다. 이진수 점수판은 위로, 장치 카드·키워드 레인 순위는 게임판 아래로 옮깁니다. 타이핑 입력·완료 결과는 보존하며 모바일 키보드와 이진수 보드 배치도 조정했습니다.
- 사이트 관리자(`manage_options`)는 개인 순위의 휴지통 버튼과 확인창으로 해당 도전 기록 한 건을 영구 삭제할 수 있습니다. 학생과 일반 게임 관리 교사에게는 버튼과 삭제 권한을 주지 않습니다. 서버에서도 관리자 권한과 REST nonce를 검사합니다.
- 삭제 후 순위·개인 최고점·관련 통계를 원본 기록에서 다시 계산합니다. 같은 학생의 다른 도전이 있으면 다음 최고 기록이 표시됩니다. 팀·전체 이력을 일괄 삭제하는 기능은 아니며 진행 중인 도전과 별도 수집 진도는 건드리지 않습니다. 성공한 삭제의 관리자·게임·기록 ID·시각을 서버 로그와 훅에 남깁니다.
- 허브 상세 페이지, 블록, 숏코드에서 동일하게 적용합니다. 채점 규칙·DB 구조·기존 기록 형식은 바꾸지 않습니다. 아레나는 자체 화면 자산으로 같은 시각 규격을 따르며 플러그인 설치 의존성이 추가되지 않습니다.

### 1.5.1 배치·동기화 수정

- 장치 카드의 열 수를 카드 수와 실제 컨테이너 폭에 맞춰 결정합니다. 12장은 기본 4×3으로 표시하고 모든 단계의 마지막 줄을 채웁니다. 맞힌 카드의 빈자리는 기억한 위치를 보존하기 위해 유지합니다.
- 문자코드의 계정 기록 동기화 시 발생하던 `this.renderStats is not a function` 오류를 수정했습니다. 동기화 중 입력값과 초점은 유지합니다.
- 이진수 게임의 내부 레이어를 격리해 스크롤할 때 카드와 시작 화면이 사이트 메뉴를 가리지 않도록 했습니다.
- 전체 게임과 독립 플러그인인 아레나의 화면을 통일하기 위한 [인터페이스 설계](docs/game-interface-unification.md)를 추가했습니다. 전체 공통 화면 적용은 후속 구현이며 이번 패치는 위 세 가지 수정입니다. 점수 규칙과 기존 기록은 변경하지 않았습니다.

### 1.5.0 나머지 6종 직접 조작판 개편

- **데이터 잇기**: 복원 도구를 빈칸으로 끌어놓거나 선택하면 관측값, 추정값, 계산 근거가 함께 바뀝니다. 평균은 합과 개수, 중앙값은 정렬된 값과 가운데 위치로 표시합니다. 결과 확인 중에는 경쟁 시간이 멈추고 다음 데이터에서 이어집니다.
- **조건 관문 출고전**: 공장 안의 색·모양 관문과 AND/OR 연결을 바꾸면 통과 물건과 대기 물건이 바로 갈립니다. 필요한 열만 선택해 출고 라벨을 만들며, 직전 출고의 누락·오출고·라벨 오류를 확인합니다.
- **스택·큐 물류 레이스**: 입고 상자를 보관대로, 스택 맨 위·큐 맨 앞 상자를 배송대로 끌어놓습니다. 클릭·키보드 조작도 유지합니다. 잘못 꺼낸 상자는 임시 보관에 남고 재투입·재배치에 비용이 듭니다.
- **그래프 출동**: 그래프 자체에서 출동 대상을 선택하고, 원그래프 보급품 슬라이더·히스토그램 적재 범위를 조절하면 실제 배정 물량과 지원 인원이 반응합니다. 그래프 키보드 선택과 접힌 대체 선택 목록을 제공하며, 판정은 조작한 판 아래에 표시합니다.
- **분류 경계**: 예시와 이번 배송의 좌표를 전환하고 경계선을 움직여 봉투·상자 배송길로 나뉘는 모습을 확인합니다. 예시 일치와 실제 배송 판정은 구분하며, 새 물건의 정답은 배송 전 공개하지 않습니다.
- **손글씨 로봇**: 이름표 붙이기, 9칸 기억, 오인식 표본, 판단에 사용된 가장 가까운 기억을 한 화면에서 연결합니다. 터치 드래그와 오인식 필터를 지원하고, 기존 12개 숫자 조합·미공개 검정 90장은 유지합니다.
- 점수 저장·순위·기존 기록은 유지합니다. 결측값만 시간 계산 변경에 맞춰 `missing-repair-v3` 순위로 분리하며 이전 기록은 보관 조회로 남습니다. 별도 데이터베이스 이전은 없습니다. 다른 게임의 채점 규칙은 변경하지 않았습니다.

### 1.4.0 게임판 중심 인터페이스

- 데이터·AI 직접 조작 게임 7종에 공통 점수판을 적용했습니다. 남은 시간 막대, 연속 성공, 해당 도전의 개인 최고 기록을 표시하고, 종료 화면에서 최고 기록과의 차이·다시 도전·순위 이동을 제공합니다.
- 상황 선택은 접힌 도전 설정으로 이동하고, 게임의 확정 동작은 게임판 아래에 배치했습니다. 저장 오류·재시도·이어 하기는 별도로 유지합니다.
- 이상치 게임은 분포판의 숫자를 클릭하거나 검토함으로 드래그해 분리합니다. 원래 위치는 점선으로 남고, 원본 평균·검토 대상 제외 평균·변화량이 즉시 바뀝니다. 직전 모음의 놓친 값·과잉 선택·실제 점수 변화도 같은 판에서 확인합니다. 마우스·터치·키보드를 지원합니다.
- 이번 개편은 공통 화면과 이상치 조작판에 집중합니다. 나머지 6종의 개별 게임 규칙 재설계는 포함하지 않습니다. 채점 규칙·서버 판정·기존 기록 형식은 유지합니다.

### 게임 하단 보충 문제 풀이 제거 (1.4.0 포함)

- 10개 게임에 자동으로 붙던 개념 연습·평가 영역과 해당 화면 전용 자산을 제거했습니다. 게임 허브에서 들어가는 상세 페이지와 블록·숏코드 모두 동일하게 적용됩니다.
- 게임 본래의 연습·도전·검정, 점수·순위는 변경하지 않았습니다. 기존 개념 문항·평가 데이터와 기록 조회도 유지합니다.

### 1.3.0 통합 화면(D-010)

- 학생 게임 허브와 게임 순위 화면에 공용 머리말을 달고, 허브 카드를 토큰 색 카드로 바꿨습니다. 분류와 공개 상태는 배지로 표시합니다. 게임 플레이 화면과 채점 규칙은 바꾸지 않았습니다.

설치 파일은 `edu-games-1.3.0.zip`입니다.

### 1.2.4 콘솔 화면 수정

### 1.2.3 점검 수정

전체 점검에서 찾은 문제를 고쳤습니다.

- 개인 순위가 MySQL 8에서 오류가 나던 문제(`rank` 예약어)를 고쳤습니다.
- 일일 문제와 보드의 "오늘"을 UTC가 아니라 사이트 시간대 기준으로 정합니다(한국 시각 오전 9시에 날짜가 바뀌던 문제).
- 아케이드 게임 점수에 플레이 시간 대비 최대 정답 수 상한을 적용하고, 게임 시작마다 새 세션 토큰을 발급해 오래된 토큰으로 플레이 시간을 부풀릴 수 없게 했습니다.
- 서버 판정 보드로 옮겨 간 퀴즈형 6개 게임은 예전 일반 점수 제출(`/games/<game>/scores`)을 받지 않습니다.
- 장치 매칭: 카드 ID에 짝 정보가 드러나지 않고, 뒤집힌 카드의 앞면 내용이 HTML에 들어가지 않습니다.
- 키워드 레인: 종료 후 입력 무시, 다른 단어의 앞부분인 입력은 Enter까지 판정 보류, 결과 중복 저장 방지.
- 문자 코드: 0점 기록은 저장하지 않습니다. 브라우저 저장소가 막힌 환경에서도 최고 기록 표시가 멈추지 않습니다.
- 보드 게임에서 행동 뒤 키보드 포커스가 같은 컨트롤에 남습니다.

채점 점수 체계와 게임 수는 바꾸지 않았습니다. 설치 파일은 `edu-games-1.2.3.zip`입니다.

### 1.2.2 이진수 아케이드 점수 상한 처리

이진수 아케이드에서 정상적으로 획득한 점수가 저장 상한을 초과하면 제출을 거부하지 않고 순위 점수를 999,999점으로 기록합니다. 원래 점수에 대한 게임 규칙 검증은 유지하며, 검증된 원점수는 기록의 `meta.originalScore`에, 상한 적용 여부는 `meta.scoreCapped`에 보존합니다. 결과 화면에는 실제 획득 점수와 상한 적용 저장 안내를 표시합니다. 다른 게임의 채점 규칙은 변경하지 않습니다. 설치 파일은 `edu-games-1.2.2.zip`이며, 이전에 저장에 실패한 기록을 자동 복구하지는 않습니다.

### 1.2.1 애드온 등록 수정

1.2.0에서는 일부 페이지의 JavaScript 자산 묶음이 Addon API v1의 최대 8개 제한을 넘어 애드온 등록이 거부되었습니다. 공통 게임 런타임을 별도 묶음으로 분리하고, 기본 라이브러리 다음에 불러오도록 수정했습니다. 기존 게임·순위·관리 페이지와 채점 규칙은 유지합니다. 1.2.0 설치 파일 대신 `edu-games-1.2.1.zip`을 사용합니다. 운영 사이트 배포는 수행하지 않았습니다.

### 1.2.0 직접 조작 게임

일곱 기본 화면을 [직접 조작 방식](docs/games/hands-on-implementation.md)으로 다시 만들었습니다. 숫자 점 분리, 다양한 결측값 처리, 조건 관문, 실제 스택·큐 입출고, 경계선 이동, 0~9 손글씨의 세 숫자 조합 라벨링을 기본 조작으로 사용합니다. 시각화는 혼자 하는 그래프 출동으로 막대·꺾은선·원그래프·히스토그램·산점도를 제공합니다. 배분과 지원 범위의 즉시 변화, 다양한 자료와 임무 조건, 결과 확인 중 시간 정지, 차트별 성공 기록을 포함합니다.

기본 기록은 `hands-2026-09-v1-YYYY-MM-DD` / `play`로 분리하며 결측값은 `missing-methods-v2`, 손글씨는 `handwriting-digits-v2`, 시각화는 `chart-action-v4`에 날짜를 붙입니다. 기존 기록은 보존하고 새 채점과 합치지 않습니다. 현재 작업 트리의 실행 파일과 자료를 `edu-games-1.2.0.zip`에 포함하며, 이전 1.1.0 ZIP은 덮어쓰지 않습니다. 운영 사이트 배포는 수행하지 않았습니다. 아래는 보존된 이전 릴리스의 설명입니다.

### 보존된 1.1.0 게임 플레이 개편

일곱 게임의 기본 화면을 [새 핵심 플레이](docs/games/seven-games-play.md)로 교체했습니다. 관측망 운영, 불완전 지도 탐험, 차트 전달·항구 배차, 자동 분류 공장, 실제 스택·큐 미로 탐색, 분류 게이트, 표본 덱 훈련을 각각 두 상황씩 제공합니다.

새 기록은 `play-2026-09-v1` / `play` 모드로 저장하며 기존 전략·물류 기록과 분리합니다. 기존 게임 ID, 숏코드, 허브 경로, 전체 참여자 페이지네이션과 교사 보고서를 유지합니다. AI 덱은 scikit-learn으로 계산한 280개 유한 조합의 실제 예측을 사용합니다. 항구는 한 기기의 역할 교대 연습이며 독립적인 협동 순위는 표시하지 않습니다. 이 변경은 1.1.0 설치 패키지에 포함합니다. 기존 1.0.0 ZIP은 보존하며 운영 사이트 배포는 수행하지 않았습니다.

### 1.0.0 주요 변경

전체·팀·팀 내부·게임 내 순위와 전략/물류/개념 평가 순위를 기본 20명씩 표시하며 50명·100명으로 바꿀 수 있습니다. 처음·이전·다음·마지막 이동, 현재 페이지·전체 인원, 원래 순위와 공동 순위를 유지합니다. 게임·팀·보드 변경 시 첫 페이지로 돌아갑니다. 개념 평가 보고서를 새로 조회할 때에도 첫 페이지로 시작합니다.

화면은 `page`와 `perPage`를 보내고 서버는 해당 페이지의 행과 `pagination` 정보만 반환합니다. 전체 인원과 순위는 전체 기록 기준이며, 페이지 밖 동점자와 팀원도 계산에 포함합니다. 오류 시 기존 목록과 재시도 버튼을 유지합니다. 기존 `limit` 기반 전체 조회 API는 호환용으로 남겨두었습니다.

개인 목표·도감의 계정 동기화, 담당 학급의 게임 기록 보고서, 최고 기록 조회용 인덱스와 이전 AI 테이블 보존을 추가했습니다. 게임 수·보드 수·시즌·채점 규칙은 변경하지 않았습니다. [기존 계획과 구현 상태](docs/release-1.0-plan.md)에 구현 범위와 남은 운영 확인을 구분했습니다. 이 문단은 1.0.0 릴리스 기준 설명이며, 현재 버전은 1.2.3입니다. 운영 사이트 배포는 수행하지 않았으며 이전 ZIP은 그대로 보존합니다.

### 전체 참여자 순위 및 설치 패키지

전체 순위·게임 안 순위·팀 순위는 상위 10/20/50명 제한 없이 기록이 있는 참여자를 모두 조회할 수 있습니다. 한 사람의 최고 기록만 집계하며, 종료된 0점 기록도 포함합니다. 팀 조회 권한, 게임/보드/시즌 구분과 기존 동점 기준은 유지합니다. 팀 평균은 기록이 있는 모든 팀원을 대상으로 계산합니다. 아케이드 순위 API의 `limit=0` 또는 생략은 전체 조회이고, 명시한 양수 제한은 기존 연동을 위해 지원합니다.

검증은 `npm run test:rankings`로 실행합니다. `scripts/build-release.ps1`은 현재 작업 트리의 실행 파일·사진·실험 은행을 `edu-games/` 한 폴더의 ZIP으로 만들고 각 파일 해시를 대조합니다. 결과는 상위 `_releases`에 저장하며 `.git`, 테스트, 개발 스크립트, 검수 문서는 제외합니다. 기존 같은 버전의 ZIP은 덮어쓰지 않습니다. 설치에는 OJ Platform 2.0.0-dev.30 이상이 필요하며 패키징은 운영 사이트 배포를 수행하지 않습니다.
패키징 전에 `tests/addon-assets.php`가 실제 플랫폼의 등록 게이트웨이·매니페스트 검사·자산 출력 순서를 확인하며 실패하면 ZIP을 만들지 않습니다. 플랫폼 소스 기본 위치는 상위 `oj-integration-rebuild/oj-platform/src`이며 다른 환경에서는 `OJ_PLATFORM_SOURCE`로 지정합니다. PHP는 `-PhpBinary` 인자, `PHP_BINARY`, PATH 또는 `D:\php\php.exe`를 사용합니다. 이 검사는 격리된 호스트 상태로 수행하며 실제 운영 WordPress의 설치 검증을 대신하지 않습니다.
숏코드의 `oj_` 접두사 별칭도 지원합니다. 이진수 블록 이름은 게임 ID와 다른 `edu-games/binary-arcade`입니다.

## 화면과 설정

- 게임 허브: `/oj-addons/edu-games/games`
- 게임 상세: `/oj-addons/edu-games/games/{game-id}`
- 순위: `/oj-addons/edu-games/ranking`
- 게임 공개·팀(콘솔 메뉴 "교육 게임"): `/oj-console/addons/edu-games/manage`
- 게임 기록(같은 메뉴의 구획): `/oj-console/addons/edu-games/report`
- AI 모델 훈련소 성적(같은 메뉴의 구획): `/oj-console/addons/edu-games/report/ai-model-lab`

공개 설정은 블록·숏코드·게임 페이지·기록 API에 적용됩니다. 관리자의 비공개 게임 미리보기는 허용하지만, 비공개 상태에서 기록 제출은 허용하지 않습니다.
허브의 블록·숏코드 정보는 슈퍼관리자에게만 표시합니다.

### 학급 기록

플랫폼에서 `edu_games_manage` 권한을 받은 교사가 자신의 담당 학급·그룹, 게임, 기록 종류, 조회 기간을 선택합니다. 반 명단은 공개 Addon API로 조회하며 플러그인의 초대 팀을 실제 반으로 취급하지 않습니다. 명단·권한이 바뀌면 재조회가 필요하며 다른 반 ID를 임의로 입력해도 명단 권한 확인을 거칩니다.

미참여 학생을 포함한 전체 명단을 20/50/100명씩 조회합니다. 참여 인원, 시도·완료 횟수, 완주 보드·별·최고점, 최근 완료한 개념 활동의 첫 답/수정 후 결과를 구분합니다. 현재 콘텐츠 버전별 기록이며 기간은 UTC 날짜 기준입니다. 아케이드는 저장된 종료 기록만 집계하므로 저장하지 않고 나간 플레이는 참여로 계산하지 않습니다. 이미지 도감은 서로 다른 복원 그림 수를 표시하며 반복 복원 시도 수는 저장하지 않습니다.

## 기록 검증

2026.09 보강판의 문항형 활동 7종과 장치·타이핑·키워드의 개념 연습은 `/learning/{game}/...` API에서 서버 발급 문제를 한 답안씩 채점합니다. 1.3.1부터 기존 문항을 게임 하단의 보충 연습으로 붙이지 않으며, 직접 조작 게임과 기존 기록 조회는 유지합니다. 문항형 활동은 안내·독립 연습·평가를 구분하며, 평가 점수는 속도와 무관한 첫 답 정답률입니다. 첫 답·수정 답·힌트·재시도·문제 버전을 보존하고 `edu_games_learning_runs`에 따로 저장합니다. 아래 내용은 기존 아케이드 및 이전 규칙 기록 경로입니다.

- 문항형 게임 6종(이상치, 결측값, 시각화, 추출, 자료구조, 분류 경계)은 제출한 답과 서버 문제 데이터를 비교하여 점수·연속 정답 보너스·감점·정확도를 재계산합니다.
- 문항 수, 난이도 진행, 미출제 문제가 남았을 때의 중복 문제도 검사합니다. 클라이언트의 정답표·정답 여부·획득 점수를 신뢰하지 않습니다.
- 이진수, 문자 코드, 장치 매칭, 키워드 레인은 게임 규칙과 정답 수로 계산한 점수 상한을 검사합니다. 코드 타이핑 검정은 입력 문자 수·오타 수·시간으로 점수와 속도를 재계산합니다.
- 음수, 잘못된 자료형, 비정상적인 범위, 서버 세션 경과시간보다 긴 제출 시간, 과도한 메타데이터를 거부합니다.
- 일반 점수 API는 AI 모델 훈련소의 점수를 받지 않습니다. 해당 게임은 전용 API에서 서버 채점한 결과만 저장합니다.
- 세션은 저장 전에 조건부 UPDATE로 한 번만 선점합니다. 동시·재전송 제출은 거부하고, 확실한 저장 실패일 때만 선점을 해제하여 재시도를 허용합니다.

기존 경로의 한계: 아케이드·이전 문항형의 문제 선택 및 플레이 이력은 브라우저에서 만들어집니다. 재채점은 이력 전체 위조를 입증하지 못합니다. 새 개념 활동은 서버 발급과 답안별 채점을 사용하지만, 공개된 유한 문제 은행이므로 외부 도움이나 문제 암기를 막는 공식 시험 시스템은 아닙니다.

AI 모델 훈련소의 1단계는 실제 정답 라벨로 채점합니다. 2단계는 선택 모델과 라벨링 정답 개수를 키로 사전 계산된 성능표를 조회하는 시뮬레이션이며, 요청마다 모델을 재학습하지 않습니다.

## 구조와 데이터

- `src/Games/Modules`: 게임별 규칙·문제·도메인 로직
- `src/Frontend`, `src/Blocks`, `src/Shortcodes`: 공통 렌더링과 삽입 경로
- `blocks`: 블록 메타데이터, JavaScript, CSS
- `src/Addon`: 플랫폼 화면·메뉴·보고서 연동
- `src/Rest`, `src/Sessions`, `src/Scoring`: API·세션·서버 채점과 저장
- `src/Rankings`, `src/Statistics`, `src/Groups`: 순위·통계·팀
- `src/Progress`, `src/Reports`: 계정 목표·도감 저장과 담당 학급 보고서
- `src/Database`: 설치와 이전 이름의 테이블·옵션 이전
- `tests`: WordPress/DB 대역을 사용하는 회귀 검사와 실제 클라이언트 계산 함수 비교

전용 테이블은 WordPress 접두사 뒤에 `edu_games_scores`, `edu_games_sessions`, `edu_games_teams`, `edu_games_team_members`, `edu_games_ai_model_lab_attempts`를 붙입니다. 개인 순위는 최고 기록을 사용하며 동점은 정확도, 소요 시간, 기록 시각, ID 순으로 판정합니다.

`edu_games_learning_runs`는 별도 스키마 옵션 `edu_games_learning_schema=2`를 사용합니다. 개념 평가는 콘텐츠 버전·난이도를 나눠 개인 최고 점수로 순위를 매기며 동점은 공동 순위입니다. 기존 AI 교사 보고서는 이전 시도 전용입니다.

1.0은 `edu_games_progress`와 `edu_games_progress_schema=1`을 추가합니다. 계정·게임·항목별 최고값과 갱신 시각만 보관하며 연습 코드 원문은 저장하지 않습니다. 기존 점수 테이블에는 `best_attempt` 복합 인덱스를 추가합니다. 오래된 AI 프로토타입 테이블은 삭제하지 않고 `_legacy_...` 이름으로 보존하고 `edu_games_legacy_ai_backup` 옵션에 이름을 기록합니다. 보존한 프로토타입 기록을 새 규칙 점수로 변환하지는 않습니다.

이전 자동 생성 순위 페이지는 추적된 페이지에 기본 순위 블록만 남아 있을 때 휴지통으로 이동합니다. 편집된 본문·사용자 지정 블록·빈 페이지는 보존하며, 휴지통이 꺼진 사이트에서는 삭제하지 않습니다. 이미 이전 버전이 영구 삭제한 페이지를 복원하는 기능은 아닙니다.

## 콘텐츠 보강

### 반복 도전과 게임 개편

[게임성 평가·구현 상태·전체 개편 설계](docs/content-review/gameplay-redesign-2026-09.md)를 정리했습니다. 자료구조는 스택·큐·우선순위 큐를 조작하는 12구역 물류 보드로 바뀌었으며, 별 36개와 최소 이동 기록에 도전합니다. `/warehouse/{start|update|resume|summary}`에서 서버가 이동·해금·점수를 검증하고 같은 구역 최고점과 공동 순위를 저장합니다. 기존 블록·숏코드·허브 경로를 유지합니다.

이미지는 45개 복원 도감, 타이핑은 정확도 97% 이상 CPM 및 키워드 정확도 100% 연속 기록, 카드 매칭은 별 12개 이후 실수 감소 목표, 이진수·문자 암호·키워드 레인은 다음 점수 목표를 제공합니다. 로그인 상태에서는 **계정 기록**을 사용해 다른 PC에서도 이어갑니다. 로그아웃 상태나 연결 실패 시 기기 기록을 사용할 수 있으며 동기화 오류는 화면에 표시합니다.

- 이미지: 실제 정답 색상 배열과 일치하는 복원 항목을 합집합으로 보관합니다. 자유 창작 캔버스는 계정 동기화 대상이 아닙니다.
- 타이핑: 완성한 연습 코드의 정확도·소요 시간으로 CPM을 계산합니다. 검정은 300초를 마친 기존 서버 기록의 CPM을 사용하므로 마지막 예제의 일부 작성도 포함됩니다. 최고 속도는 정확도 97% 이상일 때 갱신합니다.
- 키워드 연속 기록은 현재 브라우저 연습 세션의 값입니다. 단어 목록과 완료 입력은 확인하지만, 클라이언트가 신고하는 연속 횟수·연습 시간은 공정한 경쟁을 입증하는 증거가 아닙니다. 개인 목표 전용이며 순위 점수에 합산하지 않습니다.
- 카드 별은 완주한 자기 서버 기록의 최댓값, 실수는 최솟값을 각각 보관합니다. 다른 기기에서 동시에 저장해도 최고 기록이 낮아지지 않습니다.
- 이진수·문자 암호·키워드 레인의 최고점은 기존 계정 점수에서 조회합니다. 과거 기기의 localStorage 기록은 자동 업로드하거나 경쟁 점수로 이전하지 않습니다.

데이터 추출·결측값·이상치·시각화·분류 경계·AI 모델은 **확장 포함 84개 전략 보드, 별 252개**를 제공합니다. 추출·시각화는 각 18판, 나머지 네 게임은 각 12판입니다. 다음 보드 해금과 같은 보드의 품질 유지·비용 절약이 목표이며, 모든 보드에서 1,000점을 달성할 수 있습니다. 복수 주문·결측 집계, 이웃 관측 복구, 불확실한 증거 보류, 비율·산점도·복수 작업판, 잡음·편중 표본과 최근접 이웃, AI 분포 변화까지 구현했습니다.

`/strategy/{game}/{start|update|resume|summary|archive}`가 서버 판정·이어 하기·개인 최고점·공동 순위·이전 시즌 조회를 담당합니다. 시즌 2는 `strategy-2026-09-v2`이며 과거 기록을 삭제하거나 재채점하지 않습니다. AI 운영 936개와 최근접 이웃 576개 조합은 scikit-learn으로 사전 계산한 서버 전용 실험입니다. [전체 구현 내역과 검증 범위](docs/content-review/strategy-full-release-2026-09.md)를 확인하세요. 테스트는 `npm run test:strategy`이며 PHP가 PATH에 없으면 `D:/php/php.exe`로 실행합니다. 실제 WordPress 운영 배포·학급 부하 검증은 별도입니다.

추가 검사: `D:\php\php.exe tests/warehouse.php`, `node tests/browser-warehouse.cjs`, `node tests/personal-challenges.cjs`, `D:\php\php.exe tests/addon-assets.php`. 마지막 검사는 로컬 OJ Platform 소스의 DTO를 사용하며 `OJ_PLATFORM_SOURCE`로 플랫폼 `src` 경로를 지정할 수 있습니다.

## 검증 실행

플러그인 폴더에서 실행합니다. 아래 기본 검사는 별도 npm 패키지가 필요하지 않습니다. 브라우저 검사는 Playwright와 Chrome, C 검사는 별도 컴파일러가 필요합니다.

```powershell
D:\php\php.exe tests/regression.php
node tests/client-scoring.cjs D:\php\php.exe
node tests/content-seeds.cjs
D:\php\php.exe tests/learning-content.php
D:\php\php.exe tests/learning-state.php
node tests/learning-assets.cjs
```

PHP가 PATH에 있으면 `npm run test:php`, `npm run test:scoring`으로도 실행할 수 있습니다.
1.0 변경 부분은 `D:\php\php.exe -d extension=pdo_sqlite tests/v1.php`와 `node tests/browser-v1.cjs`로 확인합니다. 전자는 메모리 SQLite에서 조회 SQL과 공개 명단 API 대역을 사용하고, 후자는 실제 렌더러·입력 검증과 격리된 계정/학급 응답을 사용합니다. MySQL 설치·실제 학교 서버 부하 검사의 대체물은 아닙니다.
휴지통 비활성 시나리오는 `EDU_TEST_TRASH_DAYS=0` 환경변수로 PHP 회귀 검사를 실행합니다.

자동 검사는 정답 일관성·난이도별 A/B 균형, 공개 설정, 페이지 정리 판단, 정상·변조 기록, 저장 실패 재시도, 동시 제출의 선점 경쟁을 확인합니다. 실제 WordPress 블록 파서와 DB 대신 대역을 사용하므로, 배포 전 활성화·실제 DB 동시 제출·블록 렌더링·30명 이상 동시 접속은 별도로 검증해야 합니다.

## 업데이트와 보관

운영 사이트에 적용하기 전 DB와 플러그인 파일을 백업합니다. 이 버전은 기존 점수·시즌 기록을 재채점하거나 지우지 않습니다. 파일만 이전 버전으로 바꾸는 것은 DB 복구가 아니므로 문제가 생기면 쓰기를 중단하고 원본 기록과 오류 로그를 보존합니다. 동기화 오류는 화면에서 재시도하고, 로그인 계정이 바뀐 탭은 새로 열어 사용합니다.

공개 아케이드 순위에는 저장 당시 플레이 이름이 표시되고, 보드/개념 평가 순위는 자신을 제외한 사용자를 익명으로 표시합니다. 실제 학생 이름이 있는 학급 보고서는 담당 권한으로 제한합니다. 플러그인 비활성화는 기록 삭제를 수행하지 않습니다. 자동 보관 기간·학생별 일괄 삭제 도구는 제공하지 않으므로 운영자의 기존 개인정보 보관·삭제 절차를 따릅니다.
