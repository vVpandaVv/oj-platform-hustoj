# 교육 게임 인터페이스 통일 설계

작성일: 2026-10-14
구현 반영: 2026-10-15, Edu Games 1.6.1

## 결정

**공통으로 만드는 것은 게임을 둘러싼 화면 구조이고, 게임판과 학습 조작은 각 게임에 맞게 유지한다.**

학생은 어느 게임에서든 같은 위치에서 시작, 현재 목표, 기록, 다시 도전을 찾는다. 이진수의 비트 전환, 카드 뒤집기, 그래프 선택 등을 공통 객관식 화면으로 바꾸지 않는다. 코드 아레나는 별도 플러그인과 별도 주소를 유지하되 같은 화면 규격을 따른다.

13종에 공통 화면 자산을 적용했고 아레나의 독립 화면 스타일도 정렬했다. 카드 배치, 문자코드 동기화 오류, 이진수 메뉴 겹침 수정은 유지한다. 점수 산식과 순위 구분은 변경하지 않는다. 기존 기록은 유지하며 관리자에게만 명시적인 개별 기록 삭제 기능을 제공한다.

              화면의 가장 넓고 눈에 띄는 공간

- 게임 시작에 필요한 선택만 시작 전 설정으로 둔다. 플레이 중 사용할 도구는 조작 대상 가까이에 둔다.
- 순위와 긴 도움말은 기본적으로 게임판 아래에 접는다. 좁은 사이드바 때문에 게임판을 축소하지 않는다.
- 도움말은 사용자가 열 때만 보여 준다. 화면 전체에 설명 문단이나 별도 문제 풀이를 붙이지 않는다.
- 실행 버튼은 `확인`, `실행`보다 `출고`, `배송`, `기록 종료`처럼 결과를 예측할 수 있는 동사를 쓴다. 도구는 익숙한 아이콘·색상·숫자로 표현한다.
- 정오 판정과 점수 변화는 조작한 대상 바로 옆에 표시한다. 화면 맨 아래 알림만 보고 원인을 추측하게 하지 않는다.
- 결과는 다음 도전을 시작할 때까지 남긴다. 게임판을 다시 보여 주기 위해 결과를 즉시 지우지 않는다.

## 크기와 시각 규격

| 항목 | 공통 규격 |
| --- | --- |
| 바깥 너비 | 최대 1120px, 가운데 정렬, 부모 폭 100% 이내. 허브와 상세 페이지에 같은 기준 적용 |
| 너비 소유자 | 상세 페이지 컨테이너가 바깥 여백을 한 번만 부여. 안쪽 게임에 다시 바깥 여백을 차감하지 않음 |
| 블록·숏코드 | 삽입된 부모 컨테이너 안에서 동일한 내부 구조 사용. 테마가 좁힌 부모를 `transform`이나 음수 마진으로 강제로 탈출하지 않음 |
| 간격 | 주요 영역 24px, 영역 내부 12~16px, 모바일 바깥 여백 12px |
| 글자 | 공통 한국어 글꼴 상속, 제목 24px, 본문 16px, 보조 항목 13px. 화면 폭에 따라 글자 크기를 비례 확대하지 않음 |
| 모서리 | 카드·버튼 최대 8px. 게임 영역을 장식용 카드 안에 반복해서 넣지 않음 |
| 버튼과 입력 | 기본 높이 44px, 아이콘 버튼도 44×44px. 실제 명령은 글자 또는 아이콘+글자, 도구는 아이콘과 툴팁 |
| 색상 | 게임 루트의 `--eg-*` 공통 토큰: 흰색·회색 바탕, 진한 글자, 파란 주요 동작, 초록 성공·빨강 오류. 기존 게임 토큰을 이 값에 연결하고 의미를 전달하는 게임판 색상은 유지 |
| 게임 고유 색 | 비트, 장치 사진, 그래프, 도형 분류 등에 사용. 바깥 제목·설정·기록 영역까지 게임별 별도 테마로 바꾸지 않음 |
| 반응형 | 점수판 4칸은 작은 화면에서 2×2. 버튼은 줄바꿈하되 게임판을 덮지 않음. 고정 형식 보드는 명시적인 칸 수와 비율 사용 |

일반 페이지의 게임 루트는 독립된 쌓임 맥락(`isolation: isolate`, 위치 지정과 `z-index: 0`)을 갖는다. 게임 내부 카드·판정창의 높은 레이어 값은 사이트 메뉴와 경쟁하지 않는다.

1.6.1에서는 플레이 중 페이지 스크롤로 집중이 끊기는 문제를 해결하기 위해 게임 시작 시 집중 화면을 연다. 브라우저 전체 화면 API가 아닌 닫을 수 있는 HTML dialog이며, 게임판 원본 노드를 이동한다. X 또는 Esc는 노드와 원래 스크롤 설정을 복원하고 입력·선택·점수를 유지한다. 실행 중 닫으면 자동 재진입하지 않으며, 다음 게임 시작이나 모니터 버튼으로 다시 연다. 타이머는 기존 규칙대로 계속 흐른다.

집중 화면은 최대 1280px 안에서 실제 화면 높이를 사용한다. 순위·설정·긴 도움말은 일반 페이지에 두고, HUD와 조작 도구는 유지한다. 이진수는 8줄과 물리 위치 계산, 장치 카드는 최대 24장과 설명 영역, 그림은 팔레트·격자·행별 코드를 함께 배치한다. 그래프 판정은 기존 조작판의 공간을 재사용하며 상세 비교만 펼침 창으로 연다. 1280×720 및 390×844 화면을 검증 기준으로 삼되, 더 작은 창·화면 확대에서는 조작을 자르거나 무리하게 축소하지 않고 내부 스크롤을 안전장치로 남긴다.

## 공통 상태와 동작

| 상태 | 화면 동작 |
| --- | --- |
| 준비 | 도전 목표와 필요한 설정, 시작 동작 하나. 코드 타이핑은 기존처럼 첫 글자 입력이 시작 |
| 진행 | 실제 게임의 점수·목표·시간만 갱신. 지원하지 않는 타이머나 생명 수를 장식용으로 추가하지 않음 |
| 판정 확인 | 조작 결과와 이유를 해당 판에서 표시. 다음 판으로 이동하는 위치는 일정하게 유지 |
| 종료 | 결과, 개인 최고와 차이, 다시 도전, 기록 이동을 같은 위치에 표시 |
| 저장 중·실패 | 게임 결과를 보존하고 별도의 저장 상태 표시. 저장 재시도가 점수를 다시 더하거나 새 게임을 시작하지 않음 |

일시 정지는 원래 게임 규칙에서 지원할 때만 제공한다. 공통 화면을 적용한다는 이유로 순위 게임의 타이머를 멈추거나 서버와 다른 시간을 계산하지 않는다. 결측값 결과 확인, 타이핑의 첫 입력 시작처럼 이미 정해진 시간 정책도 유지한다.

키보드 초점과 입력값은 기록 동기화 때문에 초기화하지 않는다. 색상 외에도 숫자·기호·문자로 상태를 구분한다. 뒤집기 애니메이션은 유지하되 동작 줄이기 설정에서는 짧게 처리한다.

항목 이름은 게임에 맞게 바꾸되 위치와 서체를 통일한다. 기록을 표시할 때 `계정 최고`, `이 기기 최고`, `이번 단계`를 구분한다. 서로 다른 채점 버전·난이도·검정 예제를 무조건 같은 최고점으로 비교하지 않는다.

### 장치 카드 배치

카드 수와 실제 게임판 폭으로 열 수를 결정한다. 빈 마지막 줄을 만드는 `auto-fit`만으로는 배치하지 않는다.

| 카드 수 | 충분한 폭에서 목표 배치 | 폭이 좁을 때 |
| --- | --- | --- |
| 12장 | 4열 × 3행 | 3열 × 4행 또는 2열 × 6행 |
| 16장 | 4열 × 4행 | 2열 × 8행 |
| 20장 | 5열 × 4행 | 4열 × 5행 또는 2열 × 10행 |
| 24장 | 6열 × 4행 | 4열 × 6행, 3열 × 8행 또는 2열 × 12행 |

글자와 사진의 최소 가독 폭을 확보하면서 카드 수의 약수를 열 수로 선택한다. 매우 좁은 삽입 영역에서는 1열까지 줄일 수 있다. 창 크기뿐 아니라 삽입된 부모 폭의 변화도 관찰한다.

**맞힌 카드가 사라져 생기는 빈자리는 유지한다.** 남은 카드가 자동으로 앞으로 당겨지면 기억한 위치가 바뀌기 때문이다. 빈칸 제거는 새 단계의 초기 배치에 적용한다.

## 구현 경계

기존 게임의 상태와 이벤트를 유지하는 범위에서 공통 외곽을 적용했다. 전체 렌더러를 새 상태 모델로 다시 작성하지 않는다.

- `src/Blocks/Game_Shell_Renderer.php`: 공통 CSS·JS 로드. `Abstract_Game_Renderer`가 공통 루트와 허브 주소를 제공한다.
- `assets/shell/shell.css`: 너비, 간격, 글꼴, 공통 도구, 상태, 반응형, 레이어 규칙. 모든 선택자를 게임 루트 아래로 제한.
- `assets/shell/shell.js`: 허브 링크, 제목 정렬, 기존 순위·도움말 노드의 접기와 재배치. 노드를 복제하지 않아 입력·이벤트 참조를 보존한다.
- 개별 게임 렌더러와 상태: 게임판 이벤트와 시간·정답·점수 계산·결과 표시를 계속 소유한다. 공통 CSS가 기존 의미 있는 클래스와 필드에 적용된다.

계정 기록을 받는 콜백은 명시적인 통계 갱신 함수에 연결한다. 이름만 비슷한 `renderStats`가 모든 게임에 있을 것이라고 가정하지 않는다. 전체 게임판 재렌더링 대신 필요한 통계만 갱신한다.

`Play_Renderer`의 7종과 개별 렌더러 6종은 `.edu-game` 루트와 공통 자산을 사용한다. 허브 상세 경로, 블록, 숏코드가 별도 UI 복제본을 만들지 않도록 실제 게임 렌더러에서 공통 화면을 사용한다. 플랫폼에서는 공통 자산을 별도 번들로 등록해 번들당 스크립트 제한을 지킨다. 게임 모듈·점수 산식·데이터베이스 이전은 이 작업에 포함하지 않는다.

### 아레나는 독립 설치 유지

- 아레나는 자체 주소, 게임 서버, 방 상태, 경기 기록을 소유한다. 에듀게임 점수 API에 아레나 경기 결과를 억지로 넣지 않는다.
- 두 플러그인은 동일한 화면 규격과 색상 값을 사용한다. 아레나가 `edu-games`의 PHP 클래스나 JS 파일을 필수로 불러오는 구조는 만들지 않는다.
- 각 플러그인은 필요한 최소 화면 자산과 대체 색상을 자체 제공한다. 공용 플랫폼 부품이 제공되는 환경에서는 그 부품을 사용하되 설치 순서는 요구하지 않는다.
- 에듀게임이 활성화되어 있으면 기존 외부 게임 등록 경로를 통해 허브에 연결한다. 없으면 아레나 자체 게임 목록·로비로 돌아간다.
- REST/WebSocket 전송 방식은 화면 공통화와 분리한다. 서버 통합 여부가 제목·점수판·버튼의 모양을 결정하지 않는다.

## 적용 상태

1. **공통 화면 적용 완료**: 데이터·AI 7종의 제목·설정·점수판·결과·기록 시각 규격을 정렬했다. 개별 게임판은 유지한다.
2. **기존 6종 연결 완료**: 이진수·문자코드·이미지·타이핑·장치 카드·키워드 레인에 공통 스타일을 적용했다. 측면 순위를 아래로 옮겨 게임판 폭을 확보했다. 이미지 제작에는 불필요한 순위나 타이머를 추가하지 않았다.
3. **아레나 정렬 완료**: 로비와 경기 화면에 같은 외곽 규격을 적용했다. 아레나 단독 설치와 에듀게임 허브 연결 양쪽을 유지한다.

검증은 바뀐 화면에 집중한다. 실제 렌더러의 데스크톱·모바일 배치, 키보드·터치 조작, 입력 중 기록 동기화, 스크롤과 사이트 메뉴, 결과 보존·저장 재시도를 확인한다. 채점 변경이 없는 UI 작업을 위해 별도 게임 콘텐츠 확장이나 새로운 평가 체계를 추가하지 않는다.

## 기존 수정 유지

- 장치 카드: 카드 수의 약수를 이용한 완전한 행 배치, 컨테이너 크기 변경 대응, 매칭 후 위치 보존.
- 문자코드: 계정 동기화 시 `renderStatsOnly()` 호출로 수정. 입력값·문제·초점은 유지.
- 이진수: 게임 루트의 쌓임 맥락을 격리해 카드·시작 화면이 사이트 고정 메뉴를 덮지 않도록 수정.

## 관리자 순위 기록 삭제

- `Record_Moderation`은 로그인한 사이트 관리자(`manage_options`)에게만 삭제 URL을 제공한다. 일반 교사의 게임 관리 권한과 구분한다.
- `Ranking_Records_Controller`의 DELETE 경로는 권한·REST nonce·게임·저장소·기록 ID를 확인한다. 진행 중 실행은 삭제하지 않는다. 권한 없는 직접 요청도 거부한다.
- 공통 순위 페이지네이션이 각 개인 순위 옆에 삭제 아이콘을 표시한다. 이름·점수와 되돌릴 수 없다는 설명을 확인한 뒤 한 건만 삭제한다. 실패하면 기존 순위와 확인창을 남겨 재시도할 수 있다.
- 삭제 후 목록·개인 최고·계정 통계를 다시 읽는다. 다음 유효 기록이 있으면 다시 순위에 올라간다. 동일 최고점이 여러 개일 때도 실제 선택한 한 건만 지운다. 팀 순위·학생 전체 이력의 일괄 삭제는 지원하지 않는다.
- 감사 정보(관리자·게임·기록 ID·시각)는 서버 로그와 `edu_games_ranking_record_deleted` 훅에 남긴다. 별도 진도/수집 항목과 아레나 경기 기록은 이 API의 대상이 아니다.
