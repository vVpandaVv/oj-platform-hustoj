# 학생 반응을 반영한 흥미성 반복 검토와 재설계

**후속 사용자 지적 반영:** 아래의 '같은 값, 다른 판정' 쌍찾기는 선택한 두 슬롯만 반복해도 새 쌍이 유지되는 허점이 확인되어 철회했다. 최신 UI·게임 규칙·정적 정책 회귀 검사는 [동적 게임판 수정](dynamic-play-review.md)을 따른다. 아래 결과를 새 시안의 흥미 검증 통과로 사용하지 않는다.

이 문서는 이전의 '개념은 맞지만 흥미는 확인하지 않은 후보'에서 멈추지 않기 위한 후속 작업이다. 운영 게임 구현 보고서가 아니다. 설계자의 반례 실행, 사용자가 전해 준 학생 반응, 새 안에 대한 실제 학생 검증을 분리한다.

## 1. 이번에 확보한 학생 반응

사용자가 전해 준 교실 관찰:

- 재미있어 한 것: 이진수 변환 아케이드, 장치 카드 매칭, 키워드 레인, **초기 이미지 데이터 표현**.
- 나머지 기존 게임: 딱히 흥미를 가지지 않음.

이는 실제 수업 반응에 대한 사용자 보고다. 참여 인원, 관찰 시간, 재도전 비율은 주어지지 않았으므로 만들어 넣지 않는다. 기존 게임에 대한 이 반응을 아직 하지 않은 새 시안의 학생 검증 결과로 옮겨 적지도 않는다.

이진수·카드·키워드에서 높은 점수가 목표가 되는 반면, 초기 이미지에서는 직접 만든 결과 자체가 보상이 된다. 따라서 모든 게임에 타이머·자원·운영 설정을 붙이는 것은 근거에 맞지 않는다. **이미지 표현의 직접 색칠·배열 복원·자유 창작을 보존**한다. 학생들이 재미있어 한 활동을 슬라이딩 퍼즐이나 복잡한 송수신 관리로 교체하지 않는다.

다섯 유지 게임(이진수·장치 매칭·키워드 레인·코드 타이핑·AI 모델 훈련소)의 운영 코드와 기록은 그대로 둔다. 이번 작업에서 이미지의 운영 코드를 되돌리거나 다른 게임의 코드를 바꾸지도 않는다.

## 2. 흥미에 대한 추론을 검토 기준으로 바꾸기

다음은 성공한 게임들의 조작과 사용자 보고를 대조해 세운 **설계 가설**이다. 학생의 재미를 일으킨 원인이 실험으로 확정됐다는 뜻은 아니다.

1. 처음 무엇을 할지 게임판에서 찾을 수 있다. 설명부터 읽고 설정을 완성해야 움직이는 구조를 반려한다.
2. 조작할 때마다 값·그림·카드·자료가 직접 바뀐다. 긴 자동 실행을 관찰하는 시간을 주 플레이로 삼지 않는다.
3. 반복이 있어도 결과가 누적되고 다음 상황이 바뀐다. 반복 행동 자체를 나쁘다고 보지 않는다.
4. 틀리거나 불리해진 이유가 구체적이고, 다음 판에서 바꿀 선택이 있다.
5. 개념을 무시하는 기계적 전략이 개념을 사용하는 전략과 같아지지 않는다.
6. 보상은 높은 기록 또는 눈에 보이는 완성물 중 게임에 맞는 것으로 둔다. 모든 게임에 같은 콤보·별점·시간제를 덧씌우지 않는다.

내부 검토만으로 '흥미 검증 완료' 도장을 찍지 않는다. 그러나 미확인이라는 말만 붙여 좋지 않은 규칙을 그대로 넘기지도 않는다. 아래와 같이 실제 상태·반례·수정 규칙을 남긴다.

## 3. 실제 수행한 세 차례 검토

| 게임 | 1차: 기존 후보를 플레이 순서로 검토한 문제 | 2차: 수정안에 넣어 본 반례 | 3차: 최종 수정 결정 |
| --- | --- | --- | --- |
| 문자 코드 | 한 통씩 변환은 개념에 맞지만 표와 입력 칸만 남으면 기존 연습의 반복 | 여러 통을 두되 짧은 것만 계속 골라도 유리하면 선택은 가짜 | 송수신·표 복원은 실제 변환으로 유지. 한 묶음의 도착·마감이 다른 통신을 처리하고 완전히 전송한 문자만 누적하는 릴레이 후보로 변경 |
| 이미지 | 긴 전체 배열을 의무 작성시키면 창작보다 숙제의 느낌을 강화할 위험 | 클릭 횟수를 줄이려 자동 정답 채우기를 넣으면 개념을 우회 | 학생 반응이 좋았던 초기 직접 색칠/복원을 유지. 누른 동안 드래그·되돌리기 등 도구만 보강하고 강제 타임어택을 기본값으로 삼지 않음 |
| 이상치 | 구간 설정 후 자동 통과를 기다림. 학생의 반복 조작이 적음 | 단순 숫자 짝만 찾으면 분포를 보지 않아도 성공할 수 있음 | **같은 값, 다른 판정**으로 전환. 같은 주목 값의 두 분포 중 후보인 쪽을 먼저, 아닌 쪽을 다음에 찾아야 득점 |
| 결측값 | 방법 메뉴와 빈칸을 차례로 제출하면 문제 풀이에 가까움 | 다시 측정해 가린 정답을 얻으면 항상 최고점. 방법 카드의 임의 희소성도 부적절 | **관측 선택이 있는 복원 퍼즐**. 제한된 추가 관측은 근거 자료만 열며 채점할 빈칸의 원래 값은 열지 않음. 관측 위치·근거·방법으로 실제 오차를 줄임 |
| 시각화 | 매번 변수·집계·차트부터 설정하면 실제 탐색 전에 준비가 길어짐 | 차트를 미리 다 만들어 주면 표현 선택은 학습에서 사라짐 | 한 원자료 보드를 여러 발견에 재사용. 첫 장면은 필요한 축/표현 하나만 직접 배치하고, 심화 팩에서 변수·집계를 늘림. 그래프의 실제 근거를 터치하는 시각 탐색 유지 |
| 추출 | 조건 한 번 맞춘 후 자동 선별을 관찰함 | 같은 조건만 반복하거나 번호를 외워 처리할 수 있음 | **정확히 N행 추출 퍼즐**. 보이는 자료에서 복수의 합법적인 조건 조합으로 필요한 행 수와 출력 열을 만들고 새 자료를 이어 처리. 긴 자동 실행 제거 |
| 자료구조 | 출력 줄에서 연속 세 개만 지우면 초반 다른 종류를 끼운 대가가 지나치게 큼 | 아무 블록이나 뽑거나 순서를 정렬하면 구조 규칙이 무의미 | 출구는 여전히 스택·큐 규칙. 다만 별도의 매칭 받침대에서 같은 종류 세 개를 모아 제거. 회복 가능한 판을 만들고 받침대와 큐를 명확히 구분 |
| AI 경계 | 알려진 점을 맞춘 뒤 새 점 자동 평가를 기다림. 후보 규칙 간 차이가 안 보임 | 정답을 본 평가점을 다시 쓰면 표본을 외우는 게임 | **경계 근처의 학습 관측 선택** 추가. 고정된 별도 학습 후보에서 라벨을 확인해 경계를 좁히고, 전혀 다른 평가점으로 기록. 분류 경계 조작이 주 플레이 |

이전 핵심 개념 문서는 개념의 필수 범위를 참고하는 자료로만 남긴다. 위에서 바꾼 흐름과 충돌하면 이 검토의 수정 결정을 따른다. 새로운 학생 반응이 다시 부정적이면 이 수정안도 고집하지 않는다.

## 4. 규칙을 실제로 실행해 확인한 반례

실행 파일: [interest-cases.cjs](review/interest-cases.cjs). 생성 결과: [interest-results.json](review/interest-results.json).

검증용 게임의 원본은 [outlier-context-playtest.html](prototypes/outlier-context-playtest.html)이다. 규칙 검사는 `node edu-games/docs/design/review/interest-cases.cjs`로 반복 실행할 수 있다. HTML의 실제 규칙 함수를 불러오므로 별개의 흉내 함수를 검사하는 방식이 아니다. 다른 7종 검사는 아직 운영 구현이 아닌 작은 규칙 모델임을 구분한다.

아래는 **자동화한 설계 규칙 모델**의 결과다. 중학생의 실제 속도·성적·재미 측정치가 아니다. 정책 비교는 같은 수의 판단을 수행한 것이며 사람의 시각 탐색 속도를 모델링하지 않는다.

### 문자 코드: 처리 순서가 실제 결과를 바꾸는가

세 통신의 처리량은 3·8·4문자, 작업량은 2·5·4, 마감은 3·9·12로 둔 추상 사례다. 작업량의 숫자는 실제 초가 아니다. 긴 통신부터 처리하면 짧고 급한 통신의 마감이 지나 완전 전송 12문자이고, 급한 순서로 처리하면 15문자를 모두 전송한다. 불가능하게 짧은 제한시간으로 반드시 실패하도록 만든 사례가 아니다.

학생의 실제 암호화/복호화/표 복원은 그대로 해야 한다. 미완성 원문, 일부만 맞춘 숫자열, 표 클릭 자동 변환에 문자를 주지 않는다. 앞으로 실제 조작에서 통신 선택이 변환보다 큰 부담이면 큐 관리를 줄이고 변환 아케이드로 축소한다. 코드표를 도미노로 바꾸는 안으로 되돌아가지 않는다.

### 이미지: 손이 편해지는 것과 정답 자동화 구분

실행한 16×16 도안은 256칸이지만 행별 같은 색 연속 구간은 36개다. 이는 256번의 독립 클릭 대신 36개의 행 구간을 **학생이 색을 골라 직접 드래그**할 수 있다는 조작 수 비교다. 팔레트 전환·정정 동작이나 실제 소요 시간을 포함한 실측은 아니다. 이 차이를 속도 개선 비율로 보고하지 않는다.

점검 결론은 더 복잡한 새 게임을 만들라는 것이 아니라 좋은 원래 활동을 편하게 하라는 것이다. 자유 창작을 시간 부족으로 종료시키지 않는다. 4×4 소도안부터 완성 경험을 주되 16×16·16색 범위를 제거하지 않는다. 창작에서 그림→배열 자동 내보내기는 표현 도구로 제공할 수 있으나, 별도 인코딩 연습의 정답 입력을 대신하지 않는다.

### 이상치: 숫자만 짝지으면 되는가

같은 주목 값의 두 분포를 만들고 하나만 후보가 되도록 실제 1.5×IQR 규칙으로 확인했다. 초급용 생성 자료 3,000쌍에서 그 성질이 유지됐다. 사분위수는 정렬 6개를 아래 3개/위 3개로 나눠 각각의 중앙값을 쓰는 방식으로 고정한다. 이것은 가상 사례를 일관되게 판정하는 게임 규칙이지 현실의 모든 이상치 판단을 보증하는 공식이 아니다.

각 1,200번의 컴퓨터 판단에서 분포 판정을 완전히 아는 정책은 +1,200, 단지 먼저 보이는 장부터 같은 숫자를 짝짓는 정책은 +8이었다. **이 숫자는 재미 검증이 아니라, 분포 판단을 빼도 같은 최고점이 나오는 허점을 막았다는 검사**다.

그 뒤 추가 반례도 발견했다. 최초 생성기는 일반 사례의 주목 값을 항상 가운데에 놓아, '수직선의 끝이면 후보'라는 표면적 요령이 통했다. 일반 사례에도 최솟값·최댓값이 오게 생성기를 다시 바꿨다. 최종 3,000쌍 중 1,999쌍은 일반 사례의 주목 값도 끝값이다. 같은 수의 판단에서 끝점만 보는 정책은 +370으로 분포 판정 정책의 +1,200에 못 미쳤다. 끝점 정책은 정보를 일부 사용하므로 숫자만 짝짓는 정책보다 나을 수 있지만, 주변 무리와의 상대적 간격을 읽는 수행을 대신하지는 못한다. 이 추가 검사 때문에 규칙 검토를 통과한 뒤에도 생성기를 다시 수정했다.

오답을 낸 두 장은 판정 피드백 후 새로운 사례로 교체한다. 공개된 정답의 같은 카드로 재득점하지 못한다. 같은 장 두 번 누르기, 다른 숫자 선택, 시간 종료 후 입력도 검사했다. 60초는 검증용 한 판의 초기값이며 운영 게임의 확정 시간이나 학생별 실력 기준이 아니다.

### 결측값: A만 선택하는 전략을 반박할 수 있는가

같은 단위로 구성한 네 예시에서 무조건 평균은 절대 오차 합 40.4166…이고, 자료에 맞는 보간·중앙값·앞값·주기 참고는 0이다. 의도적으로 차이를 드러내는 네 사례이므로 일반적인 방법 우열을 증명한 것으로 해석하지 않는다.

추가 관측 예시에서는 아직 가능한 세 패턴이 기존 위치에서 모두 10을 내지만 다른 관측 위치에서는 각각 10·20·30을 낸다. 이미 본 곳을 다시 보는 선택과, 패턴이 갈리는 곳을 보는 선택이 다르다. 채점할 가린 위치는 관측 후보에 넣지 않았다. '다시 측정' 한 번으로 채점 정답을 공개하는 우회는 없다.

최종 게임의 경쟁 수치 기록은 같은 자료의 복원 오차이고, 범주형 팩은 틀린 복원 수로 따로 비교한다. 실제로 채우면 안 되는 식별번호·취향·근거 부족 사례의 보류/재수집/제외 판단도 별도 팩에 포함한다. 기존 문서의 평균·중앙값·최빈값·상수·앞/뒷값·보간·주기·유사 사례 범위는 줄이지 않는다.

### 시각화: 준비만 하다가 끝나는가

설계의 작업 단위를 놓고, 네 준비 동작을 세 번 반복해 세 정보를 찾는 흐름(15동작)과 같은 보드/표현에서 준비를 재사용하는 흐름(7동작)을 비교했다. 이는 규칙 모델의 가정이지 현재 UI 클릭 수를 측정한 결과가 아니다. 핵심은 과제마다 설정 폼을 다시 채우지 않는 것이다.

실제 값 검사에서는 선 그래프의 가장 큰 증가가 1→2의 +8, 원의 절반이 50/100, 히스토그램 도수가 3·5·2임을 확인했다. 이후 시각 탐색에서 정답 위치를 외워도 다음 자료에서는 위치가 바뀌어야 한다. 막대·선·원·히스토그램·산점도 전체 범위를 유지하되 단순 차트 이름 맞히기나 출동 버튼으로 되돌리지 않는다.

### 추출: 하나의 정답 조건만 따라 쓰는가

6행에서 정확히 3행을 꺼내는 예시에는 `빨강`과 `파랑 OR 초록`이라는 서로 다른 합법 선택이 있다. `빨강 AND 원`은 2행으로 목표와 다르다. 학생이 조건을 바꿀 때 선택된 집합과 개수가 바로 보인다. 필요한 열만 남긴 뒤에도 선택된 세 원본 행은 그대로다.

새 자료에서는 빨강 반복이 0행, 파랑 조건이 3행이 된다. 같은 조건을 클릭한 뒤 관찰만 하는 것이 아니라 새 판의 분포와 조건을 읽어야 한다. 숫자 N은 추출 연습의 게임 목표이며 데이터의 진실성을 바꾸지 않는다. 요구하는 행 수에 도달하려 원자료 값을 고치거나 중복 행을 복제하는 기능은 없다. 완성 결과의 확인된 패킷 수가 기록이고, 같은 도전에서는 조건 수와 시간을 복기한다. 비교 연산·AND/OR/NOT·행/열 구분·원본 추적을 모두 보존한다.

### 자료구조: 실패 후 바꿀 선택이 남는가

기존 규칙의 받침대 `A B A B C C`에 큐 앞의 A를 내면 `A B A B C C A`가 되어 7칸이 가득 찬다. 연속 세 개가 없어 합법적인 선택을 해도 복구하지 못한다. 새 받침대에서는 A 세 개가 제거되어 `B B C C` 네 칸이 남는다.

**받침대는 큐가 아니다.** 큐 내부에서는 여전히 앞 자료만 꺼내고, 스택 내부에서는 위 자료만 꺼낸다. 두 위치를 다른 형태와 입·출구로 표시한다. 꽉 찬 받침대라도 다음 합법 출구의 블록이 즉시 세 개를 완성해 공간을 만들면 그 조작을 허용한다. 단순히 빈 슬롯 0이라는 이유로 게임을 먼저 종료하지 않는다.

스택/큐의 첫 출구가 B/A로 다름, peek이 제거하지 않음, 우선순위 큰 수 우선·동률 입력순을 별도로 실행 확인했다. 자료 자체가 같은 종류를 모으는 데 쓰이므로 연결 4의 숫자 카드 같은 우회 활동이 아니다.

### AI 경계: 기다리기 외에 어떤 판단이 있는가

학습점 2개에는 경계 3과 6이 모두 맞지만, 별도 새 자료 10개에서는 7개/10개를 맞힌다. 이미 아는 위치를 재관측하면 후보 규칙 7개가 그대로 남지만, 경계 근처의 학습 후보를 세 번 확인하면 일치하는 규칙이 6 하나로 좁혀지는 반례를 실행했다.

이것은 1차원 설명 사례다. 2차원 전체 게임의 완성도나 학생 흥미가 검증됐다는 결과가 아니다. 새 안은 학생이 관측할 학습 후보를 고르고 실제 경계를 옮기며, 평가 자료의 정답은 관측 도구로 열 수 없게 한다. 실제 라벨을 직접 바꾸지 않는다. 기존 두 특성·경계 포함·최근접 이웃/다수결·일반화 범위는 보존하며 AI 모델 훈련소를 수정하지 않는다.

## 5. 직접 한 판 가능한 검증용 사례

대상이 특히 불분명했던 이상치 한 종을 먼저 **선택→판정→사례 교체→시간 종료→결과 유지→자발적 재도전**까지 진행할 수 있는 별도 검증용 게임으로 만들었다. 운영 게임 교체·패키징·서버 기록 기능은 아니다. 나머지 일곱 종을 구현했다고 주장하지 않는다.

게임 규칙은 '같은 주목 값 두 장에서 후보인 쪽을 먼저, 아닌 쪽을 다음에 선택'이다. 정답 짝 +1, 반대 순서 -1, 첫 선택부터 60초다. 배치는 매번 섞이고 성공한 두 장은 새 사례로 바뀐다. 같은 숫자라도 주위 자료에 따라 판정이 달라진다는 개념이 승리의 조건이다.

이 사례에서 확인할 질문은 세 개로 좁힌다: 설명 없이 두 장을 찾기 시작하는가, 숫자만 보지 않고 주변 무리를 비교하는가, 끝난 뒤 스스로 다시 누르는가. 숫자가 너무 많거나 이미 좋아한 카드 게임을 피상적으로 베낀 느낌이라는 반응이면 이 형식도 폐기한다. '시뮬레이션 점수가 다르다'는 이유로 반응을 무시하지 않는다.

## 6. 다음 학생 반응을 받았을 때의 결정

관찰을 장기 연구로 늘리지 않는다. 검증용 한 판 뒤에 처음 막힌 장면, 다시 하고 싶은지, 왜 틀렸는지 이해했는지만 짧게 확인한다. 기존에 좋아한 게임이 이미 있으므로 같은 학생의 기존 활동 반응과 새 안의 반응을 대조할 수 있다. 선생님의 권유나 수행평가 점수 때문에 계속한 것을 자발적 재도전으로 세지 않는다.

- 조작을 이해 못하면: 문구를 늘리기 전에 조작 수와 화면 배치를 바꿔 재검토한다.
- 이해했지만 지루하면: 속도·효과음을 먼저 올리지 않고 판의 선택·발견·회복 구조를 다시 설계한다.
- 재미는 있지만 개념을 안 쓰면: 보상·판정을 고쳐 개념 우회를 막는다. 막을 수 없으면 그 놀이 형식을 폐기한다.
- 기존에 좋았던 창작이 새 규칙 때문에 재미없어지면: 초기 이미지처럼 좋은 기본 활동을 보존하고 경쟁은 선택 모드로 분리한다.

자가 검토에서 '통과'라는 표현은 다음 검증용 플레이로 가져갈 최소 조건을 뜻한다. 실제 학생이 새 게임을 좋아했다고 확정하는 뜻이 아니다. 현재 학생 반응 근거는 첫 절의 사용자 보고뿐이며, 새 시안의 학생 참여 결과는 아직 없다.

## 7. 참고한 검토 방법

[Tabletop Game Designers Association의 플레이테스트 안내](https://www.ttgda.org/in-person-playtesting)에 따라 혼자 규칙을 실행하고, 외부/블라인드 관찰에서 문제를 발견하면 다시 앞 단계로 되돌리는 방식을 참고했다. 특정 문구를 재미있다고 설득하는 대신 불편했던 장면을 규칙 수정의 근거로 삼는다.

[UFSM의 MEEGA+ 및 MEEGA+KIDS 안내](https://www.ufsm.br/grupos/gptec/paginas/portfolio/meega)에서는 사용성과 학습자의 플레이 경험을 구분해 평가하는 관점을 참고했다. 이 문서의 짧은 질문이나 자동화 검사를 정식 MEEGA+ 검사로 부르지 않으며, 표준 설문을 실시하거나 통계적 타당성을 확보했다고 주장하지 않는다.

새 게임의 '높은 점수'와 '학생이 더 하고 싶어 함'은 서로 다른 근거로 확인해야 한다. 이번에는 단순히 미확인이라고 남기는 대신 기존 반응을 반영해 8종의 흐름을 반복 수정하고, 반례를 실행하고, 실제 플레이 가능한 한 판까지 준비했다.

## 8. 이번 작업의 확인 결과

- 8종의 작은 규칙 모델 실행 검사 통과. 이상치만 검증용 게임의 실제 규칙 함수를 공유하며, 나머지는 운영 코드 검사가 아니다.
- 이상치 브라우저 플레이에서 첫 입력 시작, 다른 숫자의 선택은 무득점, 정답/오답, 공개 사례 교체, 직전 판정 근거, 만료 상태 복원 시 종료, 결과 유지, 마치기, 새 판 재도전을 확인했다. 60초 전체의 사람이 플레이한 성적이 아니다.
- 320·390·736·1024px와 라이트/다크 8개 조합에서 텍스트 넘침·빈 그림·선택 시 카드 크기 변화가 없음을 검사했다. 좁은 화면의 연속된 세 자리 숫자는 두 줄로 나누어 읽을 수 있게 수정했다.
- 텍스트 UTF-8/BOM 없음과 대화용/저장소용 검증판 사본 일치를 확인했다.
- 필수 `_release-kit/release.cmd check`는 두 번 실행했으나 별도 콘텐츠 원본 누락으로 실패했다: `_releases/readcontents-library/content/computing-pioneers-2026-11-16-v1`. 해당 경로가 없는 것을 읽기 전용으로 확인했으며, 정책 검사를 통과시키기 위한 빈 폴더 생성이나 다른 콘텐츠 목록 수정은 하지 않았다. 이 게임 작업의 검사와 전체 저장소 검사 결과를 혼동하지 않는다.

운영 게임, 학생 기록, 순위, 버전, 패키지는 이번에 변경하지 않았다.
