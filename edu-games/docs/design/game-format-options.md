# 게임 형식 선택안: 8종 × 3안

선택 전 비교안이다. 24종을 구현하거나 학생 흥미가 검증됐다는 문서가 아니다. 각 주제 안에서 주된 행동과 목표가 다른 세 형식을 제시한다. 사용자가 선택하기 전에는 새 게임 구현을 진행하지 않는다.

범위는 문자 코드, 이미지 데이터, 이상치, 결측값, 데이터 시각화, 데이터 추출, 자료구조, AI 분류 경계다. 기존 다섯 유지 게임과 운영 기록은 변경하지 않는다. 이미 좋은 반응이 보고된 초기 이미지 표현은 B1로 남긴다.

## A. 문자 코드

핵심은 코드표에 따라 원문 전체를 코드열로 바꾸고, 역변환하고, 대응에서 표를 복원하는 것이다. ABC 연결이나 단어 보기 고르기로 대체하지 않는다. 이전의 `C A T` 순서로 배치한 축약 코드표와 이미 순서대로 놓인 손패 예시는 철회한다.

### 세 안에 공통으로 적용할 코드표

- 알파벳 26개, 숫자 문자 10개, 공백 1개를 모두 포함한다. 알파벳 표와 숫자 문자 표는 구분하되 코드값은 전체 37문자에서 중복되지 않는다.
- 알파벳 표는 A부터 Z까지, 코드값은 `01`부터 `26`까지 오름차순으로 표시한다. 숫자 문자 표는 0부터 9까지, 코드값은 `27`부터 `36`까지 오름차순으로 표시한다. 공백은 `00`이다.
- 문자 대응과 표의 배치는 모든 판에서 동일하다. 무작위 코드 배정과 표 섞기를 사용하지 않는다. 답에 필요한 문자만 문장 순서로 추려 주는 축약 표는 사용하지 않는다.
- 원문의 순서는 유지하고 공백도 한 문자로 변환한다. 예를 들어 표시된 문자 `7`과 그 코드 `34`를 구별한다. 코드값은 두 자리로 표기하고 코드 사이의 구분과 공백 문자의 코드 `00`을 구별한다.
- 코드표는 계속 볼 수 있다. 표를 누른다고 정답 칸에 자동 변환 입력되거나 다음 정답 항목이 강조되지 않는다.
- 쉬운 단어만으로 원문을 짐작하지 못하도록 일반 어휘뿐 아니라 `R7 Q2` 같은 임의 식별자, 공백, 숫자 문자를 섞는다. 짧은 예시가 전체 콘텐츠를 대표하는 것은 아니다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| A1 | 암호 금고 레이스 / 속도 아케이드 | 암호열을 해독하거나 원문을 암호화해 금고를 연속으로 연다. 원문과 코드를 동시에 정답으로 제공하지 않음 | 전체 변환에 성공한 금고 하나가 1점. 오답 제출 또는 제한시간 초과로 종료 |
| A2 | 코드표 복원 / 기초 퍼즐 | 오름차순 코드표의 빈칸을 원문·코드열의 대응으로 확인하며 채우고 새 통신 해독 | 표 완성과 새 통신 해독을 모두 완료하면 복원 1회. 같은 과제에서 시간 비교 |
| A3 | 암호 러미 / 손패 운영 대결 | 무작위 손패에서 필요한 숫자 코드를 모으고 교환해 공개 요청 하나의 전체 코드열을 제출 | 올바른 통신 하나가 1점. 먼저 5점이면 승리, 뽑기 더미 소진 시 높은 점수 |

### A1: 빠른 변환이 금고를 여는 행동

1. 알파벳·숫자 문자 순서로 정렬한 전체 표와 `18 34 00 17 29`가 보인다. 원문은 빈칸이다.
2. 표에서 R=18, 7=34, 공백=00, Q=17, 2=29를 찾아 `R7 Q2`를 입력한다.
3. 전체가 일치하면 금고가 열리며 1점, 다음 금고로 넘어간다. 다음에는 `Q2 R7`을 숫자열로 바꾸는 역방향이 나올 수 있다.

빠르고 정확한 양방향 변환이 경쟁 요소다. 표를 찾기 어렵게 만들지 않는다. 난이도는 메시지 길이, 변환 방향, 제한시간으로 조정하되 처음에는 짧고 여유 있게 시작한다. 모든 모드를 복잡한 전략 게임이라고 포장하지 않는다. 제한시간은 문자열 길이·방향을 반영하고, 최소 시간은 이후 실제 학생 관찰로 조정한다. 한 글자만 입력해도 정답 항목을 알려주는 식의 피드백은 없다.

### A2: 오름차순 표의 빈 대응을 채우는 기초 복원

다른 모드와 같은 표를 사용한다. Q, R, 2, 7의 코드만 비어 있고 공백=00은 표시한다.

- 원문 `R7 Q2`와 코드열 `18 34 00 17 29`를 대조한다.
- 표의 알파벳·숫자 순서와 원문·코드열을 확인해 Q=17, R=18, 2=29, 7=34를 채운다.
- 표를 채운 뒤, 새로운 코드열 `17 29 00 18`을 `Q2 R`로 해독하면 복원 1회가 완료된다.

오름차순 규칙으로 빈칸을 유추할 수 있는 기초 활동임을 명시한다. 이전의 짝이 섞인 수신 기록 수사와 무작위 대응 추리는 기본안에서 제외한다. 복원형은 대응 익히기가 목적이며, 깊은 추리나 전략이 생긴다고 주장하지 않는다.

### A3: 변환 결과가 손패 운영을 결정하는 대결

- 동일 길이의 공개 통신 요청 여러 개와 순서를 섞은 손패, 뽑기·교환 후보가 있다. 메시지별 길이가 짧아서 무조건 유리한 요청은 같은 단계 안에서 피한다.
- 예시 손패 `00 34 07 29 11 18 01`로는 `Q7 R2`를 만들 수 없다. 코드표를 보면 Q의 코드 17이 없다는 것을 알 수 있다.
- 공개 뽑기 후보 `17, 03, 06`에서 17을 얻고 필요 없는 11을 버린 뒤, `17 34 00 18 29`를 순서대로 제출한다. 정확하면 1점, 사용한 카드는 손패에서 빠진다.
- 공개 요청들은 일부 코드를 공유하므로 어느 요청을 먼저 완성하고 어떤 카드를 남길지, 상대가 필요로 하는 카드를 버릴지 판단한다. 손패 부족 때문에 수행 불가능해지지 않도록 합법적인 뽑기·교환·넘기기와 소진 종료 규칙을 둔다.

A3의 순서와 글자별 대응을 모두 확인한다. 타일 내부 글자/숫자의 관계가 불분명한 과거 암호 도미노는 재사용하지 않는다. 코드표 수정과 설계 장면만 갱신한 상태이며 실제 게임 구현이나 학생 흥미 검증을 완료했다는 뜻은 아니다.

## B. 이미지 데이터

최대 16×16·16색, 팔레트 코드와 픽셀 좌표의 관계를 유지한다. RGB 실습은 넣지 않는다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| B1 | 픽셀 공방 / 창작·복원 | 팔레트로 직접 그리고, 같은 행의 숫자 배열을 읽어 그림 복원 | 작품·도안 갤러리 완성. 경쟁은 선택 모드 |
| B2 | 고장 난 그림 수리 / 디버깅 퍼즐 | 잘못된 배열 값이나 팔레트 대응을 수정해 실제 픽셀 변화를 확인 | 적은 수정으로 원래 그림 복구 |
| B3 | 숫자 타일 모자이크 / 공간 조립 | 숫자 배열 지시와 팔레트를 읽어 색상 타일 조각을 올바른 좌표에 배치 | 전체 이미지 완성. 같은 도안의 시간·정정 횟수 비교 |

B3에서는 목표 지시는 숫자, 타일은 색상으로 제공한다. 숫자끼리 모양만 맞춰 팔레트 해독을 우회할 수 없게 한다. 역방향 팩은 그림을 보고 숫자 타일로 배열을 구성한다.

## C. 이상치

비교 자료 속에서 유난히 벗어난 값을 다루며 후보와 오류를 구별한다. 이동하는 초록 띠, 자동으로 바뀌는 범위 밖 체크, 과거 체크 고정 방식은 세 안 모두에서 사용하지 않는다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| C1 | 자료 묶음 만들기 / 숫자 타일 배치 | 숫자 타일을 배치해 비슷한 값들과 유난히 떨어진 값이 있는 자료 묶음을 직접 구성 | 유한한 타일로 더 많은 유효 사례 완성 |
| C2 | 데이터 사건 수사 / 단서 추리 | 필요한 비교 자료를 조사하고, 그 근거로 검토 후보를 지목 | 적은 조사로 타당한 후보 발견 |
| C3 | 사례 수집전 / 세트 수집 카드게임 | 손패를 뽑고 교환해 같은 값이 다른 집단에서 다르게 해석되는 사례 세트 구성 | 상대보다 먼저 타당한 사례 세트 완성 |

C1은 숫자 카드로 자료를 만드는 모의 실험이지 실제 측정값을 조작하라는 활동이 아니다. '후보 하나' 등의 조건은 해당 퍼즐 목표일 뿐 실제 자료에는 후보가 항상 하나라는 뜻이 아니다. C2의 조사는 채점 정답을 직접 보여 주는 재측정이 아니라 비교 근거를 제공한다. C3는 공개 보드의 고정 두 칸에 같은 쌍을 다시 채우지 않고 유한한 손패와 뽑기/교환으로 진행한다.

숫자 카드를 내고 마지막 이상치가 자기 것이면 점수를 얻는 단순 대결도 검토했지만, 무작위 손패의 상당수에서 첫 선택에 따른 승패 차이가 작고 극단값 전략이 강했다. 이 형식은 이번 추천에서 제외했다.

## D. 결측값 처리

실제 근거와 방법으로 추정값이 달라져야 한다. 평균·중앙값·최빈값·상수·앞/뒷값·보간·주기·유사 사례와 보류·재수집·집계 제외 범위를 선택한 형식에 맞게 구성한다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| D1 | 복원 탐사 / 정보 수집 | 어디를 추가 관측할지 선택한 뒤 근거와 방법으로 가린 기록 복원 | 같은 자료에서 더 작은 복원 오차 |
| D2 | 끊긴 기록 조립 / 구성 퍼즐 | 실제 관측을 연결하거나 대표값·상태 유지 도구로 여러 빈칸을 한 보드에서 복원 | 정확하게 복원한 전체 기록, 적은 정정 |
| D3 | 데이터 검수관 / 업무 판단 시뮬레이션 | 자료의 용도에 따라 추정·원본 확인·미확인 보존을 결정하고 실제 처리 | 허위 값을 만들지 않고 올바르게 처리한 기록 수 |

D1의 추가 관측은 평가 대상 빈칸의 원래 값을 직접 열지 않는다. D2의 조각은 임의의 예쁜 곡선이 아니라 관측값과 방법에서 계산한다. D3에서는 식별번호·취향 같은 정보를 숫자 평균으로 채우면 실패한다. 경쟁 오차는 원래 관측을 교육용으로 가린 자료에서만 계산하고 실제 불명 값을 정답처럼 채점하지 않는다.

## E. 데이터 시각화

막대·선·원·히스토그램·산점도와 축·단위·범례·집계의 의미를 실제 표현/판정에 사용한다. 차트 이름만 고르거나 원자료 없이 실루엣만 맞추지 않는다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| E1 | 그래프 수리공 / 오류 수정 퍼즐 | 잘못된 눈금·축·범례·비율·구간을 고쳐 원자료와 맞는 표현으로 복구 | 적은 수정으로 정확한 그래프 완성 |
| E2 | 데이터 미스터리 / 분석 추리 | 그래프·집단·구간을 바꿔 숨은 변화나 관계를 찾고 실제 근거를 연결 | 더 적은 힌트로 사건의 데이터 근거 완성 |
| E3 | 그래프 전시회 / 구성·최적화 | 같은 자료로 여러 표현을 만들고 제한된 전시 칸에 배치 | 필요한 정보를 모두 전달하는 적은 그래프 구성 |

E2는 혼자 가능하게 한다. 지도를 이동하거나 출동 버튼을 고르는 것이 아니라 그래프에서 증거를 찾는다. E3의 판정은 주관적인 아름다움 점수가 아니라 원자료 정확성과 명시한 정보 목표의 충족이다. 합법적인 대체 표현도 인정한다.

## F. 데이터 추출

조건에 맞는 행과 출력할 열을 구별하고 AND·OR·NOT·복합 조건을 실제로 실행한다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| F1 | 정확히 N행 / 집합 퍼즐 | 보이는 자료에서 조건을 조합해 목표 행 수와 필요한 열을 추출 | 더 많은 올바른 패킷 완성, 간결한 조건 |
| F2 | 자동 추출 공장 / 엔진 제작 | 필터·분기·합류·열 선택을 조립해 아직 보지 못한 자료도 처리 | 정확하면서 실제 조건 평가가 적은 추출기 |
| F3 | 데이터 스무고개 / 질의 추리 | 조건 질문으로 후보 집합을 줄이고 마지막에 목표 행·필요 열을 조회 | 적은 질의로 정확한 보고서 추출 |

F1의 여러 합법 선택은 다음 남은 표시 자료와 선택지를 바꿔야 한다. F2는 설정 뒤 긴 자동 실행을 구경하는 게임이 아니라 즉시 시험하고 개선하는 제작형이다. F3도 마지막에 실제 필터와 열 선택을 수행하며 이름 추측만으로 끝나지 않는다. 추출은 원본을 삭제하는 것이 아니고, 같은 원본 행의 OR 합류와 서로 다른 행의 동일 값은 구별한다.

## G. 자료구조 운용

넣기·조회·꺼내기, 스택 LIFO·큐 FIFO·우선순위/동률 규칙이 실제 자료 이동을 결정한다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| G1 | 스택·큐 블록매치 / 생존 퍼즐 | 구조에 넣고 합법적인 출구로 꺼내 받침대에서 같은 블록 수집 | 더 많은 묶음을 지우며 공간 유지 |
| G2 | 컨테이너 야드 / 공간·순서 퍼즐 | 스택 선로·큐 통로를 이용해 요청한 출력 순서 구성 | 적은 이동으로 출고 순서 완성 |
| G3 | 출구 쟁탈전 / 턴제 보드 대결 | 상대와 공유한 구조에 자료를 넣고 꺼내 자신의 요청 순서를 먼저 완성 | 먼저 정해진 요청들을 완수 |

G1의 받침대는 큐와 구별한다. G2도 중간 컨테이너를 자유롭게 끌어내지 못하고 실제 다음 출구만 움직인다. G3에서 상대가 스택 위에 넣는 것, 큐 뒤에 넣는 것, 우선순위를 높여 넣는 것의 효과가 달라야 한다. 연결 4의 열 번호를 얻는 식의 우회는 사용하지 않는다. 대결형은 단독 봇 상대도 가능하게 하고 Code Arena 설치에 의존하지 않는다.

## H. AI 분류 경계

특성·규칙·결정 경계·예측/오류를 연결한다. 관측 라벨을 학생이 임의로 바꾸지 않고 학습/평가 자료를 분리한다. 기존 AI 모델 훈련소는 변경하지 않는다.

| ID | 형식 | 주된 행동 | 목표·기록 |
| --- | --- | --- | --- |
| H1 | 분류 규칙 조립 / 논리 구성 퍼즐 | 특성·비교·논리 블록으로 분류 규칙을 만들고 영역 변화 확인 | 새 자료도 잘 분류하는 간결한 규칙 |
| H2 | 경계 탐사 / 능동 정보 수집 | 유용한 학습점의 실제 라벨을 확인하고 경계 후보를 좁힘 | 적은 관측으로 새 자료의 높은 정확도 |
| H3 | 반례 사냥 / 적응형 모델 공략 | 주어진 모델이 틀릴 새 점을 찾아 검증. 모델이 반례를 반영하면 다음 약점 탐색 | 제한된 검사로 확인한 새로운 오류 수 |

H1은 경계 숫자가 어느 축에 해당하는지 항상 보인다. H2의 관측으로 평가 정답을 직접 열 수 없다. H3에서는 이미 확인한 점으로 재득점하지 못하고, 모형의 수정도 실제 규칙과 화면에 일치해야 한다. 불가능한 오류 찾기를 요구하지 않도록 유한한 도전 영역과 종료 조건을 정한다.

## 선택 방법과 이후 작업

`A2, B1, C3, D1, E2, F1, G3, H2`처럼 주제별 하나를 고를 수 있다. 이것은 예시 조합이며 추천 확정값이나 사전 선택값이 아니다.

선택 후에만 해당 형식의 첫 행동·한 판·종료·재도전·UI를 구체화한다. 새 형식을 선택했다는 이유로 핵심 개념을 줄이거나 구현 전에 재미 검토를 생략하지 않는다. 반대로 선택되지 않은 16안을 먼저 개발하지 않는다.
