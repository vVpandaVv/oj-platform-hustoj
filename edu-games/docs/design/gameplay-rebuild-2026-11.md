# Edu Games 게임성 재설계

> 검토 이력: 이 초안은 기존 조작을 새 기능처럼 제안한 항목이 있어 전면 재설계안으로 채택하지 않는다. 주된 행동·승패 조건을 다시 정의한 [핵심 규칙 재설계](gameplay-rules-redesign-2026-11.md)를 개발 검토 기준으로 사용한다. 아래 내용은 이전 제안과 로딩 장애 조사 이력이다.

2026-11-16 설계안. 대상은 문자 코드, 이미지 데이터, 이상치, 결측값, 시각화, 추출, 자료구조, 분류 경계, 모델 훈련의 9종이다. 아래 게임 방식은 구현 제안이며 기존 게임을 이미 교체했다는 뜻이 아니다. 자료구조 페이지의 자산 누락 수정은 이 설계와 분리해 진행한다.

## 방향

학습 문제에 제한시간과 점수를 붙이는 대신, 학습 개념이 게임판을 움직이는 규칙이 되어야 한다. 버튼을 눌러 정답 여부를 받는 것보다 물건의 이동, 분포의 변화, 그림의 완성, 로봇의 행동을 먼저 보여준다.

KAIT Play 로컬 0.10.0의 `play/public/js/app.js`, `play/server/game/match.js`, `play/server/game/board.js`에서 참고한 것은 다음 구조다.

- 블록 해결 결과가 같은 판에 계속 쌓여 공동 목표의 진행을 눈으로 확인한다.
- 이동, 점유, 입력 등 현재 상태에 따라 가능한 행동이 달라진다.
- 대상 가까이에서 조작하고 해당 위치에서 성공과 실패를 보여준다.
- 기본 행동을 익힌 뒤 보스, 자원 사용, 동료의 행동이 다음 판단을 만든다.

이 원칙은 빌리되 모든 게임을 점령전으로 바꾸거나 캐릭터 이동을 강요하지 않는다. 코드·그림·브랜드를 복제하지 않고 기존 Edu Games의 라이트·다크 디자인을 유지한다. 경쟁과 조작이 학습에 도움이 되는 게임에만 넣는다.

## 현재 구조의 문제

| 대상 | 현재 구현에서 확인한 점 | 바꿀 중심 |
| --- | --- | --- |
| 문자 코드 | 무작위 코드표를 참조해 복호화·암호화·복원을 제출하는 구조 | 같은 코드표의 발견이 다음 통신에도 도움이 되게 하기 |
| 이미지 데이터 | 직접 그리기와 배열 보고 복원이 중심 | 창작은 유지하고 복원에는 짧은 완성 목표와 편집 전략 추가 |
| 이상치 | 좁게 모인 7개 값에 크게 떨어진 값을 섞고 검토 대상을 제출 | 거리뿐 아니라 집단·맥락을 보고 후보와 오류를 구분 |
| 결측값 | 이미 9개 방법이 있으나 사례별 도구 선택·제출·다음 사례가 반복 | 같은 설비의 기록을 복구하며 결과와 추정 위험을 비교 |
| 시각화 | 차트 장면은 다양하지만 임무 문장을 읽고 선택·제출하는 비중이 큼 | 그래프 위 배치·범위 선택 자체가 게임 행동이 되게 하기 |
| 추출 | 색·모양·AND/OR·출력 열을 주문 문장대로 고르는 구조 | 만든 처리 라인이 다음 입고에도 계속 작동하게 하기 |
| 자료구조 | 병렬 주문·적재 전략은 있으나 출고장 선택과 여러 조작의 연결이 복잡 | 기존 엔진을 살리고 출구에서 주문으로 직접 이동 |
| 분류 경계 | 경계와 예측은 보이지만 8개씩 제출하고 다시 맞추는 흐름 | 분류기가 계속 일하며 경계 변경의 손익을 보여주기 |
| 모델 훈련 | 실제 최근접 이웃 예측과 표본 선택은 있으나 최종 검정 전 목표가 약함 | 로봇이 처리하는 새 표본과 오류 원인으로 훈련 필요를 보여주기 |

특히 결측값의 문제는 방법 수 부족이 아니다. 이상치·추출·분류의 입력이 새로 생성되어도 판단 방식과 이후 상태가 같다면 반복의 매력은 약하다. 무작위 문장이나 숫자 추가만으로 해결하지 않는다.

## 공통 화면과 조작

게임 중에는 상단에 현재 목표, 핵심 기록, 남은 시간 또는 자원만 두고 중앙을 게임판으로 사용한다. 하단에는 지금 선택한 대상의 도구만 둔다. 순위·규칙·상세 통계는 종료 뒤 또는 별도 화면으로 분리한다.

첫 체험은 정지된 작은 판에서 첫 대상과 목적지를 강조한다. 한 번의 행동 뒤 상태를 바꾸고 다음에 가능한 대상만 드러낸다. 긴 설명문이나 여러 설정을 먼저 제시하지 않는다. 연습은 시간 압박 없이, 도전은 게임별 종료 규칙으로 구분한다.

- 클릭·터치로 대상을 고른 뒤 목적지를 선택한다. 드래그는 같은 행동의 빠른 경로이며 필수 조작으로 만들지 않는다.
- 이동 전 도착 위치나 변경 결과를 잔상으로 보여주고, 적용 뒤 실제 객체가 이동하거나 색·높이·경로가 달라진다.
- 불가능한 조작은 원래 위치로 되돌리며 막힌 출구나 부족한 슬롯을 강조한다. 이유 없는 감점이나 반응 없는 버튼을 없앤다.
- 제한된 판에서 꼭 필요한 도구만 표시한다. 색상만으로 의미를 구분하지 않고 모양·기호·위치도 사용한다.
- 화면이 작아도 조작 대상·목표·결과를 함께 유지한다. 설명을 잘라내거나 게임 도중 페이지를 스크롤하게 하는 방식으로 맞추지 않는다.

### 계속 하고 싶은 이유

첫 20초 안에 작은 통신 한 건, 그림 한 부분, 첫 배송처럼 눈에 보이는 성과를 만든다. 이후에는 이미 익힌 행동을 반복하는 대신 그 행동의 선택지가 충돌하는 상황을 넣는다. 급행 주문과 보관 공간, 실제 극단 관측과 단위 오류, 새 필체와 부족한 기억처럼 학습 개념에 해당하는 사건을 사용한다. 모든 게임에 같은 보스나 방해 아이템을 복사하지 않는다.

캐릭터나 소리는 상태를 전달할 때만 쓴다. 로봇의 성공·오인식 반응, 들어오고 나가는 화물, 이어지는 신호선, 완성되어 작품 모음에 놓이는 그림처럼 결과가 사물에 남는다. 짧은 이동·완성 연출은 다음 입력을 막지 않으며 소리 끄기와 동작 감소 설정을 지원한다. 중립적인 앱 테두리를 장식하는 것보다 게임판 내부의 사물·전환·반응을 다듬는다.

종료 화면은 큰 점수 하나와 다음에 바꿀 수 있는 기록 하나를 보여준다. 예를 들어 배송은 늘었지만 재배치가 많았다면 다음 목표는 재배치 감소이며, 로봇이 특정 숫자에 약했다면 그 형태를 보강하는 것이 목표다. 항상 다음 문제를 더 빨리 풀라는 목표로 끝내지 않는다.

## 1 문자 코드 통신국

**학습 개념:** 문자와 코드의 일대일 대응, 양방향 변환, 같은 규칙의 일관된 적용. 교육용 치환 코드이며 현대 보안 암호라고 설명하지 않는다.

**형식:** 통신 패킷을 이어 처리하는 생존 퍼즐. 중앙에는 송신·수신·코드표 복원 패킷이 놓이고 코드표는 한 도전 동안 유지한다. 패킷을 처리하면 관련 문자와 코드의 연결이 판 전체에 반영된다.

**조작:** 수신 패킷의 숫자 칸을 선택해 문자를 연결하거나, 송신 패킷의 문자에 코드를 넣는다. 복원 패킷은 문자·숫자의 대응을 코드표에 끼워 넣는다. 같은 숫자가 있는 다른 위치가 함께 강조되어 연결을 확인한다. 필드마다 멀리 있는 표와 제출 버튼을 왕복하지 않는다.

**전략:** 익숙한 문자로 빠르게 처리할 패킷과 새로운 대응을 알아낼 수 있지만 오래 걸리는 패킷 중 선택한다. 복원한 대응이 다음 패킷의 처리 시간을 줄이므로 자신의 코드표가 성장한다. 힌트는 해당 대응을 공개하고 기록상 사용 횟수를 남긴다.

**도전과 종료:** 패킷별 제한시간 안에 확정하면 다음 패킷의 시간이 초기화된다. 기존 요구대로 오답 확정·시간 초과가 종료 조건이다. 길이·방식·미확인 대응 수를 고려한 시간 하한을 적용하고 전체 90초 제한으로 되돌리지 않는다. 발견 대응 수, 정확한 통신량, 처리 시간으로 기록하며 힌트 사용 조건을 분리한다.

**학습이 보이는 장면:** `A ↔ 27`을 연결하자 여러 패킷의 27 위치가 동시에 A로 읽힌다. 영단어를 추측하는 능력보다 코드 대응이 진행을 돕는다. 기존 연습은 유지한다.

## 2 픽셀 복원 공방

**학습 개념:** 행·열 주소와 픽셀, 색상 번호와 화면 색의 대응, 같은 배열의 반복과 편집. 최대 16색·16×16은 유지한다.

**형식:** 그림 복원 퍼즐과 창작 공방을 분리한다. 창작은 평가 점수보다 완성·저장·작품 모음이 목표다. 복원은 일부가 망가진 이미지에 코드 조각을 적용해 다시 완성하는 퍼즐이다.

**조작:** 상단 팔레트, 중앙 그림판, 오른쪽에 같은 높이로 이어진 행별 숫자 배열을 둔다. 색상 번호 선택과 픽셀 변화가 연결된다. 짧은 숫자 조각을 행의 특정 구간에 놓거나 잘못된 조각을 바꾼다. 기본 펜·지우개·채우기·실행 취소와 아래 그림 보기는 유지한다.

**전략:** 한 칸 수정, 반복 구간 적용, 같은 행 복사 중 효율적인 복원 방법을 선택한다. 조각을 반복 적용하기 전에 위치를 확인해야 하고, 그림의 이름만 맞혀서는 복원 완료가 되지 않는다. 창작의 도구 사용을 감점하지 않는다.

**도전과 종료:** 한 작품의 복원이 끝나면 작품 모음에 남고 다음 도안을 연다. 무제한 연습과 동일 도안의 기록 도전을 구분한다. 기록은 정확한 완성 후 소요시간·잘못 적용한 횟수이며 자동 채우기 사용 조건이 다른 기록은 섞지 않는다. 실수 시 바로 게임오버보다 수정 기회를 주는 편이 적합하다.

**학습이 보이는 장면:** 4행의 코드 조각을 5행에 놓으면 그림이 한 줄 어긋나고, 같은 조각을 올바른 행으로 옮기면 복원된다. 숫자 배열을 변경하면 해당 픽셀만 변한다. 반사 신경보다 배열과 이미지의 연결을 배운다.

## 3 관측값 검문소

**학습 개념:** 비교 집단과 분포, 이상치 후보와 실제 오류의 차이, 원본 보존과 맥락 확인.

**형식:** 관측 기록이 들어오는 분류 보드게임. 같은 조건의 기록이 쌓이는 관측판과 검토함을 둔다. 자료를 매번 통째로 버리고 새 문제로 교체하지 않고, 최근 관측 이력이 다음 비교의 기준으로 남는다.

**조작:** 유난한 값을 검토함으로 옮기면 원본 잔상을 유지하고 분포·요약값 변화가 즉시 보인다. 필요한 후보에 한해 단위, 측정 장소, 시각 등 제한된 근거를 확인한다. 실제 오류면 수정·제외하고 실제 극단 관측이면 경보로 유지한다.

**전략:** 검토 용량은 한정되어 있다. 모두 보류하면 처리가 막히고, 모두 통과시키면 오류가 지표에 섞인다. 기록을 멀리 떨어진 숫자순으로만 고르지 않고 같은 집단인지, 집단 전체가 이동한 것인지도 구분한다. 정답을 그대로 알려주는 재측정 버튼을 반복하는 방식은 제외한다.

**도전과 종료:** 관측 흐름을 처리하며 오염된 확정 기록과 잘못 버린 정상 기록이 운영 위험을 높인다. 위험 한도 또는 미처리 적체로 종료한다. 정확한 검토·유효 관측 유지·실제 경보 보존을 기록하고, 불필요한 조사와 과잉 제외에는 비용을 둔다. 관측 유입은 짧은 묶음 단위로 멈춰 판단할 수 있게 한다.

**학습이 보이는 장면:** 높은 관측 두 개 중 하나는 °F를 °C로 읽은 오류이고, 다른 하나는 실제 고온이다. 둘을 함께 제외하면 온도계 그래프는 매끈해져도 실제 고온 경보를 놓친다. 극단값을 무조건 제거하는 행동은 고득점 전략이 될 수 없다.

## 4 끊어진 신호 복구소

**학습 개념:** 결측을 0과 구분하기, 자료의 시간·집단·종류에 맞는 대체, 관측값과 추정값의 구분, 불확실성을 남기는 판단.

**형식:** 같은 설비의 기록을 이어 복구하는 수리 퍼즐. 중앙 신호선에서 결측 부분이 끊기고, 복구한 값은 실선 관측과 다른 점선으로 연결한다. 수리 결과가 다음 구간의 계획·제어 결과로 이어진다.

**조작:** 끊긴 구간을 고르고 참고할 관측이나 집단을 선택한 뒤 복구 도구를 적용한다. 적용 전 예상 선과 값이 보이고, 확정하면 설비의 다음 동작·복구 오차·남은 미상 구간이 달라진다. 각 빈칸을 다른 방식으로 처리할 수 있다.

**전략:** 평균·중앙값·보간 등 도구 이름 자체가 정답이 아니다. 안정된 반복 측정, 오염된 집단, 계단식 설정, 주기적 변화, 범주 자료에서 결과가 달라진다. 추정이 불가능한 실제 시행 결과는 미상으로 남기고 추가 관측 비용을 선택한다. 미래 기록을 쓰는 뒷값 채우기는 사후 복구에서만 허용한다.

**도전과 종료:** 복구 예산 내에 유효한 기록을 많이 확보하는 것이 목표다. 예산 소진 또는 위험이 큰 복구의 누적으로 종료한다. 숫자 자료는 목표에 맞게 공개한 오차 지표·허용범위로 평가하고, 범주·미상 판단은 별도 정확성으로 계산한다. 모두 같은 방법을 쓰거나 모두 보류하는 전략은 손해가 생기도록 한다.

**학습이 보이는 장면:** 계단식 장치 설정을 보간하면 실제로 없던 중간 설정이 만들어지고, 앞값을 잇으면 유지 명령과 일치한다. 큰 오염 관측 하나가 섞인 집단은 평균선이 끌려가지만 중앙값은 덜 움직인다. 합성 자료에서만 원래 값을 알고 오차를 비교하며, 현실 결측의 정답을 항상 안다고 표현하지 않는다.

## 5 그래프 작전판

**학습 개념:** 비교·추세·비율·분포·관계에 맞는 시각화, 집계 단위와 축, 선택한 범위가 뜻하는 자료.

**형식:** 그래프 위에 제한된 자원을 배치하는 최적화 게임. 별도 구조대 설정을 이해해야 조작할 수 있는 화면은 없애고 그래프 자체가 판이 된다. 원자료와 선택된 범위의 대응이 유지된다.

**조작:** 막대에서는 지원할 범주·시간 묶음, 꺾은선에서는 대응할 시간 창, 원그래프에서는 확보할 구성비, 히스토그램에서는 처리할 값 구간, 산점도에서는 조사할 영역을 직접 고른다. 드래그·핸들·단계 조절로 선택하고 공통 확정 동작은 하나만 둔다. 한 번에 차트 종류 퀴즈와 범위 퀴즈를 모두 풀게 하지 않는다.

**전략:** 예를 들어 대응 시간 창 두 개로 요청을 최대한 포함하되 중복 지원과 초과 용량은 손해다. 가장 높은 한 막대만 고르는 것으로 끝나지 않는다. 같은 데이터의 시간 묶음이나 구간 폭을 바꾸면 선택 가능한 대응과 놓치는 정보가 달라진다.

**도전과 종료:** 작전 자원을 쓴 뒤 다음 상황으로 이어가며, 자원 대비 제대로 포착한 대상과 낭비·누락으로 기록한다. 순차 도전은 운영 시간 종료, 퍼즐은 같은 데이터에서 제한 자원 사용 완료로 종료한다. 분포가 다른 원점수는 같은 순위에 합치지 않는다. 각 장면은 적합한 자료와 목표를 가진다.

**학습이 보이는 장면:** 오전 합계가 같은 두 지역도 한 시간의 집중 요청은 다르다. 선택한 시간 창 안의 원자료가 강조되고 실제 지원량이 바로 늘어난다. 넓힌 히스토그램 구간은 더 많은 표본을 담지만 필요 없는 표본까지 포함할 수 있다. 차트를 바꾸는 행위 자체에는 점수를 주지 않는다. 유효하지만 불리한 집계는 무조건 입력 오류로 막지 않고 놓친 정보와 결과 차이를 보여준다. 자료형에 맞지 않아 계산 자체가 불가능한 조작과 정보가 부족한 표현은 구분한다.

## 6 데이터 처리 공장

**학습 개념:** 행 조건과 열 선택, AND·OR·NOT, 연산 순서, 재사용할 수 있는 처리 과정.

**형식:** 제한된 처리기로 자동 생산 라인을 만드는 공장 게임. 매 주문마다 조건을 다시 입력하지 않고 만든 라인이 다음 입고도 처리한다. 성과는 회로가 처리한 실제 출력으로 계산한다.

**조작:** 필터·분기·필요 열만 남기기 블록을 입구와 출구 사이에 놓는다. 시험 입고를 흐르게 하면 자료가 단계별로 이동하고 선택에서 빠진 행, 제거된 열이 눈에 보인다. 필터 대상을 먼저 없애면 다음 처리기가 왜 작동하지 않는지 해당 위치에서 보인다.

**전략:** 여러 주문이 공통으로 쓰는 조건은 앞에서 한 번 처리하고 다른 주문은 분기한다. 출력 전용 열 선택을 너무 일찍 하면 뒤쪽 필터가 필요한 값을 잃는다. 모든 자료·모든 열을 그대로 보내는 것으로 정상 배송을 인정하지 않는다.

**도전과 종료:** 제한된 블록 수·처리 용량으로 생산을 유지한다. 적체 한도 또는 운영 시간 종료가 끝이다. 정확한 납품량에서 반송·누락·불필요한 처리 비용을 차감한다. 느려도 정확한 라인과 빠르지만 오배송이 많은 라인을 실제 처리량으로 비교한다. 시험 입고를 반복해 같은 납품 점수를 얻을 수는 없다.

**학습이 보이는 장면:** 빨강 AND 원은 두 조건이 모두 맞는 자료만 한 경로로 보내고 OR 분기는 한 조건만 맞는 자료도 보낸다. 새 입고가 들어와도 설정이 유지되어 조건식이 여러 자료에 적용되는 절차임을 경험한다.

## 7 스택과 큐 물류 레이스

**학습 개념:** LIFO·FIFO, 삽입·삭제 위치, 용량, 미래 요청을 고려한 저장 전략.

**형식:** 현재의 물류 엔진을 유지하는 창고 운영 게임. 새 미로나 다른 장르로 다시 교체하지 않는다. 먼저 페이지 로딩과 조작 연결을 바로잡고 게임판의 사물로 규칙을 전달한다.

**조작:** 스택 맨 위 또는 큐 맨 앞의 물건에서 원하는 출고장으로 직접 옮긴다. 클릭 후 목적지 선택도 같은 결과를 낸다. 별도의 출고장 선택 뒤 다른 곳의 출고 버튼을 누르는 왕복을 줄인다. 내부 물건을 누르면 위·앞 물건이 막고 있음을 짧게 강조한다.

**전략:** 다음 입고와 주문 일부를 보고 어느 쪽에 저장할지 정한다. 바로 배송하려고 스택을 쓰다가 다음 요청을 가릴 수도 있고, 큐에 잘못 넣으면 앞 물건을 먼저 처리해야 한다. 임시 보관은 탈출구지만 이동 비용을 둔다. 첫 체험은 두 물건·한 주문이며 익숙해지면 실제 병렬 주문으로 넓힌다.

**도전과 종료:** 날짜별 같은 조건의 120초 최고 기록 도전은 유지한다. 배송 수·주문 완수·취급 효율에서 재배치 비용을 차감한다. 입고 공급이 같은 조건에서도 작업 순서와 속도가 기록을 바꾼다. 고정 미로 완주에 같은 점수를 주는 구조로 되돌리지 않는다.

**학습이 보이는 장면:** A 다음 B를 스택에 넣으면 B가 출구에, 큐에 넣으면 A가 출구에 남는다. 둘의 차이가 같은 사물의 이동으로 반복해서 드러난다. 잘못 넣은 물건은 사라지거나 판을 초기화하지 않고 다음 판단의 일부로 남는다.

## 8 분류 게이트 방어전

**학습 개념:** 두 특성과 결정 경계, 경계에 따른 예측, 오분류와 클래스별 성능, 복잡한 경계의 한계.

**형식:** 만든 경계가 계속 유입되는 대상을 두 경로로 나누는 방어 게임. 대상이 좌표판의 자기 위치를 거쳐 실제 분류 출구로 이동한다. 움직이는 연출은 처리 결과를 설명하는 범위에서만 사용한다.

**조작:** 선의 양 끝을 움직이면 배경 영역과 아직 처리하지 않은 대상의 예측 출구가 즉시 바뀐다. 확인한 표본에는 실제 분류와 예측을 서로 다른 기호로 보여준다. 다음 유입 묶음을 보내면 고정한 경계가 자동 처리하고 오류가 난 좌표에 흔적을 남긴다.

**전략:** 이번 한 표본을 맞히려고 경계를 크게 움직이면 다른 표본을 놓칠 수 있다. 다음 묶음에도 적용할 수 있는 선을 고른다. 처음에는 직선 하나, 이후 직선으로 완벽히 나눌 수 없는 상황을 제공한다. 복잡한 경계를 늘리는 것이 무조건 유리하지 않게 확인 표본과 새 표본 성능을 함께 보여준다.

**도전과 종료:** 유입 처리량과 양쪽 클래스의 성공률을 함께 기록하고 오분류 위험 한도 또는 운영 시간으로 종료한다. 전부 한쪽으로 보내는 전략은 한 클래스 성능이 0이 되어 불리하다. 클래스 비율이 다른 판은 균형 지표와 조건을 고정해 비교한다.

**학습이 보이는 장면:** 기울기를 바꾸자 같은 점의 출구가 바뀌고 반대편 예시가 오분류된다. 여기서 학생이 직접 그은 선은 사람이 만든 분류 규칙이다. 이를 이미 AI가 학습한 모델이라고 설명하지 않고 다음 로봇 게임의 표본 기반 학습과 대비한다.

## 9 손글씨 로봇 작업장

**학습 개념:** 표본의 대표성·다양성·라벨 품질, 훈련·검증·미공개 평가의 분리, 일반화.

**형식:** 제한된 기억을 가진 로봇을 훈련해 처음 보는 손글씨 작업을 처리하는 덱 구성 게임. 기존 실제 손글씨와 최근접 이웃 엔진을 재사용한다. 0~9 자료를 쓰되 첫 판은 세 숫자로 시작하고 숙련에 따라 조합·형태 차이를 넓힌다.

**조작:** 표본을 기억 슬롯에 넣고 이름을 붙이면 로봇이 비슷한 확인 표본의 답을 즉시 바꾼다. 잘못 처리된 확인 표본을 선택하면 참고한 기억과 거리 비교를 보여준다. 비슷한 표본만 여러 개 넣는 대신 빠진 형태의 표본으로 교체한다.

**전략:** 기억 슬롯을 한 숫자로 채울지, 클래스별 대표와 서로 다른 필체에 나눌지 선택한다. 라벨을 잘못 붙이면 닮은 여러 표본의 답이 함께 틀린다. 빠른 최종 제출에 점수 보너스를 붙이기보다 제한된 훈련 예산으로 새 자료에서의 성능을 올리는 것이 중심이다.

**도전과 종료:** 훈련 예산을 쓰거나 직접 평가를 시작하면 단 한 번의 미공개 작업을 수행한다. 최종 클래스별 인식률과 균형 성능, 사용 기억 수를 기록한다. 시간은 동점 보조 지표이지 핵심 점수가 아니다. 평가에 공개한 원본과 그 변형을 훈련·검증에 다시 섞지 않는다. 재도전은 새 조건 또는 정해진 일일 조건으로 구분하고 검증 반복 최적화와 평가 기록을 혼동하지 않는다.

**학습이 보이는 장면:** 같은 모양의 7만 여러 장 기억시켜도 둥근 획의 다른 7에는 약할 수 있다. 빠진 모양을 추가하자 로봇의 해당 오인식이 줄고 잘 보던 다른 숫자의 성능도 함께 확인된다. 표본 수를 늘린 것 자체를 학습 성공 점수로 치환하지 않는다.

| 분류 경계 | 균형 잡힌 분류를 오래 유지 | 같은 표본·유입·오류 비용 |
| 모델 훈련 | 적은 대표 표본으로 새 필체에 강한 로봇 만들기 | 같은 훈련·검증·평가 분할·기억·예산 |

빠른 입력, 정답 개수, 장식적인 별을 모든 게임의 공통 점수로 삼지 않는다. 동일 선택 반복으로 점수가 계속 쌓이지 않게 새 입력·실제 상태 변화·처리 결과에만 기록을 부여한다. 이전 점수는 보존하고 새 규칙의 버전·조건별로 순위를 분리한다.

무작위 연습과 동일 조건의 기록 도전을 분리한다. 같은 판 재시도로 좋아지는 기록은 숙련 기록이며 처음 보는 문제의 수행평가로 간주하지 않는다. 모델 평가처럼 정답 노출의 영향이 큰 게임은 재응시와 자료 분할까지 따로 취급한다. 수행평가는 경쟁 점수만으로 자동 성적을 만들지 않는다.

## 구현 순서와 범위

1. 자료구조의 실제 애드온 페이지 로딩을 먼저 복구한다. 새 게임 없이 현재 게임판이 열리고 조작되는지 확인한다.
2. 자료구조의 직접 출고와 이상치의 후보·맥락 판단을 각각 작은 플레이 가능한 판으로 만든다. 한 게임은 운영 전략, 다른 게임은 판단 학습을 대표해 공통 화면을 점검한다.
3. 결측값은 같은 설비의 복구 결과, 추출은 지속 처리 라인으로 개편한다. 두 게임을 같은 제출 양식으로 만들지 않는다.
4. 시각화는 그래프 위 선택과 자원 배치로, 분류·모델은 처리 장면과 오류 피드백으로 연결한다.
5. 문자 코드는 코드표의 누적 사용, 이미지는 복원 목표와 창작 작품 모음을 보강한다. 유지할 가치가 있는 현재 도구를 다시 만들지 않는다.

각 게임의 첫 범위는 핵심 조작 하나, 그 조작의 효과를 반대로 보여주는 상황 둘, 명확한 종료와 재도전 기록이다. 처음부터 대규모 캠페인·아이템 상점·모든 게임의 팀전을 붙이지 않는다. 초반 체험 뒤에는 매번 새 판으로 리셋하지 않고 선택의 영향이 남아야 한다.

완성 판단은 버튼 수나 콘텐츠 개수가 아니다. 학생이 설명 없이 첫 행동을 찾는지, 첫 행동 뒤 무엇이 달라졌는지 말할 수 있는지, 같은 방법이 통하지 않는 상황에서 판단을 바꾸는지, 다시 할 때 자기 목표를 고르는지 짧게 관찰한다. 재미는 코드 검사만으로 검증했다고 보고하지 않는다.

## 연결 장애 조사 메모

사용자는 실제 설치 사이트에서 자료구조 페이지가 빈 화면 또는 로딩 상태에 남는다고 보고했다. 현재 소스의 `Oj_Platform_Registration::register_game_pages()`는 새 물류 게임이 호출하는 `assets/play/warehouse.js`와 스타일을 등록하지 않았다. `hands.js`의 `window.EduWarehouse.render()`·`mount()` 호출과 연결되지 않는 경로다. 미리보기는 이 파일을 별도로 추가하고 있어 기존 검사로는 누락을 발견하지 못했다.

페이지 등록 목록에 파일을 추가하고 실제 등록 목록을 브라우저 검사에 전달하는 경로를 만들었다. 이는 확인한 결함의 수정이며, 운영 사이트의 로그·응답·배포 파일을 직접 확인했다는 뜻은 아니다. 최신 ZIP 적용과 캐시 갱신 뒤에도 문제가 남으면 해당 페이지의 오류·실패 자산 응답을 확인한다. 현재 타이핑 전용 로컬 미리보기의 허브 링크 문제도 별개이며 운영 장애의 증거로 사용하지 않는다.
