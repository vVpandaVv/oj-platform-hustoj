# Edu Games 핵심 규칙 재설계

이 문서는 이전 후보안이다. 다섯 유지 게임을 제외한 최신 8종 계획은 [핵심 개념 중심 8종 재설계](concept-first-redesign-2026-11.md)를 따른다. 암호 도미노 등이 포함된 앞선 8종 계획도 철회했다. 이 문서나 이전 시안을 제작 승인으로 해석하지 않는다.

2026-11-16 설계안. 문자 코드, 이미지 데이터, 이상치, 결측값, 시각화, 추출, 자료구조, 분류 경계, 모델 훈련의 9종을 대상으로 한다. 기존 게임·기록을 변경한 구현 보고서가 아니다. 수량·자원·목표치는 첫 플레이를 구체화하기 위한 초기 규칙이며, 해결 가능한 판과 대비 사례로 조정한다.

후속 [중학생 관점의 점검과 첫 화면 설계](middle-school-screen-review-2026-11.md)에서 운영 규칙의 부담과 반복 플레이의 약점을 평가했다. 아래 규칙을 그대로 제작 확정한 것으로 보지 않으며, 첫 조작 시안과 본게임의 미해결 부분을 구분한다.

최신 변경은 [보드게임 방식의 2차 개편](boardgame-development-round-2-2026-11.md)을 따른다. 세 종의 실제 진행 프로토타입과, 선택형 과제로 돌아가지 않기 위한 나머지 여섯 종의 변경 기준을 구분했다.

기존 조작에 점수나 상황 설명을 붙이는 대신, 플레이어가 결정하는 대상과 게임을 끝내는 조건을 바꾼다. 자료구조의 드래그 배송, 경계선 이동에 따른 즉시 예측, AI의 기억 교체에 따른 예측 변경은 이미 있으므로 개편 성과로 세지 않는다.

## 공통 결정

- 기본은 혼자 가능한 게임이다. 상대가 필요한 자료구조 게임은 로컬 규칙 봇을 기본으로 사용하며 팀전·Code Arena 설치를 요구하지 않는다.
- 새 도전은 기존 연습·창작·아케이드와 구분한다. 기존 기록을 새 점수로 환산하지 않고 규칙·도전 조건별로 순위를 분리한다.
- 퍼즐에는 완성과 새 콘텐츠, 운영 게임에는 처리 효율, 대전에는 승률이라는 서로 다른 목표를 둔다. 모든 게임을 120초 정답 개수 경쟁으로 통일하지 않는다.
- 행동이 소비한 자원과 남긴 상태를 공개한다. 조사나 추정으로 알 수 없는 사실을 숨긴 채 정답을 요구하지 않는다. 추정은 불확실성을 허용하고 퍼즐에는 충분한 단서가 있는 해를 제공한다.
- 위험은 잘못된 처리, 자원 낭비, 적체 등 해당 행동의 결과에서 발생한다. 학습과 상관없는 연료 미로, 임의의 보스, 이유 없는 즉사 조건은 사용하지 않는다.
- 기본 조작은 클릭·터치 선택과 목적지 지정이다. 드래그는 보조 경로다. 계획·미리보기와 되돌리기는 충분히 허용하고, 자원 차감이 발생하는 확정 행동은 구분한다.
- 상태 변화는 한 판 안에 누적된다. 성공 후 모든 자료를 지우고 다른 문제를 띄우는 것을 기본 진행 방식으로 사용하지 않는다.

## 1 문자 코드 통신망 퍼즐

### 현재와 달라지는 것

현재는 복호화·암호화·코드표 복원 중 제시된 일을 수행하고 다음 패킷으로 넘어간다. 새 게임에서는 개별 패킷 정답이 아니라 통신망 전체의 연결 상태를 해결한다. 손으로 문장을 길게 타이핑하는 속도보다 어떤 단서를 먼저 확보하고 어느 대응에 확신을 둘지가 중요하다.

### 첫 화면과 행동

중앙에 통신소 6개와 아직 연결되지 않은 필수 경로 4개를 놓는다. 하단에는 한 판 동안 고정되는 문자·공백·숫자의 대응표, 옆에는 평문과 숫자가 함께 남은 단서 패킷을 둔다. 첫 판은 전체 37기호 중 일부만 사용한다.

1. 코드 타일과 문자 타일을 연결해 대응 가설을 만든다. 동일 숫자의 다른 위치도 함께 변한다.
2. 이미 연결한 통신소에서 단서 패킷을 선택해 확인한다. 확인권을 소비하므로 모든 단서를 열 수는 없다.
3. 만든 대응표를 수신기·송신기에 적용하고 통신을 시험한다. 송신은 문자에서 숫자로, 수신은 숫자에서 문자로 같은 표를 반대로 사용한다.
4. 성공하면 해당 통신소가 열리고 새로운 연결 또는 단서를 사용할 수 있다. 대응표는 유지된다.

미확정 가설의 이동은 무료이며 시험 전 결과를 미리 볼 수 있다. 실제 시험에 실패하면 확인권 1개를 소비한다. 정보가 부족한 상태에서 영단어를 추측해야만 진행되는 판은 만들지 않는다.

### 승패와 구체적인 선택

필수 경로 4개를 모두 열면 승리다. 초기 확인권 6개를 모두 쓰고도 연결이 남으면 실패다. 임의 재전송으로 권한을 다시 얻지 못한다. 정답 패킷을 빨리 제출해 무한 점수를 올리는 기존 아케이드와 다른 퍼즐 모드다.

예를 들어 단서 `A1 → 38 62`, `B1 → 17 62`는 A·B·1의 대응을 함께 밝힌다. 이 기호들을 공유하는 두 연결을 먼저 열면 추가 단서에 접근할 수 있다. 당장 한 경로만 여는 단서보다 여러 경로에 재사용할 단서가 유리할 수 있다. 코드표에는 서로 다른 두 문자를 같은 숫자에 연결할 수 없다.

학습은 일대일 대응과 양방향 변환을 동시에 적용하는 데서 발생한다. 숫자는 게임용 치환표의 값이며 ASCII·유니코드의 실제 표준값이나 현대 보안 암호라고 설명하지 않는다. 기록은 완성 경로, 사용 확인권, 오시험 수를 우선하고 동점에서 시간으로 비교한다. 완성 퍼즐에 모두 같은 1,000점을 주지 않으며 더 복잡한 연결망 해제를 주요 보상으로 삼는다. 기존 패킷별 시간제 아케이드와 연습은 별도 유지한다.

## 2 픽셀 타일 조립

### 현재와 달라지는 것

현재의 중심은 한 칸씩 칠하기와 복원 정확도 확인이다. 새 도전에서는 이미지를 이루는 코드 타일을 공간에 배치하고 회전시키는 조립 퍼즐로 바꾼다. 그리기 도구를 늘리는 것은 이 개편의 핵심이 아니다. 자유 창작과 기존 직접 복원 활동은 유지한다.

### 첫 화면과 행동

최대 16×16 보드, 상단의 16색 이하 팔레트, 각 행과 정확히 높이가 맞는 목표 숫자 배열을 둔다. 목표 그림은 가리고 아래에는 그림 이름 보기를 둔다. 타일은 처음 네 조각부터 시작하고 16×16 도전은 8~16조각을 사용한다. 숫자와 색상 패턴을 함께 볼 수 있다.

1. 타일을 선택하고 회전시켜 보드의 행·열 위치에 놓는다. 클릭으로 타일과 위치를 고르는 방식도 지원한다.
2. 회전하면 해당 타일의 숫자 배열도 실제 픽셀 순서에 맞게 바뀐다.
3. 확정 배치는 잉크 1개를 쓴다. 들어갈 자리는 미리 보되 전체 정답 일치 표시는 확정 후에 한다.
4. 확정한 타일을 회수해 다른 위치로 옮길 수 있으나 새 확정에 잉크를 쓴다. 타일이 겹치거나 보드 밖이면 확정할 수 없다.

### 승패와 구체적인 선택

배열의 모든 칸이 일치하고 타일 배치가 끝나면 승리다. 초기 잉크는 조각 수에 3개를 더해 제공하고, 모두 쓰고도 완성하지 못하면 실패다. 실패해도 판과 수정 이력은 남고 무제한 연습으로 이어갈 수 있다. 그림 이름만 맞혀서는 조립을 건너뛰지 못한다.

타일 배열이 `[[1,0],[2,3]]`이면 시계 방향 회전 결과는 `[[2,1],[3,0]]`이다. 색상 집합이 같아도 위치는 다르다. 특정 행의 연속 코드와 모서리를 먼저 맞추면 배치 후보를 줄일 수 있다. 매 조각을 무작정 대입하면 잉크를 소모한다.

학습은 색상 번호, 행·열 주소, 공간 변환과 배열 순서의 연결이다. 같은 도안은 사용 잉크와 시간으로 비교하고 새 도안 모음을 주된 재도전 목표로 둔다. 창작물의 예술성이나 그리기 도구 사용을 점수로 서열화하지 않는다.

## 3 관측소 복구 보드

### 현재와 달라지는 것

현재는 한 묶음의 숫자에서 멀리 떨어진 값을 골라 제출한다. 새 게임은 점을 골라 버리는 것이 아니라 비교 집단과 관측소의 해석 규칙을 고쳐 다음 관측에서도 잘못된 경보가 나지 않게 만드는 게임이다.

### 첫 화면과 행동

관측소 6개, 장소·시각·단위가 보이는 관측 이력, 비교 집단 두 곳, 이동식 기준계 2개를 둔다. 초반에는 실내·실외처럼 조건이 명확히 다른 집단을 사용한다. 수치뿐 아니라 기록 출처를 항상 함께 표시한다.

1. 같은 조건으로 비교해야 할 관측소들을 연결한다. 집단별 분포와 기준 범위가 달라진다.
2. 이상 징후가 있는 관측소에 기준계를 배치해 독립 관측과 비교한다. 검사 위치 선택은 무료이고 실제 관측은 검사권을 쓴다.
3. 단위 변환·확인된 편향 교정·기준 유지 중 필요한 규칙을 해당 관측소에 설치한다. 단순히 값이 크다는 이유로 교정하지 못한다.
4. 다음 관측 묶음을 실행한다. 설치한 규칙과 비교 집단은 그대로 적용되며 실제 고온과 허위 경보의 결과가 누적된다.

원본값과 교정값은 둘 다 남긴다. 보류는 원인을 모르는 관측에 가능하지만 해당 관측소의 유효 보고가 빠진다. 모두 보류하면 목표를 달성할 수 없다.

### 승패와 구체적인 선택

최종 두 관측 묶음에서 예정된 실제 경보 2개를 놓치지 않고 허위 경보를 1개 이하로 억제하면 승리다. 중요한 실제 경보 누락 또는 허위 경보 3개 누적이면 조기 실패하며, 마지막 묶음 이후 승리 조건에 미달해도 실패다. 실제 경보와 이상 원인의 구성은 한 도전 동안 일관되며, 해결에 필요한 독립 단서와 검사권을 제공한다.

예를 들어 A의 77은 독립 기준계와 단위 설정을 확인하면 77°F, 즉 25°C이다. 반면 B의 40°C는 주변 독립 관측과 상승 이력도 같은 실제 고온이다. 둘을 검토함에 넣는 것으로 끝나지 않는다. A의 수신 단위를 고치면 이후 허위 경보도 줄고 B의 실제 경보는 유지해야 한다. 집단 전체가 변한 경우를 개별 센서 고장으로 오인하는 상황도 둔다.

전략은 한 번의 교정이 여러 미래 관측에 미치는 효과, 검사 우선순위, 보류에 따른 관측 손실의 균형이다. 학습 목표는 상대적 이상 징후와 데이터 오류를 구분하고 맥락으로 원인을 확인하는 것이다. 정확한 경보, 보존한 유효 보고, 사용 검사권으로 기록한다. 분포에서 멀수록 무조건 제외하는 전략은 실패해야 한다.

## 4 관측 예산과 물자 배분

### 현재와 달라지는 것

현재는 대체 방법과 참고 자료를 고르고 숨긴 관측값과 비교한다. 새 게임의 주된 결정은 결측 하나마다 정답 방법을 고르는 것이 아니라 제한된 관측권을 어디에 쓰고 불확실한 기록을 바탕으로 물자를 어떻게 배분할지 정하는 것이다.

### 첫 화면과 행동

공급해야 할 구역 3곳, 수요 이력의 결측, 이번 턴의 물자, 전체 운영에 사용할 관측권을 둔다. 채워 넣은 추정은 실제 관측과 다른 점선·범위로 표시한다. 물자 계획은 빈칸을 0으로 간주하지 않는다.

1. 수요가 불확실한 구역에 관측권을 배치한다. 관측하면 해당 결측의 실제 기록을 얻는다.
2. 나머지 구역은 관련 집단·시점과 대체 방법을 정해 추정하거나 미상으로 남긴다. 방법별 예상값과 근거 범위를 비교할 수 있다.
3. 구역별로 물자를 나누고 배송을 실행한다. 공급 부족과 낭비가 실제 운영 결과로 남는다.
4. 확인된 실제 수요와 추정의 차이를 보고 다음 턴의 관측 우선순위를 정한다. 사용 관측권과 서비스 실패는 초기화하지 않는다.

### 승패와 구체적인 선택

6턴 중 5턴 이상을 공개한 부족 허용범위 내에서 운영하면 승리다. 심각한 공급 부족 2회면 조기 실패한다. 남은 관측권이 0이어도 추정으로 운영할 수 있으며 단순히 0이 되었다고 즉사시키지 않는다. 자료 생성은 공개한 변화·오차 범위를 따르고 관측해도 풀 수 없는 무작위 수요로 승패를 정하지 않는다.

예를 들어 A의 같은 시점·같은 조건 반복 관측이 `22,24,?,24,26`으로 좁게 모여 있으면 24를 대표 추정으로 쓸 근거가 있다. B는 이력의 변동이 크고 추가 정보 없이는 범위가 넓다. 이번 물자가 50이고 관측을 한 곳만 할 수 있다면 B를 확인하는 편이 유리하다. B의 실제 수요가 26으로 확인되면 A에 24, B에 26을 줄 수 있다. A부터 확인하고 B를 무조건 평균으로 채우면 부족하거나 과잉 배분할 수 있다. A처럼 평균과 중앙값이 같은 합리적 추정이면 둘 다 인정한다. 다른 관측 분포와 운영 목표에서 결과 차이가 나게 하며 도구 이름이 다르다는 이유로 감점하지 않는다. 같은 시점의 다른 관측과 과거 기록만 사용하고 실시간 계획에서 미래 관측을 미리 보여주지 않는다.

학습은 평균·중앙값의 성질뿐 아니라 추정과 관측의 차이, 불확실성이 큰 곳에 정보를 확보하는 판단이다. 기존 9개 방법은 연습에 남긴다. 뒷값 채우기는 사후 기록 복구에만, 최빈값은 종류 자료에만 제공하는 등 적용 가능한 상황을 구분한다. 관측 자료에 없는 값을 만들었다고 실제값으로 표시하지 않는다.

기록은 충족한 수요, 부족·낭비, 관측 비용으로 비교한다. 숨긴 원래 숫자 하나와 정확히 일치해야만 성공하는 채점은 중심에서 제외한다. 모두 관측하기는 관측권 때문에, 모두 평균 채우기는 서로 다른 자료 성질 때문에, 모두 보류하기는 실제 공급 판단이 필요하기 때문에 불리하다.

## 5 한 화면 정보 설계 퍼즐

### 현재와 달라지는 것

현재는 제공된 그래프에서 임무에 맞는 범위·지역·배분을 선택한다. 새 게임은 제한된 차트 공간에 필요한 정보를 얼마나 손실 없이 담을지 설계하는 퍼즐이다. 그래프 위 선택 범위를 늘리는 것만으로 개편했다고 하지 않는다.

### 첫 화면과 행동

한 자료판, 차트 슬롯 2곳, 정보 목표 3개, 제작 잉크 4개를 둔다. 목표는 특정 차트 이름이 아니라 알아낼 수 있어야 하는 사실이다. 예를 들어 지역별 총량, 시간별 최대 요청, 대기 10분 이상인 표본 수다.

1. 자료의 범주·시간·수치 열과 집계 방식을 골라 차트 타일을 만든다. 제작 전 미리보기는 자유롭다.
2. 차트 타일을 슬롯에 확정하면 잉크를 쓴다. 같은 차트가 여러 정보 목표를 충족할 수도 있다.
3. 축·단위·집계 구간을 조합해 정보를 보존한다. 새 타일로 교체하면 잉크가 추가로 필요하다.
4. 완성된 차트들로 정보 목표를 확인한다. 잘못된 집계로 사라진 정보는 원자료와 대응시켜 보여준다.

### 승패와 구체적인 선택

두 슬롯과 제작 예산 안에서 세 정보 목표를 모두 충족하면 승리다. 잉크를 모두 쓰고 목표가 남으면 실패다. 무제한 연습에서는 예산을 제거한다. 유효한 다른 차트 조합도 같은 목표를 충족하면 인정하며 정해진 차트 종류와 일치하는지만 검사하지 않는다.

예를 들어 A 지역은 오전 9시에 20, 10시에 0이고 B는 4와 16이다. 총량 막대는 두 지역 모두 20임을 보이지만 시간 피크는 잃는다. 지역·시간을 함께 담은 묶음 막대는 총량과 시간 피크를 모두 보여줄 수 있어 다른 슬롯을 대기시간 분포에 사용할 수 있다. 총량 막대와 같은 총량의 원그래프를 나란히 두면 두 슬롯을 썼어도 시간 정보는 여전히 부족하다.

차트는 막대·꺾은선·원·히스토그램·산점도를 자료와 목표에 맞게 제공한다. 히스토그램은 구간 경계에 따라 특정 기준 이상의 빈도를 보존하는지, 산점도는 동일 표본의 두 변수가 함께 남는지 검사한다. 사람의 미적 평가나 실제 가독성을 자동으로 판정했다고 주장하지 않는다. 프로그램은 표현된 데이터로 요구된 사실을 계산 가능한지 검증한다.

학습은 차트 이름 암기가 아니라 정보 손실과 중복, 집계와 표현의 선택이다. 정보 목표를 적은 잉크로 충족한 기록과 새 설계 과제 해제를 중심으로 한다. 속도가 핵심인 아케이드로 억지 변환하지 않는다.

## 6 자동 데이터 공장

### 현재와 달라지는 것

현재는 한 입고 묶음의 조건과 출력 열을 고르고 출고한다. 새 게임에서는 한 번 만든 처리 라인이 다음 입고에도 계속 작동한다. 플레이어가 각 묶음의 정답을 직접 골라주는 방식으로는 납품할 수 없다.

### 첫 화면과 행동

입구, 고객 출구 2개, 처리 블록 최대 6개, 예정된 입고와 고객 계약을 둔다. 필터·분기·합치기·열 선택 블록은 실제 자료를 처리한다. 각 블록에 처리 용량과 대기 칸이 있으며 물건의 이동은 자료의 흐름과 일치한다.

1. 블록을 놓고 연결해 처리 라인을 만든다. 필터는 AND·OR·NOT을 설정할 수 있다.
2. 시험 자료를 흘려 각 단계의 행·열 변화를 확인한다. 시험은 납품 점수를 주지 않는다.
3. 생산을 실행하면 정해진 시뮬레이션 틱마다 자료가 자동 처리된다. 네트워크 지연이나 클릭 속도가 처리량이 되지 않는다.
4. 적체가 보이면 다음 계획 구간에 공유 필터, 분기 위치, 열 선택 순서를 바꾼다. 이미 납품한 자료와 대기 자료는 보존된다.

### 승패와 구체적인 선택

생산 기한 안에 두 고객의 납품 목표와 필수 열을 충족하면 승리다. 반송 3회, 입고 대기열 넘침 또는 계약 기한 초과가 실패다. 첫 판은 한 계약과 세 블록으로 시작하고 이후 두 고객·공유 조건으로 넓힌다.

예를 들어 두 고객 모두 빨강만 받지만 한 고객은 원, 다른 고객은 삼각형을 원한다. 빨강 필터를 공유한 뒤 분기하면 각 경로에서 다른 색을 계속 처리하는 비용을 줄인다. 색 열을 앞에서 지워버리면 뒤 필터가 판단할 수 없다. 반대로 주문별로 완전히 다른 조건이면 앞에서 너무 많이 걸러 필요한 자료를 잃을 수 있다.

전략은 공통 작업 재사용, 처리 순서, 용량과 병목이다. 학습은 행 선택과 열 선택의 차이, 논리 조건과 처리 절차다. 합치기는 같은 입력을 중복 납품해 점수를 얻지 못하도록 출처 ID로 중복을 구분한다. 기록은 정확한 납품량·반송·처리 비용이며 단순히 블록 수를 늘린 것에는 점수를 주지 않는다.

## 7 스택과 큐 행동카드 대전

### 현재와 달라지는 것

현재는 화물을 하나씩 움직여 120초 점수를 쌓는 운영 게임이다. 드래그를 추가하는 것이 아니라 다음 세 조작을 미리 예약하고 결과를 예측하는 턴제 대전으로 바꾼다. 시간에 쫓겨 클릭하는 능력과 자료구조 이해를 분리한다.

### 첫 화면과 행동

내 스택·큐와 봇의 스택·큐, 다음 입고 일부, 공개 주문 3개, 명령 슬롯 3개를 둔다. 스택·큐는 각 4칸이고 출력 준비대가 있다. 입고와 주문은 같은 공개 규칙으로 공급되며 상대 저장 상태를 볼 수 있다.

1. `스택 넣기`, `큐 넣기`, `스택 꺼내기`, `큐 꺼내기` 행동카드를 세 슬롯에 놓는다. 가능한 명령은 반복할 수 있다.
2. 계획 중에는 카드 순서를 바꾸고 취소할 수 있다. 스택의 내부나 큐 중간을 직접 꺼내는 명령은 없다.
3. 실행하면 내 계획과 봇 계획이 한 동작씩 번갈아 진행된다. 먼저 실행할 쪽은 라운드마다 교대하며 화면에 표시한다.
4. 꺼낸 물건은 자신의 출력 준비대에 남는다. 공개 주문의 순서와 일치하면 자동으로 주문을 확보하고 그 물건을 소비한다. 다른 주문을 뺏겼더라도 준비 물건은 사라지지 않는다.

### 승패와 구체적인 선택

주문 3개를 먼저 확보하면 승리다. 봇이 먼저 3개면 패배다. 10라운드까지 끝나지 않으면 확보 주문 수, 동률이면 낭비한 동작 수로 판정하며 둘 다 같으면 무승부다. 봇은 공개한 난이도의 제한된 계획 능력을 사용한다. 학생이 계획을 확정하기 전에 동일한 공개 상태만 보고 봇 계획을 고정하며, 학생의 카드나 미공개 입고 순서를 보고 대응하지 않는다.

입고가 A 다음 B일 때 스택에 차례로 넣으면 출력은 B-A가 되고 큐면 A-B가 된다. 공개 주문이 B-A라도 봇의 스택 위에 이미 B-A 순서가 준비되어 있다면, 같은 주문을 쫓는 대신 A-B 주문을 큐로 노릴 수 있다. 세 번째 카드의 출고가 어떤 물건을 꺼낼지 첫 두 카드로 미리 생각해야 한다.

학습은 LIFO·FIFO와 상태 추적, 용량과 명령 순서의 결과 예측이다. 잘못된 예약은 입력 단계에서 막힌 원인을 보여주고 수정할 수 있다. 상대 행동으로 상황이 바뀐 경우 실행할 수 없는 명령은 물건을 삭제하지 않고 그 동작을 소비한다. 막힌 판을 풀 수 있는 재입고는 한 행동 비용으로 제공한다.

기록은 상대 난이도별 승패와 주문당 동작 효율이다. 동일 주문을 완료하면 항상 같은 점수를 받는 단독 미로가 아니다. 기존 120초 개인 물류는 이전 게임으로 남기고 새 대전 순위와 섞지 않는다. 온라인 팀전은 이 설계의 필수 범위가 아니다.

## 8 조건 관문 방어전

### 현재와 달라지는 것

현재는 직선 하나의 끝점을 조정하고 한 묶음을 분류한다. 새 게임은 여러 조건 관문을 분기 연결해 비선형 분류 구역을 만드는 방어전이다. 직선 이동이나 실시간 미리보기를 새 기능으로 주장하지 않는다.

### 첫 화면과 행동

두 특성의 좌표판, 실제 분류가 알려진 예시, 두 출구와 조건 관문을 놓을 건설 슬롯을 둔다. 초기 관문은 두 개이고 최대 세 개다. 관문은 `가로 ≥ 기준` 또는 `무게 ≥ 기준`처럼 한 특성의 비교를 실행한다.

1. 첫 관문을 설치하고 참·거짓 출구를 다른 관문이나 최종 출구에 연결한다.
2. 관문을 움직이거나 기준을 바꾸면 그 조건이 적용되는 좌표 영역과 대상의 통과 경로가 함께 바뀐다. 모든 점에 같은 두 번째 조건이 적용되는 것은 아니다.
3. 유입을 시작하면 설치된 관문이 자동 분류한다. 오류는 발생한 좌표와 통과한 조건 경로에 남는다.
4. 다음 유입 전 한정된 건설·수정 에너지를 써서 문제 구역의 관문을 보강한다. 기존 관문과 기록은 유지한다.

### 승패와 구체적인 선택

3차례 유입을 끝낸 뒤 두 클래스 각각의 성공률이 80% 이상이고 건설 예산을 지키면 승리다. 최종 성능이 미달하면 패배다. 에너지가 0이어도 현재 관문으로 계속 운영할 수 있다. 각 유입의 클래스 수와 관문으로 해결 가능한 구조를 검토해 제시하며, 부족한 표현력 때문에 애초에 달성 불가능한 목표를 내지 않는다.

예를 들어 분류 규칙이 `가로 60 이상 또는 무게 70 이상`에 해당하는 모양이면 먼저 가로로 나누고 가로가 작은 영역에만 무게 관문을 붙일 수 있다. 단일 직선보다 ㄱ자 영역에 맞는 경로가 된다. 세 관문으로 네 구역을 나누는 상황에서는 어디에 분기를 투자할지가 달라진다.

전략은 어느 하위 집단에 추가 조건을 적용할지, 적은 관문으로 일반화할지다. 모든 대상을 한 출구로 보내면 반대 클래스 성능이 0이어서 이길 수 없다. 양쪽 클래스 성능·사용 에너지·복잡도를 기록한다. 학습 개념은 결정 경계와 결정트리의 분기이며 사람이 만든 규칙이라는 점을 명시한다. AI가 표본에서 자동 학습하는 다음 게임과 구분한다.

## 9 학습 예산으로 운영하는 로봇 연구소

### 현재와 달라지는 것

현재는 이미 주어진 표본을 골라 라벨과 기억을 바꾸고 마지막에 평가한다. 새 게임에서는 어떤 자료를 확보하고 어느 오류를 검수할지, 언제 훈련하고 배포할지를 운영한다. 표본 교체 시 예측이 바뀌는 기능만으로 새 게임이라고 하지 않는다.

### 첫 화면과 행동

반듯한 글씨·기울어진 글씨·희미한 글씨 같은 자료 출처, 남은 연구비, 학습기와 확인 작업, 미공개 작업 계약을 둔다. 초기 연구비 12, 미검수 자료 팩 2, 검수된 자료 팩 3, 표본 한 장 검수 1, 모델 갱신 2, 확인 작업 1의 비용으로 시작한다. 모두 게임 내 자원이며 실제 결제는 없다. 자료 팩의 예시·숫자 구성·검수 여부·가격을 구매 전에 볼 수 있다. 무작위 뽑기가 아니며 첫 판은 숫자 세 종류, 이후 0~9의 조합을 넓힌다.

1. 필요한 출처에서 학습 자료를 수집한다. 검수된 자료는 비싸지만 라벨 품질이 확보된다.
2. 의심되는 표본에 검수 비용을 쓰거나 새로운 형태의 표본 확보에 투자한다. 이름과 기억의 수정은 이 자원 선택의 결과다.
3. 훈련 비용을 지불해 모델을 갱신하고 별도 확인 자료에서 로봇의 처리와 오류를 본다. 실제 최근접 이웃 등 검증 가능한 학습 엔진으로 계산한다.
4. 목표가 충족될 것으로 판단하면 모델을 고정하고 미공개 작업에 배포한다. 운영 피드백을 받은 자료는 이후 학습에 쓸 수 있지만 독립 평가 자료로 다시 쓰지 않는다.

### 승패와 구체적인 선택

고정한 미공개 작업에서 숫자별 인식률 75% 이상이라는 계약을 연구비 안에서 달성하면 승리다. 연구비를 모두 쓰고 성능이 부족하거나 고정 배포의 계약 성능이 미달이면 패배다. 확인용 표본에는 반복 접근할 수 있지만 최종 작업의 정답은 배포 전에 공개하지 않는다. 임의의 숨은 자료 운으로 계약이 불가능해지지 않도록 도전별 도달 가능성을 확인한다.

예를 들어 확인 자료 대부분이 반듯한 필체라 성적이 높더라도 계약의 작업 예시는 기울어진 7을 포함한다. 같은 출처에서 표본을 더 사기보다 기울어진 자료를 확보할 수 있다. 반대로 모양은 충분한데 7에 잘못된 이름이 붙어 있다면 표본을 늘리기보다 검수가 효율적이다. 자주 훈련하면 연구비를 소모하고 마지막에 한꺼번에 훈련하면 오류를 보완할 기회를 잃을 수 있다.

학습은 자료 대표성·라벨 품질·훈련과 검증의 차이·미공개 자료에 대한 일반화다. 알려진 정확도에 연구비를 더해 만든 가짜 모델 점수가 아니라 실제 예측으로 결과를 계산한다. 원본 이미지와 그 변형을 서로 다른 자료 분할에 섞지 않는다. 기록은 계약 난이도와 최종 클래스별 성능, 사용 연구비이며 빠른 버튼 클릭이나 구입 표본 수 자체를 점수로 주지 않는다.

## 같은 행동이 통하지 않는지 확인하는 기준

| 게임 | 쉬운 고정 행동 | 그 행동이 실패하거나 비효율적인 이유 |
| --- | --- | --- |
| 문자 코드 | 눈앞의 단서부터 전부 열기 | 확인권이 부족하고 여러 경로에 공유할 기호를 먼저 알아내는 편이 유리함 |
| 이미지 데이터 | 모든 타일을 모든 자리에 확정해 보기 | 확정 잉크가 소모되며 회전·행 패턴으로 후보를 줄여야 함 |
| 이상치 | 가장 큰 값은 모두 고장으로 처리 | 실제 경보와 집단 이동까지 지우게 되며 최종 관측에서 실패함 |
| 결측값 | 모든 빈칸을 평균 또는 0으로 채우기 | 자료 성질과 수요 불확실성이 달라 부족·낭비가 발생함 |
| 시각화 | 차트를 많이 만들거나 합계만 보이기 | 슬롯·잉크를 쓰고도 시간·분포 등 필요한 정보를 잃음 |
| 데이터 추출 | 모두 통과시키고 모든 열 보내기 | 고객 계약과 열 조건 위반으로 반송되며 중복 자료도 인정하지 않음 |
| 자료구조 | 모든 화물을 스택에 넣고 즉시 꺼내기 | 요구 순서와 상대의 주문 준비 상태에 따라 선점당함 |
| 분류 경계 | 모든 대상을 한쪽으로 보내기 | 다른 클래스 성능이 0이므로 승리 기준을 만족할 수 없음 |
| AI 모델 | 같은 종류 자료만 계속 구입하기 | 계약에 필요한 필체·클래스를 확보하지 못하고 연구비만 소비함 |

단일 고정 행동을 임의 감점으로 막지 않는다. 조건을 정확히 처리하거나 정보를 효율적으로 쓰는 행동이 실제 운영 결과에서 유리해야 한다. 첫 도전에는 두 전략의 차이가 눈에 보이는 작은 상황을 둔다.

## 화면과 구현 경계

첫 화면은 목표 하나, 게임판, 핵심 자원 두세 개로 구성한다. 복잡한 지표는 종료 뒤에 두고 대상에서 바로 조작한다. 성공·실패는 전체 화면의 긴 설명보다 해당 연결·타일·관측소·출고 경로에서 드러난다. KAIT Play의 지속되는 공동 목표와 조작 위치의 명확함을 참고하되 해당 코드·브랜드·자산은 복제하지 않는다.

자료구조와 분류 경계의 계산은 플레이어가 조작한 명령·조건 그대로, 데이터 게임은 실제 변환·분류 결과로, AI는 실제 학습 엔진의 예측으로 판정한다. 점수·승패는 서버가 상태 전이로 재현하며 같은 요청을 재전송해 자원이나 기록을 중복 얻지 못하게 한다. 구현 전 새로운 DB 컬럼이나 공용 서버 의존성을 미리 추가하지 않는다.

기존 연습·창작·순위는 보존한다. 새 규칙은 모듈별로 분리하고 첫 적용 게임의 주 화면만 교체한다. 초기 제작은 핵심 판과 두 대비 상황, 승패·재도전까지로 제한한다. 온라인 팀전, 대규모 캠페인, 장식용 상점은 뒤로 미룬다.

제작 시작은 데이터 추출의 자동 라인과 자료구조의 행동카드를 권한다. 현재와의 조작 차이와 전략 차이를 가장 명확하게 비교할 수 있다. 이후 이상치·결측값의 판단 결과, 시각화의 정보 설계, 분류·AI의 자동 운영, 문자·이미지의 제약 퍼즐 순으로 연결한다. 이 문서는 설계이며 재미·난이도 검증이나 구현 완료를 뜻하지 않는다.
