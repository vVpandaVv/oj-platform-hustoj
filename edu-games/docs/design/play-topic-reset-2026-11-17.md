# 게임 주제 교체와 암호 금고 개인전·팀전

2026-11-17. **검토용 설계·조작 시안이며 운영 플러그인 구현이 아니다.** 이전 문서의 6종 후보를 철회한다. 실제 학생의 흥미를 확인했다고 주장하지 않는다. 시안의 로컬 조작 결과는 학생 기록이나 서버 순위에 저장하지 않는다.

후속 사용자 결정은 [게임과 개념 체험 분리·새 게임 후보](play-game-and-lab-directions-2026-11-17.md)를 우선한다. 댄스봇·보물 책장·공개 전 점검은 유지하며 댄스봇 외 후보들은 개념 체험으로 분리하는 안이다. 패킷 시안은 비교차 연결과 전송 전 취소·확정, 전송 후 되돌리기를 반영했다. 아래의 즉시 전송·게임 순위 항목은 그 변경 이전 제안이다. 암호 금고 개인/팀전 설계는 그대로 유지한다.

## 유지와 철회

유지: 암호 금고, 픽셀 공방, 이진수 아케이드, 장치 카드 매칭, 키워드 레인, 코드 타이핑, 손글씨 로봇. 기존 개인·팀 기록, 타이핑 수행평가, 교사·학생 화면은 변경하지 않는다.

철회: 데이터 사건 파일, 끊긴 신호 작업대, 그래프 수리공, 자동 추출 공장, 스택·큐 블록매치, 경계 탐사. 이름이나 점수만 바꿔 재사용하지 않는다. 아래 6종은 **다른 학습 주제로 교체하는 후보**이며 선택 전 기존 게임을 삭제하거나 순위를 이전하지 않는다. 이상치·결측치·시각화·추출·자료구조·AI 분류의 학습을 대체 이수했다고 표시해서도 안 된다.

## 암호 금고 공통 판

- 12개 직사각형 대신 **24개 정사각형 금고**. PC는 6열×4행, 좁은 화면은 4열×3행씩 두 구역. 화살표 이동으로 구역 경계도 이동한다.
- 같은 외형과 조작을 개인전·팀전에서 사용한다. 방향키 선택 → Enter 진입 → 코드표를 보고 변환·복원 → Enter 확인 → 금고 열림과 보상 → 다음 금고.
- 코드표 고정: A=01~Z=26, 숫자 문자 0=27~9=36, 공백=00. 알파벳 순서와 숫자 오름차순. 안전한 보안 암호나 ASCII 표준이라고 설명하지 않는다.
- 기본·강화·복구 금고에 각각 복호화, 암호화, 코드 복구를 배치한다. 복구 금고는 대응 문자 백업 등 충분한 근거를 주며 찍어서 복구하게 하지 않는다.
- 금고 문뿐 아니라 선택 버튼의 가로·세로 비율도 1:1. 해독 중에는 금고실 대신 입력 작업대와 코드표에 집중한다. 긴 규칙은 접어 둔다.

### 개인전: 24개 완주

혼자서 모든 금고를 **직접 열어야** 완주한다. 무작위 공격·자동 열쇠는 사용하지 않는다. 완주 점수와 시간은 기존 문자 코드 생존전 기록과 별도 규칙 버전으로 분리한다.

첫 금고에 진입할 때 전체 시간과 그 금고의 해결 시간이 시작된다. 금고를 닫거나 다른 금고로 이동해도 이미 시작된 시간은 계속 흐른다. 입력 전 문제를 충분히 읽고 시계를 켜는 방식은 허용하지 않는다. 첫 진입 전에는 금고 유형·보상만 보이며 문제 내용은 보이지 않는다.

**금고 점수 = 기본 점수 + 시간 보너스**

`시간 보너스 = 반올림(기본 점수 × 기준 시간 / (기준 시간 + 보정 해결 시간))`

| 금고 | 기본 점수 | 보너스 계산의 기준 시간 |
|---|---|---|
| 기본 | 100 | 20초 |
| 강화 | 200 | 35초 |
| 복구 | 300 | 50초 |

기준 시간은 제한시간이 아니다. 늦어도 게임이 갑자기 끝나지 않으며 해결 시간 증가에 따라 보너스만 점진적으로 줄어든다. 기준 수치는 학생 관찰 후 조정할 제안이다. 기본 금고를 10초에 해결하면 `기본 100 + 보너스 67 = 167점`, 40초면 `100 + 33 = 133점`이다. 입력 중 받을 수 있는 현재 보너스가 보이고, 열 때 실제 산식의 두 항을 짧게 표시한다.

오답을 확정하면 **해당 금고의 보정 해결 시간과 전체 보정 완주 시간에 각각 2초를 반영**한다. 총점에서 또 감점하지 않아 이중 감점을 피한다. 금고별 오답은 그 금고 보너스에만 반영한다. 서버에서는 제출 요청 ID로 중복 오답·중복 보상을 막는다.

순위: **같은 문제 팩·난이도의 24개 완주 기록 → 총점 내림차순 → 동점이면 보정 완주 시간 오름차순(밀리초) → 오답 수 오름차순**. 전부 같으면 공동 순위. 정답 개수만으로 동점이 되지 않는다. 중도 종료는 해결 수·획득 점수를 개인 활동 기록에 남기되 완주 순위에는 넣지 않는다. 시간 측정형 순위는 같은 팩의 보정 완주 시간을 별도로 비교할 수 있다.

과제 순서·문자 길이·암호화/복호화/복원 비율이 다르면 점수를 직접 비교하지 않는다. 정식 기록은 서버가 팩, 최초 공개 시각, 금고별 시작·오답·정답 시각, 보정 시간, 기본/보너스 항, 규칙 버전을 검증해야 한다. 클라이언트가 보낸 최종 점수·시간을 그대로 믿지 않는다. 재접속에도 서버 시작 시각 유지, 중단 후 몰래 재시작 불가. 접근성을 위한 시간 보너스 없는 연습은 별도 비경쟁 모드로 제공할 수 있다.

### 팀전: 3분 쟁탈전

같은 구성의 24개를 각 팀에 제공하고 팀원들이 같은 판을 함께 조작한다. 입력 중인 금고는 담당자 표시·서버 예약으로 중복 작업을 막는다. 3분 또는 한 팀의 24개 완성 시 종료한다. 팀전은 **기본 점수**로 경쟁하고 시간 차이는 더 많은 금고 해결과 자원 운용에서 발생한다. 개인전의 속도 보너스를 그대로 섞지 않는다.

금고에서 동전·아이템 획득. 순서 교란은 패킷의 순서만 바꾸고 원래 자리 번호를 제공한다. 숫자 지우개는 코드 일부를 가리되 대응 문자 백업으로 복구 가능하다. 방어막은 다음 공격 1회 차단, 렌치는 공격만 해제한다. 만능열쇠는 미작업 기본 금고 하나를 50점·동전 1개로 즉시 열고 아이템은 추가 드롭하지 않는다.

입력 중인 상대 금고를 바꾸지 않는다. 공격 중첩·연속 재공격·열쇠 보상 반복을 방지한다. 점수와 소비 동전은 별도. 순위는 팀 점수 → 직접 해결 수 → 공동 순위. 학생 연습 방·봇, 교사 콘솔의 정식 방·팀 편성·현황판, 기존 공용 웹소켓과 REST 대체 전송을 사용하는 독립 게임 어댑터 설계는 이전 문서를 따른다. Code Arena 설치 의존성은 만들지 않는다.

시안의 팀 시점 전환은 효과를 살펴보는 기능이며 실제 상대 입력을 관찰하는 기능이 아니다. 팀원 한 명의 작업 표시 역시 예시다. 팀 규모별 금고·유입량 확장은 실제 인원 관찰 후 결정하며 불필요한 단계 추가로 해결하지 않는다.

## 새 학습 주제 후보 6종

### 패킷 배달부: 네트워크 경로와 혼잡

- 판: 발신 S, 중계 X/Y, 수신 A/B, 링크마다 전송 비용. 패킷의 목적지와 현재 위치를 크게 표시한다.
- 행동: 연결된 다음 지점을 클릭하면 패킷이 그곳으로 이동하고 예산이 정확히 그 링크 비용만큼 줄어든다.
- 도전: 24 전송 예산으로 6개 중 정확한 목적지까지 배달한 수. 잘못 도착하면 배달 +0. 버튼을 많이 누르는 것에는 보상 없음.
- 선택의 의미: 두 경로 모두 배달 가능하지만 혼잡 비용이 패킷마다 바뀐다. 예시 첫 A행은 S-X-A 비용 6, S-Y-A 비용 4. 다음 패킷은 목적지·유리한 경로가 달라진다. 고정 미로 정답 암기가 아니다.
- 기록: 같은 배송 팩의 정확 배달 수 → 남은 예산. 다음 팩은 목적지·링크 혼잡을 바꾼다.
- 개념: 주소를 확인하고 경로를 통해 자료를 전달한다. 전송 비용은 지연·혼잡을 단순화한 게임 자원이며 실제 네트워크 속도 공식이라고 설명하지 않는다.

### 압축 택배: 연속 반복과 무손실 압축

- 판: 원문 문자 띠, 직접 만든 압축 문자열, 상자 용량, 복원된 원문.
- 행동: 연속된 같은 글자의 처음과 끝을 골라 `AAAA → 4A`로 묶는다. 원문·압축 크기와 복원 결과가 함께 바뀐다. 묶음은 다시 풀 수 있다.
- 도전: 5개 택배를 원문과 동일하게 복원 가능하도록 출고하며 절약 바이트를 누적. 글자/숫자 각각 1바이트로 세는 제한된 ASCII 학습 코덱이다. 일반 파일 전체의 바이트 크기를 이 모형으로 설명하지 않는다.
- 선택의 의미: 반복이 긴 구간은 이득이고, `ABABAB...`처럼 반복이 없는 것은 원문 출고가 합리적이며 절약 +0. 단일 문자까지 강제로 묶는 방식은 손해다.
- 기록: 동일 팩 절약 바이트 → 같은 절약이면 완료 시간. 손실 없는 복원 통과가 우선이며 출고 ID 재보상 불가.
- 개념: 크기를 줄이되 정보는 보존한다. 시안은 숫자가 없는 A~Z 원문만 사용하여 횟수 표기와 원문 숫자의 모호성을 피한다. 실제 구현은 명시적인 토큰 스키마·디코더가 필요하다.

### 코어 러시: 병렬 처리와 작업 배치

- 판: 두 코어, 작업별 필요한 틱·마감, 0~8의 현재 시각 축, 실행 중 남은 처리량.
- 행동: 대기 작업 선택 → 빈 코어 배치 → 1틱 실행. 두 코어의 작업이 실제로 동시에 1씩 줄어든다.
- 도전: 8틱 운영에서 마감 전에 끝낸 작업 수. 작업 A(3틱/마감6), B(1/2), C(2/3), D(2/7). B·C 우선 배치는 4개 마감 성공이 가능하나 A·D 우선은 B의 마감을 놓친다.
- 기록: 동일 작업 팩의 마감 성공 수 → 모든 작업 완료 시각. 필요한 틱과 마감이 다음 팩에서 달라져 매번 같은 글자부터 배치할 수 없다.
- 개념: 두 코어에 실행을 분산하고 시간을 겹쳐 쓴다. 시안은 독립 작업·비선점·동일 성능 코어라는 모형이며 실제 운영체제의 모든 제약이나 항상 2배 성능을 주장하지 않는다.

### 댄스봇: 순서와 반복 프로그램

- 판: 로봇 무대, 목표 안무의 박자별 동작, 내 명령 줄, 반복 횟수, 실행 결과.
- 행동: 왼쪽·오른쪽·점프·불빛 명령 추가, 반복 횟수 조정, 재생. 로봇이 실제 순서대로 동작하고 현재 박자가 이동한다.
- 도전: 같은 안무를 적은 명령으로 표현. `[왼쪽, 오른쪽, 점프] × 2`는 6박자를 재현하며 본문 3개+반복 명령 1개로 기록한다. 단순히 줄만 줄여 동작이 틀리면 성공 아님.
- 기록: 정확히 재현한 안무 수 → 동일 안무 팩의 명령 수 합. 이미 해결한 안무 재생은 중복 득점하지 않고 더 짧은 최선 기록만 갱신한다.
- 다음 도전: 반복 단위가 다른 안무와 자유 안무 제작. 승인 후 변수·중첩 반복 등 확장을 별도 검토하되 처음부터 용어 설명문을 길게 붙이지 않는다.
- 개념: 반복이 어떤 명령 묶음을 몇 번 실행하는지 실행 추적으로 확인한다. 고정 경로의 미로 도착이 목표가 아니다.

### 보물 책장: 정렬된 자료의 이진 탐색

- 판: 번호가 작은 것부터 큰 것까지 정렬된 닫힌 책 32권. 값은 불규칙하게 증가하며 위치 번호와 실제 값은 다르다.
- 행동: 책 하나를 열어 목표와 비교. 작으면 왼쪽, 크면 오른쪽 후보가 즉시 사라져 남은 범위가 보인다.
- 도전: 새 배열에서 보물 3개를 적은 조회로 찾기. 이미 조회했거나 제외한 위치는 다시 조회·보상하지 않는다.
- 기록: 동일 탐색 팩의 3개 완수 → 조회 수 오름차순 → 시간. 1~32 순서값을 그대로 보여 목표값으로 위치를 계산하는 허점을 피한다.
- 개념: 정렬 때문에 절반을 제외할 수 있고 중간값 조회가 남은 범위를 효율적으로 줄인다. 단순 운의 번호 맞히기로 설명하지 않는다.

### 공개 전 점검: 목적에 맞는 개인정보 최소 공개

- 판: 가상 게시물 편집과 받는 사람 미리보기. 공개 대상과 목적을 짧고 명확하게 제시한다.
- 행동: 정보 항목에 가림 스티커를 붙이거나 떼면 수신 화면이 즉시 바뀐다. 되돌리기 가능.
- 도전: 목적상 필요한 안내를 유지하고 비공개 정보는 모두 감춘 게시물 완성. 전체를 가리면 필수 안내 누락으로 +0, 아무것도 가리지 않으면 노출로 +0.
- 선택의 의미: 전체 공개 행사 안내와 학급 내부 과제 안내의 필요한 정보가 다르다. 다음 게시물은 위치·허용 항목·목적이 바뀐다. 이름을 무조건 숨겨야 한다는 식의 잘못된 일반화를 피한다.
- 기록: 동일 팩의 안전하고 유용한 게시물 수. 시안은 연습용 되돌리기를 허용하며 실수로 실제 게시되지 않는다. 경쟁 모드의 제한 횟수·시간은 승인 전 확정하지 않는다.
- 개념: 정보의 의미, 목적, 수신 범위를 함께 판단한다. 개인 정보는 모두 가짜이며 법률 자문이나 실제 게시 기능이 아니다.

## 다시 버려야 하는 신호

시안으로 동작·채점 관계는 검사하되 학생 흥미 검증과 구분한다. 실제 학생이 이진수·장치 카드·키워드 레인·초기 픽셀을 재미있어 했다는 기존 관찰을 기준으로 삼는다.

1. 첫 화면에서 목적지·상자·코어·안무·책·게시물 중 무엇을 만져야 하는지 말로 설명해 줘야만 알 수 있으면 다시 그린다.
2. 같은 버튼·같은 위치·같은 순서를 무조건 반복해 최선 기록을 얻으면 데이터를 추가하기 전에 규칙을 버린다.
3. 정답 확인 문장만 바뀌고 실제 판의 대상이 변하지 않으면 실패다.
4. 기록 상승 원인을 학생이 “배달 하나”, “2바이트 절약”, “마감 성공”, “명령 2개 절약”, “조회 절약”, “노출 없이 안내”처럼 설명할 수 없으면 보상을 단순화한다.
5. 한 번 성공한 뒤 더 해 볼 이유가 없으면 팩 경쟁·만들기·선택 비용을 확인한다. 타이머와 단계만 붙여 게임성 있다고 평가하지 않는다.

확인 후 선택한 주제만 운영 모듈로 구현한다. 기존 게임과 다른 학습 목표이므로 게임 ID·규칙 버전·공개 설정·순위를 독립시켜야 하며 학생 결과를 묵시적으로 덮어쓰지 않는다.
