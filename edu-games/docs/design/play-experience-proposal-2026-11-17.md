# Edu Games: 전체 플레이 경험·화면 제안

2026-11-17. **사용자 확인 전 설계안**이다. 운영 플러그인, 개인전 규칙, 채점, DB, 순위, 공개 설정, 웹소켓 서버를 변경하지 않는다. 화면 시안은 일부 사례를 조작해 보는 설계 예시이며 완성 게임·실제 팀 접속·학생 흥미 검증 결과가 아니다.

후속 결정: [주제 교체와 암호 금고 개인전·팀전](play-topic-reset-2026-11-17.md)을 우선한다. 아래 사건 파일·신호 작업대·그래프 수리공·추출 공장·블록매치·경계 탐사 **6종은 철회한 이전 후보**다. 금고는 정사각형 24개와 새 개인 완주전·팀전으로 재설계했다. 아래 12개 금고·개인 생존 규칙 유지 항목은 이전 제안 기록이며 최신안으로 구현하지 않는다.

## 기준과 변경 범위

- 이전 `play-interface-directions`의 금고, 직접 조작 작업대, 첫 행동 안내를 출발점으로 삼는다. 제안 화면과 실제 플러그인 적용을 구분한다.
- 이진수, 장치 카드, 키워드 레인, 코드 타이핑, AI 모델 훈련소의 핵심 규칙은 유지한다. 초기 이미지의 자유 창작·행별 코드 복원도 유지한다. 새로운 개인 게임 형식은 후보이며 확인 후 구현한다.
- 코드표는 A=01~Z=26, 숫자 문자 0=27~9=36, 공백=00으로 고정한다. 공격 아이템도 표 자체를 섞거나 대응값을 바꾸지 않는다.
- 금고는 놀이의 목표물이다. 사용하는 표는 학습용 문자 대응 모형이며 ASCII·유니코드 표준이나 안전한 보안 암호라고 설명하지 않는다.
- 암호 도미노, 이미지 슬라이딩, 이상치의 이동 범위 밖 체크, 고정 두 칸 반복 짝찾기, 개념과 무관한 연결 4를 재사용하지 않는다.
- 공통 요소는 허브·설정·종료 위치, 기본 글꼴, 아이콘, 피드백 문법뿐이다. 게임판·주된 행동·종료·기록은 게임에 맞게 다르게 한다.
- 보상은 실제 처리 결과로 계산한다. 버튼 클릭 자체에는 점수를 주지 않는다. 정답을 자동 공개하는 조사 버튼이나 보상 반복 수령을 허용하지 않는다.

## 문자 코드 팀전 상세

### 판과 조작

두 팀은 같은 난도·보상 구성의 **독립된 금고 구역**을 갖고, 팀원들은 자기 팀 구역의 같은 금고들을 함께 조작한다. 상대 미니맵에는 잠김·작업 중·열림·공격 상태만 보이며 정답·입력 내용은 공개하지 않는다. 시안의 시점 전환은 효과 비교용이지 실제 학생 기능이 아니다.

- 기본 4열×3행, 12개 금고. 많은 팀원은 금고 수를 늘리고 같은 보상 비율을 유지한다.
- 방향키로 선택 이동 → Enter로 금고 조작 → 원문 또는 코드 입력 → Enter로 확인 → 성공 연출·보상 → 이동 재개. Esc는 작업 취소이며 정답 공개·보상 없음.
- PC 키보드 조작과 터치 선택을 함께 지원한다. 입력 중 방향키는 커서 편집에 쓰고 게임판 이동으로 해석하지 않는다.
- 팀원이 작업하는 금고는 담당자 표시와 짧은 갱신 잠금으로 중복 작업을 막는다. 연결 종료·취소·유효시간 만료 시 반납한다. 한 팀원이 모든 금고를 예약하지 못한다.
- 금고는 복호화·암호화·표 복원 세 유형이며 난도와 보상을 선택 전에 표시한다. 열린 금고는 같은 ID로 다시 득점하지 못한다. 새 금고는 다른 과제로 보충한다.
- 개인전의 오답 즉시 종료는 팀전에 강요하지 않는다. 팀전은 오답 확정 시 해당 작업만 제안 2초 잠기고 재시도한다. 전체 팀은 제한시간까지 계속한다.

### 보상과 승패

제안 수치는 균형 조정용이며 기존 개인전 산식 변경이 아니다.

| 금고 | 직접 해결 보상 | 선택 이유 |
|---|---|---|
| 기본 | 100점·동전 2개 | 짧은 변환으로 빠르게 자원 확보 |
| 강화 | 200점·동전 3개 | 긴 통신·암호화 등 더 많은 실제 입력 |
| 복구 | 300점·동전 4개 | 빈 코드 대응을 먼저 복원한 뒤 전체 변환 |

점수는 승패용, 동전은 아이템 구매용으로 분리한다. 아이템을 샀다고 이미 얻은 승리 점수가 줄지 않는다. 시안의 가격은 순서 교란 3개, 숫자 지우개 4개, 만능열쇠 5개, 방어막·복구 렌치 각 2개다. 가격·재사용 대기·기본 재고는 판 시작 전에 공개하며 이 수치는 균형 조정 전 제안이다. 교사 설정으로 아이템 없는 협력 연습도 가능하며 순위는 규칙별로 분리한다.

3분 종료 시 점수 높은 팀 승리, 동률은 **아이템이 아닌 직접 해결 금고 수**, 둘 다 같으면 공동 순위다. 불투명한 보너스로 승패를 뒤집지 않는다. 난도별 금고와 아이템 드롭은 팀 간 같은 구성의 서버 시드·유한 보상 주머니를 사용해 운빨 격차를 줄인다.

### 아이템 제안

| 아이템 | 대상·효과 | 개념·공정성 조건 |
|---|---|---|
| 순서 교란 | 상대의 미작업 금고 코드 패킷 순서를 섞음 | 코드표와 대응값은 고정. 패킷에 원래 자리 번호를 남겨 **순서 복구 후 복호화** 가능. 원문 순서를 무작위 정답으로 바꾸지 않음 |
| 숫자 지우개 | 상대 금고 코드 1~2개를 가림 | 대응 문자 백업·같은 문자의 다른 기록 등 충분한 근거를 제공. **코드 복원 후 전체 메시지 해독**. 근거 없는 찍기 금지 |
| 만능열쇠 | 자기 팀의 미작업 기본 금고 하나를 즉시 엶 | 50점·동전 1개, 아이템 추가 드롭 없음. 강화·복구 금고에는 불가. 직접 해결 수에 포함하지 않아 학습을 우회한 독점 전략을 제한 |
| 방어막 | 자기 팀 다음 공격 1회 차단 | 공격 차단이 화면에 표시됨. 지속 무적·자기 공격으로 재보상 없음 |
| 복구 렌치 | 자기 팀 금고의 순서 교란/코드 가림 해제 | 공격 해제만 하며 원문 정답을 자동 입력하지 않음. 기존 입력 보존 |

공격은 시작한 금고의 입력을 갑자기 바꾸지 않는다. 다음 미작업 금고를 대상으로 적용하고, 작업 중인 것만 남았다면 적용 대기 또는 취소한다. 금고 하나에는 공격 하나, 공격 종류·복구 방법·남은 상태를 명확히 표시한다. 같은 금고를 무한 공격하지 못하도록 제안 10초 재공격 보호를 둔다. 제한된 아이템 비용은 시안에서 확정하지 않는다.

### 방·운영·기록

기존 팀 운영 계약을 확장하는 제안이며 Code Arena 설치에 의존하지 않는다. 학생은 봇 포함 연습 방, 교사는 콘솔에서 정식 방·팀 수/인원·수동/랜덤 팀 배정·현황판·아이템 설정을 관리한다. 대기실에는 준비·연결·담당 금고가 표시된다. 방 재접속 시 서버 판을 복원하고, 비어 있는 연습 방 정리와 완료 방 결과 보존을 구분한다.

웹소켓은 기존 공용 서버의 `edu-games` 범용 방·채널에 새 게임 어댑터를 등록하는 방향이다. 점수·금고 생성·작업 잠금·아이템 소비/효과·종료는 서버가 판정하고 클라이언트는 의도만 보낸다. 요청 ID·버전으로 재전송 중복 보상을 막는다. REST 대체 전송과 연결 상태 표시, 게임/규칙 버전/팀 인원별 결과 분리도 필요하다. 현재 서버·API는 수정하지 않는다.

## 화면에서 확인할 기준

1. 금고·픽셀·기록 띠·차트·관문·저장대 등 실제 대상이 첫 화면의 중심인가.
2. 첫 조작 뒤 데이터와 목표물이 같이 바뀌는가. '정답입니다' 문장만으로 대체하지 않았는가.
3. 득점은 무엇을 해결했는지 바로 설명되는가. 오차·수정 수·수집 작품처럼 게임에 맞는 기록을 사용하는가.
4. 같은 위치·같은 방법·같은 조건·같은 표본만 반복하는 정책이 항상 최선이 되지 않는가.
5. 코드표·그래프 축·색상 행·장치 사진·오타 위치가 작아지거나 잘리지 않는가.
6. 수행평가는 **공개 평가 수 + 미응시 상태 + 버튼형 입구**로 작게 강조하고, 목록은 선택 시에만 확장하는가.

이번 시안으로 확인 가능한 것은 조작 이해와 화면·보상 흐름이다. 중학생의 자발적인 재도전·흥미·학습 효과는 새로 확인된 사실로 주장하지 않는다. 시안 확인 후 선택된 형식만 실제 엔진으로 구현한다.

결측값의 첫 복원 결과를 공개한 뒤에는 해당 기록을 고쳐 경쟁 기록으로 바꿀 수 없다. 새로운 자료에서 다시 도전한다. 최빈값이 하나로 정해지지 않거나 시간 순서가 없는 자료, 0/1 상태에 중간 실수를 넣는 등 부적절한 도구 적용은 숫자를 임의로 만들어 채점하지 않고 근거 부족·적용 불가로 표시한다.
