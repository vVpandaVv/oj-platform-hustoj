# Edu Games 1.0 정식 출시 보강 계획

작성일: 2026-09-12. 최초 기준: `0.1.19`. 구현 반영: **소스 1.0.0, 운영 배포 전**.

## 구현 반영 요약

사용자 요청에 따라 새 개발 단계나 검증 게이트를 추가하지 않고 아래 기능을 구현했다. 아래의 P0/P1·출시 게이트는 최초 계획의 참고 기록이며, 이번 작업에서 모든 운영 인수 항목을 완료했다는 뜻은 아니다.

- R05/Q03: 서버 페이지네이션을 전체·팀·게임 내·보드·개념 평가 순위에 연결했다. 페이지당 20/50/100개만 반환하며 전체 순위·공동 순위·팀 전체 평균을 보존한다. 오류 재시도와 오래된 응답 무시를 제공한다.
- Q01: 도감·타이핑 연습·카드 목표를 계정에 저장하고 아케이드 최고점을 서버에서 읽는다. 항목 합집합/최고값/최소 실수로 병합하며 이전 기기 기록은 자동 업로드하지 않는다. 연습 세션의 연속 횟수는 개인 목표이지 검증된 경쟁 점수가 아니다.
- R03/Q02: 기존 공개 학급·명단 API를 사용한 `/oj-console/addons/edu-games/report`를 추가했다. 허용된 명단에서 미참여·완료·완주·별·최고점·개념 첫 답/수정 후를 구분하고 페이지·게임·기간을 선택한다.
- R02: 최고 기록 조회 인덱스를 추가하고 오래된 AI 프로토타입 테이블을 삭제 대신 이름을 바꿔 보존한다. 기존 시즌·규칙·점수를 변경하지 않는다.
- Q05: 실제 동작, 동기화 정책, 권한, 업데이트·보관 주의사항을 README에 정리했다.

변경 범위 검사: 순위 브라우저 155항목과 공통 페이지네이션 108항목, 새 기능 PHP 43항목 및 브라우저 14항목, 기존 회귀·Addon 자산 검사. 격리된 데이터/SQLite와 로컬 플랫폼 DTO를 사용했다. 실제 WordPress/MySQL 설치·동시 수업 부하·교사 콘텐츠 파일럿은 이번에 수행하지 않았다. R04의 전 아케이드 서버 출제·행동 증거 검증은 포함하지 않으며 기존 범위 검증의 한계를 유지한다. 신규 게임·시즌 추가, 별도 RC 단계, 추가 검증 캠페인은 만들지 않았다.

## 1. 출시 목표와 범위

학생 30명이 한 수업에서 안정적으로 사용하고, 6개 이상 반의 기록을 권한에 맞게 구분하며, 재접속해도 자신의 도전을 이어갈 수 있는 교육 게임 패키지를 목표로 한다. 새 게임 수보다 현재 13종의 학습 타당성·게임성·기록 신뢰성을 먼저 보장한다.

- 1.0 대상: 기존 13종, 게임 허브·공개 설정·블록·숏코드·플랫폼 페이지, 순위·통계, 기본 교사 학급 조회.
- 콘텐츠 기준선: 자료구조 12구역, 데이터·AI 6종 84보드/별 252개, 보충 개념 활동 303문항, 이미지 45개, 장치 38종. 세부 내역은 [전체 보드 구현](content-review/strategy-full-release-2026-09.md), [게임성 개편](content-review/gameplay-redesign-2026-09.md)을 따른다.
- 게임 성취와 개념 평가를 분리한다. 점수는 같은 게임·모드·보드·규칙 버전에서만 비교한다. 타이핑 검정은 연습용 수행 기록이며 공인 자격이나 부정행위 방지 시험으로 소개하지 않는다.
- 실시간 다인전, 새 분야 게임, 무한 자동 생성 보드, 전면적인 디자인 교체는 1.0 필수 범위에서 제외한다.

### 이번 페이지네이션의 동작과 한계

- 기본 20명, 50명·100명 선택, 처음·이전·다음·마지막 이동, 현재 페이지와 전체 인원을 제공한다. 팀 순위의 단위는 팀이다.
- 게임 전체·팀 전체·팀 내부·게임 내 순위·전략/물류 보드·개념 평가 순위에 적용한다. 개인 플레이 이력은 이번 대상이 아니다.
- 실제 순위와 공동 순위를 유지한다. 게임·팀·보드 변경 시 첫 페이지로 돌아가고, 같은 목록 갱신 시 가능한 페이지를 유지한다. 개념 평가 보고서는 새로 구성할 때 첫 페이지로 열린다.
- **1.0 화면은 서버가 해당 페이지의 행만 반환한다.** `limit=0` API는 이전 연동을 위한 호환 경로로 유지한다. 180명 페이지 경계를 격리 환경에서 확인했으며 실제 동시 접속 성능을 측정한 것은 아니다.
- 0.1.18 설치 ZIP은 이전 산출물로 보존한다. 1.0 소스로 덮어쓰지 않았으며 운영 배포도 수행하지 않았다.

R03의 반 명단 계약이 제공되지 않으면 플랫폼 내부 DB를 직접 조회해 우회하지 않는다. 필요한 공개 계약을 먼저 확정하고, 학급 운영을 포함한 1.0 승인을 보류한다.

R05는 6개 반 × 30명(180명)의 계정과 누적 기록으로 준비한다. 최소 30명 동시 플레이·동시 저장·순위 새로고침을 실측한다. 6개 반의 동시 수업까지 지원한다고 발표하려면 180명 동시 시나리오도 통과해야 한다. 교실의 공용 IP 하나를 학생 한 명처럼 제한하지 않는다.

부하 인수 목표 초안은 저장/순위 API p95 1초 이내, p99 3초 이내, 예상하지 못한 서버 오류율 0.5% 미만이다. **아직 측정 결과가 아니다.** 시험 서버 사양·데이터량·실행 시간·요청 분포를 고정하고 학교 환경에 맞는 최종 기준을 합의한다. 기록 손실·중복 확정 저장·권한 누출은 0건이어야 한다.

학생 파일럿은 서로 다른 숙련도의 학생이 같은 판을 두 번 수행하도록 하고 선택 이유·실패 원인·다음 목표를 설명할 수 있는지 관찰한다. 암호 시간 하한, 타이핑 목표, 카드 사진 인식과 보드 예산은 교사 승인 전에 고정하지 않는다. 규칙을 바꾸면 콘텐츠 버전을 올려 기존 점수와 분리한다.

## 6. 진행 순서와 출시 게이트

1. **기준선 동결**: 13종/버전/지원 환경/공개 범위를 확정하고 재현 가능한 패키지·테스트 결과를 보관한다. 개발 브랜치와 출시 후보를 구분한다.
2. **기록·권한·성능**: R01~R05와 Q01~Q03 구현. 실제 DB 통합 검사 및 페이지 경계·공동 순위·180명/팀원 전체 평균 회귀 추가.
3. **콘텐츠·조작**: R06~R07, Q04~Q05. 교사 전 게임 검수 후 학생 파일럿으로 시간·예산·표현 조정. 변경한 판의 해법·회귀 재검증.
4. **베타 수업**: 최소 한 반 30명 실습 후 6개 반 기록 분리, 기기 변경·재접속 시나리오 수행. 운영 부하 기준과 장애 대응 확인.
5. **1.0.0-rc 후보**: 기능 추가 중단, 치명/중대 오류 해소. 새 설치·0.1.18 및 기존 지원 버전 업그레이드·복구 리허설, 패키지/버전/해시 검사 후 교사·운영자 승인.
6. **1.0.0 발표**: 승인된 소스에서 ZIP 생성. 변경 내역·지원 환경·알려진 한계·업데이트/복구 절차·체크섬 제공. 자동 배포는 별도 승인 없이 실행하지 않음.

각 게이트의 증거는 비식별 검수표, 테스트 명령/결과, DB 비교, 부하 로그, 화면 캡처, 패키지 매니페스트로 남긴다. `tests/`의 PHP/브라우저 대역 검사를 실제 WordPress나 실제 학생 사용 결과로 대신 표시하지 않는다.

## 7. 배포·복구 원칙

- 업데이트 직전 DB와 업로드/플러그인 파일을 백업하고 복구 가능성을 확인한다. 실습이 없는 시간에 적용한다.
- 스키마 변경은 기존 버전의 읽기 호환을 우선한다. 비호환 변경은 쓰기를 중지한 뒤 검증된 복구 절차를 따른다. 운영 기록이 생긴 뒤 ZIP만 이전 버전으로 바꾸는 것을 완전한 복구로 간주하지 않는다.
- 소수 시험 계정으로 정상 저장과 반 권한을 확인한 뒤 수업을 연다. 불확실한 저장 오류가 있으면 점수 쓰기를 중지하고 로그와 기록을 보존한다.
- 일정·반 배정·운영 서버 변경은 담당자 승인 후 확정한다. 이 문서는 구현이나 배포를 승인·완료했다는 기록이 아니다.

## 8. 1.0 이후

안정화 이후 시즌별 새 보드, 교사용 과제 편성, 성취 요소별 보고서 확장, 협력/대전 모드를 별도로 설계한다. 새 시즌은 숫자만 늘리기보다 다른 의사결정과 전략을 추가하며 기존 시즌 기록 조회를 유지한다.
