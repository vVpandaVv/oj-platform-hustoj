# 일곱 학습 게임 재설계

작성: 2026-09-13. 상태: 게임별 두 상황의 핵심 플레이 구현 완료. 아래의 확장 항목 전체를 구현한 것은 아니다.

대상은 이상치, 결측값 처리, 데이터 시각화, 데이터 추출, 자료구조 운용, AI 분류 경계, AI 모델 훈련소다. 기존 문서의 제안에 따라 별도 play 모드와 일곱 기본 화면을 구현했다. 기존 기록은 삭제하지 않고 새 시즌과 분리했다. 정확한 현재 규칙, 초기 범위와 남겨 둔 확장 항목은 [구현 현황](seven-games-play.md)을 기준으로 확인한다. 아래의 최초 설계에 나오는 수량과 판 길이를 모두 구현·검증한 것은 아니다.

## 1. 무엇이 잘못됐는가

현재 게임은 학습 내용을 화면에 표시하지만, 그 내용을 이해하는 것과 재미있는 선택을 하는 것이 충분히 연결되지 않는다. 비용을 올리고 정답 확인을 늦춰도 동일한 순서를 반복하면 되는 문제는 남는다. 최근 이상치의 첫 선택 채점과 재측정 제한도 우회 방지이지 완성된 게임성 개편은 아니다.

| 현재 게임 | 실제 구조에서 발견한 한계 | 새 설계에서 버리는 것 |
| --- | --- | --- |
| 이상치 | 후보 선택 뒤 기록별 증거 구매와 처리 선택. 판마다 같은 조사 절차로 수렴하기 쉬움 | 기록마다 정답 근거를 열고 세 구역 중 하나를 누르는 주 게임 |
| 결측값 | 설명이 선형 변화·급변·상태 전환을 알려주고 세 노드의 도구를 매일 선택함 | 빈칸마다 지정 도구를 골라 실제 값과 일치시키는 채점 |
| 시각화 | 제공된 값을 칸·좌표에 옮기고 정해진 차트 조건을 맞춤 | 이미 알고 있는 좌표에 점을 하나씩 찍는 반복 작업 |
| 추출 | 고정 주문에 필터·열 선택·정렬을 매번 실행함 | 원자료 입고부터 출고까지 정해진 명령 순서를 재입력 |
| 자료구조 | 실제 LIFO/FIFO 제약은 있으나 고정 문자 순열의 입출고에 경험이 한정됨 | 같은 종류의 순서 맞추기만 늘리는 캠페인 |
| 분류 경계 | 알려진 점에 경계를 배치하고 검증 수치를 확인함 | 경계 숫자 조정과 검증 버튼을 반복하는 주 게임 |
| AI 모델 | 세 자료 묶음과 모델 조합을 골라 집계 지표를 확인함 | 어느 표본을 배웠는지 보이지 않는 패키지 구매와 모델 고르기 |

분석 근거: 각 모듈의 Strategy_Board.php, 자료구조의 Warehouse_Board.php, 현재 board-views.js 및 이전 개편 문서. 구현 상태에 대한 분석이며 실제 학생 대상 관찰 결과는 아니다.

## 2. 공통 설계 원칙

- 학습 내용이 게임의 작동 규칙이어야 한다. 정답 뒤에 이동 애니메이션을 붙이는 방식은 제외한다.
- 한 번의 선택은 이후 상태에 남는다. 설치한 처리망, 탐색 대기열, 수집한 표본, 복구한 센서가 다음 상황을 바꾼다.
- 반복 실행은 시스템이 담당한다. 학생은 경로·정책·표본·표현을 결정한다.
- 결과는 숫자 감점보다 먼저 세계에 나타난다. 상자가 잘못 배송되거나 길이 막히거나 로봇이 특정 표본을 계속 놓치는 장면이 필요하다.
- 전문가 용어를 외워야 조작할 수 있게 만들지 않는다. 행동 결과와 함께 정확한 용어를 연결한다.
- 탐구 중 배치·확대·비교는 자유롭게 한다. 비용은 실제 출동, 생산, 탐색, 시험 운영처럼 게임 안의 행동에 붙인다.
- 사고 시간에 점수를 매기지 않는다. 아래의 시간·파동·주기는 학생이 실행하는 시뮬레이션 시간이다. 애니메이션 속도나 네트워크 지연은 기록과 무관하다.
- 실패해도 현재 판과 원인, 직전 선택의 영향을 남긴다. 연습 재시도와 최초 도전 기록은 구분한다.
- 일곱 게임에 같은 1,000점 감점식을 강제하지 않는다. 주 목표 달성 여부가 먼저이며 각 게임의 성능 지표로 기록을 비교한다.

## 3. 서로 다른 일곱 가지 플레이

| 분야 | 새 게임 | 주된 게임 형식 | 학생의 핵심 행동 |
| --- | --- | --- | --- |
| 이상치 | 관측 지도 수비대 | 공간 추리·원인 복구 | 비교 집단을 구성하고 이상 현상의 원인을 추적해 관측망을 복구 |
| 결측값 | 빈 지도 탐험대 | 불완전 정보 탐험·경로 계획 | 추정 가능한 구간과 확인할 구간을 나누어 이동 계획 수립 |
| 시각화 | 차트로 지휘하는 항구 | 정보 비대칭 협력 | 차트로 전달하고 그 차트를 근거로 배를 배치 |
| 추출 | 데이터 자동 분류 공장 | 연결망 제작·자동화 | 처리기를 연결해 새 데이터까지 처리하는 생산선 구성 |
| 자료구조 | 미로 탐색 엔진 | 탐색·메모리 퍼즐 | 스택·큐·우선순위 큐로 다음 탐색 순서를 운영 |
| 분류 경계 | 분류 게이트 디펜스 | 영역 설계·파동 방어 | 경계를 설치하고 연속 유입 자료의 자동 분류 결과 관찰 |
| AI 모델 | 표본 덱으로 키우는 로봇 | 덱 구성·실험 | 실제 학습 표본을 선택·검수·교체해 로봇의 행동 개선 |

### 3.1 이상치: 관측 지도 수비대

**게임판**

작은 지역 지도에 관측소 6개와 짧은 시간 그래프가 놓인다. 지도의 실제 환경과 센서가 보고하는 값은 별개다. 평소와 다른 현상에는 실제 환경 변화와 기록·센서 문제가 섞인다. 비교 자료는 같은 장치·같은 지역·같은 시간 등 출처를 구분해 제공한다.

**핵심 행동**

학생이 지도에서 관측소를 묶으면 해당 집단의 분포와 시간 변화가 겹쳐 보인다. 개별 값의 정답을 여는 대신 주변 관측, 이전 구간, 원본 단위를 비교한다. 조치 도구는 특정 출처에 대한 단위 변환, 센서 교체, 비교 집단 분리, 불확실한 보고의 보류다. 조치는 이후 그 출처에서 들어오는 자료에도 적용된다.

비교 자체는 자유롭다. 현장 점검은 한 기록의 정답을 주는 버튼이 아니라 일정 지역의 독립 관측을 얻는 출동이며, 도착까지 운영 주기가 흐른다. 점검 결과에도 측정 시각과 범위가 있어 모든 의문을 동시에 해결하지 않는다.

**한 장면**

세 관측소가 함께 더워지고 하나의 장치만 86을 보고한다. 서로 다른 단위의 자료를 합친 문제라면 해당 출처에 변환을 적용해야 한다. 실제 고온 지역을 통째로 지우면 지도의 중요한 현상이 사라진다. 반대로 장치 문제를 고치지 않으면 다음 주기에도 잘못된 보고가 쌓인다. 학생은 값 하나를 제외하는 대신 원인을 찾아 다음 보고를 정상화한다.

**게임의 목표**

정해진 운영 기간 동안 실제 환경 변화가 지도에 남고, 잘못된 보고로 인한 불필요한 대응이 한도를 넘지 않으면 성공한다. 기록은 중요한 실제 현상의 보존, 잘못된 보고의 차단, 점검 자원 순으로 비교한다. 모든 값을 지우거나 경고를 꺼도 성공할 수 없다.

**학습과 게임이 연결되는 지점**

이상치는 비교 기준과 맥락에 따라 달라진다. 실제 현상과 자료 오류를 구별해야 관측망이 작동한다. 통계적 후보 표시가 자동 삭제 명령이 되어서는 안 된다.

**반복 전략의 반례**

장치 하나의 오류와 지역 전체의 실제 변화가 겉보기에는 비슷하지만 필요한 조치가 달라야 한다. 다만 혼자 튀는 값이 언제나 고장이고 함께 튀면 언제나 정상이라는 새 암기 규칙도 만들지 않는다. 판단할 자료가 부족한 사건에는 합리적인 보류·추가 관측 경로가 있어야 한다.

**첫 제작 범위**

한 지도와 두 대조 사건으로 시작한다. 출처의 단위 오류를 복구하는 사건과 실제 국지 현상을 보존하는 사건이다. 기존의 값·단위·출처 사례는 재사용할 수 있지만 기록별 세 구역 선택 화면은 주 게임에서 뺀다.

### 3.2 결측값: 빈 지도 탐험대

**게임판**

관측이 일부 끊긴 지도와 보급 차량이 등장한다. 지점별 수심·경사·노면 상태 중 이번 임무에 필요한 한두 속성이 있다. 확인된 값, 추정 범위, 알 수 없는 구간을 서로 다른 모양으로 표시한다. 최초에는 지도에 작은 갈림길 하나만 둔다.

**핵심 행동**

학생은 도착해야 할 곳까지 경로를 그린다. 결측 구간을 지나려면 같은 조건의 앞뒤 기록을 연결하거나 관련 관측을 묶어 추정 범위를 만들 수 있다. 현장 탐사에 차량·드론을 보내거나, 모르는 채로 남겨 두고 알려진 길로 우회하는 선택도 가능하다. 추정은 숫자 한 칸 채우기가 아니라 이용 가능한 경로와 계획의 여유를 바꾼다.

**한 장면**

완만하게 변하는 구간에는 앞뒤 관측으로 예상 가능한 범위가 있지만, 지형 경계 너머의 빈 구간에는 같은 방식이 통하지 않는다. 무조건 평균을 넣어 가까운 길로 가면 이동 계획이 어긋날 수 있다. 모든 곳을 직접 조사하면 탐사 비용 때문에 보급량이 줄어든다. 우회는 확실하지만 이동 거리가 늘어난다.

**게임의 목표**

제한된 이동·탐사 자원으로 필요한 보급을 마치면 성공한다. 기록은 완료한 임무, 보급 손실, 소모 자원으로 비교한다. 정확한 숨은 숫자를 맞힌 개수가 주 점수가 아니다.

**학습과 게임이 연결되는 지점**

결측값은 0이 아니다. 추정과 실측은 다르며, 다른 집단의 자료를 가져오거나 범주형 상태를 수치 평균으로 채우면 계획의 근거가 무너진다. 값을 채우지 않는 결정도 합리적일 수 있다.

**반복 전략의 반례**

항상 보간하기, 항상 직접 조사하기, 전부 미확정으로 두기가 각각 불리한 지도를 마련한다. 같은 지도에도 안전한 우회와 필요한 곳만 조사하는 복수 해법을 허용한다. 자료로 알 수 없는 숨은 값 하나를 운 좋게 맞혔다고 최고 숙련으로 평가하지 않는다.

**첫 제작 범위**

한 갈림길에서 추정이 유효한 지도와 조건이 끊기는 지도만 만든다. 원래 지형의 실제 값은 학생이 대체값을 입력한다고 바뀌지 않는다. 추정 방법을 바꾸면 정보와 이동 계획이 바뀌는 것이지 세계 자체가 복구되는 것은 아니다.

### 3.3 데이터 시각화: 차트로 지휘하는 항구

**게임판과 역할**

관측 담당은 여러 항구의 기간별 주문 자료를 보고, 운항 담당은 선박과 제한된 운항 슬롯을 본다. 관측 담당의 원자료는 운항 담당에게 보이지 않고, 보낸 차트만 공유된다. 두 사람은 하나의 항구 운영 결과를 함께 만든다.

2인 협력을 권장한다. 처음부터 네트워크 다인전을 요구하지 않고 한 기기 역할 교대로 핵심 규칙을 만들 수 있다. 역할 교대 연습은 이미 본 정보를 기억할 수 있으므로 정보 비대칭을 검증하는 본 게임 기록과 동일하게 취급하지 않는다. 1인에게 원자료와 차트를 모두 보여주고 같은 협력 경험이라고 주장하지 않는다.

**핵심 행동**

관측 담당은 비교할 항구, 시간 범위, 집계 단위와 표현 방식을 정해 차트 두 장 안에 정보를 구성한다. 차트의 실제 점·막대는 데이터에서 자동 생성한다. 운항 담당은 차트를 보고 선박의 목적지·방문 순서·적재량을 배치한다. 실행하면 납품, 적체, 빈 운항이 항구에 나타난다.

**한 장면**

기간 합계는 같아도 한 항구는 특정 날에 주문이 몰리고 다른 항구는 고르게 주문한다. 합계만 전달하면 배가 필요한 날을 놓칠 수 있다. 일별 변화와 항구별 양을 나눠 표현하면 실제 운항 계획이 달라진다. 상대가 원자료를 보지 않아도 일을 할 수 있어야 차트가 제 역할을 한 것이다.

**게임의 목표**

정해진 운항 기간에 두 사람이 납품 목표를 달성하면 성공한다. 결과는 공동 납품량과 적체·빈 운항으로 남긴다. 역할별로 만든 차트와 운항 판단도 남기되 상대의 실수만으로 개인의 시각화 능력을 단정하지 않는다.

**학습과 게임이 연결되는 지점**

시각화는 예쁜 그림이나 차트 이름 맞히기가 아니라 다른 사람이 비교·추세·분포를 읽도록 하는 표현이다. 축·단위·집계와 범례가 실제 판단에 영향을 준다.

**반복 전략의 반례**

언제나 합계 막대 하나만 보내는 전략과 모든 상황에 원그래프를 쓰는 전략으로 서로 다른 운항 목표를 해결할 수 없어야 한다. 차트 종류의 정답을 하나로 고정하지는 않는다. 같은 정보를 충실하게 전달하는 여러 구성은 인정한다.

**첫 제작 범위**

항구 3곳, 선박 2대, 합계는 비슷하지만 주문 시점이 다른 두 운항표로 시작한다. 축·단위·값의 정합성은 시스템이 보장하고, 무엇을 묶고 보여줄지는 학생이 결정한다. 정답 문장이나 원자료 표 전체를 별도 메시지로 보내는 것은 이 게임의 전달 수단에서 제외한다. 무작위로 오해하는 가상 독자를 만들어 차트에 임의 감점을 주지 않는다.

### 3.4 데이터 추출: 데이터 자동 분류 공장

**게임판**

입력 구역, 처리기를 놓는 격자, 여러 고객의 출력 구역이 있다. 자료 카드는 이름·분류·값처럼 실제 속성을 가진다. 작은 미리보기 묶음과 다음 주문 조건을 볼 수 있다.

**핵심 행동**

필터·분기·필요 열 선택·집계 처리기를 연결한다. 가동하면 새 자료가 생산선에 흘러 들어가고 자동으로 여러 주문을 채운다. 학생은 자료를 한 건씩 골라 출고할 수 없다. 혼잡 구간, 잘못된 분기, 일찍 제거한 열 때문에 멈춘 곳을 보고 처리망을 수정한다.

**한 장면**

두 고객이 과학책 자료를 공유하지만 가격 조건이 다르다. 과학책 필터 뒤에 분기를 만들면 같은 처리를 재사용한다. 가격 열을 먼저 없애면 뒤의 가격 조건 처리기가 작동하지 않는다. 첫 주문만 맞춘 생산선은 새 주문이 들어올 때 한쪽을 굶기거나 필요 없는 정보를 보낼 수 있다.

**게임의 목표**

정해진 입고 묶음을 처리해 고객 주문을 품질 기준 안에서 완료하면 성공한다. 기록은 올바른 납품, 시뮬레이션 처리 주기, 최대 임시 저장량으로 비교한다. 마우스 클릭이 적었다는 이유만으로 고득점이 되지 않는다.

**학습과 게임이 연결되는 지점**

조건 결합, 분기, 열 선택 순서, 중간 결과 재사용이 실제 처리 결과와 처리량을 바꾼다. 표의 행을 골라 정답 칸에 넣는 활동과 구분한다.

**반복 전략의 반례**

항상 필터를 직렬로 붙이기, 주문마다 생산선을 복제하기, 모든 열을 끝까지 보내기가 동시에 효율적일 수 없어야 한다. 반대로 장식용 복잡한 회로에 보너스를 주지 않는다. 입력 ID를 외워 고정 분기한 회로는 새 자료에서도 동작하는 회로와 구분한다.

**첫 제작 범위**

처리기 3종과 고객 2곳으로 공유 분기와 처리 순서가 다른 두 계약을 만든다. 분기는 정보 복사이며 상품을 무한 생성하는 행위가 아니다. 같은 고객에 중복된 ID를 여러 번 보내도 납품량이 늘지 않게 한다. 결측값은 0으로 바꾸지 않고 미확정 자료 경로로 보낼 수 있다.

### 3.5 자료구조 운용: 미로 탐색 엔진

**게임판**

출발점, 목적지, 아직 조사하지 않은 갈림길이 있는 미로와 탐색 대기 보관함이 함께 보인다. 보관함은 스택 탑, 큐 줄, 우선순위 대기판으로 표현하며 다음에 나올 위치가 눈에 보인다.

**핵심 행동**

학생은 발견한 갈림길을 넣는 순서와 보관함 종류를 정한다. 실행하면 여러 번의 삽입·꺼내기를 자동 진행하고 탐색 영역이 퍼진다. 중간 항목을 임의로 꺼내거나 목적지 칸을 직접 클릭해서 도달 처리할 수 없다. 보관함을 교체할 때도 대기 항목이 사라지지 않으며 이관 순서를 보여준다.

**한 장면**

스택에 넣은 마지막 갈림길을 먼저 꺼내면 한 통로를 깊게 조사한다. 큐를 쓰면 먼저 발견한 갈림길부터 조사해 주변이 넓게 밝혀지지만 대기 위치가 많이 쌓일 수 있다. 목적지와 가까워 보이는 위치를 우선하면 빠른 지름길이 될 수도 있고 벽 때문에 긴 우회가 될 수도 있다.

**게임의 목표**

탐색량과 대기 메모리 한도 안에서 목적지를 찾아 경로를 복원하면 성공한다. 어떤 임무는 짧은 경로, 다른 임무는 작은 메모리나 적은 탐색량을 우선한다. 임무의 우선순위는 시작 전에 공개한다. 비교할 지표는 탐색한 위치 수, 최고 대기량, 복원 경로 길이다.

**학습과 게임이 연결되는 지점**

LIFO/FIFO/우선순위는 외울 설명이 아니라 다음에 펼쳐지는 위치를 결정하는 규칙이다. 같은 자료를 넣어도 자료구조에 따라 실행 흐름이 달라진다.

**반복 전략의 반례**

깊고 좁은 통로와 얕지만 가지가 많은 미로에서 같은 전략이 항상 유리하지 않아야 한다. 우선순위 방식은 임의의 정답 위치를 알려주는 기능이 아니며 목적지까지의 추정 거리도 벽 너머 실제 거리를 보장하지 않는다.

**첫 제작 범위**

스택·큐와 대비되는 미로 2개부터 만든다. 기존 SPL 연산은 유지할 수 있다. 이 게임은 탐색 상태를 처리하는 시뮬레이션이며, 대기 위치를 꺼내는 애니메이션을 실제 로봇이 그곳으로 순간이동하는 것으로 묘사하지 않는다. 이미 본 위치와 부모 경로를 별도로 관리해 중복 탐색·잘못된 경로 복원을 막는다.

### 3.6 AI 분류 경계: 분류 게이트 디펜스

**게임판**

두 특성 축이 표시된 분류판, 자동 분류 게이트, 정상 납품과 잘못된 통과를 보여주는 출구가 있다. 첫 표본에는 종류 표시가 있지만 이후 유입 표본의 정답은 분류가 끝나기 전에는 드러나지 않는다. 특성의 단위와 좌표는 계속 고정한다.

**핵심 행동**

학생은 경계를 배치하고 영역의 목적지를 정한다. 한 묶음을 실행하면 여러 표본이 그 규칙으로 자동 분류된다. 오분류가 실제 출구와 작업 결과에 쌓인다. 학생은 다음 묶음 전에 경계를 넓히거나 나누고, 불확실한 구간 일부를 제한된 검수 통로로 보낼 수 있다. 자료 하나마다 정답 출구를 직접 고르는 조작은 없다.

**한 장면**

경계를 크게 넓히면 처리 대상은 많이 잡지만 반대 종류도 함께 통과한다. 좁히면 혼입은 줄어도 필요한 자료를 놓친다. 보이는 점마다 작은 영역을 만들면 이전 표본에는 맞지만 처음 보는 위치의 표본을 놓칠 수 있다. 학생이 만든 경계가 실제로 작동하는 장면이 성적표보다 먼저 나타난다.

**게임의 목표**

정해진 파동 동안 필요한 처리를 완료하고 혼입·누락이 한도를 넘지 않으면 성공한다. 기록은 완료한 파동, 두 종류 각각의 처리 품질, 사용한 경계·검수 용량이다. 한 종류가 많다고 전체 정확도만으로 승리시키지 않는다.

**학습과 게임이 연결되는 지점**

한계값과 경계의 포함 방향, 두 특성의 조합, 오탐·누락의 교환 관계, 처음 보는 자료에서의 일반화를 경험한다. 사람이 직접 분류 규칙을 만드는 게임이며, 자동으로 모델을 훈련하는 다음 게임과 구분한다.

**반복 전략의 반례**

전부 통과, 전부 차단, 모든 표본을 검수 통로로 보내기가 처리 목표를 만족할 수 없어야 한다. 정답을 본 시험 묶음을 같은 독립 평가로 반복 제출하지 않는다. 반례가 전혀 보이지 않는 숨은 규칙을 맞히라고 강요하지 않는다.

**첫 제작 범위**

경계 한 개의 기본 파동과 좁히기·넓히기의 손익이 다른 파동을 만든다. 각 파동은 실행 전 멈춰 있으며 반사 신경 게임으로 만들지 않는다. 이동 애니메이션 때문에 표본의 특성 좌표가 바뀌어서는 안 된다.

### 3.7 AI 모델 훈련소: 표본 덱으로 키우는 로봇

**게임판**

실제 작은 이미지·특성이 있는 학습 표본 카드, 제한된 학습 덱, 로봇의 작업장이 보인다. 초급에서는 학습 방식 하나를 고정해 어떤 모델 이름을 찍었는지가 아니라 어떤 자료를 배웠는지에 집중한다.

**핵심 행동**

학생은 여러 수집 장소에서 가져올 표본을 고르고, 덱의 중복 사례를 다른 조건의 사례와 교체한다. 잘못 붙은 이름표는 원본과 대조해 검수한다. 훈련하면 로봇이 새 작업 묶음을 자동 처리하며, 놓친 표본이 그대로 작업장에 남는다. 다음에는 그 실패 유형을 줄일 자료를 찾아 덱을 바꾼다.

**한 장면**

밝은 배경의 표본만 배운 로봇이 어두운 배경의 같은 종류를 자꾸 놓친다. 밝은 표본 열 장을 더 넣는 것보다 어두운 환경의 사례를 확보하는 것이 도움이 될 수 있다. 반대로 새롭다는 이유로 잘못 표시된 카드를 넣으면 로봇의 판단이 나빠진다. 카드 수를 늘렸다는 사실만으로 성능을 올려주지 않는다.

**게임의 목표**

정해진 준비 기간 후 처음 공개되는 작업장에서 두 종류와 관측 조건별 임무를 달성하면 성공한다. 기록은 새 작업의 실제 처리 품질, 취약 조건의 성능, 표본·훈련 자원이다. 완성된 덱과 실패했던 사례가 남아 다음 도전의 비교 대상이 된다.

**학습과 게임이 연결되는 지점**

표본의 대표성, 라벨 품질, 학습 자료와 새 자료의 차이가 로봇 행동을 바꾼다. 카드는 공격력 강화 아이템이 아니라 실제 학습 입력이다. 덱을 바꿔도 예측이 정해진 보너스만큼만 오르는 가짜 학습은 허용하지 않는다.

**반복 전략의 반례**

항상 많은 자료 수집, 항상 A/B 수만 균등하게 맞추기, 항상 최신·희귀 카드 선택이 모든 조건을 해결하지 않아야 한다. 표본 수가 같고 종류 비율도 같은 두 덱이라도 관측 조건의 차이로 결과가 달라져야 한다. 운 나쁜 카드 뽑기만으로 진행이 막히지 않게 수집 위치 선택과 교환을 제공한다.

**첫 제작 범위**

작은 합성 표본과 학습 방식 하나, 관측 조건이 다른 작업장 두 개로 시작한다. 선택한 실제 덱과 대응하는 재현 가능한 예측이 필요하다. 현재의 세 자료 묶음 조합용 실험 은행을 그대로 쓰면서 개별 카드가 반영되는 것처럼 표시할 수는 없다. 덱 구성을 반영하는 학습 엔진 또는 유한한 덱 조합을 정확히 계산한 실험 은행으로 바꿔야 한다.

검증 작업에서 정답을 본 표본을 이후 학습에 넣는 것은 가능하지만 그 표본은 앞으로의 독립 평가에서 제외한다. 최종 시험 표본은 시험이 끝난 뒤에 공개한다. 반복 연습 성적과 새 환경의 최초 성적을 구분한다.

## 4. 비슷해지지 않게 나눌 책임

- 이상치와 결측값: 잘못됐을 수 있는 관측의 원인을 추적하는 것과, 정보가 없는 상태에서 추정·확인·우회를 선택하는 것을 구분한다.
- 데이터 추출과 자료구조: 전자는 속성과 집합을 처리하는 자동화, 후자는 자료를 꺼내는 순서와 메모리 사용이 만드는 탐색이다.
- 분류 경계와 모델 훈련: 전자는 학생이 직접 규칙을 설계하고, 후자는 사례를 제공해 학습기가 규칙을 만든다.
- 시각화와 다른 게임: 시각화는 자료를 맞히는 단계가 아니라 다른 플레이어의 의사결정을 돕는 전달 도구다.

게임마다 별도 중심 화면과 조작을 만든다. 현재 공통 전략 보드의 '제목·예산·여러 선택지·검증·제출' 화면에 이름만 바꿔 넣지 않는다. 계정·세션·이어 하기·오류 복구·순위 페이지네이션은 공통으로 유지한다.

## 5. 기록과 수업 운영

연습은 같은 상황에서 정책을 바꾸고 결과를 비교하는 용도다. 도전은 같은 게임 규칙·시나리오·조건·도전 코드끼리 비교한다. 다른 지도를 무작위로 받은 학생을 하나의 점수표에 그대로 섞지 않는다. 새 상황은 숫자와 그림만 바꾸는 것이 아니라 기존 전략의 유불리가 달라지는 상황이어야 한다.

새 규칙의 기록은 기존 최고점과 별도 버전으로 보존한다. 한 게임의 높은 점수를 학습 개념 전체의 이해로 해석하지 않는다. 학생의 선택·결과·재시도 변화는 확인할 수 있게 하되 개념 평가는 게임 순위와 구분한다.

30명·6개 반 운영은 기존 계정과 학급 경계를 유지한다. 시각화 협력은 30명 기준 15쌍으로 진행할 수 있지만 연결 실패 때문에 상대의 기록이 소실되면 안 된다. 최초 제작에는 실시간 동기화 서버를 추가하지 않으며, 협력의 재미가 확인된 뒤 기존 세션 구조에서 턴별 공유를 설계한다. 다른 여섯 게임은 독립 플레이가 기본이다.

## 6. 이번 설계의 완료선

바로 84개 보드를 새로 채우거나 콘텐츠 개수를 늘리지 않는다. 먼저 게임마다 같은 습관으로는 둘 다 최선의 결과를 낼 수 없는 대조 상황 두 개를 만든다. 어느 행동 때문에 다음 상태가 달라졌는지 화면만으로 설명할 수 있어야 한다.

우선 제작을 권하는 기준 사례는 데이터 자동 분류 공장이다. 처리망 하나가 새 입력을 연속 처리하는지 보면 '의미 있는 설계'와 '반복 클릭'의 차이를 가장 직접적으로 확인할 수 있다. 이것이 다른 여섯 게임을 미루거나 동일한 공장 형식으로 만들자는 뜻은 아니다.

판 수 확대 전에 확인할 질문은 세 개로 제한한다.

1. 같은 버튼·같은 정책만 반복해도 모든 상황에서 유리한가?
2. 학습 개념을 다르게 판단하면 게임의 다음 상태도 달라지는가?
3. 실패한 학생이 무엇을 바꿔 다시 시도할지 판에서 찾을 수 있는가?

이번 문서로 게임성이나 학습 효과가 검증됐다고 보지 않는다. 아직 코드 구현·밸런스 검사·학생 플레이는 수행하지 않았다.
