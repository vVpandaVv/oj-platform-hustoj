# 직접 조작 게임 구현 현황

2026-09-14. 기존 일곱 게임 ID, 숏코드, 블록, 허브 경로의 기본 화면을 교체했다. 규칙은 각 모듈의 `Hands_Board.php`, 화면은 `assets/play/hands.js`와 장면별 보조 파일에 있다. 기존 `Play_Board.php`와 과거 기록은 보존한다. 후속 패키징 요청에 따라 이 구현을 1.2.0 설치 ZIP에 포함하며 이전 ZIP은 보존한다. 운영 사이트 배포는 수행하지 않았다.

## 기록과 제한

- 시간은 서버의 마감 시각으로 판정한다. 만료 후 도착한 행동에는 추가 점수를 주지 않는다. 시작 버튼 또는 첫 제출로 기록이 시작된다. 시작 전에는 화면을 조작해 볼 수 있다.
- 출고·분리 등의 기록은 기본 점수와 최대 25점의 연속 보너스를 합산하고 실수에 감점한다. AI는 미공개 평가의 종류별 인식률 평균을 1,000점으로 환산하며 라벨 변경 횟수로 가짜 점수를 주지 않는다.
- 날짜별 같은 입력 순서를 사용하며 날짜는 UTC 기준이다. 반복 도전을 허용하는 일별 최고 기록이다. 최초 노출 평가나 실력 인증 점수로 해석하지 않는다. AI의 이미지 풀은 고정되어 있으며 날짜별로 새로운 필자를 생성하는 기능은 아니다.
- 기본 저장 버전은 `hands-2026-09-v1-YYYY-MM-DD`, 결측값은 `missing-methods-v2-YYYY-MM-DD`, 손글씨는 `handwriting-digits-v2-YYYY-MM-DD`, 시각화는 `chart-action-v4-YYYY-MM-DD`다. 기존 점수와 합치지 않으며 이전 기록 조회로 남긴다. 전체 참여자 페이지네이션, 서버 계산 점수, 요청 중복 방지, 사용자별 세션, 교사 보고서를 유지한다.
- 시각화는 혼자 하는 게임으로 교체했다. `BroadcastChannel` 수신 창·팝업·전송 대기는 제거했다. 협동 게임이나 기기 간 통신 기능을 포함하지 않는다.
- 게임의 숫자 자료와 배송 규칙은 교육용 합성 자료다. 분류 경계는 사람이 만든 규칙이며 실제 우편 규정이나 학습된 AI라고 부르지 않는다. 이상치 선택은 검토이며 자동 삭제나 오류 확정이 아니다.
- 결측값은 원래 관측값을 일부러 가린 게임이며 근거 부족으로 보류하는 사례도 추가했다. 실제 결측값에 유일한 정답이 있거나 보간이 언제나 맞는다고 해석하지 않는다. 개인별 전이 평가는 이 개발분에 포함하지 않았다.

## 손글씨 자료와 모델

자료: E. Alpaydin, C. Kaynak (1998), [Optical Recognition of Handwritten Digits, UCI](https://doi.org/10.24432/C50P49), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). [scikit-learn의 load_digits](https://scikit-learn.org/stable/datasets/toy_dataset.html#optical-recognition-of-handwritten-digits-dataset)에 포함된 8×8, 0~16 픽셀 값의 0~9 숫자 전체 종류를 사용한다. 원본 그림은 유지하고 부분 집합·자료 분할·화면 표현·최근접 순서를 파생했다.

- 전체 자료는 학습 후보 120장, 확인 40장, 최종 평가 300장이다. 숫자마다 각각 12·4·30장으로 균등하며 세 집합의 원본 ID가 겹치지 않는다. 필자 단위의 분리라고 주장하지 않는다.
- 한 도전에는 선택한 세 숫자의 학습 후보 36장, 확인 12장, 최종 평가 90장만 사용한다. 각 숫자의 인식률을 같은 비중으로 채점한다. 숫자 조합을 바꾸면 사진·이름 칸·예측·종류별 최종 결과가 함께 바뀐다. 조합 밖의 이름이나 사진 ID는 서버에서 거부한다.
- 오늘의 조합은 UTC 날짜에 따라 120가지 세 숫자 조합을 한 번씩 순회한다. 같은 날 같은 도전에는 같은 자료를 사용하며, 진행 중 날짜가 바뀌어도 시작할 때의 조합을 유지한다.
- 직접 선택할 수 있는 12개 조합은 `017`, `069`, `358`, `147`, `235`, `268`, `049`, `128`, `456`, `239`, `578`, `024`다. `digits-<조합>`별로 순위를 분리한다. 전체 열 숫자를 동시에 분류하는 모드는 아니며, 새 도전은 같은 조합으로 최고 기록에 재도전한다.
- 학생이 선택한 임의의 후보 부분 집합과 붙인 라벨을 그대로 사용한다. 유클리드 거리의 1-최근접 이웃이며 같은 거리면 후보 번호 순이다.
- 모든 후보에 대한 거리 순서를 미리 계산한다. 실행 때 첫 번째 선택 후보의 현재 라벨을 찾는 것은 해당 부분 집합의 1-NN과 동일하다. 고정 덱 점수표나 가장 비슷한 덱의 성적을 대신 쓰지 않는다.
- Python은 자료 생성·대조 때만 필요하며 WordPress 실행 중에는 필요하지 않다. 생성기는 `scripts/edu-game/build-handwriting-coach.py`. 평가 원본과 정답은 PHP 파일에 있고 종료 전 공개 응답에는 포함하지 않는다.

## 확인한 범위

- `tests/hands.php`: 직접 조작 규칙, 새로운 모음, 기한 후 점수 차단, 기억 제한, 자료 분리.
- `tests/handwriting-combinations.php`: 120가지 조합의 균등 분할·최근접 순서·일별 순회, 선택 조합의 이름 수정·기억 제한·허용되지 않은 입력·평가와 기록 버전 확인.
- `tests/play-api.php`: 실제 REST 컨트롤러와 SQLite 쿼리 대역으로 저장·재시도·접근 제한·일별 순위·교사 보고서 확인. 실 WordPress/MySQL 운영 점검은 아니다.
- `tests/browser-play.cjs`: 실제 PHP 규칙과 렌더러를 사용하는 HTTP 대역에서 마우스 이동·드래그·입력·단독 출동·복구 확인. 360px/1280px 화면과 손글씨·그래프 캔버스 확인.
- 이미지 생성기: 120가지 조합에서 임의 부분 집합과 임의 라벨의 예측 36,720개를 scikit-learn 1-NN 결과와 대조했다.
- 이 확인은 동작 확인이며 학생이 직관적으로 이해하거나 재미를 느꼈다는 증거는 아니다. 학생 실습은 아직 실시하지 않았다.
