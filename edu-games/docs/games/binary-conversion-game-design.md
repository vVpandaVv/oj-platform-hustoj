# 이진수 변환 게임 설계

## 1. 게임 개요

- 게임 ID: `binary-conversion`
- 게임명 후보:
  - `Binary Conversion`
  - `비트 카드 변환`
  - `이진수 변환 챌린지`
- 학습 목표:
  - 10진수와 2진수의 대응 관계를 빠르게 이해한다.
  - 각 비트 자리값(`1, 2, 4, 8, 16, ...`) 개념을 반복 학습한다.
  - 제한 시간 안에 변환하는 훈련을 통해 숙련도를 높인다.

## 1.1 레퍼런스 반영 방향

- 참고 레퍼런스: Cisco Binary Game  
  URL: [https://learningcontent.cisco.com/games/binary/index.html](https://learningcontent.cisco.com/games/binary/index.html)
- 레퍼런스에서 가져올 핵심:
  - 문제를 정적인 퀴즈처럼 한 개씩 보여주기보다, 화면 안에서 문제 행이 계속 생성되는 아케이드 감각
  - `10진수 → 2진수`, `2진수 → 10진수`를 모두 빠르게 오가며 푸는 방식
  - 시간이 흐를수록 문제 생성 속도가 빨라지는 압박 구조
  - 점수 중심의 짧은 반복 플레이
- 우리 플러그인에서 추가할 요소:
  - 개인 통계
  - 게임별/전체/그룹별 랭킹
  - 관리자 설정 가능 난이도
  - 모바일 대응 및 워드프레스 블록 기반 배치

참고 근거:

- 공개된 자동 풀이 gist를 보면 Cisco 게임은 두 유형을 모두 포함한다.
  - 비트를 클릭해 맞추는 유형
  - 이진수를 보고 10진수를 입력하는 유형  
  [GitHub Gist](https://gist.github.com/KonradowyPL/a2bb49ce29c89cc598e4dceabb02448b)

## 2. 핵심 플레이 컨셉

- 화면에는 여러 개의 문제 행이 아래에서 생성되어 위쪽 위험선 방향으로 이동한다.
- 각 문제는 `10진수 → 2진수` 또는 `2진수 → 10진수` 변환 문제다.
- 사용자는 현재 선택한 문제를 빠르게 해결해야 한다.
- 정답이면 해당 문제 행이 제거되고 점수를 획득한다.
- 문제 행이 위험선에 도달하거나, 전체 세션 타이머가 종료되면 게임 오버다.
- 게임은 짧고 빠른 세션 중심의 `아케이드 학습형`으로 설계한다.

## 2.1 권장 플레이 모드

권장 기본 모드는 2개다.

1. `Arcade Mode`
   - Cisco 스타일 메인 모드
   - 문제 행이 계속 생성
   - 속도가 점점 빨라짐
   - 랭킹 기준 점수 모드
2. `Practice Mode`
   - 한 문제씩 차분히 푸는 연습 모드
   - 시간 제한 완화 또는 없음
   - 통계는 저장하되 경쟁 랭킹에는 미반영 가능

초기 MVP는 `Arcade Mode` 우선 구현을 권장한다.

## 3. 화면 구성

### 3.1 공통 HUD

- 현재 점수
- 현재 단계
- 남은 시간
- 현재 연속 정답 수
- 일시정지 없음

### 3.2 문제 영역

- 여러 개의 `문제 행(problem row)`이 세로 스택 형태로 존재
- 문제 행은 일정 간격으로 아래에서 생성되어 위로 이동
- 각 행에는 다음 정보 포함
  - 모드 표시:
    - `10진수 → 2진수`
    - `2진수 → 10진수`
  - 문제 값
  - 비트 카드 또는 숫자 입력 슬롯
  - 선택 상태 하이라이트
- 상단에는 `위험선(danger line)` 표시
- 행이 위험선을 넘으면 즉시 실패
- 별도 자리값 힌트 바:
  - `512 256 128 64 32 16 8 4 2 1`
  - 현재 선택된 문제의 비트 길이에 맞춰 강조

### 3.3 입력 영역

#### A. `10진수 → 2진수`

- 4자리~10자리 이진수 카드를 가로로 표시
- 각 카드는 현재 값이 `0` 또는 `1`
- 카드 클릭 시 `0 ↔ 1` 토글
- 기본값은 모두 `0`
- 필요 시 `전체 초기화` 버튼 제공
- 카드 아래에 각 자리의 값 표시 가능:
  - 예: `8 | 4 | 2 | 1`
- 현재 선택된 문제 행에서만 카드 조작 가능
- 정답이 되면 자동 제출 또는 `확인` 버튼 제출 중 하나 선택 가능

권장:

- 카드 값이 목표와 일치하는 순간 자동 판정
- 아케이드 템포를 위해 별도 제출 버튼 없이 즉시 제거

#### B. `2진수 → 10진수`

- 문제 이진수는 카드 형태로 표시하되 이 카드는 읽기 전용
- 답안 입력은 아래 둘 중 하나로 구현
  - MVP 권장안: 객관식 4지선다
  - 확장안: 숫자 패드 입력
- Cisco 스타일에 더 가까운 방식은 `숫자 패드 입력`이다.

설계 가정:
- 사용자가 요청한 `카드 클릭 토글` UX는 `10진수 → 2진수`의 핵심 입력 방식으로 사용한다.
- `2진수 → 10진수`는 카드 토글만으로 답 입력이 어렵기 때문에 별도 입력 방식을 둔다.
- 레퍼런스 유사도를 높이려면 최종 구현은 `숫자 패드 입력`을 우선 고려한다.

## 4. 라운드 구조

### 4.1 시작

- 게임 시작 시 3초 카운트다운 후 즉시 시작
- 초반에는 4비트 중심의 쉬운 문제만 등장
- 최초 5~10초는 문제 생성 속도를 느리게 잡아 적응 시간을 준다

### 4.2 진행

- 게임은 `웨이브` 또는 `속도 단계(stage band)` 단위로 진행된다.
- 문제를 맞힐수록 점수와 연속 정답이 쌓인다.
- 일정 시간 또는 일정 점수마다 다음 단계로 넘어가며 아래 요소가 증가한다.
  - 비트 길이
  - 문제 생성 속도
  - 문제 행 이동 속도
  - `2진수 → 10진수` 비율

권장 구조:

- `단계`는 여전히 존재하되, 사용자가 문제 하나를 맞힐 때마다 넘어가는 구조가 아니라
  `난이도 구간`으로 쓰는 편이 레퍼런스와 더 잘 맞는다.

### 4.3 종료

- 아래 중 하나면 즉시 종료
  - 전체 제한 시간 0초 도달
  - 문제 행이 위험선 도달
  - 정답 제출 후 오답 판정

## 5. 난이도 설계

## 5.1 비트 길이 범위

- 사용 비트 길이: `4~10비트`
- 문제 숫자 범위:
  - 4비트: `0~15`
  - 5비트: `0~31`
  - 6비트: `0~63`
  - 7비트: `0~127`
  - 8비트: `0~255`
  - 9비트: `0~511`
  - 10비트: `0~1023`

### 5.2 단계 그룹

권장 기본 설계:

1. 단계 1: 4비트, `10진수 → 2진수`만, 느린 생성 속도
2. 단계 2: 5비트, `10진수 → 2진수`만
3. 단계 3: 6비트, 두 모드 혼합 시작
4. 단계 4: 7비트, 생성 속도 증가
5. 단계 5: 8비트, 두 모드 랜덤
6. 단계 6: 9비트
7. 단계 7+: 10비트 반복, 최대 속도 구간

### 5.3 모드 비율

- 초반: `10진수 → 2진수` 100%
- 중반: `10진수 → 2진수` 70%, `2진수 → 10진수` 30%
- 후반: 50:50

이유:
- 카드 토글 학습의 핵심은 `10진수 → 2진수` 쪽에 있다.
- 반대 방향은 읽기 능력 점검용으로 섞는 것이 좋다.

## 6. 시간 설계

### 6.1 기본 규칙

- 게임 전체 세션 타이머를 둔다.
- 별도로 문제 행은 생성 주기와 이동 속도를 가진다.
- 시간이 지날수록 생성 주기가 짧아진다.
- 레퍼런스 감각을 살리기 위해 `개별 문제 타이머`보다 `전체 세션 압박 + 누적 속도 상승` 구조를 우선 권장한다.

### 6.2 권장 시간표

권장 `Arcade Mode` 기준:

- 전체 플레이 시간: 90초
- 시작 0~15초: 문제 1개씩 천천히 생성
- 15~35초: 생성 속도 1단계 상승
- 35~55초: 생성 속도 2단계 상승
- 55~75초: 생성 속도 3단계 상승
- 75~90초: 최대 압박 구간

보조 수치 예시:

- 시작 생성 주기: 3.2초
- 중반 생성 주기: 2.2초
- 후반 생성 주기: 1.4초
- 최종 생성 주기: 0.9초

문제 행 상승 속도도 같은 구간에서 함께 증가시킨다.

### 6.3 보정 규칙

- 초반 10초 동안 화면에 동시에 존재할 수 있는 문제 수를 2개 이하로 제한 가능
- 연속 정답 5회 이상 시 시각 효과만 주고 시간 보너스는 주지 않음
- 너무 오래 같은 문제를 붙잡지 못하게 하기 위해 선택된 문제 강조를 강하게 준다

권장 이유:
- 점수 게임의 긴장감을 유지하기 위해 시간 보너스보다 고정 타이머가 더 명확하다.

## 7. 점수 설계

### 7.1 기본 점수

- 정답 시 점수 획득
- 오답 또는 시간 초과 시 추가 점수 없음

### 7.2 권장 공식

`획득 점수 = 기본 점수 + 남은 시간 보너스 + 연속 정답 보너스`

세부안:

- 기본 점수: `비트 길이 × 10`
- 남은 시간 보너스: `남은 초 × 2`
- 연속 정답 보너스: `floor(연속 정답 수 / 3) × 5`

예시:

- 6비트 문제를 4초 남기고 맞힘
- 연속 정답 4회째
- 점수 = `60 + 8 + 5 = 73`

### 7.3 최종 점수

- 최종 점수 = 모든 단계 획득 점수 합계
- 랭킹에는 아래 값을 함께 저장
  - 총점
  - 도달 단계
  - 총 정답 수
  - 최고 연속 정답
  - 평균 응답 시간

## 8. 정답 판정 규칙

### 8.1 `10진수 → 2진수`

- 카드 배열을 이어 붙인 이진 문자열을 10진수로 변환
- 문제의 10진수와 같으면 정답

예:

- 목표값: `13`
- 카드값: `1101`
- 정답 처리

주의:
- 문제 길이는 고정 길이 비교로 처리한다.
- 예를 들어 6비트 문제에서 `001101`과 `1101`은 의미상 같지만, 실제 UI에서는 6장 카드를 모두 가진 상태로 `001101`이 제출된다.

### 8.2 `2진수 → 10진수`

- 표시된 이진 문자열을 10진수로 변환한 값과 사용자의 입력값을 비교
- 동일하면 정답

## 9. 문제 생성 규칙

### 9.1 공통 규칙

- 현재 단계에 맞는 비트 길이를 먼저 결정
- 해당 비트 길이에서 표현 가능한 값 범위 안에서 무작위 숫자 선택
- 바로 직전 문제와 동일한 정답은 피함

### 9.2 편향 방지

- `0000`, `1111` 같은 극단 패턴만 연속 등장하지 않게 조정
- `2의 거듭제곱`, `2의 거듭제곱 - 1`, 랜덤 일반값을 섞음

권장 분포:

- 25%: 자리값 학습형 숫자
  - `1, 2, 4, 8, 16, 32 ...`
- 25%: 누적 패턴형 숫자
  - `3, 7, 15, 31 ...`
- 50%: 일반 랜덤 숫자

## 10. UX 디테일

### 10.1 입력 피드백

- 카드 토글 시 즉시 시각 강조
- 제출 직전 현재 이진수 값과 변환된 10진수 미리보기 제공 가능
  - 예: `현재 값: 22`

MVP 권장:
- 초급 학습용이므로 `현재 값 미리보기`를 켠다.

하드 모드 확장:
- 미리보기 제거

### 10.2 정답 피드백

- 정답:
  - 카드 또는 답안 영역 초록색 플래시
  - 해당 문제 행이 빠르게 사라짐
  - 점수 팝업이 행 위치에서 떠오름
- 오답:
  - 빨간색 플래시
  - 정답 표시 후 결과 화면 이동
- 시간 초과:
  - 전체 타이머 종료 또는 위험선 충돌 애니메이션 후 결과 화면 이동

### 10.3 접근성

- 카드는 마우스 클릭뿐 아니라 키보드 포커스와 `Enter`/`Space` 토글 지원
- 색만으로 상태를 구분하지 않고 숫자 자체를 크게 표시

## 11. 통계 설계

개인 통계 페이지에 권장할 지표:

- 총 플레이 수
- 총 정답 수
- 총 오답 수
- 평균 도달 단계
- 최고 점수
- 최고 단계
- 평균 응답 시간
- 모드별 정답률
  - `10진수 → 2진수`
  - `2진수 → 10진수`
- 비트 길이별 정답률
  - 4비트~10비트

## 12. 랭킹 설계

이 게임은 아래 랭킹 집계 대상이 된다.

- 게임별 전체 랭킹:
  - 기준값 `최고 점수`
- 게임별 주간 랭킹:
  - 기준값 `해당 기간 최고 점수`
- 그룹별 랭킹:
  - 그룹 구성원의 최고 점수 기준
- 그룹 내 랭킹:
  - 동일 그룹 내 사용자 순위

동점 처리 권장 순서:

1. 최고 점수 우선
2. 더 높은 단계 우선
3. 평균 응답 시간이 짧은 쪽 우선
4. 먼저 달성한 기록 우선

## 14. 상태 머신

권장 상태:

1. `idle`
2. `round_intro`
3. `playing`
4. `checking`

6. `game_over`

`idle → round_intro → playing → checking → round_clear → round_intro`

`playing → checking → game_over → result`

## 17. 확인이 필요한 결정 포인트

현재 설계에서 제가 임시로 정한 부분:

1. 오답 즉시 게임 오버
2. 라이프 시스템 없음
3. `2진수 → 10진수`는 객관식 또는 숫자 입력 사용
4. 시간은 단계별 고정, 다음 문제로 이월 없음
5. 점수는 `비트 길이 + 남은 시간 + 연속 정답` 기반

사용자 확정이 필요할 수 있는 부분:

1. `2진수 → 10진수` 답안 입력 방식
2. 오답 시 즉시 종료 여부
3. 초급자용 `현재 값 미리보기` 노출 여부
4. 10비트까지 처음부터 열지, 단계 해금식으로 갈지
