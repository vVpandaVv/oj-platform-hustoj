# 코드 타이핑 검정과 그룹 평가

## 채점 기준

현재 기준 `typing-verified-v3`은 제시 코드의 같은 위치와 일치하는 현재 입력의 비공백 문자 전부와 완전히 맞힌 이전 예제의 비공백 문자를 유효 문자로 인정한다. 앞부분의 오타가 뒤쪽 정타를 무효로 만들지 않는다. 유효 CPM은 유효 문자 수를 검정 전체 분으로 나눈다. 검정 중 실시간 값은 경과 분 기준의 잠정 값이고 종료 결과는 서버의 고정 제한시간 기준이다. 빈칸만 입력하면 유효 문자는 0이며 길이만 채웠다고 완료되거나 다음 코드가 열리지 않는다. 불필요한 삽입·누락으로 글자 위치가 밀렸다면 그 위치를 고쳐야 하며 문자열을 임의로 재정렬해 정타로 만들지 않는다.

이전 `typing-verified-v2`의 처음부터 연속 일치 기준은 기존 기록·진행 중 세션과 개설된 그룹 평가에만 유지한다. 새 개인 검정·새 그룹 평가는 v3를 사용한다. v2 그룹 평가를 중간에 v3로 바꾸지 않고, 새 기준 평가는 새로 개설한다. 두 순위는 별도로 조회하며 기존 완료 기록을 소급 변경하지 않는다.

입력 정확도는 `인정 정타 / (인정 정타 + 누적 오입력) × 100`이다. 정답 위치별 정타는 예제마다 한 번만 인정한다. 잘못 넣은 문자는 지우고 수정해도 오입력에 남고, 이미 맞혔던 위치를 지웠다 다시 입력해도 정타를 추가하지 않는다. 삭제 동작 자체는 오타로 계산하지 않는다. 공백·줄바꿈은 정타·오타 판정에 포함하지만 속도에는 포함하지 않는다. Tab은 공백 4칸의 편집으로 처리한다. IME 중간 조합은 제외하고 확정된 문자열을 문자 단위로 처리한다.

작성 부분 일치율은 현재 남아 있는 입력과 이전 완성 코드의 일치율이다. 이것은 전체 제시 코드의 완성률이 아니다. 입력 정확도와 별도 지표이며 학생이 고친 오타를 없애는 용도로 쓰지 않는다. 같은 위치의 반복 입력으로 정확도를 회복하거나 삭제·재입력으로 속도를 누적하지 않는다. 현재의 정타를 삭제하면 유효 글자 수에서도 빠지고 다시 입력하면 한 번만 인정한다.

검정의 첫 오타 위치 버튼은 편집 커서를 해당 위치로 옮긴다. 이전 줄을 수정해도 현재 입력으로 즉시 다시 표시하며, 완전히 맞힌 코드만 다음 지문으로 넘어간다. 평가 선택 시에는 저장된 코드 스냅샷을 먼저 보여주고 첫 입력 때 서버 시계를 시작한다.

기준 충족은 유효 문자가 1개 이상이고 설정된 입력 정확도 이상이며 전송 이력 확인 문제가 없는 경우다. 기준 미달 결과도 지표·편집 이력을 저장하고 자동으로 삭제하지 않는다. 저장용 게임 점수는 충족 시 유효 CPM×10, 미달 시 0이며 이는 자동 학업 성적이 아니다. 학생 화면과 순위는 유효 CPM을 표시하고 교사가 결과를 평가한다.

## 서버 검증과 한계

- 로그인·게임 공개·평가 지정 명단을 확인하고 서버가 토큰, 마감 시각, 코드 스냅샷과 순서를 발급한다. 입력 범위·종류·양·시간 순서를 검증하고 서버의 상태에서 편집을 재생한다. 클라이언트가 보낸 CPM·정확도·완료 개수는 사용하지 않는다.
- 입력은 약 1.5초마다 묶어 저장한다. revision과 요청 ID로 중복·경합을 검사하며 응답을 잃으면 같은 요청을 재전송한다. 작성 상태와 수정 전 오타는 새로 고침 뒤에도 서버 기록으로 복구한다. 이 기기의 아직 확인되지 않은 요청은 로컬 캐시에서 재전송한다.
- 브라우저를 닫아 종료 요청을 보내지 못한 기록도 평가 결과·참가 목록·개인 순위를 읽을 때 마감 여부를 확인해 마지막 서버 저장 지점까지 확정한다. 별도 상시 실행 서버나 cron 설치가 필요하지 않다.
- 끝나기 전에 전송한 마지막 묶음에는 2초의 전송 유예가 있지만 이벤트 시각은 검정 시간 이내여야 한다. 8초 넘게 지난 입력을 뒤늦게 한꺼번에 보내면 재계산 결과를 보존하되 확인 필요로 표시하고 자동 순위에서 제외한다. 마감 유예 이후 도착한 입력은 가산하지 않고 마지막 확인 지점까지 확정한다. 장시간 통신 장애 결과는 교사가 검토한다.
- 붙여넣기·끌어 넣기를 UI에서 차단하고 과도한 대량 편집을 서버에서 제한한다. 일반 브라우저의 입력 이력만으로 자동화나 개발자 도구를 완벽히 막거나 손입력을 증명할 수는 없다. 감독 평가로 운영하고 확인 필요 기록을 부정행위로 단정하지 않는다.

## 그룹 평가

허브와 코드 타이핑 상단은 본인에게 배정된 평가와 대표 유효 CPM·입력 정확도를 펼친 카드로 표시한다. 미응시·응시 중·완료는 현재 참여 상태이며 정확도 기준 충족 여부·마감·남은 응시 횟수와 별개다. 응시 중인 평가를 우선 표시하고 학생 화면의 상태별 필터로 찾는다. 허브에도 완료 결과를 표시하고 내 평가 보기로 전체 목록에 접근한다. 교사는 공개한 평가의 참여 링크를 복사할 수 있다. `?evaluation=평가ID`는 지정 명단을 서버에서 확인한 뒤 해당 코드의 집중 준비 화면만 연다. 마감·응시 횟수 소진 시에는 내 기록 목록을 보여주며, 조회·목록 복귀는 응시 횟수나 제한시간을 소모하지 않는다. 첫 입력이 서버 시작 요청이다. UI 개선은 채점·명단·권한 규칙을 바꾸지 않는다.

학생 카드의 대표 기록은 교사 결과와 같은 서버 선택 함수를 사용한다. 재응시 중에도 기존 확정 대표 기록은 유지한다. 확정 기록이 없는 진행 중 수치에는 잠정을 표시하고 미응시는 0점 대신 대기로 표시한다. 회차별 기록을 펼치면 모든 완료 응시의 CPM·입력 정확도·판정을 확인할 수 있다. 종료 직후에는 서버 확정 결과·정확도 기준선·수정 전 포함 오타를 우선 표시하고 작성 코드는 접어 둔다. Space로 공식 결과를 초기화하지 않으며 재응시는 목록에서 선택한다. 이 동작은 개인 연습의 Space 재시작을 변경하지 않는다.

교사는 기존 플랫폼 Addon Context Gateway가 승인한 담당 학급·그룹을 선택한다. 대상 명단은 생성 당시의 합집합이고 중복 학생은 한 번만 배정한다. 최대 12개 그룹·2,000명, 동일 언어의 지문 최대 30개를 지정 순서로 사용한다. 코드는 서버가 복사해 저장하므로 진행 중 콘텐츠 수정에 영향을 받지 않는다. 한 지문 묶음을 모두 작성하면 같은 순서로 다시 순환한다.

초안 → 응시 가능 → 응시 마감 상태이며 마감은 새 시작만 차단한다. 이미 시작한 학생은 본래 제한시간까지 응시·저장한다. 학생은 지정된 평가만 보고 본인의 기록만 조회한다. 새로 고침·중복 시작으로 응시 횟수가 늘어나거나 제한이 초기화되지 않으며 학생별 허용 횟수는 1~3회다.

개설 교사 또는 관리 권한이 있는 사이트 관리자만 명단·결과·CSV를 조회한다. 다른 교사나 다른 학생이 평가 번호·토큰을 추측해도 결과를 읽지 못한다. 미참가자를 포함한 결과는 20·50·100명 페이지로 조회 가능하며 CSV는 전체 대상자를 포함한다. 여러 응시는 모두 보존하고 대표 결과는 기준 충족 우선, 최고 유효 CPM, 높은 입력 정확도, 먼저 제출된 기록 순이다. 생성·공개·마감 변경은 평가의 감사 이력에 남긴다.

개인 검정은 언어·첫 예제별 고정 순서, 5분·95%로 같은 조건끼리 비교한다. 그룹 평가의 코드·시간·정확도·시도 횟수는 평가별로 고정하고 공개 개인 순위와 섞지 않는다. 기존 `edu_games_scores` 기록은 계속 조회하고 새 제출만 중단한다. 새 결과는 `edu_games_typing_*` 테이블 3개에 분리한다. 기존 기록에는 원문이 없어 새 기준으로 재산정하지 않는다.

## 확인 범위

교사 비교표는 전체 대상자의 상태·CPM·입력 정확도·판정을 읽기 전용으로 조회한다. 검색·필터·정렬은 페이지 분할 전에 적용한다. 상단 인원·평균·CPM 막대 기준은 필터와 무관한 전체 평가이며 평균에는 확정된 대표 기록만 포함한다. 여러 회차가 있으면 대표 기록 선택 규칙을 유지하면서 현재 재응시 여부를 별도로 표시한다. 잠정 수치와 전송 확인을 정확도 미달로 혼동하지 않는다. 회차별 상세·전체 CSV는 보존하며 채점 규칙이나 저장 기록을 고치지 않는다.

`tests/typing-verified.php`는 실제 도메인 규칙과 SQLite 쿼리 대역으로 공백 반복·수정 전 오타·정타 반복·부분 코드·시간·버전·명단·응시 제한·권한·재시도를 검사한다. `tests/browser-typing-verified.cjs`는 같은 PHP 서비스와 분리된 SQLite로 교사 개설 → 학생 응시 → 서버 결과 → 전체 명단·CSV를 확인한다. 실 WordPress/MySQL 마이그레이션, 30명 동시 부하, iPad Safari 실기기 검증을 완료했다고 주장하지 않는다.
