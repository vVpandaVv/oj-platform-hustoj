# 스택·큐 물류 레이스

## 플레이와 학습

입고열의 첫 물건을 스택 또는 큐에 넣고 세 출고장 중 하나의 다음 주문을 배송한다. 스택은 마지막 삽입 위치와 제거 위치가 같고 큐는 삽입과 제거 위치가 반대다. 내부 물건은 직접 선택할 수 없다. 실제 출구가 강조되며 이동 직후 적재 상태·주문 진척·점수가 바뀐다. 임시 보관함 2칸은 추가 적재 또는 직접 배송이 가능하다.

세 주문이 동시에 남아 있으므로 어느 주문부터 처리할지와 어느 자료구조에 적재할지 선택한다. 주문 하나를 끝내도 나머지 물건과 주문은 초기화하지 않는다. 새 주문 물건은 입고열 뒤에 추가된다. 네 주문을 완수하면 새 주문 크기가 3개에서 4개로 증가하고 저장 용량은 각 5칸을 유지한다. 막힌 판은 비용을 지불하고 보관 물건을 입고열 앞으로 옮길 수 있으며 물건이 삭제되지는 않는다.

## 점수와 기록

- 개인전 120초. 날짜별 같은 초기 입력과 주문을 사용한다. 이후 주문 공급 순서는 완수한 주문 수에 따르며 속도·작업 순서에 따라 판이 달라진다. 반복 재도전이 가능한 최고 기록이지 처음 보는 문제의 인증 점수는 아니다.
- 배송 30점 + 두 번의 취급(입고/출고)으로 끝낸 배송 10점 + 연속 배송 2~10점. 주문 완수 50점. 매 세 주문 중 한 급행 주문은 완료 시 남은 정시 보너스 시간 비율에 따라 0~50점을 추가한다.
- 임시 보관 이동·재적재는 3점, 긴급 재입고는 25점 비용이며 0점 아래로 내려가지 않는다. 우회 없는 배송과 우회 배송은 같은 수를 배송해도 점수가 다르다. 보너스 만료는 주문 실패나 게임 종료가 아니다.
- 서버가 물건 위치·주문·시간·점수를 판정한다. API의 기존 요청 중복 방지·revision 검사·저장 재시도·이어 하기를 유지한다. 종료 시 배송 수·주문 수·효율 배송·재배치·이동·최대 연속과 점수 내역을 저장한다.
- 기록 버전은 `warehouse-rush-v2-YYYY-MM-DD`. 기존 순위·이전 규칙 기록을 삭제하거나 합산하지 않는다. DB 구조 변경과 실시간 팀전 추가는 없다.

## 인터페이스

중앙 게임판, 상단 점수·배송·연속·최고점·시간, 대상 위치의 적재·출고, 출고장별 현재 주문, 하단 실제 이동 피드백으로 구성한다. 화면 모드 토큰과 기존 집중 화면을 사용한다. PC의 단축키는 출고장 1/2/3, 선택 물건 적재 A/S, 출구 출고 J/K이며 버튼 title에도 표시한다. 기본 Tab·Enter 버튼 조작을 보존한다. 태블릿은 클릭·터치로 동일 작업이 가능하고 누른 채 움직인 경우에만 드래그한다. 동작 감소 설정에서는 이동 강조 애니메이션을 생략한다.

KAIT Play 로컬 0.10.0의 정보 배치·상태 색상·대상 가까이에서 조작하는 원칙을 참고했다. 해당 소스·그림·문제를 복제하지 않았다. 실제 학생 수업에서의 이해도·흥미 검증을 완료했다고 주장하지 않는다.

## 확인

`tests/warehouse-rush.php`는 LIFO/FIFO, 병렬 주문과 잔여 재고 유지, 효율 차등 점수, 보너스 만료, 시간 종료, 재고 보존과 점수 내역을 확인한다. `PLAY_WAREHOUSE_ONLY=1 node tests/browser-play.cjs`는 PHP 규칙을 사용하는 로컬 대역으로 버튼·키보드·드래그·저장 재시도와 반응형 화면을 확인한다. 실 WordPress/MySQL 부하 검증을 대신하지 않는다.
