# 콘텐츠 보강 구현 명세

상태: 원래의 구현 준비안(설계 기준으로 보존). [2026.09 적용 현황](reinforcement-2026-09.md), [평가 근거](README.md), [문제 초안](seed-cases.json). 이하의 목표·출시 기준 전체를 구현 완료 목록으로 읽지 않는다. 구현·검증된 범위와 남은 승인 항목은 적용 현황에서 구분한다.

## 1. 유지할 제품 범위

- 기존 게임 ID·허브·블록·숏코드·공개 설정을 사용한다. 신규 활동마다 별도 플러그인이나 허브를 만들지 않는다.
- 중학생을 기본 대상으로 한다. IQR·최근접 이웃·혼동행렬은 선행 개념 확인 후 심화로 제공한다. 공식 교육과정 일치 여부는 담당 교사가 확인한다.
- 이진수 8행 게임 공간과 수동 생성 연습, 문자 코드의 문항별 제한시간·정답 후 초기화·오답 종료 규칙은 유지한다. 개념 연습에는 무제한 모드를 사용한다.
- 이미지 표현은 최대 16×16, 최대 16색으로 유지한다. RGB 성분 편집은 추가하지 않는다. 상단 팔레트·행과 같은 높이의 숫자 코드·하단 그림 보기·드래그 중만 칠하기를 유지한다.
- 장치 매칭은 실수 횟수로 게임오버시키지 않는다. 틀린 쌍은 되돌리고 실수에 따라 점수/보너스를 조절한다. 마지막 단계 완료가 세트의 종료다.
- 타이핑은 첫 입력 시작·완료 결과 유지·다음 연습 전환 정책을 보존한다. 검정의 제한시간과 기록을 없애거나 개념 점수로 바꾸지 않는다.
- 운영 설정·기존 학생 기록을 자동 삭제하거나 기존 점수를 새 규칙으로 소급 재채점하지 않는다.

## 2. 공통 학습 흐름

### 모드와 기록

| 모드 | 행동 | 기록 원칙 |
| --- | --- | --- |
| 안내 연습 | 방법과 기준을 보고 한 단계씩 수행 | 도움 사용·수정 과정, 경쟁 순위 제외 |
| 독립 연습 | 기준/문제만 제시, 제출 후 근거와 수정 기회 | 첫 답과 최종 답 구분, 재시도 자체 감점 없음 |
| 평가 | 서버 발급 미학습 변형, 제출 전 정답 힌트 없음 | 첫 답·규칙 버전·문제 버전 고정, 제출 후 피드백 |

기존 아케이드 순위는 별도 유지한다. 개념 평가에서 반응 속도로 정답 점수를 차등화하지 않는다. 타이핑 속도·카드 기억력·데이터 추론 점수를 합쳐 하나의 학업 성취 점수로 표시하지 않는다.

상태 전이는 `준비 → 풀이 → 제출 중 → 결과 → 수정 또는 다음 문제 → 세트 결과`로 통일한다. 제출 실패는 답을 보존하고 재전송하며, 중복 클릭으로 기록이 늘어나지 않아야 한다. 결과 화면은 사용자가 다음 문제를 요청할 때까지 유지한다. 이는 새로운 문항형 활동의 기준이며 기존 타이핑 전환을 다시 바꾸는 지시가 아니다.

피드백은 단순 '오답' 대신 틀린 행·열·단계와 대응하는 근거를 보여준다. 예: 'A는 재고 3개이므로 3개 미만 조건에서 제외됩니다.' 정답을 본 후 수정한 답은 첫 시도 정답률에 합산하지 않는다. 서술형 근거는 선택형 근거 코드로 기본 구현하고, 자유 서술은 교사 검토용으로 보존하되 자동 정오 판정을 보장하지 않는다.

### 화면·접근성

- 원본 표와 결과 표를 분리한다. 원본 값에 덮어쓰지 않고 선택·대체·제외·추정 상태를 별도로 표현한다.
- 도구에는 기존 아이콘 체계를 쓰고, 값은 숫자 입력, 방법은 선택 메뉴, 모드는 탭, 열 선택은 체크박스로 제공한다. 불필요한 설명용 카드나 홍보형 화면을 추가하지 않는다.
- 색만으로 정오·A/B·선택 여부를 표현하지 않는다. 모양/문자/테두리를 함께 쓰며 축 이름·단위·정확한 수치를 텍스트로 읽을 수 있어야 한다.
- 표는 키보드로 셀 이동·선택·입력할 수 있고 포커스가 보인다. 모바일에서는 표 영역 내부만 스크롤하며 페이지 전체 가로 넘침이 없어야 한다.
- 허브·게임 상세는 기존 1120px 중앙 정렬 정책을 유지한다. 360px, 768px, 1280px, 1440px 화면에서 긴 한국어·숫자·툴팁 겹침을 검사한다.
- 연습은 시간 제한 완화/해제 가능. 소리·빠른 애니메이션이 필수 단서가 되지 않으며 `prefers-reduced-motion`을 존중한다.

## 3. 게임별 작업

### 데이터 추출: 결과 표를 실제로 생성

화면: 원본 → 출력 열 선택 → 조건/정렬/집계 설정 → 결과 미리보기 → 제출. 입문은 조건에 해당하는 행을 직접 선택하고, 다음 단계는 구조화된 필터를 조합한다. 임의 SQL이나 코드를 실행하지 않는다.

채점은 출력 열, 결과 행 집합, 필요한 경우 행 순서, 계산값을 별도로 검사한다. `null`은 0으로 변환하지 않는다. `lt/lte/gt/gte/eq/notNull`, AND를 먼저 구현한다. 정렬 동률의 보조 키를 명시하고 분모 0은 별도 정책 없이는 출제하지 않는다. 집계 결과는 원본 행 ID 목록이 아니라 그룹 키와 결과 값으로 비교한다. 열 순서도 평가하는 문제라면 지시문에 명시한다.

출제 목표: 6유형 × 4문제 = 24개. 현재 준비한 6개를 기준으로 서로 다른 경계·단위·원본 행 수를 갖는 변형을 만든다. 단순히 이름·숫자만 바꾼 문제는 새로운 유형으로 세지 않는다.

완료 기준: `extract-*` 6개를 학생 조작으로 실제 제출 가능. 재고 3/2/0, 150/151쪽, 잔량 동률, 분모, null, 빈 결과, 그룹 합계가 서버/화면에서 동일하게 처리된다. 학생 건강·집중도·소비 성향 단정 소재는 새 세트에서 제외한다.

### 결측값: 계산과 정책 선택 분리

안내 연습은 '평균으로 대체'처럼 규칙을 명시한다. 독립 연습은 자료 종류·이용 목적·결측 원인에 관한 정보와 허용 정책/근거를 제시한다. 근거만으로 유일한 선택이 나오지 않으면 복수 정책을 허용하거나 토론형으로 전환한다.

`action = impute | keep-unknown | recollect | exclude-for-this-analysis`를 구분한다. 제외는 해당 분석의 조건부 제외이며 원본 삭제가 아니다. 초안의 `leave`는 `keep-unknown`의 계산 예시다. 대체 칸은 `originalValue: null`, `estimatedValue`, `method`를 보존한다. 평균의 분모에서 null 제외, 중앙값의 짝수 처리, 최빈값 동률 정책, 보간 시간 간격, 소수점 자릿수·반올림 정책을 명시한다. 관측값을 잃지 않는다.

출제 목표 36개: 평균 6, 중앙값 6, 최빈값 6, 보간 6, 이전 상태 4, 미대체 4, 방법 비교 4. 이 중 일부는 안내 전용이다. 방법 비교에서는 같은 숫자가 나와도 정책 근거를 별도로 평가한다.

완료 기준: 초안 6개와 복수 정답 정책 2개를 모두 통과. `quiz-median`에 평균으로 7을 쓴 답을 근거 없이 오답 처리하지 않는다. 처음부터 빈 값인 상태 로그·양끝 없는 보간·최빈값 동률은 명시된 처리 없이 자동 출제되지 않는다. 추정 표시와 근거 선택의 학생 응답도 기록한다.

### AI 모델 훈련소: 관찰·실험·해석을 구별

출제 목표는 숫자 라벨링, 라벨 품질 시뮬레이션, 불균형 평가의 완결된 3활동이다. 단순 데이터 파일 개수를 늘리는 방식이 아니다.

1. 숫자 라벨링: 눈으로 확인 가능한 숫자 0·1·7로 시작한다. 모호한 그림은 '판단 보류'와 재검토를 허용한다. 보류율·판정한 항목의 정확도·전체 완료율을 각각 보고하여 전부 보류로 만점을 받지 못하게 한다. 연습 재시도 감점은 없애고 첫 시도와 학습 후 결과를 비교한다.
2. 라벨 품질 비교: 현재 사전 계산 방식을 유지하되 '정답 개수별 사전 실험 평균'이라는 사실을 결과의 데이터 속성으로 명시한다. 학생이 틀린 바로 그 항목으로 실시간 학습한 것처럼 표현하지 않는다. 반복 횟수·자료 수·데이터 분할·라벨 오염 방식·모델 매개변수·라이브러리 버전·seed를 버전별 메타데이터로 남긴다.
3. 평가 실습: 학습/검증/평가 분리, 혼동행렬의 축, 정확도·정밀도·재현율을 다룬다. 기본은 정답 수와 놓친 대상 수, 심화는 비율/F1이다. `model-*` 초안 두 개를 연결한다. 평가 데이터는 모델 선택 반복에 쓰지 않는다.

행렬 표시 정책은 출시 전에 하나를 정한다. 권장: 대표 실험 한 번의 정수 행렬과 같은 실험에서 계산한 지표를 한 묶음으로 표시하고, 반복 실험 평균/편차는 별도 필드로 표시한다. 평균 행렬을 사용할 경우 소수 기대 횟수와 '평균' 표기를 유지하며, 정수로 반올림해 실제 표본 수처럼 보여주지 않는다. F1의 실험별 평균과 평균 행렬에서 계산한 F1이 다를 수 있다는 점도 구분한다.

실제 실시간 학습으로 전환한다면 별도 승인 범위로 Python 작업 큐·타임아웃·동시 작업 제한·버전 고정·캐시를 설계한다. 이번 보강은 브라우저에 모델 훈련 기능을 임의 구현하는 계획이 아니다. scikit-learn 등 검증된 엔진을 사용한다.

타이타닉 라벨 추측은 기본 활동에서 제외한다. 기존 활동 기록과 ID는 보존하며 교사용 역사적 자료 해석으로 재사용할지 별도 결정한다. 사람의 생존/가치에 대한 규범적 판단으로 점수화하지 않는다. 전체 원본 데이터와 균형 추출 배치의 분포를 따로 제시한다.

완료 기준: `publicView()` 응답에 정답 라벨·성능표가 없음, 같은 정답 개수의 시뮬레이션 동작을 정확히 설명, 혼동행렬/표본 수/같은 실험 지표 일치, train-only 전처리, 평가 분할 ID 비중복, 재시도 기록 분리.

### 이상치: 선택 뒤에 검토 판단

화면: 판단 기준 확인 → 후보 선택 또는 '없음' → 유지/추가 확인/확인된 오류 수정 중 결정 → 근거 피드백. 오류 수정은 원래 값이 잘못됐다는 독립 근거를 준 경우에만 정답으로 사용한다.

출제 목표 36개: 허용 범위 12, IQR 12, 집단/맥락 12. 각 묶음에서 '없음' 3개 이상, 단일·다중 후보 혼합. IQR은 정렬 후 절반의 중앙값, 홀수 개일 때 전체 중앙값 제외라는 계산법을 고정한다. 다른 사분위수 정의를 섞지 않는다. 범위 경계에 등호가 포함되는지 명시한다.

원본 순서에 의미가 없으면 서버 발급 시 값과 안정적인 행 ID를 함께 섞는다. 시계열은 순서를 유지하고 후보가 앞·중간·뒤에 나오는 자료를 만든다. 위치를 섞은 뒤 배열 인덱스만 이전 정답으로 남는 버그를 검사한다.

완료 기준: 선택 0개로 '없음' 제출 가능, 범위 경계값 미선택, 극단값을 무조건 삭제하지 않는 근거 평가, 잘못 선택한 정상값과 놓친 후보를 구분한 결과. 초안 `outlier-*` 4개 통과.

### 데이터 시각화: 목적·구성·해석

화면: 원본 → 목적 확인 → 그래프 종류 → 축/열/단위/구간 설정 → 그래프 갱신 → 읽은 결과 제출. 그래프 렌더링은 현재 프로젝트 라이브러리를 우선 확인하고 지원이 부족하면 검증된 차트 라이브러리를 선택한다. 이미지 위 좌표를 임의 추정해 채점하지 않고 원본 수치와 설정으로 채점한다.

출제 목표 30개를 비교·시간 변화·전체 비율·분포·변수 관계·오해 유발 표현의 6묶음으로 재구성한다(각 5개). 기존 30개를 그대로 30개 추가했다는 의미가 아니다. 타당한 여러 그래프는 허용 목록과 축/단위 조건으로 인정한다. 출제 목적이 다르면 같은 자료도 다른 표현을 쓸 수 있다.

검사: 히스토그램 `[0,10), [10,20), [20,30]` 집계 합=관측 수, 전체 비율 분모·항목 비중복, 막대 길이를 비교하는 문제의 기준선, 증가량과 최댓값 구분, 관찰 자료만으로 인과 확정하지 않기. 초안 `viz-*` 4개가 직접 구성/결과 제출까지 가능해야 한다. 그래프 허용의 타당성은 교사가 함께 검토한다.

### 자료구조: 명령별 상태를 직접 구성

화면: 구조 방향 표시 → 현재 명령 → 넣기/꺼내기/조회 → 학생이 다음 상태 배치 → 결과 비교. 마지막 보기만 맞히는 모드 외에 매 단계 추적 모드를 둔다. 스택 바닥/top, 큐 front/rear, 우선순위 정렬 방향을 계속 표시한다.

출제 목표 36개: 각 구조 12개. 조회/삭제, 교차 삽입, 빈 구조, 우선순위 동률을 포함한다. 용량 제한 문제는 크기·초과 삽입 정책을 명시한 심화로만 제공한다. 빈 구조의 pop은 반환값 0으로 대체하지 않고 오류와 이후 진행 정책을 구분한다.

서버 핵심 연산은 PHP SPL의 `SplStack`, `SplQueue`, `SplPriorityQueue`를 검토한다. 우선순위 동률의 FIFO는 삽입 순번을 비교 기준에 포함해야 하며 기본 동률 동작에 의존하지 않는다. 자연어 명령 문자열을 파싱해 채점하지 않고 구조화된 연산 배열을 사용한다. 이번 Node 초안 검증기는 소수 예제의 오프라인 정답 확인용이며 운영 엔진이 아니다.

완료 기준: `structure-*` 4개에서 모든 중간 상태·반환값·오류 단계 일치, 키보드만으로 수행 가능, 잘못된 단계로 돌아가 복습 가능. 탐색·정렬을 구현하지 않은 상태에서 알고리즘 전 영역 완료로 표시하지 않는다.

### AI 분류 경계: 규칙 적용에서 예측으로

화면 좌표 눈금·단위·축별 변수명·경계선을 표시하고, 선택 점의 정확한 좌표와 `x >= 5` 같은 조건을 연결한다. 색과 함께 A/B 문자·서로 다른 마커를 사용한다. 축 스케일/정규화 여부를 데이터에 명시한다.

출제 목표 36개: 주어진 규칙과 경계 12, 학습점에 맞는 후보 규칙 12, 최근접 이웃 6, 새 점 검증·일반화 6. 주어진 규칙 적용을 모델 학습이라고 부르지 않는다. 규칙 찾기는 복수 규칙이 모두 설명할 수 있으면 복수 허용 또는 추가 관측 요청을 인정한다. 평가점 라벨을 보고 경계를 수정하면 그 점은 평가용으로 다시 쓰지 않는다.

초안의 최근접 이웃은 같은 단위의 2차원 제곱거리, k=3, 거리 동률은 ID순, A/B 다수결이다. 추후 엔진은 검증된 구현을 사용하고 거리 표/선택된 이웃을 함께 보여준다. 임의 단위의 건강·신용 수치를 현실 규칙으로 설명하지 않는다.

완료 기준: 기존 30개 분류 회귀 유지, 경계 위 점·축 반전·거리 동률 검증, `classifier-*` 2개 통과, 학습점과 새 점을 시각적으로 구별.

### 이미지 데이터: 인식 가능한 작은 그림

33개 현 자산을 먼저 심사한다. 목표는 인식 검사를 통과한 16×16 24개 이상과 입문용 8×8 12개다. 숫자를 맞추려고 식별되지 않는 그림을 유지하거나 단순 좌우 반전만 새 그림으로 세지 않는다. 8×8은 새 UI/데이터 지원이 필요한 계획이다.

우선 수정: 잎사귀는 대각 줄기와 한 장의 비대칭 잎 윤곽, 책은 펼친 두 면과 가운데 접힘, 연필은 명확한 흑연 끝과 몸통. 피자는 삼각 조각·윗면 토핑을 유지하되 이름을 가린 검사 대상에 포함한다. 정답 보기에 비슷한 실루엣만 무조건 묶지 않는다. 틀린 보기는 분야와 모양이 비교 가능하되 구별 근거가 있어야 한다.

결과 지표:

```text
그림 부분 정확도 = 목표 색이 배경과 다른 칸 중 맞힌 수 / 목표의 비배경 칸 수
배경 오염 = 목표가 배경인 칸에 잘못 찍은 수
전체 정확도 = 전체 칸 중 맞힌 수 / 전체 칸 수 (보조 정보)
완료 = 전체 칸 일치 AND 그림 정답 선택
```

전부 배경인 복원 문제는 만들지 않는다. 제작 모드의 흰색 그림은 허용하되 채점 대상으로 보지 않는다. 원본 배열·팔레트·크기를 포함한 내보내기/가져오기, 잘못된 길이·색상 ID 거부, 되돌리기 단위는 한 번의 드래그 동작으로 유지한다.

이름을 가린 5~8명 학생 파일럿에서 정답 명칭 또는 동의어 인식률 80% 이상을 일차 유지 기준으로 제안한다. 이는 아직 측정되지 않은 출시 기준이며 표본이 작아 일반화하지 않는다. 실패 그림은 수정/교체 후 재검사한다. 팔레트만 보고 색 구분이 어려운 학생도 숫자 코드로 작업할 수 있어야 한다.

## 4. 문제 계약과 서버 채점

### 초안의 의미

`seed-cases.json`은 `status: draft-not-runtime`이다. `grading`은 계산 정책, `expected`는 작성자 검증용 정답, `explanation`/`misconception`은 제출 후 피드백의 재료다. **이 파일을 그대로 브라우저에 전달하거나 현재 `samples`에 붙여 넣으면 안 된다.** 기존 렌더러·채점기는 이 계약을 해석하지 못한다.

| 필드 | 역할 | 배포 전 처리 |
| --- | --- | --- |
| `id`, `gameId`, `level`, `skill`, `kind` | 식별·학습 분류 | 버전 내 고유성/지원 유형 검사 |
| `prompt`, `data` | 학습자에게 제시할 문제 | 공개 필드 허용 목록으로 투영, 단위·행 ID 보완 |
| `grading` | 연산·정책·허용 정답 조건 | 서버 소유; 지시문에 필요한 기준만 별도로 공개 |
| `expected` | 작성자 정답/테스트 오라클 | 평가 세션 중 비공개 |
| `explanation`, `misconception` | 해설·오개념 | 제출 후 정책에 맞게 반환 |

안내 모드에서 평균 대체 정책을 지시하는 것과 계산 정답을 전달하는 것은 다르다. 단순 블랙리스트로 몇 필드를 지우지 말고 `publicQuestion` 허용 목록을 작성한다. 향후 실제 출제에 사용하는 답안 파일은 정적 공개 경로의 JSON으로 배포하지 않는다. 현재 문서 초안은 비운영 자료이며, 배포 패키지에서 문서/검토 파일을 제외하거나 운영 문제를 서버 비공개 저장소로 옮기는 절차가 필요하다.

신규 런타임 문제는 `contentVersion`, `rulesVersion`, `rubricVersion`, `conceptTags`, `estimatedDifficulty`, `source/provenance`를 갖도록 한다. 기존 문제와 기록에는 `legacy` 버전을 부여하는 비파괴 마이그레이션을 설계한다. 점수 규칙이 바뀌면 다른 버전의 순위를 직접 합치지 않고 허브/순위에 버전과 모드를 표시한다.

### 코드 책임

| 위치 | 책임/변경 범위 |
| --- | --- |
| `src/Games/Modules/{Game}/` | 문제와 순수 도메인 판정, 모듈별 허용 정책, 공개 문제 투영 |
| `src/Games/Contracts/Game_Module.php`, `Game_Module_Registry.php` | 기존 등록 계약 유지; 새 문항형 채점용 선택적 계약을 필요한 범위에서만 도입 |
| `src/Scoring/Quiz_Scorer.php` | 문항별 판정을 모듈 채점기로 위임하고 점수·첫 시도·순서를 집계 |
| `src/Scoring/Score_Validator.php` | 버전·타입·범위 검증, 구버전/신버전 경로 분리 |
| `src/Rest/Controllers/Games_Controller.php`, `src/Sessions/` | 평가 문제 발급, 문제/학생/세션 결합, 재전송·중복 저장 제어 |
| `src/Games/Modules/AI_Model_Lab/` | 기존 전용 세션/API·비공개 데이터 계약 유지, 활동별 평가 정책 |
| `src/Blocks/*_Renderer.php`, `blocks/{game}/view.js`, `style.css` | 조작 UI·키보드·피드백; 최종 점수의 권위 없음 |
| `src/Statistics/`, `src/Rankings/`, `src/Addon/` | 버전별/모드별 통계, 교사에게 학습 지표 제공 |
| `tests/`, `scripts/edu-game/` | 문제 계약·서버 판정·브라우저 계약·생성 데이터 재현 검사 |

제안하는 순수 판정 결과는 `correct`, `checks`(열/행/값/순서 등 항목별), `feedbackCodes`, `maxPoints`, `earnedPoints`다. 초안 검증기의 함수들을 그대로 PHP로 복사하지 말고 먼저 공통 계약/단위 검사를 확정한다. 기존 6개 문항형의 일괄 채점과 아케이드 기록은 새 모듈 이관 전까지 유지한다. 모든 모듈을 한 번에 재설계하지 않는다.

평가는 서버에서 문제 버전·문제 ID·seed·순서를 발급하고 세션과 연결한다. 클라이언트가 보낸 정답표/정오 여부/점수를 신뢰하지 않는다. 서버 채점이 있어도 전체 플레이 이력을 클라이언트가 임의로 만들 수 있으면 부정행위 증명은 불완전하다. 따라서 순위 공개 조건에 서버 발급·답안별 검증을 포함한다.

저장 후보: `gameId`, `contentVersion`, `rulesVersion`, `mode`, `skillTags`, `questionId`, `firstAnswer`, `finalAnswer`, `firstCorrect`, `finalCorrect`, `hintUsed`, `retryCount`, `elapsedMs`, `feedbackCodes`. 학생/반 식별자는 플랫폼의 기존 권한 모델을 사용하고 브라우저가 임의 지정한 반 ID를 신뢰하지 않는다. 큰 원본 표/정답 데이터를 매 답안에 중복 저장하지 않는다.

## 5. 개발 순서와 승인 기준

다음은 파일 단위 작업 티켓이다. 앞 단계가 통과하지 않으면 다음 단계의 평가 출제를 열지 않는다.

| 순서 | 작업 | 산출물/완료 기준 |
| --- | --- | --- |
| 1 | P0 콘텐츠 확정 | 담당 교사의 추출·결측·AI 루브릭 검토, 소재/복수 정답/설명 승인 |
| 2 | 새 문항 계약 | 공개/비공개 필드 테스트, 버전 규칙, 모듈 판정 결과 타입, 구버전 호환 검사 |
| 3 | 추출·결측 UI/채점 | 결과 표·미대체·복수 정책 직접 제출, 초안 12개 PHP/JS 일치, 원본 보존 |
| 4 | AI 활동 전환 | 라벨링과 시뮬레이션 구별, 동일 실험 지표, 분할/전처리 재현, 전용 API 회귀 |
| 5 | P1 직접 활동 | 이상치 없음, 그래프 구성, 자료구조 상태, 분류 좌표/이웃, 픽셀 지표 |
| 6 | 문제 은행·자산 확장 | 위 게임별 목표의 유형·난이도 충족, 라벨 가린 그림 검사, 사진 권리 확인 |
| 7 | 통계·수업 검증 | 첫 시도/재시도·버전 분리, 실제 반별 권한, 브라우저/부하 검사 |
| 8 | 단계 공개 | 기존 공개 설정에서 검증된 게임만 교사가 오픈, 새 세트 롤백 경로 확인 |

새 문제가 미지원 입력 유형을 요구하면 출제를 차단한다. 지원되지 않는 문제를 객관식으로 임시 변환하거나 정답을 클라이언트에 내려서 자동 통과시키지 않는다. 시작 시 '문제 부족'을 감지하고 세션 생성 전에 안내한다. 새 버전의 문제/기록을 보존하면서 이전 버전 공개로 돌아갈 수 있어야 한다.

### 자동 검사

- 초안 검증: 28개 계산/중간 상태, 잘못된 기대값·중복 ID·미지원 유형·0 분모·분할 중복 등 거부.
- 운영 모듈 검사: 같은 초안으로 PHP 실제 채점과 브라우저 응답 계약을 연결한다. 현재 초안 검사는 이를 아직 대신하지 않는다.
- 생성기 검사: 고정 seed 집합에서 단위·범위·고유 ID·복수 타당 답·출제 위치 분포 검사. 랜덤으로 한 번 성공했다고 완료하지 않는다.
- 기존 회귀 유지: 공개/비공개, 페이지 보존, 세션 1회 저장, 점수 재계산, 분류 규칙, 기존 게임 진행.
- 브라우저 검사: 실제 블록/숏코드/허브 경로에서 시작·제출·실패 재시도·결과 유지·다음 문제, 모바일 표/캔버스 표시·키보드 수행·파일 가져오기 오류.

### 30명·6개 반 운영

180개 테스트 계정을 6개 반으로 구성하고 한 반 30명 동시 시작·제출을 필수 리허설로 한다. 6개 반을 순차 운영하는 요구와 180명 완전 동시 접속은 구분한다. 후자는 확장 스트레스 검사이며 성능을 미리 보장하지 않는다.

검사할 사항은 다른 반 기록 접근 차단, 교사의 담당 반 범위, 개인 기록 분리, 네트워크 재시도 시 중복 없음, 한 학생의 중복 탭, 수업 중 게임 비공개 변경, 세션 만료, 장치 이미지/데이터 캐시다. 키 입력/픽셀 변경마다 서버 기록을 보내지 않고 의미 있는 제출 단위로 저장한다. 실제 호스팅 환경에서 API 지연 p50/p95·오류율·DB 부하를 측정한 후 허용 수치를 정한다.

교사 보고서는 기능별 첫 정답률, 대표 오개념, 도움 사용, 수정 후 개선을 우선한다. 학급 공개 순위에는 필요한 최소 표시명만 사용하고, 학생 간 점수보다 개인 학습 이력을 먼저 보여준다. 보존 기간·삭제 권한·동의 절차는 운영 정책으로 확정한다.

## 6. 남은 결정

대상 학년, 수업당 활동 시간, 개념 평가의 공식 성적 반영 여부, 실제 서버 자원, 사진 재사용 조건은 아직 확정하지 않았다. 이 항목들은 연습 모드·합성 자료·기존 환경을 기본값으로 개발 준비를 진행하되, 공식 평가와 대규모 공개 전에 확인한다. 신규 게임 전체를 배포 가능한 것으로 표시하는 기준은 위 코드 검사와 학생/교사 파일럿을 모두 통과하는 것이다.
