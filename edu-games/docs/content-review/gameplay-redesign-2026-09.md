## 판단 기준

문제를 맞히면 점수·배지를 주거나 말을 한 칸 움직이는 것만으로 보드게임이 되지는 않는다. 학생의 선택이 보드의 배치, 다음에 가능한 행동, 확보한 정보, 남은 자원을 바꿔야 한다. 학습 개념을 이해하는 것이 더 나은 전략을 만드는 데 직접 쓰여야 한다.

공통 인수 기준:

1. 첫 화면에서 현재 판과 이번 도전의 목표가 보인다.
2. 학생이 답란을 채우는 것 이외의 유의미한 행동을 선택한다.
3. 선택의 결과가 즉시 판에 나타나고 이후 행동에 영향을 준다.
4. 승리·실패 또는 명확한 완주가 있으며 결과를 확인한 뒤 재도전한다.
5. 같은 판의 숙련 목표와 다른 판을 열어 가는 목표를 구분한다.
6. 사고·탐구 게임에는 무조건 빠른 답을 요구하지 않는다. 속도는 타이핑·반응형 아케이드에만 주된 목표로 쓴다.
7. 게임 점수와 개념 평가를 분리한다. 높은 게임 점수를 학업 성취도 전체로 해석하지 않는다.

## 이번 구현: 자료구조 물류 기지

- 화물 A~F는 정해진 순서로 입고된다. 출고 주문은 다른 순서다.
- 학생은 입고, 출고, 다른 보관함으로 옮기기 중 하나를 선택한다. 임의의 중간 화물을 클릭해서 꺼낼 수는 없다.
- 스택은 LIFO, 큐는 FIFO다. 우선순위 큐는 큰 숫자부터 꺼내며 동률은 해당 보관함 입고순이다. PHP SPL로 실제 연산한다.
- 각 보관함은 2~3칸이다. 제한된 공간에서 미리 배치를 계획해야 한다.
- 이동은 에너지 1을 사용한다. 잘못 출고하면 화물을 버리지 않고 에너지 1과 실수 1을 기록한다.
- 되돌리기는 최대 3회다. 배치만 복원하며 이미 사용한 에너지와 실수는 복원하지 않는다. 되돌리기도 에너지 1을 사용한다.
- 모든 주문을 출고하면 승리한다. 에너지를 소진하면 실패한다. 마지막 에너지로 마지막 출고를 마치면 승리다.
- 에너지는 구역의 최단 이동 수 + 10이다. 시간 제한은 없다.
- 점수는 `max(100, 1000 - 25 × 최단 대비 초과 이동 - 80 × 오출고 - 100 × 되돌리기)`다. 실패는 0점이다.
- 별은 975점 이상 3개, 850점 이상 2개, 그 밖의 완주 1개다. 1개 이상이면 다음 구역이 열린다. 모든 구역의 최단 기록은 1,000점이다.
- 12개 구역 전체에 대해 너비 우선 탐색으로 최단 해법을 계산했다. 최단 탐색은 개발용 스크립트에서만 실행하며 학생의 이동 API에서는 실행하지 않는다.
- 12구역은 유한한 캠페인이다. 임의의 글자 교체를 새 콘텐츠로 집계하거나 무한한 새 판이라고 주장하지 않는다. 모든 별을 모은 뒤에도 최단 기록을 개선할 수 있다.

규칙·보드·상태 전이: `src/Games/Modules/Data_Structure_Lab/Warehouse_Board.php`.
최단 해법: `warehouse-solutions.php`, 생성기: `scripts/edu-game/build-warehouse-solutions.php`.

서버가 잠금·이동·점수·별을 판정한다. 토큰은 사용자·게임·버전·2시간 만료에 결합하고 revision 조건부 저장과 요청 ID 재시도를 사용한다. 순위는 같은 구역·버전의 최고 점수로 비교하며 동점은 공동 순위다. 빠른 네트워크 응답 시간에 보너스를 주지 않는다.

## 이번 구현: 기존 게임의 목표

### 이미지 도감

정확한 픽셀 배열과 올바른 이름을 모두 맞혀야 수집된다. 부분 복원, 이름만 맞히기, 직접 만들기에서는 수집되지 않는다. 동일 그림을 반복해도 수집 수는 늘지 않는다. 현재 크기에서 아직 수집하지 않은 그림이 우선 나오며, 수집한 그림만 도감에 이름과 축소 이미지가 열린다. 사용자가 복원할 정답 그림을 직접 고르는 방식으로 바꾸지 않았다.

### 타이핑

짧은·긴 코드 연습은 같은 언어·모드·예제의 완료 기록을 비교한다. 정확도 97% 미만은 CPM 최고 목표 기록에 넣지 않는다. 검정은 같은 언어·제한시간의 종료 기록을 비교한다. 검정 중 이어 나오는 코드가 달라질 수 있으므로 동일 시험지 순위나 공식 인증으로 해석하지 않는다. 적어도 50자 또는 그보다 짧은 예제 전체를 작성해야 속도 목표 기록 대상이다.

키워드는 제출 시 정확도 100%인 완료가 이어질 때 연속 수가 증가하고, 최종 입력에 오류가 남으면 현재 연속 수가 0이 된다. 기존 정확도는 최종 입력 기준이므로 중간에 수정한 오타까지 없었다는 뜻은 아니다. 언어를 바꾸면 현재 연속 수를 새로 시작한다. 최고 기록은 보존한다. 다음 목표는 연속 5개 단위, CPM은 20 단위이며 코드 길이와 1초 최소 측정 시간으로 정해지는 측정 상한을 넘지 않는다. 첫 글자 시작, 완료 후 결과 유지, Space로 다음 예제 준비, 검정 타이머는 유지했다.

### 카드 매칭과 아케이드

카드 매칭은 기존 6·8·10·12쌍과 뒤집기 애니메이션을 유지한다. 실수 횟수 때문에 게임을 중단하지 않는다. 먼저 별 12개를 목표로 하고, 이를 모은 뒤에는 한 번의 전체 완주에서 오답을 줄이며 무오답 완주에 도전한다. 뒤집힌 카드의 접근성 이름에 정답 장치 이름이 노출되지 않도록 수정했고, 맞힌 카드는 키보드 탐색에서도 제외한다.

후속 보강으로 센서 9종·액추에이터 5종과 실제 사진을 추가해 카드 풀을 24종에서 38종으로 늘렸다. 한 도전에서는 미출제 장치를 우선 추출하여 36쌍이 모두 다른 장치로 나온다. [추가 목록과 검증](device-expansion-2026-09.md)에 이번 변경을 따로 기록했다.

이진수·문자 암호·키워드 레인은 기존 낙하·생존·콤보의 게임성을 유지하면서 다음 점수 목표를 표시한다. 문자 암호의 문항별 타이머 최소 한계와 오답·시간 초과 종료는 변경하지 않았다.

**저장 범위:** 이번에 추가한 이미지 도감·타이핑 목표·카드 별 목표·아케이드 목표는 로그인 사용자별로 나눈 **이 기기 기록**이다. 다른 PC로 자동 동기화되지 않으며 브라우저 저장소를 지우면 사라진다. 기존 서버 점수·검정 기록과 물류 보드 진행은 별도로 서버에 저장된다. 예전 공용 localStorage 기록을 새 학생에게 임의 귀속하지 않고 읽기 키를 분리했다. 계정 간 공용 기록은 삭제하지 않았다.

## 전체 개편 설계: 후속 확장 포함 6종

아래는 전체 목표 설계다. 일인용 84판과 작업판 다중화·산점도·잡음 경계·분포 변화까지 구현했다. 실제 판정은 아래 설명보다 [현재 규칙 보고서](strategy-full-release-2026-09.md)를 우선한다. 실시간 다인전은 이번 범위에 포함하지 않으며 학급 부하·접근성 검증 뒤 별도로 다룬다.

### 1. 데이터 추출: 주문 처리 보드

형식은 계약 카드와 처리 경로를 조합하는 물류 퍼즐이다. 상품·관측 자료 카드가 보드에 놓이고, 주문 슬롯마다 서로 다른 조건과 정렬 요구가 있다. 학생은 어느 주문을 먼저 처리할지 정하고 필터·정렬·집계 처리기를 경로에 놓는다. 처리기를 실행하면 실제 데이터 카드가 이동·분기·묶인다. 답 문자열은 입력하지 않는다.

- 자원: 보관 슬롯 4개, 처리 에너지, 한 턴에 설치할 처리기 수. 하나의 필터를 여러 주문에 재사용하는 전략이 가능하다.
- 승리: 모든 주문을 잘못된 항목 없이 출고. 실패: 처리 에너지 소진 또는 주문 슬롯 봉쇄.
- 점수·재도전: 적은 처리 비용, 중간 결과 재사용, 별 수집. 같은 초기 보드끼리 비교한다.
- 학습 연결: 조건 AND, 정렬 동률 규칙, 필요한 열 선택, 그룹 집계가 실제 카드 흐름을 바꾼다.
- 초기 콘텐츠: 기본 필터 6판, 다중 주문·정렬 6판, 집계·결측 포함 6판. 해법이 있는 초기 배치를 생성·검증한다.

### 2. 결측값: 관측망 복구 보드

형식은 제한된 복구 도구로 운영 상태를 유지하는 협력형 퍼즐의 일인용 버전이다. 시간축 관측 타일과 지역 노드가 연결된 보드에서 결측이 발생한다. 재측정, 전후 보간, 대표값 대체, 이전 상태 유지, 미확정 보류 카드를 배치한다. 처리한 값과 추정 표시는 다음 관측 턴·예측 경로에 실제 반영된다.

- 자원: 재측정권, 처리 카드, 유지 예산. 확실한 관측을 얻는 비용과 추정하는 비용이 다르다.
- 승리: 제한 턴 뒤 필수 관측망을 유지하고 근거 없는 확정값을 만들지 않음. 실패: 중요 노드의 불확실성이 허용 범위를 넘음.
- 점수·재도전: 데이터 품질을 충족한 해법 중 남긴 예산, 재측정 배분, 새 지역 개방. 빠른 계산에는 보너스를 주지 않는다.
- 학습 연결: 연속형·범주형·상태형·급변 구간에 따라 합리적인 복구 방법이 달라진다. 보류도 정당한 전략이다.
- 초기 콘텐츠: 자료형 3종 × 상황 4종 = 12판. 복수 타당한 방법은 비용·불확실성 차이로 평가하고 하나의 임의 정답만 강요하지 않는다.

### 3. 이상치: 관측소 조사 보드

형식은 증거를 모아 판단하는 수사·추리 보드다. 측정 카드 중 실제 입력 오류, 센서 고장, 정상적인 드문 값이 섞여 있다. 학생은 조사 토큰으로 단위, 기기별 정상 범위, 인접 시점, 재측정 기록을 공개한 뒤 유지·표시·격리 영역으로 옮긴다. 처음부터 오류의 정체를 보여 주지 않으며 통계적 극단값이라는 이유만으로 삭제하는 전략이 유리하지 않다.

- 자원: 조사 토큰, 재측정 횟수, 오격리 허용량. 어떤 증거를 먼저 확보할지가 핵심 선택이다.
- 승리: 위험한 실제 오류를 처리하면서 정상 자료를 지킴. 실패: 오격리 과다 또는 미해결 중요 오류로 조사 종료.
- 점수·재도전: 정상 자료 보존, 오류 탐지, 조사 효율. 같은 사건 파일에서 조사 횟수를 줄인다.
- 학습 연결: IQR은 후보 탐지 도구이며 삭제 판정이 아니다. 집단별 기준, 단위, 맥락을 증거로 사용한다.
- 초기 콘텐츠: 오류 없음 포함 사건 12개. 해법에 필요한 증거를 조사 예산 안에 얻을 수 있는지 자동 검증한다.

### 4. 데이터 시각화: 차트 타일 공방

형식은 자원 타일을 배치해 주문을 완성하는 제작 게임이다. 원자료 카드와 미션이 주어지고, 학생은 축·범주·막대·구간·점 타일을 작업판에 배치한다. 같은 자료를 여러 관점으로 전달할 수 있으며, 선택한 축과 구간은 실제 그래프 모양을 바꾼다. 마지막에 차트 이름을 고르는 객관식 활동으로 끝내지 않는다.

- 자원: 작업판 수, 표현 타일, 수정 횟수. 필요한 메시지를 여러 차트로 분담하거나 한 차트에 통합한다.
- 승리: 미션의 비교·추세·분포·관계를 왜곡 없이 전달. 실패: 누락·왜곡 기준 위반 상태로 제작 종료.
- 점수·재도전: 메시지 충족과 정확성 우선, 불필요한 구성 감소를 보조 목표로 사용. 차트 외형 취향은 정답 기준이 아니다.
- 학습 연결: 시간 순서, 비율 합계, 히스토그램 구간, 산점도 관계, 기준선의 효과를 타일 조작으로 경험한다.
- 초기 콘텐츠: 6목적 × 3자료 = 18미션. 허용 가능한 여러 차트 구성을 서버 규칙으로 검증한다.

### 5. 분류 경계: 분류 구역 설계

형식은 격자 위에 울타리와 관측 지점을 놓는 영역 퍼즐이다. 학생은 숫자가 표시된 평면에 경계를 배치하고, 어느 지역의 추가 표본을 조사할지 선택한다. 경계를 옮기면 A/B 구역과 분류 결과가 즉시 바뀐다. 경계 개수를 늘리면 훈련 자료를 더 잘 맞힐 수 있지만 유지 비용이 커진다.

- 자원: 경계 조각, 표본 조사권, 유지 비용. 복잡한 경계와 단순한 경계 중 선택한다.
- 승리: 정해진 검증 성능을 비용 한도 안에서 달성. 실패: 조사·설치 예산 소진 시 성능 기준 미달.
- 점수·재도전: 성능 하한을 충족한 상태에서 경계 복잡도와 조사 비용 최소화. 최종 시험 표본을 반복 노출해 외우게 하지 않는다.
- 학습 연결: 분류 규칙, 임계값, 경계 위 포함 규칙, 최근접 이웃, 과적합·일반화를 실제 공간 조작에 연결한다.
- 초기 콘텐츠: 축 평행 경계, 다중 경계, 잡음 포함, 편중 표본 각 3판. 모든 좌표·단위·눈금과 경계 포함 방향이 명확해야 한다.

### 6. AI 모델: 모델 운영 전략 게임

형식은 예산과 라운드를 사용하는 연구소 운영 게임이다. 학생은 데이터 수집, 라벨 검수, 모델 선택, 훈련, 검증에 자원을 배분한다. 매 라운드 실행 결과가 다음에 가능한 행동과 예산에 영향을 준다. 단순히 세 모델 중 정답 하나를 선택하는 활동이 아니다.

- 자원: 데이터·검수·훈련 예산, 3~5라운드. 저렴한 많은 데이터와 적지만 검수한 데이터 사이의 선택을 제공한다.
- 승리: 임무별 성능·공정한 클래스별 품질 기준을 충족. 실패: 예산 소진 후 기준 미달.
- 점수·재도전: 정확도 또는 매크로 F1 하한 충족 후 비용 효율, 서로 다른 임무·데이터 특성의 개방. 불균형 자료에서는 전체 정확도만 보상하지 않는다.
- 학습 연결: 라벨 품질, 표본 대표성, 모델의 차이, 훈련·검증·최종 평가 분리를 의사결정으로 경험한다.
- 초기 콘텐츠: 균형·불균형·노이즈·분포 변화 임무 각 3판. 검증 피드백과 최종 비공개 평가를 분리하고 동일 실험의 혼동행렬·지표를 사용한다.
- 구현 선행 조건: 현재의 정답 개수별 사전 계산표만으로는 이 전략을 표현할 수 없다. 자료 구성·검수 정책·모델·예산 조합의 재현 가능한 실험 은행이 먼저 필요하다. 실시간 훈련이나 서로 다른 표본 실험을 같은 결과처럼 표시하지 않는다.

## 후속 구현 순서와 검수

1~3의 보드 개편과 84판 확장은 완료했다. 4의 기존 기기 기록 동기화·교사 학급 집계는 보드 콘텐츠 확장과 분리한 후속 범위로 남아 있으며, 이번 확장 완료에 포함하지 않는다.

1. 이상치·결측값: 조사/복구 자원과 상태 전이를 먼저 만든다. 기존 문항은 설명·연습으로 이동한다.
2. 데이터 추출·시각화: 카드 흐름과 타일 배치의 복수 해법을 구현한다.
3. 분류 경계·AI 모델: 공간 조작·예산 전략과 재현 가능한 실험 은행을 구현한다.
4. 각 게임의 기기 내 도감·목표를 서버 계정 기록으로 동기화하고, 학급별 교사 집계에 게임 성취와 개념 평가를 분리해 추가한다.

각 게임은 규칙을 모듈 클래스에, 상태와 점수 판정을 서버에 둔다. 버전·보드 ID·난이도가 같은 기록만 비교한다. 중단·재시도·중복 제출·다중 창 충돌을 처리한다. 기존 최고점·평가 기록을 새 기준으로 재채점하지 않는다.

출시 전 필수 검사: 모든 판의 해결 가능성, 자원 한도의 타당성, 최소 두 가지 유효 전략 또는 실제 계획 선택, 오답을 반복해 이득을 얻는 경로 없음, 키보드·터치·마우스, 360~1440px 배치, 결과 유지, 사용자 간 기록 분리, 같은 버전 순위, 30명 동시 제출과 6개 반 명단 권한 검증.

교사 검토와 학생 파일럿에서 '정답 칸 찾기' 대신 선택 이유와 다음 수를 설명할 수 있는지 확인한다. 보드 모양이나 클릭 수만으로 게임성을 승인하지 않는다.
