# Focus Tracker 설계 (1.0.0-rc.3)

## 1. 측정 대상과 해석

화면이 보인다는 사실은 주의를 기울였다는 증거가 아니며, 입력이 없다는 사실도 집중하지 않았다는 증거가 아닙니다. 반복 수정이나 버튼 클릭만으로 학습의 질을 판단할 수도 없습니다.

UI는 `화면 활성률`, `입력·제출 활동률`, `참여 지표`로 표현하고 명단을 점수로 서열화하지 않습니다. 읽기·사고 중심 활동은 입력·제출 가중치를 0으로 둘 수 있습니다. 교사는 풀이 결과, 설명, 수업 관찰과 함께 판단해야 합니다. 지표를 확정 성적으로 자동 전환하는 기능은 없습니다.

## 2. 플랫폼 연결

OJ Platform 2.3.22 / Addon API 1.4의 `siteAsset`을 사용합니다. PHP 8.3 이상과 WordPress 6.6 이상이 필요합니다. 현재 사용자 권한과 요청 경로를 확인해 `focus-tracker-config` JSON과 추적 번들을 등록하며, 플랫폼 `HtmlDocumentRenderer`가 직접 출력합니다. WordPress 테마 훅에 의존하지 않습니다. 테마 화면의 enqueue도 동일한 설정 제공 함수를 씁니다.

설치 하위 경로와 `oj_route`를 정규화하고 문제 번호는 경로 또는 `/submit?problem_id=...`에서 읽습니다. 컨텍스트와 명단은 공개 Addon Context Gateway로 끝까지 조회합니다. 부분 실패·반복 커서는 완성된 명단으로 취급하지 않습니다.

## 3. 클라이언트와 전송

- 페이지 로드마다 `session_uid`, 이벤트마다 증가하는 `seq`를 만듭니다. BFCache 복원도 새 세션입니다.
- 초기 상태와 상태 변경·heartbeat에는 가시성과 포커스 스냅샷을 보냅니다. heartbeat는 15초마다 시도하며 숨겨진 상태도 포함합니다. 브라우저의 백그라운드 타이머 제한으로 주기는 보장되지 않습니다.
- Ace의 원래 textarea input, 일반 코드 입력, `completion_answers[...]`, Blockly 모델 변경, 실제 `[data-oj-submission-form]` 제출을 기록합니다. 연속 입력은 800ms 단위로 기록하고 이동 전 마지막 신호를 반영합니다. 클릭은 제출 성공이나 정답을 증명하지 않습니다.
- 활동 이벤트에는 코드 원문·키 입력 내용·페이지 URL·다른 사이트 내역을 넣지 않습니다. 서버도 허용한 상태·이벤트 종류·길이 변화만 저장합니다. 자동 확인의 초안 일시 전송은 아래 별도 흐름을 사용합니다.
- 서버 시각과 단조 시계로 클라이언트 시계 차이를 줄입니다. 서버는 시각 범위·소유자·문제 번호·시작 시각을 검사하지만, 악의적인 클라이언트 이벤트 위조까지 증명할 수는 없습니다.
- 로그인 사용자와 REST 주소별 localStorage 대기열에 보관합니다. 정상 HTTP와 `acknowledged:true`를 확인해야 삭제합니다. 종료 beacon이 큐에 들어갔다는 사실만으로 삭제하지 않습니다.
- 대기열은 최대 1,000건/24시간이며 한도 초과는 `queue_dropped`로 보고합니다. 저장소 사용 불가·강제 종료·장기 오프라인에서 완전한 수집을 보장할 수 없습니다.

## 4. 저장과 활동 귀속

활동용 다섯 테이블 `activities`, `participations`, `events`, `activity_links`, `scores`, 문항용 `checks`, `check_states`, 장기 통계용 `daily_statistics`를 사용합니다. 활동 연결 테이블은 하나의 브라우저 세션을 여러 활동에 연결합니다. 기존 `participations.activity_id`도 이전 자료 호환 경로로 읽습니다.

매 배치마다 관측 시간·현재 학습 컨텍스트·문제 번호에 맞는 모든 활동을 연결합니다. 수업 전 접속, 연속·중첩 활동도 첫 활동 하나에 고정하지 않습니다. 교사가 시간·문제를 변경하면 승인된 현재 명단의 기존 관측 자료를 다시 연결하며 계산은 현재 문제·시간에 일치하는 자료만 사용합니다.

이벤트의 `(participation_id, sequence_number)` 고유 키가 재전송 중복을 막습니다. 이벤트·heartbeat·종료·활동 연결·캐시 무효화를 트랜잭션으로 저장한 뒤 ACK합니다. 저장·활동 조회 실패는 ACK하지 않습니다. 새 삽입 수가 `event_revision`에 반영돼 같은 시각의 지연 이벤트도 구별합니다.

설치기는 필수 테이블·컬럼 확인 후 DB 버전을 갱신합니다. 비활성화는 데이터를 유지하고 플러그인 삭제는 여덟 테이블과 설정을 삭제합니다.

## 5. 구간과 점수

탭별로 시각·순번순 상태를 재구성해 `visible && focused` 구간을 만든 후 합집합으로 병합합니다. 다른 탭의 종료가 현재 탭을 덮어쓰지 않습니다. 수업 시작 전 상태를 이어서 적용하고 임의의 초기 활성 상태를 만들지 않습니다.

열린 세션의 최신 관측이 45초 이내면 현재까지 계산하고, 오래된 세션은 마지막 관측까지만 사용합니다. 나중에 heartbeat가 와도 중간의 45초 초과 활성 공백을 전부 활성으로 채우지 않습니다. 다른 탭의 관측된 활성 구간이 공백을 덮으면 누락으로 보지 않습니다. 점수와 그래프는 같은 함수를 사용합니다.

기존 가중치 규칙은 보존합니다.

1. 화면 활성률 = 활성 합집합 길이 / 활동 경과 시간.
2. 복귀 지표는 비활성 구간의 평균 복귀 시간에 구간표를 적용합니다. 최신 heartbeat를 완료된 이탈로 오해하지 않습니다.
3. 입력·제출 활동률은 기본 30초 창 중 활성 시간이 절반을 넘는 창에서 편집·실행·제출이 발생한 비율입니다. 비활성 탭의 입력을 다른 활성 탭의 작업으로 합산하지 않습니다.
4. 가중치를 곱해 합계를 0.5 단위로 반올림하되 가중치 합계가 상한입니다. 각 가중치는 0~100입니다.

진행 중에는 재계산하고 종료 45초 이후 집계를 캐시합니다. 계산기 버전·문제 목록·시간·가중치·설정·관측 시각과 이벤트 리비전을 검증합니다. 원시 자료가 남아 있으면 지연 이벤트를 반영해 재계산합니다.

## 6. 품질 상태와 보관

| 상태 | 의미와 표시 |
|---|---|
| provisional | 진행 중 또는 종료 직후, 값이 달라질 수 있음 |
| complete | 종료·유예시간 이후 계산 완료, 인지적 집중의 증명은 아님 |
| incomplete | 대기열 손실·관측 공백·일부 원시 자료 누락, 검토 필요와 지표 대시 표시 |
| no_data | 관측 자료 없음, 0점이나 미참여로 단정하지 않음 |
| unavailable | 원시 자료와 유효 집계가 없어 임의 점수 생성 금지 |
| archived | 최종 집계만 보관, 원시 타임라인은 표시하지 않음 |

원시 기록은 기본 60일 보관합니다. 삭제 전 연결된 모든 활동의 최종 집계를 강제 계산하고 **저장 성공을 확인**합니다. 미종료 활동, 저장·조회 오류, 일부 원시 자료 누락으로 안전한 최종 집계를 만들 수 없으면 삭제하지 않습니다. 보관된 집계에도 누락 여부를 보존합니다.

원시 자료 삭제 후 가중치를 바꿔도 과거 점수를 재구성하지 않습니다. 기존 집계를 유지하고 조건 변경은 검토 대상으로 표시합니다. 한 번도 점수표를 열지 않았더라도 정리 작업이 먼저 최종 집계를 만듭니다.

## 7. 테스트 경계와 남는 한계

계산기·서비스 회귀, SQL 저장/재전송/보존, 현재 플랫폼 렌더러/라우트/애드온 검증기, 실제 Chrome의 Ace/빈칸/Blockly/제출/오프라인/교사·학생 화면 검사를 제공합니다. 명령은 README에 있습니다.

플랫폼 UI·REST·저장소·계산기는 운영 소스를 사용하지만 WordPress 인증·컨텍스트는 대역이고 DB는 SQLite 어댑터입니다. 실제 WordPress 쿠키/nonce, MySQL dbDelta 업그레이드, 학교 서버 캐시·프록시는 별도 설치 검증 범위입니다.

설계로 줄인 것은 누락·중복·계산 오류·불확실성 은폐입니다. 학생이 이해했는지, 종이에 풀었는지, 의미 없는 편집을 했는지는 브라우저 로그로 확정할 수 없습니다. 자동 확인 결과도 해당 문항의 응답 근거이며 지속적 집중의 증명이나 정답률에 따른 집중 점수가 아닙니다.

## 8. 교사 개입 없는 자동 확인

클라이언트는 현재 문제의 활성 제출 폼만 읽습니다. Ace가 동기화하는 textarea, 모든 빈칸이 채워진 보이는 템플릿, 정상 생성된 Blockly Python을 UTF-8 64KB 이내에서 전송합니다. 미완성·숨겨진 모드·다른 문제·다른 입력 필드·외부 IDE는 읽지 않습니다. 초안을 잘라서 프로그램 의미를 바꾸지 않습니다. 초안이 없어도 서버가 본인의 제출·공개 문제 예제로 진행합니다.

플랫폼의 `AddonLearningCheckRuntimeContextV1::learningChecks()`가 현재 사용자·문제·수업/그룹/대회 접근을 확인합니다. 본인 제출만 조회하고 기존 제출 코드 공개 범위 및 대회 피드백 제한을 적용합니다. 비공개 테스트, 채점 래퍼, 오류 로그, 다른 학생 자료는 전달하지 않습니다. RC는 이 확장을 제공하는 플랫폼 2.3.22 이상만 지원합니다.

결정적 생성기는 코드의 독립된 정수 비교식에 새 정수 값을 모두 지정하거나, Python 내장 `range`의 제한된 리터럴 인자를 나열하게 합니다. 주석·문자열은 코드 후보에서 제외하며 지원하지 않는 문법·언어는 보수적으로 거부합니다. 공식 예제 문항은 해당 입력에 문제에서 **명시한 출력**을 묻습니다. 이것은 문제 전체를 이해했거나 학생 프로그램이 정답이라는 검증이 아닙니다. 외부 AI 호출·학생 코드 실행은 없습니다.

출제 전에 정답, 보기, 출처 해시와 표시 내용을 원본 후보에 결합해 재검증합니다. 검증 실패·서로 충돌하는 예제·후보 없음은 조용히 출제를 건너뜁니다. 브라우저 응답에는 정답·검증 근거·전체 원본을 포함하지 않습니다. 공개 문항과 검증 근거는 출제 시점의 스냅샷입니다. 이후 초안을 수정해도 문항에 명시된 값으로 답할 수 있으며, 문제 내용 변경·제출 접근 철회 시 문항을 취소합니다.

`checks`에는 문항 일부, 해시, 비공개 검증 근거, 응답과 허용된 활동 ID·시간 범위를 저장합니다. 전체 초안은 일시 분석 후 별도로 저장하지 않습니다. `check_states`에는 학생별 일일 발급 수와 다음 발급 시각만 저장합니다. 사용자별 잠금 트랜잭션으로 다중 탭의 중복 발급과 상한 경쟁을 막고, `response_uid`로 저장 후 재전송을 멱등 처리합니다. 기본 발급 간격 5분·하루 3개·10분 만료이며 활동 종료 시각이 더 빠르면 종료 시 취소합니다. 교사는 활동 시간만 설정하고 문항 제작·채점·수동 출제는 하지 않습니다.

정답, 오답, 모름, 건너뛰기, 무응답, 취소를 별도 상태로 보관합니다. 확인 문항 조작은 편집·실행·제출 이벤트가 아니며 어느 결과도 집중 점수 계산기에 들어가지 않습니다. 24시간 요약 역시 점수·학생 서열을 만들지 않습니다. 문항·응답은 별도 설정 기간(기본 60일) 후 삭제하고, 개인정보 항목을 플랫폼 통합 재고에 등록합니다.

## 9. 그룹별 시간표와 주간·월간 누적 통계

활동의 학급·그룹과 시작·종료 시각을 지정하고 그룹별 목록에서 시간 수정·조기 종료를 제공합니다. 일정의 현재 상태는 실제 시간 구간으로 표시합니다. 브라우저의 시간 입력은 명시적 UTC 오프셋으로 전송하고 API의 오프셋 없는 기존 입력은 사이트 시간대로 처리합니다. 종료한 활동의 재개·기간 연장과 원시 기록이 삭제된 활동의 평가 범위 변경은 막습니다. 그룹 시간표는 원시 수집·자동 확인 문항과 집계 범위 모두에 적용합니다.

학생은 별도의 참여 신청이나 시작 버튼을 사용하지 않습니다. 학생 역할(`subscriber`)에 추적 권한을 기본 부여해 기존·신규 학생이 상속합니다. 로그인·추적 권한·현재 학급/그룹 소속을 서버에서 확인하고, 지정 활동 시간과 문제 범위가 맞는 추적 대상 문제/제출 화면에서 자동으로 작동합니다. 자동 확인 문항에 응답하는 동작은 활동 참여 절차가 아니며, 응답하지 않아도 활동 기록은 계속되고 미집중으로 판정하지 않습니다.

`DELETE /activities/{id}`는 기능 관리 권한·작성자·현재 대상 관리 권한을 확인한 뒤 활동 행을 잠그고 삭제 상태로 전환합니다. 삭제한 활동은 목록·활동별 결과·최근 활동 요약·현재 및 지연 기록의 수집 승인에서 제외하고 수정·복구를 허용하지 않습니다. 진행 중 활동은 관측 종료를 삭제 시각까지 줄이고, 시작 전 활동은 유효 관측 구간을 0으로 만듭니다. 대기 문항은 같은 트랜잭션에서 원래 연결된 다른 활동의 유효 구간에 다시 연결하거나 취소합니다. 반복 삭제는 권한을 재확인한 후 성공으로 처리합니다.

활동 삭제는 학습 기록의 개인정보 삭제와 구분합니다. 통계 출처로 필요한 삭제 상태의 활동 행·연결·원시 기록·기존 문항 응답과 집계를 보관 정책에 따라 유지합니다. 통계 전용 과거 조회는 삭제한 활동도 포함해 주간·월간 누적과 다른 활동의 공유 기록을 보호합니다. 이미 원본이 만료된 긴 활동의 관측 종료가 변경되면 수치를 임의 재구성하지 않고 기존 보수적 불완전 표시를 유지합니다. 활동 삭제의 확인 화면에 보관 범위와 복구 불가를 명시하고 변경 이력을 남깁니다.

`GET /me/statistics`는 현재 학생 본인 전체 기록을, `GET /statistics`는 현재 교사의 열람 권한과 전체 명단을 재확인한 해당 학급·그룹 학생의 기록을 제공합니다. 교사 통계는 저장된 활동 연결과 해당 활동의 문제·시간 구간을 모두 확인합니다. 같은 문제·시간이라는 이유만으로 다른 그룹이나 소속 이전의 기록을 끌어오지 않습니다. 다른 그룹·다른 학생의 기록을 ID 추측으로 조회할 수 없습니다. 기간은 사이트 시간대의 월요일 시작 주간 또는 달력 월입니다.

일별로 각 탭의 확인된 관측 구간과 활성 구간을 합집합으로 병합합니다. 서로 다른 세션 사이의 밤·빈 시간, 하루 전체를 활성률의 분모에 넣지 않습니다. 겹치는 탭·활동은 시간을 중복 가산하지 않고 전체 활성률은 활성 시간 합계 / 관측 시간 합계로 계산합니다. 편집·실행·제출 신호는 물리적 저장 이벤트를 한 번씩 셉니다. 제출 횟수는 채점 성공 횟수가 아닙니다. 문항 응답은 별도 항목이며 집중 점수·통계 비율에 가중하지 않습니다.

일별 막대는 활성 시간, 선은 화면 활성률입니다. 같은 정보를 접근 가능한 표로도 제공합니다. 자료 없음·상세 기록 확인 불가·일부 누락은 비율을 0으로 만들어 연결하지 않습니다. 진행 중 기간은 표시하고, 이전 기간의 같은 경과 구간과 비교할 자료가 충분한 경우에만 차이를 표시합니다.

`daily_statistics`는 학생·학급/그룹 범위·날짜·시간대별 숫자 집계와 원본 리비전을 저장합니다. 일별 집계에는 코드·문항 본문·학생 이름·개별 선택 답을 넣지 않습니다. 원시 이벤트나 문항을 삭제하기 전에 전체 학생/날짜와 관련 그룹의 겹치는 구간을 먼저 집계합니다. 집계 저장 실패 시 원시 자료를 유지합니다. 원본 삭제 후 집계는 보관하며, 이후 과거 활동 조건·원본 리비전이 변경되면 삭제된 내용을 재생성하지 않고 불완전 상태로 표시합니다. 새 기능 설치 전에 이미 삭제된 기록이나 다른 시간대의 일별 상세는 복원할 수 없습니다.

설치 시 `focus_tracker_statistics_coverage_since`에 당시 원시 보관 범위 안의 첫 온전한 날짜를 한 번만 기록합니다. 이 경계 이후 관측 기록이 없는 날은 자료 없음으로 구분해 장기 합계에서 제외합니다. 경계 이전의 빈 날짜는 기록 유무를 알 수 없으므로 확인 불가로 둡니다. 보관 기간 설정 변경으로 이 경계를 과거로 옮기지 않습니다. 플러그인 삭제 시 이 경계 옵션도 삭제합니다.

## 10. 수집·출제의 활동 시간 제한

`POST /tracking/state`는 학생의 현재 전체 학습 명단과 문제·페이지 문맥으로 활동을 조회합니다. 학급·그룹 페이지는 해당 문맥만, 일반 문제 페이지는 학생이 속한 학급·그룹의 일치하는 활동을 허용합니다. 대회 문맥은 학급·그룹 일정으로 승인하지 않습니다. 권한·일정 조회가 실패하면 수집을 허용하지 않습니다. 응답에는 시각·활동 범위만 있으며 초안이나 코드 조회는 없습니다.

공통 브라우저 게이트는 기본 5초마다 확인하고 승인 기한은 최대 10초입니다. 서버 시각과 단조 시계로 종료를 예약하며 네트워크 지연은 승인 시간을 늘리지 않습니다. 시작 시 서버의 새 확인 후 수집과 문항을 켜고, 알려진 종료·승인 만료·페이지 종료 시 즉시 멈춥니다. 일정 수정·조기 종료는 다음 확인에서 반영합니다. 숨겨진 탭도 활동 시간 안의 숨김 상태를 관측하지만 초안·문항은 보이는 페이지에서만 처리합니다. BFCache 복원은 새 승인을 받습니다.

서버는 같은 `Activity_Window_Gate`로 매 기록 배치와 문항 요청·응답을 검사합니다. 시간 구간은 `[시작, 종료)`이며 종료 제어 이벤트만 끝 시각을 허용합니다. 종료 전 발생한 기록은 24시간 이내 지연 전송할 수 있고 시간 밖 이벤트는 저장하지 않은 정책 처리 ACK를 반환합니다. 데이터 저장 실패는 ACK하지 않습니다. 저장 직전 권한·일정도 재확인합니다.

연속·중첩 활동의 합집합마다 `g6-` 접두 세션을 생성해 빈 시간을 분리합니다. 합집합의 모든 활동을 연결하고 서버 제어 순번을 예약해 재전송을 중복 처리하지 않습니다. 시작 제어 이벤트는 실제 관측 이전의 활성을 만들어내지 않으며 종료 경계는 관측 상한입니다. 학생 누적 통계도 연결된 현재 활동 범위로 다시 잘라 조기 종료 후 시간을 추론해 채우지 않습니다. 이전 버전의 본인 기록은 유지합니다.

시간 밖에서는 초안을 읽거나 전송하지 않습니다. 출제·응답 시 현재 활동과 저장된 문항 범위를 확인하고, 종료된 문항을 다음 활동에 되살리지 않습니다. 활동 종료에 따른 취소는 무응답과 구별하며 모든 문항 결과는 집중 지표에서 분리합니다.

## 11. 출시 후보의 운영·개인정보 보호

설치·업그레이드는 필수 컬럼, 이벤트·세션·집계의 UNIQUE 인덱스, 모든 전용 테이블과 원자적 요청·개인정보 잠금에 쓰는 WordPress 옵션 테이블의 InnoDB 및 option_name 고유성을 확인한 뒤 DB 버전을 갱신합니다. 새 전용 테이블은 InnoDB로 만들고 기존 엔진이나 WordPress 테이블은 임의로 변환하지 않습니다. 확인 실패는 설정과 WordPress 사이트 건강에 표시하며 기록 API를 503으로 중단합니다. 정상 상태의 전체 메타데이터 검사는 10분마다 재확인하며 사이트 건강 검사로 즉시 확인할 수 있습니다.

요청 제한은 사용자·작업별 60초 구간을 DB의 원자적 조건 UPDATE로 계산합니다. 시간 확인·기록 수집은 각각 분당 180회, 문항 요청·요약은 60회, 응답은 120회입니다. 발급 상한과 별개로 원문 분석 전에 검사하고 초과 시 429 및 Retry-After를 제공합니다. 오류를 숨기거나 무제한 재전송으로 바꾸지 않습니다. 운영 진단은 고정된 작업·사유별 카운터와 최근 성공·실패 시각만 보관하며 사용자·문제·초안·선택 답·오류 원문을 넣지 않습니다.

보관 기간은 `retention_days`(원시 활동), `check_retention_days`(문항·응답), `aggregate_retention_days`(일별·활동 집계)로 분리합니다. 기본값은 60·60·0이며 집계 0은 기간 제한 없음입니다. 유한 집계는 앞 두 기간보다 최소 1일 길게 지정합니다. 정리 작업은 전역 CAS 잠금, 실행 예산과 건수 제한, 종류별 ID 커서, 30초 뒤 이어 처리와 보류 항목 재시도를 사용합니다. 실패 항목에서 커서를 전진해 뒤의 정상 자료를 처리하고 다음 순회에서 다시 시도합니다. cron이 실행되지 않으면 작업도 지연됩니다.

원본 삭제 전 일별·활동 집계 저장을 확인하고 실패하면 원본을 유지합니다. 문항이 먼저 만료돼도 그 집계는 보존하고, 복원할 수 없는 분포·조건 변경은 불완전 상태로 표시합니다. 집계가 만료된 완료 날짜는 조회로 다시 만들지 않으며 원시·문항이 남은 자료는 안전한 보존을 마친 뒤 지웁니다. 집계의 출처 확인에 쓰는 세션·활동 연결도 집계 기간에 따라 정리하며, 현재 활동·보존 중인 원본이나 집계에 필요한 연결은 유지합니다. 집계 기간이 0이면 이 출처 자료도 계속 보관할 수 있습니다. 설정 변경 실패는 성공이나 변경 이력으로 표시하지 않습니다.

WordPress 개인정보 내보내기는 페이지당 최대 100개 본인 기록을 제공하고 문항의 비공개 정답·검증 근거는 제외합니다. 개인정보 삭제는 자식 자료부터 배치로 삭제하며 계정 삭제는 전체 원시·문항·집계·발급 상태·본인 변경 이력을 제거합니다. 공유 활동과 다른 학생 자료는 유지합니다. 현재 교사 명단에 없는 학생의 개인 타임라인·통계는 열람하지 못합니다.

개인별 보호 행의 잠금으로 수집·출제·개인 삭제와 파생 집계의 저장을 직렬화합니다. 개인정보 삭제 배치 사이에는 erasing 상태로 새 학습 기록 처리를 중단하고 완료 후 새 학습은 허용합니다. 일반 개인정보 삭제 후에는 HMAC 보호 키와 삭제 완료 시각을 남겨 브라우저의 이전 대기열이 지운 자료를 복원하지 못하게 합니다. 계정 삭제 뒤에는 HMAC 키와 deleted 상태만 남겨 계정 삭제 전에 인증된 지연 요청의 재생성을 차단합니다. 계정 삭제 표식은 계정 번호 원문·학습 자료·시각을 포함하지 않습니다. 이 최소 보안 정보는 개인정보 도구의 보관 사유와 내보내기에 표시하며 TTL 없이 유지하고 플러그인 삭제 시 제거합니다. 익명 정보라고 단정하지 않습니다. 개인정보 삭제와 보관 정리는 공통 잠금으로 직렬화합니다.

학생 상태는 활동 대기·기록 중·종료·연결 오류를 구분하고 교사 목록은 시간 경계를 자동 반영합니다. 문항 알림 영역은 영구 유지하며 편집 중 초점을 빼앗지 않고, 학생이 문항 안에 있을 때만 응답·닫기·종료에 따른 초점을 복구합니다. 실제 모바일·화면 읽기·MySQL 부하 등 남은 인수 범위는 `RC-ACCEPTANCE.md`에 기록합니다.

## 12. 학생 기본 추적 권한

`Student_Participation_Defaults`는 승인된 플랫폼 런타임이 연결된 뒤 init 우선순위 3에서 학생 역할(`subscriber`)에 공개 capability mapper의 PARTICIPATE 키만 기본 부여합니다. 역할 상속이므로 기존·신규 학생별 대량 쓰기가 없고 현재 사용자 역할 캐시를 갱신해 첫 요청도 반영합니다. 보존된 역할 옵션으로 저장 성공을 확인하며 역할 부재·저장 실패는 다음 요청에 재시도합니다. 최초 적용 전에 역할 키가 없는 상태는 기본 부여 대상이며, 이미 저장된 false와 이후 관리자 회수는 덮어쓰지 않습니다. 학생 요약 열람이나 교사 관리 권한을 자동 추가하지 않습니다.

기본 부여 상태와 자체 부여 여부를 옵션에 기록합니다. 비활성화 시 자체 부여한 현재 true 권한만 회수하고 재활성화 시 복원하며, 이미 관리자가 회수했다면 이를 유지합니다. 회수 저장 실패는 비활성화를 중단합니다. 기존 수동 역할·개인 권한을 지우지 않습니다. 플랫폼의 `oj_platform_unprivileged_addon_capabilities`에는 추적 참여 키만 등록해 일반 학생의 계정 관리가 막히지 않게 하며 관리자·관리 권한 보호를 유지합니다. 이 공개 확장을 보장하는 플랫폼 2.3.22 이상을 요구합니다.
