# 실제 WordPress·MySQL 계열 검증

## 1.1.2 조회·갱신 비교 (2026-10-28)

별도 Oracle MySQL Community 8.0.46 / InnoDB / REPEATABLE READ, WordPress 7.1·PHP 8.3.33·공식 Platform 2.5.5에서 공식 Focus 1.1.1 ZIP과 개선본을 비교했습니다. 설치된 런타임 PHP 49개의 SHA를 작업 소스와 대조하고 최종 업무 비교 38조건·결과 SHA 8개, 개인정보 삭제·일정 변경 경계 21조건, 종료 선두 인덱스·복구 10조건을 확인했습니다. 다른 학생의 직접 점수 캐시 저장과 PK 무효화 경합 17조건은 repository 범위입니다. 별도 두 개인정보 잠금 구성의 timeout은 전체 경로 통과 증거에서 제외했습니다.

60명 과거 활동 강제 점수 계산 431→195 SQL, 캐시 조회 307→130 SQL, 월간·이전 기간 통계 287→47 SQL로 줄고 결과가 같았습니다. 예열 재전송의 학습 테이블 쓰기는 0회이며 일정 조회의 실제 스캔은 10,003→2행입니다. WordPress 부팅·계정 로딩과 네트워크 부하는 이 내부 REST 비교 밖입니다. 상세 조건은 `DB-OPTIMIZATION.md`에 기록합니다.

최종 ZIP 설치 전 70테이블 13,717행의 행·컬럼·인덱스·엔진·역할·설정을 고정했습니다. 실제 WordPress 업데이터로 교체한 뒤의 파일 SHA·자료 보존 결과는 별도 릴리스 영수증에 기록합니다. 시험 계정·암호·비공개 연결 설정은 공개 증거와 ZIP에 넣지 않습니다. 아래 1.1.1의 30~60명 HTTP 실패를 이번 구성요소 비교의 성공으로 대체하지 않습니다.

## 1.1.1 Oracle MySQL 8.0.46 (2026-10-28)

실제 Oracle MySQL Community Server 8.0.46을 별도 loopback 인스턴스로 실행했습니다. WordPress 7.1·PHP 8.3.33·Platform 2.5.4와 공식 Focus Tracker 1.1.0 ZIP에서 출발해 수정본 1.1.1을 검사합니다. 후속 실제 로그인 부하에서 발견한 요청 제한 만료 누락은 Platform 2.5.5로 수정하고 별도 검증합니다. 기본 RR 격리 수준, 전역 SQL 모드와 실제 WordPress session 모드를 보고서에 각각 기록합니다. 운영 DB·시스템 서비스는 사용하지 않습니다.

새 세션과 첫 문항 INSERT의 교착, 겹친 일정 변경의 pending 취소 누락을 실제 독립 WordPress 프로세스로 재현했습니다. 수정 후 같은 프로브에서 교착이 없어졌고, 삭제 둘·단축 둘·단축 후 삭제는 모두 정상 취소됐습니다. 60학생의 문항 발급·응답·종료 280개 프로세스도 재시도·교착 없이 통과했습니다. 설치 전후 여덟 Focus 테이블의 기존 행·컬럼 정의와 설정·역할도 보존됐습니다.

여러 PHP 프로세스의 내부 REST, 실제 Chrome 페이지와 실제 인증 HTTP 채널은 별도 시험입니다. 환경·부하 규모·판정 기준·정확한 지연·ACK/DB 대조·메모리 경계는 `MYSQL8-LOAD.md`와 `VERIFICATION.md`에 기록합니다. 아래 MariaDB 결과를 Oracle의 측정값으로 대신 사용하지 않습니다.

## 1.1.0 페이지 분류 (2026-10-28)

별도의 빈 DB에 WordPress 7.1·PHP 8.3.33·MariaDB 11.4.10을 설치하고 공식 Platform 2.5.4·Focus Tracker 1.0.1·Edu Games 1.6.7·Learning Materials 1.1.2 ZIP을 사용했습니다. `test-bootstrap.php`, SQLite, 가짜 권한·명단을 사용하지 않습니다. `page-categories-acceptance.php` baseline 보고서 21개·verify 보고서 67개를 통과했습니다. 파일 저장 확인까지 세는 콘솔 출력은 22·68입니다.

공식 1.0.1에서 실제 활동·세션·이벤트·점수·연결을 만든 뒤 1.1.0으로 스키마를 갱신했습니다. 기존 공통 컬럼의 SHA-256과 사용자 지정 경로·가중치·보관 설정을 대조하고 신규 페이지 컬럼 네 개와 평가 가능 컬럼 두 개의 기본값을 확인했습니다. 예전 자료를 새 페이지 종류로 추정하지 않습니다.

교사 시험 계정은 WordPress 관리자 대신 실제 `oj_group_manager` 역할을 사용합니다. 현재 그룹 관리·Focus 활동/결과 권한으로 활동을 생성·종료하고 기존·신규 학생은 `subscriber` 권한을 상속합니다. 학생 개인 참여 권한 쓰기는 없습니다. 내부 REST 디스패치에서 서명된 자료·게임·ML 각 30초를 저장해 주간·월간 합계와 분류별 중복 없는 분할, 입력 평가 중립 20점을 확인했습니다. 변조·타계정·무서명 페이지 요청을 거부하고, 별도 학생의 개인정보 내보내기·삭제 뒤 다른 학생의 이력을 보존했습니다.

첫 일반 교사 브라우저 검사에서 Judge DB 설정이 빠진 새 검증 사이트의 대회 메뉴 조회가 예외로 중단됐습니다. 실제 콘솔 메뉴가 요구하는 Judge 연결을 `setup-problem.php`의 정식 후보 검사·적용으로 준비했습니다. 독립 로컬 DB의 `jol` 스키마와 공개 문제를 실제 플랫폼 서비스로 만들었으며, 교사를 관리자로 바꾸거나 응답·권한을 대체하지 않았습니다. 이 실행 준비 오류와 Focus Tracker의 수집 검사를 구분합니다.

설정 후 실제 Chrome 전체 31개가 통과했습니다. 두 계정의 실제 로그인·nonce, 일반 그룹 교사의 콘솔 UI 일정 생성, 학생이 미리 연 자료 화면의 자동 시작, ML·교육게임 이동, 90초 일정의 자연 종료와 종료 후 통계 불변, 주간/월간의 분류 합계, 학생 요약·교사 타임라인을 검사했습니다. 독립 PHP 작업자 4개와 OPcache를 사용하며 프록시는 요청을 전달할 뿐 응답·쿠키·시간을 바꾸지 않습니다. 제품의 승인 주기·기한을 늘리지 않았습니다.

네이티브 브라우저와 최종 ZIP의 검증 도구는 `tests/real-wordpress/page-categories-browser.cjs`, `page-categories-package.php`입니다. 재현 절차는 해당 폴더 `README.md`에 있으며 전용 계정 설정은 공개 증거와 설치 ZIP에서 제외합니다. 상세 실행 결과는 `VERIFICATION.md`와 `_notes/verification/2026-10-28/focus-tracker-1.1.0/`에 기록합니다. 아래 내용은 이전 1.0.0 검사 이력이며 이번 검사와 합산하지 않습니다.

WordPress 코어 `deactivate_plugins()`와 `activate_plugin()`을 실행한 뒤 새 WordPress 요청을 거쳤습니다. 자체 부여한 추적 권한의 회수·복원, 개인 거부와 교사 수동 권한 보존, 이후 관리자의 역할 `false`와 권한 제거를 재활성화가 덮어쓰지 않는 것을 확인했습니다.

## 실제 브라우저와 설치 패키지

브라우저 검사는 `tests/real-wordpress/browser-acceptance.cjs`로 실행합니다. 실제 `/login`과 WordPress 로그인 쿠키, 페이지에서 발급한 REST nonce를 사용하며 성공 응답 대체나 시간·권한 조작을 하지 않습니다. 초기 출제 45초, 승인 재확인 5초, 문항 사이 최소 5분을 실제 설정대로 유지합니다. 결과는 별도 검증 기록에 보관합니다.

RC3와 조기 번역 수정 소스의 첫 실제 브라우저 실행에서 자동 참여·문항·오답 분리·자연 종료·종료 뒤 전송 중단 30개 검사를 확인했습니다. 이후 검증 도구가 본문을 읽을 수 없는 종료 beacon을 처리하다 멈췄습니다. 원래 실패 보고서를 보존하고 새 활동·문항 없이 실제 재로그인·nonce·계정 위조 거부·저장 결과 조회 14개를 별도로 확인했습니다. 검증 도구는 본문 없는 요청도 전체 요청 수에 유지하며, 시각을 읽을 수 없는 본문은 실제 DB 조회로 보완합니다. 정식 ZIP 설치 후에는 수정한 전체 브라우저 검사를 다시 실행합니다.

릴리스 킷으로 생성한 ZIP은 `tests/package-smoke.php`로 배포 파일 전체와 검사한 소스의 바이트·SHA-256을 대조합니다. 설치 후 네이티브 DB 버전·저장소 준비·기존 기록 보존과 브라우저 검사를 다시 확인합니다. 검증용 자격증명, 테스트 사이트, DB 파일과 테스트 스크립트는 설치 ZIP에 포함하지 않습니다.

RC3 업데이트 전 스냅샷에는 활동·참여·연결·이벤트·점수·문항·발급 상태가 실제로 저장돼 있습니다. 일별 집계 테이블은 이 시험에서 0행이므로, 그 테이블의 동일성 검사를 기존 운영 일별 집계 이력의 보존 실측으로 해석하지 않습니다.

## 확인 중 발견한 사항

- 초기 메타데이터 등록에서 번역 함수를 호출해 WordPress 6.7 이후의 조기 번역 경고가 발생했습니다. init 전에 수집되는 선언 정보는 기존 다른 메타데이터처럼 문자열로 등록하고, 페이지의 번역은 초기화 후 처리하도록 수정했습니다.
- 최초 설치 도우미의 모듈 등록 누락과 제한된 프로세스의 localhost 소켓 차단을 확인해 검증 실행 방법을 수정했습니다. 교사 관리 권한을 준비하지 않은 첫 REST 호출은 정상적으로 403을 반환했으며 검증 계정의 권한을 실제 플랫폼 역할 설정 API로 준비했습니다. 이 실패를 학생 자동 권한의 결함으로 취급하지 않습니다.
- 새 플랫폼 문제 주제 초기화에서 한 차례 오류가 기록됐으며 이후 재시도에서 복구됐습니다. 동시 초기화 경합으로 추정하지만 원래 오류 코드가 로그에 없어 원인을 확정하지 않습니다. 현재 기본 주제 93개가 모두 존재하고 누락·중복·오류 재발이 없음을 별도 조회로 확인했습니다. Focus Tracker 기록·문항의 성공 근거와 구분합니다.

## 별도로 남는 운영 검증

위 1.0 검사 시점에는 Oracle MySQL 8과 여러 탭의 동시 경합이 남아 있었습니다. 이후 1.1.1의 실제 Oracle MySQL 8.0.46·다중 학생 검사는 문서 첫 부분과 `MYSQL8-LOAD.md`를 따릅니다. 최소 WordPress 6.6 조합, 학교 목표 동시 접속·고장 주입, 실제 운영 DB의 과거 버전 마이그레이션·백업 복원, 운영 캐시·프록시·WP-Cron, 실제 모바일 절전·화면 읽기 프로그램과 장기 수업 시범 운영은 별도입니다. 상세 기준은 `RC-ACCEPTANCE.md`에 있습니다. 이 결과만으로 학생의 인지적 집중·문제 전체 이해나 모든 브라우저에서 무손실 수집을 보장하지 않습니다.
