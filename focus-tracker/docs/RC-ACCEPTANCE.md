# 1.0.0 운영 환경 추가 인수·복구 점검

요구사항: OJ Platform 2.3.22 이상 / Addon API 1.4, WordPress 6.6 이상, PHP 8.3 이상, 트랜잭션을 지원하는 MySQL/InnoDB. 정식 소스 회귀는 플랫폼 2.3.22 원본을 사용합니다. 작성일: 2026-10-24 한국 시간.

## 자동 검사로 확인한 범위

소스 회귀 결과는 `VERIFICATION.md`, 별도 실제 WordPress·MariaDB 검증은 `REAL-WORDPRESS.md`에 기록합니다. 네이티브 검증에서 기존·신규 학생의 자동 역할 권한, 거부·회수 보존, 실제 비활성화·재활성화, WordPress 쿠키·nonce 인증, 그룹 시간표의 자동 참여·종료와 종료 뒤 수집 중단을 확인했습니다. WordPress 관리자 역할의 검증 계정이 교사 관리 권한을 행사했습니다. 단일 PHP 서버의 두 학생 검사를 학교의 목표 동접이나 DB 경합 검사로 확대 해석하지 않습니다.

## 학교 운영과 같은 환경에서 추가할 점검

아래 표는 학교의 실제 서버 구성·과거 운영 자료·기기와 규모로 확인할 범위입니다. 로컬 네이티브 검증을 이 범위 전체의 통과로 표시하지 않습니다. 운영과 같은 별도 검증 사이트에서 담당자·환경 버전·실행 시각·결과를 기록합니다. 학생 기본 권한과 자동 참여·종료의 로컬 검증 통과를 정식 1.0.0 릴리스 조건으로 삼았으며, 아래 항목은 배포 학교의 인수 범위로 분리합니다.

## 업데이트와 복구 순서

1. 학생 활동이 없는 시간에 플랫폼·애드온 버전, DB 버전, 각 보관 기간, 활동·문항·일별 집계 건수와 대표 화면을 기록합니다.
2. 사용 중인 호스팅/DB 관리 도구로 WordPress DB 전체를 백업하고 `wp-content/plugins/oj-platform/`, `wp-content/plugins/focus-tracker/`를 함께 보관합니다. 실제 운영 DB와 같은 검증 사이트에서 먼저 복원 가능성을 확인합니다.
3. 플랫폼 2.3.22를 활성화한 뒤 WordPress 플러그인 업로드로 1.0.0 ZIP을 설치합니다. 설정 운영 상태와 도구의 사이트 건강에서 저장소 상태를 확인합니다.
4. 학생·교사 계정으로 일정·기록·문항·통계·개인정보 도구를 확인합니다. 기존 버전의 보관 기간은 보존하고 새 집계 기간 기본값은 0(무제한)입니다.
5. 실패하면 새 활동을 중지하고 Focus Tracker를 **비활성화**합니다. 플러그인 **삭제**는 여덟 테이블과 옵션을 영구 제거하므로 복구 절차에서 사용하지 않습니다.
6. 백업 시점의 플랫폼 파일·Focus Tracker 파일·DB를 같은 묶음으로 복원합니다. 소스 파일만 이전 버전으로 바꾸는 방법은 DB 복구를 대신하지 않습니다.
7. 다시 활성화한 뒤 버전·명단 권한·보관 설정·활동 시간·기록 상태·대표 문항과 주간/월간 합계를 백업 전 기록과 대조합니다. 브라우저를 새로고침해 이전 자산과 승인 상태를 갱신합니다.

## 운영 해석

화면 활성·편집·제출과 확인 문항은 관측 근거입니다. 인지적 집중이나 풀이 전체의 이해를 확정하지 않습니다. 교사는 문항을 제작·채점할 필요가 없습니다. 자료 없음·불출제·오답·무응답을 집중 점수 불이익으로 바꾸지 않습니다.

기본 보관은 원시 기록 60일, 문항·응답 60일, 일별·활동 집계 0(기간 제한 없음)입니다. 각 기간은 별도로 설정할 수 있습니다. 유한 집계 기간은 원시·문항 기간 중 긴 값보다 최소 1일 길어야 하며, 만료된 완료 날짜는 조회로 재생성하지 않습니다. 원시 삭제 안전 검증 실패나 cron 지연으로 삭제가 늦어질 수 있으므로 운영 상태의 실패·남은 작업을 확인합니다.

집계 출처에 필요한 세션·활동 연결도 집계 기간에 맞춰 보관합니다. 유한 집계가 만료하면 현재 활동·보존 중 자료에 필요한 연결을 제외하고 정리합니다. 집계 기간이 0이면 이 출처 자료도 계속 보관할 수 있습니다.

개인정보 삭제 후 지연 전송으로 지운 기록이 복원되지 않도록 HMAC 보호 키와 삭제 완료 시각을 유지합니다. 계정 삭제의 보호 키는 deleted 상태만 보관합니다. 이 최소 보안 정보는 학습 기록과 구분해 개인정보 도구에 표시하고 플러그인 삭제 시 제거합니다. 학생이 계속 재학 중이면 삭제 완료 후 새 시각의 학습 기록은 수집할 수 있습니다.
