# 검증 기록

## 1.0.1 DB 부하 개선 (2026-10-26)

Windows의 PHP와 SQLite SQL 어댑터에서 `database-performance.php` 34개를 포함하여 PHP 회귀 16종·1,282항목을 확인했습니다. 실행한 회귀는 `activity-gate`, `release-readiness`, `privacy-security`, `events-storage`, `check-gate`, `check-storage`, `activity-schedules`, `activity-delete`, `activity-delete-statistics`, `statistics`, `retention-cleanup`, `scoring-service`, `student-defaults`, `platform-integration`, `bootstrap-smoke`, `database-performance`입니다.

PHP 80개 문법 검사, 텍스트 112개 UTF-8/BOM 점검과 `git diff --check`도 통과했습니다.

성능 회귀는 실패한 설치 이후 50번의 요청에서 반복 DDL·메타데이터 조회가 없고, 살아 있는 임대 잠금·만료된 임대 교체·획득 후 내구성 상태 재확인과 기록 API의 버전·준비 상태 검증을 확인합니다. 학습 컨텍스트 100개에서 활동 조회는 1 SQL이고, 소속 회수는 다음 확인에 반영됩니다. 일정 단축·삭제를 낙관적 조회와 잠금 조회 사이에 삽입하면 수집이 롤백되며, 학생 일정 조회는 공유 잠금, 개인정보·세션·이벤트는 배타 잠금을 사용합니다. 100번의 같은 진단 요청은 한 관측과 두 번의 카운터 쓰기로 제한됩니다.

진단 초기화는 고정된 진단·분당 승인 키를 WordPress 옵션 API로 삭제하고 캐시도 무효화합니다. 영속 옵션 캐시를 켠 대역에서 초기화 직후와 이후 분의 표본 기록이 재개되는지도 확인했습니다.

이 버전은 새 운영 DB·학교 동접 부하·실제 MySQL/MariaDB의 공유 잠금 경합을 측정한 결과가 아닙니다. SQLite 대역은 잠금 SQL과 일정 변경 경쟁의 거부 결과를 확인하며 InnoDB의 동시 잠금 스케줄링을 재현하지 않습니다. 활동 확인 5초·승인 최대 10초와 숨긴 탭 기록은 유지합니다. 아래 네이티브 검증과 브라우저 검증 기록은 1.0.0의 이력이며 1.0.1에서 재실행한 것으로 해석하지 않습니다.

## RC에서 추가한 검사

rc.3의 독립 역할 검사는 허용을 고정 반환하는 기존 대역을 사용하지 않습니다. 실제 SQLite 옵션 저장과 WordPress 역할·사용자 계약 모델로 기존 학생의 캐시 갱신, 신규 학생 상속, 개인 직접 권한 쓰기 없음, 게스트·교사 전용 역할·개인 false·역할 false 거부, 최초/완료 후 관리자의 권한 회수, 역할 부재·권한/마커 저장 실패 재시도를 확인했습니다. 자체 기본 부여의 비활성화 회수·재활성화 복원과 수동 권한 보존, 실제 독립 uninstall 진입점도 확인했습니다. 플랫폼의 실제 특권 계정 감지기와 연결해 추적 권한만 가진 학생은 일반 학생으로 유지하고 관리 권한·다른 애드온의 민감 권한은 계속 보호합니다.

새 Chrome 검사는 교사에게 그룹·시간을 선택해 실제 활동 UI로 생성하게 하고, 권한 수동 부여 API는 호출하지 않습니다. 기존·신규 학생이 네이티브 역할에서 권한을 상속하며 직접 user cap이 없는 상태로 문제를 미리 열고, 시작 전 요청 0건→자동 수집·문항→예정 종료 뒤 새 편집에도 기록·초안·문항 요청 0건을 검증했습니다. 비학생·게스트·개인 거부·역할 거부·관리자 회수는 bootstrap 미제공과 실제 추적 API의 401/403 양쪽에서 확인했습니다. WordPress 역할 API와 인증은 계약 대역이라는 경계는 유지합니다.

플랫폼의 공개 읽기 전용 애드온 권한 필터와 실제 계정 관리·비밀번호 초기화 정책도 검사했습니다. 플랫폼 빠른 회귀는 96개 스크립트 통과이며 Focus Tracker 합계와 분리합니다. 첫 제한 환경 실행의 10개 실패는 임시 파일 교체 권한 및 PHP cURL 미활성 환경이었고, 필요한 확장과 작업 폴더 임시 저장소를 갖춘 동일 소스 재실행은 96개 모두 통과했습니다. 공식 플랫폼 패키징에서도 전체 PHP 문법·릴리스 검사를 다시 통과했으며 manifest의 source_dirty=false, 커밋과 oj-platform-v2.3.22 태그를 확인했습니다.

rc.2에서 활동 삭제의 역할·nonce·작성자·현재 학급/그룹 관리 권한과 반복 요청의 재검증, 잘못된 ID, 예정·진행·종료·보관 활동 삭제를 확인했습니다. 삭제 활동의 목록·활동별 점수·타임라인·최근 활동 요약·수집 승인 제외, 삭제 후 오래된 패킷 폐기, 다른 유효 활동의 계속 수집, 대기 문항 취소·겹친 원래 활동의 유효 구간 재연결을 검사했습니다. 삭제 전 읽은 수정 요청의 재활성화 차단과 저장·문항 처리·캐시 무효화·커밋 실패의 전체 롤백·재시도, 변경 이력도 확인했습니다. 로그인 학생의 첫 정상 페이지 관측만으로 세션·활동 연결이 만들어지는 자동 참여도 검사했습니다.

이미 수집한 raw·활동 연결·완료 문항 응답과 self/class 누적을 보존하고, 완료한 활동의 삭제가 보관 집계의 출처 서명을 바꾸지 않는지 확인했습니다. 진행 중 활동의 종료 제한, 다른 활동과 공유하는 자료, 시작 전 활동의 길이 0 구간을 구분합니다. 삭제된 예정 활동이나 이전의 긴 세션 종료 메타데이터 때문에 보관 작업이 영구 대기하지 않도록 실제 역사 구간으로 정리 범위를 제한하며, 다른 유효 활동이 필요로 하는 자료와 무제한 집계의 출처는 보호합니다.

실제 Chrome의 삭제 검사는 예정·진행·종료 버튼, 확인·취소, nonce 전달·반복 ACK, 중복 클릭 방지, 현재 권한 철회의 실제 403, 네트워크 실패 후 재시도, 대기 중 그룹 필터 변경, 초점 복귀·편집 초점 보호를 포함합니다. 삭제 전 시작한 실제 결과·타임라인 응답을 늦게 전달해도 화면이 복원되지 않습니다. 유일한 활동을 삭제하면 열린 학생 화면의 승인과 문항이 닫히고 이후 편집에서 새 기록·초안·응답 요청이 발생하지 않는지 확인했습니다. 모바일은 390px 콘솔·확인문의 가독성과 표 내부의 독립 스크롤을 검사합니다. 플랫폼 공용 페이지 자체의 문서 가로 넘침은 남아 있으므로 전체 페이지의 넘침 해소를 검증한 것으로 해석하지 않습니다.

독립 보관 기간의 기본값·기존 설정 이전·잘못된 조합 거부, 100건을 넘긴 자료의 이어 처리, 앞 자료 실패 후 뒤 자료 진행과 재시도, 중복 잠금·만료 복구, 처리 중단 대비 커서·재실행, 원본 저장 실패 시 보존을 확인했습니다. 문항을 먼저 삭제한 뒤 재계산하거나 시간대를 바꿔도 삭제된 응답을 0건으로 오인하지 않습니다. 유한 집계 만료 후 일별·활동 집계와 불필요한 세션·연결 자료를 정리하며 기본 무제한 집계·다른 학생·보존 중 자료·공유 활동을 보호합니다.

WordPress 개인정보 훅의 페이지당 100건 내보내기·분할 삭제·계정 삭제, 본인 자료 범위, 비공개 정답·검증 근거 미노출, 삭제 실패 롤백·재시도를 검사했습니다. 삭제 중 수집·출제·통계·점수 저장 차단, 삭제 후 오래된 outbox ACK 폐기, 열린 페이지의 새로운 기록 수집과 재전송 멱등성, 반복 삭제의 경계 갱신, 계정 삭제 후 지연 요청 차단을 확인했습니다. 최소 보호정보의 내보내기와 보관 사유도 표시합니다. 삭제 전 구간은 자료 확인 불가, 삭제 경계일은 불완전으로 표시해 저집중·확정 무관측으로 만들지 않습니다.

별도 요청 제한의 정상 두 탭 예산, 구간 초기화·다른 계정/채널 격리, 실제 HTTP 403·413·429와 Retry-After, 고정 카운터와 운영 패널의 원문 비노출을 검사했습니다. 운영 화면에서 세 기간을 별도로 저장하고 오류 입력은 기존 값을 보존합니다. 설정 DB 저장 실패를 성공이나 감사 이력으로 표시하지 않습니다. 390px 화면에서 운영 표 넘침도 검사했습니다.

필수 컬럼·중복 방지 인덱스·InnoDB 준비 검사, 실패 시 DB 버전 미갱신·REST 503·관리자/사이트 건강 표시·복구 재시도, 실제 자동 로더와 개인정보·보관·API 훅 등록을 확인했습니다. 단, 엔진 메타데이터는 SQLite 어댑터의 대역이며 실제 MySQL 엔진 전환·잠금을 실행한 검사는 아닙니다.

학생 상태와 시각, 고지 닫기와 독립적인 상태 표시, 교사 예정→진행→종료의 배지·버튼 갱신, 새 GET·쓰기 없는 시각 갱신, 문항의 영구 알림·응답 중 초점 보존·응답/종료 후 복귀·편집 초점 비탈취를 Chrome에서 확인했습니다. 실제 화면 읽기 프로그램 검사는 남습니다.

검증한 주요 회귀는 수업 전 접속, 중첩 활동, 다중 탭 구간 합집합, 최신·오래된 heartbeat, 장시간 관측 공백, 연속 입력, 마지막 입력과 제출, 초기 비활성 상태, BFCache 복원, 오프라인 재시도와 중복 방지, 사용자 격리, 가중치·시간·문제 변경, 그래프·점수 일치, 관측 자료 없음·일부 누락 표시, 원시 기록 만료 전 집계 저장과 실패 시 보존입니다.

자동 확인 검사는 제출 전 초안, 본인 제출, 문제 예제의 출처 선택·회전, 코드 언어·주석·문자열·모호한 예제 거부, 정답 변조 거부, 비공개 정답 키 미전송, 전체 초안 미보관, 본인·현재 문제·수업/그룹/대회 권한, 대회 제한, nonce·계정 전환, 중복 응답·발급 상한·만료·자료 변경 취소, 저장/커밋 실패 롤백, 보관 기간 삭제를 포함합니다. 모든 응답 결과 전후 실제 집중 점수와 활동 기록이 같은지 확인했습니다.

실제 브라우저는 Ace·완성 빈칸·Blockly 초안, 제출 없는 문제 예제 대체, 출제 불가 시 조용한 건너뛰기, 정답·오답·모름·건너뛰기·무응답, 저장 후 ACK 유실 재전송, 계정 변경 거부, HTML 텍스트 안전 출력, 입력 포커스 보존을 검증했습니다. 실제 활동 시간 안에서 390px 모바일 화면의 알림 버튼을 직접 눌러 문항을 열고 학생 자기 요약까지 확인했습니다. 짧은 대기·만료 시간은 테스트 전용 도구에서만 조정합니다.

새 활동 시간 제한 검사는 활동 없음·시작 전의 참여/이벤트/문항/초안 요청 0건, 열린 페이지의 자동 시작, 알려진 종료의 수집·문항·응답 중단, 빈 시간 후 새 세션, 명시된 다른 그룹·문제 차단, 조기 종료, 통신 장애 시 10초 이내 승인 만료, 숨긴 탭의 비활성 관측과 종료·기록 복원 차단을 포함합니다. 브라우저는 실제 HTTP 성공과 SQL 저장을 사용하며 숨긴 탭 검사는 제어된 visibility 이벤트를 사용합니다. 기본 5초 재확인은 일부 브라우저 검사에서 500ms로 줄이고 승인 상한은 유지했습니다.

서버 검사는 반열린 시간 경계, 종료 전 기록의 지연 업로드, 시간 밖 정책 처리 ACK, 계정·명단·컨텍스트 조회 실패, 연속·중첩 활동과 분리된 시간, 종료 후 문항 취소와 응답 멱등성을 확인했습니다. 시간 수정으로 활동 합집합이 분할·병합된 뒤 같은 순번을 재전송해도 중복 저장하지 않습니다. 실제 이른 종료 메타데이터와 뒤늦은 종료 패킷도 검사했습니다. 조기 종료·문제 범위 변경 시 남은 문항을 트랜잭션 안에서 갱신/취소하며, 겹치는 다른 활동이 계속 유효한 경우와 연속 활동이 끊기는 경우, 갱신 실패의 전체 롤백을 확인했습니다. 학생 누적 통계도 조기 종료 후 시간을 제외합니다.

그룹 일정 검사는 서로 다른 그룹의 독립 시간표, 날짜·시간대 변환, 수정·조기 종료·권한 거부·보관된 평가 범위 보호를 확인했습니다. 누적 통계 검사는 탭·활동 중첩 합집합, 시간 가중 비율, 세션 사이의 밤·빈 시간 제외, 물리적 이벤트 횟수, 다른 학생·그룹·연결 없는 과거 기록 제외, 자정·월말·윤년·연도·DST 경계, 같은 경과 구간 비교를 포함합니다.

일별 집계 저장 실패 시 원시 자료 보존, 원시 자료 삭제 후 전체 일별·주간 합계 유지, 이전 기간 일부 날짜의 상세를 복원할 수 없을 때 비교 생략, 지연 조회가 보관된 집계를 덮어쓰지 못하는 SQL 보호, 문항 100개씩 보존·삭제하는 배치와 다음 실행의 이어 처리, 만료 문항 상태 확정, 기능 설치 시점의 관측 가능 범위 보존도 검증했습니다. 실제 MySQL 동시 실행 자체를 재현한 검사는 아닙니다.

실제 Chrome 통계 검사는 학생·교사 화면의 주간/월간 전환·이전 기간·날짜 선택, 표와 SVG 그래프의 누락 구간, 390px 화면, 브라우저와 서버 시간대가 다른 경우, 그룹별 학생 기록·현재 명단·권한 철회·다른 학생 ID 거부, 실제 시간 수정과 조기 종료를 연결했습니다. 기존 보관 UI 검사는 실제 REST 수집 후 테스트 도구로 완료된 과거 날짜로 옮긴 자료를 삭제하며, 진행 중인 날짜를 강제로 보관하지 않습니다.

PHP 79개를 PHP 8.3.33으로 문법 검사하고 JavaScript 19개, 텍스트 110개의 UTF-8/BOM과 `git diff --check`를 확인했습니다. 릴리스 킷으로 1.0.0 ZIP과 안내서를 생성하며 기존 rc.1·rc.2·rc.3 설치 ZIP은 변경하지 않습니다. 기존 0.1.0 개발 ZIP은 릴리스 킷 migrate로 버전별 폴더로 이동했습니다. 함께 설치할 플랫폼은 2.3.22입니다. 공용 CSS의 버튼 표시 규칙보다 우선해 hidden 속성을 지키는 범위 제한 규칙의 `!important` 경고는 남습니다.

## 검증 경계

위 회귀의 WordPress 인증·사용자·컨텍스트는 대역이고 DB는 SQLite 어댑터입니다. 별도 네이티브 검사는 실제 WordPress 쿠키·nonce·역할 API와 MariaDB의 dbDelta·트랜잭션을 사용합니다. 여러 학생 브라우저 요청은 단일 PHP 개발 서버가 처리하므로 MySQL 동시 잠금 경합·목표 부하를 증명하지 않습니다. Oracle MySQL 8, 학교 서버 캐시·프록시·cron, 과거 운영 DB 복사본의 업그레이드·복원과 실제 기기·화면 읽기·시범 수업은 별도 `RC-ACCEPTANCE.md`에 남깁니다. 운영 서버 배포는 수행하지 않습니다.

생성된 문항은 독립 정수 비교·Python 내장 range·공개 예제 확인 범위입니다. 전체 프로그램·임의 문제 변형의 의미와 정답을 자동 판정하는 기능은 아닙니다. 정답은 해당 문항 응답의 근거이며, 오답·모름·무응답은 미집중 근거로 사용하지 않습니다. 브라우저 관측이나 문항 응답으로 학생의 지속적 인지적 집중·풀이 전체의 질을 검증한 것은 아닙니다. 원시 기록이 이미 누락·삭제된 과거 구간은 복원할 수 없습니다.
