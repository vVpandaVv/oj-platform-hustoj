## 하는 일

기존 OJ 문제의 본문·입력·출력·공개 예제로 PRIMM 단계별 예제·질문·수정 과제와 Parsons·빈칸 도움 자료를 자동 준비합니다. 생성 코드·예상 출력은 기존 OJ에서 검증하고 오류를 최대 두 번 수정합니다. 학생 수정 코드도 같은 채점기에서 연습 실행합니다.

## 1. 서버와 플랫폼 준비

[서버 준비](00-server-setup.md) 1~12단계를 마치고 **OJ Platform {{platform_requires}}(Addon API 1.7.0)**을 먼저 설치·활성화합니다. 업데이트 전 서버 준비 20단계로 백업합니다. PRIMM용 별도 실행 서비스는 설치하지 않습니다. 기존 `custominput` 테이블·쓰기 권한·동작 중인 OJ 채점기가 필요합니다.

플랫폼 **제출 → 제출 설정**(`/oj-console/submissions/settings`)을 엽니다. 상단 **언어와 결과 갱신 → 직접 제출 허용 언어**에서 사용할 언어를 선택하고 **언어 설정 저장**을 누릅니다. 하단 **예제·실습 실행 지원**에서 언어별 **실행 검사**를 누르고, 대기 상태이면 **결과 조회**로 **실행 통과**까지 확인합니다. Python·C·C++·Java 중 허용되고 실제 시험에 성공한 언어로만 자료를 생성할 수 있습니다. 이전 버전에서 업데이트해도 성공을 간주하지 않으므로 먼저 이 검사를 진행합니다. 채점기나 언어 설정이 바뀌면 다시 시험합니다.

방문이 없는 시간에도 생성 복구와 실행 기록 정리가 진행되도록 서버 준비 **11단계의 WordPress 1분 예약 실행**을 확인합니다.

## 2. ZIP 업로드와 AI 설정

1. WordPress 관리자 → 플러그인 → 새 플러그인 추가 → 플러그인 업로드에서 설치 ZIP을 업로드하고 사이트별로 활성화합니다. 기존 설치는 ZIP 교체를 선택합니다. 네트워크 전체 활성화는 지원하지 않습니다.
2. 기존 활동·학생 응답은 유지하며 PRIMM 전용 저장소를 스키마 3으로 갱신합니다. 오류가 있으면 활성화 상태와 WordPress DB의 InnoDB·테이블 생성 권한을 확인합니다. 플랫폼도 최신 ZIP으로 먼저 업데이트합니다.
3. **AI 제공자 설정**(`/oj-console/settings/ai-provider`)에서 연결을 시험하고 **AI 작업 배정**(`/oj-console/settings/ai-routing`)에서 **문제로 PRIMM 수업 자료 생성**(`addon.oj_primm.generate_lesson`)에 모델을 배정합니다. 모델 지원 한도에서 최대 출력 토큰 **8192 이상**을 권장합니다. API 키는 플랫폼에서만 관리합니다.

기존 AI 프로필에 작업이 많으면 전체 연결 검사가 시간 제한에 걸릴 수 있습니다. 플랫폼 2.4.1 이상에서는 기존 프로필의 **복제**로 새 프로필을 만들고 PRIMM 작업만 선택해 검사·저장한 뒤 배정합니다. 기존 작업 연결과 비밀값을 변경하지 않습니다. 복제할 때 비밀값을 비워 두면 같은 연결 대상·인증 방식에서만 서버가 기존 값을 사용하며 화면에 노출하지 않습니다.

## 3. 학급 기본값과 자동 준비

OJ Platform 2.5.0(Addon API 1.8) 이상에서는 자동 저장의 문제 확인과 제출 조회를 분리해 반복 DB 조회를 줄입니다. 기존 지원 플랫폼에서는 원래 조회 경로로 동작합니다. 본인 제출 자동 확인은 결과가 같으면 대기 간격을 늘리며, 숨긴 탭에서는 중지하고 돌아오면 다시 확인합니다. 스키마 갱신이 실패하면 60초 간격으로 재시도하므로 원인을 수정한 뒤 다시 확인하거나 플러그인을 활성화합니다.

1. 교사 메뉴 **학습 활동 → PRIMM 수업**(`/oj-console/addons/oj-primm`)을 열고 담당 수업·모둠을 선택합니다. 메뉴가 없으면 역할·권한의 **PRIMM 수업 관리**와 담당 공간 권한을 확인합니다.
2. **선택: 학급 기본 설정**에서 언어, 기초·중급·심화 수준, 선수 개념, 수업 시간(15~180분), **없음 / Parsons 코드 순서 배열 / 코드 빈칸 완성**을 선택하고 **학급 기본 설정 저장**을 누릅니다.
3. **학급 기본값으로 자료 자동 준비**를 켜면 이후 문제 저장 때 담당 공간에서 접근 가능한 문제를 자동 준비합니다. 새 문제는 해당 학급에 배정한 직후에도 준비합니다. 미배정 문제·권한 부족·한도 초과는 건너뛰고 안전한 운영 상태를 남깁니다. 배정하거나 원인을 해결한 뒤 다시 저장하거나 수동 생성합니다.
4. **검증 후 자동 공개**는 기본으로 켜져 있습니다. 실행·품질 검사를 통과하면 공개하고 검토 사유가 있는 자료는 교사가 확인한 뒤 공개합니다. 끄면 검증된 자료도 초안으로 저장합니다.
5. 기존 문제를 선택해 **AI로 PRIMM 자동 생성**을 눌러 즉시 준비할 수도 있습니다. AI 없이 시작하는 기초 템플릿은 OJ 검증 후 원문과의 관련성을 교사가 검토합니다.

AI는 도입 코드·학습 목표·다섯 단계 질문·수정 요구와 최대 여덟 시험 사례·최종 제작 안내를 만듭니다. **생성 → OJ 검증 → 필요 시 수정·재검증 → 품질 확인**이 끝난 뒤 활동을 공개합니다. 처음 받은 초안의 구조나 도움 조각이 일치하지 않으면 한 차례 자동 복구하고, 코드·출력 검증 실패는 최대 두 차례 수정합니다. 모두 AI 호출 한도에 포함하며 복구되지 않은 자료는 배포하지 않습니다. 수정 전 코드와 Modify 사례도 실행해 실제 행동 변화가 있는지 비교합니다. 사례 구별이 부족하거나 위험한 코드 패턴·수업 수준 대비 과도한 크기 등이 발견되면 검토 사유를 표시합니다. 실행 검증은 제공된 입력의 출력 일치를 확인하며 모든 입력의 정확성이나 질문의 교육적 적합성을 보장하지 않습니다.

같은 내용의 요청은 기존 작업을 재사용합니다. 일시 오류는 대기 시간을 늘려 같은 단계에서 재개합니다. 요청 결과 수신 여부가 불명확한 AI 호출은 중복 과금을 막기 위해 자동 재전송하지 않습니다. 상태를 확인하고 필요한 경우 명시적으로 새 요청을 시작합니다. 미완료 생성·연습은 시작 후 **24시간**이 지나면 만료되며 새 요청이 필요합니다. 플랫폼 AI 원장의 결과 보관은 **7일**입니다. **취소·재개**, 관리자의 **중지**, 운영 상태·사용량 확인을 제공합니다. 이미 전송한 외부 호출은 취소로 비용이 취소되지 않습니다.

WordPress **설정 → OJ PRIMM**에서 생성 한도를 변경합니다. 기본값은 교사 활성 3개·사이트 30개, UTC 일일 AI 호출 교사 40회·사이트 400회, 작업별 AI 6회·일시 오류 자동 재시도 4회입니다. 플랫폼 제출 설정에는 별도의 실행 동시·시간당 한도가 있습니다.

## 4. 편집·검토·공개와 보고서

활동의 **검토·수정·배포 관리**에서 단계별 질문·코드·입출력·도움 자료를 편집합니다. **새 버전 초안으로 저장 → 검증 후 배포 준비 → 수업에 공개** 순서로 진행하며 전체 재검증을 통과해야 공개할 수 있습니다. 직접 편집한 초안의 재검증은 AI를 호출하지 않으며 잘못된 코드는 교사가 수정합니다. 도움 조각·빈칸은 기준 코드와 일치해야 합니다. 필요한 단계는 **선택한 부분 재생성**으로 다시 만들 수 있습니다.

기존 공개 자료를 편집·재생성하면 새 버전으로 저장하고 기존 학생의 활동 번호·내용·응답을 보존합니다. 기초 템플릿으로 시작한 자료는 편집·부분 재생성·재검증 후에도 출처와 검토 요구를 유지하며 원문 관련성을 확인한 뒤 공개합니다. 전체 자료를 AI로 다시 생성하면 새 자료의 품질 검사를 적용합니다. **배포 회수** 후에도 기존 참여자는 기록을 읽을 수 있습니다. **이 자료를 선택한 수업에 복제**는 검증 자료를 초안으로 복제하며 학생 기록을 복사하지 않습니다. 원문 문제나 연결된 도움 템플릿이 바뀌면 새 자료를 준비합니다.

교사 보고서는 담당 학급의 **미시작 학생을 포함한 전체 명단**을 보여 줍니다. 검색·페이지 이동·전체 CSV 내보내기를 지원합니다. 활동 100개·학생 기록 200개의 기존 표시 제한을 넘어 전용 보고서와 페이지 목록에서 확인할 수 있습니다. 과정 완료와 최종 정답은 별도 열입니다.

기존 수동 활동도 사용할 수 있습니다. **선택: 기존 기초 예제로 활동 만들기**에서 Python 기초 예제와 플랫폼 배열·빈칸 문제를 연결합니다. 배열은 플랫폼 문제 편집기의 **코드 순서 배열 → 완성 코드**, 빈칸은 **코드 빈칸 완성 → 선택 영역을 빈칸으로 만들기**로 준비합니다.

## 5. 학생 활동

학생은 `/oj-addons/oj-primm/learn?activity=<활동 번호>`에서 예측·실행 비교·탐구·수정·제작을 진행합니다. 기본 학생 역할에는 최초 정상 초기화 때 **PRIMM 활동 참여** 권한을 부여하며 기존 명시적 허용·거부와 이후 회수는 유지합니다. 현재 소속 공간에서 본인 기록만 조회합니다.

최초 예측·단계 응답·초안·도움 입력을 저장하고 재접속해 이어 갑니다. 여러 탭 저장 충돌 때 서버 내용과 로컬 초안을 비교해 복원합니다. 완료 단계는 읽기 전용으로 다시 열 수 있으며 현재 단계를 바꾸지 않습니다. 예측이 틀렸다는 이유로 차단하지 않습니다. 화면은 기본 예제와 AI 생성 예제의 출처를 구분하며 OJ 검증 상태를 별도로 표시합니다.

배열은 모든 조각을 한 번씩 사용하고 내용·들여쓰기는 고정합니다. 조밀한 행과 손잡이 드래그·터치·위아래 버튼·Alt+방향키를 지원합니다. 빈칸은 지정한 칸만 입력합니다. 새 자료의 Modify에서는 수정 코드나 배열·빈칸 복원 코드로 **수정 코드 실행·확인**을 누릅니다. 현재 저장 코드가 모든 사례를 통과해야 Make로 이동합니다. 연습 결과는 공식 제출·AC에 포함하지 않습니다.

Make에서 코드를 작성하고 **채점 화면에서 제출하기**를 누르면 초안을 저장하고 기존 OJ 제출 화면을 새 탭으로 엽니다. 저장한 코드와 수업 언어를 자동으로 채우므로 복사·붙여넣기가 필요 없습니다. 학생은 채워진 코드를 확인하고 필요하면 수정한 뒤 직접 **제출하기**를 누릅니다. PRIMM 학습 창으로 돌아오면 본인의 새 제출과 채점 결과를 자동 연결합니다. 제출번호도 복사할 필요가 없습니다. 팝업이 차단되면 표시된 제출 화면 링크를 사용합니다.

초안 전달을 준비하는 동안 편집을 잠시 고정합니다. 전달 링크는 같은 계정·문제·수업에서 5분간 사용할 수 있으며, 만료되거나 초안을 바꿨다면 PRIMM에서 다시 준비합니다. 전체 코드 제출 문제에서 자동 채우기를 지원하며, 최종 문제 자체가 배열·빈칸 방식이거나 수업 언어를 허용하지 않으면 기존 문제 정책을 안내합니다. OJ 화면에서 수정한 코드를 PRIMM 초안에 자동으로 덮어쓰지는 않습니다.

처음 제작 단계에 들어왔을 때 과거 정답을 자동 연결하지 않습니다. 기존 결과를 사용하려면 **이전 내 제출 결과 사용**을 누릅니다. 연결한 제출은 같은 번호의 결과를 계속 조회하며 다른 탭의 새 제출로 바뀌지 않습니다. 제출 시각과 결과를 표시하고, 현재 초안과 다른 코드의 결과이거나 저장된 원문을 비교할 수 없으면 안내합니다. 코드 자동 채우기만으로 채점 요청이나 공식 제출이 생성되지는 않습니다.

자동 확인은 화면이 활성화된 동안 제한된 시간만 진행합니다. 오래 걸리거나 결과 공개 정책 때문에 연결하지 못하면 **채점 결과 다시 확인** 또는 OJ 결과 화면을 이용합니다. 과정 완료와 공식 정답은 별도로 보관하며 기존 OJ의 제출·재제출 제한을 적용합니다.

## 6. 보관·삭제

AI에는 문제의 공개 자료와 생성된 수업·예제 실행 진단을 보냅니다. 학생 코드·응답·명단·비공개 테스트는 보내지 않습니다. 학생 수정 코드는 기존 OJ의 비공개 연습 실행 경로로 전달합니다. Make 초안을 제출 화면으로 전달할 때는 플랫폼의 암호화 임시 저장소에 보관하고 5분 후 링크가 만료되며, 만료된 자료는 플랫폼의 기존 예약 정리로 제거합니다. 코드 원문은 URL에 넣지 않습니다. 자료 버전·생성 상태·사용량·학생 기록·개인 연습 결과를 저장합니다. 플랫폼 **운영 → 약관과 정책**의 저장 항목 재고에서도 확인합니다.

완료한 네이티브 실행 자료는 24시간이 지난 뒤 독립 예약 작업으로 정리합니다. 실행 중인 자료는 채점기 쓰기와 겹치지 않도록 종료를 확인한 뒤 지우며, 정체 상태는 제출 설정에서 확인합니다. 플랫폼 AI 요청 원장은 결과 재사용·불명확 상태 보존을 담당합니다.

기본 보존은 무기한입니다. **설정 → OJ PRIMM**의 `0`은 무기한, `1`~`3650`은 학생 응답·초안·진행·연습과 종료된 생성 작업의 보관 일수입니다. 매일 정리하며 수업 자료는 유지합니다. WordPress 개인정보 도구에서 개인별 내보내기·삭제를 지원합니다.

비활성화와 일반 삭제는 기록을 보존합니다. **삭제 시 데이터 제거**를 명시적으로 켠 뒤 플러그인을 삭제할 때만 전용 6개 테이블과 옵션을 제거합니다. 먼저 백업합니다.

## 7. 설치 후 인수 확인

- 사용할 언어의 고정 실행 검사, AI 작업 배정과 실제 생성·검증 완료를 확인합니다.
- 문제 저장·학급 배정 뒤 자동 준비와 정상 자료 자동 공개·검토 자료 공개 차단을 확인합니다.
- 배열·빈칸 각각 생성해 학생 실행·저장·새로고침·Make 이동을 확인합니다.
- Make에서 작성한 초안과 언어가 제출 화면에 정확히 채워지고, 직접 제출한 뒤 돌아와 번호 입력 없이 새 본인 결과가 연결되는지 확인합니다. 처음 입장할 때 과거 정답이 자동 연결되지 않는지, 명시적으로 이전 결과를 사용할 수 있는지도 확인합니다.
- 틀린 출력·채점기 중단·AI 연결 오류에서 자료가 오인 공개되지 않는지 확인합니다.
- 두 탭 저장 충돌 복구, 완료 단계 열람, 자료 새 버전과 회수, 미시작 학생 보고서·CSV를 확인합니다.
- 실제 WordPress·MariaDB·AI 제공자·채점 서버의 판정은 설치 사이트에서 수행합니다. 로컬 가짜 채점기 테스트 통과와 구분합니다.
