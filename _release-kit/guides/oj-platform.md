## 하는 일

모든 애드온의 기반입니다. HUSTOJ 채점 DB(`jol`)에 연결해 문제, 제출, 반, 권한, AI 설정을 관리합니다.

OJ Platform은 다른 애드온 없이 단독 설치할 수 있습니다. WordPress 플러그인 목록의 OJ Platform 행에는 애드온 의존 목록을 별도로 표시하지 않습니다. 이는 표시만 조정하는 것으로, 각 애드온의 OJ Platform 필수 설치 검사와 사용 중인 플랫폼의 비활성화·삭제 보호는 유지합니다.

학습자용 애드온의 안전한 참여 권한과 계정 관리 권한을 구분합니다. 애드온은 공개 `oj_platform_unprivileged_addon_capabilities` 필터로 자기 학습자 권한을 명시할 수 있으며, 이 예외는 관리자·superadmin 보호나 작업자의 계정 관리 권한 검사를 생략하지 않습니다. 학생 자동 추적을 사용하는 Focus Tracker 업데이트에서는 이 확장이 포함된 플랫폼을 먼저 설치합니다.

## 1. 서버 준비

새 서버에서 자동 설치 스크립트를 사용하면 플랫폼 설치 마법사·채점 DB 연결·테스트데이터 설정까지 완료됩니다. 명령은 [서버 준비](00-server-setup.md)의 **새 서버 자동 설치**를 참고합니다.

[서버 준비](00-server-setup.md) 1~12단계를 먼저 마칩니다. 12단계에서 메모한 채점 DB 접속 정보가 아래 3단계에 필요합니다. 이미지 채점(Matplotlib·turtle)을 쓰려면 16·17단계도 진행합니다.

## 2. 업로드와 설치 마법사

1. 관리자 화면에서 `packages/{{package}}`를 업로드하고 **활성화**합니다.
2. 왼쪽 메뉴의 **OJ Platform 설치**를 누르고 **실행**합니다.
3. 완료되면 채점 DB 설정 화면(`/oj-console/settings/database`)으로 자동 이동합니다.

"테이블 이름 충돌"이 나오면 같은 이름의 테이블이 이미 있다는 뜻입니다. 이때는 진행하지 말고 서버 준비 20단계로 백업한 뒤 원인을 확인합니다.

## 3. 채점 DB 연결 — `/oj-console/settings/database`

| 칸 | 값 |
|---|---|
| 호스트 / 포트 | `OJ_HOST_NAME` / `OJ_PORT_NUMBER` (보통 `127.0.0.1` / `3306`) |
| 데이터베이스 | `jol` |
| 읽기 계정·비밀번호 | `OJ_USER_NAME` / `OJ_PASSWORD` |
| 쓰기 계정·비밀번호 | 위와 같은 값 |
| TLS | 끔 (같은 서버일 때) |
| 기존 제출 일시가 UTC | 서버 준비 12단계 `timedatectl` 결과가 `Etc/UTC`면 체크 |

**연결 시험**(15분에 5회까지) → **적용** 순서로 누릅니다.

## 4. 테스트데이터 — `/oj-console/settings/test-data`

기본값 그대로 **저장**합니다: 폴더 `/home/judge/data`, 컴파일러 `/usr/bin/gcc`·`/usr/bin/g++`, 실행 제한 `/usr/bin/prlimit`, 샌드박스 `/usr/bin/bwrap`.

## 5. (선택) AI·메일

| 화면 | 설정 |
|---|---|
| `/oj-console/settings/ai-provider` | AI 제공자, 주소, **API 키**, 모델 → 시험 → 저장 |
| `/oj-console/settings/ai-routing` | 작업별로 사용할 AI 프로필 지정 (OJ AI Dashboard도 사용) |
| `/oj-console/settings/smtp` | 메일 발송 서버 |
| `/oj-console/roles` | 역할과 권한 (애드온 권한 포함) |

기존 AI 프로필에 새 애드온 작업을 추가하다 연결 검사의 전체 시간 제한에 걸리면 프로필의 **복제**를 사용합니다. 새 프로필 키를 입력하고 새 작업만 선택해 **후보 연결 검사 → 검사한 프로필 저장**을 진행한 뒤 작업 배정에서 연결합니다. 기존 프로필과 작업 배정은 유지합니다. 연결 대상·인증 방식이 같은 경우에만 서버가 기존 비밀값을 재사용하며 비밀값 자체를 화면에 표시하지 않습니다. 복제는 기존 프로필 키를 덮어쓰지 않습니다.

## 6. 애드온 공식 연동

Addon API 1.6은 교사용 예제 검증과 학생용 연습 실행을 별도의 선택형 계약으로 제공합니다. 현재 사용자·소속·자료 버전을 매번 검사하며 비공개 실행 번호를 사용자·애드온·자료에 묶습니다. 연습은 학생의 문제 제출·정답 횟수·수업 점수에 포함하지 않습니다. 채점 DB 연결, 기존 `custominput` 테이블과 쓰기 권한, 동작 중인 채점 프로세스가 필요합니다. 정상 종료가 확인된 출력만 반환하며 연결 오류나 미완료 출력을 검증 성공으로 처리하지 않습니다.

**제출 → 제출 설정**(`/oj-console/submissions/settings`)을 엽니다. 상단 **언어와 결과 갱신 → 직접 제출 허용 언어**를 선택하고 **언어 설정 저장**을 누릅니다. 하단 **예제·실습 실행 지원**에서 언어별 **실행 검사 → 결과 조회**로 **실행 통과**를 확인합니다. Python·C·C++·Java 중 허용되고 실제 시험에 성공한 언어만 애드온에 제공합니다. 업데이트 직후에는 기존 설정만으로 시험 성공을 간주하지 않습니다. 채점기·언어 설정 변경 후 다시 시험합니다. 같은 화면에서 실행 동시·시간당 한도, 정체 상태와 정리 결과를 확인합니다. 완료한 실행 자료는 24시간이 지난 뒤 독립 예약 작업으로 정리하며 진행 중인 자료는 종료를 확인한 뒤 정리합니다. 방문이 없는 시간에도 서버 준비 11단계의 WordPress 예약 실행이 필요합니다.

AI 요청 결과와 처리 중·불명확 상태는 플랫폼 원장에 저장합니다. 같은 요청을 다시 받으면 7일 보관 기간 안에서 결과를 재사용하고, 호출 뒤 결과 수신 여부가 불명확한 경우 자동 재전송을 차단합니다. PRIMM은 미완료 작업의 최대 수명을 24시간으로 제한해 원장 정리 후 자동 재발송을 막습니다. 원문 생성·오류 수정 정책, 예상 출력 비교와 학생 진행 관리는 PRIMM에서 담당합니다. 공개 문제 저장·학급 문제 배정 이벤트로 권한 있는 애드온이 자료 자동 준비를 연결할 수 있습니다.

새 비공개 실행은 WordPress 인증 salt와 분리된 플랫폼 전용 식별 키를 사용하므로 이후 salt 변경에도 개인별 삭제를 유지합니다. 2.3.25에서 시작한 기존 실행은 salt 변경 전에 종료·정리를 확인합니다. 이미 잃어버린 옛 salt로 만든 정체 실행의 사용자 매핑은 소급 복구할 수 없습니다. 업데이트 후 설치 마법사의 **설치 재개**가 표시되면 실행해 AI 요청 원장 테이블을 준비하며 기존 문제·제출을 다시 가져오지 않습니다.

OJ Platform 2.3.0의 Addon API 1.4는 명단, 공개 문제, 명단 범위의 정답 제출, 다른 애드온의 학습 활동을 `AddonIntegrationGatewayV1` 하나로 중계합니다. 애드온이 다른 플러그인의 테이블·옵션·PHP 클래스·REST 라우트를 직접 읽지 않도록 하고, 플랫폼이 현재 사용자와 수업 명단 권한을 다시 검증합니다.

학습자 식별자는 정수 `id`로 통일합니다. 명단은 학습자에게 보여 줄 **표시 이름**과 교사·관리자가 구분에 쓸 **관리용 이름**을 따로 제공할 수 있습니다. 이메일과 로그인 아이디는 애드온 명단 응답에 포함하지 않습니다.

자동 학습 확인 애드온은 선택형 `AddonLearningCheckRuntimeContextV1`을 통해 현재 학생이 열 수 있는 문제·공개 예제·본인 제출 코드를 조회합니다. 기존 수업·그룹·대회 및 제출 코드 공개 제한을 다시 확인하며 비공개 테스트·채점 래퍼·다른 학생 코드는 제공하지 않습니다. 교사가 문항을 제작하지 않아도 운영할 수 있고, 출제·정답 검증·응답 해석은 해당 애드온이 담당합니다. 외부 AI 설정은 이 조회 API에 필요하지 않습니다.

애드온이 등록한 저장 항목과 보관 기간은 **운영 → 약관과 정책**의 통합 재고에서 확인합니다. 각 애드온은 처리방침 문구를 자동 생성하거나 게시하지 않으며, 관리자가 이 재고를 검토해 플랫폼의 통합 문서를 작성·게시합니다.

## 업데이트·삭제

공통 HTML 응답에는 `X-Frame-Options: SAMEORIGIN`, CSP의 `frame-ancestors 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`이 자동 적용됩니다. 로그인·복구·비밀번호 재설정·계정 전환 화면에는 `Cache-Control: private, no-store`와 `Referrer-Policy: no-referrer`를 적용합니다. HSTS는 [서버 준비](00-server-setup.md) 5단계에서 nginx에 설정합니다.

OJ 로그인 런타임을 사용할 수 있고 환경 준비 검사를 통과했으며 **로그인과 계정** 기능이 켜져 있으면, 기본 WordPress 로그인·비밀번호 복구·회원가입 입구를 OJ 화면으로 연결합니다. 기본 로그인에 보낸 POST의 아이디·비밀번호는 전달하지 않으므로 OJ 로그인 화면에서 다시 입력합니다. 관리자는 `/login`에서 로그인한 뒤 `/wp-admin/`을 열 수 있습니다. 세션이 만료되면 새 탭에서 다시 로그인합니다. `/wp-admin/` 전체나 `admin-post.php`·`admin-ajax.php`를 차단하지 않습니다.

초기 설치·업그레이드 대기·환경 준비 오류 및 검증된 WordPress 복구 모드에서는 기본 로그인을 유지합니다. 로그아웃·암호로 보호된 글·요청 확인 등 WordPress의 별도 처리도 유지합니다. XML-RPC·REST·다른 플러그인의 인증을 일괄 차단하는 기능은 아닙니다. 적용 확인과 서버에서만 가능한 비상 해제는 [서버 준비](00-server-setup.md) 5단계를 따릅니다.

OJ Platform 자체 코드는 **GPL-3.0-or-later**로 배포합니다. 공통 푸터의 **오픈소스 라이선스**(`/open-source-licenses`)에서 로그인 없이 GPL 전문과 포함 라이브러리의 버전·용도·개별 라이선스·원본 소스를 확인합니다. WordPress·HUSTOJ는 별도 설치 시스템으로 구분합니다. 배포 시 루트 `LICENSE.txt`, `THIRD_PARTY_NOTICES.txt` 및 각 외부 라이선스 파일을 보존하고 수정본의 소스 제공 등 적용되는 조건을 지키세요. 외부 구성요소는 각 원래 라이선스를 유지하며 사용자 제출 코드·문서에 GPL이 자동 적용되지는 않습니다.

공개 약관·동의 화면과 공통 편집기의 본문은 동일한 줄간격·문단·제목·목록 여백을 사용합니다. HTML 태그 사이의 소스 줄바꿈은 추가 빈 줄로 표시하지 않으며, 명시한 줄바꿈(`br`)과 코드 블록의 줄바꿈은 유지합니다.

동의 문서 목록의 **수정**을 누르면 해당 문서의 최신 제목·본문·필수 여부를 공통 편집기로 불러옵니다. 수정본은 새 버전으로 게시하며 이전 문서와 동의 기록은 덮어쓰지 않습니다. 버전은 현재 버전에 `.1`을 붙여 제안하고 게시 전에 원하는 값으로 바꿀 수 있습니다. **새 문서 작성**은 불러온 내용을 비운 새 작성 화면으로 이동합니다.

문제 설명·입력·출력·힌트, 게시판·공지 본문과 동의 문서는 같은 Jodit 공통 편집기를 사용합니다. 아이콘에 마우스를 올리면 기능 이름이 표시됩니다. 모바일에서는 추가 도구를 더 보기 메뉴에서 엽니다. 라이브러리와 한국어 자산은 플러그인에 포함되어 외부 CDN이나 API 키가 필요하지 않습니다.

격자 모양 표 버튼에서 원하는 행·열 크기를 선택해 삽입합니다. 표 안의 셀을 선택하면 행·열 추가/삭제와 셀 병합/분할 도구가 나타납니다. `</>` 버튼은 HTML 소스 편집과 시각 편집을 전환하며 소스 상태에서도 저장할 수 있습니다. 표와 셀 병합은 HTML로 보존합니다. DOMPurify와 WordPress 보안 필터가 위험한 HTML을 제거합니다. 문제의 이미지 업로드와 LaTeX 삽입은 유지하며 게시판 첨부파일과 댓글 방식은 변경하지 않습니다.

관리자 대시보드의 담당 바로가기 숫자는 아래에 표시하는 학습 공간과 관리 메뉴 전체를 집계합니다. 사용자 홈의 내 학습 공간 → 전체 보기는 `/learning-spaces`로 연결되며, 현재 사용자가 열 수 있는 수업·대회·그룹을 한 페이지에 20개씩 표시합니다. 홈의 요약 표시 수 제한은 그대로 유지합니다.

사용자 화면과 로그인 화면의 공통 하단 **약관 및 정책 문서** 메뉴에서 이용약관·개인정보 처리방침·저작권 정책·이메일 수집 거부·법정대리인 동의서를 로그인 없이 열람합니다. 로그인 카드에는 비밀번호 복구·회원가입 같은 계정 작업만 표시해 이용약관 링크를 중복하지 않습니다. 게시된 최신 문서를 표시하며 미게시 문서는 미게시 상태를 알립니다. 내 정보 → 동의 현황은 문서 버전과 본문을 함께 표시하고, 미동의 문서는 본문을 펼친 상태로 제공합니다. 필수·선택 동의를 구분하며 법정대리인 문서는 일반 사용자 동의 항목에 포함하지 않습니다.

**운영 → 사이트**에서 공통 푸터의 운영 안내, 저작권 표시, 관리자 이메일과 추가 링크를 관리합니다. 약관과 정책 문서 5종은 플랫폼이 항상 제공하고, 학교 홈페이지·도움말처럼 별도로 필요한 링크를 최대 6개까지 추가할 수 있습니다. 같은 주소는 한 번만 표시하며 내부 경로(`/help`)와 HTTP(S) 주소만 저장합니다.

제출 → AI 피드백 → 피드백 기록에서 사용자 아이디·수업 번호·문제 번호로 저장된 피드백을 조회합니다. 목록에서 내용을 펼치거나 관리자 제출 상세로 이동할 수 있습니다. 사용자 → 역할과 권한에서 AI 피드백 관리 권한을 부여하고, 전체 제출을 조회하려면 제출 관리·제출 상세 열람·제출 코드 열람 권한도 확인합니다. 수업·대회 담당자는 기존 제출 열람 범위 안에서만 볼 수 있습니다. 생성 정책이 변경되어도 관리자 검토용 저장 피드백은 삭제하거나 숨기지 않으며, 학습자에게 새 피드백을 생성하는 권한·정책은 변경하지 않습니다. 현재 저장 구조는 제출당 최신 피드백 한 건을 보관하므로 재생성 전의 모든 버전을 보여주는 기록 목록은 아닙니다.

홈의 이어서 풀기는 동일 문제의 과거 오답을 중복 추천하지 않으며, 전체 유효 제출에 정답 이력이 있는 문제를 제외합니다. 사용자 모바일 2차 메뉴는 텍스트로 통일하고, 모바일 관리자 대시보드의 요약 지표는 2열로 표시합니다.

관리자 사이드바는 1차 메뉴에 공통 Lucide 아이콘을 표시하고, 2차 메뉴는 아이콘 없이 텍스트로 통일합니다. 하위 메뉴 펼침·접힘 화살표는 1차 메뉴 오른쪽에만 표시합니다. 미지정 애드온 메뉴의 기본 아이콘은 퍼즐이며, 지원하지 않는 아이콘도 퍼즐로 대체합니다.

문제 목록과 상세의 정답·제출 횟수는 HUSTOJ `solution`의 유효 제출(`valid=1`)에서 집계합니다. 일반·수업·대회 제출을 모두 포함하며, 정답 횟수는 그중 `result=4`인 제출 수입니다. 삭제 처리된 제출은 제외하고, 대회 종료나 보관만으로 제출을 제외하지 않습니다. HUSTOJ `problem` 테이블의 누적 카운터는 변경하지 않습니다.

- 수업·그룹·대회 목록의 **보관**으로 운영 목록에서 옮기고, **보관됨** 목록의 **복원**으로 되돌립니다. 보관 권한이 있는 소유자·관리자에게 버튼이 표시되며 학습 기록은 유지됩니다. 대회의 **보관 대회 제출**은 보관된 대회의 정상 제출을 조회하는 화면입니다. 종료 시각이 지난 대회는 종료 상태로 남으며, 제출의 무효 처리·복원은 별도의 제출 삭제 기록에서 관리합니다.
- 게시판·공지·댓글은 입력한 줄바꿈과 빈 줄을 화면에 반영합니다. 기존 글도 다시 저장할 필요 없이 적용되며 HTML 문단과 코드 블록은 유지됩니다.
- **업데이트**: [서버 준비](00-server-setup.md) 20단계로 백업한 뒤 같은 방법으로 업로드하고 "교체"를 선택합니다. 설치 마법사가 다시 나타나면 실행합니다. 서버의 PHP·nginx 갱신은 2단계, HTTPS 보안 헤더와 기본 로그인 입구의 GET 응답 확인은 5단계를 따릅니다.
- **삭제**: 아무 데이터도 지우지 않습니다. 다른 애드온이 모두 이 플러그인에 의존하므로 운영 중에는 비활성화하지 마세요.

## 코드 순서 배열 문제

문제 만들기·수정에서 코드 작성 방식을 **코드 순서 배열**로 선택하고 Python·C·C++·Java 중 한 언어와 완성 코드를 입력합니다. 입력·출력 설명과 채점 데이터는 기존 문제처럼 준비합니다. 완성 코드의 정답 여부는 교사가 기존 채점 환경에서 확인합니다. 시스템은 논리 줄 단위로 조각을 나누며 여러 줄 문자열·괄호로 이어지는 코드는 함께 묶습니다. 조각은 2~200개이며 모든 조각을 한 번씩 사용합니다. 조각 내용과 들여쓰기는 수정할 수 없습니다.

학생은 드래그 또는 위·아래 이동 버튼으로 조각을 배열하고 제출합니다. 번호·잡기 손잡이·코드·작은 이동 버튼을 한 행에 표시하고, 여러 줄 조각만 내용에 맞춰 높아집니다. 터치 화면은 손잡이를 끌어 이동하며 삽입 위치를 표시합니다. Alt+방향키 이동도 지원합니다. 표시를 위한 끝 줄바꿈 정리는 실제 코드나 들여쓰기를 바꾸지 않습니다. 배열은 문제 버전·수업 문맥별로 브라우저 탭에 임시 보관합니다. 서버가 등록된 조각으로 코드를 복원해 기존 채점기에 전달하므로, 원본과 다른 순서라도 테스트케이스를 통과하면 정답으로 인정합니다. 교사가 코드를 변경하면 이전 버전의 배열 제출은 새로고침 안내와 함께 거부합니다.

업데이트 후 설치 화면에서 문제 메타데이터의 추가 열 적용을 마칩니다. 외부 채점엔진 테이블은 변경하지 않습니다. PRIMM 등 애드온은 선택형 코드 배열 런타임 계약을 확인한 뒤 퍼즐 조회·코드 복원을 사용할 수 있습니다. 이 계약은 최종 정답 판정을 대신하지 않으며 채점은 기존 제출 경로를 사용합니다.

PRIMM은 별도 애드온 ZIP으로 설치합니다. 플랫폼을 먼저 업데이트한 뒤 [PRIMM 설치 안내](11-oj-primm.md)를 따릅니다. PRIMM은 문제·입출력으로 단계별 예제·질문·수정 과제와 배열·빈칸 도움 자료를 AI 생성합니다. 도입 예제와 수정 기준 코드의 예상 출력을 OJ에서 자동 검증하고 오류가 있으면 최대 두 번 수정·재검증한 뒤 모든 사례가 통과한 자료만 배포합니다. 플랫폼 AI 작업 배정에서 PRIMM 생성 모델을 연결합니다. 기존 **코드 빈칸 완성**·배열 문제를 수동 연결하는 방식도 유지합니다. 학생의 최종 정답 판정은 별도로 기존 OJ 제출·채점 결과를 사용합니다.

## 로그인 이후 권한 보호

사용자 운영 권한만 가진 담당자는 일반 학습자의 계정 정보를 관리할 수 있습니다. 운영 권한이 있는 계정의 이메일·프로필 또는 이용 상태를 바꾸려면 해당 계정에 대한 WordPress 사용자 편집 권한도 필요합니다. 권한이 없으면 수정·이용 상태 버튼을 제공하지 않으며 저장 요청도 거부합니다. 역할 이름뿐 아니라 계정에 실제 부여된 운영 권한을 확인합니다.

그룹·수업의 구성원으로 추가해도 다른 운영 계정의 비밀번호를 초기화할 수 없습니다. 일반 학습자의 초기화와 기존 세션 폐기는 유지합니다. 승인 대기 계정은 이용 상태 전환으로 활성화할 수 없으며, 가입 승인 권한과 필수 문서·법정대리인 동의를 확인하는 가입 승인 절차를 거쳐야 합니다.

제출 요청 키의 재사용은 같은 계정에서만 허용하고, 백그라운드 작업의 중복 판정도 계정별로 구분합니다. 개인화된 화면과 운영 화면을 포함한 플랫폼 HTML은 `Cache-Control: private, no-store`로 반환합니다. 기존에 외부 캐시가 저장한 응답을 삭제하는 절차는 [서버 준비](00-server-setup.md) 5단계를 따릅니다.

업데이트 후 일반 점검 계정으로 사용자·시스템 운영 화면이 제한되는지 확인합니다. 담당자 계정으로는 허용된 일반 학습자 관리 기능을 확인하고, 상위 운영 계정의 수정·이용 상태 버튼이 권한에 맞게 제한되는지 확인합니다. 실제 계정의 이메일·비밀번호·권한을 바꾸거나 다른 사용자의 제출 키를 재사용하는 시험은 운영 사이트에서 수행하지 않습니다. 서버 프로그램의 별도 설정 변경은 필요하지 않습니다.

## 입력·저장·외부 통신 경계

게시판·공지는 OJ 댓글 화면과 서비스가 계정 상태·참여 범위·비밀글·nonce를 확인한 뒤 저장합니다. 기본 WordPress 댓글 제출 입구에서는 OJ 게시글·공지 댓글을 받지 않습니다. 기존 OJ 댓글과 일반 WordPress 게시글의 댓글은 유지합니다.

관리용 학생 이름은 OJ 사용자 관리·권한 있는 그룹 담당자의 이름 수정에서만 바꿉니다. WordPress 기본 프로필과 REST의 본인 프로필 수정으로는 이 이름을 바꿀 수 없습니다. 기존 이름이 비어 있던 계정은 공개 이름 변경 전에 이전 관리 표시를 고정합니다. 공개 표시 이름·다른 프로필 값과 계정 익명화는 기존 정책을 유지합니다.

AI 연결은 PHP cURL 확장과 직접 HTTPS 연결이 필요합니다. 제공자 주소의 IPv6·IPv4 매핑 표기를 같은 주소로 비교하고, 승인한 IP를 실제 연결에 고정하며 TLS 호스트 검증을 유지합니다. 금지 네트워크와 Judge 주소 분리를 우회할 수 있는 표기는 거부합니다. HTTP 프록시를 통한 AI 연결은 주소 고정을 보장할 수 없어 거부합니다. 확장 설치와 FPM 확인은 [서버 준비](00-server-setup.md) 8단계를 따릅니다.

문제 XML은 UTF-8만 받고 DOCTYPE을 허용하지 않습니다. 테스트데이터 ZIP의 임시 생성물은 전용 비공개 디렉터리에 보관하고 정리합니다. SPJ 컴파일 프로세스의 출력은 종료 직전까지 합산 한도를 적용합니다. 실제 컴파일은 기존 bubblewrap 격리를 유지하며 격리 실패 시 호스트에서 재시도하지 않습니다.

## 서버 설치 창

설치 마법사의 **서버 설치 열기**, 운영 설정의 **서버 설치·복구**, WordPress 플러그인 목록의 **서버 준비 필요** 안내에서 서버 준비 명령을 복사할 수 있습니다. AI·ML은 활성화 전에 준비하세요. 서버 설치 권한이 있는 관리자에게 표시됩니다.

공통 준비 화면은 OJ Platform 2.2.7 이상에서 제공합니다. 명령은 서버 설치 권한이 있는 관리자가 실행합니다.

서버 설치 메뉴와 자산은 WordPress 요구 버전을 충족한 뒤 등록합니다. 요구 버전 미달 상태에서는 기존 오류 안내만 표시합니다. 운영 설정의 설치 링크도 WordPress `install_plugins` 권한을 확인하며, OJ 운영 권한만으로 서버 설치 명령 화면을 열 수는 없습니다.

OJ Platform 2.2.9 이상에서 업로드된 플러그인만 공통 화면에 표시합니다. 복사 명령은 `sudo bash …/resources/server/install.sh` 형식입니다. 필요한 PHP CLI는 설치기가 준비하며, PHP 보조 파일은 `wp-config.php` 검사·수정에만 사용합니다.

Platform에는 그림 채점용 설치기만 포함합니다. AI·ML·읽기자료 준비 명령은 업로드된 각 플러그인의 설치기를 사용하며, 미설치 플러그인은 표시하지 않습니다.

서버 준비가 필요한 경우에만 플러그인 목록과 관리자 OJ 콘솔 첫 화면에 안내합니다. 준비를 마치면 새로고침 후 안내가 사라집니다. 상시 OJ 서버 설치 메뉴는 표시하지 않습니다.

## 하단 링크와 라이선스

**운영 → 사이트 → 하단 기본 링크 표시**에서 이용약관·개인정보 처리방침·저작권 정책·이메일 수집 거부·법정대리인 동의서·오픈소스 라이선스의 표시 여부를 각각 저장합니다. 하단 링크를 숨겨도 문서 주소와 동의 절차는 유지됩니다. 오픈소스 고지는 `/open-source-licenses`의 **설치된 추가 플러그인**에서도 확인할 수 있습니다. 제공 애드온의 설치 파일이 있는 경우에만 해당 고지를 표시하며, 자체 라이선스 미선언은 독점 이용허락을 의미하지 않습니다.

## 마지막 기록 오류 확인

**운영 → 시스템 상태 → 마지막 기록 오류**에서 발생 작업, 안전한 원인 설명, 다음 조치를 확인합니다. 시스템 관리 권한(`oj_manage_system`)이 있으면 펼쳐진 기술 정보에서 오류 코드·발생 파일과 줄 번호·원인 예외·추적 ID를 함께 확인할 수 있습니다. 요청 한도 초과와 카운터 저장 실패, 권한·세션 오류, 알려진 DB 오류 코드와 AI Provider 오류를 구분합니다. 오류 유형을 확인했더라도 DB·캐시·네트워크 중 실제 장애 지점은 다음 조치에 따라 점검해야 하며, 분류할 근거가 없는 오류는 **정확한 원인 확인 필요**로 표시합니다.

시스템 상태의 추적 ID와 같은 ID를 서버 PHP 또는 Nginx 오류 로그에서 검색합니다. `diagnostic_code=` 줄에는 읽을 수 있는 원인 설명과 다음 조치가, `exception_context=` 줄에는 같은 ID와 구조화 진단·인수 없는 호출 경로가 기록됩니다. 임의의 예외 원문·입력 코드·요청 인수·인증정보는 이 진단이나 플랫폼 오류 보고 로그에 추가하지 않습니다. 업데이트 이전 로그는 자동으로 지워지지 않으며, 이미 저장된 과거 오류에는 없던 상세 정보를 소급해서 만들지 않습니다. 화면 기록을 지우는 것은 오류 원인을 해결하는 동작이 아닙니다.
# 요청 제한 저장 오류 점검

## 동시 접속 성능 기준

최소 36명 동시 사용을 운영 인수 기준으로 둡니다. 단일 비로그인 URL의 응답 시간만으로 통과 판정하지 않습니다. 36개 독립 계정·세션에서 로그인, 홈·문제·수업 페이지 이동, 쪽지 갱신, 분산 제출을 조합해 실제 서버에서 측정해야 합니다. 오류율, 응답시간 p95, PHP-FPM 대기열, DB 느린 쿼리와 채점 지연을 함께 기록합니다. 운영 데이터에 제출을 생성하는 부하 시험은 별도 시험 계정·문제와 사전 계획으로 수행합니다.

일반 요청의 설치 상태 검사는 동일 요청에서 결과를 재사용합니다. 레거시 테이블 존재 확인에는 COUNT(*)를 수행하지 않으며, 실제 이전 검증에서 필요한 정확한 행 수 계산은 유지합니다. 이 최적화에 대한 회귀 검사 통과는 36명 운영 부하 시험 통과를 의미하지 않습니다.

기본 문제 주제의 존재 여부는 주제별 개별 조회 대신 일괄 조회하며, 누락 항목 생성과 별칭 보완은 유지합니다. 이 방식은 영구 캐시로 검사를 생략하지 않으므로 주제 변경·누락이 오래된 캐시 때문에 감춰지지 않습니다.

## 제출 코드 복사·붙여넣기

**제출 → 제출 설정 → 제출 제한**에서 **제출 코드 복사·잘라내기 허용**과 **제출 코드 붙여넣기 허용**을 각각 설정합니다. 기본값은 모두 허용이며 일반·수업·대회 제출 화면과 문제 안의 제출 패널에 같은 설정을 적용합니다. Ace 편집기와 기본 입력창, 코드 빈칸 입력에서 클립보드 이벤트·단축키를 제한하며 붙여넣기 금지 시 코드 입력란으로 끌어놓기도 차단합니다. 설정 변경은 화면을 새로 연 뒤 적용됩니다. 이는 브라우저 편집기 사용 제한이며 개발자 도구·직접 HTTP 요청·다른 입력 경로를 차단하거나 코드의 작성 출처를 판별하는 보안 기능은 아닙니다. 별도 DB 스키마 갱신은 없습니다.

## 비밀번호 초기화 결과

사용자·그룹 관리의 비밀번호 초기화 결과는 공통 컴포넌트로 기본 숨김 표시합니다. 로그인·가입·비밀번호 변경/복구·사용자 생성·수업 및 그룹 참가·SMTP 및 Judge DB 설정 등 공통 화면의 비밀번호 입력란에도 **보임·숨김** 전환을 제공합니다. 입력값과 자동완성·검증·전송 방식은 유지하며 저장된 서버 비밀번호를 다시 내려주지는 않습니다. Esc, 탭 이동, 화면 복귀 및 제출 시 숨김으로 복원하고 표시 상태를 저장하지 않습니다. 자동 생성 비밀번호도 새로 생성하면 숨깁니다. 초기화 결과 응답은 private, no-store로 캐시를 제한합니다. 화면을 닫으면 임시 비밀번호를 다시 조회할 수 없으므로 필요한 대상에게 안전하게 전달합니다.

## 수업 참여와 승인

수업 추가·수정의 **참여 승인 필요**를 끄면 공개 수업은 학생이 **수업 참여**를 눌러 즉시 참여하고, 비밀번호 수업은 목록에서 연 뒤 올바른 비밀번호를 입력하면 즉시 참여합니다. 설정을 켜면 참여 요청이 승인 대기로 저장되고 담당자가 승인해야 문제를 볼 수 있습니다. 비밀번호 수업도 목록과 참가 화면에는 표시하지만, 참여 전에는 문제와 제출·학습 기록에 접근할 수 없습니다. 비공개·연결 그룹 수업의 접근 제한은 유지합니다.

classes 테이블의 스키마 버전 2에 approval_required를 추가하므로 업데이트 후 설치 화면에서 스키마 갱신을 완료합니다. 기본값은 승인 불필요이며 기존 대기자를 자동 일괄 승인하지 않습니다. 승인 불필요로 바뀐 수업의 대기자는 다시 **수업 참여**를 눌러 즉시 참여할 수 있습니다. 거절·제외된 학생은 직접 재참여할 수 없으며 담당자가 참여 상태를 복원해야 합니다. 공동 강사는 이 승인 정책을 변경할 수 없습니다.

## 대회 참가와 승인

공개 대회는 **참가 승인 필요**를 끄면 **대회 참가** 버튼으로 즉시 참가합니다. 설정을 켜면 담당자가 승인해야 참가 상태가 활성화됩니다. 기본값은 승인 불필요이며, 기존 승인 대기자는 설정이 꺼진 대회에서 참가 버튼을 다시 눌러 활성화할 수 있습니다. 제외된 학생은 담당자의 복원 없이는 재참가할 수 없습니다. 준비·진행·종료 단계별 문제 및 제출 제한, 비공개·연결 그룹 접근 제한은 유지합니다. 참가 승인 정책은 다른 기본 설정과 마찬가지로 준비 단계에서 설정합니다.

contest_settings 스키마 버전 2의 approval_required 열이 추가되므로 설치 화면에서 스키마 갱신을 완료합니다. 현재 대회의 공개 범위는 공개·비공개·연결 그룹이며 비밀번호 참가 방식은 제공하지 않습니다. 기존 애드온 API 계약은 변경하지 않습니다.

## 페이지 없음 안내

존재하지 않는 주소에는 플랫폼 공통 디자인의 **페이지를 찾을 수 없습니다** 안내와 홈 이동 버튼을 표시합니다. 로그인 여부에 맞는 공통 화면을 사용하고 HTTP 404 상태를 유지합니다. 실제 WordPress 페이지·게시글과 JSON·피드 응답은 이 안내로 대체하지 않습니다. 웹 서버가 요청을 WordPress의 index.php로 전달하지 않고 자체 404를 반환하는 경우에는 서버 라우팅 설정을 먼저 확인해야 합니다.

## DB 조회 성능 개선

정상 설치가 완료된 런타임의 구조 검사는 최대 5분 동안 재사용합니다. 플랫폼 버전·설치 상태·설치 식별자·등록 스키마가 바뀌면 다시 검사하며, 설치·복구 화면은 항상 실제 DB 상태를 검사합니다. PHP 확장·DB 연결 등 실행 환경의 준비 여부는 매 요청 확인합니다. 외부에서 테이블을 직접 변경한 경우에는 설치·복구 화면을 열어 즉시 재검사할 수 있습니다.

학습 소속 학급·그룹은 실제 활성 참여와 연결 그룹 조건을 일괄 조회합니다. 공개 학급 수에 따라 개별 참여 확인 쿼리가 증가하지 않습니다. 타임어택용 최초 정답 시각은 권한이 확인된 학생·문제·기간 안에서 DB가 한 번에 집계합니다. Judge DB 테이블·인덱스는 자동 변경하지 않습니다.

Addon API 1.8은 학습 확인 자료에 문제 본문만 또는 본인의 최신 제출 한 건만 요청하는 선택형 조회를 추가합니다. 기존 기본 조회와 접근 권한 검증은 유지하며, 각 애드온은 다른 애드온의 코드나 테이블에 의존하지 않습니다.

문제 목록은 현재 페이지의 문제 번호만 묶어 정답·제출 수를 집계하며 긴 본문과 코드 템플릿은 읽지 않습니다. 상세 화면의 본문과 일반·수업·대회를 포함한 유효 제출 집계 기준은 유지합니다. 숫자 검색은 문제·제출 번호의 정확한 일치 검색이며, 제목·아이디 등 문자열 검색은 기존 부분 일치 방식입니다.

수업·그룹 제출 조회는 큰 OFFSET 대신 제출 번호 커서를 사용하고 사용자·문제·결과·기간 조건을 Judge 조회에 전달합니다. 수업 학습 현황은 수업 기간을 사이트 시간대에서 UTC로 변환해 조회하며, 학생이나 문제가 없는 경우 제출 이력을 읽지 않습니다. 정확한 보고서에 필요한 기간 내 기록은 여전히 모두 조회하므로 장기간 대규모 보고서의 실행 시간은 별도로 측정해야 합니다.

퀴즈 목록은 페이지당 최대 50개를 표시하고 해당 페이지의 통계·버전·문항을 묶어 읽습니다. 접근 가능한 퀴즈만 표시하며 권한 때문에 비어 있는 후보 페이지에서도 다음 페이지로 이동할 수 있습니다. 홈 학습 공간은 표시할 수업·대회·그룹 개수만 조회하고 기존 접근 권한을 적용합니다.

랭킹의 최신 집계 캐시는 60초이며 갱신 잠금으로 중복 전체 집계를 방지합니다. 다른 요청이 갱신 중이면 최대 300초 보관된 이전 집계를 사용하되 사용자 공개 설정은 매번 적용합니다. 이전 집계가 없는 최초 갱신 중에는 재시도 안내(HTTP 503)가 표시될 수 있습니다. WordPress DB 계정에서 MySQL GET_LOCK/RELEASE_LOCK 사용이 가능해야 합니다.

Judge 읽기 연결은 동일 요청 내에서만 재사용하며 쓰기 연결·트랜잭션은 분리합니다. 요청을 넘는 영구 연결은 사용하지 않습니다. 외부 애드온 API 계약은 변경하지 않습니다.

**업데이트 후 설치 화면에서 설치 재개/스키마 갱신을 완료합니다.** 쪽지 미읽음 집계용 복합 인덱스를 플랫폼 DB의 messages 테이블에 추가합니다(스키마 버전 2). 기존 메시지는 유지하며 Judge DB 테이블과 인덱스는 변경하지 않습니다. 운영 DB의 EXPLAIN·느린 쿼리 로그 및 36명 동시 접속 부하 시험은 별도 확인이 필요하며, 로컬 회귀 검증 통과가 운영 용량을 보장하지는 않습니다.

## 쪽지 알림과 사용자 찾기

쪽지 발송 한도는 **커뮤니티 → 쪽지 설정 → 10분당 발송 건수**에서 조정합니다(기본 10건, 1~30건). IP가 아닌 발송 사용자별로 집계하며 알림 조회·쪽지함 열람은 발송 횟수에 포함하지 않습니다. 수신자·권한·본문 검증을 통과한 발송 시도만 집계하고, 첫 시도부터 10분이 지나면 초기화합니다. 중간 발송이나 제한 후 재시도로 초기화 시각을 연장하지 않습니다. 저장소 오류 등 실제 장애는 기록하지만 한도 초과·잘못된 입력 등 예상 가능한 거절은 시스템 오류로 기록하지 않습니다. 새 고정 시간창 카운터는 기존 로그인·제출 제한과 분리되며 설정된 발송 한도 자체를 해제하지 않습니다.

커뮤니티 → 사용자 찾기 메뉴에서도 검색 화면을 열 수 있습니다. 사용자 메뉴 설정에서 이 항목의 표시 여부와 순서를 변경할 수 있습니다.

쪽지 기능을 켜면 사용자 화면 상단에 쪽지 아이콘과 읽지 않은 쪽지 개수를 표시합니다. 프로필 메뉴에서도 쪽지함·사용자 찾기로 이동할 수 있습니다. 활성 화면에서는 30초 간격으로 개수를 갱신하며, 대화를 열 때 읽음 처리합니다. 쪽지함의 읽지 않음 필터는 내가 답장한 대화에 남은 미확인 수신 쪽지도 포함합니다.

쪽지 쓰기 → 사용자 찾기에서 표시 이름이나 아이디 일부를 검색하고 상대를 선택합니다. 이메일·관리용 이름은 검색하거나 표시하지 않으며, 중지된 계정·본인·발송 범위 밖 사용자는 결과에서 제외합니다. 그룹 구성원과 수업 학습 현황에도 쪽지 바로가기가 있으며, 발송 가능 여부는 작성 화면과 전송 시 다시 확인합니다. 기존 애드온 API 및 MessageRepository 계약은 변경하지 않습니다.

OJ 콘솔 → 제출 관리 → 제출 설정 → 제출 제한에서 사용자별 제출 요청 횟수 제한을 켜거나 끄고 허용 횟수(1~1000), 카운터 만료 시간(1~3600초)을 설정합니다. 기본값은 사용, 30회, 60초입니다. 일반·수업·대회 제출에 공통 적용하며 최소 제출 간격 등 제출 검증에서 거절된 요청은 집계하지 않습니다. 정상 집계할 때마다 만료 시간이 연장되며, 설정을 끄더라도 최소 제출 간격은 유지됩니다. 기존 카운터는 설정 변경 시 즉시 삭제되지 않고 만료될 때 제거됩니다.

PRIMM 제작 단계의 제출 자동 연결에는 현재 본인·문제의 최근 제출 기준값을 제공합니다. 처음 제출하는 학생도 제출번호를 복사하지 않고 새 제출 결과를 연결할 수 있습니다. 원문 공개·대회 피드백 제한은 유지하며 별도 관리자 설정은 필요하지 않습니다. PRIMM과 플랫폼 ZIP을 함께 업데이트합니다.

Addon API 1.7의 선택형 초안 전달 기능은 PRIMM에서 작성한 코드를 기존 OJ 제출 화면에 자동으로 채웁니다. 코드·수업 언어·문제·학급을 본인에게 묶어 기존 암호화 임시 저장소에 보관하며 전달 링크는 5분 후 만료됩니다. 코드 원문은 URL에 넣지 않습니다. 제출 화면을 열 때 현재 소속·문제·언어 정책을 다시 확인하고, 학생이 **제출하기**를 눌러야 공식 채점 요청을 만듭니다. 별도 서버 서비스나 AI 설정은 추가하지 않습니다.

제출 중 `요청 횟수 제한 상태를 저장하지 못했습니다.`가 기록되면 transient 저장 상태를 확인합니다. 동일 값이 이미 저장된 경우에는 재조회로 확인하고 계속 처리하며, 실제 저장 실패는 보호를 유지하기 위해 차단합니다. 오류가 지속되면 WordPress DB 및 오브젝트 캐시 상태를 점검합니다.
