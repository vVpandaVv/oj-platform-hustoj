# 마이크로비트 실습·채점 설치

현재 버전은 **{{version}} 출시 후보**입니다. 선택한 집중형 샘플과 실제 생성·보기 화면의 버튼·여백·카드·핀별 출력 행 차이를 수정했습니다. 여러 핀의 일괄 설정은 유지합니다. OJ Platform 2.5.9·Addon API 1.9 이상을 먼저 설치하고 이 ZIP을 적용합니다. 스키마 5와 기존 채점 계약을 사용합니다. 실제 시험 서버에서 승인하기 전에는 운영 검증을 마친 정식 1.0으로 표시하지 않습니다. 동봉 `docs/FEATURE-FREEZE.md`, `docs/ACCEPTANCE-CHECKLIST.md`, `docs/ACCEPTANCE-REPORT-TEMPLATE.md`와 **서버 준비 22-5단계**를 사용합니다.

## 서버 준비

공통 1~12단계와 **서버 준비 22단계(마이크로비트 실행기)**를 진행합니다. MakeCode 편집·HEX·USB 기능만 사용할 때는 실행기 없이 시작할 수 있지만 센서 실험과 자동 채점에는 실행기가 필요합니다.

ZIP을 설치·활성화한 뒤 Ubuntu 24.04 amd64 서버의 SSH에서 한 번 실행할 수 있습니다. 필요한 PHP 8.3 CLI와 WordPress가 같은 호스트에 있어야 합니다.

신규 Docker 호스트를 포함해 포트 사전 점검용 `ss`(iproute2)가 필요합니다. 없으면 설치기는 패키지 변경 전에 중단하므로 서버 준비 22-0단계를 확인합니다.

```bash
sudo bash /home/judge/src/web/wp-content/plugins/oj-microbit/runner/install.sh
```

전용 Node·Docker 준비, 이미지 빌드, 서비스 등록, 실제 GPIO 점검과 WordPress 연결을 자동 처리합니다. 경로가 다르면 **설정 → OJ Microbit**의 설치 명령을 복사합니다. `--dry-run`으로 계획, `--check`로 설치 후 진단을 확인하며, 계정 지정·백업·실패 복원은 서버 준비 22-0단계와 동봉 `docs/INSTALLER.md`를 따릅니다. 기존 Docker가 있으면 APT·저장소·Docker 서비스 시작/재시작 없이 재사용하며 도구가 부족하면 중단합니다. 다른 서비스의 포트를 종료하지 않고, npm·이미지 빌드 전 설치·Docker 파일시스템에 각각 4GiB 이상 여유를 요구합니다. HUSTOJ 자원 보존과 공유 CPU·디스크 부하의 현장 확인은 동봉 `docs/HUSTOJ-COEXISTENCE.md`를 따릅니다. 실제 Ubuntu 설치는 시험 서버에서 먼저 확인합니다.

## ZIP 업로드

1. **OJ Platform 2.5.9 이상을 먼저 업로드·활성화한 뒤** OJ Microbit을 업데이트합니다. 기반 플랫폼의 Addon API 1.9가 전용 페이지 주소와 메뉴 이동을 제공하므로 이전 플랫폼에 애드온 ZIP만 교체하지 않습니다. 요구 버전은 위 자동 생성 표를 확인합니다.
2. WordPress **플러그인 → 새 플러그인 추가 → 플러그인 업로드**에서 `{{package}}`를 선택하고 설치·활성화합니다. 사이트별 활성화만 지원합니다.
3. 자동 설치를 실행했다면 WordPress 연결도 설정됩니다. WordPress **설정 → OJ Microbit**에서 준비 상태를 확인합니다. 수동 설치일 때는 실행 서비스 주소 `http://127.0.0.1:3037`과 22단계에서 만든 인증키를 입력합니다. 별도 호스트는 HTTPS 주소를 사용합니다.

rc.8 → 현재 버전은 화면 개선이며 스키마 5와 채점 계약이 같습니다. 추가 DB 이전이나 HUSTOJ 변경은 없습니다. 기존 실행기의 준비 상태가 정상이고 실행 식별자가 `pxt-microbit/9.1.1;pxt-core/13.0.1;oj-gpio/3`이면 화면 업데이트를 위해 다시 설치할 필요는 없습니다. 신규 설치·실행기 교체는 서버 준비 22단계를 따릅니다.

업데이트는 먼저 DB를 백업하고 점검 모드에서 진행합니다. **스키마 5**는 수업 배정·수업 프로젝트·최근 결과와 제출의 배정 식별자 및 인덱스를 추가합니다. 기존 제출은 일반 기록(배정 0)으로 보존하며 이전 그룹·수업 제한 배포도 자동 공개하거나 새 수업 배정으로 옮기지 않습니다. 기존 기록을 수업 성적으로 소급하지 않습니다. 큰 테이블의 DDL은 유지보수 시간에 실행하고 자료·인덱스를 확인합니다. 원자적 저장에 필요한 문제·관계·제출·수업 저장소는 InnoDB여야 하며 자동 엔진 변환은 하지 않습니다. 이전 플러그인으로 복구할 때는 코드만 낮추지 말고 해당 시점의 DB 백업과 함께 복원합니다. rc.2 이하 코드는 새 수업 제출 분리 조건을 모르므로 새 DB에 그대로 적용하지 않습니다. 활성화 후 설정과 사이트 건강의 **마이크로비트 저장소와 정리 작업**을 확인한 뒤 학생 접근을 엽니다. 호환되지 않는 구 실행기는 동봉 실행기/Docker 이미지로 갱신합니다. 개발용 test-process 응답은 운영 연결에서 거부합니다.

## 교사·학생 사용

1. OJ 콘솔의 **문제 → 마이크로비트 문제 → 문제 생성**에서 새 문제를 만듭니다. 새 예시는 빈 상태로 시작하고 핀은 단계 도우미 안에서도 연결할 수 있습니다. 아날로그·PWM은 0~1023, 디지털은 꺼짐/켜짐(0/1), 서보는 각도 0~180도 또는 펄스 폭 1~20000µs입니다.
2. 작성은 **안내 작성 → 동작 조건 → 코드 준비 → 공개 점검** 중 현재 단계에 집중합니다. **동작 조건 → 첫 단계 만들기**에서 **단계 → 핀 여러 개 선택 → 핀별 값 → 시간**을 순서대로 정합니다. 입력과 출력 여러 개를 함께 선택하고 새 장치도 같은 창에서 연결합니다. 출력 핀의 **→ 다음 값 추가**로 켜짐→꺼짐을 만들고 **핀 N개 함께 적용**을 누릅니다. 기존 **단계 수정**은 모든 핀과 동작을 불러오므로 핀마다 다시 입력하지 않습니다. 취소·오류는 원본을 보존합니다. 공개 전 점검에서 학생용 빈 틀 또는 현재 코드 배포를 선택하고 공개 예시·범위·학생 화면을 확인한 뒤 **확인하고 공개**합니다. 점검 후 내용이 바뀌면 재점검합니다. 빈 틀로 공개하기 전 참조 코드는 **교사용 현재 프로젝트 내보내기**로 보관합니다.
3. 학생은 **문제 → 마이크로비트 문제** 메뉴에서 **문제 보기 → 문제 풀기**로 이동합니다. 설명·장치 연결·공개 실험 예시를 읽고 MakeCode로 풉니다. **임시 저장**은 작업 보관, **센서 값으로 실행**은 연습이며 성적을 만들지 않습니다. **제출하여 채점**한 결과만 **제출 내역**에 저장됩니다. 교사도 문제별 학생 제출 내역을 확인합니다. 문제 링크를 공유할 수 있고 새로고침·이전/다음 이동 시 같은 문제로 돌아갑니다. 저장하지 않은 변경이 있으면 이동 전에 안내합니다. 기존 OJ의 AC·순위에는 자동 합산되지 않습니다.
4. 교사는 **수업 → 마이크로비트 수업** 메뉴에서 관리 수업을 선택해 공개 문제를 적용합니다. 다른 교사의 공개 문제와 같은 문제의 여러 수업 적용도 지원합니다. 학생은 **수업 → 마이크로비트 수업** 메뉴에서 참여 중인 수업의 문제를 열어 제출하고, 교사는 수업 명단의 **최근 제출 결과**·미제출 학생·배정별 제출 내역을 확인합니다. 일반 풀이와 각 수업의 프로젝트·제출은 따로 저장됩니다.
5. **HEX 다운로드**로 실제 파일을 저장하거나 HTTPS의 Chrome·Edge에서 **기기 연결 → USB 업로드**를 사용합니다. 미지원 브라우저는 HEX를 MICROBIT 드라이브로 복사합니다.

과제·채점 이력은 20개씩 **이전/다음 페이지**로 조회합니다. 이력 목록은 요약만 읽으며 **결과 보기**를 선택한 한 건의 출력 기록을 불러옵니다. 목록에서 전체 소스나 출력 로그를 한꺼번에 읽지 않습니다.

교사 목록의 **켜졌다 꺼짐 예제**, **서보 예제**, **I²C 예제**로 동작하는 설정을 불러와 수정할 수 있습니다. I²C 과제는 장치의 7비트 주소·초기 레지스터·학생 코드 쓰기 허용 여부를 먼저 설정합니다. 입력 시나리오에는 시간별 레지스터 값을, 출력 검사에는 주소·읽기/쓰기·기대 바이트·repeated 여부·시간 조건을 넣습니다. 거래 검사는 표에 설정한 순서로 각각 다른 거래와 대응합니다. I²C를 사용하면 P19·P20은 일반 핀 연결에 지정할 수 없습니다. 읽기 전용 센서 레지스터도 학생 실험 화면에서 외부 입력값으로 바꿔 시험할 수 있습니다.

각 실험 예시는 프로그램을 초기화하고 같은 예시의 다음 입력 단계는 이전 변수·장치 상태를 이어갑니다. **입력 단계 간격 0.5초**는 다음 입력 기준 시점을 정합니다. 출력 전 0.5초 기다리라는 뜻이 아닙니다. **반응 한도**는 정답 값이 나타날 때까지, **출력 유지**는 정답 값이 나타난 뒤를 확인합니다. 바로 켠 뒤 0.5초 기다리면 0.2초 유지 조건을 충족할 수 있지만, 켜기 전에 0.5초 기다리면 반응 한도 0.1초를 넘겨 실패합니다. 뒤에 꺼짐 조건을 넣었다면 그 전환에도 정한 반응 한도가 적용됩니다.

**+ 함께 시작할 핀 추가**는 같은 기준 시점부터 확인할 핀을 병렬로, 값 설정 화면에서 한 핀의 **→ 다음 값 추가**는 앞 동작의 실제 유지 완료 뒤 확인할 값을 직렬 화살표로 표시합니다. 예를 들어 **켜짐 0.5초 → 꺼짐 0.2초**로 설정합니다. 병렬/직렬 표시는 채점 조건의 관계이며 CPU 스레드 검출은 아닙니다. 학생도 같은 동작 그림으로 읽습니다. 입력 단계 추가와 별도 예시 생성은 구분하며 취소한 설정은 저장되지 않습니다.

핀을 함께 설정할 때 **다음 입력 단계까지 간격**이 모든 출력 조건을 담아야 합니다. 병렬 핀은 최대 필요시간을, 한 핀의 직렬 동작은 각 반응·유지시간의 합계를 확인합니다. 간격을 바꾸면 단순 시간표의 뒤 시점이 함께 이동하며 복잡한 기존 시간표는 세부 설정으로 안내합니다. 새 핀 동작의 유지 종료와 정확히 같은 시각의 전환은 허용합니다. 기존 고정 시각 조건의 채점 의미는 유지하고, 복잡한 시간표·I²C는 **세부 채점 설정**에서 편집합니다. 단계 도우미의 새 입력 핀은 처음 값이 없는 다른 예시에도 0 초기값을 준비하므로 공개 전에 각 예시의 처음 값을 확인합니다. 세부 사용법은 동봉 docs/DESIGN-FIDELITY-1.0.0-rc.9.md를 확인합니다.

MakeCode 내부 상태 파일 때문에 발생하던 `project.files` 파일명 오류 수정도 포함합니다. 기존 과제와 프로젝트를 다시 열어도 소스·블록을 유지하며 내부 상태만 정리합니다. 화면이 이전 버전처럼 보이면 WordPress 플러그인 목록의 현재 버전을 확인하고 사이트 캐시·최적화 플러그인·CDN 캐시를 지운 뒤 브라우저를 강력 새로고침합니다. 개발자 도구 Network에서 microbit.css와 microbit.js의 버전 쿼리가 현재 설치 버전인지 확인합니다. 실제 사이트의 테마·캐시 영향은 별도 확인합니다. 동작 순서 검사를 지원하는 실행 식별자 `oj-gpio/3`을 확인하고, 호환되지 않는 구 실행기만 동봉 버전으로 갱신합니다. 기존 단일 출력의 핀·시간 의미는 유지합니다.

새로 공개한 문제는 수업 소속과 관계없이 사이트의 마이크로비트 실습 권한이 있는 로그인 사용자 모두가 일반 풀이·채점을 할 수 있습니다. 수업에 적용해도 문제는 전체 공개로 유지합니다. 일반 100점은 수업에서 제출하기 전까지 해당 수업의 **미제출** 상태를 바꾸지 않습니다. 수업 A와 수업 B에 같은 문제를 적용해도 프로젝트·결과를 섞지 않습니다. 잘못되거나 권한이 없는 배정 요청은 일반 풀이로 대체하지 않고 접근을 거부합니다.

전용 **마이크로비트 수업** 목록과 결과 링크는 플랫폼의 수업(class) 참여·관리 권한을 사용합니다. 그룹(group)은 실제 학급 구성원이며, 수업에 연결된 그룹의 학생 참여·명단은 플랫폼이 제공하는 규칙을 따릅니다. 교사는 자신의 문제 원본·일반 제출을 관리하고, 수업 결과는 해당 수업의 관리 권한으로 확인합니다. 다른 교사의 공개 문제를 적용해도 원본 비공개 채점 조건은 제공하지 않습니다. 애드온 권한에서 교사에게 `oj_microbit_teach`, 학생에게 `oj_microbit_learn`을 허용합니다.

학생의 활성 수업 소속은 한 번에 100개까지 완전한 조회를 사용합니다. 초과·불완전 응답은 수업 접근을 차단하지만 공개 문제의 일반 풀이는 계속 사용할 수 있습니다. 플랫폼이 비활성 수업의 현재 명단을 제공하지 않으면 보관된 제출 내역으로 안내합니다.

수업 결과는 현재 명단 한 페이지와 해당 학생들의 최근 결과를 일괄 조회합니다. 0점·컴파일 오류도 제출이며 미제출과 구분합니다. 최고 점수나 전체 시도 수를 계산하는 표는 아닙니다. 문제 회수·원본 공개 중단은 새 수업 작업을 막고 과거 배정의 결과 연결을 유지합니다. 기존 제한 배포는 기존 범위로 남기며 작성 교사의 명시적 전체 공개 전환과 재점검 후 공개 문제로 바꿉니다. 상세 흐름·보존 범위는 동봉 `docs/PROBLEM-WORKFLOW.md`를 따릅니다. 플랫폼 기본 문제의 AC·순위에는 자동 합산하지 않습니다.

입력 오류는 한국어 항목명과 수정 위치로 안내하고 해당 입력을 펼쳐 초점을 옮깁니다. 혼잡·통신·버전·시간 초과·저장 충돌은 구분해 표시하며 문의 번호로 운영 로그를 대조할 수 있습니다. 429는 안내한 대기 시간 동안 실행 버튼을 잠그고 자동 재요청하지 않습니다. 시스템 장애를 오답 점수로 저장하지 않으며 학생 코드의 컴파일·실행 오류는 채점 결과로 기록합니다.

## 화면과 메뉴 확인

**마이크로비트 문제**와 **마이크로비트 수업**은 일반 프로그래밍의 문제·수업 메뉴와 별개입니다. 교사는 **문제 → 마이크로비트 문제**에서 **문제 목록 / 문제 생성** 탭 한 줄만 사용합니다. 수업은 **수업 → 마이크로비트 수업**에서 확인합니다. 본문에 반복되던 문제·수업·생성 탭은 제거했습니다. 문제 목록은 제목 중심의 한 줄 행입니다. 일반 문제의 마이크로비트 유형 필터·통합 목록과 일반 수업 화면의 마이크로비트 목록은 등록하지 않습니다. 기존 그룹·수업 원장의 참여·관리 권한과 수업별 저장 자료는 계속 사용하며 일반 문제 수정 권한을 추가하지 않습니다. 예전 생성·수업 링크는 전용 페이지로 이동합니다.

학생 보기 화면은 **이번에 만들 동작 → 연결할 장치 → 이렇게 동작하면 돼요 → 문제 풀기** 순서입니다. 기대 동작은 숫자 표 대신 **처음 → 0.5초 후 → 1초 후** 단계 카드와 핀별 동작 그림으로 읽습니다. 같은 시각의 출력은 병렬 가지로 모으고 디지털 값은 켜짐/꺼짐으로 표시합니다. 정확한 반응 시간·오차·핀 신호 표는 **세부 채점 조건 보기**에서 확인합니다. 복잡한 기존 시간표도 원문을 유지합니다.

**시작 코드**를 처음 열 때 MakeCode가 한 번 로딩되고, 같은 코드의 저장·재저장과 작성 단계 전환에서는 편집기를 재사용합니다. 초기 빈 블록·표시 모드·파일 순서 정리는 실제 코드 변경과 구별합니다. 코드를 바꾸고 저장하지 않았을 때의 이탈 경고는 유지하며, 저장 중 새로 바뀐 코드는 덮어쓰지 않고 다시 저장하도록 알립니다.

공개 메뉴의 두 마이크로비트 항목은 새 배치용 항목으로 교체합니다. 이전 항목을 별도로 숨기거나 정렬했다면 메뉴 설정에서 새 위치·숨김·순서를 다시 확인합니다. 다른 메뉴의 설정은 유지합니다.

빈 목록은 화면 왼쪽에 제목과 안내를 표시하고, 선택 항목은 밑줄·강조색·현재 위치 표시로 구분합니다. 모바일 표는 표 영역에서 스크롤합니다. 미저장 상태로 다른 메뉴로 이동할 때 취소하면 코드가 보존되고 확인하면 중복 확인창 없이 이동합니다. 밝은/어두운 화면과 키보드 초점도 점검합니다.

## 확인과 지원 범위

실제 마이크로비트 없이 센서·액추에이터 시뮬레이션과 채점을 사용할 수 있습니다. 실행 서비스는 필요하며, 실제 보드는 USB 업로드를 시험할 때만 필요합니다. 일반 핀 논리, 서보 각도·펄스 폭, I²C 레지스터 장치의 읽기·쓰기를 지원합니다. 장치 그림과 버스 기록은 실제 컴파일된 프로그램 실행에서 발생한 명령을 표시합니다. I²C 버퍼/Number API와 서보 API를 지원하지만 연속 회전 서보의 물성·초음파·SPI·내장 센서 전용 입력은 포함하지 않습니다. 기본 패키지 이외의 GitHub 확장은 채점에 사용할 수 없습니다.

MakeCode 기본 시뮬레이터가 제공하지 않는 I²C와 서보 펄스 기능은 플러그인의 별도 논리 장치 모델로 처리합니다. 버스 전압·클록 파형·서보 부하·토크를 계산하지 않습니다. 호환되지 않는 구 버전에서 업데이트하면 ZIP과 실행기/Docker 이미지를 갱신하며, 서버 준비 22단계의 현재 실행 식별자가 표시되는지 확인합니다. 기존 일반 핀 과제와 학생 프로젝트는 유지합니다.

동봉 `docs/VALIDATION.md`의 실제 기기 확인 목록을 따라 보드 연결·HEX 실행·USB 전송·배선·재연결을 확인합니다. 실제 WordPress/MySQL과 운영 Docker의 격리·시간 초과 회수도 설치 후 확인합니다. MakeCode 편집기에는 인터넷 연결이 필요합니다.

정식 출시 전 `docs/RELEASE-PLAN.md`의 P0 설치 공존·권한·MySQL 실행계획·대량 자료·교실 동시 접속·복구·실제 Docker/USB 시험을 완료합니다. 공개 전 교사 점검·쉬운 오류 안내·운영 오류 분류·공개 문제·수업 적용·분리 결과 흐름은 구현했고 로컬 검사 근거를 `docs/VALIDATION.md`에 정리했습니다. 실제 플랫폼 권한·DB·기기 승인은 별도입니다.

RC에는 `scripts/acceptance/`의 HUSTOJ 전후 비교·설치/실패 복원·읽기 전용 DB·시험 nonce·REST 권한/제한 부하 도구가 포함됩니다. 기본 점검과 명시적 시험 변경을 구분하며 표식·비공개 계정 파일·요청 상한·자기 생성 과제 회수 가드를 사용합니다. `PENDING/SKIP`과 종료 코드 0을 정식 승인으로 오인하지 않습니다. 실제 HUSTOJ 제출·DB 복원·행 잠금·수업 권한 회수·공개/수업 기록 분리·USB는 수동 근거를 남깁니다.

## 삭제 시

비활성화와 기본 플러그인 삭제는 과제·학생 프로젝트·채점 기록을 보존합니다. 설정에서 **삭제 시 데이터 제거**를 켠 뒤 삭제하면 전용 테이블과 설정을 제거합니다. 학생 기록은 기본 365일 후 정리하며 설정에서 바꿀 수 있습니다. WordPress 개인정보 도구에서 사용자별 내보내기·삭제가 가능합니다. 별도 실행 서비스는 자동으로 제거하지 않으며 서버 준비 22단계의 중지 절차를 따릅니다.

기간 정리는 데이터 테이블당 50건씩 처리합니다. 개인정보 삭제는 일반 프로젝트·수업 프로젝트·수업 최근 결과·제출을 각각 100건씩, 작성 문제는 부모 2개와 기존 수업·그룹 관계 최대 200개씩 처리합니다. 실행 중인 채점이 있으면 재시도합니다. 수업 배정의 생성자 표시는 한 번에 최대 100건씩 익명화하고 배정·제목·다른 학생의 수업 기록은 보존합니다. 개인정보 내보내기는 여섯 종류의 자료를 각각 한 건씩 여러 요청으로 처리합니다. 계정 삭제 후 남은 작업은 저장소에 보존해 재활성화 후 재개합니다. 중앙 WP-Cron 설정을 유지하고 오류는 사이트 건강에서 확인합니다. 자료 제거 중 DDL이 실패하면 설정·진단 정보를 보존하며 일부 테이블은 이미 삭제됐을 수 있으므로 권한과 남은 테이블을 확인한 뒤 재시도합니다.
