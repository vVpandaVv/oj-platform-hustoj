## 하는 일

브라우저 머신러닝 실습 과제를 내고, 결과 파일(`.mlpx`)을 제출·평가합니다.

## 1. 서버 준비

[서버 준비](00-server-setup.md) 1~12단계(필수)를 마치고 OJ Platform을 설치한 뒤 진행합니다. **14단계(ML 플레이그라운드 저장 폴더)**를 활성화 전에 진행합니다. PHP 8.3 이상이 필요하고, `OJ_ML_PLAYGROUNDS_PRIVATE_DIR`가 없으면 `rest_no_route` 오류가 납니다.

## 2. 업로드

관리자 화면에서 `packages/{{package}}`를 업로드하고 **활성화**합니다.

## 3. 관리자 화면 설정

| 순서 | 화면 | 설정 |
|---|---|---|
| 1 | **교사 메뉴 › ML 실습 › 설정** (`/oj-console/addons/oj-ml-playgrounds/settings`, 사이트 관리자 또는 'ML 실습 설정' 권한을 받은 교사) | 서버 상태에서 스키마 버전이 4인지 확인. 4보다 낮으면 **DB 업데이트 및 검증** |
| 2 | `/oj-console/roles` | `oj_ml_playgrounds_use`, `_submit`, `_review`, `_manage`, 설정을 맡길 교사에게 `_settings`('ML 실습 설정') |
| 3 | **교사 메뉴 › ML 실습 › 설정** | 저장 한도, 보존 정책, 개인정보 처리방침 URL (비우면 `/privacy`). OJ Platform 2.0.x에서는 **학습 활동 › ML 실습 설정** |

교사 화면은 OJ 콘솔 **학습 활동 › ML 실습**이며, 화면 위의 [과제 | 제출·평가 | 설정]으로 오갑니다. 학생 화면은 `/oj-addons/oj-ml-playgrounds/assignments`입니다.

### 과제 생성과 항목별 평가

- 새 과제는 **그룹**만 선택합니다. 기존 수업 과제의 조회·편집·제출·평가는 유지됩니다. 수업 과제를 복제할 때는 새 대상 그룹을 선택한 뒤 초안을 저장하며, 이전 학생 명단·제출·평가를 복제하지 않습니다.
- **기본 정보 → 실습·일정 → 평가 기준**을 차례로 펼쳐 입력하세요. 처음에는 기본 정보만 열립니다. 양식·모델·자료·한도도 해당 제목을 눌러 편집하며 긴 설명은 **도움말**에 있습니다. 초안을 만든 뒤 **게시**해야 학생에게 보입니다.
- 과제 목록의 **과제** 탭에는 초안·게시·종료 과제, **보관** 탭에는 보관 과제만 표시합니다. 보관해도 제출·평가는 유지하며 보관 탭에서 결과 확인·복제·보관 취소를 할 수 있습니다. 보관을 취소한 과제는 종료 상태로 과제 탭에 돌아오므로 학생에게 다시 열려면 **다시 열기**를 누르세요.
- 새 과제의 평가 기준은 수정 가능한 **4항목·총 100점**으로 시작합니다. 항목마다 이름·평가 방법과 **등급별 이름·점수·구체적인 판단 기준**을 입력하세요. 등급은 항목당 2~10개이며 점수는 서로 달라야 합니다. 항목 배점은 등급의 최고 점수, 총점은 각 항목 배점의 합계로 자동 계산합니다.
- 항목 개수는 **1~25개**입니다. 평가 기준 상단의 **항목 추가**, 각 항목 오른쪽의 **삭제**로 조절하세요. 삭제 버튼은 항목을 접어도 보이며 확인 후 삭제됩니다. 편집한 기준은 과제를 저장해야 반영됩니다. 게시된 과제는 기준을 변경할 수 없으므로 복제한 초안에서 수정하세요.
- 기본안에는 **충분히 충족·대체로 충족·일부 충족·미충족**의 등급별 기준이 있습니다. 이름·점수·기준은 모두 수정할 수 있고 등급과 항목을 추가·삭제할 수 있습니다. 포트폴리오 문항과 평가 항목은 서로 다른 설정입니다.
- 같은 등급별 기준표가 학생 안내·교사 수동 채점·선택적 AI 평가에 사용됩니다. 과제 작성 시 항목 제목을 누르면 등급별 기준을 편집할 수 있습니다. 채점 화면에는 **현재 등급·점수·판단 기준**이 표시됩니다. 점수 영역의 **점수 조정**을 누르고 등급 카드를 선택하면 항목 점수와 합계가 바뀝니다. AI 플러그인 없이도 동작하며 전체 기준표는 펼쳐 확인할 수 있습니다. 임의의 중간 점수는 저장할 수 없고 모든 등급을 비우면 피드백만 저장할 수 있습니다.
- 선택을 바꾼 뒤 **평가 저장**(비공개) 또는 **저장 후 학생에게 공개**를 눌러 완료하세요. 클릭만으로 자동 저장·공개하지 않습니다. 이미 공개된 평가를 비공개 저장하면 학생은 다시 공개하기 전까지 이전 공개 점수를 봅니다. 저장·재조회 후에도 선택 등급·점수·당시 기준표가 유지됩니다. 동시 수정 충돌이 표시되면 새로 조회해 최신 평가를 확인하고 다시 수정하세요.
- 저장 중에는 평가 입력이 잠깁니다. 실패하면 작성한 점수·피드백은 유지되고 다시 편집할 수 있습니다. 성공·실패 안내를 확인한 뒤 다음 학생으로 이동하세요.
- 기존 과제의 총점·자유 점수 방식과 평가 기록은 자동 변환하지 않습니다. 기존 초안을 편집할 때 **기존 자유 점수 방식 · 전환 옵션**을 펼쳐 **등급별 루브릭으로 전환**을 누르고 등급을 확인한 뒤 저장하세요. 게시된 과제는 **복제 → 새 그룹 선택 → 등급별 루브릭으로 전환 → 저장·게시** 순서로 만듭니다. 기존 제출은 새 과제로 이동하지 않습니다.
- **총점** 방식도 명시적으로 선택할 수 있지만 AI 평가에는 항목별 기준이 필요합니다. 기존 자유 점수 과제는 전환 전까지 종전의 채점 방식을 유지합니다.
- **설정**은 사이트 전체 운영값입니다. 자주 쓰는 화면 설정을 먼저 표시하고, 정상 서버 상태·고급 용량·보존 정책·점검 모드는 접어 둡니다. 서버 이상 또는 켜진 점검 모드는 펼쳐 안내합니다. 과제별 기준·양식·허용 모델은 **과제** 화면에서 설정합니다.

### 수업의 허용 유형·알고리즘

- 과제 생성 시 학습 유형과 **알고리즘·지정 데이터셋 › 허용 알고리즘**을 지정합니다. 알고리즘을 하나도 선택하지 않으면 알고리즘 제한은 없습니다. 선택한 학습 유형에서 사용할 수 있는 알고리즘을 지정하세요.
- 학생 실습 화면은 해당 과제에서 금지한 유형·알고리즘을 새로 선택할 수 없게 표시합니다. 과제 조건을 불러오지 못하면 무제한으로 진행하지 않고 이유를 안내하며 학습·직접 제출을 막습니다.
- 제출이 차단되면 상단 **OJ에 제출하기** 옆의 **사유 보기**를 누르세요. 좁은 화면에서는 경고 아이콘으로 표시합니다. 긴 설명은 별도 확인창에 표시되며 **닫기** 또는 Esc로 닫습니다. 경고를 닫아도 제출 조건은 해제되지 않습니다.
- **OJ에 제출하기**는 업로드 전에 현재 유형·선택 모델·과거 모든 실험 기록을 확인합니다. 실패·취소한 이전 실행도 포함합니다. 예전 프로젝트의 금지 모델은 선택 목록에서 직접 빼야 하며, 금지 실험 기록까지 남아 있다면 원본을 보존하고 이 과제용 새 프로젝트에서 허용 모델로 작업하세요. 기록을 자동 삭제하거나 몰래 제외해 제출하지 않습니다.
- 제출 준비 중 프로젝트를 전환하거나 내용을 바꾸면 업로드를 중단하고 이유를 표시합니다. 현재 프로젝트와 모델 선택을 확인한 뒤 다시 제출하세요.
- 서버의 최종 파일 검사는 유지됩니다. 수동 파일 업로드는 이 사전 검사의 대상이 아니므로 가능하면 실습 화면의 직접 제출을 사용하세요. 이미 반려된 파일은 업데이트만으로 자동 승인되지 않으며, 같은 파일을 다시 제출하거나 재검토만 요청해도 실제 정책 불일치는 해결되지 않습니다.
- 업데이트 후 기존 실습 탭을 닫고 다시 열어 **금지 모델 선택 불가 → 허용 모델 학습 → 직접 제출**을 시험하세요. 과거 금지 실험이 있는 프로젝트도 업로드 전에 사유가 표시되는지 확인하세요. DB 구조 변경은 없습니다.

### 범주가 많은 분류와 메모리 안내

- 학습 전 정답의 범주 수가 많으면 주의사항과 계속 학습 확인이 표시됩니다. 숫자 하나하나를 별도 분류로 다루는 과제인지 확인하세요. 수량·온도 등 숫자 자체를 예측하려는 목적이라면 교사와 회귀 과제를 검토해야 합니다. 플러그인이 유형을 바꾸거나 값을 임의 구간으로 묶지는 않습니다.
- 새 브라우저 학습의 분류 평가에서 범주가 50개를 넘으면 수백만 칸으로 커질 수 있는 전체 혼동 행렬은 만들지 않습니다. 정확도·F1·범주별 점수는 전체 평가 데이터로 계산하며, 결과 화면에서 혼동 행렬 생략을 안내합니다. 저장·제출 형식은 그대로입니다.
- 기존 프로젝트의 혼동 행렬은 삭제하지 않고 최대 20행 × 20열씩 표시합니다. 행과 열을 각각 이동해 다른 범주 조합을 확인할 수 있습니다. 범주별 점수와 모델 매개변수도 나누어 표시합니다.
- 자동저장 중 결과 화면 이동이나 직접 제출을 눌러도 저장을 중복 실행하지 않도록 순서를 보장합니다. 저장 실패 시 작업은 메모리에 남고 오류가 표시되므로, 재시도나 내보내기를 완료하기 전에 탭을 닫지 마세요.
- 이번 보완은 큰 결과표와 중복 저장으로 생기는 메모리 급증을 줄이는 조치입니다. 특성의 원-핫 확장, 모델 종류, 다른 탭과 PC 상태에 따른 메모리·학습 시간 제한까지 없애는 것은 아닙니다. 공용 PC에서는 시험용 데이터로 학습 전 안내 → 학습 → 결과 페이지 이동 → 저장·제출을 확인하세요. 새 서버 확장 설치나 RAM 설정 변경은 필요하지 않습니다.

## 4. AI 평가 연결 (선택, 두 플러그인 1.2.0 이상)

### 데이터 설명과 실습 통계

- 과제 작성의 **데이터 설명**에 출처·변수 의미·단위·예측 목표와 수집 맥락을 입력합니다(4,000자 이내). 학생이 직접 데이터를 선택하면 **학생 설명 항목 추가**를 눌러 기존 포트폴리오 양식에 선택 문항을 추가하세요. 기존 문항·답변을 덮어쓰지 않으며 문항 ID 기본값은 `dataset_description`입니다. 설명에는 원본 행·개인정보를 붙여 넣지 마세요.
- 평가항목의 **평가 근거**에서 데이터 설명·통계 요약·비교 실험을 선택합니다. 선택된 근거가 없으면 그 항목을 **교사 확인 필요**로 표시합니다. 기존에 요구를 지정하지 않은 항목은 AI에 한해 설명·통계를 기본 요구합니다. 보고서만 평가하는 항목은 명시적으로 모두 해제할 수 있습니다. 게시 과제는 기존 잠금 정책에 따라 **복제한 초안**에서 변경하세요.
- 학생 제출의 안전 바로보기에서 **데이터 설명·통계**를 확인합니다. 이미 제출된 원본 CSV도 조회할 때 서버 안에서 집계하므로 통계만을 위해 재제출할 필요는 없습니다. 원본 파일에 데이터나 과거 실험 설정이 없으면 현재 데이터로 대신 채우지 않습니다.
- 지원 범위는 제출물 안의 UTF-8 CSV 표 데이터이며 집계 한도는 전체 8 MiB·1,000,000셀·6개 파일·3초, 파일당 50,000행·128열입니다. 원본은 압축 해제하거나 실행하지 않고 스트림으로 읽습니다. 한도·형식·연결 문제는 부분 집계 또는 확인 불가로 표시하며 전체 데이터라고 간주하지 않습니다. 이미지 통계는 지원하지 않습니다.
- 열별 자료형·결측 수/비율·고유값 수와 보호 가능한 평균·모집단 표준편차·익명 빈도를 제공합니다. 결측은 빈 값/공백이며 `NA`, `null` 같은 문자열을 임의로 결측으로 해석하지 않습니다. 5개 미만 자료·상수·95% 이상 고유값·고유값 추적 한도·수치 범위 문제에서는 상세 수치가 생략됩니다. 소수 범주가 있으면 빈도 목록을 모두 숨깁니다. 통계에는 표본 행·범주 값·최솟값/최댓값·파일명/경로를 넣지 않습니다.
- 통계는 **전처리 전 제출 CSV**의 집계입니다. 전처리 후 효과·모델 성능·데이터 누수·수집 편향을 재검증하지 않습니다. 동일 데이터·타깃·분할 설정으로 기록된 성공 실행이 둘 이상이고 공통 지표가 있을 때만 비교 근거를 갖춘 것으로 분류하며, 실제 분할 재현을 인증하지 않습니다.
- AI 요청 전에 근거 상태를 표시합니다. 부족한 항목은 AI가 높은 점수를 반환해도 점수·총점을 비우고 자동 반영을 차단합니다. 교사는 별도 수동 평가로 판단할 수 있고 AI 미설치 시에도 설명·통계 바로보기를 사용할 수 있습니다. 설명·통계·근거 조건이 바뀌면 기존 AI 결과는 재사용하지 않습니다.

### 연결과 요청

ML이 실습·원본 제출·최종 점수와 공개를 담당하고, OJ AI Dashboard가 분석·검토 초안을 담당합니다. AI 활동지를 따로 만들거나 제출 파일을 다시 업로드하지 않습니다. **OJ Platform은 필수이며 OJ AI Dashboard는 선택**입니다. AI 플러그인 없이도 과제 생성·실습·제출·안전 바로보기·항목별 수동 채점·학생 공개까지 사용할 수 있습니다. AI 설정 오류가 수동 평가 입력을 지우거나 저장을 막지 않습니다.

1. OJ AI Dashboard 1.2.0 이상을 설치·활성화하고 해당 안내서의 비공개 저장소와 AI 연결을 준비합니다. ML 자료 전송 동의는 아래 제출 상세 화면에서 별도로 받습니다.
2. OJ Platform **AI 연결**에서 사용할 제공자·모델을 설정하고, **AI 작업 배정**(`/oj-console/settings/ai-routing`)에서 `addon.oj_ai_dashboard.ml_submission_assessment` 작업에 프로필을 배정합니다. 기존 활동지 평가 작업의 배정을 자동 복사하지 않습니다.
3. ML 과제에 **항목별 등급·점수·판단 기준**을 설정합니다. 포트폴리오 양식을 함께 제공하면 학생의 해석·한계·개선 계획을 근거로 검토할 수 있습니다.
4. 학생이 실습 화면에서 직접 제출하면 서버의 형식·무결성 검사를 먼저 통과해야 합니다.
5. **ML 실습 › 제출·평가 › 학생 제출 상세**의 **AI 평가 보조 (선택)**를 직접 펼쳐 연결 상태와 **AI에 전달되는 정보**를 확인합니다. 제출 상세만 열면 AI 조회·요청은 하지 않습니다. 전송할 자료에 개인정보가 없는지 확인하고 동의한 뒤 **AI 평가 요청**을 누릅니다.
6. **진행 상태 확인**으로 결과를 확인하고 선택 등급·항목 점수·근거·한계를 검토합니다. 등급별 과제에서 AI가 정의되지 않은 점수를 제안하면 **자료 확인 필요**로 표시하고 반영을 막습니다. 가까운 등급으로 바꾸지 않으므로 교사가 직접 등급을 선택해 평가하세요. 자동 새로고침은 하지 않습니다. 요청은 서버 작업 대기열에서 순차 처리되므로 36명이 제출해도 동시에 36개의 AI 호출을 시작하지 않습니다.
7. **비공개 교사 초안에 반영**을 누르면 비공개 평가로 저장됩니다. 교사가 수정한 뒤 기존 **저장 후 학생에게 공개**를 눌러야 학생에게 점수와 피드백이 보입니다. AI 초안 자체는 학생에게 공개하지 않습니다.

AI에 전달하는 것은 **서버가 검증한 읽기 전용 요약**입니다. 포트폴리오만 보내는 것이 아닙니다.

| 구분 | 포함하는 정보 |
|---|---|
| 과제·포트폴리오 | 과제 제목·설명, 항목별 평가 방법과 전체 등급표(이름·점수·판단 기준), 교사 양식, 학생 답변 텍스트와 첨부 개수 |
| 프로젝트 | 학습·데이터 유형, 앱·파일 형식 버전, 현재 타깃·특성·전처리·분할·알고리즘·하이퍼파라미터, 실험·실행 개수 |
| 실험 | 기록 순서, 실험 당시 타깃·특성·전처리·분할·실행 환경·알고리즘·하이퍼파라미터 |
| 실행 결과 | 알고리즘·상태, 기록된 성능 지표·범주별 점수·혼동 행렬·특성 중요도, 실패·경고 코드, 모델 형식·크기 등의 메타데이터 |
| 데이터 맥락·통계 | 교사 설명·지정 학생 설명 답변, 서버 집계한 전처리 전 CSV 통계와 현재/실험별 연결·생략 상태, 항목별 필수 근거 준비 상태 |

원본 데이터 행·이미지·모델 바이너리·첨부 내용·원시 실행 로그는 보내지 않습니다. 범주별 점수·혼동 행렬의 원본 범주명은 번호로 대체하고 이미지 설정의 범주 목록은 개수로 대체합니다. 계정·그룹 ID, 제출 파일명, 프로젝트·실험 이름과 식별자·시각·경로도 외부 AI 입력에서 제외합니다. 자유 입력 답변·데이터 설명이나 열 이름의 개인정보를 자동으로 완벽히 제거하지는 않으므로 교사의 사전 확인이 필요합니다. AI는 모델을 실행하거나 지표를 재현하지 않으며, 학생이 기록한 지표를 검증된 성능으로 간주하지 않습니다. 과거 실험에 저장되지 않은 설정을 현재 설정으로 추정하여 채우지 않습니다.

안전 요약은 최대 실험 20개·전체 실행 50개, 특성·범주별 점수·중요도 각 50개, 혼동 행렬 20×20 등의 한도를 적용합니다. 요약에 생략이 있거나 전체 AI 자료가 120,000바이트를 넘으면 일부만 몰래 보내지 않고 **AI 요청을 차단**합니다. 큰 범주 수의 결과 등은 교사가 원본을 보존한 채 수동 평가해야 할 수 있습니다. 바로보기에도 생략 안내가 표시됩니다.

근거 부족은 **교사 확인 필요**로 표시하고 점수 초안 자동 반영을 막습니다. AI 장애·시간 초과도 0점 처리하지 않습니다. 제출 원본이나 평가 기준이 바뀌면 이전 AI 결과를 적용할 수 없습니다. 오류 후 재시도는 교사가 직접 요청하며 새 AI 사용 비용이 발생할 수 있습니다.

등급표는 기존 AI 연결 계약의 교사 기준에 포함하므로 이 기능 때문에 AI Dashboard를 별도로 수정할 필요는 없습니다. 등급명·점수·설명 중 하나만 바뀌어도 이전 AI 결과를 사용할 수 없습니다. 한 항목의 평가 방법과 등급표를 합친 AI 입력이 8,000바이트를 넘으면 잘라 보내지 않고 요청을 차단합니다. 문구를 간결하게 정리하거나 수동 평가하세요. 이는 임의 점수의 반영을 막는 검증이며 AI의 교육적 판단이 항상 옳다는 보증은 아닙니다.

서버에서 WordPress 예약 작업(WP-Cron)이 실행되어야 합니다. `DISABLE_WP_CRON`을 사용하는 운영 환경에서는 기존 시스템 예약 작업이 `wp-cron.php` 또는 WordPress CLI 예약 작업을 실행하는지 확인하세요. AI 대기열·임시 결과는 AI 플러그인이 소유하며 ML 원본 제출과 분리합니다.

설치 후 시험용 과제로 **직접 제출 → AI 요청 → 비공개 초안 → 교사 공개 → 학생 확인**을 한 번 확인하세요. API 키·기관의 외부 AI 정책에 따라 실제 호출 성공 여부는 서버에서 별도로 확인해야 합니다.

## 업데이트·삭제

일반 요청의 저장소 소유권 확인은 같은 DB·사이트 접두사·설치 URL·플러그인/스키마 버전에서 최대 5분간 재사용합니다. 다른 설치로 옮기거나 업데이트하면 새로 검사하며, 확인 실패 시에는 접근을 차단하고 30초 뒤 재검사합니다. DB 업데이트·삭제는 캐시를 사용하지 않고 실제 소유권을 확인합니다. 다른 애드온 설치 여부에 의존하지 않습니다.

- **업데이트**: 업로드하고 "교체"를 선택한 뒤 `sudo systemctl restart php8.3-fpm`을 실행하고, 위 표 1번의 스키마를 확인합니다.
- **구버전 복귀 주의**: DB 테이블 구조는 같지만 새 등급별 루브릭은 버전 2 형식으로 저장됩니다. 이 형식을 지원하지 않는 이전 ML 플러그인에서는 해당 과제를 정상 편집·채점할 수 없으므로 플러그인 파일만 구버전으로 교체하지 마세요.
- **삭제**: 데이터를 지우지 않습니다.

## 서버 설치 창

설정의 **서버 설치·복구**에서 비공개 저장소 준비 명령을 복사합니다. 활성화 전에는 WordPress 플러그인 목록의 **서버 준비 필요 → ML 실습 설치 안내**으로 들어갑니다.

공통 준비 화면은 OJ Platform 2.2.7 이상에서 제공합니다. 명령은 서버 설치 권한이 있는 관리자가 실행합니다.

OJ Platform 2.2.9 이상에서 업로드된 플러그인만 공통 화면에 표시합니다. 복사 명령은 `sudo bash …/resources/server/install.sh` 형식입니다. 필요한 PHP CLI는 설치기가 준비하며, PHP 보조 파일은 `wp-config.php` 검사·수정에만 사용합니다.

서버 설치기는 해당 플러그인의 `resources/server/install.sh`에 포함됩니다. AI·ML의 `wp-config-helper.php`도 각 ZIP에 포함되며 Platform의 설치 파일을 사용하지 않습니다.

활성화 후에는 각 플러그인 설정·관리 화면의 **서버 설치·복구** 창에서 자체 설치 명령을 바로 복사합니다. wp-admin 공통 화면으로 이동할 필요가 없습니다.

서버 준비가 필요한 경우에만 플러그인 목록과 관리자 OJ 콘솔 첫 화면에 안내합니다. 준비를 마치면 새로고침 후 안내가 사라집니다. 상시 OJ 서버 설치 메뉴는 표시하지 않습니다.
