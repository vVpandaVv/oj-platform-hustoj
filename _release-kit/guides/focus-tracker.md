## 설치와 업데이트

1. WordPress 관리자 › 플러그인에서 **OJ Platform 2.3.22 이상 / Addon API 1.4 이상**을 먼저 활성화하고 플랫폼 초기 설정과 Judge DB 연결 검사·적용을 마칩니다. PHP 8.3 이상, WordPress 6.6 이상, MySQL/InnoDB가 필요합니다. 이전 플랫폼은 지원하지 않습니다.

   공통 배포 세트의 플랫폼 ZIP이 2.3.22보다 낮으면 이 요구사항을 충족하지 않습니다. 검증된 플랫폼 2.3.22 이상을 별도로 준비한 뒤 Focus Tracker를 설치합니다.
2. 관리자 › 플러그인 › 새 플러그인 추가 › 플러그인 업로드에서 Focus Tracker 설치 ZIP을 업로드하고 활성화합니다. 업데이트는 업로드 뒤 **현재 설치된 플러그인을 업로드한 것으로 교체**를 선택합니다. 기존 플러그인을 삭제하면 학습 데이터도 지워지므로 교체 설치를 사용합니다. 설치 ZIP 생성은 릴리스 킷만 사용합니다. 소스 저장만으로 ZIP이 만들어지지는 않습니다.
3. 업데이트 전 WordPress DB 전체와 기존 `oj-platform`, `focus-tracker` 플러그인 파일을 같은 시점으로 백업합니다. 기존 데이터를 유지하고 필요한 컬럼·인덱스를 추가합니다. 설치기는 필수 컬럼·중복 방지 인덱스·InnoDB를 확인한 뒤 DB 버전을 갱신합니다. 실패하면 관리자에게 표시하고 기록 API를 중단합니다. DB를 복사한 검증 사이트에서 먼저 업데이트합니다.
4. 학생 역할(`subscriber`, 학습자)의 **집중도 추적 대상** 권한은 업데이트 뒤 첫 정상 초기화에서 기본 부여됩니다. 기존·신규 학생에게 역할 상속으로 적용하며 교사가 학생별로 부여하지 않습니다. 교사의 활동 관리·결과 열람 권한, 선택적인 학생 본인 요약 열람 권한은 OJ 콘솔 › 역할 관리에서 설정합니다. 설정 담당에게만 집중도 평가 설정 권한을 부여합니다.
5. 교사 콘솔 › 수업 › 집중도 평가 › 설정에서 **운영 상태**, 세 보관 기간, 추적 경로, 가중치를 확인합니다. WordPress 도구 › 사이트 건강에서도 저장소 상태를 확인합니다. 기본 범위는 지원되는 문제·자료·실습·교육게임·게시판 등 내부 학습 화면입니다. 이전 기본 경로는 자동 확장하며 사용자가 지정한 정규식은 보존합니다.
6. 활동을 만들고 학생 계정으로 실제 문제를 열어 코드·빈칸·블록을 수정하고 제출합니다. 수업 전 열어 둔 페이지, 두 문제 탭, 이탈·복귀, 네트워크 복구 후에도 해당 활동의 기록 상태와 타임라인을 확인합니다. 자료 없음·일부 누락은 성적 0점으로 해석하지 않습니다.

저장소 점검·업그레이드는 동시에 한 요청만 실행합니다. 실패하면 기록 API를 계속 중단하고 같은 버전의 자동 재시도는 최소 1분 뒤에 수행합니다. 정상 저장소의 정기 점검은 10분 간격입니다. 실패 원인을 해결한 후 다음 재시도나 WordPress 사이트 건강의 저장소 점검으로 준비 상태를 확인합니다.

## 그룹별 시간 지정과 누적 통계

교사 콘솔의 새 활동에서 학급·그룹과 시작·종료 시각, 문제 범위를 지정합니다. 그룹별 목록에서 활동을 골라 **시간 수정**으로 기간을 바꾸거나 **지금 종료**로 일찍 마칠 수 있습니다. 조기 종료는 확인 후 적용합니다. 학생이 현재 속한 학급·그룹의 지정 시간·문제 범위에서만 기록 수집과 자동 문항이 동작합니다. 활동이 없거나 시작 전·종료 후에는 초안도 읽거나 전송하지 않습니다.

학생에게 별도의 활동 신청·입장·시작 버튼은 없습니다. 학생 역할에는 추적 권한을 기본 적용하므로, 그룹 소속을 준비하고 교사가 활동의 그룹·시간을 지정하면 학생은 자기 계정으로 로그인해 평소처럼 지원되는 내부 학습 화면에서 학습하면 됩니다. 문제 범위는 문제·제출 화면을 제한하며, 같은 활동 시간의 자료·게시판·교육게임·실습 화면은 계속 기록합니다. 확인 문항에 답하지 않아도 활동 기록은 계속되며 미집중으로 단정하지 않습니다.

기본 권한은 한 번만 적용합니다. 이미 저장된 역할·개인의 명시적 거부와 적용 이후 관리자의 권한 회수는 덮어쓰지 않습니다. 최초 적용 전 역할 관리의 단순 미선택은 미설정과 구별할 수 없어 기본 부여 대상입니다. 추적 권한만 자동 부여하며 학생의 결과 열람·교사 관리 권한을 추가하지 않습니다. 일반 학생을 특권 계정으로 오인하지 않도록 보완한 플랫폼이 필요하므로 이전 플랫폼을 유지한 채 이 ZIP만 업데이트하지 않습니다.

시작 전부터 열어 둔 페이지도 서버 확인 후 자동 시작하고 알려진 종료 시각에는 자동 중단합니다. 조기 종료·시간 수정·소속 변경은 기본 최대 5초마다 확인 요청을 시작하고 승인 만료가 가까우면 더 일찍 갱신합니다. 응답이 늦거나 통신에 실패하면 최대 10초 승인 기한이 만료될 때 멈춥니다. 서버는 변경된 시간 밖의 새 기록·출제·응답을 받지 않습니다. 종료 전에 발생한 기록의 24시간 이내 지연 전송은 허용합니다. 활동 사이 빈 시간은 누적 통계에 넣지 않습니다.

활동 결과에서 학생의 **누적 통계**를 열면 해당 학급·그룹의 주간·월간 기록과 일별 변화 그래프를 봅니다. 현재 명단과 열람 권한을 다시 확인하며 다른 그룹의 기록은 포함하지 않습니다. 학생은 **내 집중도 요약**에서 자신의 전체 누적 기록을 확인합니다. 주간은 월요일~일요일, 월간은 달력 월이며 사이트 시간대를 표시합니다. 날짜·이전/다음 기간을 선택하고 그래프 아래의 일별 수치 표도 펼쳐 볼 수 있습니다.

여러 탭과 겹치는 활동의 시간은 중복 집계하지 않습니다. 활성률은 시간 합계로 계산하며 일별 비율이나 활동 점수를 더한 값이 아닙니다. 편집·실행·제출은 브라우저 신호 횟수이고 실제 채점 성공 횟수는 아닙니다. 자료가 없는 날·누락된 날은 0점으로 바꾸지 않으며 확인 문항 응답은 집중 점수와 분리합니다.

## 페이지 분류와 교육게임·ML 실습

| 분류 | 포함 화면 |
|---|---|
| 문제 풀이 | 개별 문제 내용과 지원되는 코드 편집 |
| 제출·결과 | 제출 작성, 제출 내역·결과 |
| 학습자료 | Learning Materials, ReadContents Library |
| 실습·학습도구 | Code Lab, PRIMM, 퀴즈·학습도구, **ML 실습** |
| 교육게임 | Edu Games의 일반 게임 |
| 질문·토론 | 내부 게시판·질문 |
| 기타 내부 학습 | 문제 목록·학습 대시보드·그룹 등 허용된 탐색 화면 |

**ML 실습은 ‘실습·학습도구 → ML 실습’**으로 표시합니다. Edu Games에 포함된 AI 모델 실험실·AI 분류 실험실도 교육게임 시간과 섞지 않습니다. 관리자·개인 메시지·계정 설정·로그인은 수집 대상에서 제외합니다. 사용자 지정 추적 정규식이 좁으면 새 화면이 제외되므로 설정에서 확인합니다. 외부 사이트 이동은 수집하지 않습니다.

활동 결과의 타임라인에서 페이지 분류·방문 기록을 보고, 학생·교사 누적 통계에서 주간·월간 분류별 활성·관측 시간의 합계 막대와 전체 일별 변화 그래프를 봅니다. ML 실습은 실습 계열의 별도 행으로 표시하고 일반 실습 행에 중복 합산하지 않습니다. 여러 탭은 같은 시각을 한 분류에만 귀속해 전체 시간과 합계가 일치합니다. 방문 수는 일별 페이지 세션 수의 합이며 기간 전체의 고유 페이지 수가 아닙니다. 타임라인의 개별 탭 방문 표는 최대 500개를 표시하며 일부 생략 여부를 알립니다. 방문 구간은 겹칠 수 있으므로 직접 더하지 않습니다. 이전 기록은 ‘이전 기록·미분류’로 유지합니다.

자료나 게시판으로 이동했다는 이유와 편집이 없다는 이유로 감점하지 않습니다. 지원 코드 입력이 없는 게임·ML·실습·결과 조회도 입력·제출 평가에서 제외하고, 적용 가능한 가중치만으로 총점을 원래 상한에 맞춥니다. 적용 가능한 가중치가 모두 0이면 ‘미평가’로 표시합니다. 화면 활성·비활성과 관측 공백은 계속 구분합니다. 화면을 열어 둔 시간은 실제 읽기·게임 성과·ML 모델 이해의 증명이 아닙니다.

## 활동 삭제

활동 목록의 **삭제**를 누르고 확인 화면에서 **삭제 확인**을 선택합니다. 해당 활동을 만든 교사에게 현재 학급·그룹 관리 권한이 있어야 합니다. 예정·진행·종료 활동 모두 삭제할 수 있으며 목록과 활동별 결과에서 제거합니다. 삭제한 활동은 수정하거나 복구할 수 없습니다.

삭제한 활동은 서버에서 수집·출제 승인 대상에서 즉시 제외합니다. 열린 학생 화면은 다음 확인(기본 5초, 통신 장애 시 승인 기한 최대 10초)까지 중단하며, 해당 활동에만 속하는 지연 기록은 저장하지 않습니다. 다른 유효한 활동이 있으면 그 활동은 계속합니다.

이미 수집한 학습 기록·기존 문항 응답·주간·월간 누적 통계와 출처 확인용 연결은 보관 기간에 따라 유지합니다. 활동 삭제는 학생의 개인정보 삭제가 아닙니다. 원본이 이미 만료돼 바뀐 범위를 재구성할 수 없는 과거 자료는 불완전 상태로 표시할 수 있습니다. 학생 자료까지 제거하려면 WordPress 개인정보 삭제 도구를 사용합니다.

## 자동 학습 확인

OJ Platform 2.3.22 이상의 학습 확인 API를 사용하며 기본으로 켜집니다. 교사는 활동 시간만 지정하며 문항 제작·채점·수동 출제는 필요하지 않습니다. 제출 여부와 관계없이 현재 코딩 문제의 초안, 본인 제출 코드, 공개 문제 예제를 활용합니다. 독립 정수 비교식·Python `range`·공식 예제처럼 서버가 정답을 검증한 문항만 표시하며 검증할 자료가 없으면 건너뜁니다. 자료·게임·ML·일반 게시판의 내용을 추측해 문항을 만들지 않습니다. 외부 AI 설정이나 API 키는 필요하지 않습니다.

기본값은 활동 시간 안에서 켜진 45초 후 확인, 최소 5분 간격, 학생별 하루 3문항, 10분 만료입니다. 활동 종료가 먼저이면 문항을 닫고 취소로 구분합니다. 설정에서 활성 여부·간격·상한을 바꿀 수 있습니다. 실제 학생 계정으로 제출 없이 코드 초안을 작성해 문항이 표시되는지, 모름·나중에·만료가 집중 점수를 바꾸지 않는지 확인합니다. 학생의 내 집중도 요약에서 최근 24시간 응답을 볼 수 있습니다.

## 측정과 보관

화면 활성·복귀·입력과 제출은 학습 참여 참고 지표입니다. 실제 집중·이해·풀이의 질을 직접 측정하지 않습니다. 진행 중 값은 달라질 수 있으며, 누락된 기록의 참여 지표는 화면에 숫자로 확정 표시하지 않습니다.

브라우저 이벤트 전송 대기열은 사용자별 최대 1,000건/24시간입니다. 장기 오프라인, 저장소 차단, 강제 종료에서는 무손실 수집을 보장할 수 없습니다. 활동 이벤트에 코드 원문·페이지 URL·다른 사이트 방문 기록은 넣지 않습니다. 자동 확인은 UTF-8 64KB 이하의 초안을 서버에서 일시 분석하고, 전체 초안 대신 문항에 필요한 코드 일부·검증 근거·자료 해시·응답만 보관합니다. 외부 AI에는 보내지 않습니다.

정답·오답·모름·건너뛰기·무응답은 집중 점수와 별도 기록입니다. 오답이나 무응답을 미집중으로 단정하지 않습니다. 정답도 해당 문항을 확인했다는 근거이며 학생의 지속적인 집중이나 문제 전체 이해를 보장하지 않습니다.

설정에서 보관 기간을 각각 정합니다.

| 항목 | 기본값 | 입력 범위 |
|---|---|---|
| 원시 활동 기록 | 60일 | 1~36500일 |
| 확인 문항·응답과 문항 코드 일부 | 60일 | 1~36500일 |
| 일별·활동 집계 | 0(기간 제한 없음) | 0 또는 앞 두 기간보다 최소 1일 긴 기간 |

기존 설치의 공통 보관 기간은 원시·문항에 이어 적용하고 집계는 기본적으로 계속 보관합니다. 만료 전에 최종·일별 집계를 저장하고 저장·조회 실패 시 원시 자료를 유지합니다. 정리 작업은 실행 시간과 건수를 제한하고 남은 자료를 이어 처리하며 실패한 자료를 재시도합니다. WP-Cron이 지연되거나 안전한 집계를 만들지 못하면 실제 삭제가 늦어질 수 있습니다. 설정의 마지막 성공·실패·남은 작업을 확인합니다. 기간을 줄이면 다음 정리에서 삭제될 수 있으며 이미 삭제된 상세 기록은 복원하지 않습니다. 만료한 집계는 조회로 재생성하지 않습니다.

집계의 출처 확인에 필요한 세션·활동 연결과 해당 세션의 페이지 분류·내부 자료 식별자는 집계 기간에 맞춰 보관합니다. 집계 기간이 0이면 이 출처 자료도 계속 보관할 수 있습니다. 페이지 전체 URL·검색어·게시글 제목·내용은 저장하지 않습니다. 일별 집계에는 분류별 숫자만 저장하며 개별 페이지 식별자를 복사하지 않습니다. 원시 이벤트가 만료되면 세부 타임라인은 표시하지 않고 분류별 누적 수치는 보존합니다. 유한 기간 만료 후에는 현재 활동이나 보존 중인 자료에 필요한 연결을 제외하고 정리합니다. 학생의 페이지 출처까지 지우려면 개인정보 삭제 도구를 사용합니다.

## 개인정보와 운영 진단

WordPress 도구 › 개인정보 내보내기·개인정보 삭제에서 해당 이메일 계정의 Focus Tracker 기록을 처리합니다. 내보내기는 본인 기록과 표시된 문항·응답만 포함하고 비공개 정답·검증 근거는 제외합니다. 계정 삭제 시 해당 학생의 원시 자료·문항·발급 상태·집계를 삭제하고 다른 학생의 자료와 공유 활동은 유지합니다. 교사 화면의 학생별 기록은 현재 명단과 열람 권한을 확인합니다.

개인정보 삭제 처리 중에는 새 기록·문항·집계 저장을 중단하며 완료 후 새 학습은 가능합니다. 삭제 전 기록의 재전송을 차단하기 위해 HMAC 보호 키와 삭제 완료 시각만 유지하며, 개인정보 도구의 보관 항목과 내보내기에 이 보호정보를 표시합니다. 계정 삭제 후 보호 메타데이터에는 계정 번호 원문이나 학습 내용이 없는 HMAC 키의 삭제 상태 표식만 유지해 이전에 인증된 요청의 재생성을 막습니다. 이 최소 보안 정보는 기간 제한 없이 유지하고 플러그인 삭제 시 제거합니다. 다른 학생과 공유하는 활동의 작성자 참조는 공유 활동과 함께 유지됩니다.

운영 상태에는 저장소 준비 상태, 정리 마지막 성공·미처리 작업, 기록·시간 확인·문항 요청의 성공·오류·요청 제한, 검증 문항 없음·대기·자료 접근 실패를 표시합니다. 문항을 만들지 못한 정상 상태와 장애를 구분합니다. 변경 이력에는 담당자·변경 항목만 남기고 초안·선택 답은 넣지 않습니다. 요청 제한은 문항 일일 상한과 별개이며 일반적인 두 탭의 수집·시간 확인을 허용합니다.

요청 진단은 종류·상태별로 분당 한 번만 저장합니다. 표시한 관측 분 수는 전체 요청 횟수가 아니며 최근 시각도 최대 1분 간격의 표본입니다. 학생 기록·문항 횟수·요청 제한은 표본으로 바꾸지 않습니다. 학급·그룹 활동 일정을 한 번에 조회하고 학생 간에는 일정 공유 읽기 잠금을 사용하며, 교사의 시간 수정·종료·삭제와 개인정보 삭제 보호는 계속 검증합니다. 활동 확인 5초·승인 기한 최대 10초와 숨겨진 탭의 관측은 유지합니다.

## 검증과 복구

이번 버전은 그룹·학급 소속 조회 범위를 줄이고 승인된 학생의 점수와 통계 메타데이터를 묶어 읽습니다. 진행 중 점수의 불필요한 캐시 저장과 같은 통계의 재저장을 줄이며, 재전송은 변경된 참여 정보만 한 번 갱신합니다. 실제 Oracle 8.0.46의 같은 자료에서 60명 강제 점수 계산 431→195 SQL, 월간·이전 기간 통계 287→47 SQL이고 결과가 같았습니다. 내부 REST 처리의 비교이며 WordPress 부팅·계정 로딩·전체 HTTP 동접은 별도입니다. 자세한 범위는 ZIP의 `focus-tracker/docs/DB-OPTIMIZATION.md`에 있습니다.

종료 시각 기준 일정 인덱스가 자동 추가됩니다. 업데이트 전 DB를 백업하고 설치 후 설정·사이트 건강에서 저장소 준비 완료를 확인합니다. 인덱스 생성 실패 시 API를 중단하고 DB 버전을 완료로 표시하지 않으므로 DB 권한을 복구한 뒤 준비 검사를 다시 실행합니다. 교사는 계속 그룹과 활동 시간만 설정하면 됩니다.

이전 릴리스에서 Oracle MySQL 8.0.46의 여러 학생 동시 저장·자동 문항 발급 교착과 겹친 활동 동시 종료·삭제 오류를 수정했습니다. 이미 저장된 이벤트와 시작·종료 제어는 다시 INSERT하지 않고 확인 처리하되 새 종료 상태·활동 연결은 반영합니다. 교사가 시간을 바꾸는 순간에는 최신 시간으로 기록을 나눠 허용된 종료 전 기록을 저장하고 시간 밖 기록은 정책 처리합니다. 새 heartbeat가 도착한 세션의 잘못된 정리도 방지합니다.

응답이 늦거나 종료 시각이 가까울 때는 승인이 만료되기 전에 다시 확인해 불필요한 중단·재시작을 줄입니다. 서버 확인 없이 승인 시간을 연장하거나 활동 종료 뒤 수집을 허용하지 않습니다.

동시 로그인 준비에서 발견한 기본 Platform 요청 제한 캐시의 교착·만료 누락은 Platform 2.5.5에서 수정했습니다. 이전 Platform을 사용한다면 해당 공식 ZIP을 먼저 업데이트한 뒤 Focus ZIP을 설치합니다. 이미 2.5.5라면 이번 Focus ZIP만 교체합니다. 기존 카운터 횟수와 제한을 유지하며 누락된 만료를 다음 요청에서 자동 복구하므로 교사가 학생별 설정이나 전체 제한 초기화를 할 필요는 없습니다.

Oracle 검사 환경·정상 응답과 저장 무결성 기준·실제 브라우저 수와 HTTP 채널 수·규모별 측정 결과는 ZIP의 `focus-tracker/docs/MYSQL8-LOAD.md`에 구분합니다. 이번 PC의 실제 Chrome 다중 학생 부하는 메모리 안전선에 걸려 미실행이며, 소스 Chrome 기능 회귀와 학생별 실제 쿠키·nonce를 사용하는 인증 HTTP 부하는 별도입니다. HTTP 채널의 상태 신호는 합성 부하이며 실제 학생의 화면 집중을 측정한 결과가 아닙니다. 실제 학생 기기의 여러 탭과 학교 목표 동접은 운영과 같은 환경에서 추가 확인합니다.

이전 1.1.1의 로컬 PHP 작업자 4개 구성에서 10학생·20채널은 통과했지만 30학생은 응답 기한에 미달했고, 작업자 12개 구성의 30학생도 미달했습니다. 별도 120개 단발 승인 요청은 모두 응답했어도 48개가 제품의 5초 기한을 넘었으며, 계측을 끈 최종 60학생·120채널 시험도 수집 시작 전 timeout 96회로 실패했습니다. PHP 초기화 처리와 요청 대기가 주된 비용 범위였습니다. 이번 DB 최적화만으로 이 부하를 통과 처리하지 않습니다. 학교의 PHP-FPM·OPcache·하드웨어·애드온 구성에서 목표 학생 수와 탭 수로 다시 측정해야 하며, 작업자 수만 복사해 용량을 보장하지 않습니다.

이전 페이지 분류 릴리스는 실제 WordPress 7.1·PHP 8.3.33·MariaDB 11.4.10 / Platform 2.5.4에서 기존 Focus Tracker 1.0.1의 기록·설정을 보존하며 업그레이드했습니다. 일반 그룹 관리자와 기존·신규 학생의 권한 상속, 자료·교육게임·ML의 주간/월간 집계·입력 평가 중립·개인정보 삭제를 확인했습니다. 실제 로그인 브라우저의 90초 일정으로 자동 시작·자연 종료와 종료 후 통계 불변도 확인했습니다. 소스 회귀 결과는 ZIP의 `focus-tracker/docs/VERIFICATION.md`, 네이티브 검증 범위와 이전 릴리스 이력은 `focus-tracker/docs/REAL-WORDPRESS.md`에 있습니다. 다른 Oracle/MySQL 버전·학교 운영 DB·학교 목표 동접 부하·운영 캐시와 cron·실제 모바일 절전과 화면 읽기·백업 복원·수업 시범 운영은 `focus-tracker/docs/RC-ACCEPTANCE.md`의 추가 인수 범위입니다.

네이티브 브라우저는 PHP 작업자 4개와 OPcache를 사용합니다. 단일 Windows PHP 개발 서버에서 요청이 밀리면 연결 오류로 안전하게 중단되는 경우가 있어, 5초 확인·10초 승인 제한을 유지한 채 작업자를 준비했습니다. 학교 규모에 맞는 PHP-FPM 작업자·OPcache와 응답 시간을 별도로 확인해야 합니다. 이 로컬 기능 검사를 학교 전체 동접 부하 통과로 해석하지 않습니다.

업데이트 실패 시 새 활동을 멈추고 Focus Tracker를 비활성화합니다. 백업한 플랫폼 파일·애드온 파일·DB를 같은 묶음으로 복원한 뒤 버전·명단 권한·보관 기간·활동 시간·문항·대표 주간/월간 합계를 대조합니다. 브라우저를 새로고침해 이전 자산과 승인 상태를 갱신합니다. 플러그인 삭제는 데이터까지 지우므로 복구 방법으로 사용하지 않습니다.

## 비활성화와 삭제

비활성화는 데이터를 유지하고 정기 정리를 해제하며, 이 플러그인이 기본 부여한 학생 추적 권한만 회수합니다. 재활성화하면 자동 부여를 복원하며 관리자가 별도로 거부·회수한 권한은 강제로 복원하지 않습니다. 역할 저장 실패로 안전하게 회수하지 못하면 비활성화를 중단하고 오류를 표시합니다. 설치 전부터 수동으로 부여한 권한과 개인 권한은 변경하지 않습니다. WordPress의 플러그인 삭제는 여덟 전용 테이블과 설정을 영구 삭제합니다. 필요한 집계와 DB 백업을 먼저 보관합니다.
