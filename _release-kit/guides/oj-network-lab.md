## 하는 일

허브·스위치·라우터·방화벽과 가상 VPN을 구성하고 명령어와 패킷 이동으로 실습합니다. **별도 Linux 실습 서버·Docker·AI 설정은 필요하지 않습니다.** 계산은 학습자 브라우저에서 수행합니다.

## 1. 서버와 플랫폼 준비

[서버 준비](00-server-setup.md) 1~12단계를 마치고 OJ Platform {{platform_requires}}와 Addon API 1.9 이상을 먼저 활성화합니다. 새 사이트에서는 WordPress 관리자 → **OJ Platform 설치 → 신규 설치**까지 완료해야 플랫폼 경로가 열립니다. 단순히 플랫폼 플러그인만 활성화한 상태는 설치 완료가 아닙니다. 일반 WordPress 환경에서 실행하며 네트워크 실습 전용 서버 작업은 없습니다. 업데이트 전에는 서버 준비 20단계로 백업합니다.

## 2. ZIP 업로드

WordPress 관리자 → 플러그인 → 새 플러그인 추가 → 플러그인 업로드에서 **{{package}}**를 업로드하고 활성화합니다. 기존 버전은 ZIP 교체를 선택합니다. 1.0.0-rc.1~rc.3 프로젝트·초안은 Linux 프로필을 유지하며 schema 2로 읽고 현재 버전으로 저장할 수 있습니다. DB 테이블 재생성은 필요하지 않습니다. 네트워크 전체 활성화는 지원하지 않으므로 사이트별로 활성화합니다. 자체 프로젝트 테이블만 만들고 플랫폼·채점기 테이블은 변경하지 않습니다.

## 3. 권한과 실습 화면

네트워크 읽기자료의 바로 열기 버전에서는 **네트워크 실습 열기**를 누르면 해당 예제가 새 탭에서 시작됩니다. 일반 메뉴에서는 마지막 초안을 복원합니다. 교재 탭에서 변경한 구성은 일반 초안을 덮어쓰지 않고 별도 복구 사본에 보관합니다.

교재 실습 링크는 `/oj-addons/oj-network-lab/learn?exercise=l01`부터 `l23`까지 지원합니다. 실습 번호에 맞는 예제가 자동 선택되고 화면의 목표 영역에 단원 제목·업무 목표가 표시됩니다. 링크를 다시 열어도 이전 작업을 자동 적용하지 않고 초기 구성으로 시작합니다. 이어서 작업하려면 **내 프로젝트 → 해당 실습의 복구 사본**에서 복구합니다. 같은 예제를 쓰는 서로 다른 단원도 저장·복구 목록·보관 한도(각 20개)·로컬 삭제 범위가 분리됩니다. 일반 화면의 로컬 삭제도 교재 실습 사본은 지우지 않습니다. 서버 프로젝트는 기존처럼 계정별 목록을 공유합니다.

기존 `?scenario=lan` 등의 링크는 계속 지원합니다. 유효한 exercise와 scenario가 함께 있으면 exercise가 우선하고, 알 수 없거나 중복된 exercise는 무시한 뒤 유효한 scenario 또는 일반 화면으로 돌아갑니다. 허용목록은 설치 파일의 `resources/js/curriculum.js`에 있는 `CURRICULUM` 배열이며 각 항목은 `id`, `scenario`, `title`, `goal`입니다. 교재 빌더는 이 배열의 scenario와 원고의 초기 예제를 대조할 수 있습니다. URL로 임의 구성·코드·목표 문구를 주입하는 기능은 제공하지 않습니다.

**다음에 열 예제**는 **예제 열기**로 새로 시작할 대상이며 현재 저장본의 종류를 표시하지 않습니다. 선택만 바꾸면 현재 구성·목표는 유지됩니다. 새로 연 예제의 시나리오가 교재 링크와 일치할 때만 단원 안내를 표시하고, 다른 예제에는 해당 예제의 일반 목표를 표시합니다. 서버 프로젝트·파일·로컬 사본을 불러오면 출처 단원을 추측하지 않고 일반 불러오기·복구 안내만 표시합니다. 예제를 바꾸거나 저장본을 열어도 해당 탭의 교재별 복구 저장 범위와 일반 초안 보호는 유지됩니다.

1. 플랫폼 역할·권한에서 학생에게 **네트워크 실습 참여**, 교사에게 **네트워크 실습 교사**를 배정합니다. 학생 역할에 자동 부여하지 않습니다.
2. 플랫폼에 로그인하고 프로필 보완 안내가 있으면 계정 설정을 먼저 완료합니다. 교사는 네트워크 실습 메뉴(`/oj-console/addons/oj-network-lab`), 학생은 `/oj-addons/oj-network-lab/learn`을 엽니다.
3. 기초 예제 또는 07 IOS 스위치·08 IOS 라우터·09 FortiOS 정책·NAT·10 FortiOS IPsec을 엽니다. IOS는 `enable`, `configure terminal`, `show running-config`, FortiOS는 `config`, `edit`, `set`, `next/end`를 사용합니다. 현재 모드의 `?`와 Tab으로 문법을 확인합니다. 새 장비의 권장 CLI와 기존 장비의 프로필 교체를 제공합니다.
4. 서버 저장·파일 내보내기는 실행 설정과 시작 설정을 함께 보관합니다. IOS의 `copy running-config startup-config`와 FortiOS의 automatic/manual 저장은 장비의 시작 설정을 관리합니다. 장비 재부팅은 시작 설정을 복원하며 상단 실행 초기화는 현재 설정을 유지합니다. 로컬 초안은 이 브라우저·계정에 남으며 서버 저장 완료와 별도로 표시합니다. 서버 충돌 시 서버본 불러오기 또는 새 사본 저장을 선택합니다.
5. 터미널 출력 다음 줄의 프롬프트에서 명령을 입력하고 Enter로 실행합니다. 화면의 빈 공간을 클릭해 입력하며 긴 명령은 자동 줄바꿈됩니다. 상단 실행 버튼, 화살표 이력·Tab 완성·Ctrl+C 중단·Ctrl+L 화면 지우기를 제공합니다. 터미널의 **분석 도구** 또는 `lab help`로 출력 검색·정렬·줄 선택·설정 비교를 확인합니다. Linux의 `ip addr | grep -n inet`, IOS의 `show running-config | include interface`, FortiOS의 `show firewall policy | grep -f HTTP`와 공통 `lab logs | grep drop`을 지원합니다. 장비별 `lab` 도구는 실제 셸이 아니며 선택 장비의 가상 파일만 읽습니다. 상세 옵션과 한도는 설치 ZIP의 TOOLS-GUIDE.md에 있습니다.
6. **11 Windows CMD·PowerShell·방화벽** 예제를 열거나 PC·서버의 CLI 프로필을 Windows로 선택합니다. 터미널 상단에서 CMD/PowerShell을 전환하며 네트워크 설정을 공유합니다. WIN-PC의 `ipconfig /renew`, `powershell`, `Test-NetConnection winweb.lab -Port 80`으로 시작합니다. WIN-Web에서 PowerShell 방화벽 규칙과 활성 Public/Private 범주를 바꾸면 통신 결과도 바뀝니다. 설치 ZIP의 WINDOWS-GUIDE.md에서 지원 문법·객체 파이프·가상 파일·한계를 확인합니다. Windows 실습 서버 설치는 필요하지 않습니다.

현재는 개인 실습과 본인 프로젝트 저장을 제공합니다. 교사도 다른 사용자의 프로젝트를 열 수 없으며 학급 배정·공식 성적 채점은 제공하지 않습니다. 장비 20개·링크 40개·서버 프로젝트 사용자당 20개 한도가 있습니다.

## 4. 운영 설정과 확인

L21은 Linux IPv6 정적 주소·기본 경로·전달 설정과 NS/NA·MTU 복구, L22는 IOS OSPFv2 단일 영역의 비용·이웃·자동 우회, L23은 직접 연결 eBGP IPv4의 피어·경로 광고·Weight·철회를 다룹니다. 기본 예제 이름은 `ipv6`, `ospf`, `bgp`입니다. 기존 예제·프로젝트·시작 설정을 유지하며 데이터베이스를 다시 만들지 않습니다. 업데이트 후 모듈 자산 캐시를 갱신하고 세 교재 링크에서 올바른 새 예제가 열리는지 확인합니다.

WordPress **설정 → OJ Network Lab**에서 서버 보관 일수와 플러그인 삭제 시 데이터 제거 여부를 설정합니다. 0일은 무기한이며 기간을 지정하면 일일 예약 작업이 만료 프로젝트를 최대 500개씩 정리합니다. **도구 → 사이트 건강**에서 실습 저장소 상태를 확인합니다.

설치 확인은 허브와 스위치 예제에서 PC-A의 `ping 192.168.10.20`, 방화벽 예제의 `curl http://203.0.113.10`, VPN 예제의 `ping 192.168.20.10`, DHCP 예제의 `dhclient eth0`으로 진행합니다. 서버 저장 후 새로 열어 설정을 확인합니다. 화면을 준비하지 못하면 브라우저 개발자 도구에서 JavaScript 자산·module Worker 차단·캐시 버전을 확인합니다.

IOS·FortiOS 명령은 교육용 부분집합이며 실제 펌웨어를 실행하지 않습니다. 지원 목록은 설치 ZIP의 CLI-GUIDE.md를 확인합니다. 출력 분석은 브라우저에서 수행하며 추가 서버 요청을 만들지 않습니다. 동기 조회만 파이프에 연결하며 실시간 ping·traceroute·tcpdump 파이프, 쓰기·리다이렉션·셸 실행은 미지원입니다. 한 줄 2048자·8단계·200,000자·4000줄과 패턴·작업 예산을 적용합니다. WireGuard와 IKEv2·ESP는 실제 암호화가 없는 모델입니다. 동적 라우팅은 설정 변화 후 가상 500ms에 안정 경로를 계산하며 실제 Hello/Dead/Hold 타이머를 측정하지 않습니다. SLAAC·DAD·DHCPv6·IPv6 방화벽·OSPFv3·iBGP·MP-BGP·STP·IPv4 MTU·DHCP 자동 갱신은 미지원입니다. 실제 동작 범위는 화면 도움말과 설치 ZIP의 README를 기준으로 합니다.

## 5. 비활성화와 삭제

비활성화는 예약 작업을 해제하고 프로젝트를 보존합니다. 삭제도 기본으로 서버 기록을 보존합니다. 설정에서 **플러그인 삭제 시 데이터 제거**를 켠 뒤 삭제하면 해당 사이트의 전용 테이블과 설정을 제거합니다. 개인정보 내보내기·삭제는 WordPress 개인정보 도구를 사용합니다. 브라우저 초안·복구 사본은 실습 화면의 **로컬 초안 삭제**로 현재 일반/교재 실습 범위만 별도 정리합니다. 다른 실습의 복구 사본을 지우려면 그 실습을 열어 삭제합니다.
