# OJ PRIMM

문제의 본문·입력·출력·공개 예제로 PRIMM 수업을 자동 준비하는 OJ Platform 애드온입니다. 교사가 학급 기본값을 한 번 설정하면 문제 저장·학급 배정 뒤 예측(Predict)·실행 비교(Run)·탐구(Investigate)·수정(Modify)·제작(Make)의 자료와 질문을 생성합니다.

버전 **1.0.5**. OJ Platform **2.4.3 이상**, Addon API **1.7.0**, WordPress 6.6 이상, PHP 8.3 이상이 필요합니다. 자체 코드의 라이선스는 GPL-3.0-or-later이며 `LICENSE.txt`를 참고합니다.

## 교사의 준비

1. 플랫폼 AI 작업 배정에서 **문제로 PRIMM 수업 자료 생성**(`addon.oj_primm.generate_lesson`)에 AI 모델을 연결합니다. 전체 JSON이 잘리지 않도록 모델 지원 범위에서 최대 출력 토큰 8192 이상을 권장합니다.
2. 플랫폼 **제출 → 제출 설정**(`/oj-console/submissions/settings`)의 **직접 제출 허용 언어**를 저장한 뒤 **예제·실습 실행 지원**의 **실행 검사 → 결과 조회**로 성공을 확인합니다. 설정으로 허용되고 시험에 성공한 Python·C·C++·Java만 생성·실습에 사용합니다.
3. **학습 활동 → PRIMM 수업**에서 학급·모둠별 언어, 수준, 선수 개념, 수업 시간(15~180분), 도움 방식을 저장합니다. **학급 기본값으로 자료 자동 준비**를 켜면 담당 공간에서 접근 가능한 문제를 저장할 때 준비합니다. 신규 문제는 학급 문제로 배정한 뒤에도 준비를 시도합니다. 권한·한도로 생략된 경우 자동 준비 운영 상태에서 확인하고 다시 생성합니다.
4. 자동 공개의 기본값은 켜짐입니다. 실행 검증과 품질 검사를 통과하면 공개하고, 검토 사유가 있는 자료는 교사 검토 후 공개합니다. 자동 공개를 끄면 검증된 자료도 초안으로 보관합니다.

수동 생성, AI 없이 기초 템플릿으로 시작하기, 기존 배열·빈칸 문제를 연결하는 수동 활동도 제공합니다. 기초 템플릿은 원문과의 관련성을 교사가 검토해야 합니다. 편집·부분 재생성·재검증한 버전도 이 출처와 검토 요구를 유지합니다. 전체 자료를 AI로 새로 생성하면 새 자료의 품질 검사를 적용합니다.

## 검증·품질·운영

도입 예제 한 건과 Modify 기준 코드의 시험 사례(최대 여덟 건)를 기존 OJ 채점 경로에서 실행합니다. 예상 출력과 실제 출력이 모두 일치해야 실행 검증 완료로 표시합니다. 오류가 있으면 AI가 최대 두 번 고치고 매번 전체 사례를 다시 확인합니다. 직접 편집한 초안의 재검증은 AI 호출 없이 수행하고 오류를 그대로 알려줍니다.

추가로 수정 전 도입 코드가 Modify 사례에서도 통과해 버리는지 실행해 과제가 실제 행동 변화를 요구하는지 검사합니다. 구별되는 사례 부족, 위험한 코드 패턴, 수준·시간 대비 코드 크기 등의 사유는 검토 대상으로 표시합니다. 이 검사는 질문의 교육적 적합성이나 모든 입력의 정답을 보증하지 않습니다.

일시적인 연결 오류는 대기 시간을 늘리며 같은 파이프라인을 재개합니다. AI 요청 원장은 결과를 7일간 보관해 같은 요청을 재사용합니다. 외부 호출 뒤 결과 수신 여부가 불명확한 경우 자동 재발송하지 않으며, 교사가 확인하고 명시적으로 새 요청을 시작합니다. 미완료 생성·연습 작업은 시작 후 24시간이 지나면 만료되어 새 요청이 필요합니다. 오래 중단된 작업이 원장 보관 종료 후 자동 재발송되는 것을 막습니다. 취소·재개, 관리자 중지, 교사별 공정한 대기열, 사용량과 정체 상태를 제공합니다.

WordPress **설정 → OJ PRIMM**의 기본 한도는 교사별 활성 작업 3개·사이트 30개, UTC 일일 AI 호출 교사 40회·사이트 400회, 작업별 AI 6회, 일시 오류 자동 재시도 4회입니다. 플랫폼은 별도로 실제 실행 요청의 동시·시간당 한도를 관리합니다. 취소는 추가 단계 처리를 멈추며 이미 전송한 외부 호출의 비용을 되돌리지는 않습니다. 방문이 없는 사이트에서도 WordPress 예약 작업이 실행되도록 기존 서버 예약 설정을 유지합니다.

## 학생 활동

- 단계 응답·최초 예측·초안·도움 활동 상태를 저장하고 이어서 진행합니다. 여러 탭의 저장 충돌 때 서버 자료와 로컬 초안을 비교해 복구할 수 있습니다.
- 완료한 단계는 읽기 전용으로 다시 확인하며 현재 진행 단계를 바꾸지 않습니다. 단계 이동 시 초점과 상태 안내를 제공합니다.
- Modify 도움 방식은 없음, Parsons 코드 순서 배열, 코드 빈칸 채우기입니다. 배열은 모든 조각을 한 번씩 사용하며 들여쓰기를 고정합니다. 조밀한 행, 마우스·터치 손잡이와 키보드 이동을 지원합니다.
- 새 자료에서는 수정 코드·배열 복원 코드·빈칸 완성 코드를 실제 OJ로 연습 실행합니다. 저장한 현재 코드가 모든 Modify 사례를 통과해야 Make로 이동합니다. 연습 결과는 공식 제출이나 AC에 합산하지 않습니다.
- Make에서 **채점 화면에서 제출하기**를 누르면 초안을 저장하고 기존 OJ 제출 화면에 코드와 수업 언어를 자동으로 채웁니다. 학생은 확인 후 직접 **제출하기**를 누릅니다. 제출 후 학습 창으로 돌아오면 본인의 새 제출과 채점 결과를 자동 연결하므로 코드나 제출번호를 복사하지 않습니다. 이전 제출은 **이전 내 제출 결과 사용**으로 선택하며 과정 완료와 최종 정답은 별도 지표입니다.

## 자료 관리와 보고서

교사는 단계별 자료를 편집하거나 필요한 단계만 AI로 다시 생성할 수 있습니다. 편집본은 전체 재검증 후 공개합니다. 공개 자료의 내용은 새 버전으로 만들며 기존 학생의 활동 번호와 응답을 보존합니다. 공개·회수·다른 학급에 재사용을 지원하고, 문제나 연결된 도움 템플릿이 바뀌면 오래된 내용을 공개·복제하지 못하게 합니다. 회수된 활동의 기존 참여자는 기록을 읽을 수 있습니다.

보고서는 현재 담당 명단의 미시작 학생을 포함하며 검색·페이지 이동·전체 CSV 내보내기를 제공합니다. 100개 이상의 활동과 200개 이상의 학생 기록도 전용 보고서에서 모두 조회합니다. CSV의 수식 문자를 안전하게 처리합니다.

## 화면·권한·개인정보

| 화면 | 경로 | 애드온 권한 |
| --- | --- | --- |
| 교사 수업 관리 | `/oj-console/addons/oj-primm` | `oj_primm_teach` |
| 학생 활동 | `/oj-addons/oj-primm/learn?activity=<id>` | `oj_primm_learn` |

실제 WordPress 권한 키는 `oj_addon_` 접두사를 사용합니다. 교사는 담당 공간, 학생은 본인 기록만 조회하며 처리 전후에 현재 권한을 검사합니다. PRIMM은 공개 Addon API만 사용하고 플랫폼 내부 DB·채점 연결에 직접 접근하지 않습니다.

AI에는 문제의 공개 자료와 생성된 수업·예제 실행 오류만 보냅니다. 학생 코드·응답·명단·비공개 테스트는 AI에 보내지 않습니다. 학생 수정 코드는 기존 OJ 연습 실행 경로로 전달합니다. Make의 초안 전달은 플랫폼의 암호화 임시 저장소를 사용하고, 본인·문제·수업에 묶인 링크는 5분 후 만료됩니다. 코드 원문은 URL에 넣지 않습니다. 생성 자료·검증 결과·학생 진행·개인별 연습·생성 사용량은 개인정보 내보내기·삭제 대상입니다. 플랫폼은 임시 자료·AI 원장·네이티브 실행 기록의 별도 보관·삭제를 담당합니다.

기본 보관 기간은 무기한입니다. **설정 → OJ PRIMM**의 보관 일수를 1~3650일로 지정하면 지난 학생 기록·연습과 종료된 생성 작업을 매일 정리하며 수업 자료는 유지합니다. 비활성화·일반 삭제는 보존하고, **삭제 시 데이터 제거**를 명시적으로 켠 뒤 플러그인을 삭제할 때 전용 6개 테이블과 옵션을 제거합니다. 단일 사이트별 활성화만 지원합니다.

## 설치와 개발 검증

OJ Platform 2.5.0(Addon API 1.8) 이상에서는 공개 문제 확인과 제출 확인을 분리합니다. 자동 저장은 제출 목록·전체 개수·소스를 읽지 않으며 최신 제출 확인은 한 건만 조회합니다. 기존 지원 플랫폼에서는 기존 공개 API 경로로 동작합니다. 결과가 같으면 자동 확인 간격을 늘리고, 실패한 스키마 갱신은 60초 간격으로 제한합니다.

플랫폼을 먼저 업데이트하고 PRIMM ZIP을 WordPress에서 업로드합니다. 기존 데이터는 유지하며 PRIMM 저장소는 스키마 3으로 갱신합니다. 실제 설치 절차는 `_release-kit/guides/oj-primm.md`를 참고합니다.

공식 패키지는 저장소 루트의 릴리스 킷으로만 생성합니다.

```powershell
_release-kit\release.cmd package -Plugin oj-platform,oj-primm
_release-kit\release.cmd docs
_release-kit\release.cmd check
```

출력은 `_releases/oj-primm/1.0.5/`이며 릴리스된 파일은 덮어쓰지 않습니다. 개발 검증은 `scripts/verify.ps1`, 실제 설치 인수 검증은 `tests/ACCEPTANCE.md`를 사용합니다. 로컬 SQL 어댑터·가짜 AI/채점기 검증과 실제 WordPress·MariaDB·AI 제공자·네이티브 OJ 검증을 구분해 기록합니다.
