# 실제 설치 인수 검증

이 문서는 테스트용 WordPress·MariaDB·실제 AI 제공자·HUSTOJ 채점기를 연결한 뒤 수행합니다. `scripts/verify.ps1`의 fixture 검증을 이 결과로 대신 기록하지 않습니다. 운영 자료 대신 복구 가능한 시험 학급과 계정을 사용합니다.

## 사전 조건과 기록

- 설치할 OJ Platform / PRIMM ZIP의 버전·SHA-256, 설치 시각, PHP·WordPress·MariaDB·채점기 버전을 기록합니다.
- 플랫폼 2.3.25 / PRIMM 0.3.0의 기존 응답·활동이 있는 DB를 백업하고 업데이트합니다. PRIMM 스키마 3과 플랫폼 설치 마법사의 갱신 완료를 확인합니다.
- 교사 두 명, 서로 다른 학급의 학생 두 명, 미시작 학생을 준비합니다. 교사 담당 범위와 학생 참여 권한을 확인합니다.
- 서버 준비 11단계 예약 실행과 플랫폼 AI 제공자·작업 배정이 정상인지 확인합니다. 사용할 언어는 제출 설정의 고정 실행 검사로 실제 통과시킵니다.
- 표에는 실행일·사용 계정·작업/활동 번호·결과·증거 경로를 남깁니다. API 키·학생 코드·개인정보를 공유 로그에 넣지 않습니다.

## 출시 기록 구분

로컬 생산 저장소 SQL 테스트는 SQLite 어댑터, AI/OJ는 fixture를 사용합니다. 2026-10-25에는 사용자가 지정한 judge.codingpanda.kr에서 기존 플랫폼 업데이트·실제 Gemini 생성·네이티브 OJ 검증을 추가로 진행했습니다. 실행한 항목과 미실행 항목, 발견한 문제는 저장소의 `_notes/verification/2026-10-25/oj-primm-1.0-live/README.md`에 구분해 기록합니다. 실제 MariaDB 잠금·외부 장애 복구·전체 사이트 인수를 모두 통과한 것으로 간주하지 않습니다.
