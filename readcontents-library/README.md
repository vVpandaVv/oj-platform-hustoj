# ReadContents Library Plugin 3.3.10

## 3.3.10 변경

- 학생 레슨 화면에 같은 주제의 공개 목차를 본문 옆에 표시한다. 현재 레슨이 속한 장을 펼치고 읽는 레슨을 표시한다. 초안·보관된 상위 항목 아래의 레슨은 목차에 노출하지 않는다.
- 목차와 본문 사이의 세로선을 드래그하거나 좌우 방향키로 목차 너비를 조절한다. 두 번 클릭하면 기본 너비로 돌아간다. 학생 화면의 너비는 편집기 설정과 별도로 기억한다.
- 목차 숨기기로 본문을 넓게 보고 목차 보기로 다시 열 수 있다. 데스크톱의 너비와 숨김 상태를 같은 브라우저에서 기억하며, 모바일에서는 기본으로 접고 필요할 때 펼친다.
- 화면 모드, 본문·퀴즈·시각화와 기존 접근 권한을 유지한다. 콘텐츠 재가져오기나 DB 변경은 필요 없다.

## 3.3.9 변경

- 목차와 본문이 나란히 표시되는 레슨 편집 화면에 너비 조절선을 추가했다. 두 영역 사이를 드래그하거나 조절선에 포커스를 두고 좌우 방향키를 누르면 목차 너비가 바뀐다.
- 조절한 너비는 같은 브라우저에서 기억한다. 창 크기가 줄면 본문 공간에 맞춰 제한하며, 다시 넓히면 선택한 너비를 복원한다. 조절선을 두 번 클릭하면 기본 너비로 돌아간다.
- 모바일에서는 기존 목차 서랍을 유지한다. 본문과 목차의 독립 스크롤, 콘텐츠 저장 방식은 유지한다.

## 3.3.8 변경

- 학생 레슨 화면의 밝은 모드 고정을 해제했다. 플랫폼의 라이트·다크·시스템 화면 모드를 목록·주제·레슨에 동일하게 적용한다.
- 레슨 제목·표·인용·인라인 코드·접기·퀴즈·시각화 조작부의 기본 색을 플랫폼 토큰에 연결했다. 모드를 바꾸면 페이지를 다시 열지 않아도 반영된다.
- 작성자가 직접 지정한 본문 색과 이미지·도표의 원래 색은 유지한다. 콘텐츠 재가져오기나 DB 변경은 필요 없다.

## 3.3.7 변경

- 레슨 편집 화면의 목차와 본문을 독립 스크롤 영역으로 분리했다. 편집기 상단과 목차 제목은 고정되며, 본문 도구 모음은 본문 영역 안에서 유지된다.
- 다른 레슨을 선택하면 목차의 스크롤 위치는 유지하고 본문만 맨 위로 이동한다. 입력·저장이나 서랍 열기에는 본문 위치를 초기화하지 않는다.
- 콘솔 상단 높이, 서버 설치 안내 펼침, 창 크기와 모바일 화면 변화를 반영해 편집 영역 높이를 계산한다. 라이브러리와 목차 편집 목록은 페이지 스크롤을 유지한다.
- 이전 번들의 높이 설정을 덮어쓰던 `!important` 규칙을 제거했다. 본문·DB·미디어·공개 화면은 변경하지 않는다.

## 3.3.6 변경

- 편집기에 남아 있던 TypeScript 진단 22건을 수정했다. 검사 범위를 제외하거나 `any`·검사 무시 주석을 추가하지 않았다.
- 달력의 날짜 포커스·표 스타일을 현재 DayPicker API에 맞추고, 툴바 버튼의 ref·접근성 속성 타입을 명확히 했다.
- 브라우저 환경 변수·타이머·선택 범위 검사, 콤보박스 상태 확인, Lodash 하위 모듈 계약, 객체 검색 옵션을 정리했다.
- 시각화의 계산 불가 셀·누락된 병합 연결·산점도 기본 항목·간트 축 데이터 및 SVG 경계선 드래그 타입을 보완했다.
- `npm run check`는 타입 검사를 통과한 다음 빌드를 실행한다. 콘텐츠 본문·DB·미디어·삭제 정책은 변경하지 않는다.

## 3.3.4 변경

- 라이브러리 주제 카드, 목차의 선택 항목 관리, 레슨 본문에 보관·영구 삭제 아이콘 버튼을 연결했다.
- 보관함을 주제뿐 아니라 챕터·장·레슨까지 조회하도록 고쳤다. 초안 복원·영구 삭제 버튼과 처리 결과를 표시한다.
- 저장되지 않은 본문은 먼저 저장하고, 확인 취소·저장 실패 시 보관/삭제를 진행하지 않는다. 중복 클릭을 차단한다.
- 복원은 보관된 항목에만 허용하며 보관 중인 상위 항목을 먼저 복원한다. 삭제 경고는 보관된 하위 항목도 포함함을 명시한다.
- WordPress가 삭제를 거부한 레슨의 본문 메타데이터를 먼저 지우지 않도록 수정했다. 보관·복원·삭제 성공은 사용 가능한 감사 로그에 기록한다.

플러그인에는 편집·목차 관리·공개 화면·콘텐츠 가져오기 기능만 포함한다. 읽기자료 본문과 사진은 포함하지 않으며 활성화 시 특정 자료를 자동으로 생성하지 않는다.

## FTP 서버 ZIP 가져오기

1. **플러그인을 삭제하지 않고 3.3.10으로 업데이트**한다. 기존 편집본과 DB·미디어를 먼저 백업한다.
2. 콘솔 **읽기자료** 메뉴(편집기)의 **보조 기능(더보기) → 패키지 가져오기/내보내기 → 서버 ZIP 가져오기**를 연다.
3. 표시된 **FTP 업로드 폴더**에 콘텐츠 ZIP을 압축 그대로 전송한다. 플러그인 설치 ZIP이 아닌 `information-science-content-2026-09-12.zip` 또는 챕터별 콘텐츠 ZIP을 사용한다.
4. FTP 전송 완료 후 새로고침 아이콘을 누르고 파일을 선택해 미리본다. 처리 중 ZIP을 교체하거나 수정하지 않는다.
5. 중복 레슨 처리 방법을 확인하고 가져오기를 시작한다. 기본값은 **기존 레슨 유지**다. 옛 이미지 경로까지 새 본문으로 교체하려면 백업 후 **기존 레슨 대체**를 선택한다. 레슨별 선택과 덮어쓰기 확인을 지원한다.
6. 완료 후 콘텐츠를 확인한다. 원본 ZIP은 자동 삭제하지 않으므로 필요 없으면 FTP에서 직접 지운다.

이 기능은 FTP 접속 클라이언트가 아니다. FTP/SFTP로 **같은 웹 서버에 업로드해 둔 ZIP**을 읽으며 FTP 비밀번호를 저장하지 않는다. 브라우저 업로드 용량 제한을 거치지 않는다.

### 폴더와 서버 조건

- 기본 폴더는 웹 서버 `DOCUMENT_ROOT`의 상위 폴더 아래 `readcontents-imports`다. 실제 경로는 관리 화면에서 확인한다.
- **웹 공개 경로 밖의 전용 폴더**만 허용한다. WordPress 폴더, `wp-content`, 웹 루트 내부와 심볼릭 링크는 거부한다. 폴더에는 PHP 읽기·쓰기 권한이 필요하다.
- 호스팅의 기본 경로가 맞지 않으면 `wp-config.php`에 아래 상수를 설정한다. 예시 경로를 그대로 쓰지 말고 호스팅의 실제 비공개 절대 경로로 바꾼다.

```php
define('READCONTENTS_LIBRARY_IMPORT_DIR', '/home/ACCOUNT/readcontents-imports');
```

- FTP 계정이 웹 루트 밖에 접근하지 못하거나 PHP `open_basedir`가 막으면 호스팅 관리자에게 전용 비공개 폴더와 PHP 접근 권한을 요청한다. 웹에 노출된 폴더로 우회하지 않는다.
- PHP `ZipArchive` 확장이 필요하다. 원본 ZIP, 임시 파일, 미디어 라이브러리와 썸네일을 위한 디스크 공간도 필요하다.
- 관리자 설정 변경, 파일 업로드, 읽기자료 편집·공개 권한을 모두 가진 사용자에게만 제공한다. 다른 관리자는 진행 상황만 볼 수 있으며 이어하기·취소는 시작한 계정으로 한다.

### 진행 상태와 복구

이미지 한 개 또는 레슨 한 개씩 처리하고 DB 옵션에 진행 위치를 저장한다. 원본 ZIP 전체를 DB에 넣지 않는다. 이미지 파일은 스트림으로 읽어 WordPress 미디어 라이브러리에 등록하고 본문의 주소를 바꾼다.

가져오는 동안 화면을 열어 둔다. 별도 백그라운드 작업은 아니다. 일시 정지 후 또는 화면을 다시 열고 **이어하기**로 계속할 수 있다. 서랍을 닫으면 현재 항목 처리 후 정지한다. 브라우저 종료·연결 단절 때 현재 요청의 처리 결과가 확실하면 마지막 저장 지점에서 계속한다.

서버가 항목 처리 도중 강제 종료되어 등록 여부를 알 수 없으면 **등록 결과 확인 필요**로 멈춘다. 중복 등록을 막기 위해 해당 항목을 자동 재시도하지 않는다. 이미 등록된 콘텐츠·미디어를 확인하고 작업을 취소한 뒤 새 미리보기를 진행한다. 취소는 기존 작업을 롤백하지 않으며 재가져오기에 따라 이미지 중복이 생길 수 있다.

분할 처리도 개별 대형 이미지의 썸네일 생성에 필요한 메모리·실행 시간까지 없애지는 못한다. 같은 자료를 동시에 편집하거나 다른 패키지를 가져오지 말고 작업 완료/취소 후 플러그인을 비활성화한다.

## 삭제 정책

**WordPress 관리자에서 플러그인을 삭제하면 읽기자료 라이브러리에 등록된 모든 주제·챕터·장·레슨과 본문이 영구 삭제된다.** 정보과학 자료뿐 아니라 이 라이브러리에서 만든 알고리즘·파이썬 등 다른 주제와 직접 수정한 내용도 포함한다. 먼저 콘텐츠 내보내기와 DB 백업을 수행한다.

- 비활성화 또는 ZIP 업데이트: 기존 콘텐츠를 유지한다. 비활성화 시 자체 상태 점검용 임시 캐시만 제거한다.
- 플러그인 삭제: `rcis_content_node` 전체, 해당 문서의 메타데이터·수정 이력, 구형 본문 덮어쓰기 옵션과 이전 완료 표시, 서버 ZIP 가져오기 진행 옵션, 버전·활성화 설정, 자체 상태 점검 캐시를 제거한다. 초안·휴지통·사용자 정의 상태도 포함한다.
- 재설치: 빈 라이브러리로 시작한다. 별도 콘텐츠 ZIP을 다시 가져와야 한다. 삭제한 편집 내용은 자동 복구하지 않는다.
- WordPress 미디어 라이브러리의 이미지·첨부파일과 다른 플러그인의 데이터는 유지한다. 공용 미디어를 임의 삭제하지 않으며 재가져오면 미디어 파일이 중복 등록될 수 있다.
- 멀티사이트에서는 플러그인 파일이 공유되므로 각 사이트의 읽기자료를 정리한다.
- FTP로 플러그인 폴더만 지우면 WordPress 삭제 절차가 실행되지 않아 DB 정리가 되지 않는다.
- FTP로 올린 원본 ZIP과 비공개 폴더의 잠금 파일은 플러그인 삭제 시에도 남는다. 다른 용도로 사용되는 파일을 임의 삭제하지 않는다.

3.2.12 이하에서 이 삭제 정책으로 초기화하려면 **먼저 3.2.14 이상으로 업데이트한 뒤 비활성화 → 삭제 → 재설치**한다. 구버전을 먼저 삭제하면 구버전에 정리 코드가 없어 기존 DB가 남는다. 업데이트 자체로 데이터가 삭제되지는 않는다.

## 3.3.0 변경 (D-010 통합 디자인)

- 콘솔 메뉴 이름을 **읽기자료 관리**에서 **읽기자료**로 바꿨다. 주소(`/oj-console/addons/readcontents-library`)와 권한은 그대로다.
- 편집기 화면은 플랫폼 2.1.0 이상에서 몰입형 레이아웃으로 열린다. 셸이 사이드바를 접고 전체 폭을 준다. 2.0.x에서는 이전처럼 표시한다.
- 학생 메뉴 **학습 활동 › 읽기자료**를 기본으로 켠다. 사용자 메뉴 설정을 이미 저장한 사이트는 저장된 값(켜짐·꺼짐)을 따르므로 필요하면 메뉴 설정에서 직접 켠다.
- 학생 화면(목록, 주제, 레슨)을 플랫폼 공용 부품으로 바꿨다. 페이지 머리말, 빈 상태, 경로, 초안 알림이 `ojp-*` 부품이고 색·모서리는 `--ojp-*` 토큰이다. 그라데이션 머리말과 영어 표기를 없앴다.
- 목록과 주제 화면은 플랫폼 다크 모드를 따른다. 당시 밝은 화면으로 고정했던 레슨 화면은 3.3.8에서 같은 화면 모드를 따르도록 수정했다.
- 레슨 본문은 17px로 키우고 본문 변수(글자·선·강조 색)를 플랫폼 토큰에 연결했다. Plate 본문 HTML은 바꾸지 않았다.
- 화면 용어를 **주제 › 장 › 레슨**으로 맞췄다(챕터 → 장). 장 안의 묶음은 따로 이름을 붙이지 않고 묶음 제목만 보여 준다.
- 찾을 수 없는 주제·레슨 화면의 돌아가기 문구를 "읽기자료 목록으로 돌아가기"로 통일하고, 학생 화면의 모든 링크를 `home_url()` 기준으로 만든다(하위 폴더 설치 대응).
- 옛 콘솔 화면의 `.rcis-console*` 스타일과 쓰이지 않는 학생 화면 스타일(히어로, 목차 격자, 옛 장 카드 등)을 지웠다.
- `assets/editor/workspace-layout.css`의 `!important` 3개는 편집기 번들이 직접 넣는 인라인 높이를 풀기 위해 남겼다. 셸을 덮어쓰는 규칙은 없다.

## 3.2.14 변경

- FTP 업로드 ZIP 목록·미리보기·중복 처리·분할 등록·진행 상태·일시 정지·이어하기·취소를 추가했다.
- 서버 작업을 파일 잠금과 진행 커서로 보호하고 완료된 요청 재전송 시 중복 실행하지 않는다. 미리보기 이후 ZIP이나 대체할 기존 본문이 바뀌면 재확인을 요구한다.
- 기존 웹 ZIP 가져오기도 ZipArchive 사용 시 이미지 전체를 메모리에 올리지 않고 스트리밍하며 크기와 CRC를 검증한다.

- WordPress 표준 `uninstall.php`에만 영구 삭제 처리를 연결했다. 활성화·비활성화·업데이트에는 연결하지 않았다. 직접 URL 접근은 차단한다.
- 100개씩 ID 순서로 삭제하고 실패 시 완료로 처리하지 않는다. 중단 후 재시도할 수 있지만 이미 삭제한 데이터의 자동 롤백은 제공하지 않는다.
- WordPress 연결 시 데모 목차로 초기화하지 않아 `demo-lesson-1/document` 404 요청을 보내지 않는다. WordPress 밖의 프리뷰 데모는 유지한다.
- 내부 JSON이 없는 분리 배포에서는 단일·전체 JSON 재가져오기 메뉴를 표시하지 않는다. 서버도 데이터 조회·변경 전에 콘텐츠 ZIP 가져오기를 안내한다.
- 3.2.10 배포 번들과 해시가 같은 빌드의 원본 소스에서 수정 후 편집기 번들을 다시 빌드했다.
- 편집기 전체의 고정 높이와 내부 세로 스크롤을 해제했다. 라이브러리·목차·본문은 페이지 스크롤을 사용한다.
- 영구 목차 패널도 페이지 높이에 맞춰 표시한다. 팝업·서랍의 스크롤과 넓은 표·코드의 가로 스크롤은 유지한다.
- 스크롤 수정은 별도 `assets/editor/workspace-layout.css`를 유지한다. 인라인 높이를 해제하는 선택자는 실제 편집기 DOM으로 회귀 검사한다.
- 콘텐츠 ZIP 가져오기의 URL 판별 정규식을 수정했다. 외부 출처 링크를 로컬 미디어 경로로 오인하지 않는다.
- ZIP 목차와 참조 미디어의 존재를 업로드 전에 확인한다.

## 설치 및 데이터 경계

기존과 같은 `readcontents-library/contents-editor.php` 경로를 사용한다. 콘텐츠는 별도 `information-science-content-2026-09-12.zip` 또는 장별 ZIP을 콘텐츠 가져오기 화면에서 등록한다. 콘텐츠 ZIP은 플러그인 설치용이 아니다.

기존 DB 편집본·다른 주제는 플러그인 활성화/업데이트에서 삭제하거나 덮어쓰지 않는다. 플러그인 폴더의 옛 이미지 URL이 남은 기존 자료는 콘텐츠 팩 재가져오기 또는 별도 미디어 이전이 필요하다. 전환 전에 DB·업로드·기존 통합 플러그인을 백업한다.

새 분리 배포에서는 플러그인 내부 JSON 재가져오기 대신 콘텐츠 ZIP 가져오기를 사용한다. 실제 운영 DB·권한·서버 업로드 한도는 시험 사이트에서 확인해야 한다.

이미지 404는 이 업데이트만으로 복원되지 않는다. 기존 이미지 파일의 임시 FTP 복원 또는 콘텐츠 ZIP을 통한 미디어 저장소 이전이 필요하다. 플러그인 교체 후 FTP 복원을 수행해야 하며, 옛 경로에 복원한 파일은 다음 플러그인 교체에서 제거될 수 있다.
