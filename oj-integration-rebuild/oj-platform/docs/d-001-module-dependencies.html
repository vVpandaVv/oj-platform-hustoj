OJ Platform 재정비 기준 · D-001

모듈·의존 관계 재정비

이 문서는 모듈 목록을 조사하는 데 그치지 않고, OJ Platform 재정비에서 유지·분리·제거할 책임과 필수·선택 의존 계약을 확정하기 위한 기준서입니다.

기준일 2026-07-15 근거 config/modules.php, modules/*/Module.php 상태 재정비 결정 확정
19현재 활성 선언 모듈
20전환기 목표 모듈
9목표 필수 기반 모듈
10 + 1선택 기능 + 임시 전환 모듈
핵심 결론: 현재 코드는 초기 18개에 PlatformDb를 추가한 19개를 선언합니다. 재정비 목표는 CF-5와 D-008에서 확정한 필수 jobs를 더해 전환기 20개로 조립합니다. 사용자 선택 기능 10개는 개별 비활성화가 가능한 구조를 보존하고, migration은 전환 완료까지 잠근 뒤 제거하므로 정상 운영은 다시 19개입니다.

재정비 확정 결정

D-001 검토 과정에서 사용자 확인을 받은 세 가지 기준입니다.

  1. 1

    초기 18개 모듈 전체 조사

    지금 제거 대상을 고르지 않고 모든 모듈의 화면과 데이터를 조사한 뒤 유지·통합·제거를 결정합니다.

  2. 2

    선택 모듈 독립성 유지

    선택 기능은 개별적으로 끌 수 있어야 하며, 숨겨진 전이 의존을 명시적인 계약으로 정리합니다.

  3. 3

    이전 도구는 전환 완료까지 유지

    migration은 재정비 중 필요한 운영 도구로 유지하고, D-008의 확정 계약에 따라 이전 검증과 7일 관찰 및 별도 제거 승인이 끝나면 제거합니다.

재정비 기준이 되는 현재 적재 흐름

숫자는 config/modules.php의 우선순위입니다. 같은 단계 안에서도 왼쪽에서 오른쪽 순서를 의미하지는 않습니다.

재정비 선결 과제 8가지

8개 문제 모두 소스 반영·정적 검사를 마쳤고 사용자 확인까지 완료했습니다.

  1. 01

    설정 모듈의 역방향 참조

    문제별 제출 방식은 문제 편집 화면이, AI 피드백 설정은 ai_feedback이 소유합니다.

    소스 반영·정적 검사·사용자 확인 완료

  2. 02

    문제와 AI 책임 중첩

    공통 AI 호출을 인프라로 옮기고 문제 메타데이터와 제출 피드백이 이를 독립적으로 사용합니다.

    소스 반영·정적 검사·사용자 확인 완료

  3. 03

    Blockly의 숨은 전이 의존

    문제·권한의 직접 의존을 선언하고 제출 화면에서 필요할 때만 Blockly 본체를 적재합니다.

    소스 반영·정적 검사·사용자 확인 완료

  4. 04

    대회·수업의 선택적 그룹 의존

    대회·수업은 그룹을 선택 의존으로 선언하며 그룹 OFF에서도 정상 적재됩니다.

    소스 반영·정적 검사·사용자 확인 완료

  5. 05

    AI의 전이 인증 의존

    AI가 실제 사용하는 인증과 권한 모듈을 직접 선행 조건으로 선언합니다.

    소스 반영·정적 검사·사용자 확인 완료

  6. 06

    학습 현황의 의존 관계 불투명

    학습 현황 서비스와 렌더러가 필요한 의존을 생성자로 직접 받습니다.

    소스 반영·정적 검사·사용자 확인 완료

  7. 07

    DB 모듈의 이중 책임

    platform_db가 플랫폼 스키마를, judge_db가 저지 연결과 저지 테이블을 소유합니다.

    모듈 책임만 분리했으며 DB·테이블명·데이터는 변경하지 않음

  8. 08

    관리자 메뉴 소유권 분산

    AdminConsole만 메뉴를 등록하며 경로 권한을 메뉴에 반영하고 두 권한 검사를 모두 통과한 항목만 표시합니다.

    소스 반영·정적 검사·사용자 확인 완료
