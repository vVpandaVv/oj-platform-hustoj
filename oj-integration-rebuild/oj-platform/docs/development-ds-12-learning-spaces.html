DS-12 · 메뉴 기반 상세 설계

학습 공간 상세 설계

서비스의 상시 학습은 수업, 시간 제한 평가는 대회, 여러 수업에서 재사용하는 사용자 묶음은 그룹으로 구분한다. 일반 사용자에게는 학습, 관리자에게는 학습 공간 1차 메뉴 아래 수업 → 대회·평가 → 그룹 순서로 표시한다. 데이터와 권한은 기능별로 소유하며 수업과 대회는 그룹 기능 없이도 완전하게 동작해야 한다.

시안 확정: DS12-Q01~Q08과 메뉴 순서, 사용자·관리자, 수업·대회·평가·그룹을 나눈 시안 7종을 사용자 확정으로 동결했다. 직접 화면 47개와 관리자 허브 상태를 기준으로 I-00 보호 환경을 통과한 뒤 I-05에서 수업 → 대회·평가 → 그룹 순서로 구현한다.
범위 경계: 문제 원본과 문제 은행은 DS-10, 제출 생성·채점 결과·상세 정책은 DS-11, AI 피드백·개인 학습 분석·전체 랭킹은 DS-13이 소유한다. DS-12는 문제와 제출을 복제하지 않고 문맥별 접근과 보고서만 조립한다.

액션 수량 유지: 새 액션을 추가하지 않는다. 기존 oj_class_join·oj_class_delete는 oj_class_membership_command·oj_class_lifecycle_command로, oj_contest_join·oj_contest_delete는 oj_contest_participation_command·oj_contest_lifecycle_command로 일대일 교체한다. 각 명령은 등록된 operation 허용 목록과 작업별 nonce·권한·현재 상태를 검사하며 서로 다른 기능을 받는 범용 액션으로 확장하지 않는다.

수업 설계

수업은 일정·접근·담당자·문제·직접 참여자와 학습 진도를 소유한다.

구현 1순위
1 · 준비기본 정보·담당자·접근 설정
2 · 운영참여자·문제·풀이·진도
3 · 종료보고서·보관·복원
기능권장 동작권한저장·조회
개설·편집추가 화면에서 이름, 설명, 시작·종료, 접근 방식, 전체 풀이 현황 공개, Blockly 프로필, 공동 강사, 그룹과 문제 구성을 한 번에 저장한다. 수정 화면은 생성 이후 변경에 사용생성 권한 또는 전역 관리자. 개설자를 소유자로 기록classes와 수업 관계 4개 테이블
수업 복사목록·수정 화면에서 기존 추가 화면의 copy_from으로 초안을 연다. 이름·설명·Blockly·문제 순서와 숨김 여부·현재 연결 가능한 그룹을 가져온다. 주소는 새로 입력하고 비공개·운영 중지를 기본으로 확인 후 저장한다. 참여자·학습 기록·공동 강사·비밀번호·수업 및 문제 공개 기간은 복사하지 않는다.원본 관리 권한과 수업 생성 권한 모두 필요. 저장 시 그룹·문제 사용 권한 재검증GET은 저장하지 않으며 기존 oj_class_save와 원자 저장을 사용. 새 ID와 저장자의 소유권 생성, 문제 원본·제출은 복제하지 않음
접근 방식public, password, private, group_only 네 가지. 기본은 private소유자만 변경, 공동 강사는 조회classes.visibility, 비밀번호 해시, class_group_links
공동 강사사용자 검색으로 추가·해제하고 해제는 다음 요청부터 즉시 반영소유자만 담당자 변경. 공동 강사는 구성원·문제·보고서 운영class_instructors
참여자신청, 초대, 직접 등록, 승인, 거절, 나가기, 제외, 재등록을 같은 사용자 행의 상태 전환으로 처리본인 신청·나가기, 소유자·공동 강사 승인·직접 등록·제외class_enrollments
문제 구성제목·난이도·주제로 검색해 선택하고 순서, 공개 기간, 공개 여부를 조정소유자·공동 강사class_problem_links, Problems 읽기 Provider
그룹 연결활성 그룹을 검색해 참여 대상에 추가한다. 그룹은 참여 후보를 제공할 뿐 수업 참여 행을 대신하지 않음소유자·공동 강사와 그룹 조회 범위class_group_links, 선택적 Groups Provider
진도·제출세로 참여자·가로 문제 행렬에 해결·시도·미시도와 합계를 표시하고, 문제 공개 뒤 활성 참여자의 첫 정답을 최초 해결로 표시한다. 담당자는 항상 전체를 보며 참여자는 participants_live일 때 행렬을 보고, private이면 본인 진도만 본다. 수업·문제 기간은 워드프레스 지역 시간, Judge 제출 시각은 UTC로 해석해 동일한 절대 시각으로 비교하며 시작·종료 경계를 포함한다. 내 제출과 모든 학습 현황이 같은 조회 기준을 사용하고, 참여 승인 시각은 저장된 UTC 기준을 유지한다.담당 수업 소유자·공동 강사 또는 공개 정책을 통과한 활성 참여자classes.progress_visibility + 수업 관계 + DS-11 제출 조회. 시간대 보정은 조회에만 적용하며 기존 기록을 수정하거나 재제출하지 않는다.
보관·복원보관하면 신규 참여와 수업 문맥 제출을 닫고 보고서는 유지. 복원은 현재 관계와 기간을 재검증소유자 보관, 소유자 또는 전역 관리자 복원classes.deleted_at와 관계 유지
수업 추가 화면: 기본 정보만 먼저 저장한 뒤 수정 화면으로 보내지 않는다. 추가 화면에서 접근 방식·전체 풀이 현황 공개·Blockly 프로필·공동 강사·그룹 연결·문제·공개 순서를 모두 구성하고 수업 만들기 한 번으로 원자 저장한다. 수정 화면은 생성 이후 변경에만 사용한다.
수업 전체 풀이 현황: 관리자 화면은 공개 설정과 관계없이 전체 행렬을 조회한다. 참여자 공개 시에는 표시 이름·문제별 상태·최초 해결자·전체 진도만 제공하고 다른 참여자의 제출 상세·코드는 제공하지 않는다. 최초 해결은 문제 공개 이후이면서 당시 활성 참여자였던 사용자의 가장 이른 정답 제출로 계산한다.
입력·행렬 사용성 보완 (2026-09-18): 연결 그룹은 공통 다중 선택기에서 최소 240px·8줄 이상으로 표시한다. 학습 현황은 참여자 이름 옆에 푼 문제 수(정답 / 전체)를 표시하며, 수업·문제 공개 기간과 참여 승인 기준을 통과한 유효 정답 문제를 중복 없이 집계한다. 문제 열은 폭을 유지하고 표 내부에서 좌우로 스크롤하며 참여자 열과 표 머리글은 고정한다. 별도 누적 스냅샷이나 카운터를 저장하지 않고 기존 제출 조회 결과로 계산한다.
원자 저장: 수업 본체, 공동 강사, 그룹 연결과 문제 연결은 하나의 Classes 업무 서비스가 검증하고 같은 PlatformDb 트랜잭션에서 모두 성공하거나 모두 되돌린다. Judge 문제 존재 확인은 쓰기 전에 완료한다.

대회 문제 구성: 대회 추가 화면에서 문제·대회 문제 번호·순서·배점을 구성한 뒤 준비 단계로 생성한다. 같은 수정 경로에서 준비 단계까지는 문제를 추가·삭제·정렬하고 배점을 바꿀 수 있지만, 시작과 동시에 문제·순서·배점을 잠가 진행 중 일반 편집을 허용하지 않는다.
대회 전체 풀이 현황: 참가자를 행, 문제를 열로 두고 선택한 채점 방식에 맞는 값을 표시한다. ICPC는 해결·오답·벌점, OI는 최고 통과율 점수·완전 해결·벌점, 일반 점수형은 실제 첫 정답 풀이 시간·정확성·시간 점수·오답 감점을 보여준다. 순위·총점 또는 벌점·이름 정렬을 지원하며, 관리자는 항상 담당 범위를 보고 참여자는 live일 때 실시간, final일 때 종료 뒤, private이면 조회하지 못한다.

채점과 순위

채점 방식문제 결과순위고정 규칙
ICPC icpc_v1맞았습니다 여부와 정답 전 오답 수해결 수 내림차순 → 벌점 오름차순벌점은 첫 정답 경과 초 + 감점 대상 오답당 1,200초이며 미해결 문제의 오답은 총 벌점에 넣지 않는다.
OI oi_v1문제별 최고 pass_rate × 배점총점 내림차순 → 완전 해결 수 내림차순 → 벌점 오름차순정답 여부와 관계없이 최고 부분 점수를 인정하고, 벌점은 동점 비교에만 사용한다.

일반 점수형 세부 규칙

항목확정 규칙설명
정답 기본 점수배점 - 최대 시간 점수기본 시간 비율 10%이면 100점 문제의 정답 기본 점수는 90점이다. 시간 비율은 준비 단계에서 1~30%로 설정하고 시작 뒤 잠근다.
부분 점수none 또는 pass_rate_correctness_base_v1사용하지 않으면 완전 정답일 때만 정답 기본 점수를 부여한다. 사용하면 현재까지의 최고 clamp(pass_rate, 0, 1) × 정답 기본 점수를 정확성 점수로 사용한다.
시간 점수floor(최대 시간 점수 × (대회 시간 - clamp(실제 풀이 시간, 0, 대회 시간)) / 대회 시간)완전 정답일 때만 부여한다. 실제 풀이 시간은 대회 시작부터 해당 문제의 첫 정답 제출까지의 경과 초이며 늦게 풀수록 선형으로 감소한다.
문제 점수max(0, 적용 정확성 점수 + 완전 정답 시간 점수 - 정답 전 오답 감점)부분 점수를 사용하면 미해결 문제도 최고 통과율에 따른 점수를 가질 수 있다. 최종 점수는 원래 문제 배점을 넘지 않으며 감점 대상 제출이 추가되거나 재채점되면 다시 계산한다.
감점 대상틀렸습니다, 시간 초과, 메모리 초과, 런타임 오류, 출력 초과컴파일 오류, 시스템 오류, 채점 대기, 첫 정답 이후 제출은 감점하지 않는다. 기본 감점은 오답 1회당 5점이며 준비 단계에서 0 이상으로 설정한다.
순위 1차시간 반영 총점 내림차순모든 문제의 정확성·시간·오답 감점을 반영한 최종 점수를 합산한다. 빠른 풀이가 이 단계에서 점수 차이로 드러난다.
순위 2차해결 문제 수 내림차순총점이 같으면 더 많은 문제를 해결한 참가자가 앞선다.
순위 3차점수 완성 시각 오름차순시간 점수까지 같은 경우 현재 총점을 먼저 달성한 참가자가 앞선다. 대회 시작부터 해당 점수를 완성한 마지막 첫 정답까지의 경과 초를 비교한다.
완전 동점공동 순위총점·해결 수·점수 완성 시각이 모두 같으면 같은 순위를 부여하고 표시 순서만 이름순으로 안정화한다.
재채점현재 유효 결과로 전체 재계산Judge 결과가 바뀌면 오답 수, 문제 점수, 점수 완성 시각과 순위를 같은 정책 버전으로 다시 계산한다.

그룹은 재사용 가능한 구성원·운영자 묶음이며 수업·대회 콘텐츠를 소유하지 않는다.

일반·수행 모드수행 모드에서도 풀이·제출·채점·결과 목록은 유지하고 제출 결과 상세·코드·오류·AI 피드백만 제한소유자·활성 위임 운영자evaluation_mode와 Groups 제출 정책 Provider
제출·순위현재 활성 구성원의 제출을 기간별로 조회한다. 제출이 그룹 안에서 생성됐다고 표시하지 않음학습자는 허용된 목록, 운영자는 담당 그룹 전체구성원 범위 + DS-11 제출 조회
보관·복원가입과 관리 작업을 닫고 관계·보고서를 유지한 뒤 현재 소유·관계를 재검증해 복원소유자 또는 전역 관리자그룹 3개 테이블 관계 유지
이름 저장 범위: 관리용 이름은 그룹별 별칭이 아니라 계정에 저장하는 학생 이름이다. 수정하면 같은 사용자가 속한 다른 그룹 관리 화면에도 반영된다. 일반 사용자 그룹 화면에는 표시 이름만 제공하며 관리용 이름은 전송하지 않는다. 기존 이름이 바뀐 경우 덮어쓰지 않고 충돌을 알린다. 일괄 저장 Action은 oj_group_save_member_names이며 nonce·활성 로그인·현재 그룹 관리 범위를 서버에서 검증한다. 애드온 공개 API와 DB 스키마는 변경하지 않는다.
수행 모드 우회 방지: 활성 수행 모드 그룹의 일반 구성원은 그룹 안팎에서 생성한 본인의 모든 제출에 result_only가 적용된다. 화면 링크, 직접 URL, AJAX·파일 응답과 AI Jobs가 같은 DS-11 정책을 사용하며 여러 그룹 중 하나라도 수행 모드이면 제한을 유지한다.
