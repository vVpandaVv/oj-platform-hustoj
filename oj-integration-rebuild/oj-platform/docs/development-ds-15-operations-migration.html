신규 설치·운영·데이터 이전 상세 설계

학습용 채점 서비스의 신규 설치, 기능·사이트·사용자 메뉴·홈·메일·AI 연결 프로필·작업별 AI 배정·Judge DB 연결을 한 운영 체계에서 관리하고, 시스템 상태와 데이터 이전을 일상 설정에서 분리한다. 위험 작업은 사전 검사, 영향 확인, 승인, Jobs 실행, 검증과 복구 증거가 모두 갖춰져야 실행할 수 있다.

공통 화면 구성

설정과 위험 작업을 같은 시각 무게로 섞지 않는다.

시안 1종 작성
통합 시안: 신규 설치 마법사와 정상 운영 관리자 화면 13개에서 설치 전 단일 작업 흐름과 운영 개요, 일반 설정, AI 연결 프로필, 작업별 AI 배정, 상태·데이터 이전의 실제 배치와 반응형 구성을 한 문서에서 확인한다.
운영 개요상태·마지막 변경·다음 조치 표
일반 설정현재값·수정·변경 비교·저장

  • 운영 개요는 카드 모음이 아니라 화면명, 상태, 마지막 확인·변경 시각, 담당 권한, 필요한 조치를 비교하는 한 개 표를 사용한다.
  • 일반 설정은 화면 하단의 고정 저장 영역에서 변경 개수와 마지막 저장자를 보여 주고, 다른 관리자가 먼저 저장한 revision은 덮어쓰지 않는다.
  • 연결 화면은 저장된 비밀값을 다시 표시하지 않는다. 입력이 비어 있으면 기존 값을 유지하고, 삭제는 별도 선택과 확인이 있어야 한다.
  • 위험 작업은 빨간 버튼을 첫 화면에 두지 않는다. 사전 검사와 복구 증거를 통과한 경우에만 마지막 확인 영역에 실행 버튼을 표시한다.
  • 기술 키, 테이블·열, fingerprint와 오류 코드는 접힌 기술 상세에만 표시한다. 기본 화면은 정상·확인 필요·사용 불가와 다음 행동을 한글로 제공한다.
  • DS-15 UI 시안은 운영 관리자 화면 한 문서로 묶는다. 신규 설치 마법사와 정상 운영 13개 화면을 각각 별도 문서로 늘리지 않는다.

10건 확정
  1. DS15-Q01 · 메뉴·페이지 · 확정·보완: 권한별 운영 개요를 첫 화면으로 사용한다. AI 연결 프로필·작업별 배정 분리를 유지하고 2026-09-14 통합 AI 사용량을 추가해 운영 2차 메뉴는 13개, 직접 화면은 14개로 보완한다.
  2. DS15-Q02 · 사이트·메뉴·홈 · 확정·보완: 직접 루트와 Route Registry는 다시 설정하지 않지만 사용자 메뉴의 1차·2차 표시 이름·내부 Route 연결·부모·표시 대상·순서·모바일 위치는 모두 관리한다. 외부 HTTPS 링크도 1차 또는 2차로 배치한다. 메뉴 깊이는 최대 2단계이고 내부 주소는 Registry에서만 선택하며, 외부 링크는 OJ Route나 접근 권한으로 해석하지 않는다.
  3. DS15-Q03 · 외부 연결 · 확정·보완: Judge DB·메일·AI는 후보 검사 뒤 명시적으로 적용하며 실패 시 기존 active 연결과 비밀값을 유지한다. AI는 OpenAI·Gemini·Ollama·MLX-LM·vLLM·SGLang·고정 HTTP 계약의 OpenAI 호환 Gateway를 허용한다. 자체 모델은 Judge와 분리된 AI 서버에서 설치하고 HTTPS·인증 Reverse Proxy 또는 서버 API 키, 모델 ID·digest/revision, 채팅·구조화 응답을 검사한 뒤 활성화한다. Provider 선택 시 관리자 화면의 입력 예시와 통신 예시를 같은 Registry에서 즉시 갱신한다. endpoint·인증·모델은 연결 프로필에만 저장하고 네 업무의 주·대체 프로필과 제한은 별도 작업 배정 revision에 저장한다.
  4. DS15-Q04 · 시스템 상태 · 확정: 등록형 Provider의 안전한 요약과 다음 조치를 우선하고 기술 상세는 시스템 관리자에게만 제공한다.
  5. DS15-Q05 · 점검·삭제 · 확정: 점검 모드와 모듈별 쓰기 동결을 분리한다. 플러그인 제거 데이터 삭제는 상시 토글이 아니라 30분짜리 일회성 승인으로만 허용한다.
  6. DS15-Q06 · 데이터 이전 · 확정: D-008의 파동과 0~10단계를 platform_migration Jobs로 실행하고 사전 검사·승인·검증·7일 관찰 없이는 전환·정리하지 않는다.

  8. DS15-Q08 · 호환 제거 · 확정: 호환 리디렉션과 oj_migration_clear_redirects를 만들지 않고 같은 명령 수 안에서 승인형 oj_migration_run으로 교체한다.
