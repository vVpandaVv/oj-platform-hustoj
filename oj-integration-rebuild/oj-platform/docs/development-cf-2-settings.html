Settings 상세 설계

공통 설정 저장기는 기술 기반만 제공하고, 각 기능이 자기 설정의 기본값·검증·화면·저장 명령을 소유하도록 재정비한다. 기존 운영 데이터는 유지하면서 비밀값과 기능 전환을 안전하게 관리하는 실제 구현 계약이다.

설계 원칙

설정 기반이 업무 모듈의 책임을 다시 흡수하지 않게 한다.

고정 원칙
  1. 단일 소유: 각 설정 묶음은 한 기능 모듈만 정의·검증·정규화·저장 명령·화면을 소유한다.
  2. 기반 역할 제한: Settings는 정의 등록, 권한 연결, WordPress 옵션 입출력, 비밀값 보호와 변경 충돌 검사만 제공한다.
  3. 직접 저장 금지: 업무 코드는 get_option()·update_option()을 직접 호출하지 않고 소유 모듈의 읽기 계약과 명령 서비스를 사용한다.
  4. 기능 OFF 데이터 보존: 기능을 끄면 경로·메뉴·명령·작업을 닫되 기존 설정과 업무 데이터는 삭제하지 않는다.
  5. 명시적 저장: 화면을 열거나 플러그인을 활성화하는 것만으로 옵션을 새로 쓰거나 기존 값을 정규화해 덮어쓰지 않는다.
  6. 서버 재검증: 화면의 숨김·비활성 상태와 관계없이 저장 요청은 권한·nonce·기능 상태·스키마·현재 revision을 다시 검사한다.

WordPress 옵션 저장 계약

기존 옵션을 읽으면서 변경 충돌과 스키마 전환을 관리한다.

새 테이블 없음
속성의미규칙
schema_version소유 모듈 설정 스키마 버전읽을 수 없는 미래 버전은 저장하지 않고 확인 필요로 표시
revision낙관적 동시성 번호화면을 연 뒤 다른 사용자가 저장했다면 덮어쓰지 않고 변경 비교 제공
updated_by_user_id마지막 저장 사용자숫자 wp_users.ID, 시스템 변경은 명시적 시스템 주체 사용
updated_atUTC 저장 시각표시는 사이트 시간대로 변환
values소유 모듈이 검증한 실제 설정비밀값은 평문이 아니라 Secret_Vault 참조만 저장
  1. 현재의 평면 배열 옵션은 schema_version=0, revision=0인 기존 형식으로 읽는다.
  2. 기존 형식은 화면 조회만으로 바꾸지 않고, 소유 모듈 화면에서 첫 저장이 성공할 때 검증 후 새 봉투 형식으로 전환한다.
  3. 정의에 없는 필드는 자동 삭제하거나 그대로 복사하지 않고 “확인 필요”에 표시해 소유 모듈 이전 규칙으로 처리한다.
  4. 저장 시 옵션별 짧은 잠금을 원자적으로 획득하고 최신 revision을 다시 읽어 유실 갱신을 막는다.
  5. 모든 옵션은 autoload=false로 저장하며 페이지에 필요한 설정만 Settings_Reader가 요청 단위로 캐시한다.
연결 검사 결과: oj_platform_database_test_result는 사용자 설정이 아니라 짧게 보존하는 운영 상태다. 비밀번호와 전체 오류 문장을 저장하지 않고 검사 시각·결과 코드·지연·안전한 요약만 보관한다.

비밀값 보호와 키 교체

SMTP·Judge DB·AI 연결 비밀값을 같은 규칙으로 보호한다.

민감 데이터
작업목표 동작실패 처리
키 구성신규 설치는 WordPress 보안 키에서 플러그인 암호화 키를 자동 파생한다. 별도 키 회전이 필요하면 OJ_PLATFORM_SECRET_KEYS와 OJ_PLATFORM_SECRET_PRIMARY_KEY_ID를 지정하며 이 구성이 우선한다.WordPress 보안 키와 별도 키가 모두 없거나 OpenSSL을 사용할 수 없으면 비밀값 저장만 차단하고 원인을 화면에 표시
저장새 비밀값을 AES-256-GCM으로 먼저 암호화하고 secret:v2:{uuid} 참조를 설정에 저장설정 저장 실패 시 새 비밀값 레코드를 폐기하고 기존 참조 유지
유지비밀값 입력을 비우면 기존 값을 유지하고 “저장됨” 상태만 표시빈 입력을 삭제로 해석하지 않음
삭제별도 “저장된 비밀값 삭제” 선택과 확인 뒤 설정 참조를 먼저 제거하고 미참조 레코드 폐기필수 비밀값이면 기능 비활성 또는 새 값 입력 없이는 차단
교체교체 미리보기 후 새 기본 키로 재암호화하고 모든 참조 검증이 끝날 때까지 이전 키 유지일부 실패는 확인 필요로 남기고 이전 키와 기존 암호문 유지
노출 방지화면·HTML·로그·내보내기·스냅샷·예외에는 평문과 암호문을 모두 표시하지 않음진단에는 참조 ID 끝 6자와 상태 코드만 사용
기존 키 호환: 현재 OJ_PLATFORM_SECRET_KEY는 이전 암호문을 읽고 v2로 교체하는 기간에만 허용한다. 모든 참조 검증과 사용자 승인 뒤 제거하며 자동으로 새 키 목록에 복사하지 않는다.

1 · 선택토글 변경을 임시 상태로만 보관저장 전 변경 개수와 원래 상태
2 · 의존 계산필수 의존과 종속 기능, 경로·메뉴·명령·에셋·예약 작업 영향 계산함께 변경될 기능과 사유
3 · 사전 검사각 소유 모듈이 진행 중 쓰기 작업, 필수 연결, 보존·복구 가능 여부 검사진행 가능·주의·차단을 한글로 표시
4 · 확인차단이 없을 때 영향 요약을 확인하고 변경 토큰 발급데이터가 삭제되지 않음과 다시 켰을 때 복구 범위
5 · 확정최신 revision과 사전 검사 결과를 다시 확인하고 기능 상태 묶음을 저장성공·실패와 실제 변경 목록
  1. 필수 기능은 토글을 제공하지 않고 잠금 사유를 표시한다.
  2. 진행 중인 쓰기 작업이 있는 기능은 작업 완료 또는 안전한 취소 전까지 끌 수 없다.
  3. Groups를 꺼도 Classes와 Contests를 자동으로 끄지 않으며 두 기능은 직접 참여 관계로 계속 동작한다.
  4. 기능 OFF는 데이터 삭제·옵션 삭제가 아니며, 화면·직접 주소·POST·API·Jobs 진입을 같은 기능 상태로 차단한다.
  5. 미리보기 이후 상태가 바뀌면 확정을 거부하고 새 미리보기를 요구한다.

DS-16 승인 후 전환 순서

운영 옵션을 한 번에 바꾸지 않고 읽기 호환부터 단계적으로 전환한다.

아직 구현 안 함
순서작업통과 조건
1현재 18개 옵션과 신규 oj_platform_ai_task_routing, 직접 get_option·update_option 호출의 실제 사용처를 자동 검사로 고정옵션·필드·소유 모듈 누락 0건
2정의 Registry, 호환 Reader, 저수준 Option Store와 기존 Secret 읽기 추가기존 옵션을 쓰지 않고 같은 유효값을 읽음
3기능별 정의·검증·설정 화면·저장 명령을 소유 모듈로 이동중복 메뉴·중복 저장 처리 0건
4새 봉투 저장, revision 충돌, Secret v2와 키 교체 기능 활성화평문 노출 0건, 실패 시 기존값 유지
5기능 전환 미리보기·사전 검사·일괄 확정 연결직접 주소·POST·API·Jobs가 같은 상태 적용
6대형 Renderer·Repository의 업무 기본값·정규화와 Module 콜백 제거Settings가 다른 기능 업무 규칙을 소유하지 않음
복구 기준: 새 Reader는 전환 기간에 기존 평면 배열과 새 봉투를 모두 읽는다. 배포를 되돌릴 때 새 봉투를 읽지 못하는 구버전으로 바로 복귀하지 않고, 검증된 이전 호환 배포본 또는 옵션별 복구 변환을 사용한다.

미래 인수 기준
소유권
모든 설정 키가 한 소유 모듈에만 등록되고 기능별 기본값·검증·화면·명령이 해당 모듈에 있다.
Registry 구조 검사
호환 읽기
18개 기존 옵션과 새 봉투 옵션이 같은 유효 설정으로 읽히며 조회만으로 저장되지 않는다. 신규 AI 배정 옵션이 없으면 기능 Registry의 안전한 기본 배정을 읽되 자동 생성하지 않는다.
고정 데이터 통합 검사
동시성
두 관리자가 같은 설정을 편집하면 오래된 revision 저장이 거부되고 차이가 표시된다.
동시 저장 검사
비밀값
저장·유지·삭제·교체·실패 복구 과정에서 평문과 암호문이 화면·로그·내보내기에 노출되지 않는다.
보안·마스킹 검사
기능 상태
30개 기능의 의존·사전 검사·데이터 보존·재활성화가 결정적이며 Groups OFF에서도 Classes·Contests가 동작한다.
기능 전환 통합 검사
권한
메뉴·GET·POST·API·연결 검사·비밀값 변경이 DS-02의 같은 권한 판정을 사용한다.
허용·거부 검사
UI·문구
한글 원문, 공통 폼, 오류 요약, 키보드 조작과 모바일 레이아웃이 DS-01 기준을 통과한다.

DS-03 확정 결과

아래 다섯 항목을 2026-07-22 사용자 확인으로 동결했다.

5건 확정
  1. DS03-Q01 · 설정 소유 · 확정: 기능별 기본값·검증·화면·저장 명령은 해당 기능 모듈이 소유하고 Settings는 공통 저장·Registry·비밀값·변경 조정만 제공한다.
  2. DS03-Q02 · 옵션 호환 · 확정·보완: 기존 oj_platform_... 옵션 이름을 유지하고, 조회만으로 쓰지 않으며 첫 유효 저장 때 revision을 포함한 봉투 형식으로 전환한다. 작업별 AI 배정은 연결 프로필과 동시성·비밀값 경계를 분리하기 위해 신규 oj_platform_ai_task_routing 옵션 하나만 사용한다.
  3. DS03-Q03 · 비밀값 · 확정: 키 ID 목록과 기본 키를 사용하고 빈 입력은 유지, 명시적 삭제는 재확인, 키 교체는 검증 완료까지 이전 키를 보존한다.
  4. DS03-Q04 · 기능 전환 · 확정: 30개 기능은 영향 미리보기와 소유 모듈 사전 검사를 거쳐 확정하며 OFF 시 화면·명령은 닫지만 설정과 업무 데이터는 보존한다.
  5. DS03-Q05 · 구조·수량 · 확정: 목표 Controller 66개를 유지하고 Settings Module의 업무 로직을 기존 소유 Controller·Command Service·Presenter로 옮기며 DS-03에서는 물리 테이블을 추가하지 않는다.
확정·구현: DS03-Q01~Q05를 설계 기준으로 유지한다. 설정 계약과 암호화 저장 코드는 재구축 작업 트리에 구현했으며 운영 비밀값과 옵션은 설치·이전 승인 전까지 쓰지 않는다.
