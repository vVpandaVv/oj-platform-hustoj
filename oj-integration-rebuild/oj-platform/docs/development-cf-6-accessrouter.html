DS-07 · 공통 기반 CF-6

AccessRouter 상세 설계

152개 GET 경로를 타입이 있는 단일 Registry로 고정하고, 직접 주소와 메뉴가 같은 로그인·기능·대상 권한을 사용하도록 매칭·URL 생성·WordPress rewrite 수명주기를 정한다.

작성일: 2026-07-23확정일: 2026-07-23전체 설계 확정일: 2026-07-26상태: 사용자 확정 · 설계 동결선행 설계: DS-00~DS-06 확정실행: I-00 뒤 I-01근거: D-002·D-003·D-005·D-006·D-007·D-009·DS-02·DS-06·DS-16
전체 순서에서의 위치: 이 문서는 전체 설계·개발 순서의 DS-07이며 DS07-Q01~Q08과 최종 Registry 152개를 사용자 확정으로 동결했다. Router·로그인 우선 접근 Policy·Action Dispatcher를 재구축 코드에 구현했으며 운영 WordPress rewrite는 설치 승인 전까지 반영하지 않는다.

모듈 범위와 의존 방향

AccessRouter는 업무 데이터를 직접 읽지 않고 등록된 계약을 조정한다.

단방향 의존

기능 Route Provider자기 Controller·접근 Policy대표 경로·매개변수·기능·접근·응답 종류 등록다른 기능 경로 소유

  1. 기능 모듈이 대표 화면을 소유하고 AccessRouter는 공통 실행기만 소유한다.
  2. 메뉴·본문 링크·직접 주소는 모두 동결된 같은 Route Definition과 Access Policy를 사용한다.
  3. AccessRouter는 Container를 실행 중 조회하지 않는다. Module 조립 시 필요한 Registry·Policy·Responder를 생성자로 전달한다.
  4. GET·HEAD는 조회와 파일 응답만 허용한다. 상태 변경은 D-003의 admin_post·AJAX 계약을 사용한다.

등록·검증·동결

일부 경로만 등록된 상태에서 rewrite나 메뉴를 만들지 않는다.

부팅 관문
1 · 수집

기능별 등록

모든 모듈이 자기 대표 경로와 Policy를 등록한다.

2 · 참조 검사

키와 대상 확인

모듈·기능·Policy·Handler가 실제 Registry에 존재하는지 확인한다.

3 · 충돌 검사

이름과 경로 고유성

이름, 메서드+경로, placeholder 이름만 다른 동일 경로 모양과 정적·동적 우선순위를 검사한다.

4 · 동결

불변 Registry

152개 수량과 영역별 합계를 검산한 뒤 Matcher·URL·메뉴·rewrite가 같은 읽기 전용 Registry를 사용한다.

  1. 검증 실패 시 잘못된 정의만 건너뛰고 부분 실행하지 않는다. OJ 라우팅은 닫고 WordPress 일반 페이지는 유지하며 시스템 상태에 소유 모듈·오류 코드를 남긴다.
  2. 동적 경로보다 같은 깊이의 정적 경로를 먼저 매칭하고 등록 순서로 결과가 바뀌지 않게 한다.
  3. 목표 수량 151은 배포 기준 Manifest와 자동 검사에서 확인한다. 선택 기능 OFF는 정의를 삭제하지 않고 접근 시 404로 처리한다.

매칭과 접근 판정 순서

메뉴와 직접 주소가 같은 결과를 내도록 한 파이프라인을 사용한다.

단일 판정
순서검사실패 응답
1GET·HEAD 정규 경로와 WordPress rewrite가 내부 전달한 oj_route 매칭OJ 경로가 아니면 WordPress에 반환, 등록된 모양인데 값이 잘못되면 404
2경로·쿼리 타입 검사와 canonical 주소 비교잘못된 값 404, 끝 슬래시와 브라우저에 남은 ?oj_route=... 요청은 정식 직접 주소로 이동
3유지보수 정책기본 503 + Retry-After, 허용 경로만 계속
4기본 authenticated 로그인 정책과 명시적 guest_only·public 예외, user_profiles.access_status비로그인 HTML은 302로 로그인 화면, API·파일은 401/403, pending·suspended는 업무 화면 차단
5기능 all·any 상태기능 존재를 숨기는 404
6Access Policy의 capability·대상 존재·소유·담당·참여·수행모드 판정Policy 결정에 따라 403, 존재를 숨기는 404, 안전한 내부 경로 이동
7대표 Controller·Stream Handler 실행과 응답 종류 검사사용자용 500 화면과 추적 ID, 원시 예외·경로 정의 비노출
로그인 우선 진입: 모든 OJ Route는 기본 authenticated다. auth.login, 가입 기능이 켜진 auth.register, auth.guardian_consent와 법적 문서 4개만 비로그인 예외로 명시한다. 비밀번호 복구·재설정은 로그인 Route의 상태다. 비로그인 HTML은 /login으로 이동하고, 성공 후 검증된 내부 redirect_to가 없으면 메인 홈 /으로 이동한다.
수행모드: 제출 상세 Policy가 result_only를 반환하면 그룹 밖 제출을 포함한 본인의 모든 상세·코드·AI 피드백을 차단한다. HTML은 제출 목록으로 이동해 일회성 안내를 표시하고 파일·데이터 응답은 본문 없이 403을 반환한다.

호환 경로 제거

새 구조는 최신 대표 주소만 등록하며 이전 주소를 변환하지 않는다.

목표 0개
  1. 현재 코드의 호환 경로 39개와 설계 중 제안했던 status 주소 8개·이전 관리자 퀴즈 주소 1개는 목표 Registry에 등록하지 않는다.
  2. /problems/quizzes와 /oj-console/problems/quiz도 만들지 않는다. 사용자 퀴즈는 /quizzes, 관리자 퀴즈는 /oj-console/quizzes만 사용한다.
  3. 이전 주소 요청은 OJ가 가로채거나 식별자를 변환하지 않는다. 다른 WordPress 원본이 없으면 WordPress의 일반 404로 끝난다.
  4. 끝 슬래시·permalink 표현을 하나로 맞추는 canonical 이동과 로그인 화면 이동은 동일 Route의 정규화·접근 제어이며 호환 경로가 아니다.

WordPress 연결과 rewrite

학습용 채점 서비스의 대표 주소와 WordPress 페이지 원본을 이중으로 만들지 않는다.

직접 경로 권장
항목목표 계약
루트서비스 OJ는 home_routing_mode=direct를 사용하고 /를 home Route로 직접 매칭한다.
WordPress 페이지경로마다 새 페이지를 자동 생성하지 않는다. OJ Route가 아닌 기존 WordPress 글·페이지는 그대로 WordPress가 처리한다.
기존 OJ 생성 페이지_oj_platform_route 표식과 이전 상태는 전환 보고서에서만 확인한다. 자동 이동·삭제·slug 변경·본문 교체를 하지 않으며 충돌이 있으면 재정비 활성화를 차단한다.
slug 충돌기존 사용자 페이지를 보존한다. OJ 대표 경로와 충돌하면 활성화·전환 사전 검사에서 차단하고 사용자가 충돌 해결안을 승인한다.
rewrite 생성전체 Route Registry 동결 뒤 한 번 생성하며 정적 경로를 동적 경로보다 앞에 둔다.
flush활성화·승인된 경로 Signature 변경·비활성화에서만 잠금 후 한 번 실행한다. 일반 화면 요청에서는 실행하지 않는다.
정식 경로 전제비어 있는 WordPress 고유주소는 최초 동기화에서 /%postname%/로 준비하고 숫자 등 이미 선택한 구조는 보존한다. 공개 링크는 항상 /login 같은 직접 주소만 생성한다. Nginx는 알 수 없는 경로를 /index.php?$args로 전달해야 하며 플러그인이 서버 설정을 대신 쓸 수 없다.
설정형 1차·2차 메뉴: 내부 메뉴는 단계나 부모가 바뀌어도 Public Menu Manifest에 등록된 Route 키만 사용하고 Route_Link_Service가 기능·권한을 판정해 URL을 생성한다. 표시 이름·순서·부모는 접근 Policy를 바꾸지 않는다. 외부 메뉴의 parent_menu_key는 배치 키일 뿐 Route가 아니며 rewrite·Controller·Policy·URL Generator에 등록하지 않는다. PublicUi는 검증된 절대 https:// URL에 외부 아이콘·정규화 호스트·새 창·noopener noreferrer를 강제하므로 Route 수와 Signature는 변하지 않는다.
전환 안전: 현재 Page_Resolver 상태와 자동 생성 페이지를 먼저 읽기 전용 보고서로 만든다. 소유 표식이 없는 페이지는 OJ가 수정하지 않으며 기존 생성 페이지 정리는 DS-15 Migration 승인 전까지 수행하지 않는다.

URL 생성과 메뉴 연결

화면 코드의 하드코딩 주소와 권한이 없는 링크 생성을 분리한다.

대표 주소만 생성
  1. Url_Generator는 대표 Route 이름과 정확한 매개변수만 받아 canonical 직접 URL을 만든다. 브라우저용 ?oj_route=... 주소는 생성하지 않는다.
  2. 알 수 없는 Route, 누락·초과 매개변수, 타입 오류는 홈 URL로 대체하지 않고 명시적 오류 결과를 반환한다.
  3. Controller·Presenter·View는 공개 주소를 문자열로 조립하지 않고 대표 Route 이름만 사용한다. 이전 주소 문자열은 목표 코드에 두지 않는다.
  4. Route_Link_Service가 현재 기능·로그인·Policy를 통과한 명령과 메뉴만 반환한다. 링크 숨김은 직접 주소 권한을 대신하지 않는다.
  5. 관리자 상위 메뉴의 first_accessible_child는 정적 하위 Route의 접근 결과와 순서로 계산하고 접근 가능한 하위 화면이 없으면 상위 메뉴도 숨긴다.
  6. Jobs 상태·제출 피드백처럼 현재 페이지에 포함된 AJAX 명령은 D-003 Action Registry가 소유하며 AccessRouter URL과 혼합하지 않는다.

확정 항목

아래 여덟 항목은 2026-07-23 사용자 확인으로 동결했다.

사용자 확정
  1. DS07-Q01 · 수량·소유 · 최종 보완: DS-10 퀴즈 화면 분리, 최고 관리자 주제 관리, DS-15 작업별 AI 배정과 DS-14 보호 첨부 응답을 반영한 D-002의 152개를 사용하고 모든 대표 경로는 기능 모듈이 소유한다. 호환 경로는 등록하지 않는다.
  2. DS07-Q02 · 타입 정의: Route를 값 객체로 등록하고 이름·메서드+경로 모양·placeholder·참조를 전체 수집 뒤 검증·동결한다.
  3. DS07-Q03 · 입력·URL: ID·slug·파일·로그인·enum·내부 URL 타입을 명시하고 URL 생성 오류를 홈으로 대체하지 않는다.
  4. DS07-Q04 · 접근 순서: canonical·유지보수·기본 로그인 필수와 7개 비로그인 예외·플랫폼 이용 상태·기능·대상 Policy·Handler 순서를 사용하고 메뉴와 직접 주소가 같은 Policy를 사용한다.
  5. DS07-Q05 · 호환 경로: 목표 호환 경로는 0개다. 이전 주소·식별자·필터 변환 코드는 만들지 않고 대표 주소만 생성한다.
  6. DS07-Q06 · 루트·페이지: 서비스 OJ 루트는 직접 Router를 사용하고 경로별 WordPress 페이지 자동 생성을 중단한다. 기존 생성 페이지는 자동 이동·삭제 없이 전환 보고서와 충돌 검사 대상으로만 둔다.
  7. DS07-Q07 · rewrite: Registry 동결 뒤 rules를 만들고 활성화·Signature 변경·비활성화에서 잠금 후 한 번만 flush한다.
  8. DS07-Q08 · UI·검증: 로그인 첫 화면·홈 복귀, 수행모드, 403·404·503, 숫자·글 이름 고유주소, Nginx front-controller 준비, 이전 주소 부재와 기존 WordPress 페이지 보존을 자동·브라우저 검사한다.
