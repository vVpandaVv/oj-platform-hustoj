보호 원칙

백업과 복원 도구 자체가 운영 데이터를 훼손하지 않게 제한한다.

강제 규칙
  • DB 비밀번호는 파일·명령 인수·JSON·Git에 기록하지 않고 실행 중 보안 입력으로만 받는다.
  • 백업 위치가 Git 저장소 내부이거나 암호화 저장소 확인이 없으면 백업을 중단한다.
  • WordPress DB와 Judge DB의 host·port·DB가 같으면 잘못된 경계로 판정하고 중단한다.
  • 복원 대상은 두 원본 서버와 다른 server:port이어야 하며 DB명은 _test로 끝나야 한다.
  • 이미 존재하는 복원 DB는 삭제하거나 덮어쓰지 않는다.
  • 복원 원본의 host·port·DB명은 수동 입력을 신뢰하지 않고 서명 대상 manifest에서 읽으며, 두 SQL 파일의 크기와 SHA-256을 다시 확인한다.
  • 복원 뒤 WordPress 핵심 테이블과 Judge 기본 8개 테이블을 확인하고 증거 파일의 SHA-256을 남긴다.

R-01 개발 진입 관문

운영 인프라를 직접 다루지 않고 새 플러그인 코드를 만들기 위한 보호 조건이다.

통과
  1. 원본 코드가 기준 commit a238a8f에 고정됐다.
  2. 재구축 branch와 worktree가 원본 작업 공간과 분리됐다.
  3. 기존 runtime 파일·Route·Action·권한·메뉴·옵션·테이블 manifest와 SHA-256이 생성됐다.
  4. I-00 당시 동결 목표 GET 151개·Action 132개와 설치 중 일시 계약의 자동 검사가 통과했다. 현재 Action 목표 126개는 R-05 구현 감사 결과다.
  5. 원본 worktree와 기존 runtime이 변경되지 않았다.
  6. 운영 DB·파일·접속 정보에 접근하거나 쓰지 않았다.
  7. 사용자가 기존 코드를 이어 붙이지 않는 완전 재구축과 개발 시작을 확정했다.
