DS-14 · 메뉴 기반 상세 설계

커뮤니티 상세 설계

서비스 사용자이 게시판과 공지를 간결하게 사용하고, 문제·수업·대회·그룹 안에서는 접근 권한을 그대로 이어받은 질문과 답변을 사용할 수 있도록 설계한다. 운영자는 게시글·댓글·공지·첨부를 한곳에서 관리하되 WordPress 원본과 기능 독립성을 유지한다.

범위 경계: 사용자·역할은 Auth·Permission, 문제·수업·대회·그룹 접근은 각 소유 모듈, 홈 공지 배치는 PublicUi가 소유한다. Board는 승인된 접근 Provider와 WordPress API만 사용하고 다른 기능의 Repository나 JudgeDb를 직접 조회하지 않는다.

사용자 게시판

전체 서비스 게시판과 접근 가능한 학습 문맥의 질문을 한 목록 계약으로 제공한다.

간결한 글 흐름
1 · 찾기검색·연결 공간·최신순
2 · 작성제목·본문·첨부만
3 · 대화본문 뒤 시간순 댓글
4 · 수정작성자 편집·개정 보존
항목사용자 동작보호 규칙
목록제목·연결 공간·작성자 표시 이름·작성 시각·댓글 수를 보여 주고 제목·본문 검색, 연결 공간, 답변 여부로 필터접근할 수 없는 문맥 글과 숨김·휴지통 글은 검색 건수에도 포함하지 않음
문제 상세 노출문제 본문 아래에 최근 질문 최대 5개의 제목·답변 상태·댓글 수·갱신 시각과 질문하기·전체 질문을 표시Board ON·문제 질문 ON·문제 접근·평가 보호를 모두 통과할 때만 Section ViewModel 제공
작성전체 게시판에서는 일반 글, 문제·수업·대회·그룹 화면에서는 해당 공간 질문으로 생성화면에 문맥 종류·숫자 ID 입력란을 노출하지 않고 서버가 검증한 진입 문맥만 사용
입력제목 1~120자, 본문 1~20,000자, 허용된 첨부만 입력스크립트·폼·iframe·이벤트 속성을 제거하고 허용 HTML만 저장
수정작성자와 게시판 운영자가 제목·본문·첨부를 수정일반 작성자는 작성자·연결 문맥·고정·숨김 상태를 바꾸지 못하며 WordPress 개정을 보존
고정·숨김운영자가 중요한 글을 위에 고정하거나 운영 기준 위반 글을 숨김·복원숨김 글은 작성자에게 상태만 알리고 본문을 공개 목록에 남기지 않음
과도한 경쟁 요소 제외: 좋아요·인기 점수·사용자 등급·게시 횟수 순위를 만들지 않는다. 목록은 고정 글 뒤 최신 작성 시각을 기본으로 하며 학습자에게 필요한 검색과 답변 여부만 제공한다.

공지

서비스 전체에 전달할 안내를 게시판 대화와 분리하고 홈에도 같은 원본을 제공한다.

전체 사용자 안내
상태·표시운영 동작사용자 화면
초안 draft공지 운영자가 작성·검토하며 저장사용자 목록·홈에서 제외
예약 futureWordPress 사이트 시각을 기준으로 게시 시작 시각 지정시작 전 제외, 시각 도달 뒤 자동 게시
게시 publish중요·상단 고정, 댓글 허용 여부, 선택 종료 시각 설정중요·고정 공지를 먼저 표시하고 나머지는 게시 시각 내림차순
종료종료 시각이 지나면 목록 기본 결과와 홈에서 제외하되 관리자 검색에는 유지직접 접근은 “게시가 종료된 공지입니다”만 표시하고 본문은 운영 정책에 따라 숨김
휴지통 trash확인 화면 뒤 이동하고 복원 가능모든 사용자 화면에서 제외
  • 공지는 로그인한 전체 active 사용자를 대상으로 하며 수업·그룹별 대상 지정은 만들지 않는다. 제한된 공간 안내는 해당 문맥 게시판을 사용한다.
  • 홈에는 현재 게시 중인 공지 최대 5개와 전체 보기만 제공한다. 지속형 읽음·안 읽음 기록과 알림 수는 새 테이블 없이 만들지 않는다.
  • 공지 댓글은 전역 기본값 OFF이며 공지 운영자가 필요한 공지에서만 켠다. 게시판 기능이 꺼져도 공지와 허용된 공지 댓글은 독립적으로 동작한다.

학습 문맥 연결형 질문

Board가 다른 업무 모듈의 내부 저장소를 읽지 않고 등록형 접근 Provider를 사용한다.

선택 Provider
문맥질문·조회 조건기능 OFF·종료 동작
전체 global게시판 ON, active 로그인, 전체 글쓰기 허용Board OFF이면 게시판 메뉴·글·댓글 모두 숨김
문제 problem문제 접근 정책을 통과하고 문제 질문 기능 ON. 문제 상세에는 같은 문맥의 최근 질문 최대 5개 표시Problems OFF·숨김·삭제면 일반 사용자에게 제외. 사용자가 참여 중인 대회·평가에 포함된 문제는 종료 전까지 질문 영역·목록·상세를 모두 숨김
수업 class활성 참여자·소유 강사·공동 강사와 수업 질문 기능 ONClasses OFF 또는 참여 종료 뒤 새 글·댓글 차단, 기존 글은 권한 있는 운영자만 확인
대회·평가 contest참가자·담당자이고 대회 질문 기능 ON. 일반 참가자는 종료 뒤 작성·조회진행 중에는 담당자만 운영 목적으로 확인하고 학습자에게 숨겨 답안 공유를 방지
그룹 group활성 구성원·소유자·위임 운영자와 그룹 질문 기능 ONGroups OFF 또는 구성원 관계 종료 시 숨김. 수업·대회·전체 게시판은 정상 유지
등록 방식: Problems·Classes·Contests·Groups는 문맥 키, 대상 표시 이름, 현재 사용자의 조회·작성·운영 가능 여부만 Board의 Community_Context_Registry에 등록한다. Board의 필수 모듈 의존은 늘리지 않으며 Provider가 없으면 해당 문맥만 사용할 수 없다.
문제 상세 조립: Problems가 소유한 문제 상세 Section Registry에 Board의 Problem_Community_Section_Provider를 두 기능이 모두 켜졌을 때만 등록한다. Provider는 현재 problem_id, 숫자 사용자 ID와 최대 5개 제한을 받아 타입이 있는 ViewModel만 반환한다. Problems는 Board Service·Repository·WordPress 글을 직접 조회하지 않고 Board는 문제 상세 HTML을 만들지 않는다.
평가 우회 방지: Contests의 선택형 평가 보호 Provider가 현재 사용자와 문제의 진행 평가 관계를 판정한다. 하나라도 보호 중이면 일반 문제 상세, 게시판 필터, 직접 글 주소, 댓글과 첨부 응답에서 같은 문제 문맥을 거부한다. 담당 운영자는 승인된 운영 범위에서만 확인할 수 있다.
연결 대상 없음: 원본 대상이 삭제되거나 Provider가 더 이상 대상을 확인하지 못하면 글을 전체 게시판으로 자동 이동하지 않는다. 일반 사용자에게 숨기고 관리자 목록의 “연결 대상 없음” 필터에서 새 문맥 배정 또는 휴지통 이동을 선택한다.

댓글과 운영

학습자 댓글은 즉시 사용할 수 있게 하되 숨김·휴지통·복원으로 운영 이력을 보존한다.

익명 댓글 없음
항목권장 정책구현 계약
작성active 사용자, 접근 가능한 글, 댓글 허용 상태에서 1~5,000자 작성표시 이름과 숫자 wp_users.ID를 사용하고 로그인 아이디·이메일은 출력하지 않음
게시 방식서비스 내부 실명 계정이므로 게시판 댓글은 즉시 표시, 공지 댓글은 공지별 허용 때만 표시같은 내용의 짧은 시간 중복 등록을 거부하고 저장 뒤 같은 댓글로 이동
작성 제한사용자당 10분에 게시글 5개, 댓글 20개를 기본 상한으로 적용WordPress transient·객체 캐시를 사용하고 관리자 설정에서 더 넓게 완화하지 않음
숨김·복원운영자가 게시글·댓글을 숨기고 같은 명령으로 복원사유, 실행자 숫자 사용자 ID와 시각을 postmeta·commentmeta에 기록
댓글 삭제기존 “댓글 삭제” 명령은 영구 삭제 대신 WordPress 댓글 휴지통 이동·복원으로 사용관리 화면에서 정상·숨김·휴지통을 구분하고 DS-15 보존 정책 전에는 영구 삭제하지 않음
게시글 삭제게시판·공지 운영자가 확인 화면 뒤 WordPress 휴지통으로 이동하고 복원댓글·첨부·문맥·고정·숨김·공지 설정 관계를 함께 유지
작성자 삭제: 학습자 작성자는 자신의 게시글을 수정할 수 있지만 직접 삭제하지 않는다. 서비스 기록 보존과 대화 맥락을 위해 삭제 요청은 게시판 운영자가 확인해 휴지통으로 처리한다. 댓글은 게시 뒤 수정하지 않고 정정 댓글을 추가하도록 한다.

첨부파일

WordPress 첨부 레코드는 사용하되 로그인·문맥 권한을 우회하는 공개 파일 주소는 만들지 않는다.
