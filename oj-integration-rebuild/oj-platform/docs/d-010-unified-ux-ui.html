시각 언어가 갈라진 원인

플랫폼에 애드온용 UI 키트 문서가 없습니다. 토큰은 있지만 글자 크기·모서리 단계가 없고, 페이지 헤더·시트·토스트를 만드는 공용 API도 없습니다. 그래서 각 애드온이 자기 토큰을 새로 만들었습니다.

메뉴가 무거워진 원인

메뉴 항목 하나가 화면 하나라는 규칙만 있습니다. "추가", "삭제된 ○○" 같은 동작과 보관함이 모두 2차 메뉴가 됐고, 애드온은 하위 화면을 표현할 방법이 없어 2차 메뉴를 2~3개씩 씁니다(이름 앞에 "코드 아레나 …"를 반복).

셸로 새는 CSS

edu-games의 전역 button{} 규칙이 콘솔 버튼 전체를 파랗게 바꾸고, teaching-tools는 :root에 변수와 OS 다크 모드를 주입합니다. readcontents는 Tailwind preflight를 그대로 실어 옵니다.

잘못된 토큰 이름

oj-ml-playgrounds는 존재하지 않는 --ojp-color-border/-text/-text-muted를, oj-ai-dashboard는 정의된 적 없는 --oj-console-*를 참조합니다. 그래서 늘 fallback 색으로 그려집니다.

02

디자인 원칙: 애플 감성을 이 서비스에 옮기면

애플 감성은 파란색이나 둥근 모서리 자체보다, 내용이 먼저 보이고 장치는 물러나는 태도에서 나옵니다. 교사가 수업 중에 쓰고 학생이 태블릿으로 들어오는 이 서비스에 맞게 다섯 가지로 정리했습니다.

1. 내용이 주인공 (Deference)

배경은 옅은 회색, 표면은 흰색, 색은 강조색 하나만 씁니다. 상태 색(성공·주의·위험)은 의미가 있을 때만 씁니다. 이모지·그라데이션 배너는 화면 장식에 쓰지 않습니다.

2. 위계는 글자로 (Clarity)

큰 제목 32px·700으로 "지금 어디인지"를 한눈에 알립니다. 굵기와 회색 단계로 위계를 만들고, 선과 상자는 최소로 줄입니다.

3. 깊이는 재질로 (Depth)

상단 바와 사이드바는 반투명 블러 재질, 시트는 그림자로 띄웁니다. 테두리 대신 0.5px 구분선과 아주 옅은 그림자를 씁니다.

4. 같은 일은 같은 모양

저장하면 토스트, 되돌릴 수 없으면 시트, 하위 화면 전환은 세그먼트 컨트롤. 9개 플러그인 어디서든 같은 동작은 같은 부품으로 처리합니다.

5. 손가락과 키보드 모두

모바일 터치 영역은 44px, 데스크톱 컨트롤은 36px입니다. ⌘K(Ctrl+K)로 모든 화면을 찾고, 포커스 링은 항상 보이게 합니다.

예외: 몰입형 화면

게임 플레이, 전광판, 노트북, 편집기는 자기 아트워크를 가져도 됩니다. 다만 상단 바·버튼·시트·토스트는 공용 부품을 쓰고, 색은 다크 토큰 안에서 고릅니다.

결론플랫폼 코어는 동작과 보관함을 화면 안으로 옮기면 2차 메뉴로 충분히 표현됩니다. 2차 메뉴만으로 안 되는 것은 세 가지입니다. ① 애드온 내부 화면, ② 수업·그룹·대회 같은 객체의 하위 화면, ③ 편집기·게임 같은 몰입형 화면입니다. 이 셋은 사이드바를 3단으로 늘리지 않고, 셸이 그리는 표준 3차 내비게이션으로 처리합니다(10장).

그룹을 나눈 기준

수업은 특정 반·그룹에 묶인 일, 학습 활동은 반과 상관없이 학생이 스스로 하는 콘텐츠·실습입니다. 같은 애드온이라도 학생 메뉴와 교사 메뉴에서 같은 그룹에 놓아, 교사가 "학생은 어디서 보나"를 바로 알 수 있게 합니다.

설정을 두는 자리

교사가 바꾸는 도메인 정책(커뮤니티 설정, 제출 설정)은 그 그룹의 마지막 항목에 둡니다. 서버·키·외부 연결처럼 운영자가 바꾸는 값은 모두 운영에 둡니다. 애드온 설정(Kaggle 키, 아레나 게임 서버, ML 서버, 활동지 평가 정책)은 운영 › 애드온 설정 한 화면에 애드온별로 모읍니다.

2.2.0 구현 메모묶음은 config/console-local-nav.php로 정의합니다. 사이드바에는 대표 항목 하나만 보이고, 나머지 화면은 머리말 아래 세그먼트로, 추가 화면은 버튼으로 보입니다. 각 화면은 원래 권한 검사를 그대로 거칩니다. 애드온 설정은 2026-10-13 결정에 따라 각 애드온 메뉴의 마지막 세그먼트 "설정"에 둡니다(예: 코드 아레나 › 설정). wp-admin 설정 화면은 모두 없앴고, 사이트 관리자와 "<애드온> 설정" 권한을 받은 교사가 설정할 수 있습니다. 상세 규칙은 _notes/settings-console-brief.md.

2차 메뉴로 표현할 수 없는 것: 개선 방안

사이드바는 2단으로 고정합니다. 대신 위계를 네 층으로 나누어, 층마다 담당 부품을 하나씩 정합니다.

L1 · 사이드바

1차 그룹

아이콘 + 이름. 8개 이하. 관리자 영역은 구분선 아래.

L1.5 · 섹션 머리말

2차 묶음 표시

누를 수 없는 회색 소제목. 2차가 6개를 넘는 그룹에만 씁니다(수업, 운영).

L2 · 사이드바

2차 목적지

목록·허브 화면만 둡니다. 동작(추가)과 보관함은 두지 않습니다. 애드온은 1개만.

L3 · 페이지

로컬 내비

큰 제목 아래 세그먼트 컨트롤(5개 이하) 또는 탭 바(6개 이상). 셸이 그립니다.

① 표준 로컬 내비 (3차)

애드온이 하위 화면 목록을 매니페스트에 선언하면 셸이 세그먼트를 그리고, 사이드바에서는 부모 항목을 계속 강조합니다. oj-ai-dashboard의 4겹 내비, ML의 작업 내비, 아레나의 h1+small 패턴이 모두 이 하나로 바뀝니다. 수업·그룹·대회 상세의 ojp-tabs도 같은 부품으로 맞춥니다.

② 경로 표시 + 조상 강조

상단 바에 "수업 › 수업 › 2학년 3반 › 참여자"를 자동으로 그립니다. 지금 ConsoleShell은 메뉴 키가 정확히 같을 때만 현재 항목을 강조하므로, 하위 화면에 들어가면 사이드바에서 위치가 사라집니다. 주소 접두사로 조상을 찾도록 바꿉니다.

③ 몰입형 레이아웃

편집기·노트북·게임·전광판은 사이드바를 접고 얇은 상단 바 [‹ 코드 아레나 · 제목 · 행동]만 남깁니다. 읽기자료 편집기가 !important로 셸을 덮어쓰던 것과 ML의 .oj-ml-wide-host 주입을 대신합니다.

④ ⌘K 찾기 (명령 팔레트)

1·2차 메뉴, 로컬 내비, 최근 연 수업·문제, 자주 쓰는 동작("문제 추가", "재채점")을 한 입력창에서 찾습니다. 깊은 화면(교실 도구의 사다리, AI 사용량)도 메뉴를 늘리지 않고 바로 갈 수 있습니다.

⑤ 허브 화면

교실 도구 8개, 교육 게임 13개처럼 개수가 많고 대등한 화면은 메뉴로 펼치지 않습니다. 앱 타일 허브 + "최근 사용" 줄로 보여 주고, 각 도구 화면에는 경로와 뒤로 가기가 자동으로 붙습니다.

⑥ 홈의 바로가기

대시보드 바로가기 블록은 메뉴 이름을 그대로 쓰게 맞춥니다(지금 "운영 설정" 바로가기는 개요 화면으로 가서 같은 이름의 메뉴와 어긋납니다).

Addon API v1.3 제안

// 1) 콘솔 메뉴: icon을 실제로 쓰고, anchor를 허용 목록으로 제한, 애드온당 1개
$b->consoleMenu(new AddonConsoleMenuDefinitionV1(
    key: 'main', label: '코드 아레나',
    anchor: 'learning_support',   // classes | problems | learning_support 만 허용
    route: '/', capability: Capabilities::TEACH, order: 20, icon: 'swords',
    section: 'tools'            // 선택: 그룹이 정한 섹션 키
));

// 2) 로컬 내비(3차): 셸이 세그먼트·경로·조상 강조를 그린다
$b->consoleLocalNav('main', [
    ['key' => 'sessions', 'label' => '수업 게임', 'route' => '/'],
    ['key' => 'bank',     'label' => '문제은행',  'route' => '/bank'],
    ['key' => 'records',  'label' => '경기 기록', 'route' => '/records'],
]);

// 3) 설정은 메뉴가 아니라 운영 › 애드온 설정에 자동 등록
$b->consoleSettings(route: '/settings', capability: Capabilities::SETTINGS);

// 4) 페이지 응답: 레이아웃과 머리말을 셸에 넘긴다
return AddonPageResponseV1::page(
    header: new PageHeader(title: '문제은행', subtitle: '코드 아레나', actions: [...]),
    body: $html, layout: 'standard'   // standard | wide | immersive
);

v1 매니페스트는 그대로 받아 주고, 메뉴가 2개 이상인 애드온은 첫 항목만 사이드바에 두고 나머지를 로컬 내비로 자동 변환합니다. 진단 화면에 "v1.3으로 옮기면 좋은 항목"을 경고로 표시합니다.
