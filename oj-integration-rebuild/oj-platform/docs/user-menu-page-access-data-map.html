메뉴와 권한 분리

메뉴가 보이지 않는다고 직접 주소가 허용되거나 차단되는 것은 아니다. 아래 표의 “공개”는 로그인한 사용자 사이의 공개 범위다. 비로그인 예외가 아닌 모든 페이지는 먼저 active 로그인 상태를 확인한 뒤 기능·공개 범위·본인·참여·담당 관계를 검사한다.

1차·2차 메뉴 데이터

내부 항목은 Public Menu Manifest의 안정된 메뉴 키와 Route 키를 기준으로 단계·부모·표시 이름·대상·순서·모바일 위치·사용 여부를 저장한다. 외부 메뉴는 별도 테이블을 만들지 않고 같은 revision 봉투에 링크 키·단계·1차 부모 키·표시 이름·정규화 URL·표시 대상·순서·사용 여부를 저장한다. 외부 페이지 본문·제목·아이콘·미리보기와 방문 기록은 저장하지 않는다.

페이지·접근 권한·사용 데이터

테이블 속성은 화면 표시와 접근 판정에 직접 쓰는 핵심 값만 기록한다.

“사용 저장소”는 해당 화면이 읽거나 쓰는 원본이다. 쓰기는 반드시 소유 모듈의 Service·Repository를 통하고, 다른 기능의 화면은 Read Provider만 사용한다. 플랫폼 42개 테이블의 전체 열·타입·키·보존 설명은 D-008을 단일 원본으로 사용한다.

공통 접근 판정 순서

메뉴 표시와 직접 주소 접근에 같은 기준을 사용하되 직접 주소에서는 모든 조건을 다시 검사한다.

단일 규칙
  1. 해당 기능이 켜져 있는지 확인한다.
  2. 페이지가 요구하는 로그인 상태를 확인한다.
  3. 공개 범위 또는 본인·수강·참가·구성원 관계를 확인한다.
  4. 강사 관리 동작은 전역 capability가 있으면 전체 범위를 허용하고, 없으면 대상별 소유·담당 역할이 허용한 작업만 제공한다.
  5. 목록과 보고서는 허용된 대상 ID로 조회 범위를 제한한다.
  6. 저장·삭제·가입·제출 같은 쓰기 요청은 같은 권한 정책과 작업별 nonce를 다시 확인한다.
사용자 ID: WordPress와 동일하게 내부 키와 로그인 아이디를 분리한다. 모든 일반 페이지와 플랫폼 테이블의 user_id는 숫자 wp_users.ID이고 로그인 아이디는 문자열 wp_users.user_login이다.
