검증 manifest

검증 ZIP의 지위: production artifact가 아니다. 공식 스크립트의 -AllowDirty를 사용했으며 향후 clean build와 충돌하지 않도록 dist/verification에 분리했다.

업그레이드 절차

  1. clean tree에서 공식 2.0.0-dev.33 패키지를 생성하고 manifest의 source_dirty=false를 확인한다.
  2. 플랫폼 패키지를 교체한다. 이번 API 변경을 위한 DB migration은 실행하지 않는다.
  3. 기존 1.0 애드온의 등록·Route·Menu·AI 4인자 선언 회귀를 확인한다.
  4. 1.1 소비 애드온은 manifest에서 >=1.1.0 <2.0.0을 요구한다.
  5. catalog accepted와 Runtime readiness를 각각 확인한다.

롤백 절차

  1. API 1.1을 요구하는 애드온을 먼저 비활성화한다.
  2. OJ Platform 코드 패키지를 dev.32로 되돌린다.
  3. 이번 변경에는 DB migration이 없으므로 schema rollback을 실행하지 않는다.
  4. 애드온 소유 oj_ai_* 데이터는 보존하며 플랫폼이 읽거나 수정하지 않는다.
  5. 1.1 애드온을 활성 상태로 둔 채 플랫폼만 1.0으로 내리는 조합은 금지한다.

남은 배포 작업

  1. development-c-28-addon-api-v1-contract.html과 development-c-28-addon-extension-api.html 갱신을 review·commit한다.
  2. -AllowDirty 없이 공식 release script를 다시 실행한다.
  3. clean manifest의 commit, SHA-256, bytes, entries를 이 문서와 changelog에 치환한다.
  4. AI 평가 애드온 G1에서 Manifest·Bridge·두 shell 인수 검사를 실행한다.
