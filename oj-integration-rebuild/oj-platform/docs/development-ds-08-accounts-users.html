DS-08 · 메뉴 기반 상세 설계

계정·사용자 상세 설계

서비스 사용자가 처음 로그인하는 순간부터 가입, 기존 계정 전환, 프로필과 동의, 사용자 운영자의 생성·일괄 등록·비활성화·목록 기반 비밀번호 초기화까지 하나의 WordPress 사용자 원본과 같은 권한 계약으로 정리한다.

전체 순서에서의 위치: 이 문서는 전체 설계·개발 순서의 DS-08이다. DS08-Q01~Q08과 비로그인·정책, 프로필·내 계정, 관리자 사용자 시안을 기준으로 별도 재구축 작업 트리의 Auth·PublicUi·계정 관리 코드를 R-04에서 구현했다. 운영 사용자 데이터 전환과 Legacy Reader 제거는 I-09 승인 전까지 수행하지 않는다.

가입·약관·법정대리인 동의

가입은 WordPress 계정을 먼저 만들고 Auth 확장 데이터를 연결한다.

명시적 동의
비로그인 예외: /login, 가입 기능이 켜진 /register, 비밀번호 복구·재설정 화면 상태, 유효한 법정대리인 동의, 이용약관·개인정보·저작권·이메일 수집 거부 문서만 로그인 전에 접근할 수 있다. 그 밖의 모든 OJ HTML 페이지는 active 플랫폼 사용자를 요구한다.
  1. 가입 OFF이면 /register는 404로 처리하고 로그인 화면의 가입 동작도 숨긴다.
  2. 로그인 아이디·이메일·비밀번호·표시 이름은 WordPress 규칙으로 검증하고, 소속·생년은 Auth 프로필 규칙으로 검증한다.
  3. 현재 활성 필수 문서의 정확한 document_id와 version에 동의해야 하며 체크박스만 저장하지 않는다.
  4. 설정한 기준 나이 미만이면 계정 생성 전에 법정대리인 요청을 완료한다. 토큰 원문과 확인 코드는 저장하지 않고 해시와 만료를 저장한다. 전용 동의서의 ID·버전·내용 SHA-256, 동의 시각·확인 방법과 법정대리인이 확인한 관계를 요청에 연결한다.
  5. WordPress 계정 생성 뒤 user_profiles, 기본 user_preferences, 동의 사건 연결이 실패하면 로그인 세션을 만들지 않고 보상·재개 절차로 이동한다.
  6. 가입 기본 역할은 허용 목록에서 하나만 선택한다. 역할이 사라졌거나 위험 권한을 포함하면 저장·가입을 차단한다.
  7. 자동 승인은 모든 필수 동의와 법정대리인 확인이 끝난 가입만 active로 만들고 세션을 생성한다.
  8. 수동 승인은 가입 완료 계정을 pending으로 만들고 세션을 생성하지 않는다. 정확한 자격 증명으로 다시 로그인해도 승인 대기 안내만 표시한다.
  9. oj_approve_user_registrations가 있는 가입 승인 담당자만 사용자 목록의 승인 대기 필터에서 pending을 active로 바꿀 수 있다. 사용자 수정·가입 정책·그룹 관리 권한은 이를 대신하지 않는다.
  10. 승인은 전용 oj_console_approve_user_registration POST만 사용한다. 사용자별 nonce, 전용 capability, 현재 pending, 필수 동의·법정대리인 확인과 원본 버전을 실행 직전에 다시 검사한다.
  11. 승인 전용 목록에는 로그인 아이디, 표시 이름, 이메일, 서비스, 가입 시각, 필수 동의·법정대리인 확인 완료 여부만 표시한다. 역할·비밀번호·제출·학습 기록·전체 프로필과 편집 링크는 제공하지 않는다.
  12. 승인 방식 변경은 이후 가입부터 적용하며 기존 pending 계정을 자동 승인하지 않는다. 관리자 생성·CSV 등록·기존 계정 전환은 공개 가입 승인 방식의 대상이 아니다.

법정대리인 동의서 연결

항목구현 계약
문서 관리/oj-console/agreements에서 법정대리인 동의서를 선택하고 공통 HTML 편집기로 게시한다. 키 guardian-consent는 서버에서 결정한다. 일반 공개 정책 4종의 경로는 유지하며 전용 문서를 사용자 가입·재동의 체크박스에 추가하지 않는다.
확인 화면기존 /guardian-consent/{token}에서 가입자 이메일, 법정대리인 이름·이메일, 요청에 연결된 동의서 전체 본문·버전을 표시한다. 부모 또는 법적으로 지정된 후견인 관계와 본인이 법정대리인이라는 동의 의사를 확인한다. 응답은 캐시·검색 수집·referrer 전달을 막는다.

정지·비밀번호·삭제

  • 이용 정지는 OJ 접근만 막고 WordPress 계정과 데이터를 삭제하지 않는다. 해제하면 다음 요청부터 다시 접근한다.
  • 비밀번호 변경과 초기화는 WordPress API만 사용하며 기존·새 비밀번호와 재설정 키를 로그·Jobs·감사 메타데이터에 남기지 않는다.
  • 본인 계정 삭제는 재인증, 영향 확인, 활성 역할·소유 대상 확인 뒤 Auth 소유 user_account_erasure Jobs를 등록하고 세션을 폐기한다. 수업·대회·그룹·문제 소유권이 남으면 작업 등록 전 차단한다.
  • 익명화 Jobs는 실행 직전 대상을 다시 확인하고 로그인 차단, 플랫폼 참조 익명화, Judge 사용자 문자열 익명화, WordPress 개인정보 제거, 고아 참조 검증을 순서대로 완료한다. 되돌릴 수 없는 단계 전까지만 취소할 수 있고 이후 실패는 마지막 미완료 단계부터 앞으로 완료한다.
  • 삭제 완료는 숫자 ID의 참조 무결성을 유지하는 익명화 절차다. deleted_users에는 자격 증명이 없는 최소 스냅샷·행위자·시각·사유만 남기며 Jobs 단계가 성공하기 전에는 완료로 표시하지 않는다.

단건·선택 일괄 초기화 계약

  1. 전역 작업은 /oj-console/users, 그룹 작업은 /oj-console/groups/{group_id}/members에서 행 명령 또는 체크박스 선택으로 실행한다. 사용자 상세 화면에는 초기화 명령을 중복 배치하지 않는다.
  2. 한 요청은 최대 100명을 처리한다. 입력된 숫자 user_id를 중복 제거한 뒤 실행 직전에 현재 행 범위, active 상태, WordPress 대상 편집 권한과 그룹 구성원·운영자 상태를 대상별로 다시 검사한다.
  3. 전역 작업은 oj_edit_users와 WordPress 대상별 edit_user 판정을 모두 통과해야 한다. 행위자 본인은 내 계정에서 변경하고 사용자 목록 초기화 대상에서는 제외한다.
  4. 그룹 작업은 소유자·활성 위임 운영자만 실행하며 같은 그룹의 승인된 일반 구성원만 허용한다. 그룹 소유자·위임 운영자·전역 계정 관리자·행위자 본인과 그룹 밖 사용자는 제외한다.
  5. 성공한 대상은 강한 무작위 임시 비밀번호로 WordPress 비밀번호를 교체하고 기존 로그인 세션을 모두 폐기하며 user_profiles.must_change_password=1을 기록한다. 임시 비밀번호로 인증한 사용자는 다른 OJ 화면보다 비밀번호 변경 화면을 먼저 완료한다.
  6. 임시 비밀번호는 성공 응답에서 한 번만 표시하고 새로고침·화면 이탈 뒤 복구하지 않는다. WordPress 옵션·PlatformDb·Jobs·로그·감사 사건·CSV 결과에는 원문을 저장하지 않으며 분실하면 다시 초기화한다.
  7. 감사 사건에는 행위자·범위·대상 user_id·시각·성공 또는 안전한 실패 코드만 남긴다. 일부 실패가 있어도 성공 항목을 되돌리지 않고 항목별 결과를 같은 화면에 표시한다.

CSV 작업 계약

  1. UTF-8 CSV를 업로드하면 열 이름·행 수·중복·WordPress 로그인·이메일·역할·그룹 범위를 먼저 검증하고 생성 전 미리보기를 보여 준다.
  2. 확정한 대상 Snapshot과 암호화된 payload_ref로 user_csv_import를 등록하며 사용자 후보 1명이 Jobs 항목 1개다.
  3. 원본 CSV와 초기 비밀번호는 Jobs 테이블·이벤트·결과 파일에 넣지 않는다. 암호화 Form Draft에서 항목 실행 때 읽고 성공·취소 시 즉시 삭제하며, 실패·확인 필요 항목은 재시도를 위해 최대 24시간만 보존한다.
  4. 기존 WordPress 로그인은 자동 병합하지 않는다. 새 계정 생성과 기존 계정의 그룹 추가를 미리보기에서 서로 다른 작업으로 표시하고 명시적으로 선택한다.
  5. 결과 파일은 행 번호·로그인 아이디·성공 여부·사용자용 사유 코드만 포함하고 비밀번호·재설정 키·내부 예외는 제외한다.

확정 항목

2026-07-23 확정한 여덟 항목을 유지하고, 2026-07-25 지시에 따라 Q05·Q06의 초기화 위치·일괄 처리·이메일 비의존 계약을 보강했다.

보강 반영
  1. DS08-Q01 · 사용자 원본: 숫자 wp_users.ID를 user_id, 문자열 user_login을 로그인·Judge 어댑터 값으로 유지하고 중복 사용자 원본과 영구 Judge 매핑을 제거한다.
  2. DS08-Q02 · 로그인·전환: WordPress 계정을 우선 인증하고 계정이 없을 때만 정확한 Judge 후보와 비밀번호를 확인한 뒤 사용자 동의·최종 재검증·단계 완료 후 로그인한다.
  3. DS08-Q03 · 가입·동의: WordPress 계정, Auth 프로필·환경설정, 현재 문서 버전 동의와 필요한 법정대리인 확인을 하나의 완료 계약으로 처리한다. 가입 승인은 기본 manual 또는 automatic으로 설정하고 auto_link_judge_user를 제거한다.
  4. DS08-Q04 · 프로필·계정: 로그인 아이디는 불변으로 두고 본인 설정·공개 범위·이용 정지·재설정·소유권 이관 뒤 익명화 절차를 구분한다.
  5. DS08-Q05 · 관리자 작업: 사용자 생성·수정·가입 승인·역할·정지·삭제 권한을 분리한다. 전용 oj_approve_user_registrations만 수동 가입을 승인하고 CSV는 Jobs 항목별 실행한다. 비밀번호 초기화는 사용자 목록의 행 또는 선택 항목에서 최대 100명까지 처리하며 이메일이 없어도 임시 비밀번호를 한 번 제공하고 다음 로그인 변경을 강제한다.
  6. DS08-Q06 · 그룹 범위: 그룹 소유자·위임 운영자는 전역 사용자 메뉴 없이 자기 그룹 구성원 목록에서 승인된 일반 구성원 일괄 등록과 단건·선택 일괄 비밀번호 초기화를 수행한다. 그룹 소유자·운영자·전역 계정 관리자·본인과 그룹 밖 사용자는 대상에서 제외한다.
  7. DS08-Q07 · 코드·데이터: 두 대형 Controller와 통합 Repository를 화면·Application·Repository·Adapter로 분리하고 D-008 Auth 7개 무접두어 테이블만 사용한다.
  8. DS08-Q08 · 검증·이전: 비로그인 예외 목록, 자동·수동 승인, 승인 대기 로그인 차단, 전환 동시성·실패 복구, 역할 상승, 그룹 범위, 민감 정보와 반응형 UI를 검증하고 일반 Auth 코드의 oj_user_id를 제거한다. 전환 Adapter 종료와 기존 데이터 최종 정리는 DS-15/I-09 관문에서 수행한다.
구현 판정: R-04는 Auth 7개 스키마·Repository, WordPress 숫자 ID, 로그인 우선 셸, 가입·자동/수동 승인·동의·복구, 명시적 Judge 계정 전환, 사용자·역할·CSV·전역 비밀번호 초기화를 실제 코드와 자동 검사로 완료했다. CSV 확정 요청은 후보별 암호화 입력과 user_csv_import 작업만 등록하고, 계정 생성·현재 권한·역할 재검사는 Worker Handler가 항목별로 수행한다. 사용자·프로필·환경설정 생성은 같은 DB 트랜잭션으로 묶으며, 작업 결과 저장 직전 중단으로 항목이 다시 실행되면 로그인·이메일·비밀번호·표시명·역할·프로필이 모두 같은 기존 결과만 완료로 인정해 중복 계정을 만들지 않는다.
