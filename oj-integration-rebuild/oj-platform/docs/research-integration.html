기존 학생 수준 평가를 활용하는
그룹별 수업 연구

구현 위치: oj-integration-rebuild/oj-platform · 작업 기준 버전 2.0.0-dev.102

소스 구현과 로컬 검증 완료. 운영 사이트 배포·설치는 수행하지 않았다.

새 연구 설계가 추가되었다.

사용자의 개정 연구 방향인 교육자료 구축과 AI 피드백·문제 추천 시범 적용은 개정 연구 설계와 화면에서 확인한다. 이 페이지는 이전 비교 조건과 현재 로컬 구현 범위를 기록한 문서다. 새 설계가 구현·배포되었다는 의미는 아니다.

기존 학생 수준 평가는 선행 연구 결과물로 그대로 사용한다.

LearnerLevelCalculator, LearnerLevelService, LearnerLevelProfile의 계산식·가중치·수준 기준을 수정하지 않았다. 이번 기능은 그 결과를 활용한 피드백의 수업 효과를 연구하기 위한 운영·자료 수집 모듈이다. 기존 평가의 재개발이나 타당성 재검증을 필수 절차로 추가하지 않는다.

1. 통합 구조와 비교 조건

별도 애드온 설치 없이 플랫폼 내부 모듈로 제공한다. 기존 그룹, 계정·권한, 제출, Jobs, AI 설정, 스키마·설치 기능과 연결한다. 외부 채점엔진의 테이블을 직접 참조하지 않는다.

항목A · 수준 반영B · 공통 피드백
수업 문제·검사·모델·공통 지침동일한 연구 계획으로 고정

주요 결과지표AI 도움 없이 치른 사후검사의 두 평가자 평균 점수

그룹마다 별도의 연구를 만들 수 있다. 하나의 연구에 여러 그룹을 연결하면 같은 계획과 진행 단계를 공유한다. 한 학생은 동시에 한 연구에만 참여한다. 그룹·초기 수준별로 사전점수가 비슷한 학생을 짝지어 A/B를 무작위 배정한다. 홀수로 남은 학생은 별도로 무작위 배정하므로 전체 인원이 정확히 반반이 되지는 않을 수 있다. 배정 후 다시 추첨할 수 없다.

2. 시작과 운영 순서

  1. 변경 소스를 시험 사이트에 반영하고 플랫폼의 기존 설치·스키마 절차로 research_studies, research_participants, research_records 테이블을 준비한다. 기존 설치·스키마 점검을 통과한 환경에서 시작한다.
  2. /oj-console/settings/features에서 그룹 수업 연구를 켠다. 기본값은 꺼짐이며 그룹·AI 피드백 기능이 필요하다. 제출 코드 전송이 허용된 AI 연결을 준비한다. 연구에는 자동 대체 모델을 사용하지 않는다.
  3. OJ Console의 학습 지원 → 수업 연구(/oj-console/research)에서 연구를 만든다. 대상 그룹, 운영자와 다른 평가자 2명, 차시별 학습 문제·독립 확인 과제, 사전·사후·지연 과제, 공통 AI 지침, 분석계획, 동의 문서 번호를 입력한다. 평가자는 Console 이용 권한이 있는 계정을 지정한다.
  4. 연구 상세에서 계획을 확인하고 동의한 학생만 선택해 초기 자료 고정을 실행한다. 저장된 기존 수준 결과를 우선 사용하며 결과가 없으면 기존 평가 서비스를 호출한다. 수준과 문제 내용 해시, AI 연결, 공통 지침을 이 시점에 고정한다.
  5. 사전검사를 열고 학생은 /research에서 코드·풀이 설명을 최종 제출한다. 평가자는 /oj-console/research/rating에서 독립 채점한다. 검사 종료 후 미응시 사유를 기록하고 조건을 배정한다.
  6. 교사가 첫 풀이 → 피드백 수정 → 혼자 확인을 전환한다. 학생의 학습 문제 링크·검사 입력이 현재 단계에 맞게 바뀐다. 각 단계의 수업 시간은 교사가 공통으로 운영한다.
  7. 마지막 차시 뒤 사후검사와 설정한 간격 뒤 지연검사를 실시한다. 지연 간격 기본값은 14일이다. 두 평가자 채점과 결측 사유를 완료한 뒤 자료를 확정·보관하고 내려받는다.

초기 수준 고정 → 사전검사·채점 → 배정 → [첫 풀이 → 피드백 수정 → 독립 확인] × 차시 → 사후 → 지연 → 확정·보관

모든 연결 그룹의 관리 권한이 있는 운영자가 연구를 관리한다. 학생은 자신의 활동을 보고 평가자는 가림 답안과 공통 루브릭을 본다. 학생명과 연구번호의 연결은 운영자 원장에만 표시한다.

3. 기존 평가와 AI 처리 경계

독립 검사 답안과 점수는 연구 테이블에 별도로 저장한다. 연구 점수로 기존 학생 수준을 덮어쓰지 않고 독립 답안을 일반 제출 이력에 섞지 않는다. 일반 수업 제출에 대한 기존 평가 서비스의 동작은 유지한다.

단계학생 AI 처리
사전·사후·지연 / 혼자 확인 / 첫 풀이 / 일시중단제출 AI 생성·응답 조회 제한. 대기 작업과 늦은 응답에도 단계 검사 적용
피드백 수정현재 차시의 첫 풀이 시작 이후 제출한 연구 문제만 허용. 고정 조건과 한도 적용
차시 사이·지연검사 대기 등일반 AI는 기존 설정에 따름. 연구 조건에서 만든 이전 캐시는 일반 피드백으로 재사용하지 않음

플랫폼 AI 게이트웨이를 이용하는 다른 애드온의 AI 실행도 연구 활동 중 요청자 기준으로 제한한다. 애드온이 독자적으로 저장·노출하는 자료나 외부 AI까지 통제하는 시험 보안 기능은 아니다.

모델 연결이나 연구 문제 내용이 바뀌면 새 피드백 생성을 거부한다. 공통 지침은 완성 정답 코드 금지, 최대 3개 힌트, 1,600자 이내를 요청한다. 저장 전에는 출력 형식과 JSON 8,000바이트 상한을 검사한다. 의미상 정답 노출·오류 설명·실제 수준 차이는 운영자가 생성 응답을 열어 확인한다.

4. 검사·채점·연구자료

독립 검사는 코드·설명 제출 후 사람이 평가하는 방식이며 자동 실행형 OJ 시험 채점과는 아직 연결하지 않았다. 문제 이해 20점, 절차 설계 20점, 코드 구현 40점, 수정 및 설명 20점의 두 평가자 평균을 사용한다. 최종 답안과 저장한 개별 점수는 수정할 수 없다. 예비 적용에서 과제와 채점 기준을 확인한다.

가림 채점 화면에는 이름·초기 수준·A/B·다른 평가자의 점수가 없다. 학생이 답안에 직접 쓴 자기소개까지 자동 익명화하지는 않으므로 이름·학번을 넣지 않도록 안내한다. 차시별 독립 확인 답안도 같은 채점함으로 전달된다.

자료포함 내용범위
CSV 결과표가명 연구번호·그룹, 원배정, 기존 초기 수준·점수·정책 버전, 사전·사후·지연 점수와 결측 사유결측은 빈 셀. 실제 0점과 구분
JSON 연구자료검사·분석계획, 결과표, 최초 배정·철회·삭제 인원수, 개별 평가 점수, 제출 관찰, 피드백 생성·전달 기록실명·계정번호·독립 답안 코드·AI 응답 전문은 기본 내보내기에서 제외
운영자 응답 확인최근 생성 응답 20개, 원배정과 실제 적용 정책운영 권한으로 열람. 철회 자료 제외

제출 기록은 피드백 수정 종료 때 기존 제출 조회 계약으로 수집한다. 처리 중인 제출은 그 상태로 기록하며 최종 정답 여부로 단정하지 않는다. generated는 유효 응답 생성, delivered는 서버의 응답 조회·제공 기록이다. 학생이 실제 읽은 시간이나 이해 정도를 측정한 값은 아니다.

미응시는 해당 검사 종료 뒤 사유를 기록한다. 원배정을 유지하며 동의 철회 자료는 향후 내보내기에서 제외한다. 계정 삭제 시 참여 연결과 답안·평가·노출 기록을 제거하고 최초 배정 인원수와 삭제 수를 남긴다. 책임자·평가자는 담당 연구 종료·보관 후 기존 계정 삭제 절차를 이용한다.

5. 저장·오류 처리

연구 전용 InnoDB 테이블 3개를 플랫폼 스키마와 이전 계획의 신규 생성 항목에 등록했다. 단계 변경은 트랜잭션·행 잠금·버전 비교로 보호한다. 고유 키로 중복 기록을 방지하며 답안·개별 점수를 다른 내용으로 덮어쓰지 않는다. 활성 연구의 기능 끄기를 제한하고 저장소를 확인할 수 없으면 연구 AI 접근을 허용하지 않는다.

기존 인증·nonce 검증과 그룹 권한을 적용한다. 다운로드는 권한 검사를 거쳐 비공개·캐시 금지 응답으로 제공한다. 페이지·Jobs·오류 보고는 기존 플랫폼 흐름에 연결했다.

6. 검증과 이번 구현 범위

  • 플랫폼 빠른 검사 52개 통과: 아키텍처·모듈 계약·레지스트리·기존 기능·설치·AI·화면 흐름.
  • 연구 서비스 46개, AI 작업 통합 17개, 연구 화면 14개 단언 통과: 수준 고정·원배정·가림 채점·한도·캐시·늦은 응답·권한·내보내기. 외부 모델 호출은 합성 응답으로 대체한 검사다.
  • 실제 MariaDB·WordPress DB 계층 검사 27개 통과: 별도의 합성 자료 DB에서 생성·중복 참여·변경 충돌·롤백·계정 삭제 검증. 시험 DB 서버 종료 완료.
  • 실제 화면 핸들러로 만든 교사·학생·평가자 화면을 브라우저에서 확인했다. 390px 화면의 입력·원장 너비와 채점 입력 정렬을 확인했다.
  • 기존 수준 계산기·서비스·프로필의 SHA-256은 작업 시작 전과 동일하다.

포함: 그룹 내 학생 배정, 고정 초기 수준, 여러 그룹의 공통 단계, 교사 수동 진행, 코드·설명 기반 독립 검사, 두 평가자 평균, CSV/JSON 수집.

별도 확장: 학급 전체 단위 배정, 한 연구 안에서 그룹별 비동기 진행, 자동 실행형 독립 시험, 설문·면담, 자동 통계 분석·효과 결론.

운영 설치와 실제 수업·외부 모델 예비 적용은 남아 있다. 이 개발 검증 자체는 교육적 효과 검증을 의미하지 않는다. 동형 과제와 수업 운영·분석계획은 연구자가 확정한다.
