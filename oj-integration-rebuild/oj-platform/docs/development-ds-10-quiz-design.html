DS-10 · 상세 설계 3/4

퀴즈 상세 설계

퀴즈는 문제에 연결된 학습 콘텐츠지만 목록·상세·응시·결과·통계를 독립 화면으로 제공한다. 학습자별 원문 스냅샷을 만들지 않고 게시 시점의 공유 불변 버전을 참조한다.

사용자 화면 5개 관리자 화면 4개 공유 불변 버전 학습자별 원문 복제 0건
개요 페이지 계약 문제 콘텐츠 퀴즈 관리 도구·구현

공유 버전과 사용자 시도

게시 콘텐츠와 학습 결과를 분리해 저장한다.

5개 테이블
테이블저장 단위핵심 속성변경 규칙
quiz_revisions문제별 초안·게시 버전problem_id, 상태, 버전, content_hash, 보호 설정, 게시 시각게시 뒤 불변. 수정은 새 버전 생성
quiz_questions버전별 문항revision_id, 안정된 question_key, 문구, 배점, 정렬게시 버전 직접 수정 금지
quiz_choices문항별 선택지안정된 choice_key, 문구, 정답 여부, 정렬게시 버전 직접 수정 금지
quiz_attempt_summaries사용자·문제별 응시숫자 user_id, quiz_revision_id, 상태, 시작 멱등 키, 점수, 부모 시도진행 슬롯 1개, 최종 제출 한 번 확정
quiz_attempt_items응시 문항별 학습자 답안문항·선택지 키, 학습자 답안, 정오, 받은 점수시도가 참조한 버전 기준으로 저장
핵심: 학습자가 응시할 때 문항·선택지 원문을 복제하지 않는다. 시도는 quiz_revision_id를 참조하고 학습자 답안과 결과만 저장한다.

응시 흐름

조회와 상태 변경을 분리하고 재전송·동시 요청에도 한 번만 저장한다.

POST 2개
단계진입점서버 재검증저장·이동
상세 조회GET /quizzes/{problem_id}로그인, 퀴즈 활성, 문제 접근, 응시 횟수안내와 본인 이력만 읽고 상태를 만들지 않는다.
응시 시작POST oj_quiz_start_attempt문제별 nonce, 현재 게시 버전, 활성 문항, 시작 멱등 키현재 버전을 참조하는 in_progress 요약 1행만 만들고 응시 화면으로 이동한다.
응시 조회GET /quizzes/{problem_id}/attempt현재 사용자 소유의 진행 시도시도가 참조한 게시 버전의 문항·선택지를 읽기만 한다.
최종 제출POST oj_quiz_submit_attempt시도 nonce, 소유자, 문제 일치, 허용 답안, in_progress 상태답안·정오·점수와 graded 상태를 한 트랜잭션에서 한 번 확정한다.
결과·통계결과·통계 GET결과는 본인 시도, 통계는 공개 범위참조 버전과 학습자 답안을 읽는다. 재채점이 있으면 원래 결과와 공식 결과를 구분한다.
식별자 전달: 상세 Renderer가 암호학적으로 안전한 64자 멱등 키와 problem_id에 묶인 nonce를 시작 폼에 넣는다. 성공 뒤 Controller는 저장된 문제·시도 ID로 Route Registry URL을 생성한다.
GET 쓰기 금지: 목록·상세·응시·결과·통계 GET은 시도 생성, 답안 저장이나 채점을 수행하지 않는다. 이미 제출된 시도를 다시 POST하면 원본을 바꾸지 않고 같은 결과로 이동한다.

게시 버전 보호와 일괄 재적용

보호를 풀어도 이전 버전과 학습자 결과를 직접 덮어쓰지 않는다.

기본 보호
선택신규 응시진행 중 응시완료 결과
게시 버전 보호새 버전 사용시작 당시 버전 유지원래 버전·결과 유지
보호 해제 · 진행 시도 재적용새 버전 사용선택 대상을 superseded로 보존하고 횟수 차감 없는 대체 시도 생성변경 없음
보호 해제 · 완료 결과 재채점새 버전 사용관리자 선택에 따름안정된 문항·선택지 키가 모두 대응할 때 원본과 연결된 regrade 결과 생성
  1. 관리자는 초안을 편집하고 항상 새 불변 버전을 먼저 게시한다.
  2. 담당 범위 관리자는 진행 중 응시 재시작만 선택할 수 있다.
  3. 완료 결과 일괄 재채점은 전역 oj_manage_quizzes 보유자에게만 표시한다.
  4. quiz_revision_reapply Job은 대상 목록을 고정하고 Worker 실행 직전 권한·버전·안정 키 대응을 다시 확인한다.
  5. 같은 원본·대상·새 버전 조합을 재실행해도 대체 기록을 중복 생성하지 않는다.

저장 공간과 읽기 부하

학습자 수에 비례해 문제 원문이 복제되지 않도록 한다.

공유 캐시
상황쓰기읽기·캐시정리
관리자 게시문항·선택지 전체를 새 불변 버전으로 한 번 저장quiz_revision_id와 content_hash로 캐시참조 있는 이전 버전 유지
학습자 응시 시작시도 요약 1행공유 게시 버전 읽기장기 방치 진행 시도는 정책에 따라 종료
학습자 제출답한 문항 수만큼 답안 행과 요약 갱신참조 버전으로 채점완료 결과는 보존 정책 유지
초안 폐기추가 쓰기 없음공개 요청에서 읽지 않음참조 없는 폐기 버전·버려진 초안만 보존 정책으로 정리

본인 학습 결과와 관리자 분석 범위를 분리한다.

문제 Context 재사용

문제 소유자·공동 편집자담당 문제의 퀴즈 초안·게시, 진행 시도 재적용담당 밖 퀴즈, 완료 결과 일괄 재채점
전역 퀴즈 관리자전체 퀴즈, 통계, 승인된 완료 결과 재채점게시 버전·원래 시도·원래 결과 직접 수정
통계 기준: 버전별 집계를 기본으로 한다. 같은 question_key의 교차 버전 비교는 관리자가 명시적으로 선택할 때만 제공하며 학습자에게 다른 사용자의 답안은 공개하지 않는다.

화면 구성

서로 다른 작업을 한 페이지 탭으로 숨기지 않고 독립 주소로 제공한다.

시안 2종
사용자관리자
목록: 검색, 상태, 문제 연결목록: 초안·게시 상태, 응시 현황
상세: 문항 수, 배점, 조건, 본인 이력생성: 대상 문제 선택, 기본 설정
응시: 진행 상태, 문항, 최종 제출편집: 문항·선택지·정답·배점, 보호·재적용 범위
결과: 본인 답안과 허용된 정오 정보통계: 버전별 문항 정답률과 응시자 결과
통계: 본인 추이와 공개 가능한 익명 집계게시·재적용 작업 상태는 공통 Jobs 상세 연결
화면 시안: 사용자 퀴즈 시안과 관리자 퀴즈·문제집 시안에서 화면별 배치를 확인한다.
