OJ Platform 재정비 기준 · D-009

관리자 UI 재정비

이 문서는 복잡하고 기능마다 다른 관리자 화면 전체를 하나의 일관된 운영 도구로 새로 설계하는 구현 기준서다. 메뉴, 화면, 문구, 상호작용, 반응형 UX, 상태와 일괄 작업의 공통 계약을 정하고 Permission의 역할 화면과 Problems의 문제 목록부터 실제 화면에 적용한다.

확정일: 2026-07-20인코딩: UTF-8 한글 원문상태: 재정비 설계 확정 · 구현 대기문서 번호: D-009

4,283단일 공통 CSS 파일 줄 수

확정: 기존 셸과 스타일은 기능 기준선과 이전 참고 자료로만 사용한다. 정보 구조와 권한 계약은 보존하되 공통 시각 체계, 컴포넌트, 화면 구성과 상호작용은 새 UI 시스템으로 다시 만들고 기능별 View에 단계적으로 적용한다.

앞선 재정비 확정 기준

D-005, D-007, D-008에서 결정한 내용은 다시 묻지 않고 D-009의 전제로 사용한다.

확정
  • 관리자 주 메뉴는 대시보드, 사용자, 문제, 제출, 학습 공간, 커뮤니티, 운영의 7개로 구성한다.
  • 내부 Controller·Adapter 정리만으로 UI 재정비를 완료하지 않는다. 모든 메뉴의 실제 화면과 핵심 작업 흐름을 새 UI 시스템으로 교체한다.
  • 화면은 목록, 상세, 작성·편집, 설정, 위험 작업, 작업 진행의 6가지 유형을 사용한다.
  • 공통 기반의 첫 관리자 화면은 Permission의 역할·권한 화면이며, 첫 업무 화면은 문제 목록과 난이도 1~5·주제 생성 작업이다.
  • 현재 페이지 선택과 필터 결과 전체 선택을 구분하고, 전체 작업은 Jobs를 통해 실행한다.
  • 수업·대회·문제 목록은 전역 관리자에게 “전체·내 담당” 범위 선택을 제공하고 일반 강사는 “내 담당”으로 고정한다. 담당 역할과 권한 해제 상태는 기술 키가 아닌 사용자 용어로 표시한다.
  • 상태는 대기, 진행 중, 확인 필요, 일부 완료, 완료, 실패, 취소의 공통 의미로 표시한다.
  • 저장 시각은 UTC를 사용하고 화면에서는 WordPress 사이트 시간대로 표시하며 내보내기와 기술 상세에는 시간대 기준을 함께 적는다.
  • 화면 문구는 UTF-8 한글 원문으로 작성하고 \u 형식의 한글 표현과 개발자 안내 문구를 사용하지 않는다.
  • 권한에 없는 메뉴와 행동은 보이지 않게 하고 직접 주소 접근도 같은 권한 계약으로 차단한다. 사용자·문제·제출 상위 메뉴는 고정 목록 주소가 아니라 현재 역할의 첫 접근 가능 하위 화면으로 연결한다.

재정비 목표 UI 구조

화면을 그리는 책임과 업무를 처리하는 책임을 명확히 나눈다.

확정 구조

UI 토큰

색상, 간격, 글자 크기, 테두리, 높이, 초점 표시의 이름과 값을 한곳에서 관리한다. 화면 코드에서 임의 색상과 임의 크기를 추가하지 않는다.

공통 컴포넌트

버튼, 입력, 배지, 알림, 필터, 선택 작업 바, 표, 빈 상태, 페이지 이동, 대화상자와 작업 진행 표시를 제공한다.

관리자 셸

권한에 맞는 메뉴, 경로, 화면 제목, 기능 명령과 본문 배치만 담당한다. 개별 기능의 조건문을 소유하지 않는다.

기능 Presenter

도메인 상태를 한글 문구, 공통 상태, 표시 가능한 행동과 ViewModel로 바꾼다. DB 행을 화면에 직접 넘기지 않는다.

기능 View

공통 컴포넌트를 조합해 문제, 제출, 수업 등의 화면을 만든다. 기능별 고유 정보만 표현한다.

컨트롤러

요청 검증, 권한 검사, 서비스 호출, 리디렉션 또는 View 응답만 담당한다. HTML, 색상과 사용자 문구를 직접 조립하지 않는다.

파일 소유 원칙: 공통 토큰·기본 요소·입력·버튼·표·상태·셸은 resources/ui/css/oj-ui-system.css 한 곳에서 관리하고 공통 상호작용은 resources/ui/js/oj-ui.js가 소유한다. 기능 CSS·JS는 이름 공간이 있는 고유 배치와 상태 연결만 추가하며 공통 선택자·토큰·문구·동작을 복제하거나 덮어쓰지 않는다.

시각 체계

운영 도구에 맞는 차분한 밀도와 의미 중심 색상을 사용한다.

확정

레이아웃

상단 바 58px, 사이드바 240px, 본문 최대 1280px를 기준으로 한다. 넓은 화면에서도 정보가 지나치게 퍼지지 않게 한다.

밀도

표 한 행은 기본 44~48px, 입력과 버튼은 36~40px를 사용한다. 페이지 제목은 크되 패널 안 제목은 작고 단단하게 유지한다.

색상

밝은 중립 배경과 흰 표면을 기본으로 하고 파랑은 주요 행동, 초록·주황·빨강은 성공·주의·위험 의미에만 사용한다.

형태

모서리는 4~8px로 제한하고 그림자는 떠 있는 메뉴와 대화상자에만 사용한다. 페이지 구역을 카드로 감싸지 않는다.

아이콘

검색, 추가, 편집, 삭제, 새로고침처럼 익숙한 행동은 아이콘을 함께 사용한다. 아이콘만 있는 버튼에는 한글 도구 설명과 접근성 이름을 제공한다.

문구

기능명보다 사용자가 하려는 행동을 먼저 쓴다. 예: “AI 메타데이터 분석 실행” 대신 “문제 정보 생성”을 사용한다.

공통 컴포넌트 계약

기능 화면은 아래 요소를 직접 다시 만들지 않고 공통 구현을 사용한다.

12개 핵심 요소
요소필수 입력·동작표시 기준
화면 제목한글 제목, 한 줄 설명, 건수 또는 현재 상태, 허용된 주 명령주 명령은 한 개를 원칙으로 한다.
기능 명령권한, 경로, 아이콘, 문구, 우선순위각 기능이 등록하고 셸이 정렬·출력한다.
검색·필터 바검색어, 필터 값, 적용·초기화, 적용된 조건 수조건이 많으면 “필터” 패널로 접되 현재 조건은 남긴다.
선택 작업 바선택 수, 현재 페이지·필터 전체 범위, 가능한 일괄 작업선택 전에는 숨기고 실행 중에는 중복 실행을 막는다.
데이터 표열 우선순위, 정렬, 행 식별자, 행 명령, 모바일 요약행 명령이 3개 이상이면 더보기 메뉴로 묶는다.
상태 배지상태 코드, 한글 문구, 아이콘 또는 짧은 기호색상만으로 의미를 전달하지 않는다.
결과 알림서버 메시지 코드, 안전한 문맥 값, 다음 행동성공은 간결하게, 실패는 해결 행동을 함께 표시한다.
빈 상태초기 없음 또는 검색 결과 없음, 가능한 다음 행동빈 표만 남기지 않는다.
페이지 이동현재 페이지, 전체 건수, 페이지 크기, 이전·다음필터와 정렬 값을 유지한다.
확인 대화상자행동명, 대상 수, 영향, 취소·확인, 위험 단계일반 저장에는 사용하지 않는다.
작업 진행Jobs 상태, 처리 수, 실패 수, 재시도·취소 가능 여부, 취소 요청 표시관리 작업은 console.jobs.show, 제출 피드백은 본인 제출 상세에서 새로 열어도 같은 작업을 다시 찾는다. 취소 요청 뒤에는 새 항목을 시작하지 않고 이미 임대한 모든 항목이 정리될 때까지 진행 중과 “취소 요청됨”을 함께 표시한다.
기술 정보추적 ID, 오류 코드, 시각, 복사 기능최고 운영 권한에만 접힌 상태로 표시한다.

일반 강사는 담당 문제 안에서 문제 번호·제목, 공개 상태, 생성 여부, 주제와 난이도로 대상을 찾는다. 전역 관리자만 전체 범위로 전환할 수 있다.

2 · 선택

범위와 저장 방식

현재 페이지 선택과 필터 결과 전체를 구분하고 기본값은 기존 정보가 없는 문제만 생성한다.

3 · 등록

대상 스냅샷 고정

확인 시 서버가 조건·권한을 재검증해 정확한 문제 ID를 작업 항목으로 저장한다. 실행 중 새로 조건에 맞는 문제는 추가하지 않는다.

4 · 결과

검증과 충돌 보호

공통 기준의 정수 난이도 1~5와 분야·세부 주제의 표준 키를 검증하고, 등록 뒤 정보가 바뀐 문제는 덮어쓰지 않고 확인 필요로 표시한다.

대상 고정 규칙: “필터 결과 전체”를 확인하는 순간 서버가 필터·정렬과 권한을 다시 검사하고 정확한 문제 ID 목록을 background_job_items에 저장한다. 작업에는 필터 요약·대상 수·정렬된 대상 해시를 남기며, Worker는 존재와 실행 권한만 다시 확인하고 대상 집합을 재계산하거나 늘리지 않는다. 저장 방식은 검색 조건이 아니므로 목록 필터에 두지 않고 “문제 정보 생성” 확인 대화상자에서 범위·영향 수와 함께 선택한다.
담당 범위 규칙: 문제 소유 강사·공동 편집자·테스트데이터 담당자는 역할에 허용된 행 작업만 본다. 목록에 표시되지 않은 문제를 직접 요청하거나 필터 전체 Jobs에 섞어 보내도 서버가 대상별 권한을 다시 검사해 제외하고 감사 사유를 남긴다. 문제 번호 변경·XML 일괄 작업과 미배정 문제 처리는 전역 관리자에게만 표시한다.
덮어쓰기 규칙: 기본은 “미생성만”이다. “AI 생성 정보 새로 만들기”는 AI가 만든 값만 갱신하고 관리자 수정값과 메모는 보존한다. 관리자 수정값까지 바꾸는 작업은 영향 수를 보여 주는 위험 확인을 별도로 받아야 한다. 작업 등록 때의 problem_metadata.updated_at 또는 입력 해시와 실행 시 값이 다르면 저장하지 않고 “확인 필요”로 종료한다.
표시와 재현성 규칙: 화면에는 주제의 한글 이름과 “1 · 매우 쉬움” 같은 난이도 이름을 보여 주고 내부 표준 키·루브릭·사전·프롬프트·모델 버전은 작업 기술 상세에서만 제공한다. 검색은 problem_topic_links의 표준 키 인덱스를 사용하며 같은 입력과 버전은 중복 작업으로 만들지 않는다.

기능별 이전

재정비 확정 결정

D-009의 다섯 권장안을 2026-07-20에 모두 확정했다.

5건 확정

  1. UI-Q01 · 사이드바와 탭의 역할

    확정안: 사이드바는 기능 이동의 유일한 주 탐색으로 사용한다. 탭은 문제 상세의 “기본 정보·문제 정보·기록”처럼 같은 기능 안에서 보기만 바꿀 때 기능이 명시적으로 등록한다.

  2. UI-Q02 · 모바일 표 표현

    확정안: 일반 목록은 식별자·상태·선택을 요약 행에 남기고 나머지 열은 행 상세 펼치기로 제공한다. 데이터 비교가 핵심인 기술 표에만 가로 스크롤을 사용한다.

  3. UI-Q03 · 아이콘 관리

    확정안: 필요한 Lucide 아이콘만 플러그인에 로컬 자산으로 포함하고 공통 아이콘 렌더러로 출력한다. CDN, 화면별 수기 SVG와 문자 기호는 사용하지 않는다.

  4. UI-Q04 · 기본 밀도와 시각값

    확정안: 상단 바 58px, 사이드바 240px, 본문 최대 1280px, 표 행 44~48px, 입력·버튼 36~40px의 조밀한 운영형 화면을 사용한다. 모서리는 최대 8px로 제한한다.

  5. UI-Q05 · 위험 작업 확인 단계

    확정안: 되돌릴 수 있는 단건 작업은 영향과 대상을 보여 주는 확인 대화상자를 사용한다. 영구 삭제, 대량 이전, ID 변경은 사전 검사 결과가 있는 별도 검토 화면에서 정확한 대상과 복구 불가 여부를 다시 확인한다.
