OJ Platform 재정비 기준 · D-007

사용자·용어·메뉴 재정비

이 문서는 학습 서비스에서 학습자가 프로그래밍 문제를 풀고 자동 채점 결과를 확인하며 강사가 수업과 평가를 운영하는 흐름을 기준으로 사용자·용어·메뉴를 재정비한다. 목표 역할 16종, 권한 계약 61개, 현재 관리자 메뉴 51개와 목표 Registry 58개를 근거로 기능별 접근 페이지와 책임을 연결한다.

재정비 문서 전환 근거

기존 작성 대기 문서와 D-007 재정비 범위가 같은지 대조한 결과다.

범위 일치
구분제목범위판정
기존 작성 대기 문서사용자·용어·메뉴 설계사용자 역할, 핵심 작업, 용어, 문구, 메뉴와 화면별 문구원본 범위
D-007 공식 문서사용자·용어·메뉴 재정비원본 범위를 재정비 기준으로 구체화제목 통일
결론: 기존 작성 대기 문서의 제목과 범위를 유지하면서 앞 문서와 같은 번호 체계의 D-007 공식 문서로 전환했다.

앞선 재정비 확정 기준

앞선 문서와 코드에서 다시 결정하지 않아도 되는 내용이다.

기준 연결

메뉴와 권한

관리 메뉴는 AdminConsole 한 곳에서 조립하고 실제 경로 권한과 기능 상태를 통과한 항목만 표시한다.

제출 용어

일반 코드·주소·화면은 제출과 submission을 사용하고 Judge DB 어댑터 안에서만 solution을 사용한다.

설정 메뉴

가입, 제출, AI, 게시판, Blockly와 Judge DB 설정은 각 기능 메뉴와 소유 모듈에서 관리한다.

사용자 문구

행동과 결과를 먼저 설명하고 DB명, 클래스명, Provider와 마이그레이션 코드는 일반 안내에서 숨긴다.

계정 단일화

WordPress와 동일하게 숫자 user_id와 문자열 user_login을 구분한다. 로그인 중 WordPress 사용자 정보가 없을 때만 Judge 정보를 참고해 전환 여부를 묻고, 전환 후 모든 기능 관계에는 숫자 WordPress 사용자 ID만 사용한다.

기능 독립성

그룹 기능을 꺼도 대회와 수업은 정상 동작하며, Blockly는 블록 제출을 선택한 제출 화면에서만 불러온다.

사용자 경험 재정비 근거

화면이 복잡하고 개발자 안내처럼 느껴지는 원인을 코드와 현재 메뉴에서 분리했다.

코드 기준

역할과 사용자가 섞여 있음

OJ 설정 관리자 같은 WordPress 역할은 권한 묶음이다. 실제 사용자인 시스템 관리자, 강사, 공동 강사, 그룹 운영자, 학습자와 같은 이름으로 화면을 설계해야 한다.

업무가 9개 1차 메뉴로 분산됨

대회·수업·그룹이 각각 1차 메뉴라 학습 운영 흐름이 나뉜다. 반대로 제출 아래에는 처리, 설정, AI, 분석, 블록 코딩이 한 단계에 함께 있어 밀도가 높다.

기술 작업이 일반 업무에 노출됨

문제 번호 변경, XML, 데이터 이전, 시스템 상태처럼 주의가 필요한 작업이 일반 목록과 같은 무게로 보이면 사용자가 작업의 위험도를 구분하기 어렵다.

노출과 접근 권한은 같은 계약이어야 함

메뉴를 숨겨도 직접 주소로 접근할 수 있다면 보안이 되지 않는다. 메뉴 표시, 라우트 접근, 기능 사용 상태가 같은 권한 판정을 사용해야 한다.

변경 경계

이번 설계는 메뉴의 묶음, 순서와 화면 표현을 정한다. 선택 기능을 묶는 안정된 첫 화면으로 console.learning.index와 console.community.index 두 허브 라우트를 추가한다. 제출 맥락 8개는 구현 4단계에서 최신 *.submissions 키·주소로만 만들고 이전 status 키·주소는 목표 Registry에 등록하지 않는다.

사용자·권한 재정비

서비스 사용자는 실제 책임으로 정의하고 WordPress 역할은 필요한 권한을 부여하는 수단으로만 사용한다.

메뉴 깊이 제한

실제 탐색은 1차 메뉴 → 2차 화면 두 단계로 유지한다. 표의 “제출 관리·AI 지원” 같은 묶음은 사이드바 안의 구분 제목이며, 클릭 단계를 하나 더 만들지 않는다.

메뉴 노출과 접근 규칙

권한별 메뉴 등록이 일관되게 동작하기 위한 단일 판정 순서다.

필수 계약
  1. 기능 확인: 기능이 꺼져 있으면 해당 기능의 메뉴와 진입 버튼을 숨긴다. 대회·수업·그룹은 서로 독립적으로 판정한다.
  2. 라우트 확인: 실제 등록된 route key가 없는 항목은 메뉴에 표시하지 않는다.
  3. 권한 확인: capability 또는 route의 access_rule을 통과한 하위 메뉴만 표시한다.
  4. 상위 메뉴 계산: 접근 가능한 하위 메뉴가 하나 이상일 때만 상위 메뉴를 표시하고, 고정 목록 주소가 아니라 순서상 첫 접근 가능 하위 화면으로 연결한다. 빈 상위 메뉴와 권한 없는 기본 링크를 만들지 않는다.
  5. 컨텍스트 재확인: 그룹 소유자·위임 운영자처럼 대상별 권한은 목록 노출 후 상세 진입과 저장 시 다시 검사한다.
  6. 직접 주소 보호: 메뉴에서 숨겨진 화면도 직접 URL 접근 시 같은 권한 판정을 사용하고, 권한이 없으면 이유를 노출하지 않은 채 접근을 거부한다.
  7. 현재 위치 유지: 권한 변경이나 기능 OFF로 현재 화면을 사용할 수 없게 되면 접근 가능한 첫 화면으로 이동하고 짧은 안내를 표시한다.
표시 조건: feature enabled AND route registered AND access allowed. 세 조건은 AdminConsole의 단일 메뉴 조립 지점에서 계산한다.

사용자 서비스 메뉴

홈·문제·제출·학습·커뮤니티·내 정보를 기본값으로 사용하며 운영자가 1차·2차 구성을 설정한다.

기본값 6개
로그인 우선 시작

모든 OJ 업무·콘텐츠 페이지는 로그인 필수다. 비로그인 사용자는 로그인 화면으로 이동하며 로그인, 가입, 복구·재설정, 법정대리인 동의와 법적 문서만 예외로 연다. active 상태로 인증에 성공한 뒤 메인 홈 /을 열고 그때부터 역할·기능에 맞는 사용자 메뉴를 표시한다.

사용자 UI 전체 재설계

메뉴 이름만 바꾸는 작업이 아니다. 로그인, 홈, 문제 목록·상세·풀이, 제출 결과, 수업·대회·그룹, 커뮤니티와 내 정보의 실제 화면·문구·상태·상호작용·모바일 경험을 공통 UI 시스템으로 새로 만든다. 내부 구조만 정리되고 기존 화면이 남아 있으면 해당 기능 재정비는 완료가 아니다.

1차·2차 메뉴 설정

시스템 관리자는 내부 메뉴의 1차·2차 단계, 표시 이름, Route Registry 연결, 부모, 표시 대상, 순서와 모바일 위치를 설정할 수 있다. 외부 HTTPS 메뉴도 1차 또는 2차로 최대 20개 등록할 수 있다. 메뉴는 2단계까지만 허용하고 역할별 접근 가능한 내부 1차 메뉴를 최소 1개 유지하며 외부 링크에는 외부 아이콘·호스트·새 창 표시를 강제한다.

상세 문서로 분리

메뉴 트리, 연결 페이지, 접근 권한, 사용 테이블과 속성은 사용자 메뉴·페이지·권한·데이터 연결표에서 관리한다. 이 문서에는 사용자 중심 용어와 메뉴 원칙만 유지한다.

서비스 화면 원칙

시스템 상태, 데이터 이전, Provider, DB 스키마와 기능 플래그는 사용자 메뉴에 두지 않는다. 운영 권한을 가진 강사는 대상별 관리 권한이 있을 때만 해당 수업·대회·그룹의 관리 화면으로 이동한다.

재정비 확정 결정

다섯 항목의 확정 내용에 2026-07-22 로그인 우선 진입 결정을 누적했다.

5건 확정

  1. U-Q01 · 관리자 1차 메뉴

    확정: 대시보드·사용자·문제·제출·학습 공간·커뮤니티·운영의 7개로 통일한다.

  2. U-Q02 · 학습 공간 명칭과 범위

    확정: 일반 사용자에게는 학습, 관리자에게는 학습 공간을 사용하고 수업 → 대회·평가 → 그룹 순서로 묶는다. 세 기능은 서로 독립적으로 켜고 끌 수 있게 한다.

  3. U-Q03 · 기술 정보 위치

    확정: DB 연결, 데이터 이전, 시스템 상태, 기능·메일 설정은 운영에 모으고 일반 업무 화면에는 결과와 다음 행동만 표시한다.

  4. U-Q04 · 제출의 AI 기능 묶음

    확정·보완: AI 피드백·AI 답변 지침·학습 수준 분석을 제출 > AI 지원 구분 아래 배치한다. 재사용 가능한 연결 프로필과 작업별 AI 배정은 운영의 서로 다른 2차 메뉴에 둔다.

  5. U-Q05 · 사용자 서비스 메뉴

    확정·보완: 로그인·가입·복구·법정대리인 동의·법적 문서만 비로그인 예외로 두고 모든 업무·콘텐츠 페이지는 로그인 필수로 한다. active 상태로 인증에 성공한 뒤 메인 홈을 연다. 홈·문제·제출·학습·커뮤니티·내 정보는 기본 메뉴 구성이며 운영자는 내부 메뉴의 1차·2차 단계·이름·Route 연결·부모·대상·순서·모바일 위치를 설정하고 외부 HTTPS 메뉴도 두 단계에 배치할 수 있다. 기능·권한이 없는 항목은 숨기고 3단계 메뉴는 허용하지 않는다.

재정비 구현 인계 기준

확정된 설계를 실제 코드에 반영할 때 반드시 검증할 항목이다.

구현 대기
  1. 완료: U-Q01~U-Q05의 사용자 확인 결과를 문서에 반영하고 설계를 확정했다.
  2. Console_Menu_Provider의 메뉴 묶음과 순서를 변경한다. capability key는 유지하고 제출 맥락 8개는 *.submissions 대표 키·주소로만 등록하며 이전 키·주소는 제거한다.
  3. 역할 관리·문제집·AI 피드백·제출 설정처럼 첫 목록 화면 권한 없이 하위 화면만 가진 역할을 자동 검사해 상위 메뉴가 해당 사용자의 첫 접근 가능 화면으로 연결되는지 확인한다.
  4. 화면 제목, 버튼, 빈 상태, 성공·실패 메시지를 용어 사전과 문구 원칙에 맞춰 조사하고 변경 목록을 만든다.
  5. 16개 역할별로 보이는 메뉴와 직접 주소 접근을 검증하고, 가입 승인 담당자의 최소 목록·승인 전용 범위와 그룹 소유자·위임 운영자의 컨텍스트 권한을 별도로 시험한다.
  6. 대회·수업·그룹·게시판·공지·AI·블록 코딩 기능을 하나씩 껐을 때 빈 메뉴와 끊어진 링크가 없는지 확인한다.
  7. 1차·2차 내부 메뉴의 키·Route·부모·이름·표시 대상·순서·모바일 위치와 외부 메뉴의 단계·최대 수량·부모·이름·HTTPS URL·사용자 정보 포함 URL·위험 스킴·정렬·새 창 보안 속성을 검사한다. 접근 가능한 내부 1차 메뉴가 0개가 되거나 3단계가 생성되지 않고 서버가 외부 URL을 미리 요청하지 않는지 확인한다.
  8. 데스크톱과 모바일에서 1차 메뉴가 과밀하지 않고 현재 위치와 다음 행동이 명확한지 화면 검증을 수행한다.
