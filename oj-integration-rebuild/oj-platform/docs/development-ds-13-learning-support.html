DS-13 · 메뉴 기반 상세 설계

학습 지원 상세 설계

채점 결과를 이해하도록 돕는 AI 피드백, 본인의 풀이 흐름을 정리하는 내 학습, 로그인 사용자 사이의 선택적 전체 랭킹을 설계한다. 세 기능은 학습을 돕는 보조 기능이며 성적·평가 결과·수업 권한을 결정하지 않는다.

전체 순서에서의 위치: DS13-Q01~Q08과 UI 시안 2종은 사용자 확정으로 동결했다. DS-16 전체 승인도 완료했으며, I-00 보호 환경을 통과한 뒤 I-06에서 AI Feedback Jobs → 내 학습 → 전체 랭킹 순서로 구현한다.
범위 경계: 문제 난이도·주제는 DS-10, 제출·결과 상세 권한은 DS-11, 수업·대회·평가·그룹 보고서는 DS-12가 소유한다. DS-13은 원본을 복제하거나 평가 점수를 만들지 않고 승인된 읽기 Provider로 학습 보조 화면만 조립한다.

AI 피드백

사용자가 요청한 제출 한 건을 Jobs에서 처리하고 성공 결과만 저장한다.

비동기·명시적 요청
1 · 요청제출·권한·수행 모드·결과 확인
2 · 생성Jobs 등록·Worker 검증·AI 호출
3 · 표시AJAX 상태 갱신·구조화된 피드백
항목권장 동작금지
생성 시점채점이 끝난 허용 결과에서 학습자 또는 승인된 담당자가 버튼을 눌렀을 때만 생성모든 제출에 자동 생성, 웹 요청에서 AI 호출
입력문제 본문·허용된 소스·오류 요약·결과 코드·분석 상태·허용된 학습 수준·답변 지침 버전이름·로그인 아이디·이메일·서비스·수업·그룹명·누적 제출 원문 전송
출력결과 이해, 가능한 원인, 단계별 힌트, 확인할 코드 구간, 다시 풀기 질문정답 코드 전체, 평가 점수 변경, 근거 없는 단정
수준 결합Worker가 최신 수준 프로필을 확인하고 수준·분석 상태에 맞는 피드백 전략을 내부 답변 지침에 결합오래된 수준 사용, 자료 부족 사용자를 임의로 초급 판정, 응답에서 학습자를 “초급 사용자”처럼 호명
중복 방지제출·소스·문제·작업 배정 revision·연결 프로필 fingerprint·모델·답변 지침·수준 정책·수준 프로필 기준점 해시가 같으면 성공 결과 재사용새로고침·중복 클릭마다 외부 호출
권한 재검사등록·Worker 실행·상태 조회·결과 조회마다 기능, 상세 권한, 수행 모드와 원본 해시 확인작업 생성자라는 이유만으로 권한 유지
실패·취소기존 결과를 보존하고 안전한 실패 코드와 재시도 가능 여부만 표시부분 응답 저장, 원본 피드백 덮어쓰기
화면: 제출 상세의 채점 요약 아래에 “AI 풀이 도움” 영역을 둔다. 생성 전에는 한 개의 요청 버튼, 처리 중에는 상태와 취소, 완료 뒤에는 결과 이해 → 힌트 → 다시 확인할 점 순으로 보여 준다. 기술적인 모델명·프롬프트 파일명·작업 ID는 일반 사용자에게 표시하지 않는다.
수행 모드: 활성 수행 모드 그룹의 일반 구성원은 그룹 밖 제출을 포함한 본인 제출 전체에서 생성 버튼, 작업 상태와 저장된 피드백을 볼 수 없다. 담당 그룹의 소유자·활성 위임 운영자와 승인된 전역 제출 범위만 DS-11 정책에 따라 접근한다.

신뢰 수준		30회 이상 그리고 10문제 이상수준과 함께 “신뢰 자료 충족” 표시판정 수준별 전략 적용
자료 부족 기본 안내: 분석 보류와 임시 분석에서는 학습자 수준을 추정하지 않는다. 결과의 의미, 관련 가능성이 높은 개념 한 가지와 스스로 실행 흐름을 확인할 질문 한 가지를 제공하되 수준 명칭은 응답에 쓰지 않는다.
표시 위치: 학습자는 본인의 /dashboard에서만 분석 상태·수준·산정 근거를 확인한다. 공개 프로필 /users/{user_id}과 전체 랭킹에는 학습 수준을 표시하지 않는다. oj_manage_ai_feedback 권한자는 관리자 학습 수준 분석 화면에서 운영에 필요한 범위만 조회한다.
  • 제출 수와 시도 문제 수는 두 기준을 모두 만족해야 다음 상태로 올라간다.
  • valid=1이고 채점이 끝난 누적 제출을 사용하며 무효 제출은 제외한다. 진행 중 대회·평가 제출은 종료 전 제외하고 종료 뒤 공개 정책을 통과한 이력만 반영한다.
  • 누적 지표는 임의의 300건 상한을 두지 않고 사용자·문제별 집계 Provider로 계산한다. 최근 지표만 최근 시도한 서로 다른 문제 최대 20개를 사용한다.

점수 산식

지표산식운영 규칙
증명 난이도
ProvenDifficulty		난이도별 TierScore = BaseScore × min(SolvedCount / RequiredSolved, 1) × min(TopicCount / RequiredTopic, 1), 다섯 단계 중 최댓값해당 난이도 이상에서 해결한 서로 다른 문제와 표준 주제를 센다. 최고 점수가 같으면 과대 판정을 막기 위해 낮은 난이도를 ProvenTier로 선택한다.
학습 범위
Breadth		min(전체 해결 고유 주제 수 / 8, 1) × 100난이도와 관계없이 해결한 문제의 표준 주제를 중복 없이 센다.
최근 도전
RecentChallenge		(ProvenTier 이상 시도 수 / 최근 난이도 확정 문제 수) × 60 + (그중 해결 수 / ProvenTier 이상 시도 수) × 40최근 시도한 서로 다른 문제 최대 20개를 사용한다. 난이도 확정 표본 또는 도전 문제가 없으면 해당 비율은 0으로 처리하고 표본 수를 함께 표시한다.
풀이 안정성
Stability		(해결 문제 수 / 최근 시도 문제 수 × 100) × 0.60 + SubmissionEfficiency × 0.40같은 최근 20문제에서 첫 Accepted까지 평균 제출이 2회 이하 100, 3회 이하 80, 5회 이하 60, 8회 이하 40, 초과 20이다. 해결 문제가 없으면 효율은 0이다.
최종 점수
SkillScore		ProvenDifficulty × 0.50 + Breadth × 0.15 + RecentChallenge × 0.20 + Stability × 0.150~100으로 제한하고 소수 첫째 자리까지 표시한다. 정책 키는 learner-level-v1로 고정해 산식 변경을 구분한다.
근거 우선순위: 난이도별 필요 해결 수·주제 수와 수준 경계는 이번에 제공된 연구를 원본으로 사용한다. 첨부 텍스트에서 수식 이미지가 빠진 RecentChallenge·Stability의 60:40 결합과 SkillScore의 50:15:20:15 결합만 기존 hustoj-ai-dashboard의 같은 지표 구현으로 복원했다. 기존 구현의 별도 최근성·단계별 학습 범위·학습 과정 보정은 연구 핵심 산식에 없으므로 포함하지 않는다.

연구 문구 해석: 제공된 연구의 본문은 초급일수록 구체적으로 안내하고 고급일수록 자기 점검을 유도하지만 마지막 요약표의 초급·고급 행은 반대로 적혀 있다. 본 설계는 반복해서 설명된 본문과 학습 지원 방향을 기준으로 적용하고, 해당 요약표는 수준 이름이 뒤바뀐 편집 오류로 본다.
현재 코드와의 차이: 통합 플러그인의 기존 단순 평균 방식과 45:20:20:15 가중치는 이 설계를 충족하지 않는다. I-00 보호 환경을 통과한 뒤 I-06에서 이 문서의 분석 상태·산식·수준별 답변 전략으로 교체한다.
생성 시점의 수준 고정: Worker는 AI 호출 직전 새 유효 제출 여부를 확인해 프로필을 갱신하고, 그때의 분석 상태·수준·정책 버전·마지막 반영 제출 ID를 피드백 결과에 함께 기록한다. 이후 수준이 바뀌어도 저장된 피드백을 자동 재생성하지 않으며 사용자가 다시 요청할 때 새 기준으로 생성한다. 외부 AI에는 수준 전략만 보내고 다른 제출 원문과 개인 식별 정보는 보내지 않는다.
관리자 화면: 학습 수준 분석은 사용자, 분석 상태, 수준, 신뢰 자료 충족 여부, 세부 지표, 난이도 확정률, 주제 연결률, 최근 분석 시각과 정책 버전을 필터링한다. AI 피드백 관리 권한은 수준 프로필을 볼 수 있지만 제출 소스·피드백 내용을 자동으로 열 수 없으며, 해당 자료는 별도의 제출 접근 정책을 다시 통과해야 한다.
