홈·대시보드·셸 상세 설계

로그인 후 첫 화면과 모든 메뉴의 공통 틀을 학습용 채점 서비스에 맞게 정리한다. 사용자 홈은 학습을 이어 가는 화면, 관리자 대시보드는 맡은 운영 작업을 확인하는 화면으로 만들고 두 셸은 권한이 검증된 ViewModel만 표시한다.

  • 사이트 로고와 기본 시작 동작은 비로그인 상태에서 /login, 로그인 상태에서 /을 사용한다.
  • 비로그인 허용 목록은 auth.login, 가입 기능이 켜진 auth.register, auth.guardian_consent, legal.terms, legal.privacy, legal.copyright, legal.email_collection_refusal 일곱 Route 키로 고정한다. 비밀번호 복구·재설정은 auth.login의 화면 상태다.
  • 위 예외를 제외한 모든 OJ HTML 페이지는 active 플랫폼 사용자만 접근한다. 비로그인·승인 대기·이용 중지 상태에서는 업무 Controller·Provider를 호출하지 않는다.
  • HTML 페이지의 비로그인 요청은 /login으로 이동한다. API·파일·작업 응답은 로그인 HTML을 섞지 않고 401 또는 403을 반환한다.
  • 홈·문제·제출·학습·커뮤니티·내 정보는 기본 구성이다. 운영자는 내부 메뉴의 1차·2차 단계·표시 이름·Route 연결·부모·대상·순서·모바일 위치를 설정하고 외부 HTTPS 메뉴도 두 단계에 배치할 수 있다. 3단계 메뉴는 만들지 않는다.
  • 메뉴는 DS-07의 Route_Link_Service가 반환한 접근 가능한 링크만 표시하며 직접 주소도 같은 Policy를 다시 검사한다.
  • 계정 메뉴에는 프로필·계정 설정·동의·로그아웃을 제공하고, 접근 가능한 관리자 경로가 하나 이상일 때만 관리자 화면 링크를 표시한다.
  • 지속형 알림함과 읽지 않음 수는 새 테이블 없이 만들지 않는다. 상단 알림 영역은 최신 공지와 현재 요청의 일회성 안내만 제공한다.

로그인 후 사용자 홈

설명보다 바로 이어 갈 수 있는 행동을 먼저 보여 준다.

학습 중심
1 · 가장 먼저이어서 하기

진행 중 대회, 최근 오답·미완료 문제, 문제 찾기 순으로 한 개 주 행동을 선택한다.

2 · 참여내 학습 공간

활성 수업·대회·그룹을 최대 6개 표시하고 각 기능의 접근 정책을 따른다.

3 · 결과최근 제출

최근 5건의 문제·시각·결과만 표시하며 상세 접근이 막힌 수행 모드에는 링크를 만들지 않는다.

4 · 안내공지

게시된 최신 공지 최대 5건과 전체 보기만 제공한다.

5 · 운영 역할담당 공간 바로가기

강사·운영자에게 맡은 수업·대회·그룹과 관리자 화면 진입을 추가한다.

빈 상태문제 찾기

참여 공간과 제출이 없어도 문제 목록으로 가는 한 개 행동을 제공한다.

우선순위후보선택 기준이동
1진행 중 대회현재 참가 중이고 접근·기간 정책을 통과대회 상세
2최근 오답·미완료 문제현재도 문제 접근 가능, 수행 모드에서 허용된 정보만 사용문제 상세 또는 제출
3최근 참여 수업활성 수강 관계와 공개된 문제 존재수업 상세
4문제 찾기Problems 기능과 목록 접근 가능문제 목록
홈에서 제거: 공개 문제 전체 수, 전체 제출 수, 모듈 수 같은 사이트 통계와 마케팅 hero·홍보 카드·임의 빠른 링크를 기본 홈에 두지 않는다. 홈은 사용자에게 필요한 현재 상태와 다음 행동만 표시한다.
부분 실패: 한 Provider가 실패하면 해당 블록만 안전한 빈 상태로 바꾸고 나머지 홈은 렌더링한다. 오류 상세는 화면에 노출하지 않고 추적 ID만 기록하며 권한 없음과 조회 실패를 같은 값으로 캐시하지 않는다.

  • 데스크톱 사이드바는 상단 바 아래의 화면 높이에 고정하고 메뉴 영역만 독립 스크롤한다. 상위 메뉴의 링크와 하위 메뉴 토글을 구분하며, 현재 페이지의 상위 메뉴는 자동으로 펼친다. 다른 메뉴의 펼침 상태는 탭 세션 안에서 유지하고 모바일 메뉴에도 같은 토글 상태를 적용한다. 아이콘 전용 접기 상태는 모바일 메뉴를 숨기지 않는다. 탭으로 다른 기능 메뉴를 반복하지 않으며, 탭은 기능이 같은 대상의 보기 전환을 명시적으로 등록한 경우에만 출력한다.
  • 화면 제목·설명·주 명령 1개·보조 명령은 Route ViewModel이 제공한다. 셸에 문제 추가·사용자 추가 같은 경로별 조건문을 두지 않는다.
  • 상단에는 사용자 화면으로 돌아가기, 현재 계정, 로그아웃을 제공한다. 시스템 경고는 해당 조회 권한과 등록된 Alert Provider를 모두 통과한 경우에만 표시한다.
상위 메뉴 진입: 사용자·문제·제출은 독립 화면을 만들지 않고 같은 Route Policy가 허용한 첫 하위 화면으로 이동한다. 허용 하위 화면이 없으면 상위 메뉴 자체를 숨기며 임의 홈 대체는 하지 않는다.

조립 화면이 기능 클래스와 Repository를 직접 찾지 않게 한다.

  • Provider는 완성 HTML, SQL, Repository 객체와 외부 URL을 반환하지 않고 타입이 있는 ViewModel만 반환한다.
  • 한 기능은 같은 키를 중복 등록할 수 없고 Registry는 owner·feature·priority·출력 스키마·Route 참조를 전체 수집 뒤 검증·동결한다.
  • 각 Provider는 제한된 한 번의 조회로 최대 항목 수를 지키고 행별 추가 조회를 금지한다. 민감한 사용자 결과는 공유 캐시에 넣지 않는다.
  • Provider 실패는 해당 블록 단위로 격리하며 권한 없음·기능 OFF는 조용히 제외하고 실제 오류만 추적 ID와 함께 기록한다.
  • Groups Provider가 없거나 기능이 꺼져도 Classes·Contests 블록과 메뉴는 독립적으로 동작한다.

확정 항목

아래 여덟 항목을 2026-07-23 사용자 확인으로 동결했다.

8건 확정
  1. DS09-Q01 · 역할·진입: 서비스 시작 엔트리는 /login으로 고정한다. 가입·복구·법정대리인 동의·법적 문서의 7개 Route 키만 비로그인 예외로 두고, 나머지 모든 HTML 페이지는 비로그인 요청을 /login으로 이동한다. active 사용자만 홈과 업무 화면을 열며 검증된 내부 이동값만 보존한다. 관리자 권한 사용자는 로그인 후 계정 메뉴에서 /oj-console로 이동한다.
  2. DS09-Q02 · 사용자 셸 · 보완: 데스크톱은 설정된 1차 메뉴와 2차 드롭다운, 모바일은 지정된 최대 4개+더보기와 부모별 2차 시트를 사용한다. 운영자는 내부 메뉴의 단계·이름·Route 연결·부모·대상·순서·모바일 위치를 설정하고 외부 HTTPS 메뉴도 1차 또는 2차에 배치할 수 있다. Route 권한은 바뀌지 않으며 3단계 메뉴는 허용하지 않는다.
  3. DS09-Q03 · 사용자 홈: 마케팅 hero·전체 통계를 제거하고 이어서 하기·내 학습 공간·최근 제출·공지·담당 바로가기를 Provider로 조립한다.
  4. DS09-Q04 · 관리자 셸: AdminConsole이 D-007의 7개 상위·51개 하위 메뉴를 단일 소유하고 사이드바·제목·등록형 명령을 렌더링하며 메뉴를 탭으로 반복하지 않는다.
  5. DS09-Q05 · 대시보드: 내 할 일·조회 가능한 최근 Jobs·권한 있는 운영 알림·담당 바로가기를 우선하고 기술 진단은 시스템 상태 화면으로 분리한다.
  6. DS09-Q06 · Provider: 홈·대시보드·명령·경고는 타입이 있는 등록형 ViewModel을 사용하고 기능 OFF·권한 없음·실패를 블록 단위로 격리한다.
  7. DS09-Q07 · 설정·알림·자산: 기존 두 WordPress 옵션의 네임스페이스를 유지하되 승인된 블록·메뉴만 설정하고 URL 문구를 Flash Store로 교체하며 기능 자산은 Route별로 적재한다.
  8. DS09-Q08 · 구현·검증: 새 테이블 없이 숫자 user_id, Route Policy, 16개 역할 메뉴 Snapshot, 가입 승인 전용 범위, 쿼리·자산 상한과 데스크톱·모바일 시각 검증을 완료한다.
현재 상태: DS09-Q01~Q08의 기능 계약을 유지한다. R-04에서 사용자 홈·셸과 관리자 대시보드·셸 실행 코드를 구현했고 역할별 메뉴·가입 승인 작업을 연결했다. Problems·Submissions·학습 공간·Jobs의 최근 항목은 각 소유 단계에서 Read Provider로 추가하며 운영 DB는 변경하지 않았다.
