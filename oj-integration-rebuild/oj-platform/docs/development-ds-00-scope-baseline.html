DS-00 목적·범위·기준선

OJ Platform을 학습 서비스에서 학습자가 문제를 풀고 제출하며, 강사가 수업·대회·평가를 운영하는 사용자 서비스로 전면 재정비한다. 내부 클래스 정리에 한정하지 않고 일반 사용자 UI, 관리자 UI, 코드, 권한, 데이터베이스와 이전 절차를 하나의 제품 범위로 다룬다.

작성일: 2026-07-22확정일: 2026-07-22상태: 사용자 확정근거: D-001~D-009 및 현재 코드 재검증인코딩: UTF-8 한글 원문
DS-00의 역할: 새 기능을 설계하는 문서가 아니라 이후 DS-01~DS-16이 바꾸면 안 되는 목적, 범위, 수량과 기술 계약을 고정하는 승인 문서다.

사용자와 기능 범위

학습용 채점 서비스에 필요한 실제 작업을 기준으로 포함 여부를 나눈다.

제품 전체

주요 사용자

  • 학습자: 문제 풀이, 제출, 결과·학습 현황 확인
  • 강사·공동 강사: 수업, 문제, 진도와 참여자 운영
  • 대회 담당자: 대회·평가 운영, 감독과 결과 확인
  • 문제 담당자: 문제·테스트데이터·난이도·주제 관리
  • 플랫폼 운영자: 사용자·권한·설정·상태·이전 관리

포함 기능

  • 로그인·계정·사용자·홈과 역할별 탐색
  • 문제·문제집·퀴즈·난이도 1~5·표준 주제
  • 전체 코드·코드 빈칸 완성·Blockly 제출, 채점 결과와 재채점
  • 수업·대회·그룹, 참여·진도·보고서
  • AI 지원·학습 현황·랭킹·커뮤니티
  • 관리자 설정·Jobs·상태·데이터 이전·복구

이번 범위에서 제외

  • 플랫폼 외부의 별도 학습 관리와 공식 성적 처리
  • 별도 조직 행정과 공식 성적 관리
  • 카메라·화면 녹화 기반 온라인 감독
  • 재정비와 관계없는 신규 서비스 확장

후속 독립 검토

코드 유사도·표절 검사와 HUSTOJ sim 기능은 이번 재정비에서 사용하지 않는다. 제출·채점·평가 화면과 설정에도 관련 기능을 만들지 않는다.

변경 금지 계약

새로운 근거와 사용자 승인 없이는 이후 점검에서 뒤집지 않는다.

고정
  1. 전체 제품 재설계: 일반 사용자 UI와 관리자 UI, UX·문구·반응형·접근성, 코드·권한·DB를 모두 포함한다.
  2. WordPress 사용자 기준: 일반 코드·URL·권한·플랫폼 데이터는 숫자 user_id만 사용하고 Judge 문자열 ID의 영구 매핑을 만들지 않는다.
  3. 저장소 명명: 플랫폼 물리 테이블에는 WordPress 접두어와 oj_를 모두 붙이지 않는다. Judge DB 연결은 별도로 유지한다.
  4. Judge 엔진: HUSTOJ 기본 채점 8개 테이블과 활성화한 custominput 선택 프로필을 공식 스키마 그대로 유지한다. OJ_SIM_ENABLE=0과 OJ_TURBO_MODE=0을 고정하고 Judge DB에 보조 열·이중 쓰기·타입 교체를 추가하지 않는다.
  5. 기능 경계: AI는 공통 기반과 기능별 사용을 분리하고, Groups를 꺼도 수업과 대회가 정상 동작해야 한다.
  6. 제출·Blockly: 사용자 용어와 공개 주소는 “제출”로 통일하고, Blockly는 제출 페이지에서 블록 모드를 선택할 때만 불러온다.
  7. 문제 메타데이터: 난이도는 AI 응답 스키마부터 정수 1~5로 제한하고, 주제는 승인된 표준 키만 저장한다.
  8. 한글: 메뉴·문구·문서는 UTF-8 한글 원문으로 기록하며 \uXXXX 형태를 사용하지 않는다.
  9. 진행 순서: DS-00~DS-16 상세 설계와 사용자 최종 승인을 마치기 전 운영 코드와 DB 재정비를 시작하지 않는다.

전체 17개 결정의 단일 원본은 D-006 변경 금지 기준이다.

완료 정의와 안전 관문

내부 클래스나 DB만 바뀐 상태는 기능 완료로 판정하지 않는다.

구현 전 필수

메뉴별 완료 조건

사용자 UI, 관리자 UI, 업무 코드, 권한·행 범위, 테이블·이전·복구, Jobs, 반응형·접근성, 자동 테스트와 브라우저 사용자 확인을 한 수직 단위로 완료한다.

데이터 변경 조건

운영 자료를 자동 채택하지 않는다. 읽기 전용 구조·건수·고아 보고서, 개인정보 보존·삭제 정책, 백업과 실제 복구 시험이 승인된 뒤에만 물리 스키마와 데이터를 바꾼다.

다음 단계 진입: DS00-Q01~Q04가 모두 승인되어 DS-00을 동결했다. 다음 단계는 DS-01 공통 사용자·관리자 UI 시스템 상세 설계다.

DS-00 확정 항목

기존 승인 내용을 압축한 기준이며 새 정책을 추가하지 않는다.

2026-07-22 확정
  1. DS00-Q01: 학습용 프로그래밍 채점 서비스의 목적과 학습자·강사·담당자·운영자 사용자 범위를 확정한다.
  2. DS00-Q02: 포함 기능과 이번 범위의 제외 기능을 확정하며 유사도·표절 검사는 사용하지 않는다.
  3. DS00-Q03: 현재·목표 수량과 8개 변경 금지 계약을 이후 상세 설계의 고정 기준으로 사용한다.
  4. DS00-Q04: DS-16 최종 승인 전에는 운영 코드·DB 재정비를 시작하지 않고, 각 메뉴를 전체 제품 수직 단위로 완성한다.
