계약 개정 기록

AM-01
AM-01 · AddonRuntimeGatewayV1·oj_platform_loaded 제거, onReady() 도입 (2026-08-11)

사유: C28-I05 구현 뒤 보안 검토에서 oj_platform_loaded(AddonRuntimeGatewayV1 $gateway) 설계 자체의 구조적 취약점을 발견했다. 이 action은 등록된 모든 애드온의 callback에 동일한 전역 $gateway 인스턴스를 방송하고, 각 callback은 $gateway->forAddon($anyAddonId)을 호출해 임의의 다른 승인된 애드온 ID의 AddonRuntimeContextV1을 받을 수 있었다. 즉 애드온 A가 forAddon('addon-b')를 호출하면 addon-b 전용 Context·AI Task Gateway에 접근할 수 있어, WordPress action 순서와 무관하게 애드온 간 권한 격리가 API 표면에서부터 깨져 있었다. 이는 애드온 코드 품질과 무관한 API 설계 결함이었다.

변경: 전역 방송 hook을 없애고, 각 애드온이 register() builder 안에서 AddonManifestBuilderV1::onReady(callable $callback)으로 자신의 준비 callback을 직접 등록하도록 바꿨다. manifest가 승인되면 플랫폼은 accepted catalog를 순회하며 각 애드온이 등록한 정확히 그 callable만, 이 애드온만을 위해 생성한 AddonRuntimeContextV1 하나를 인자로 plain PHP 함수 호출로 실행한다. WordPress action이 아니므로 다른 코드가 이 호출을 가로챌 방법이 없고, 애드온은 자신이 넘긴 callable 외에 어떤 AddonRuntimeContextV1도 참조할 수 없다. AddonRuntimeGatewayV1 interface와 forAddon(), oj_platform_loaded action은 코드베이스에서 완전히 삭제했다(하위 호환 shim 없음).

SemVer 판정: major(공개 interface 삭제, action 삭제, 새 필수 통합 지점 추가). 이 문서의 버전 규칙에 따르면 새 major namespace와 병행 지원 계획이 원칙이지만, Addon API가 아직 C28-I06 공식 릴리스 전 단계(C28-I02~I05 구현·검증 중)이고 실제 배포된 소비자가 없어 병행 지원 없이 1.0.0 표기를 유지한 채 즉시 교체하기로 사용자 승인을 받았다. API가 정식 릴리스된 뒤라면 이 판정은 유효하지 않으며 major bump와 병행 지원이 필수다.

소비자 영향: oj_platform_loaded를 구독하거나 AddonRuntimeGatewayV1/forAddon()을 import하는 기존 통합 코드는 모두 깨진다. 전환 절차와 전후 코드 예시는 별도 onReady 전환 안내서에 기록했다. C-28 변경 설계의 관련 서술과 코드 예시도 이 개정에 맞춰 갱신했다.

AM-02 · Addon API 1.1.0 additive Context·AI 계약 (2026-08-14)

사유: AI 평가 애드온의 학생 학습 Context 진입, exact assignment roster, 활동지 자체 평가와 학생 제출 평가를 구현하려면 기존 1.0 공개 표면에 없던 CG02·CG11·AJ08 계약이 필요했다.

변경: AddonLearningContextGatewayV1·AddonAssignmentRosterGatewayV1 interface 2개와 query·learner·page·instruction DTO 5개를 추가했다. AddonAiTaskDefinitionV1에는 마지막 nullable instruction parameter와 getter만 추가했다. 기존 공개 symbol 30개와 기존 4-argument AI task 선언은 모두 유지한다.

SemVer: additive minor다. API 상수는 1.0.0에서 1.1.0으로 변경했고 공개 표면은 interface 8개·DTO 28개·권한 utility 1개, 총 37개다. 새 기능을 쓰는 소비자는 requiresAddonApi >= 1.1.0을 선언한다.

저장소 영향: 플랫폼 DB migration과 애드온 소유 oj_ai_* table 변경은 없다. 1.0.x rollback 전에는 1.1 전용 기능을 사용하는 애드온을 비활성화하거나 호환 릴리스로 되돌린다.

편집기 표시 설정 공유: 선택적 확장

2026-09-10 · Platform 2.0.0-dev.104 · 코드 실습실의 제출 편집기 테마 공유 요청에 따른 추가 계약

AddonEditorRuntimeContextV1 extends AddonRuntimeContextV1에만 editor(): AddonEditorGatewayV1을 추가한다. 기존 AddonRuntimeContextV1의 세 메서드와 API 버전 1.1.0은 유지한다. 소비자는 버전 문자열 대신 선택적 인터페이스를 확인하며 이전 플랫폼에서는 기존 입력창으로 동작한다.

use CodingPanda\OjPlatform\AddonApi\V1\AddonEditorRuntimeContextV1;

if ($runtime instanceof AddonEditorRuntimeContextV1) {
    $editor = $runtime->editor()->current();
    // isAvailable()을 확인하고 coreUrl(), baseUrl(), theme(), fontSize()를 사용한다.
}
공개 계약반환값과 의미
AddonEditorGatewayV1::current(): AddonEditorSnapshotV1인자 없는 읽기 전용 현재 계정 조회. 다른 사용자 ID 입력 및 저장 메서드는 제공하지 않는다.
theme(): string제출 설정과 같은 정규화된 Ace 테마 slug. 예: chrome, monokai. ace/theme/ 접두사는 포함하지 않는다.
fontSize(): int제출 설정과 같은 14, 16, 18 중 하나.
isAvailable(): bool플랫폼에 기존 제출 Ace 자산이 준비되어 있는지 여부.
coreUrl(): string, baseUrl(): string기존 제출 편집기가 사용하는 로컬 Ace core 및 base 주소. 사용 불가 시 둘 다 빈 문자열.

AddonEditorSnapshotV1은 final DTO이며 생성자 인자는 string $theme, int $fontSize, bool $available, string $coreUrl, string $baseUrl이다. 모든 속성은 private readonly다. 공개 심벌은 기존 37개에 인터페이스 2개와 DTO 1개를 추가한 40개다.

현재 계정은 매 current() 호출 시 CurrentAccountProvider로 결정하고 UserSubmissionPreferenceProvider와 SubmissionCodeEditorAssets를 재사용한다. DB 직접 조회, 사용자 ID·이메일·코드 템플릿 공개, 설정 변경, 새 네트워크 의존성은 없다. 게스트 또는 계정·설정 조회 실패는 Chrome/16px 기본값을 사용하고 자산 오류는 기존 입력창으로 복구할 수 있도록 표시한다.

소비자는 스냅샷을 계정 간에 캐시하지 않고 페이지 요청마다 읽는다. 셀 실행·저장 권한은 기존 애드온 권한 검사로 계속 판단한다. 이 API는 화면 테마만 제공하므로 다른 계정 또는 노트북 접근 권한을 부여하지 않는다.

검증: tests/Contract/addon-editor-runtime.php의 계정 전환·비로그인·개인 정보 비노출·조회 오류·자산 대체·구버전 생성자 호환 22개 검사와 기존 공개 계약·런타임 전달·조립·부팅 검사를 실행한다. 기존 DB 스키마·설정 저장 형식·제출 화면에는 변경이 없다.
