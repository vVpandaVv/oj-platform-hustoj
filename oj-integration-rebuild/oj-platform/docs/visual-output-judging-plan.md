# Python 시각 출력 채점 계획과 현재 범위

갱신일: 2026-10-05

## 1. 확정한 방향

기존 HUSTOJ의 코드 실행·대기열·제출번호·재채점·결과 기록을 유지하고, 실행 후 이미지 비교를 전용 SPJ에 맡긴다. 이전 문서의 독립 이미지 실행 작업자, 별도 제출 테이블, 공통 제출번호 등록부 방안은 채택하지 않는다. 일반 프로그래밍 제출과 이미지 제출은 기존 `solution_id` 하나를 그대로 사용한다.

```text
기존 플랫폼 제출 정책과 소스 저장
  -> 기존 HUSTOJ solution 및 실행 대기열
  -> 기존 격리 환경에서 Python 실행
  -> 표준 출력에 PNG 기록
  -> 문제 데이터 폴더의 이미지 SPJ 호출
  -> 기존 채점 결과 기록
  -> 기존 제출·수업·대회 화면 조회
```

신규 WordPress 기능에서 Judge DB 직접 SQL 경로를 추가하지 않는다. 이미지 비교 SPJ는 DB를 읽거나 쓰지 않으며 기존 채점 어댑터 경계를 변경하지 않는다. Addon API 1.2 계약 변경도 없다.

## 2. 이번 구현

비교기는 저장소의 `tools/image-spj`에 있으며 운영 방법과 테스트 기록은 [이미지 SPJ README](../../tools/image-spj/README.md)에 둔다.

| 항목 | 현재 상태 |
| --- | --- |
| C++17 이미지 비교 SPJ | 구현. LodePNG 포함, Python·SciPy·OpenCV 런타임 불필요 |
| 기존 단일 파일 SPJ 컴파일 | `build/image-spj/spj.cpp` 생성 도구 제공. 기본 C++17 인자에 맞춤 |
| in/out 데이터 | 입력은 기존 `.in`, 정답 PNG는 `.out` 바이너리 또는 UTF-8 Base64 포장 |
| 현재 콘솔의 UTF-8 파일 업로드 제한 | 유지. 텍스트 정답 변환 도구로 대응 |
| 학생 이미지 전달 | 표준 출력 PNG. Matplotlib 예제 제공 |
| 관리자 문제 설정 | 구현. 문제 편집 > 코드 제출 조건 > "이미지 채점"에서 Matplotlib/turtle 선택. 선택하면 특수 채점기가 강제로 켜지고 허용 언어는 Python 3 하나여야 하며 전체 코드 방식에서만 사용(`problem_metadata.visual_grading_mode`, 스키마 v2) |
| 자동 Matplotlib 출력 코드 주입 | 구현. 제출 정책이 비공개(`#hidden`) 앞·뒤 코드를 자동으로 붙임. 문제에 저장된 앞·뒤 코드는 건드리지 않음(`resources/features/visual-grading/`). 학생의 `print`는 표준 오류로 우회 |
| turtle 캡처·종료 제어 | 구현. Tk·화면 없이 turtle 그림을 기록해 Pillow로 800×600 PNG로 렌더링. `done()`·`exitonclick()`·타이머·키 입력은 무시하며 `tkinter`가 없어도 동작. 이미지 파일·애니메이션 이벤트는 지원하지 않음 |
| SPJ 소스 자동 배치 | 구현. 테스트데이터 화면의 "이미지 채점기 설치·컴파일"이 `spj.cc`를 문제 폴더에 쓰고 기존 SPJ 컴파일 작업을 등록. 소스는 플러그인에 내장(`resources/features/image-spj/spj.cpp`, `tools/image-spj/build.mjs` 산출물) |
| 정답 이미지 업로드 | 구현. PNG를 올리면 검증 후 `<이름>.out`에 Base64 포장으로, `<이름>.in`에 입력으로 기존 테스트데이터 저장 흐름을 통해 저장. 정답 PNG 미리보기 제공 |
| 학생 제출 이미지 미리보기·차이 이미지 | 미구현. 플러그인은 채점 서버의 학생 표준 출력·작업 폴더를 읽을 수 없어 채점기/엔진 쪽 변경이 선행되어야 함 |
| 별도 실행 서버·번호 등록부·이미지 큐 | 추가하지 않음 |

`judge_client`에 이미지 비교 알고리즘을 넣지 않는다. 표준 출력 PNG 방식은 기존 3인자 SPJ 계약을 재사용한다. 설치 서버가 바이너리 stdout과 테스트데이터를 보존하는지 먼저 검증하고, 실제로 필요한 이미지 보관·장애 분류 연동만 별도 최소 변경으로 다룬다.

## 3. 데이터 경계

- `.out` 파일명이 아니라 PNG 내용으로 판별한다. JPEG의 확장자 변경은 형식 변환이 아니다.
- `.in`은 학생 입력이다. 이미지 처리 입력 문제에서만 PNG 입력으로 사용할 수 있다.
- 학생 출력에는 실제 PNG만 허용한다. 안내 문구·경로·Base64 점수 주장을 신뢰하지 않는다.
- 텍스트 `.out`은 PNG의 전송 포장이다. Base64를 해제한 뒤 픽셀을 비교한다.
- 실행 실패·시간 초과는 기존 실행기가 먼저 판단한다. 남아 있는 별도 이미지 파일로 실행 실패를 정답으로 바꾸지 않는다.
- 정답과 SPJ는 학생 실행 영역에서 보호해야 한다. 전체 문제 데이터 폴더가 학생에게 노출되는 실행 설정으로는 운영하지 않는다.

## 4. 비교 기준

기본 프로필은 같은 크기·좌표에서 RGB 채널 차이를 검사한다. 작은 색상 차이는 허용하지만 불일치 픽셀 허용 수는 기본 0이다. 공간 반경은 기본 0으로 위치 자동 보정은 하지 않는다. 옵션 반경 1·2는 인접 색상을 양방향으로 검사하되 그 범위의 위치 이동도 허용한다는 점을 명시한다.

- PNG 압축·부가정보·코드 작성 순서를 정답 조건으로 사용하지 않는다.
- 같은 최종 픽셀을 만드는 다른 코드 순서를 허용한다. 겹침 순서가 실제 색·가림 관계를 바꾼 경우는 별개다.
- 렌더링 환경·폰트·캔버스·DPI·색공간을 고정한다. 허용 오차만으로 모든 안티앨리어싱 차이를 제거할 수 있다고 보장하지 않는다.
- 흰 배경이 많아 유사도가 높아지는 방식의 단일 비율 판정은 쓰지 않는다.
- 의미상 같은 그래프 데이터, 텍스트 라벨 또는 특정 API 사용 여부를 이미지 비교만으로 증명하지 않는다.
- 정답/오답 예제와 미사용 검증 예제를 나누어 임계값을 점검한다. 유사도 수치를 문제 점수로 직접 변환하지 않는다.

## 5. 오류·성능 기준

학생 실행 시간과 SPJ 비교 시간을 구분한다. SPJ는 파일·해상도·압축 해제·메모리·실행 시간에 상한을 둔다. 정답 파일은 운영 전에 사전 검사한다.

원본 HUSTOJ의 SPJ 반환 규칙에는 별도 인프라 오류 상태가 없다. 이번 SPJ는 `CHECKER_ERROR` 로그와 종료 코드 3으로 구분하지만 원본 엔진 화면은 RE로 표시한다. 이를 학생 오류로 간주해 점수에 확정 반영하지 않도록 운영 확인이 필요하다. 수동 확인/시스템 오류 상태 연계는 후속 엔진 보강 항목이다.

비교기 테스트는 PNG 해독과 비교 시간을 분리해 기록한다. Matplotlib/turtle 실행·샌드박스 준비·대기·동시 제출 비용은 별도 실환경 인수로 측정한다. 현재 Windows 실행 정책 차단으로 전체 회귀·벤치마크는 완료되지 않았으므로 성능 수치를 보장하지 않는다.

## 6. 후속 순서

1. Linux에서 SPJ 회귀 테스트와 정답/오답 모음 실행.
2. 기존 HUSTOJ에서 `in/out + spj`로 Matplotlib 실제 제출·재채점 확인.
3. 정답 접근 차단, 출력·자원 제한, 비교기 장애 처리 확인.
4. turtle 출력 어댑터를 동일한 표준 출력 PNG 계약으로 검증.
5. 필요 시 이미지 보관·권한 기반 미리보기·관리자 문제 설정을 선택 기능으로 연결.
6. 기존 수업·대회·순위·통계가 같은 제출번호와 판정을 사용하는지 실환경 인수.

## 7. 플랫폼 연동 구현 현황 (2026-10-05)

플러그인 쪽 연동은 구현했고 PHP 단위 검사로 확인했다. 래퍼 코드는 로컬 Python 3.14(Pillow·Matplotlib)에서 실제로 실행해 표준 출력이 PNG만으로 이루어지는지, 같은 코드가 실행마다 같은 PNG를 내는지, `tkinter`가 없어도 같은 결과인지 검증했다(`tests/Unit/visual-grading.php`).

운영 흐름:

1. 문제 편집에서 이미지 채점 방식을 고르고 저장한다(특수 채점기 자동 활성, Python 3 단일 언어 필요).
2. 테스트데이터 화면의 "이미지 채점" 패널에서 이미지 채점기를 설치·컴파일한다(기존 SPJ 컴파일 작업 사용, 샌드박스·컴파일러 프로필 필요).
3. 정답 이미지를 만든다. 방법 A(권장): 패널의 "정답 캡처 시작"을 누르고 10분 안에 모범 답안을 일반 제출 화면으로 제출하면, 채점 환경이 만든 PNG를 SPJ가 정답 후보로 저장하고 패널에서 미리보기 후 "정답 이미지로 적용"한다. 방법 B: 출제자 풀이를 앞·뒤 코드 사이에 넣어 서버와 같은 Python 환경에서 직접 실행하고 표준 출력 PNG를 업로드한다.
4. 학생 제출에는 자동으로 비공개 앞·뒤 코드가 붙어 그림이 PNG로 출력되고 SPJ가 비교한다.

정답 캡처 동작:

- 서버에 한 번만 캡처 폴더를 만든다: 데이터 루트 아래 `_capture`를 `www-data:judge` 소유, 모드 `2775`로 만든다(패널에 실제 경로와 명령이 표시된다). 문제 폴더에는 채점기 쓰기 권한이 필요 없고, 정답 `.out`·`spj`는 계속 읽기 전용이다.
- 캡처 시작은 문제 폴더에 `capture-armed.txt` 표식을 쓰고 이전 후보를 지운다(기존 테스트가 없으면 `capture-tmp.in/.out` 임시 쌍도 만든다). 표식은 10분 안에서만 유효하다.
- 모범 답안은 일반 제출 흐름으로 들어가 `solution`·소스가 기록된다. 플러그인은 solution 테이블을 따로 건드리지 않는다.
- 표식이 있을 때 SPJ가 학생 출력 PNG를 검증한 뒤 `_capture/<문제번호>.txt`(`OJ_IMAGE_CAPTURE_V1 <테스트이름>` + Base64 포장, 0644)로 저장하고 AC로 끝난다. 후보가 표식보다 새것이면 그 표식은 사용된 것으로 보고 일반 비교만 한다. 표식이 없거나 만료되어도 일반 비교만 한다.
- 플러그인이 `_capture`의 후보를 읽어 검증·미리보기하고, 적용하면 `<이름>.in/.out`을 문제 폴더에 저장한 뒤 후보·표식·임시 쌍을 지운다. 취소 버튼으로도 정리한다. 후보를 문제 폴더로 옮기는 주체는 SPJ가 아니라 플러그인이다.
- SPJ는 `_capture` 폴더가 있으면 마지막 판정(AC/WA 사유·크기·불일치 픽셀 수/채점기 오류)을 `_capture/<문제번호>.last.txt`에 남기고, 이미지 채점 탭이 "채점기 마지막 판정"으로 풀어서 보여준다. 기록 실패는 판정에 영향을 주지 않는다.
- 픽셀 불일치로 거절된 마지막 제출 이미지는 `_capture/<문제번호>.actual.png`에 보관하고(정답 처리되면 삭제), 판정 기록에는 테스트 이름·차이 범위(`diff_bbox`)·최대 색 차이(`max_delta`)가 들어간다. 탭에서 정답·제출·겹쳐 보기(차이 블렌드)를 나란히 보여준다. 보관 이미지는 가장 최근 제출 하나뿐이라 동시 제출 시 다른 학생의 이미지가 보일 수 있고, 관리자 화면에서만 볼 수 있다.
- 비교 기준(색 허용치)은 문제 폴더의 `image-spj-settings.txt`(`color_tolerance=N`, 0~96, 기본 16이면 파일 없음)로 문제별 조정한다. 파일은 관리자 화면에서만 쓰이며 SPJ가 판정 때 읽고, 형식이 틀리거나 96을 넘으면 `settings_invalid`로 채점기 오류를 낸다. 위치 반경과 허용 불일치 픽셀 수는 설정하지 않는다(마커 하나가 약 50픽셀이라 구분되지 않고, 반경은 틀린 그림을 통과시킨다). 연한 색 요소가 있는 그림은 64 이하를 권한다.
- 학생 코드가 `_capture`에 가짜 후보를 써도 관리자가 미리보기를 확인하고 적용해야 정답이 바뀐다.

제약:

- 학생 코드가 `exit()`로 먼저 끝나거나 예외가 나면 뒤 코드가 실행되지 않아 PNG가 없다(오답 또는 런타임 오류).
- 앞 코드가 맨 위에 붙으므로 `from __future__ import ...`는 학생 코드에서 사용할 수 없다.
- 앞·뒤 코드는 제출 크기 제한(제출 설정의 최대 소스 크기)에 포함된다. 래퍼 정책 변경은 새 제출부터 적용된다.
- turtle 렌더링은 Pillow 기본 글꼴·선 그리기에 의존하므로 정답 PNG는 채점 서버와 같은 Pillow 버전에서 만들어야 한다.
- 플러그인에 내장한 `resources/features/image-spj/spj.cpp`는 `node tools/image-spj/build.mjs`의 산출물(`build/image-spj/spj.cpp`)을 복사한 것이다. 비교기를 고치면 다시 생성해 복사해야 한다.
- XML 가져오기는 이미지 채점 설정을 싣지 않는다. 같은 문제를 다시 가져오면 조건(특수 채점기, Python 3 단일 언어)이 맞는 경우에만 기존 설정을 유지한다.

아직 하지 못한 일:

- 실제 HUSTOJ 서버에서의 SPJ 설치·실행, 표준 출력 바이너리 보존, 정답 접근 차단 인수.
- 학생 제출 이미지 미리보기와 차이 이미지(엔진/SPJ가 결과를 플러그인이 읽을 수 있는 위치에 남겨야 함).
- 로컬 Windows 실행 정책으로 SPJ 실행 파일을 직접 돌려 보지 못했다. SPJ 입력으로 쓰이는 정답 포장 형식과 래퍼 출력 PNG는 PHP 쪽에서만 교차 검증했다.

현재는 플러그인 연동까지 구현한 상태이며 운영 서버 설치·실환경 인수를 완료한 상태가 아니다.
