# HUSTOJ 이미지 비교 SPJ

작성·검증 기록: 2026-10-05. 기존 HUSTOJ의 `spj 입력파일 정답파일 학생출력파일` 호출 규칙을 사용하는 C++17 비교기다. WordPress 플러그인이나 독립 실행 작업자가 아니며 DB·제출번호·대기열·공개 Addon API를 변경하지 않는다.

## 1. in, out 파일의 의미

| 파일 | 내용 |
| --- | --- |
| `case01.in` | 학생 프로그램이 읽을 입력. 보통 UTF-8 텍스트. 입력 없는 문제는 줄바꿈만 있는 파일도 가능 |
| `case01.out` | 정답 PNG 바이너리 또는 텍스트 PNG 포장 형식 |
| HUSTOJ의 학생 출력 파일 | 학생 프로그램의 표준 출력에 기록된 실제 PNG 바이너리 |
| `spj.cpp` / `spj` | 비교기 소스 / 컴파일한 실행 파일 |

PNG는 확장자가 아니라 파일 내부 형식으로 판별한다. **실제 PNG를 `.out`으로 이름만 바꾸어도 이 SPJ는 읽을 수 있다.** JPEG를 `.out`으로 바꾼다고 PNG가 되지는 않는다. `.in`을 이미지로 바꾸는 것은 학생 코드가 이미지 입력 자체를 읽는 문제에서만 의미가 있다. 그림 그리기 문제의 일반 입력을 정답 이미지로 대체하지 않는다.

현재 OJ Platform의 `RootOnlyProblemFileManager` 및 ZIP 업로드는 `.in`·`.out`을 UTF-8 텍스트로 검증한다. 따라서 원본 PNG를 `.out`으로 바꾸기만 하면 콘솔 업로드에서 거부된다. **콘솔에서는 `prepare-reference.mjs`의 기본 text 모드를 사용한다.** 서버 데이터 폴더로 바이너리 파일을 직접 배치하는 경우에는 binary 모드를 사용할 수 있다. 이번 작업은 플랫폼 파일 관리자의 기존 보안 규칙을 변경하지 않았다.

```text
OJ_IMAGE_PNG_BASE64_V1
<정답 PNG의 Base64 데이터>
```

텍스트 포장은 전송용이다. SPJ는 Base64를 해제하고 PNG를 픽셀로 해독해 비교하며 문자열이나 파일 해시를 비교하지 않는다. LF·CRLF를 모두 지원한다. 이 포장 형식은 학생 출력에서는 허용하지 않는다.

## 2. 빌드와 설치

저장소 루트에서 단일 소스 생성:

```sh
node tools/image-spj/build.mjs
```

생성 파일: `build/image-spj/spj.cpp`. 프로필, 비교기, 고정 버전 LodePNG를 한 파일에 포함하므로 비교기에 Python·SciPy·OpenCV·추가 PNG 개발 패키지가 필요하지 않다. C++17 컴파일러만 필요하다. 학생 코드 실행에 필요한 Python·Matplotlib·Tk 등은 별개다.

Linux 서버 컴파일 예:

```sh
g++ -std=c++17 -O2 -pipe -s spj.cpp -o spj
```

플랫폼의 테스트데이터 화면에서는 생성된 `spj.cpp`를 등록하고 기존 SPJ 컴파일 기능을 사용할 수 있다. C++17 기본 컴파일 인자와 호환된다. 실제 서버의 컴파일 샌드박스 인수는 아직 수행하지 않았다.

컴파일한 `spj`는 해당 문제의 데이터 폴더인 `$OJ_HOME/data/<문제번호>/spj`에 배치하고 문제에서 특수 채점을 활성화한다. 실행 권한은 기존 SPJ 운영 규칙에 따른다. 같은 문제에 다른 `tpj`·`upj`가 있으면 HUSTOJ가 그 파일을 우선 호출할 수 있으므로 기존 판정기와 혼용하지 않는다. 운영 파일을 자동 삭제하거나 덮어쓰는 설치기는 제공하지 않는다.

## 3. Matplotlib 사용 예

`examples/matplotlib_stdout.py`는 입력 숫자를 그래프로 그려 PNG를 표준 출력으로 내보낸다. 동일한 렌더링 환경에서 정답을 생성한다.

```sh
python3 tools/image-spj/examples/matplotlib_stdout.py \
  < tools/image-spj/examples/case01.in > reference.png
node tools/image-spj/prepare-reference.mjs reference.png case01.out
./spj --check-reference case01.out
```

변환 도구는 대상 파일이 이미 있으면 실패한다. `--check-reference`는 CRC·압축 내용·크기까지 검사한다. 변환 도구의 헤더 확인만으로 정답 파일 검증을 대신하지 않는다. 콘솔 ZIP 업로드의 개별/전체 파일 제한은 별도로 적용된다.

해당 문제에 `case01.in`, `case01.out`, `spj.cpp`와 컴파일된 `spj`를 등록한다. 학생 프로그램도 **PNG만 표준 출력으로 출력**해야 한다.

```python
import sys
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

# 문제에서 요구한 그래프를 그리는 학생 코드

plt.savefig(sys.stdout.buffer, format="png", facecolor="white", transparent=False)
sys.stdout.buffer.flush()
```

`plt.show()`만 호출하거나 `result.png` 파일만 생성하면 표준 출력 PNG가 없어 오답이다. `print()`로 안내 문구를 섞어도 오답이다. 디버그 출력이 필요하면 stderr를 사용한다. PNG 앞뒤의 다른 바이트는 허용하지 않는다.

플랫폼의 앞·뒤 코드 기능으로 출력 부분을 제공할 수 있으나 **이번 변경은 이를 자동 설정하지 않는다.** turtle도 최종 캔버스를 PNG로 변환해 표준 출력으로 전달하는 별도 출력 코드가 필요하다. 이 SPJ 자체는 Python 실행, `show()` 가로채기, Tk 캡처 또는 이미지 보관을 수행하지 않는다.

이 방식은 HUSTOJ가 테스트마다 표준 출력 파일을 새로 만들기 때문에 별도 `result.png`의 잔존 파일을 읽지 않는다. HUSTOJ가 stdout을 바이너리 그대로 보존하는 실제 실행 경로인지는 운영 서버에서 인수해야 한다. HTTP 데이터 다운로드·문자열 변환 경로도 환경별 확인이 필요하다.

## 4. 비교 기준

`src/profile.hpp`를 수정하고 단일 소스를 재생성한다. 생성된 `spj.cpp` 앞부분에서도 같은 매크로를 확인할 수 있다. 설정은 비교기에 포함되며 학생 출력에서 읽지 않는다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `OJ_IMAGE_COLOR_TOLERANCE` | 16 | RGB 각 채널의 최대 허용 차이. 0이면 색상 완전 일치 |
| `OJ_IMAGE_SPATIAL_RADIUS` | 0 | 인접 색상 탐색 반경. 0이면 같은 좌표만 비교 |
| `OJ_IMAGE_MAX_UNMATCHED_PIXELS` | 0 | 각 방향에서 허용하는 불일치 픽셀 수. 기본은 하나라도 있으면 오답 |

- 8비트 이하 정적 PNG를 RGBA로 해독하고 흰 배경에 알파 합성한다. 팔레트·회색조 PNG도 지원한다.
- 크기가 다르면 오답이다. 자동 확대·축소·회전·정렬을 하지 않는다.
- 기본 프로필은 색상 차이만 허용한다. 안티앨리어싱 변화가 항상 16 이하라는 보장은 없다. 정상·오답 모음으로 문제별 검증해야 한다.
- 반경 1 또는 2는 해당 범위의 위치 이동도 허용한다. 위치가 평가 대상인 문제에 안티앨리어싱 보정이라는 이유만으로 활성화하지 않는다.
- 반경 사용 시 양방향의 인접 색상 존재를 확인한다. 일대일 도형 대응이나 선 개수·좌표의 의미 분석은 아니므로 가까운 중복 선 등이 허용될 수 있다.
- 전체 흰 배경을 분모로 한 유사도 비율을 사용하지 않는다. 기본 허용 수가 0이므로 배경 위 검은 점 하나의 누락·추가도 검출한다.
- RGB 색상 프로필·감마 메타데이터는 해석하지 않는다. 렌더러·폰트·DPI·색공간을 고정한다. 16비트 PNG·APNG는 거부한다.
- 코드 순서가 달라도 최종 픽셀이 같으면 통과한다. 가림 순서가 실제 그림을 바꾸면 비교 기준에 따라 실패한다.
- 유사도를 점수로 변환하지 않는다. 그래프의 데이터 의미, 라벨 문자열 또는 특정 API 사용 여부를 증명하지 않는다.

## 5. 제한과 오류 처리

- PNG 최대 8 MiB, 정답 텍스트 포장 최대 12 MiB, 가로·세로 최대 2048, 최대 4,194,304픽셀.
- 크기·CRC·PNG 종료·단일 정적 이미지 형식을 검사한 뒤 해독한다. 압축 해제와 메모리 할당에도 상한을 적용한다.
- Linux에서는 정규 파일만 읽고 심볼릭 링크·FIFO를 거부한다. 학생이 지정한 임의 출력 경로나 설정 파일을 읽지 않는다.
- Linux 비교기 자체에는 주소 공간 256 MiB, CPU 3초, 실제 경과 5초 상한을 적용한다. 부모의 더 작은 제한은 늘리지 않는다. Windows에서는 이 POSIX 제한을 검증하지 못한다.
- 학생 실행 종료 후 신뢰된 실행자가 제공한 파일만 비교해야 한다. 정답 파일과 SPJ 바이너리를 학생이 읽거나 수정하지 못하게 하는 것은 HUSTOJ 실행 환경의 책임이다. 이 SPJ만으로 샌드박스가 완성되지는 않는다.

| 종료 코드 | SPJ 의미 | 원본 HUSTOJ 표시 |
| --- | --- | --- |
| 0 | 이미지 통과 | AC |
| 1 | 출력 누락·형식 위반·불일치 | WA |
| 3 | 정답 파일 손상·비교기 내부 오류 | RE |

**중요:** 원본 HUSTOJ에는 SPJ의 인프라 오류를 별도 상태로 연결하는 규칙이 없어 3을 RE로 표시한다. stderr에 `CHECKER_ERROR`를 남기지만 RE만으로 학생 책임인지 구분할 수 없다. 운영 전 모든 정답을 사전 검사하고, `CHECKER_ERROR`는 관리자 확인 대상으로 처리해야 한다. 별도 시스템 오류/수동 확인 상태 연계는 이번 작업에 포함되지 않았다. 원본 HUSTOJ가 자식 프로세스를 강제로 종료하면 WA로 처리할 수도 있으므로 장애 인수는 필수다.

## 6. 테스트와 성능 측정

저장소 루트에서 실행:

```sh
node tools/image-spj/tests/regression.mjs g++
```

정상·오답·PNG 손상·크기 제한·텍스트 포장·색상/공간 프로필·정답 사전 검사를 수행한다. Linux에서는 추가 프로필과 링크 거부도 검사한다. Windows 추가 프로필은 `--profiles`로 지정할 수 있으나 실행 정책이 막으면 정책을 우회하지 않는다.

완료 시 `build/image-spj/test-results.json`에 512·1024·2048 크기의 단일 프로세스 반복 측정 결과를 기록한다. `decode_ms`, `compare_ms`, `total_ms`는 비교기 내부 시간이며 Python 시작·렌더링·대기열 시간은 아니다. 동시 제출 성능은 별도 인수 대상이다.

2026-10-05 로컬 확인: 기본·색상 엄격·반경 1 프로필 C++17 빌드가 경고를 오류로 처리한 상태에서 통과했다. 최초 실행에서 기본 프로필의 9개 검사(동일 PNG, 압축·부가정보, RGB/회색조, 텍스트 포장/LF·CRLF, 투명 배경, 색상 경계)를 통과했다. 이후 Windows 애플리케이션 제어가 실행 파일을 차단하여 전체 회귀와 성능 측정은 완료하지 못했다. `tests/tooling.mjs`의 변환·덮어쓰기 방지·소스 생성 등 8개 독립 검사는 모두 통과했다. 최종 소스 빌드, JavaScript 5개 파일 문법, Python 예제 문법, UTF-8/BOM 검사도 통과했다. Linux HUSTOJ 연동, POSIX 제한, 실제 Matplotlib/turtle 실행, 운영 콘솔 등록은 미검증이다. 운영 사용 승인이나 배포 완료를 뜻하지 않는다.

## 7. 범위

이번 산출물은 **전용 SPJ 소스·단일 파일 생성 도구·정답 변환 도구·예제·테스트**다. 실제 서버에 설치하거나 기존 문제 설정을 변경하지 않았으며 플랫폼 패키지 버전도 변경하지 않았다. PNG 미리보기·차이 이미지 보관·자동 출력 래퍼·turtle 캡처는 후속 연동 범위다.
