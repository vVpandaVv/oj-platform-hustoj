A-D-002 · Screen and Entry-Point Baseline

화면과 진입 경로

현재 애드온의 브라우저 화면, 메뉴, REST, form, hook, shortcode와 예약 작업을 실제 등록 코드에서 추적했다. 이 문서는 목표 UI 상세 설계가 아니라 현재 진입 표면과 담당 클래스·권한·두 shell 통합 격차를 고정한다.

조사일 2026-08-10 상태 dev.26 재점검 완료·최종 확인 대기 기준 oj-platform 2.0.0-dev.26 REST 73경로·85작업 PublicUI 등록 0건 실행 코드 변경 0건

한 줄 판정

현재 코드는 11개 관리 shell 화면과 73개 REST 경로를 갖지만, 재정비 플랫폼에서 실제 OJ Console로 등록되는 경로는 0개이고 PublicUI 기여도 0개다. 학생 기능은 관리자 shell과 14개 shortcode 경로에 분산되어 있으므로, 상세 설계에서는 관리·교사 진입점을 C-28 Console 기여로 교체하고 학생 진입점을 PublicUI 기여로 이동해야 한다.

조사 기준: 등록 호출이 소스에 있다는 사실과 조사 대상 oj-platform 2.0.0-dev.26에서 실제 연결된다는 사실을 구분했다. 존재하지 않는 구형 hook을 기다리는 11개 Console 후보는 “코드상 후보 11, 현재 실제 등록 0”으로 센다. 2026-08-12 플랫폼 AM-01 구현은 이 역사적 수량을 바꾸지 않으며 목표 연결만 onReady() 계약으로 보정한다.

확정 결정

  1. 교사·관리자 기능은 OJ Console의 학습 공간 > AI 활동지로 통합하고, 학생 기능은 PublicUI의 학습 > 활동지로 분리한다.
  2. 학급·그룹·사용자 원장은 OJ Platform을 기준으로 하며 애드온은 별도 그룹 관리 체계를 만들지 않는다.
  3. 활동지 템플릿 가져오기는 활동지 영역에, 이전 설치 데이터 가져오기는 설정의 데이터 이전 영역에 둔다. 학생 명단 가져오기는 애드온 목표 기능에서 제거한다.
  4. 실행 환경과 플랫폼 연결 화면은 애드온 설정의 연결 및 진단으로 합친다.
  5. AI 연결 프로필·비밀값·모델 및 fallback 작업 배정은 OJ Platform이 소유한다. 애드온은 평가 정책·루브릭·검토 및 공개 기준과 실제 평가 실행을 소유한다.
  6. 플랫폼의 AI 작업 배정은 활동지 자체 평가와 학생 제출 평가에 사용할 provider·model routing 행이며, 평가 업무 화면은 아니다.
  7. 활동지 자체와 학생 제출 답안을 서로 다른 평가 대상으로 제공한다.
