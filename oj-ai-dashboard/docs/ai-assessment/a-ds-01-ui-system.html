A-DS-01 · Shared Console and Public UI System

공통 사용자·관리자 UI 시스템

OJ Console의 교사·관리자 업무와 PublicUI의 학생 업무를 플랫폼 셸 안에 네이티브로 배치하고, 활동지 제작부터 공개 결과까지 같은 상태 언어와 행동 규칙을 사용하도록 화면 체계를 확정한다. 정확한 Route·capability·API key는 후속 단계로 넘기며 업무 runtime은 구현하지 않는다.

한 줄 결론

교사는 OJ Console의 학습 공간에서 AI 활동지, 활동지 배포, AI 평가, 활동지 보고서, AI 평가 설정 다섯 업무를 바로 열고, 학생은 PublicUI의 학습 > 활동지에서 할 일·제출함·결과만 사용한다.

UI 경계: 플랫폼은 전역 탐색·사용자·breadcrumb·셸·접근 거부를 렌더링하고, 애드온은 셸 내부의 페이지 제목·로컬 탐색·업무 상태·폼·표·Plate·결과 화면만 렌더링한다. 애드온이 두 번째 관리자 셸이나 전역 헤더를 만들지 않는다.

배포발행본 선택 → 플랫폼 수업·그룹 선택 → 시작·마감과 제출 정책 → 최종 확인 → 예약 또는 시작발행된 PublishedWorksheetRevision과 AssignmentTargetSnapshot을 고정한다. 명단이 stale이면 시작하지 않으며 이미 시작한 배포가 새 발행본으로 자동 이동하지 않는다.한 활동지에 여러 배포 건을 만들 수 있고 각 건의 대상·일정·제출 상태를 독립 추적한다.

학생 제출 평가제출 확인 → AI 평가 → 교사 검토·조정 → 결과 확정 → 공개OfficialSubmissionRevision과 채점 기준 snapshot을 사용한다. AI 점수는 후보이며 교사 확정 전 학생에게 보이지 않는다.확정 결과만 공개 대기로 이동하고 공개된 결과는 정정·철회 이력을 남긴다.
보고서활동지별(기본)·수업·그룹별·학생별 중 기준 선택 → filter → 집계 확인 → 출력 생성활동지별은 활동지를 먼저 고르고 전체 배포 또는 특정 배포 건으로 내려간다. 수업·그룹별은 여러 활동지를 비교하고 학생별은 담당 권한 안의 공개·확정 결과만 조회한다.선택한 기준·filter·source snapshot을 기록한 PDF·CSV·ZIP artifact를 만든다.
보고서 drill-down: 활동지 → 배포 건 → 학생 제출 순서를 유지한다. 같은 활동지가 여러 수업·그룹에 배포되었을 때 전체 합계와 배포 건별 결과를 모두 볼 수 있지만 서로 다른 마감·대상을 설명 없이 한 건처럼 합치지 않는다.
탐색 단순화: 개요는 별도 메뉴로 만들지 않고 A-DS01-C01 위쪽의 짧은 현황으로 합친다. 작업함은 A-DS01-C04의 검토 대기 목록으로 합치고 헤더 알림은 그 필터로 바로 연결한다. 설정은 일상 업무 탭에서 빼고 권한 있는 사용자에게 톱니바퀴 아이콘으로 제공한다.
설정 소유권: A-DS01-C06에는 provider key·endpoint·model routing 편집기를 만들지 않는다. 플랫폼의 운영 > AI 연결 프로필과 운영 > AI 작업 배정 상태를 읽기 전용 요약·진단으로 보여 주고, 권한 있는 운영자에게 플랫폼 화면 링크만 제공한다.
가져오기 위치: 활동지 템플릿 가져오기는 A-DS01-C01의 보조 명령, 이전 설치 데이터는 A-DS01-C06의 데이터 이전 탭에 둔다. 학생 명단·학년·그룹 관리 화면은 만들지 않는다.
