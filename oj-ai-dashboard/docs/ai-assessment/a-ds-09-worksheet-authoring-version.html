활동지 제작과 버전

Plate 교사용 문서를 활동지 콘텐츠의 단일 정본으로 삼고, 학생 화면·응답 schema·채점·활동지 자체 평가·인쇄를 검증된 projection으로 만든다. 저장할 때마다 새 revision을 남기며 발행본은 이후 편집이나 배포와 분리된 불변 snapshot이다.

Stable ID·정규화·hash

  1. 문서, block node, response, option, 표 row·column, asset은 A-DS-08의 26자 PublicIdV1을 사용한다. 내부 auto increment PK를 JSON이나 URL에 넣지 않는다.
  2. 브라우저가 새 항목을 만들 때는 tmp_ prefix의 session-local UUID를 사용한다. 최초 저장 명령에서 서버가 stable ID를 발급하고 temporary_id_map을 응답한다.
  3. 이동·문구 수정·다음 revision에서는 ID를 유지한다. 복제·붙여넣기·다른 활동지로 가져오기는 새 ID를 발급해 기존 학생 답안과 연결되지 않게 한다.
  4. 서버는 Unicode NFC, 허용 property, 정렬된 object key, 배열의 의미 순서, decimal string을 사용해 canonical JSON을 만들고 UTF-8 byte에 SHA-256을 계산한다.
  5. 빈 optional 값은 schema에 따라 null 또는 property 부재 중 하나만 사용한다. 빈 문자열·0·빈 배열을 “없음”과 혼용하지 않는다.
  6. unknown node·property·mark, 중복 ID, 끊어진 asset·rubric reference는 저장 전 오류다. default paragraph나 첫 option으로 조용히 바꾸지 않는다.

Draft·revision·승인·발행

브라우저 편집 buffer
  → C02 save-draft(expected current revision, idempotency key)
  → 새 immutable draft revision + 질문 index + achievement links + asset owner receipt
  → C05 validate(exact revision)
  → C10 활동지 자체 평가(exact saved revision)
  → 교사 판단·필수 blocker 해소
  → C06 approve(exact draft revision, content hash 불변)
  → C07 publish(exact approved revision)
  → immutable publication + student/response/grading/print snapshot
  → 배포는 publication public ID + hash 고정
단계서버 동작불변성·충돌 규칙제품 상태
