한 줄 판정

애드온은 독립 WordPress 플러그인으로 배포하되 관리자·교사 기능은 OJ Console에, 학생 기능은 PublicUI에 네이티브로 통합한다. 현재 플랫폼에는 외부 애드온이 두 shell의 메뉴와 경로를 등록할 공개 계약이 없으므로, 범용·버전형 애드온 확장 API가 포함된 플랫폼 선행 버전이 필요하다.

확정 경계: 애드온 설치·업데이트·런타임은 oj-platform 파일을 패치하지 않는다. 플랫폼의 범용 확장 API는 별도 플랫폼 변경과 릴리스로 제공하고, 애드온은 그 공개 계약만 사용한다. 운영 데이터 쓰기는 무접두어 oj_ai_* 저장소로 제한한다.

WordPress 역할·capability관리자 및 oj_ai_teacher, oj_ai_student, 선택적 assistant 역할 변경애드온 capability만 관리하며 플랫폼 역할 정의를 직접 변경하지 않음

A-D-001 확정 계약

  1. A-D001-C01: 제품 코드 수정 범위는 oj-ai-dashboard 하나로 제한한다.
  2. A-D001-C02: 애드온 설치·업데이트·런타임은 oj-platform 파일, config, migration, schema와 운영 데이터를 수정하지 않는다. 범용 확장 API는 별도 플랫폼 작업과 릴리스로만 제공한다.
  3. A-D001-C03: 애드온 물리 테이블은 WordPress prefix 없이 고정 oj_ai_* 이름을 사용한다.
  4. A-D001-C04: 플랫폼·Judge 원본에는 쓰지 않는다. 사용자·학급·그룹은 플랫폼 공개 gateway를 원장으로 사용하며 추측 기반 table fallback을 허용하지 않는다.
  5. A-D001-C05: 플랫폼 내부 class, Composition Root, container와 동결 Registry를 런타임 의존 계약으로 사용하지 않고 공개 Registration 계약과 애드온별 AddonRuntimeContextV1만 사용한다.
  6. A-D001-C06: 관리자·교사 기능은 OJ Console, 학생 기능은 PublicUI의 네이티브 메뉴·경로 통합을 필수로 한다. 두 기여를 manifest에서 별도 선언하며 별도 WordPress 관리자 메뉴나 독립 사용자 shell로 폴백하지 않는다. 필요한 범용·버전형 확장 API가 없는 플랫폼에서는 애드온 실행을 차단한다.
  7. A-D001-C07: AI 연결 프로필·자격 증명·모델 및 fallback 작업 배정은 플랫폼이 소유한다. 애드온과 Plate 브라우저는 비밀값이나 Provider를 직접 사용하지 않고 공개 AI task gateway만 호출한다.
  8. A-D001-C08: 활동지 자체 평가와 학생 제출물 평가는 별도 Use Case, AI 계약과 저장 이력을 가진다.
  9. A-D001-C09: 기존 데이터 이전은 설치·일반 실행과 분리하며 preview와 명시적 승인 없이 변경하지 않는다.
