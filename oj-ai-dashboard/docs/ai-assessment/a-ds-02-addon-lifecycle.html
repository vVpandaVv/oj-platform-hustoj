애드온 생명주기와 플랫폼 연결

AI 평가 애드온을 OJ Platform 설치 이후 활성화하는 독립 WordPress 플러그인으로 유지하면서, 플랫폼 Registry 동결 전에 하나의 Manifest와 애드온별 onReady() callback을 원자 등록하고 승인 뒤에는 전달받은 제한된 Runtime Context만 사용하는 소비자 계약을 확정한다. 플랫폼 코드·설정·migration을 애드온이 수정하는 방식은 허용하지 않는다.

한 줄 결론

플러그인 파일 로드 시 oj_platform_register_addons callback 하나를 선언한다. 그 안에서 전체 기여와 onReady(AddonRuntimeContextV1)를 같은 Manifest builder에 등록한다. 플랫폼은 승인된 이 애드온에 자기 Runtime Context만 전달하되 공개 계약의 보장은 최대 한 번이며, Runtime Context 생성과 callback 진입이 정상일 때 한 번 호출된다.

부팅과 등록 순서

1 · Root 파일 로드
autoload와 WordPress lifecycle hook, priority 0 Runtime bootstrap만 선언한다. 플랫폼 API interface를 구현하는 Page Handler는 아직 로드하지 않는다.
2 · 애드온 내부 조립
모든 활성 플러그인 파일이 준비된 plugins_loaded priority 0에서 Addon API 1.1 공개 symbol 전체를 확인한 뒤 Composition Root를 한 번 조립하고 Bridge를 unavailable 상태로 주입한다.
3 · 등록 창
플랫폼이 Registry 동결 전에 oj_platform_register_addons을 발행하면 Registrar가 builder 안에서 Manifest 전체를 작성한다.
4 · 원자 판정
플랫폼은 애드온 ID·버전·key·path·참조·충돌을 검증하고 전체를 accepted 또는 전체를 rejected로 결정한다.
5 · Catalog 동결
승인된 Route·Menu·Asset·capability·AI task가 core와 읽기 전용으로 합성되고 추가 등록은 닫힌다.
6 · Runtime 준비
플랫폼이 accepted된 이 애드온의 onReady()를 전용 AddonRuntimeContextV1과 함께 최대 한 번 호출한다. callback에 진입하면 snapshot을 확인하고 Context·AI adapter를 원자 연결한다.
7 · 요청 처리
화면 handler와 애드온 REST는 공통 Policy를 사용하며 context·AI가 필요할 때 주입된 공개 Gateway로만 요청한다.
// 공개 계약 형태를 설명하는 소비자 의사 코드다.
add_action('oj_platform_register_addons', [Addon_Integration::class, 'register'], 10, 1);

// register()는 gateway.register('oj-ai-dashboard', builder) 안에서 Manifest와
// onReady(AddonRuntimeContextV1)를 함께 선언한다. Runtime 기여 추가는 금지한다.
순서 제한: 지연 부트는 플랫폼이 문서화한 plugins_loaded priority 1보다 앞선 priority 0만 사용한다. priority 1 이상에서 등록하거나 onReady()에서 Route를 추가하지 않는다. API symbol이 없으면 Composition Root를 만들지 않고 fail closed한다. Activation hook은 다음 정상 요청의 Catalog 결과를 미리 accepted로 간주하지 않으며 모든 handler는 애드온 Bridge ready를 별도로 확인한다.
A-DS-02-AM02 · 0.1.7 구현 보정: WordPress active plugin 정렬에서 oj-ai-dashboard가 oj-platform보다 먼저 포함될 수 있음을 production 로그로 확인했다. tests/Contract/plugin-load-order.php는 이 순서를 그대로 재현해 API 부재 비치명, full-contract guard, priority 0 단일 부트와 등록 hook 1개를 고정한다. 공개 action·Gateway·Manifest·onReady() signature는 변하지 않는다.
