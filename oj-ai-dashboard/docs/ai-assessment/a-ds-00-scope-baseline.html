A-DS-00 · Purpose, Scope and Baseline

목적·범위·기준선

AI 평가 애드온을 OJ Platform 설치 이후 활성화하는 독립 배포 애드온으로 정의하고, 활동지 제작부터 활동지 자체 평가, 학생 제출 평가, 교사 확정과 PDF까지 하나의 제품 범위로 고정한다. 이 문서는 상세 설계가 바꿀 수 없는 경계와 용어를 결정하며 아직 업무 runtime을 구현하지 않는다.

작성일 2026-08-10 A-D-001~009 사용자 확인·동결 상태 사용자 확인·동결 상세 설계 1/17 동결 A-DS-01 상세 설계 시작 업무 runtime 변경 0건

한 줄 결론

목표 제품은 OJ Console에서 교사가 Plate 활동지를 만들고 자체 AI 진단을 거쳐 발행·배포하며, PublicUI에서 학생이 작성·제출한 결과물을 별도 AI 평가와 교사 검토를 통해 공개하는 OJ Platform 필수 AI 평가 애드온이다.

고정 경계: 플랫폼은 사용자·학사 context·권한 배정·AI 연결과 공통 실행 기반을 제공하고, 애드온은 활동지·배포·제출·평가·검토·공개·PDF 업무를 소유한다. 애드온 설치·업데이트·실행은 플랫폼 파일·migration·DB를 패치하지 않는다.

제품 정의

  • 설치 형태: OJ Platform 설치 이후 별도 WordPress 플러그인 패키지로 설치·활성화하는 애드온이다.
  • 교사 경험: OJ Console 안에서 활동지를 제작·자체 평가·발행·배포하고 제출 평가를 검토·확정한다.
  • 학생 경험: PublicUI 안에서 자신에게 배정된 활동지를 조회·작성·제출하고 공개된 결과와 PDF를 확인한다.
  • AI 역할: 플랫폼이 선택한 AI 연결 경로를 통해 구조화된 진단·평가 후보와 근거를 생성한다.
  • 교사 역할: 활동지 발행, 평가 승인·수정, 학생 피드백 공개·정정의 최종 책임을 가진다.
  • 기록 역할: 어떤 활동지·학생 결과·정책·루브릭·AI 경로로 판단했는지 불변 snapshot과 이력으로 재현한다.

“AI 작업 배정”은 플랫폼 운영자가 연결 프로필과 모델 경로를 작업 종류에 매핑하는 공통 운영 기능이다. “학생 제출 평가”는 그 경로를 사용해 애드온이 소유하는 제출물을 평가·검토·공개하는 업무 기능이다. 메뉴 이름이 비슷해도 데이터와 책임은 합치지 않는다.

제품 수직 업무 흐름

활동지 초안 제작
교사가 OJ Console의 Plate 작업대에서 구조화된 활동지와 응답 블록, 교사용 기준을 작성하고 draft revision으로 저장한다.
활동지 자체 AI 평가
특정 draft revision을 학습목표 정합성·명료성·답변 가능성·난이도·루브릭 품질·안전성 관점으로 진단한다.
교사 수정·승인
교사는 근거와 개선안을 검토해 직접 수정하고 발행 가능한 상태인지 판단한다. AI가 문서를 자동 수정하거나 승인하지 않는다.
불변 발행
선택한 draft를 학생용·채점용·인쇄용 projection과 함께 불변 published worksheet revision으로 고정한다.
플랫폼 context 배포
교사가 담당하는 플랫폼 수업·학급·그룹·학생 범위에 발행 revision을 배정하고 대상 snapshot과 마감 정책을 기록한다.
학생 작성·제출
학생은 PublicUI에서 본인 배정을 열어 자동 저장하고, 충돌·마감·첨부 상태를 확인한 뒤 명시적으로 제출한다.
학생 제출물 AI 평가
확정 submission revision과 rubric revision을 별도 입력으로 평가해 점수 후보·근거·불확실성·검토 필요 항목을 만든다.
교사 검토·확정·공개
교사가 결과를 승인·수정·반려하고 공식 평가와 공개 revision을 만든 뒤 학생에게 점수·피드백을 공개하거나 정정·철회한다.
PDF·보고서
불변 worksheet/submission revision에서 권한이 적용된 PDF와 집계 projection을 비동기로 생성하고 감사 가능한 private artifact로 제공한다.

데이터와 쓰기 경계

  • 애드온 소유 물리 테이블은 WordPress prefix를 붙이지 않은 고정 oj_ai_* 이름을 사용한다.
  • 각 테이블은 정확히 한 모듈이 소유하고 해당 모듈의 Repository만 쓰기·조회를 수행한다.
  • 다른 모듈은 table·concrete Repository를 직접 호출하지 않고 명시적 application Contract를 사용한다.
  • 플랫폼 사용자·수업·학급·그룹·권한·AI profile을 애드온 master table로 복제하거나 양방향 동기화하지 않는다.
  • 플랫폼과 Judge 원본은 공개 Gateway를 통한 읽기만 허용하고 애드온에서 수정하지 않는다.
  • 활동지 발행, 학생 제출 확정, 평가 공식화, 학생 공개와 PDF source는 모두 불변 revision 또는 snapshot을 참조한다.
  • 설치·업데이트·migration은 플랫폼 파일·config·migration·schema·option을 변경하지 않는다.
  • 구체 목표 테이블·컬럼·인덱스·보존 기간은 A-DS-05에서 source 35개와 mapping한 뒤 확정한다.
