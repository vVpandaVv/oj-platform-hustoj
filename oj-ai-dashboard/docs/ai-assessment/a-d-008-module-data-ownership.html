A-D-008 · Module and Data Ownership Baseline

모듈·데이터 소유권

현재 12개 모듈의 조립 코드, 32개 구체 Repository, 35개 애드온 테이블과 플랫폼 연결을 다시 추적했다. 이름공간이 아니라 실제 생성·읽기·쓰기·JOIN 주체를 기준으로 소유자를 판정하고, 다른 모듈의 구현을 직접 참조하지 않는 목표 Contract 경계를 제안한다.

조사일 2026-08-10 상태 사용자 확인·기준선 확정 Module 12개 Service 30개 구체 Repository 32개 명시 Contract 2개 고정 테이블 35개 양방향 namespace 5쌍 경계 자동 검사 0개 실행 코드 변경 0건

한 줄 판정

현재 코드는 기능별 namespace를 갖췄지만 모듈 경계는 갖추지 못했다. 각 *_Module이 다른 도메인의 구체 Repository와 Service를 다시 생성하고, Dashboard와 Submission은 여러 소유 테이블을 직접 JOIN하며, Import는 대상 도메인의 저장소에 직접 쓴다. 목표 구조는 하나의 composition root, 모듈별 공개 application Contract, 테이블 단일 소유자, DTO 기반 교차 조회와 domain command 기반 쓰기로 전환해야 한다.

가장 큰 변경 확산 위험: Submission_Repository의 조회 한 건이 제출·과제·평가 결과·피드백·재평가·WordPress 사용자 schema를 동시에 알고, Report_Content_Builder는 11개 애드온 테이블을 직접 읽는다. 한 모듈의 column이나 상태 변경이 제출 화면과 모든 보고서에 즉시 전파된다.

확인할 목표 결정

  1. 구체 Repository·Service·adapter를 만드는 곳은 Core CompositionRoot 하나로 제한한다. 각 Module은 자기 application Contract와 registration descriptor만 제공하며 runtime service locator를 두지 않는다.
  2. 모든 oj_ai_* 물리 table에 정확히 한 owner를 부여한다. Repository는 owner module의 table만 읽고 쓰며, 다른 module의 Repository·table name·WordPress users table을 직접 참조하지 않는다.
  3. PlatformBridge는 C28의 등록·runtime gateway만 adapter로 감싼다. 플랫폼 파일·migration·Container·내부 Repository·DB·비밀 저장소를 읽거나 수정하지 않고, 자체 business table도 소유하지 않는다.
  4. 사용자·학년도·학급·그룹·담당·roster는 OJ Platform 원장만 사용한다. 현재 Academic 6개 table은 정상 업무 source에서 제외하고, A-DS-15의 명시적 legacy 이전·검증·보존·폐기 대상으로 둔다.
  5. Curriculum은 교육과정·성취기준 catalog를, Worksheet는 Plate 원문·문항·revision·발행 snapshot과 worksheet/question 성취기준 association을 소유한다. 교차 확인은 AchievementCatalogQuery로 수행한다.
  6. Submission은 assignment·target snapshot·학생 response revision·receipt·attachment·ZIP을 소유하고, PublishedWorksheetQuery와 PlatformContextPort만 소비한다. mutable Worksheet와 로컬 roster를 직접 읽지 않는다.
  7. Assessment는 활동지 자체 평가와 학생 제출 평가의 계획·실행·결과·검토·feedback·release를 소유한다. 두 subject의 prompt·input/output schema·정책·이력은 분리하고, source는 고정 revision Contract로만 받으며 AI provider routing은 플랫폼 port로 실행한다.
  8. Reporting은 report·export·PDF artifact와 전용 read projection을 소유한다. 원천 domain table을 JOIN하지 않고 versioned query DTO·event로 projection을 만들며 정확한 source revision과 권한을 보존한다.
  9. Import는 run·item·staging·preview·mapping·checkpoint만 소유한다. 대상 데이터는 각 domain의 idempotent ImportTargetPort로 commit하고 target Repository를 주입받지 않는다.
  10. Database는 transaction·migration 실행·schema version·oj_ai_* 이름과 충돌 검증만 소유한다. 각 domain이 자기 SchemaDescriptor를 제공하고, activity·audit table은 Operations가 실제 writer와 함께 소유한다.
  11. Presentation은 OJ Console·PublicUI·REST handler와 ViewModel만 소유한다. domain Service 생성, Repository·$wpdb 접근, 상태 직접 update를 금지하고 application use-case Contract를 주입받는다.
  12. A-DS-16 관문에 namespace cycle, foreign concrete import, foreign table access, table owner 1개, platform forbidden access와 platform file hash 검사를 추가한다. 위 규칙을 통과하기 전 구현 완료로 처리하지 않는다.
