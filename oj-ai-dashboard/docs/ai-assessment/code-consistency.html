AI 평가 애드온 코드 일관성 기준

전체 코드는 같은 경계, 같은 이름 규칙, 같은 계층 책임을 따르도록 작성한다. 기능을 빨리 붙이기보다 유지 가능한 구조를 우선한다.

문서 상태 구현 기준 작성일 2026-08-09 PHP 7.4 호환

작성 원칙

  • 기존 namespace OJAI\Dashboard를 유지한다.
  • 새 기능은 독립 모듈로 추가하고, 기존 모듈 책임을 흐리지 않는다.
  • controller에는 business logic을 넣지 않는다.
  • repository는 SQL과 저장소 접근만 담당한다.
  • service는 업무 흐름을 조합하되 직접 테이블명을 만들지 않는다.
  • 학생 공개 데이터는 서버에서 제거한 뒤 반환한다.

계층별 책임

Module

WordPress hook 등록만 담당한다. 객체 조립은 constructor에서 하고, 실행 로직은 service로 위임한다.

REST Controller

요청 파싱, permission callback, response 변환만 담당한다. 채점이나 진단 판단은 하지 않는다.

Service

업무 흐름과 상태 전이를 담당한다. AI 호출, normalizer, repository를 조합한다.

Repository

저장과 조회만 담당한다. 테이블명은 반드시 Table_Names::table()에서 가져온다.

Normalizer

AI 응답을 안정적인 내부 구조로 바꾼다. 점수 범위, 누락 필드, 검토 필요 상태를 정규화한다.

Admin UI

상태, 목록, 버튼, 모달 중심으로 구성한다. 긴 사용 설명은 HTML 문서로 분리한다.

Application Policy

Runtime, actor, capability, Context, 객체와 상태를 한 순서로 판정한다. Page, REST, Job과 파일은 같은 Port를 사용한다.

REST Foundation

서버 actor, 표준 nonce, 공통 Policy, correlation, 멱등키와 성공·실패 envelope를 Controller마다 같은 구현으로 제공한다.

접근 정책 규칙

  • Manifest에 선언한 15개 capability만 사용하고 AddonCapabilityKeyV1 공개 mapper로 변환한다.
  • Console은 oj_access_console + view_workspace, Public은 active actor + participate를 공통 gate로 사용한다.
  • capability는 서로 상속하지 않으며 role 이름, manage_options, ambient current user를 권한 근거로 사용하지 않는다.
  • 플랫폼 Context는 공개 AddonContextGatewayV1로 현재 class|group를 매번 재인가한다.
  • 객체 소유 모듈은 relation, revision, state와 transition을 조회 조건에서 제한하고 공통 객체 Policy Port를 구현한다.
  • owner 어댑터, Runtime 또는 Gateway가 없으면 임시 허용하지 않고 503으로 닫는다.

REST 공통 규칙

  • namespace는 oj-ai/v1 하나이며 URL은 rest_url()에서 만든다.
  • 목록 cursor 기본 상한은 191자다. 공개 플랫폼 opaque cursor를 왕복하는 Q01만 동결된 endpoint profile 512자를 사용하며 decode·절단하지 않는다.
  • 현재 actor는 WordPress 인증 상태에서만 읽고 body·query·path의 actor·권한·owner를 신뢰하지 않는다.
  • GET은 읽기 전용이다. POST는 X-WP-Nonce의 wp_rest action과 8~128자 Idempotency-Key를 요구한다.
  • correlation ID는 서버가 새로 발급하며 클라이언트 header를 반사하거나 응답 meta에서 덮어쓰지 않는다.
  • 성공은 data/meta/links/actions, 실패는 WordPress 호환 code/message/data envelope를 사용한다.
  • 내부 reason, SQL, table·class, stack, provider 원문, secret을 응답에 포함하지 않는다.
  • Controller는 명령 DTO와 하나의 Application Port만 호출하고 멱등 예약·digest·업무 row·audit·outbox는 owner transaction에서 함께 반영한다.
  • Use Case가 준비되지 않은 catalog route와 문서에 없는 진단 route는 등록하지 않는다.

데이터 접근 규칙

  • 애드온 테이블은 oj_ai_* 고정 이름을 사용한다.
  • 기능 코드에서 문자열로 테이블명을 직접 조립하지 않는다.
  • 새 테이블은 Table_Names, Schema, 새 migration, repository를 함께 추가한다.
  • OJ 원장은 공개 Addon API Gateway로만 읽고 플랫폼 table·내부 Repository에 직접 접근하지 않는다.
  • 삭제는 기본적으로 deleted_at soft delete로 처리한다.

AI 계약 규칙

  • 활동지 진단, 제출물 채점, 피드백, 특기사항은 서로 다른 policy key를 사용한다.
  • AI raw response는 교사용 검토와 디버깅 범위에서만 저장한다.
  • 서버가 최종 점수 합계와 범위 보정을 담당한다.
  • AI 결과는 곧바로 학생에게 공개하지 않는다.
