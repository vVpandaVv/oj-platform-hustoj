학생 제출물 AI 평가

학생의 공식 제출본과 그 활동지에 고정된 채점 기준만 AI에 전달해 기준별 점수 후보와 근거를 만든다. AI가 읽을 수 없는 응답은 0점으로 만들지 않고 교사 확인으로 넘기며, 모든 결과는 교사가 검토하기 전까지 학생에게 공개되지 않는다.

첨부 처리 worker는 원본을 변경하지 않고 oj_ai_private_files에 owner_type=submission_attachment, owner_public_id=attachment public ID, purpose=ai_text_representation, mime_type=text/plain인 파생 private file을 만든다. 원본 attachment의 JSON(ai_representation) manifest가 원본 SHA-256, extractor contract version, 상태, 파생 file public ID·SHA-256·byte, 생성 시각과 안전 reason code를 참조한다. 원본 파일명·storage key·추출 text는 manifest에 넣지 않는다.

평가 전 관문: C29·C30은 추출을 동기로 수행하지 않는다. official attachment마다 manifest가 ready|unavailable로 끝난 뒤에만 canonical input을 만들며 pending|failed|rejected|stale가 하나라도 있으면 evaluation·run·outbox를 0건으로 유지한다. ready manifest도 파생 private file의 owner·state·hash를 다시 검산한다.
binary 비전송: v1은 이미지·그림·PDF·문서 binary, private URL, storage key와 파일명을 플랫폼 AI Gateway에 보내지 않는다. 향후 실제 멀티모달 평가가 필요하면 별도 플랫폼 API·동의·용량·보존·provider 허용 계약을 승인한다.

엄격 정규화 순서

  1. UTF-8 byte·JSON 깊이·root object·허용 key와 schema ID·version을 검사한다.
  2. evaluation_ref와 source_hash를 저장된 immutable input과 constant-time 비교한다.
  3. expected binding 집합과 output 집합이 정확히 같고 unknown·duplicate·missing이 0건인지 검사한다.
  4. score와 abstain의 필수·금지 field 조합을 검사한다.
  5. candidate decimal을 strict parse하고 0~server-side maximum 범위인지 확인한다. 반올림·clamp하지 않는다.
  6. confidence가 유한 범위이고 text·array 상한과 enum allowlist를 지키는지 확인한다.
  7. evidence anchor가 해당 binding의 response·artifact에 속하고 quote가 canonical input substring인지 확인한다.
  8. HTML·script·URL·내부 ID·PII·정답 재노출·금지 reasoning key를 거부한다.
  9. item을 response position·criterion position으로 정렬하고 flags를 중복 없는 canonical token 목록으로 만든다.
  10. 모든 binding이 score일 때만 candidate total을 서버 decimal 합산하고 하나라도 abstain이면 null로 둔다.
  11. overall confidence·abstained·safety flag와 complete|partial|abstained 상태를 서버가 계산한다.
  12. normalized JSON·hash, result·item, run·attempt·audit·outbox를 lease 조건 한 transaction으로 append한다.
전체 거부 원칙: 일부 항목만 정상이어도 schema·coverage·점수 범위 위반이 있으면 결과 전체를 저장하지 않는다. 정상적인 abstain만 부분 평가로 저장할 수 있다.
