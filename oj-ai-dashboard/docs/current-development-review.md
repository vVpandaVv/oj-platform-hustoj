# 현재 개발 진행 점검

작성일: 2026-06-15
대상 절차: `docs/integration-completion-procedure.md`

## 1. 단계 진행 상태

| 단계 | 판정 | 근거 | 보완 필요 |
|---:|---|---|---|
| 1 | 정상 | 기존 기능 잠금 목록 작성 | 없음 |
| 2 | 정상 | 1:1 갭 매핑 작성 | 과거 기준 문서이므로 최신 점검 문서와 함께 사용 |
| 3 | 정상 | OJ 콘솔과 독립 콘솔 경로 공유 | 없음 |
| 4 | 정상 | 상태표 중심 화면을 REST 업무 화면으로 교체 | 남은 일반 JSON 폼은 후속 단계에서 전용 화면으로 축소 |
| 5 | 정상 | 템플릿 목록, 저장, 복제, 보관, 가져오기, 내보내기 연결 | 없음 |
| 6 | 정상 | Plate 원형 편집기와 빌드 산출물 연결 | Playwright 패키지 없음으로 브라우저 자동 검사는 스킵 |
| 7 | 정상 | 활동지 배포, 대상, 마감, 자동 제출, 대리 제출 설정 연결 | 없음 |
| 8 | 정상 | 학생 작성, 자동저장, 제출, 첨부, 그림 입력 연결 | 없음 |
| 9 | 정상 | 제출 목록, 상세, 재열기, 대리 업로드, PDF/ZIP 출력 연결 | ZIP 전용 업로드 화면은 11단계 |
| 10 | 보완 후 정상 | 평가 계획 저장, 루브릭 모드, 성취기준, 학생 매핑, 사전 점검 연결 | 채점 검토 표는 12단계 |
| 11 | 정상 | ZIP 미리보기, 수동 매핑, 제외, 확정 제출, 개별 업로드, 사유 제출 연결 | 채점 검토 표는 12단계 |
| 12 | 정상 | 제출 목록, 문항 상세, 채점/피드백/특기사항 버튼 분리, 선택/반 전체 실행 연결 | 재채점 변경안 전용 비교 화면은 13단계 |
| 13 | 정상 | 재채점 변경 검토, 기존/변경안 비교, 변경 반영/미반영, pending 검토 재열기 연결 | 통합 분석 대시보드는 14단계 |

## 2. 실제 사용 가능성

| 흐름 | 현재 사용 가능성 | 판단 |
|---|---|---|
| 교사 템플릿 제작 | 높음 | Plate 편집기와 템플릿 생명주기 버튼이 연결됨 |
| 과제 배포 | 높음 | 학년도, 학년, 반, 그룹, 학생 대상과 마감 설정이 저장됨 |
| 학생 작성 | 높음 | 학생 대시보드에서 활동지 열기, 자동저장, 제출이 가능함 |
| 제출 관리 | 중상 | 목록, 상세, 재열기, 대리 제출/업로드, PDF 링크가 있음 |
| 평가 계획 | 중상 | 저장, 보관, 루브릭 항목 추가, 성취기준 선택, 학생 매핑 점검이 가능함 |
| AI 채점 검토 | 중상 | 제출물, 질문, 학생 답변, 정답, 예시, 루브릭, 첨부를 함께 보고 학생별/선택/반 전체 실행이 가능함 |
| 재채점 변경 검토 | 중상 | 점수 변경 결과가 자동 반영되지 않고 변경 검토 카드에서 반영/미반영을 선택함 |
| ZIP 업로드 | 중상 | 전용 화면에서 미리보기, 매핑 저장, 제외, 확정 제출, 개별 업로드와 사유 제출이 가능함 |
| 보고서/대시보드 | 부분 | 백엔드와 일부 화면은 있으나 통합 분석 대시보드는 14, 15단계 대상 |

## 3. 이번 점검에서 보완한 부분

| 항목 | 조치 |
|---|---|
| 루브릭 JSON 직접 입력 의존 | 루브릭 기준, 배점, 문항 ID, 검토 기준 입력 후 버튼으로 항목 추가 |
| 성취기준 ID 복사 입력 의존 | 성취기준 목록에 활동지/문항 추가 버튼 연결 |
| 성취기준 초기화 | 활동지/문항 성취기준 비우기 버튼 추가 |
| 진행 문서 불일치 | 2단계 갭 맵에 과거 기준 안내 추가 |
| 하네스 부족 | 평가 계획 화면의 루브릭/성취기준 버튼 검사를 추가 |
| ZIP 전용 화면 부재 | ZIP 업로드, 항목 매핑, 제외, 확정 제출 화면을 활동지 제출 관리에 추가 |
| ZIP 파일 보존 부족 | ZIP 내부 파일을 안전 경로로 복사하고 제출 첨부 메타데이터로 연결 |
| 개별 미제출 사유 부족 | 개별 제출 패널에서 미참여, 장기결석, 결원, 기타 사유를 제출 본문에 저장 |
| 채점 검토 전용 화면 부재 | AI 채점 화면에 제출 조회, 검토 상세, 채점 결과, 피드백, 특기사항 결과 패널을 추가 |
| 버튼 컨텍스트 과다 | 채점, 피드백, 특기사항 버튼을 각각 독립 REST 호출로 분리 |
| 재채점 변경안 자동 반영 위험 | `change_pending` 결과는 변경 검토 전용 반영/미반영 버튼으로만 처리 |
| 재접속 후 pending 검토 접근 부족 | 제출 목록과 상세에 pending 재채점 검토 버튼과 상세 조회 REST 연결 |

## 4. 방향성 판단

현재 방향은 요구한 통합형 플러그인에 맞다. 기존 플러그인을 병렬로 유지하지 않고, `oj-ai-dashboard`의 콘솔 화면, REST, DB 저장소, 권한 흐름으로 병합하고 있다.

다만 12단계부터도 일반 JSON 폼을 남겨두는 방식으로 완료 판정을 하지 않는다. 채점 검토와 보고서 출력은 전용 목록, 선택, 미리보기, 승인 버튼이 있는 실제 업무 화면으로 구현해야 한다.

## 5. 다음 단계 준비

14단계 진입 전 준비 상태:

- ZIP preview/map/commit REST와 전용 화면이 연결되어 있다.
- ZIP 내부 파일이 제출 첨부 메타데이터로 전달된다.
- 제출 관리 화면에서 과제와 제출 목록을 조회할 수 있다.
- 평가 계획과 학생 매핑 사전 점검이 연결되어 제출물을 채점 대상으로 넘길 기반이 있다.
- AI 채점 화면에서 제출 상세를 열고 문항별 질문, 답변, 정답, 예시, 루브릭, 첨부를 확인할 수 있다.
- 채점, 피드백, 특기사항 버튼은 별도 요청으로 실행된다.
- 재채점 변경 검토가 pending 상태로 보존되고 교사가 변경 반영 또는 미반영을 선택할 수 있다.

14단계에서 바로 구현할 항목:

- 교사용 대시보드의 학년도, 학년, 반, 그룹별 분석
- 학생용 대시보드의 제출, 점수, 피드백, 활동 요약
- OJ 연결 모드의 코드 제출, 문제, 채점 기록 통합 분석
