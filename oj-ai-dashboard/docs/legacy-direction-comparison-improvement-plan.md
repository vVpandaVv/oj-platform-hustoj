# 기존 플러그인 방향 비교와 개선안

문서 상태: 초안
작성일: 2026-06-16
대상: `oj-ai-dashboard`

## 1. 결론

현재 통합 플러그인은 구조적으로는 통합 콘솔, REST, Plate, 제출, 채점, 보고서 기능을 넓게 품고 있다. 그러나 UX 방향은 기존 3개 플러그인의 실제 운영 경험과 다소 달라졌다.

가장 큰 차이는 다음이다.

| 구분 | 기존 3개 플러그인의 방향 | 현재 통합 플러그인/샘플의 방향 | 문제 |
|---|---|---|---|
| 화면 성격 | 교사가 바로 쓰는 운영 화면 | 통합 대시보드와 간소화된 샘플 화면 | 실제 운영 버튼과 표가 약해 보임 |
| 업무 단위 | 템플릿, 과제, 제출, 계획, 루브릭, 업로드, 검토가 독립 화면 | 한 콘솔 안의 탭/폼/카드로 압축 | 어디서 어떤 일을 하는지 흐려짐 |
| 데이터 밀도 | 학생별 표, 반별 탭, 일괄 작업, 개별 행 버튼 중심 | KPI, 카드, 미리보기 중심 | 기존 기능을 대체한다는 확신이 약함 |
| 채점 흐름 | 평가 계획 -> 업로드 -> 반별 검토 -> 학생별 버튼 -> 공개 | 계획/검토 REST는 있으나 화면이 분산 | 검토, 공개, 재채점의 조작성이 부족 |
| 활동지 흐름 | 템플릿 -> 과제 운영 -> 제출 현황 -> PDF/AI 전달 | 제작/배포/제출/업로드 탭으로 통합 | 표 기반 제출 관리와 일괄 작업 감각이 약함 |
| 대시보드 역할 | 기존 결과를 분석하고 보고서/특기사항을 생성 | 전체 기능의 시작 화면처럼 보임 | 대시보드가 운영 기능을 가리는 인상 |

개선 방향은 새 대시보드 제품으로 다시 설계하는 것이 아니라, 기존 플러그인의 업무 흐름을 `oj-ai-dashboard` 콘솔 안에 그대로 이식하고 디자인만 통일하는 것이다.

## 2. 기능 그룹별 차이

### 2.1 대시보드

| 항목 | 기존 방향 | 현재 상태 | 개선 방향 |
|---|---|---|---|
| 교사 대시보드 | 그룹/학생 분석, 학생 상세, 보고서, 특기사항 생성 | 학년도/학년/반 KPI와 학생표 중심 | 대시보드는 분석 전용으로 고정하고, 학생 행에 `보고서`, `특기사항`, `채점 보기` 버튼을 둔다 |
| 학생 대시보드 | 본인 제출/문제 활동 분석과 추천/피드백 | 활동지 제출, 공개 피드백, OJ 제출 요약 | 학생은 `내 활동`, `내 활동지`, `피드백`, `점수`만 보게 하고 관리 기능은 완전히 제거한다 |
| 문제/코드 분석 | 문제 메타데이터, 교육과정 매핑, 수준 분석 작업 | OJ 제출 지표는 있으나 작업 화면성이 약함 | `문제 분석` 전용 탭을 교사 대시보드 아래에 두고 작업 큐/매핑 상태를 표로 복원한다 |
| 보고서 | 학생/그룹 보고서 생성과 출력 | 보고서 REST와 폼 존재 | 학생 행/학급 필터에서 바로 PDF/CSV를 실행하게 한다 |

### 2.2 활동지

| 항목 | 기존 방향 | 현재 상태 | 개선 방향 |
|---|---|---|---|
| 템플릿 | 템플릿 저장, 가져오기, 내보내기, 저장 목록 | Plate mount와 템플릿 생명주기 버튼 존재 | `템플릿 목록 + Plate 편집기 + 블록 속성` 3영역으로 정리한다 |
| Plate | 빌드 산출물이 있을 때 공식 Plate UI 표시 | 통합 플러그인에도 전체 Plate 원형 소스와 mount 존재 | 샘플 디자인의 가짜 편집기 표현을 버리고 실제 Plate 화면을 기준으로 디자인한다 |
| 과제 운영 | 과제명, 그룹, 템플릿, 시작/마감/자동제출, 상태 저장 | 배포 탭에 필수 필드는 있음 | `과제 저장` 화면을 독립 탭으로 두고 저장된 과제 표, 학생 수, 상태, 수정 버튼을 복원한다 |
| 제출 현황 | 반별 탭, 학생별 상태표, PDF, 재열기, AI 전달, 대리 제출 | 제출 목록/상세/재열기/PDF/대리 제출 REST 연결 | 카드보다 표를 우선하고, 행별 `열기`, `재열기`, `PDF`, `대리 업로드`, `AI 채점 연결` 버튼을 둔다 |
| ZIP/개별 업로드 | 교사 대리 업로드와 후속 처리 큐 | ZIP/개별 업로드 UI와 REST 존재 | 업로드는 제출 관리의 하위 작업으로 두고, 제출표에서 대상 학생을 선택해 실행하게 한다 |
| 로그 | 처리 로그 확인 | 메뉴 배치는 있으나 UX가 약함 | `작업 로그`는 제출/렌더/자동제출/ZIP/채점 전달 이벤트를 한 표로 보여준다 |

### 2.3 AI 채점

| 항목 | 기존 방향 | 현재 상태 | 개선 방향 |
|---|---|---|---|
| 평가 계획 | 평가 대상과 과제, 성취기준, 운영 상태를 계획으로 관리 | 평가 계획 저장 REST와 화면 존재 | 계획 화면은 간단히 `과제`, `계획명`, `학년도/학년/반`, `상태`만 먼저 보이고 상세는 접는다 |
| 루브릭 | 계획에 연결된 기준을 저장 | 전체/문항별 단일 선택과 기준 추가가 존재 | 루브릭은 `전체` 또는 `문항별` 중 하나만 고정하고, 선택 후 다른 방식은 숨긴다 |
| 자료 업로드 | ZIP/개별 파일 업로드, 미분류/미제출 사유 | ZIP과 개별 업로드가 활동지 제출 쪽에 더 강함 | AI 채점 화면에도 `자료 업로드` 탭을 두되, 활동지 제출물과 외부 파일을 같은 제출 단위로 합친다 |
| 채점 검토 | 반별 탭, 학생별 행, 점수/검토 의견/피드백/특기사항 편집, 비동기 상태 | 제출 조회, 선택 채점, 피드백, 공개, 특기사항 버튼은 있음 | 기존처럼 `반별 표 + 우측 상세`로 바꾸고 학생 행마다 `채점`, `피드백`, `특기사항`, `공개` 버튼을 둔다 |
| 재채점 | 변경 검토 후 반영/미반영 | change pending과 accept/reject REST 존재 | 채점표에 `변경 검토` 배지를 표시하고, 상세에서 기존/제안 점수를 나란히 보여준다 |
| 학생 공개 | 피드백 승인 후 공개, 특기사항 비공개 | 승인/공개 REST 존재 | 학생 화면에는 공개 피드백과 점수만 표시하고 특기사항은 보고서 옵션에만 둔다 |

## 3. 현재 UX 샘플의 방향 차이

`docs/ux-ui-sample.html`은 교사/학생 구분, Plate 블록, 채점/피드백/특기사항 분리를 보여 주는 데는 유효하다. 그러나 기존 플러그인 대체 관점에서는 다음이 부족하다.

| 부족한 점 | 영향 | 개선 |
|---|---|---|
| 활동지가 하나의 예쁜 제작 화면처럼 보임 | 기존 과제 운영, 제출 현황, PDF, 대리 제출이 약해 보임 | 샘플을 `활동지 운영 콘솔` 중심으로 재작성한다 |
| 채점이 카드형 검토 중심 | 기존 반별 대량 채점과 학생별 행 편집 경험이 사라짐 | 반별 탭과 학생별 채점 표를 샘플의 기본 화면으로 둔다 |
| 보고서가 단순 버튼으로 보임 | PDF/CSV 포함 옵션, 대상 선택, 일괄 다운로드가 약함 | 보고서 화면에 출력 대상 표와 포함 옵션 패널을 둔다 |
| 데이터 가져오기/명단 가져오기 샘플이 없음 | 기존 데이터 수동 가져오기 요구가 보이지 않음 | 가져오기 화면 샘플을 추가한다 |
| OJ 연결 모드와 독립 모드 차이가 흐림 | OJ 그룹 우선 원칙을 사용자가 체감하기 어려움 | 학사 관리 화면에 `OJ 연결 중` 상태와 로컬 그룹 비활성 표시를 둔다 |

## 4. 개선 원칙

| 원칙 | 적용 방식 |
|---|---|
| 기존 업무 단위를 보존 | `대시보드`, `활동지`, `AI 채점`, `보고서`, `가져오기`, `학사 관리`는 유지하되 각 메뉴 내부는 기존 화면 순서로 구성한다 |
| 대시보드는 분석 전용 | 생성/수정/업로드/채점은 각 업무 화면에서 실행하고 대시보드는 상태 확인과 이동만 담당한다 |
| 표 우선, 카드 보조 | 교사용 운영 화면은 학생, 과제, 제출물, 채점 결과를 표로 보여 주고 카드는 요약에만 사용한다 |
| 행별 버튼 복원 | 기존의 `편집`, `재열기`, `PDF`, `채점`, `피드백`, `특기사항`, `공개`, `내보내기` 버튼이 대상 행 옆에 있어야 한다 |
| Plate는 실제 편집기 기준 | 샘플과 실제 화면 모두 Plate 전체 편집기를 기준으로 구성하고, 별도 모조 편집기 UI는 쓰지 않는다 |
| 필수 입력만 첫 화면 | 고급 설정은 접고, 과제/계획/채점 시작에 필요한 최소 필드만 첫 화면에 둔다 |
| 비동기 작업은 보이게 | 채점, 피드백, 특기사항, PDF, 가져오기, 메타데이터 작업은 진행 상태와 취소/재시도 버튼을 제공한다 |
| 학생 화면은 작성 중심 | 학생은 배정 활동지, 자동저장 상태, 제출, 공개 피드백, 점수만 본다 |

## 5. UI 재구성안

### 5.1 교사 대시보드

첫 화면은 다음 순서로 둔다.

| 영역 | 구성 |
|---|---|
| 필터 | 학년도, 학년, 반, 그룹, 조회 |
| 요약 | 학생 수, 과제 수, 제출률, 채점 완료, 평균, 공개 피드백, OJ 제출 |
| 학생별 현황 | 이름, 학번, 반, 활동지 제출, OJ 제출, 점수, 피드백, 특기사항, 작업 |
| 작업 버튼 | `학생 보고서`, `채점 보기`, `특기사항`, `활동지로 이동` |
| 문제/코드 분석 | OJ 문제, 제출 기록, 정답률, 성취기준 매핑 상태 |

### 5.2 활동지

기존 활동지 플러그인의 경험을 다음 5개 탭으로 복원한다.

| 탭 | 첫 화면 필수 요소 | 주요 버튼 |
|---|---|---|
| 템플릿 | 템플릿 목록, 제목, 상태, Plate 편집기 | 새로 만들기, 저장, 복제, 보관, 가져오기, 내보내기 |
| 과제 | 과제명, 템플릿, 대상, 마감일, 상태 | 저장, 배포, 대상 새로고침 |
| 제출 | 과제 선택, 반별 탭, 학생별 제출표 | 열기, 재열기, PDF, 일괄 PDF, AI 채점 연결 |
| 업로드 | ZIP, 개별 업로드, 미제출 사유 | 미리보기, 매핑 저장, 확정 제출, 대리 업로드 |
| 로그 | 자동저장, 제출, PDF, 업로드, 채점 전달 이벤트 | 조회, 재시도 |

### 5.3 AI 채점

기존 채점 플러그인의 경험을 다음 5개 탭으로 복원한다.

| 탭 | 첫 화면 필수 요소 | 주요 버튼 |
|---|---|---|
| 평가 계획 | 과제, 계획명, 학년도, 학년, 반, 상태 | 새 계획, 저장, 사전 점검 |
| 루브릭 | 전체/문항별 선택, 기준명, 배점, 설명 | 기준 추가, 저장 |
| 자료 업로드 | 계획 선택, ZIP/개별 파일, 학생 매핑 | 미리보기, 확정, 사유 저장 |
| 채점 검토 | 반별 탭, 학생별 표, 우측 상세 | 채점, 피드백, 특기사항, 공개, 공개 취소 |
| 변경 검토 | 기존 결과, 제안 결과, 점수 차이 | 변경 반영, 미반영 |

### 5.4 보고서

| 영역 | 구성 |

| 기록 | 생성된 파일, 생성일, 다운로드 |

| 영역 | 구성 |
|---|---|
| 기존 데이터 | 가져오기 대상 선택, 미리보기, 확정 |
| 학생 명단 | CSV 업로드, 미리보기, 매핑, 확정 |
| 템플릿 | JSON/DOCX/Markdown/CSV/HTML 가져오기, 내보내기 |

## 6. 구현 개선 순서

| 순서 | 작업 | 완료 기준 |
|---:|---|---|
| 1 | UX 샘플 재작성 | 샘플 첫 화면이 카드형 데모가 아니라 실제 운영 콘솔 흐름을 보여 줌 |
| 2 | 활동지 화면 표 중심 재구성 | 템플릿/과제/제출/업로드/로그 탭에서 기존 핵심 버튼을 모두 접근 가능 |
| 3 | AI 채점 화면 표 중심 재구성 | 반별 학생표, 우측 상세, 행별 채점/피드백/특기사항/공개 버튼 제공 |
| 4 | 보고서 화면 재구성 | 대상 선택, 포함 옵션, PDF/ZIP/CSV, 생성 기록을 한 흐름으로 제공 |
| 5 | 데이터 가져오기 화면 보강 | 기존 데이터, 학생 명단, 템플릿 가져오기/내보내기, 실행 기록을 별도 카드로 제공 |
| 6 | 대시보드 역할 축소 | 대시보드는 분석과 이동 중심으로 정리하고 운영 입력 폼은 각 메뉴로 이동 |
| 7 | 기존 action/shortcode 호환 점검 | 기존 버튼 경험과 새 REST 버튼이 기능적으로 대응되는지 잠금 ID 기준으로 재검증 |
| 8 | 브라우저 시각 검증 | OJ 콘솔/독립 콘솔에서 메뉴, Plate, 플로팅, 표, 모바일 줄바꿈 확인 |

## 7. 판정 기준

다음 조건을 만족해야 기존 플러그인의 방향을 되찾았다고 볼 수 있다.

| 기준 | 판정 방법 |
|---|---|
| 교사가 메뉴만 보고 작업 순서를 알 수 있음 | 활동지와 채점 메뉴가 기존 업무 순서대로 보임 |
| 기존 기능이 숨지 않음 | 기존 핵심 버튼이 행 또는 탭 안에 직접 존재 |
| 보기 전용이 아님 | 생성, 수정, 업로드, 제출, 채점, 공개, 출력이 화면에서 실행됨 |
| Plate가 실제 편집기로 보임 | 샘플과 실제 화면 모두 Plate 원형 편집기를 기준으로 함 |
| 대량 운영이 가능함 | 반별 탭, 선택 학생, 전체/선택 일괄 작업이 있음 |
| 학생 화면이 단순함 | 작성, 저장 상태, 제출, 공개 피드백, 점수만 노출 |
| OJ/독립 모드가 구분됨 | OJ 연결 시 OJ 그룹 우선, 독립 시 연도/학년/반/로컬 그룹 사용이 UI에 드러남 |
