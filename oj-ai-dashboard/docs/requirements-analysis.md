# OJ AI Dashboard 요구 분석서

문서 상태: 확정  
작성일: 2026-06-13  
대상 플러그인: `oj-ai-dashboard`

## 1. 개요

`oj-ai-dashboard`는 기존 AI 대시보드, 활동지 제출, AI 채점 기능을 하나의 플러그인으로 통합하는 WordPress 기반 교육용 플러그인이다. 이 플러그인은 OJ 플랫폼이 있는 환경에서는 OJ의 사용자, 그룹, 문제, 코드 제출 및 채점 기록을 우선 사용하고, OJ 플랫폼이 없는 환경에서는 독립적으로 학년도, 학년, 반, 학생, 활동지, AI 채점, 보고서를 운영할 수 있어야 한다.

이 플러그인은 3개 기능을 독립적으로 나열하는 방식이 아니라, 다음 흐름을 하나의 업무 흐름으로 통합한다.

```text
활동지 제작 -> 배정 -> 작성/자동저장 -> 제출/자동제출/대리제출
-> 채점 -> 변경 검토 -> 피드백 생성/승인 -> 특기사항 생성
-> 학생/학급 보고서 -> 교사/학생 대시보드
```

## 2. 목표

### 2.1 주요 목표

- 기존 3개 플러그인의 기능을 하나의 플러그인으로 물리적으로 병합한다.
- 기존 3개 플러그인은 그대로 두고, 새 플러그인에 기능을 복사하여 통합한다.
- 새 플러그인은 OJ 플랫폼과 연결하여 사용할 수도 있고, 독립적으로 사용할 수도 있어야 한다.
- OJ 플랫폼이 있으면 OJ의 그룹, 학생, 문제, 코드 제출, 채점 기록을 우선 사용한다.
- OJ 플랫폼이 없으면 자체 학년도, 학년, 반, 학생 그룹 기능을 사용한다.
- 활동지, AI 채점, 피드백, 특기사항, 보고서, 대시보드를 하나의 데이터 흐름으로 연결한다.
- 학생 작성 중 데이터 손실이 없도록 자동저장을 안정적으로 제공한다.
- 채점 기준이 흔들리지 않도록 채점 기준, 입력, 결과를 고정하고 재사용한다.

### 2.2 제외 또는 축소되는 목표

- 새 플러그인 이름, 폴더명, 화면명에 특정 기존 플랫폼명을 사용하지 않는다.
- 문제 메타데이터는 새 플러그인에서 별도 관리하지 않는다.
- OJ 플랫폼이 있을 때 문제 정보는 OJ의 기존 문제 데이터를 참조한다.
- OJ의 코드 채점 엔진을 새 플러그인에서 대체하지 않는다.
- OJ 플랫폼이 없는 독립 모드에서는 코드 문제 채점 기능을 제공하지 않는다.

## 3. 사용자와 권한

### 3.1 관리자

관리자는 플러그인 전체 운영 권한을 가진다.

- 플러그인 설정 관리
- AI 제공자 및 모델 설정 관리
- OJ 연결 상태 확인
- 기존 데이터 가져오기 실행
- 학년도, 학년, 반, 그룹 전체 관리
- 교사, 학생, 역할, 권한 관리
- 모든 활동지, 제출물, 채점 결과, 보고서 접근
- 템플릿 가져오기/내보내기
- PDF/CSV 출력
- 로그 및 작업 상태 확인

### 3.2 교사

교사는 담당 학급 또는 그룹의 활동과 평가를 운영한다.

- 담당 학년도, 학년, 반, 그룹 조회
- 활동지 생성, 수정, 복제, 배정
- Plate 기반 활동지 편집
- 활동지 템플릿 가져오기/내보내기
- 학생 제출 현황 확인
- 마감 설정
- 대리 업로드 및 대리 제출
- ZIP 제출물 업로드 및 학생별 자동 분류
- 채점 버튼 실행
- 재채점 변경 검토
- 피드백 버튼 실행
- 피드백 승인 및 공개
- 특기사항 버튼 실행
- 학생별 PDF 보고서 출력
- 학급별 PDF 보고서 출력
- 점수 CSV 출력
- 교사용 대시보드 조회

### 3.3 학생

학생은 로그인 후 본인에게 배정된 활동지를 작성하고 결과를 확인한다.

- 배정된 활동지 조회
- 활동지 작성
- 작성 중 자동저장
- 첨부파일, 이미지, 그림 입력 제출
- 마감 전 제출
- 승인된 피드백 확인
- 본인 점수 및 보고서 확인
- 학생용 대시보드 조회

### 3.4 보조교사

보조교사는 기본 3역할에는 포함하지 않고, 설정으로 활성화할 수 있는 확장 역할로 둔다. 기본 권한 모델은 관리자, 교사, 학생이다.

- 담당 학급 제출물 조회
- 채점 검토 보조
- 피드백 초안 검토
- 보고서 조회
- 설정, 삭제, 데이터 가져오기, 권한 관리는 제한

## 4. 실행 모드

### 4.1 OJ 연결 모드

OJ 플랫폼이 설치되어 있고 연결 가능한 경우 이 모드로 동작한다.

- OJ 사용자와 WordPress 사용자를 기준으로 로그인 사용
- OJ 그룹, 학급, 학생 정보를 우선 사용
- 로컬 그룹 생성 및 수정 UI는 숨김
- OJ 그룹과 학년도, 학년, 반, 번호를 연결하는 학사 컨텍스트 매핑을 사용
- 코드 제출 기록과 OJ 문제 채점 결과를 읽어 대시보드와 보고서에 반영
- 활동지와 AI 채점은 `oj-ai-dashboard`가 저장하고 운영
- 교사용 대시보드는 OJ 플랫폼 메뉴 또는 관리 화면에 통합 가능해야 함
- 독립 메뉴 접근도 설정에 따라 허용 가능해야 함

### 4.2 독립 모드

OJ 플랫폼이 없거나 비활성화된 경우 이 모드로 동작한다.

- WordPress 로그인 필수
- 자체 학년도, 학년, 반, 그룹, 학생 관리 사용
- 코드 제출 기록과 OJ 문제 채점 분석은 비활성화
- 활동지, 파일 제출, ZIP 업로드, AI 채점, 피드백, 특기사항, 보고서, 대시보드는 사용 가능
- 교사용 대시보드는 독립 메뉴 또는 shortcode 기반 페이지로 제공

## 5. 기능 요구사항

### 5.1 통합 플러그인

| ID | 요구사항 |
|---|---|
| FR-001 | 플러그인 폴더명은 `oj-ai-dashboard`로 한다. |
| FR-002 | 기존 3개 플러그인의 기능을 새 플러그인에 물리적으로 복사하고 통합한다. |
| FR-003 | 기존 3개 플러그인은 수정하지 않는다. |
| FR-004 | 새 플러그인은 기능을 독립 모듈처럼 병렬 배치하지 않고 하나의 평가 업무 흐름으로 재구성한다. |
| FR-005 | 관리자 메뉴는 하나로 통합한다. |
| FR-006 | 기존 shortcode 호환을 제공한다. |

### 5.2 OJ 연결

| ID | 요구사항 |
|---|---|
| FR-101 | OJ 플랫폼 설치 여부를 자동 감지한다. |
| FR-102 | OJ 플랫폼이 있으면 OJ 그룹과 학생 정보를 우선 사용한다. |
| FR-103 | OJ 플랫폼이 있으면 로컬 그룹 생성 및 수정 기능을 사용하지 않는다. |
| FR-104 | OJ 플랫폼이 있으면 OJ 문제 정보와 코드 제출 채점 기록을 읽어 분석한다. |
| FR-105 | OJ 플랫폼이 없으면 코드 제출 및 문제 채점 분석 기능을 비활성화한다. |
| FR-106 | 교사용 대시보드는 OJ가 있으면 OJ 플랫폼에 통합 설치될 수 있어야 한다. |
| FR-107 | OJ가 없으면 교사용 대시보드는 독립 메뉴 또는 독립 페이지로 열 수 있어야 한다. |
| FR-108 | OJ 연결 모드에서는 OJ 그룹 또는 사용자와 학년도, 학년, 반, 번호를 연결하는 학사 컨텍스트 매핑을 제공한다. |
| FR-109 | OJ 연결 모드의 교사용 대시보드는 OJ 메뉴 hook이 있으면 OJ 메뉴 아래에 붙이고, 없으면 독립 메뉴로 fallback한다. |

### 5.3 학년도, 학년, 반, 그룹

| ID | 요구사항 |
|---|---|
| FR-201 | 모든 결과는 학년도, 학년, 반 기준으로 조회할 수 있어야 한다. |
| FR-202 | 독립 모드에서는 자체 학년도, 학년, 반, 그룹, 학생 관리 기능을 제공한다. |

| FR-205 | OJ 연결 모드에서는 학생 명단 가져오기를 로컬 그룹 생성이 아닌 학생 매핑 보조 기능으로 제한한다. |
| FR-206 | OJ 연결 모드의 명단 가져오기는 OJ 사용자와 학년도, 학년, 반, 번호를 매핑하는 용도로 사용한다. |
| FR-207 | 명단 가져오기는 미리보기, 중복 확인, 오류 행 표시, 가져오기 취소를 지원한다. |

### 5.4 활동지 제작

| ID | 요구사항 |
|---|---|
| FR-301 | 활동지는 Plate 기반 편집기를 사용한다. |
| FR-302 | 활동지는 교사용 편집 화면과 학생용 작성 화면을 분리한다. |
| FR-303 | 학생은 전체 Plate 편집기가 아니라 입력 가능한 활동지 화면을 본다. |
| FR-304 | 활동지는 `plate_value_json`과 `form_schema_json`을 함께 저장한다. |
| FR-305 | 각 입력 블록은 안정적인 `block_id`를 가진다. |
| FR-306 | 활동지 템플릿 가져오기/내보내기를 지원한다. |
| FR-307 | 활동지는 `teacher_schema`, `student_schema`, `grading_schema`를 분리해서 생성한다. |
| FR-308 | 학생용 API와 학생용 화면에는 정답, 예시답안, 배점, 교사용 메모가 포함되지 않아야 한다. |
| FR-309 | 채점 문항은 안정적인 `question_id`를 가지며, 하나의 문항은 하나 이상의 입력 블록을 포함할 수 있다. |
| FR-310 | Plate 편집기는 개별 패키지나 개별 모듈을 임의 조립하지 않고, 기존 Plate 템플릿 빌더/편집기 구조를 통째로 가져와 확장한다. |
| FR-311 | Plate 기능 추가는 기존 편집기 shell, provider, floating layer, toolbar, portal 구조를 유지한 상태에서 커스텀 블록과 저장 연동을 추가하는 방식으로 한다. |
| FR-312 | Plate 편집기 구현 후 메뉴, 툴바, 플로팅 메뉴, 선택 영역 메뉴, 모달, 포털이 편집기 본문에 가리거나 잘못 배치되지 않는지 브라우저에서 반드시 점검한다. |
| FR-313 | Plate 편집기 검증은 데스크톱과 모바일 폭에서 모두 수행하고, 메뉴 겹침, z-index, overflow clipping, 스크롤 컨테이너 문제를 확인한다. |

| FR-703 | 네트워크 실패 시 재시도 큐를 제공한다. |

| FR-705 | 같은 제출물을 여러 탭에서 열 때 충돌을 감지한다. |
| FR-706 | 페이지 이탈 전 저장되지 않은 변경사항을 보호한다. |
| FR-707 | 마감일이 지나면 작성 중인 답안을 자동 제출한다. |
| FR-708 | 자동저장 요청은 `autosave_session_id`, `client_revision`, `base_revision`, `idempotency_key`를 사용해 중복 저장과 충돌을 방지한다. |
| FR-709 | 이미지, 파일, 그림 입력은 업로드 상태와 본문 저장 상태를 분리해 추적한다. |
| FR-710 | 자동저장 실패 시 브라우저 로컬 임시 큐에 보관하고 복구 가능한 상태로 표시한다. |
| FR-711 | 마감 자동 제출은 마지막 성공 저장본과 미전송 로컬 변경분 처리 정책을 명확히 적용한다. |

### 5.9 제출과 업로드

| ID | 요구사항 |
|---|---|
| FR-801 | 학생은 활동지를 직접 제출할 수 있어야 한다. |
| FR-802 | 교사는 학생 대신 대리 업로드 및 대리 제출을 할 수 있어야 한다. |
| FR-803 | 교사는 ZIP 파일을 업로드하여 학생별 제출물을 자동 분류할 수 있어야 한다. |
| FR-804 | ZIP 분류 기본 우선순위는 로그인 ID, 번호+이름, 번호, 이름 순으로 한다. |
| FR-805 | ZIP 분류 결과는 확정 전 미리보기와 수동 매핑을 제공한다. |
| FR-806 | 제출물 일괄 PDF 다운로드를 지원한다. |
| FR-807 | ZIP 업로드는 안전한 압축 해제, 허용 확장자 검사, 파일 크기 제한, 중복 파일 처리 정책을 적용한다. |
| FR-808 | 자동 매칭 신뢰도가 낮은 파일은 제출물로 확정하지 않고 수동 확인 상태로 둔다. |

### 5.10 AI 채점

| ID | 요구사항 |
|---|---|
| FR-901 | 채점은 교사의 `채점` 버튼으로 실행한다. |
| FR-902 | 채점 버튼은 점수 산출과 채점 검토의견 생성만 수행한다. |
| FR-903 | 채점 입력에는 질문, 학생 답변, 배점, 정답, 예시답안, 루브릭, 첨부자료가 함께 포함되어야 한다. |
| FR-904 | 채점 기준 snapshot을 저장한다. |
| FR-905 | 같은 질문, 답변, 루브릭, 기준, 모델 조건이면 기존 채점 결과를 재사용한다. |
| FR-906 | 점수 총합은 서버가 계산하며 AI가 임의로 총점을 만들 수 없다. |
| FR-907 | 허용 점수 범위를 벗어난 결과는 정규화하거나 검토 필요로 표시한다. |
| FR-908 | 재채점 결과가 기존 결과와 다르면 즉시 반영하지 않고 변경 검토 상태로 둔다. |
| FR-909 | 교사는 재채점 결과를 검토한 뒤 반영 또는 반영 안 함을 선택한다. |
| FR-910 | 채점 결과는 `draft`, `review_required`, `accepted`, `change_pending`, `rejected` 상태를 가진다. |
| FR-911 | 학생 공개, 피드백 생성, 특기사항 생성, 보고서 확정 출력에는 `accepted` 채점 결과를 기본으로 사용한다. |

### 5.11 피드백

### 5.12 특기사항

## 6. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-001 | 모든 학생 기능은 로그인 후 사용할 수 있어야 한다. |
| NFR-002 | 자동저장은 네트워크 지연과 일시 실패에 견딜 수 있어야 한다. |
| NFR-003 | AI 요청은 채점, 피드백, 특기사항으로 분리하여 컨텍스트 양을 줄인다. |
| NFR-004 | 대량 PDF, ZIP 업로드, AI 채점은 백그라운드 작업으로 처리할 수 있어야 한다. |
| NFR-005 | AI 원본 응답과 정규화 결과를 모두 보관한다. |
| NFR-006 | 개인정보와 학생 제출물 접근은 역할과 담당 범위로 제한한다. |
| NFR-007 | OJ 플랫폼이 없어도 플러그인 활성화가 실패하지 않아야 한다. |
| NFR-008 | OJ 플랫폼이 있을 때도 OJ 원본 데이터는 불필요하게 복제하지 않는다. |
| NFR-009 | 학생 API는 정답, 예시답안, 배점, 교사용 메모를 응답하지 않아야 한다. |
| NFR-010 | ZIP 업로드는 path traversal, 과도한 압축 크기, 허용되지 않은 파일 형식을 차단해야 한다. |
| NFR-011 | 긴 작업은 idempotency key와 job 상태를 사용해 중복 실행을 방지해야 한다. |
