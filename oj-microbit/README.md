# OJ Microbit

현재 릴리스는 **1.0.0-rc.9**입니다. **OJ Platform 2.5.9·Addon API 1.9 이상**에서 **문제 → 마이크로비트 문제**, **수업 → 마이크로비트 수업**에 전용 목록을 둡니다. 집중형 샘플과 달랐던 실제 화면의 버튼·간격·카드·핀별 출력 행을 수정했습니다. 여러 핀을 함께 설정하는 4화면 모달, 한 줄 목록과 편집기 재사용은 유지합니다. 일반 프로그래밍 문제·수업 목록에는 마이크로비트 항목을 섞지 않습니다. 선택 표시·빈 상태·모바일 배치를 실제 플랫폼 CSS로 점검하고 수정했습니다. 공개 문제와 수업별 프로젝트·제출·최근 결과의 분리, 스키마 5·채점 계약은 유지합니다. [사용 흐름](docs/PROBLEM-WORKFLOW.md), [집중형 화면·다중 핀 안내](docs/DESIGN-FIDELITY-1.0.0-rc.9.md), [동결 범위](docs/FEATURE-FREEZE.md), [현장 체크리스트](docs/ACCEPTANCE-CHECKLIST.md)를 확인합니다. 실제 서버 승인 전까지 정식 1.0으로 표시하지 않습니다.

OJ Platform 위에서 실행하는 별도 마이크로비트 실습·채점 애드온입니다. 실제 보드 없이 WordPress에서 과제를 만들고 MakeCode로 편집한 뒤, PXT 컴파일러·시뮬레이터와 플러그인 장치 모델에서 프로그램 출력을 채점합니다. 생성한 HEX는 내려받거나 브라우저에서 USB로 전송할 수 있습니다. USB 장치는 실제 보드 업로드 기능을 사용할 때만 필요합니다.

## 설치

PHP 8.3, WordPress 6.6, OJ Platform 2.5.9 이상·Addon API 1.9이 필요합니다. 네트워크 전체 활성화는 지원하지 않습니다. 설치 ZIP과 안내서는 `_release-kit/release.cmd`로만 생성합니다. 실제 설치는 생성된 `latest/install-guides`의 OJ Microbit 안내와 중앙 서버 준비 22단계를 따릅니다.

Ubuntu 24.04 amd64·systemd·동일 호스트 WordPress에서는 ZIP 활성화 후 SSH에서 한 번 설치할 수 있습니다. **설정 → OJ Microbit**에서 실제 사이트 경로의 명령을 복사합니다.

```bash
sudo bash /home/judge/src/web/wp-content/plugins/oj-microbit/runner/install.sh
```

전용 Node 24.22.1·Docker·이미지·서비스·인증키·실제 GPIO 점검·WordPress 연결까지 처리합니다. 기존 키와 자료를 보존하며 `--dry-run`, `--check`, 백업과 실패 복원을 지원합니다. 기존 Docker 경로에서는 APT·저장소·Docker 서비스 시작/재시작을 하지 않고 필요한 도구가 없으면 중단합니다. 포트 소유권과 npm/이미지 빌드 전 디스크 여유도 확인합니다. 웹에서 root 명령을 실행하지 않습니다. 지원 조건은 [설치기 안내](docs/INSTALLER.md), 기존 HUSTOJ 보존과 공유 자원 시험 범위는 [공존 점검서](docs/HUSTOJ-COEXISTENCE.md)를 따릅니다.

- 교사: **문제 → 마이크로비트 문제 → 문제 목록 / 문제 생성**, **수업 → 마이크로비트 수업**의 적용·결과
- 학생: **문제 → 마이크로비트 문제**의 공개 문제, **수업 → 마이크로비트 수업**의 적용 문제
- 기존 직접 링크는 문제/수업 전용 페이지로 구분해 유지합니다.
- 관리자: WordPress **설정 → OJ Microbit**
- shortcode는 제공하지 않으며 플랫폼의 애드온 메뉴·페이지·권한·자산 계약을 사용합니다.

관리자는 실행 서비스 URL과 비밀키를 설정합니다. 같은 서버는 `http://127.0.0.1:3037`을 사용하고 원격 서버는 HTTPS를 사용합니다. `wp-config.php`의 `OJ_MICROBIT_RUNNER_URL`, `OJ_MICROBIT_RUNNER_TOKEN` 상수로 설정할 수도 있습니다. 인증키를 JavaScript로 보내지 않습니다. 실행 서비스 설치 전에도 MakeCode 편집과 HEX·USB 기능은 사용할 수 있습니다.

## 과제와 실습

새 문제의 예시는 빈 상태로 시작합니다. 작성 화면은 **안내 작성 → 동작 조건 → 코드 준비 → 공개 점검** 중 현재 단계만 표시합니다. 왼쪽 단계 메뉴는 모바일에서 위쪽 네 칸으로 바뀝니다. 저장하거나 단계를 바꿔도 열린 MakeCode 편집기를 재사용합니다.

**동작 조건 → 첫 단계 만들기**에서 **단계 → 사용할 핀 여러 개 선택 → 핀별 입력값·출력값 → 간격·유지시간**을 차례로 정합니다. P0 센서, P1 LED, P2 모터를 함께 선택할 수 있으며 새 장치도 같은 화면에서 여러 개 연결합니다. 값 화면에서 P1의 **→ 다음 값 추가**로 켜짐→꺼짐 같은 직렬 동작을 구성합니다. 마지막에 **핀 N개 함께 적용**을 누르면 모두 반영됩니다.

기존 단계의 **단계 수정**은 그 시점의 모든 입력·출력 핀과 기존 직렬 동작을 불러옵니다. 핀마다 도우미를 다시 열지 않습니다. 이전·작성 취소·Escape는 원본을 보존하고, 잘못된 핀 하나가 있어도 일부만 적용하지 않습니다. 초기 입력은 모든 예시에 필요하므로 새 입력 핀의 빠진 처음 값은 다른 예시에도 0으로 준비하며 기존 값은 유지합니다.

입력의 **다음 입력 단계까지 간격**과 출력의 **유지시간**은 별개입니다. 반응 한도는 값이 나타날 때까지, 유지는 나타난 뒤를 확인합니다. 바로 켠 뒤 0.5초 기다리면 0.2초 유지 조건을 충족할 수 있지만 켜기 전에 0.5초 기다리면 반응 한도 0.1초를 넘습니다. 뒤 꺼짐 조건의 한도도 별도로 만족해야 합니다.

여러 핀은 같은 기준 시점부터 확인하는 **병렬 가지**, 한 핀의 값은 실제 유지 완료 뒤 확인하는 **직렬 화살표**입니다. 그림은 채점 조건의 관계를 표시하며 학생 코드의 스레드 검출은 아닙니다. 입력 간격을 바꾸면 단순 시간표의 뒤 기준 시점도 함께 이동합니다. 복잡한 기존 시간표·I²C 거래와 단일 고정 시각 조건의 의미는 보존하며 **세부 채점 설정**에서 확인합니다.

예를 들어 0.2초에 켜지고 1.2초에 꺼지는 프로그램은 ‘켜짐 1초 유지 → 꺼짐’ 검사를 통과합니다. 1초가 되기 전에 꺼지거나, 다음 출력이 반응 대기 한도보다 늦게 나타나거나, 중간에 다른 값으로 흔들리면 실패합니다. 유지가 끝나는 정확한 시각의 다음 출력 전환은 허용합니다. 한 번 시작한 유지 구간이 깨지면 뒤에 다시 맞는 값이 나와도 그 동작은 실패하며, 뒤 동작도 통과시키지 않습니다. 기존 단일 출력 검사의 시간 의미는 유지합니다.

교사는 단계 도우미에서 핀·장치를 연결하고 필요한 경우 연결한 장치 세부 표에서 확인합니다. 입력은 디지털 0/1과 아날로그 0~1023, 출력은 디지털 0/1과 PWM 0~1023, 서보 각도 0~180도, 서보 펄스 폭 1~20000µs입니다. 아날로그 입력 핀은 P0~P4·P10이며 일반 핀은 P0~P16·P19·P20입니다. 한 과제에서 같은 핀을 여러 연결에 중복 지정할 수 없습니다. I²C 장치를 설정하면 P19·P20은 버스가 사용하므로 일반 핀 연결에 사용할 수 없습니다.

시나리오마다 입력 시각·핀·값과 기대 출력·기준 시각·응답 제한·유지 시간·오차를 설정합니다. 서보도 같은 양식으로 각도 또는 펄스 폭과 시간 조건을 검사합니다. I²C 장치는 주소·초기 레지스터·학생 코드의 쓰기 허용 여부를 표에서 설정하고, 시나리오에는 시간별 레지스터 입력과 기대 읽기·쓰기 거래를 추가합니다. 학생에게 공개할 시나리오와 비공개 시나리오를 선택할 수 있습니다. 공개 상태로 저장하려면 각 시나리오의 모든 일반 입력 핀에 0ms 초기값을 지정하고 하나 이상의 핀 또는 I²C 검사를 설정해야 합니다. 과제는 초안으로 준비한 뒤 공개합니다. 이 버전의 공개 과제는 해당 사이트의 마이크로비트 참여 권한이 있는 모든 로그인 학생에게 표시됩니다. 작성 교사는 본인 문제와 일반 제출을 관리하며, 수업 결과는 해당 수업의 관리 권한으로 별도 확인합니다. 관리자는 관리 범위에서 문제를 관리할 수 있습니다.

학생은 MakeCode 블록·코드 편집기를 사용하고 프로젝트를 서버에 저장합니다. 저장 충돌은 기존 파일을 덮어쓰지 않고 안내합니다. 프로젝트 JSON 가져오기·내보내기, 브라우저 미저장 초안 복구도 지원합니다. 자동 채점은 최신 편집기 저장을 기다린 뒤 제출합니다. 센서 슬라이더·버튼으로 지정한 입력을 실행하면 공식 PXT에서 발생한 출력 기록을 LED·모터 표시와 표로 재생합니다. MakeCode 안의 기본 보드 시뮬레이터와 외부 장치 실험 화면은 각각 표시됩니다. 모터 표시는 PWM 비율을 나타내며 물리적인 회전 속도나 전류를 계산하지 않습니다.

예제 과제의 시작 프로젝트에는 교사가 동작을 확인할 수 있는 완성 예제가 들어 있습니다. 공개 전 점검에서 학생용 빈 틀 또는 현재 코드의 의도적 배포를 직접 선택하고 공개/비공개 예시·시간·전체 공개·학생 미리보기를 확인합니다. 서버는 점검한 내용의 지문을 최종 저장과 대조합니다. 빈 틀로 공개하면 저장된 시작 코드도 빈 틀이 되므로 참조 코드는 점검 패널에서 먼저 내보냅니다. 점검 취소·오류에서는 원래 작성 코드를 유지합니다.

## 독립 메뉴

**마이크로비트 문제**와 **마이크로비트 수업**을 독립 메뉴로 엽니다. 교사 문제 메뉴에는 **문제 목록 / 문제 생성** 하위 메뉴와 생성 전용 페이지가 있습니다. 일반 문제·수업 목록에 마이크로비트 목록·유형 필터를 등록하지 않습니다. 전용 메뉴에서도 플랫폼의 기존 참여·관리 권한과 그룹·수업 원장을 사용합니다. 목록은 기존 20개·상한 50개의 커서·요약 조회를 유지합니다. 본문의 반복 탐색은 제거하고 문제 목록/생성 탭만 사용합니다. 저장 후에도 같은 편집기에서 작성하며 불필요한 페이지·프레임 재로딩을 하지 않습니다.

## 수업 적용과 결과

**공개 문제**와 **수업 적용·결과**를 분리합니다. 교사는 관리하는 수업을 선택하고 다른 교사의 공개 문제도 적용할 수 있습니다. 학생은 **내 수업**에서 해당 문제를 열어 수업 이름이 표시된 화면에서 제출합니다. 일반 풀이·다른 수업의 프로젝트와 기록을 섞지 않습니다. 일반 100점은 수업에서 제출하기 전까지 해당 수업의 미제출 상태를 바꾸지 않습니다. 교사는 현재 명단의 최근 결과와 미제출 학생, 배정별 제출 상세를 확인합니다. 점수는 최근 제출 기준입니다.

플랫폼의 그룹은 실제 학급, class는 수업 단위입니다. 수업 참여자는 플랫폼 공개 Context·Roster API로 확인하므로 연결 그룹 학생도 플랫폼 규칙대로 반영됩니다. 기존 그룹/수업 제한 배포는 범위를 유지하고 새 수업 배정으로 자동 변환하지 않습니다.

## 실행·채점 구조

`브라우저 → WordPress REST → 인증된 자체 실행 서비스 → 일회성 Docker 작업` 경로로 채점합니다. 브라우저가 보내는 점수·trace·테스트 조건은 성적으로 채택하지 않습니다. 서버에 저장된 전체 시나리오와 제출 프로젝트를 실행기에 보내 재컴파일하고, 실행 버전·프로젝트 해시·과제 버전과 함께 결과를 기록합니다. 기존 OJ의 일반 문제 제출·AC·순위에는 자동 반영하지 않고 애드온 전용 기록으로 관리합니다.

실행기는 `pxt-microbit` 9.1.1, `pxt-core` 13.0.1을 고정해 사용합니다. 각 시나리오는 새로운 상태에서 시작하고 가상 시각과 난수 초기값을 고정합니다. 실제 출력 쓰기를 관찰하므로 쓰지 않은 초기 0이나 입력 주입값을 정답 출력으로 취급하지 않습니다. 응답 제한 안에 기대 출력이 나타난 뒤 지정한 유지 시간 동안 계속 맞아야 통과합니다. 자세한 계약과 지원 범위는 [runner/README.md](runner/README.md)를 참고합니다.

일반 GPIO 센서·LED·릴레이·PWM 모터, 일반 서보 각도/펄스 명령과 I²C 레지스터 장치를 지원합니다. 서보의 `pins.servoWritePin`과 `pins.servoSetPulse`, I²C의 `pins.i2cReadBuffer`/`pins.i2cWriteBuffer` 및 그 위에서 동작하는 Number API를 실행합니다. MakeCode 기본 시뮬레이터의 I²C는 읽기·쓰기 장치 모델을 제공하지 않으므로, 플러그인이 컴파일된 프로그램을 실행하는 PXT 런타임에 별도 장치 모델을 연결합니다. 서보 펄스 폭도 별도 계측 모델로 보완합니다. 이는 명령·레지스터 단위의 논리 시뮬레이션이며 기계 부하·토크·전류나 버스 전압·클록 파형은 계산하지 않습니다.

I²C 주소는 7비트 0~127이고 장치마다 사용할 레지스터 0~255와 초기 바이트를 선언합니다. 버퍼 쓰기의 첫 바이트가 레지스터 포인터이며 뒤의 바이트는 연속 레지스터에 씁니다. 읽기는 현재 포인터부터 연속 바이트를 반환하고 포인터는 256에서 순환합니다. 한 바이트 쓰기는 포인터 선택이므로 읽기 전용 레지스터에도 허용합니다. 데이터 쓰기는 쓰기를 허용한 레지스터에만 가능하고, 외부 입력 시나리오는 읽기 전용 센서 값도 변경할 수 있습니다. 선언하지 않은 장치·레지스터를 접근하면 실행 오류로 처리합니다. 레지스터가 없는 초안 장치는 저장할 수 있지만 공개하려면 초기 맵을 설정해야 합니다.

I²C 검사는 주소·읽기/쓰기·바이트 목록·repeated 조건·응답 제한을 비교합니다. 검사 표의 순서를 유지하며 각 거래를 한 번만 대응시킵니다. 연속 거래를 하나의 통과 증거로 중복 사용하지 않습니다. GPIO/서보 검사와 I²C 검사를 합한 통과 비율이 점수입니다. 서보는 선택한 각도/펄스 신호 종류를 구분하므로 해당 API와 단위로 과제를 구성합니다.

서보 모드를 위치 제어로 지정하는 `servoSetContinuous(false)`는 허용하며 그 자체를 각도 출력으로 기록하지 않습니다. 고정 번들 `servo: "*"` 패키지의 `servos.P0/P1/P2.setAngle()`·`setPulse()`도 지원합니다. 연속 회전 모드 `true`와 그 물성 모델, 초음파 펄스 측정·SPI 등의 전용 프로토콜 및 내장 센서 전용 입력은 아직 지원하지 않습니다. 허용 기본 패키지는 `core`, `radio`, `microphone`, `servo`이며 그 밖의 기능을 모두 채점한다는 뜻은 아닙니다. 임의 GitHub 확장 패키지는 실행기에 설치하지 않습니다.

프로젝트는 `main.ts`와 `pxt.json`을 포함하며 최대 256KiB·32개 파일입니다. 블록·Python 편집 자료도 보존하지만 채점은 MakeCode가 저장한 `main.ts`를 사용합니다. 시나리오는 최대 20개, 각 30초·합계 120초의 가상 시간, 각 입력·검사 목록은 256개까지 설정합니다. I²C 장치는 최대 16개, 장치당 레지스터는 최대 256개, 거래는 최대 64바이트입니다. 계정당 1개 동시 실행과 분당 30회 제한을 적용합니다.

MakeCode가 시뮬레이터 조작 후 저장하는 `.simstate.json`, 편집 이력 `_history`, Git 연결 정보 `.git.json`은 프로그램 소스와 구분해 정리합니다. 기존 과제·초안에 이 파일들이 있어도 프로그램과 블록을 보존하며 다시 열 수 있습니다. 한글·공백이 있는 안전한 파일명과 `.jres`·`.txt` 자료도 보존하고, 경로·URL·제어 문자·예약 파일명은 계속 거부합니다. 잘못된 파일이 있으면 오류 메시지에 해당 파일명이 표시됩니다.

학생 소스에서는 사용자 정의 네이티브 연결 지시자(`shim`, `helper` 등), ambient `declare`와 `.d.ts` 선언 파일을 사용하지 않습니다. 실행기는 TypeScript 구문과 컴파일러 주석 해석으로 이를 검사하고 지원하지 않는 입력에는 컴파일 오류를 반환합니다. 일반 함수·문자열·설명 주석·사용자 블록 표시 메타데이터와 검증된 기본 패키지는 유지합니다.

rc.7에서 이번 화면 업데이트는 DB 스키마·채점 실행기 코드를 바꾸지 않습니다. 아래 실행 식별자로 정상 준비된 기존 실행기를 사용할 수 있습니다. 호환되지 않는 구 실행기에서 이전할 때는 플러그인과 실행기를 함께 교체합니다. 실행 식별자는 `pxt-microbit/9.1.1;pxt-core/13.0.1;oj-gpio/3`입니다. 기존 일반 핀·서보·I²C 과제와 저장 프로젝트는 새 동작 순서 필드 없이도 사용할 수 있습니다. oj-gpio/3 이전 실행기는 동작 순서 검사를 지원하지 않으므로 새 플러그인이 호환되지 않는 상태로 안내합니다.

## HEX와 USB

공식 Microsoft MakeCode 임베드의 App 제어 모드에서 실제 네이티브 컴파일 결과를 받아 Intel HEX 레코드 체크섬을 확인합니다. 파일 다운로드와 USB 전송은 해당 프로젝트의 생성 HEX를 사용합니다. WebUSB는 HTTPS 또는 loopback의 Chrome·Edge에서 사용하며 사용자가 **기기 연결**을 눌러 장치를 선택합니다. 연결 후 **USB 업로드**가 다시 최신 코드를 컴파일해 플래시합니다. 다른 브라우저에서는 HEX를 MICROBIT 드라이브로 복사합니다.

편집기는 `makecode.microbit.org`의 현재 공식 서비스이므로 인터넷 연결이 필요합니다. 서비스의 네이티브 컴파일 버전과 고정된 채점 실행 버전은 다를 수 있어, 지원하는 GPIO·서보·I²C API 범위로 과제를 구성하고 변경 시 호환성을 확인합니다. 임베드 메시지는 출처와 iframe window·요청 ID를 검사하며 연결·저장·컴파일 시간 초과를 표시합니다. USB 코드는 고정 버전의 재단 연결 라이브러리를 번들로 포함합니다. [외부 고지](resources/vendor/THIRD_PARTY_NOTICES.txt)를 함께 배포합니다.

## 기록·권한·운영

목록은 기본 20건·최대 50건의 커서 페이지이며 큰 JSON은 권한을 확인한 단건 상세에서 읽습니다. 스키마 5는 배정·문제·학생 조건과 정렬에 맞춘 제출 인덱스를 사용하고 학생별 최근 결과를 별도 요약으로 읽습니다. 수업 명단 한 페이지와 결과 한 번의 일괄 조회를 결합하며 전체 제출 집계나 학생별 쿼리를 쓰지 않습니다. 기간 정리는 데이터 테이블당 50건, 개인정보 삭제는 일반 프로젝트·수업 프로젝트·최근 결과·제출 각각 100건, 작성 문제 2개와 기존 배포 관계 최대 200개, 수업 배정 생성자 익명화 최대 100개로 제한합니다. 내보내기는 여섯 자료 종류에서 한 건씩 진행합니다. 실행 중인 채점은 삭제와 같은 잠금으로 충돌을 피하며 원자 저장·삭제를 적용합니다. 실제 MySQL 계획·동시 잠금과 플랫폼 명단 원장 비용은 현장 검증이 필요합니다. 이후 DB 변경에는 `AGENTS.md`의 상한·쿼리 회귀 규칙을 적용합니다.

플러그인은 전용 문제·배포·프로젝트·제출·요청 제한·수업 배정·수업 프로젝트·최근 결과 테이블을 소유하며 플랫폼이나 채점기 테이블을 변경하지 않습니다. 교사/학생 권한은 플랫폼의 애드온 권한을 사용합니다. subscriber 역할에 기본 실습 권한을 추가하되 기존 수동 허용·거부를 보존하고, 자신이 추가한 허용만 비활성화 시 정리합니다. REST 조회·저장은 로그인과 WordPress nonce를 검사합니다. 비공개 테스트 상세는 학생 응답에서 제거합니다.

설정 변경·과제 저장/회수·채점을 `oj_microbit_audit`에 알리고 기존 `oj_log_audit_event`가 있으면 감사 로그에도 기록합니다. 실행 서비스 상태는 설정 화면과 WordPress 사이트 건강에서 확인합니다. 학생 기록은 기본 365일 후 일일 WordPress cron으로 정리하며 0일은 무기한 보관입니다. 개인정보 도구로 사용자별 자료를 내보내거나 삭제할 수 있고, 작성 교사 개인정보 삭제 시 작성 과제도 제거합니다. 비활성화와 기본 삭제는 학습 자료를 보존합니다. **삭제 시 데이터 제거**를 켠 뒤 삭제하면 전용 테이블·설정을 제거합니다. 별도 실행 서비스와 Docker 이미지는 WordPress에서 자동 삭제하지 않습니다.

## 개발 검증

처음에는 `runner/`와 `resources/tools/`에서 각각 `npm ci --ignore-scripts`로 lockfile의 의존성을 설치합니다. USB 브라우저 번들을 다시 만들 때는 `resources/tools/`에서 `npm run build`를 실행하고 생성된 외부 고지도 함께 유지합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File oj-microbit/scripts/verify.ps1
```

실제 Microsoft 임베드·네이티브 HEX 검사는 별도 네트워크 브라우저 검사입니다.

```powershell
node oj-microbit/tests/browser-acceptance.cjs
node oj-microbit/tests/browser-extended.cjs
node oj-microbit/tests/browser-workspace.cjs
node oj-microbit/tests/browser-steps.cjs
node oj-microbit/tests/browser-sequence.cjs
node oj-microbit/tests/browser-performance.cjs
```

Playwright와 Chromium을 설치한 개발 환경에서 실행하며 `PLAYWRIGHT_MODULE`, `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 경로를 지정할 수 있습니다. 이 검사는 로컬 메모리 REST fixture와 실제 PXT 실행기를 사용합니다. 실제 WordPress/MySQL 및 Docker·물리 USB 보드 검증은 별도로 수행합니다. 검증 기록과 운영 전 확인 사항은 [docs/VALIDATION.md](docs/VALIDATION.md)에 있습니다.

정식 출시 판정과 DB 실행계획·부하 측정 기준은 [출시 점검 보고서](docs/RELEASE-REVIEW.md)를 따릅니다. 실제 환경 승인 시험과 새 기능·오류 개선의 우선순위·완료 기준은 [정식 출시 계획](docs/RELEASE-PLAN.md)에 정리했습니다. 0.5.0의 공개 전 점검·한국어 필드 오류·운영 오류 분류·학급 배포와 스키마 3은 [사용 안내](docs/P1-FEATURES.md)를 확인합니다. 운영 연결은 상태·실행 응답 모두 `docker-no-network`를 요구합니다. 준비 상태는 이미지 확인이며 실제 실행 canary 시험을 대신하지 않습니다.
