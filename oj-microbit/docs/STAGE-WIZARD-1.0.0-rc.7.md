# 단계 도우미와 시간 조건 — 1.0.0-rc.7

2026-11-04. OJ Platform 2.5.9/API 1.9 이상. DB 스키마 5, oj-gpio/3, PXT micro:bit 9.1.1/core 13.0.1을 유지합니다.

## 한 번에 한 항목 작성

새 문제는 빈 예시에서 시작합니다. **입력과 기대 동작 → 첫 단계 만들기**를 누릅니다.

1. **단계 만들기**: 처음/시작 후 기준 시점과 함께 시작할지, 앞 동작 뒤에 이을지 확인합니다.
2. **사용할 핀**: 연결한 장치를 고르거나 센서·버튼·LED·모터·서보를 새 핀에 연결합니다. 아날로그가 가능한 핀과 I²C 버스 예약을 반영합니다.
3. **입력값 또는 출력값**: 디지털은 누름/켜짐·꺼짐 버튼, 아날로그/PWM·서보는 범위가 표시된 숫자를 입력합니다.
4. **유지시간**: 입력은 다음 입력 단계까지 간격, 출력은 이 값이 나타난 뒤 유지할 시간을 정합니다. 출력의 반응 시간·오차는 필요할 때만 펼칩니다.

**단계에 적용**을 누를 때만 핀·예시를 반영합니다. 이전 화면·작성 취소·Escape를 지원하고 Tab/Shift+Tab은 모달 안에서 순환합니다. 취소하면 원본과 초점을 복원합니다. 핀이나 값을 바꿔도 열린 MakeCode 프레임은 재사용합니다. 모달에서 작성하는 동안 서버 요청을 추가하지 않습니다.

새 입력 핀은 다른 예시에도 처음 값이 필요하므로 빠진 0초 초기값을 0으로 준비합니다. 기존 값은 바꾸지 않으며, 공개 전 각 예시의 처음 값을 확인합니다. 입력 256개·예시 20개·예시별 30초·총 120초 제한과 다음 입력 시점 충돌은 적용 전 검사합니다.

## 세 종류의 시간

| 화면 항목 | 의미 | 예 |
|---|---|---|
| 다음 입력 단계까지 간격 | 다음 단계의 기준 시점. 입력값은 다음에 바꿀 때까지 유지 | 0초에 P0=800, 0.5초 뒤 다음 입력 |
| 이 값이 나타나기까지 허용할 시간 | 기준 시점부터 정답 값에 도달할 때까지의 한도 | 0.1초 안에 P1 켜기 |
| 이 출력 상태를 유지할 시간 | 정답 값이 나타난 뒤 확인할 최소 유지시간 | 켜진 뒤 0.2초 유지 |

**0.2초 유지 조건이라고 0.5초 기다리면 무조건 틀리는 것은 아닙니다.** 반응 한도를 0.1초로 설정했다면 다음처럼 구별합니다.

| 프로그램 동작 | 판정 |
|---|---|
| 바로 켬 → 0.5초 대기 | 켜짐 0.2초 유지 조건을 만족할 수 있음 |
| 0.5초 대기 → 켬 | 켜지기까지 반응 한도 0.1초를 넘겨 실패 |
| 켜짐 0.2초 → 꺼짐 조건, 꺼짐 반응 0.1초, 실제로 0.5초 뒤 끔 | 켜짐은 충족하나 꺼짐의 한도를 넘겨 실패 |
| 켜짐 0.5초 → 꺼짐 조건, 실제로 0.5초 뒤 끔 | 각 유지·반응 조건을 충족하면 통과 |

출력 유지가 끝났다고 자동으로 출력이 꺼지는 것은 아닙니다. 꺼짐까지 요구하려면 화살표 뒤에 꺼짐 조건을 추가합니다. 현재 반응·유지의 최악 시간을 합쳐 실행 시간을 확보하고 마지막 단계는 자동 연장합니다. 이미 있는 다음 입력 시점과 겹치면 입력 간격을 먼저 늘려야 합니다.

## 병렬과 직렬 그림

**+ 함께 시작할 핀 추가**는 같은 기준 시점부터 각 핀을 독립적으로 확인합니다. P1 LED와 P2 모터는 나란한 가지이며 서로의 완료를 기다리지 않습니다. **→ 다음 값**은 한 핀에서 앞 출력의 실제 유지 완료 뒤 다음 값을 확인하는 화살표입니다. 별도의 검사 방식 전환 버튼 없이 그림과 모달로 작성합니다. 모바일에서는 병렬 가지의 공통 선과 표시를 유지하고 직렬 화살표는 아래를 향합니다.

이 그림은 **채점 조건의 관계**를 표현합니다. 학생 코드의 스레드나 하드웨어 동시성을 검출하지 않습니다. 실행 결과에서는 실제 출력 도달·완료 시각을 확인합니다. 새 핀 동작은 기존 출력 시퀀스 계약으로 저장하고, 기존 고정 시각 조건은 열거나 수정해도 자동 변환하지 않습니다. 기존 조건에 다음 값을 명시적으로 추가할 때만 해당 핀을 직렬 동작으로 전환합니다.

**다음 입력 단계 만들기**는 현재 실행의 다음 입력 기준을 추가하고 **별도 예시 만들기**는 프로그램을 처음부터 실행합니다. 임의 시각·겹치는 기존 시간표와 I²C 레지스터/읽기·쓰기 거래는 원문과 세부 편집을 유지합니다. I²C는 한 버스 안에서 실제 거래 순서를 확인하며 핀 모달로 버스 바이트를 바꾸지 않습니다.
