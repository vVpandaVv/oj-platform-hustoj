# 정식 출시 기능·오류 검증 계획

갱신일: 2026-11-04. 현재 대상: **OJ Microbit 1.0.0-rc.9 + OJ Platform 2.5.9/API 1.9**. 선택한 집중형 시안과 실제 화면 사이의 버튼·카드·핀 행·제목 여백 차이를 수정했습니다. 샘플 원본과 같은 내용·화면 크기로 배치를 비교하며 기존 다중 핀 모달·저장·권한 흐름을 유지합니다. DB 쿼리/스키마·채점 실행기·권한은 유지합니다. [집중형·다중 핀 안내](DESIGN-FIDELITY-1.0.0-rc.9.md)를 확인합니다. 실제 사이트는 브라우저 주소 확인 제한으로 직접 검증하지 못했으며 설치 버전·캐시·테마 확인은 현장 항목입니다. 아래 이전 버전의 경로·메뉴·검증은 해당 버전 기록입니다.


## rc.4 실제 메뉴·화면 추가 점검

두 ZIP 설치 순서, 기본 문제 유형 필터, 수업별 적용·결과 링크와 실제 역할 권한, 원래 요청 경로를 바꾸지 않는 메뉴 선택, WordPress 하위 경로 주소 생성·전송을 확인합니다. 외부 유형만 선택할 때 기존 프로그램 집계는 실행하지 않고, 정확한 수업 한 페이지는 현재 권한과 일괄 메타데이터만 조회합니다. 표준 메뉴를 이용할 수 없는 전용 권한 교사는 대체 관리 메뉴를 사용하며 일반 문제 수정 권한은 얻지 않습니다. 수행 모드에서 새 수업 상세/결과 링크를 제한하며 기존 마이크로비트 직접 페이지의 정책은 별도 현장 검증 범위입니다. 실제 WordPress 테마·MySQL·서버 부하·USB 승인은 P0로 남아 있습니다.

## 범위와 순서

WordPress는 호스트에 직접 설치하고 기존 HUSTOJ Docker와 마이크로비트 작업 이미지는 같은 Docker에서 사용합니다. MakeCode 저장·복원, GPIO·서보·I²C 논리 시뮬레이션, 단일 출력·동작 순서 채점, HEX와 USB 경로는 구현되어 있습니다. 실제 보드 없이 실습·채점할 수 있으며 실행 서비스는 필요합니다. 전압·토크·버스 파형을 재현하는 물리 시뮬레이터는 아닙니다.

먼저 시험 서버에서 설치·격리·권한·DB·부하를 검증하고, 이어 실제 교사·학생의 사용과 보드 전송을 확인합니다. 새 기능은 그 결과에 따라 작은 단위로 추가합니다. 일정은 서버와 보드 확보 후 정하며, 시험하지 않은 항목을 완료로 표시하지 않습니다.

## 공개·수업 결과 분리 P0

새 공개 문제의 수업 밖 일반 접근, 같은 문제의 일반/수업 A/수업 B 저장·제출 격리, 현재 명단·미제출·0점·컴파일 오류, 다른 교사 공개 문제의 적용과 원본 숨김 보호를 필수로 검증합니다. 공개 중단·배정 회수·수업 탈퇴·실행 중 회수·원본 삭제 후 과거 결과 권한도 확인합니다. 제출과 최근 결과의 원자 저장 실패, 명단 리비전 변경, 개인정보 삭제·보관 배치, 새 인덱스의 실제 MySQL 실행계획을 남깁니다. 일반 문제 작성자에게 수업 기록이 자동 노출되거나 기존 일반 성적을 수업으로 소급하면 불합격입니다.

| 과제 | 반드시 포함할 경계·실패 |
|---|---|
| 센서→LED/PWM | 0/1023·511/512 경계, 여러 핀 동시 출력, 쓰기 없는 초기 0, 잘못된 핀·신호 |
| 켜짐→유지→꺼짐 | 실제 도달 기준 다음 동작, 정확한 유지 종료 전환 통과, 1ms 조기 전환·유지 중 흔들림·늦은 전환 실패, 실패 뒤 생략 |
| 상태 유지 | 같은 예시의 `0→1→0→1`에서 변수 누적, 독립 예시에서 초기화, 다음 입력 단계와 시간 충돌 |
| 서보 | 각도 0/90/180, 펄스 경계·servo 패키지, 각도/PWM 혼동, 미지원 연속 회전 안내 |
| I²C | 읽기 전용 센서·쓰기 가능 레지스터, Buffer/Number 부호·바이트 순서, repeated·거래 순서·중복 매칭 금지, 미등록 주소·레지스터, P19/P20 충돌 |

## DB 속도 저하를 막는 변경 기준

- 대화형 목록은 기본 20개·상한 50개, `id < beforeId` 커서로 조회합니다. `COUNT(*)`·깊은 OFFSET·행별 추가 조회를 넣지 않습니다.
- 목록에는 요약 컬럼만 읽습니다. 소스·프로젝트·result_json·trace는 권한 확인 후 단건 상세에서 읽습니다. 데이터가 늘어도 목록의 조회 수·응답 크기·JSON 처리량이 함께 늘어나면 불합격입니다.
- 필터의 동등 조건과 범위·정렬 순서를 복합 인덱스에 맞춥니다. 실제 SQL의 EXPLAIN, 읽은 행 수·정렬·잠금 대기·PHP 최대 메모리를 남깁니다. SQLite 결과로 운영 MySQL 성능을 대체하지 않습니다.
- 기간 정리 50건/테이블, 개인정보 프로젝트·시도 삭제 100건/테이블, 문제 부모 2개·수업/그룹 관계 합계 최대 200개, 구요약 전환 8건의 배치 상한과 영속 재시도를 유지합니다. 배경 작업 지연과 쓰기 비용도 측정합니다.
- 시험용 초안 목표는 목록 SQL p95 100ms 이하, 목록 API p95 500ms 이하입니다. 현재 운영 측정값이 아니며 서버 사양·동시 사용자·실제 계획을 기록해 승인 기준을 확정합니다.
- 새 조회·필터·스키마 변경마다 실행 SQL의 쿼리 수·페이지 경계·대량 자료 회귀를 추가합니다. 통과 후에만 실제 MySQL 계획과 부하 결과로 출시 승인합니다.

## P2 — 실측 후 선택할 확장

제출 식별자 기반 멱등성, 수업 대시보드·CSV·마감·시도 정책, 크기 제한 컴파일 캐시·대기열, 추가 센서·SPI·초음파·연속 회전 서보, 여러 핀을 묶는 상대 동작을 검토합니다. 현재 구현으로 표시하지 않습니다. 캐시는 검증된 런타임·정규화 소스 해시에 묶고 성적 결과를 임의 재사용하지 않습니다. 큐·대시보드·통계도 상한과 인덱스를 먼저 설계합니다.

학급 달력 연동과 100개를 넘는 활성 학급은 플랫폼의 생명주기·일괄 멤버십 공개 계약 확장이 필요합니다. 현재 플랫폼의 학급 목록 구현 자체가 읽는 원장의 비용은 마이크로비트의 SQL 후보 상한과 별개이므로 실제 플랫폼 데이터량으로 측정합니다.

## 출시 결정과 복구

각 P0 기록에 환경·실행 명령·재현 입력·기대/실제 결과·로그 위치·검수자를 남깁니다. 키·학생 소스·개인정보는 증거에서 제외합니다. P0 미해결, 자료 손실, 숨김 조건 노출, HUSTOJ 중단, 격리 실패가 있으면 출시를 보류합니다.

릴리스는 `_release-kit/release.cmd`로 새 버전 ZIP·설치 안내서·체크섬을 생성하고 `check`를 통과시킵니다. 이미 만든 버전은 덮어쓰지 않습니다. 운영 배포는 DB 백업과 점검 시간에 진행합니다. 실패 시 실행기는 설치 백업의 이전 환경·유닛과 보존한 버전으로 복원합니다. 스키마가 바뀐 경우 ZIP만 내려서 DB를 복구했다고 간주하지 말고 시험한 DB 백업 복원 절차를 함께 적용합니다.
