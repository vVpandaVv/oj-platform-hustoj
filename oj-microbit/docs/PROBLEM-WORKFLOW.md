# 공개 문제와 수업별 실습·결과

대상: **1.0.0-rc.9**, 2026-11-04.

## 시작 메뉴

OJ Platform 2.5.9 이상에서 **문제 → 마이크로비트 문제**, **수업 → 마이크로비트 수업**의 전용 메뉴를 사용합니다. 교사는 마이크로비트 문제 메뉴의 **문제 목록 / 문제 생성** 하위 메뉴로 관리합니다. 일반 프로그래밍 문제·수업 목록과 분리하며, 작성 → 공개 → 풀이·채점 → 수업 적용 → 수업별 결과의 처리 흐름은 같습니다. 작성 화면은 안내 작성·동작 조건·코드 준비·공개 점검 중 한 단계만 표시합니다. 저장 후에는 같은 편집기를 유지합니다. 기존 생성·수업 링크도 범위를 유지해 전용 페이지로 이동합니다.

## 공개 문제

교사는 마이크로비트 문제를 초안으로 작성하고 공개 전 점검 후 공개합니다. 새로 공개한 문제는 수업 소속에 관계없이 사이트의 마이크로비트 실습 권한이 있는 로그인 사용자 모두가 풀고 채점할 수 있습니다. 문제 설명·장치 연결·공개 예시는 학생에게 표시하고 비공개 채점 조건은 서버에 보관합니다.

문제 목록은 한 줄 행이며, 학생은 기대 동작을 단계 카드로 읽고 세부 채점 표는 필요할 때 펼칩니다. 학생의 **공개 문제** 화면은 문제 목록 → 설명과 공개 예시 → MakeCode 풀이 → 임시 저장/센서 실험 → 제출하여 채점 → 일반 제출 내역 순서입니다. 일반 풀이는 해당 문제의 개인 프로젝트와 일반 제출 기록을 사용합니다.

## 단계 작성과 시간

**동작 조건 → 첫 단계 만들기**에서 **단계 → 사용할 핀 여러 개 선택 → 핀별 입력값·출력값 → 간격·유지시간**을 차례로 정합니다. P0 센서, P1 LED, P2 모터를 함께 선택할 수 있으며 새 장치도 같은 화면에서 여러 개 연결합니다. 값 화면에서 P1의 **→ 다음 값 추가**로 켜짐→꺼짐 같은 직렬 동작을 구성합니다. 마지막에 **핀 N개 함께 적용**을 누르면 모두 반영됩니다.

기존 단계의 **수정**은 그 시점의 모든 입력·출력 핀과 기존 직렬 동작을 불러옵니다. 핀마다 도우미를 다시 열지 않습니다. 이전·작성 취소·Escape는 원본을 보존하고, 잘못된 핀 하나가 있어도 일부만 적용하지 않습니다. 초기 입력은 모든 예시에 필요하므로 새 입력 핀의 빠진 처음 값은 다른 예시에도 0으로 준비하며 기존 값은 유지합니다.

입력의 **다음 입력 단계까지 간격**과 출력의 **유지시간**은 별개입니다. 반응 한도는 값이 나타날 때까지, 유지는 나타난 뒤를 확인합니다. 바로 켠 뒤 0.5초 기다리면 0.2초 유지 조건을 충족할 수 있지만 켜기 전에 0.5초 기다리면 반응 한도 0.1초를 넘습니다. 뒤 꺼짐 조건의 한도도 별도로 만족해야 합니다.

여러 핀은 같은 기준 시점부터 확인하는 **병렬 가지**, 한 핀의 값은 실제 유지 완료 뒤 확인하는 **직렬 화살표**입니다. 그림은 채점 조건의 관계를 표시하며 학생 코드의 스레드 검출은 아닙니다. 입력 간격을 바꾸면 단순 시간표의 뒤 기준 시점도 함께 이동합니다. 복잡한 기존 시간표·I²C 거래와 단일 고정 시각 조건의 의미는 보존하며 **세부 채점 설정**에서 확인합니다.

학생 보기 화면은 문제 제목·이번에 만들 동작·연결할 장치·공개 동작 예시·문제 풀기 순서입니다. 정확한 기술 표는 선택적으로 펼칩니다. 상세 사용과 모바일 화면은 [집중형 안내](DESIGN-FIDELITY-1.0.0-rc.9.md)를 따릅니다.

## 수업에 적용

교사는 전용 **마이크로비트 수업** 메뉴에서 관리 중인 수업(class)을 선택하고 공개 문제를 찾아 적용합니다. 본인이 만든 문제뿐 아니라 다른 교사의 공개 문제도 선택할 수 있습니다. 같은 문제를 여러 수업에 적용할 수 있으며 문제 원본을 복제하거나 공개 범위를 좁히지 않습니다.

플랫폼의 그룹(group)은 실제 학급 구성원이고 수업(class)은 수업 단위입니다. 그룹 제한 수업의 학생 명단과 참여 권한은 플랫폼이 연결한 그룹을 반영합니다. 마이크로비트가 그룹 번호를 수업 번호로 바꾸거나 다른 모듈의 테이블을 직접 읽지 않습니다.

학생은 전용 **마이크로비트 수업** 메뉴에서 적용된 문제를 열고 수업 이름이 표시된 풀이 화면에서 제출합니다. 수업 풀이의 저장 프로젝트·제출 기록은 해당 배정 ID에 연결되므로 일반 풀이 및 다른 수업과 섞이지 않습니다. 저장·실험은 제출을 만들지 않고 **제출하여 채점**할 때 수업 제출이 기록됩니다.

| 같은 문제 X를 푸는 위치 | 저장 프로젝트 | 제출 기록과 수업 결과 |
|---|---|---|
| 공개 문제에서 일반 풀이 | 문제 X의 개인 일반 초안 | 일반 제출 내역 |
| 수업 A에서 풀이 | 수업 A의 배정 초안 | 수업 A 결과만 갱신 |
| 수업 B에서 풀이 | 수업 B의 배정 초안 | 수업 B 결과만 갱신 |

일반 풀이에서 100점을 받아도 수업 A에서 제출한 적이 없으면 수업 A에는 **미제출**로 표시됩니다. 수업 적용 전 일반 기록이나 다른 수업 기록을 시간으로 추정해 옮기지 않습니다. 잘못된 배정·권한이 없는 수업 요청을 일반 제출로 대체하지 않습니다.

## 교사의 수업별 확인

수업의 문제별 **최근 제출 결과**는 현재 수업 명단 한 페이지에 각 학생의 최근 결과를 결합합니다. 미제출 학생도 표시합니다. 0점이나 컴파일·실행 오류는 제출한 결과이며 미제출과 구분합니다. 표의 점수는 최근 제출 점수로, 최고 점수나 전체 시도 수를 뜻하지 않습니다.

교사는 해당 배정의 제출 내역을 페이지로 조회하고 단건 결과·제출 당시 코드·문제 버전을 확인할 수 있습니다. 일반 문제 작성 권한과 수업 결과 열람 권한은 별개입니다. 문제 작성자라도 그 수업의 관리 권한이 없으면 해당 수업의 학생 기록을 열 수 없습니다. 수업 교사가 다른 교사의 공개 문제를 적용해도 원본의 비공개 채점 조건은 공개되지 않습니다.

수업에서 문제를 회수하면 새 풀이 저장·실험·제출을 중단하고 기존 배정과 결과의 연결은 보존합니다. 원본 문제를 비공개로 전환하거나 삭제해도 권한이 있는 교사는 과거 수업 제출 결과를 확인할 수 있습니다. 학생의 과거 수업 내역은 현재 수업 참여 권한을 확인한 뒤 본인 기록만 보여 줍니다. 같은 수업에 같은 문제를 다시 적용하면 기존 배정을 재활성화하며 그 수업의 이전 내역을 유지합니다.

원본 문제를 수정하면 이후 제출은 현재 공개된 문제 버전을 사용합니다. 이전 제출은 당시 프로젝트·문제 버전·결과를 유지합니다. 수업에 적용했다고 원본을 별도 버전으로 고정하거나 숨김 조건을 복사하지 않습니다.

## 기존 배포와 업데이트

rc.1/rc.2의 그룹·수업 제한 배포는 기존 범위로 보존합니다. 기존 자료를 자동으로 전체 공개하거나 수업별 배정으로 바꾸지 않습니다. 새 공개 문제는 전체 공개를 사용합니다. 기존 제한 문제를 공개 문제로 바꾸려면 작성 교사가 명시적으로 전체 공개 전환을 선택하고 공개 전 점검을 다시 진행합니다. 이전 기록은 일반 기록으로 유지하고 새 수업 배정에는 소급 반영하지 않습니다.

스키마 5는 수업 배정·별도 수업 초안·학생별 최근 결과와 제출의 배정 식별자를 추가합니다. 기존 제출의 배정 식별자 기본값 0은 일반 기록입니다. 업데이트 전에 DB를 백업하고 유지보수 시간에 필요한 DDL·인덱스 설치를 마칩니다. 원자적 제출·결과 저장에 필요한 테이블은 InnoDB여야 하며 자동 엔진 변환은 하지 않습니다. 구버전 복구는 같은 시점의 코드와 DB 백업을 함께 사용합니다. rc.2 이하 코드는 새 수업 제출 분리 조건을 모르므로 코드만 낮추지 않습니다.

문제·배정·제출 목록은 기본 20개·최대 50개의 커서 페이지이고 큰 프로젝트·결과 JSON은 권한 확인 후 단건 상세에서 읽습니다. 수업 결과는 명단 한 페이지와 해당 학생들의 최근 결과를 일괄 조회합니다. 학생마다 쿼리를 실행하거나 제출 전체를 COUNT/GROUP BY하여 표를 만들지 않습니다. 명단 리비전이 바뀌면 새 명단으로 다시 조회합니다. 활성 수업 소속은 완전한 조회 기준 사용자당 100개까지이며 초과·불완전 응답은 수업 접근만 차단합니다. 비활성 수업의 현재 명단을 플랫폼이 제공하지 못하면 교사의 보관된 제출 내역으로 안내합니다.

기간 정리는 데이터 테이블당 50건, 개인정보 삭제는 일반 프로젝트·수업 프로젝트·최근 결과·제출 각각 100건, 작성 문제 2개와 기존 배포 관계 최대 200개씩 처리합니다. 수업 배정의 생성자 표시는 최대 100건씩 익명화하며 배정 제목과 다른 학생의 기록을 삭제하지 않습니다. 배정 설정은 회수 후에도 기록 연결용으로 보존하고 데이터 삭제 옵션에 따른 플러그인 제거 시 함께 삭제합니다.

이 기능은 마이크로비트 전용 문제·수업·생성 메뉴를 사용하며 실습과 결과는 전용 저장소에서 관리합니다. 플랫폼의 수업 권한·명단을 사용합니다. 기존 OJ의 일반 문제 AC·순위와는 별도 기록입니다. 실제 WordPress·MySQL·플랫폼 권한 회수·HUSTOJ 병행 부하와 USB는 [시험 체크리스트](ACCEPTANCE-CHECKLIST.md)로 확인합니다.
