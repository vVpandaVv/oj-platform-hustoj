# 초보자 화면·메뉴·편집기 점검 — 1.0.0-rc.6

점검일: 2026-11-04. OJ Platform 2.5.9/API 1.9 코드는 유지합니다.

## 바뀐 화면

- 1차 **문제 → 마이크로비트 문제**, 1차 **수업 → 마이크로비트 수업**으로 배치합니다. 서로 다른 문제 유형의 목록은 합치지 않습니다.
- 교사의 **문제 목록 / 문제 생성**은 플랫폼 탭 한 줄로 유지하고 본문의 문제·수업·생성 반복 탭을 제거했습니다. 반복 제목·상시 안내 박스도 줄였습니다.
- 문제 목록은 번호·제목·상태 중심의 한 줄 행입니다. 기존 20개/최대 50개 커서·요약 API를 사용합니다.
- 학생 예시는 **처음 → 0.5초 후 → 1초 후** 카드로 읽습니다. 같은 시각의 센서 값·여러 출력을 묶고 디지털 값은 켜짐/꺼짐으로 표시합니다. 정확한 핀·신호·응답 제한·유지·오차 표는 선택적으로 펼칩니다.
- 교사는 **문제 안내 → 연결할 장치 → 입력과 기대 동작 → 시작 코드**를 한 단계씩 엽니다. 입력 단계 카드도 접힌 요약에서 시작하며 값·시간을 바꾸려면 해당 카드만 펼칩니다. 복잡한 기존 시나리오도 원문을 변경하지 않습니다.

## 편집기·경고 원인과 수정

기존 저장 완료 처리는 작성 화면과 iframe을 다시 만들고 새 문제 저장 시 페이지까지 이동했습니다. 또한 MakeCode가 초기 빈 블록·표시 모드·설정 파일 순서를 정리하는 자동 저장도 JSON 문자열 차이로 미저장 변경으로 판단했습니다.

**시작 코드**를 처음 열 때만 편집기를 만들고 접었다 펼치거나 같은 코드를 저장할 때 재사용합니다. 파일 순서와 표시용 설정을 정규화한 내용으로 변경을 비교하되 실제 소스·블록·리소스·의존성은 계속 검사합니다. 원본 프로젝트의 해당 메타데이터를 삭제하는 변경은 아닙니다. 실제 미저장 코드에는 이탈 경고를 유지하며 취소하면 작성 화면에 남습니다. 저장 중 늦게 도착한 코드 변경은 저장된 이전 코드로 덮어쓰지 않고 추가 저장이 필요하다고 알립니다. 학생용 빈 코드로 공개하는 명시적 선택은 새 시작 코드를 반영합니다.

## 검증과 증거

프런트 100개와 실제 공개 메뉴 서비스의 저장 메뉴 호환 6개 검사를 추가·갱신했습니다. [전체 검사 기록](rc-validation-1.0.0-rc.6.json)을 확인합니다.

실제 플랫폼 메뉴 해석·PHP 페이지 컴포넌트·CSS와 localhost REST/MakeCode 메시지 fixture를 연결한 Chromium **12개 흐름·페이지 오류 0개**입니다. 320/390/440/1280px, 밝은/어두운 화면, 한 줄 목록·중복 탐색 없음·학생 카드·원래 상세 조건·4단계 작성·iframe 유지·정확한 경고·수업 배정 범위를 확인했습니다. [브라우저 기록](browser-beginner-validation-1.0.0-rc.6.json), [학생 카드](ui-student-cards-1.0.0-rc.6.png), [문제 목록](ui-list-mobile-1.0.0-rc.6.png), [작성 화면](ui-create-mobile-1.0.0-rc.6.png), [입력 단계 카드](ui-input-cards-1.0.0-rc.6.png)를 확인합니다.

공개 메뉴의 두 항목은 위치가 바뀐 새 식별자로 등록합니다. 기존 rc.5 메뉴가 저장돼 있어도 새 기본 항목이 같은 경로를 한 번만 사용하고 옛 사본은 제외됩니다. 다른 메뉴의 사용자 설정은 유지하며 화면 조회에서 설정을 다시 쓰지 않습니다. 마이크로비트 두 항목의 이전 숨김·정렬은 새 위치에서 재확인합니다.

실제 WordPress 인증·운영 테마·메뉴 저장 설정·Microsoft MakeCode 서비스·MySQL/MariaDB·Docker/HUSTOJ 부하·물리 HEX/WebUSB는 이번 fixture가 대신하지 않습니다. [현장 체크리스트](ACCEPTANCE-CHECKLIST.md)를 따릅니다. 채점 계약 oj-gpio/3, 스키마 5·센서/서보/I²C 모델과 공개·일반·수업별 기록의 의미는 유지합니다.
