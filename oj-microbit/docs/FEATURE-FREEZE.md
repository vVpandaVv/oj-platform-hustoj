# 1.0.0-rc.9 기능 동결

갱신일: 2026-11-04. 사용자 요청에 따라 **집중형 샘플과 실제 생성·보기 화면의 디자인 차이**를 수정했습니다. 다중 핀 모달과 채점·저장 기능은 유지합니다. OJ Platform 2.5.9 / Addon API 1.9가 필요하며 기반 ZIP을 먼저 업데이트합니다. 모바일·다크 모드·키보드와 저장·취소를 실제 공통 CSS로 점검했습니다. [집중형·다중 핀 점검](DESIGN-FIDELITY-1.0.0-rc.9.md)과 [사용 흐름](PROBLEM-WORKFLOW.md)을 확인합니다.

스키마 5·공개/수업 기록 분리·oj-gpio/3와 GPIO/PWM/서보/I²C 모델, PXT micro:bit 9.1.1/core 13.0.1은 유지합니다. 일반 문제·수업에 대한 통합 목록 제공자 등록은 해제하고 기존 API의 전용 메뉴·페이지·권한을 사용합니다. 코어 채점 DB에 외부 문제를 복사하지 않습니다. 별도 설치 서버 기능을 추가하지 않습니다.

[rc.9 동결 목록](feature-freeze-1.0.0-rc.9.json)은 51개 제품 파일과 버전 진입점, 기존 최소 플랫폼 의존성을 기록합니다. rc.1/rc.2/rc.3/rc.4/rc.5/rc.6/rc.7/rc.8 ZIP과 동결 JSON은 보존합니다. 이 요청 이후에는 결함·호환·검증·문서를 보완하고 새 기능은 별도 요청으로 설계합니다.

시험 대상은 Ubuntu 24.04 amd64, PHP 8.3/POSIX, 호스트 직접 설치 WordPress, 로컬 rootful Docker와 기존 HUSTOJ입니다. 현재 자동 설치·호스트 점검의 기본 검증 경로는 활성 `docker.service`입니다. 원격 Docker·rootless Docker·ARM·WordPress 컨테이너·멀티사이트는 이 시험 절차에 포함하지 않습니다.

시뮬레이터·채점 1.0의 승인에는 실제 보드가 필요하지 않습니다. HEX·WebUSB까지 정식 지원 범위에 포함하려면 별도 보드 시험을 완료합니다. RC에서 제공되는 장치 업로드 경로가 물리적으로 검증됐다고 표시하지 않습니다.

정식 전환은 [시험 체크리스트](ACCEPTANCE-CHECKLIST.md)의 필수 항목과 [판정 기록](ACCEPTANCE-REPORT-TEMPLATE.md)에 환경·지원 규모·검수자·근거를 채운 뒤 결정합니다. 모의 테스트 통과나 도구의 종료 코드 0만으로 승인하지 않습니다.
