# 1.0.0-rc.15 기능 동결

갱신일: 2026-11-06. 현재 대상은 **1.0.0-rc.15 + OJ Platform 2.5.9 / Addon API 1.9 이상**입니다. 최신 ZIP을 먼저 설치한 뒤 기존 설치 명령을 다시 실행하면 현재 ZIP의 실행기 버전으로 업데이트합니다. 새 버전 폴더·이미지를 준비한 뒤 **릴리스·oj-live/1·GPIO 채점·실제 PXT 컴파일**을 검사하고 마지막에 WordPress 연결을 확정합니다. 실패 시 이전 설정과 서비스 상태를 복원하고 이전 포트·인증키로 health를 확인합니다. HUSTOJ Docker·컨테이너·볼륨·네트워크·DB를 관리하는 명령을 추가하지 않았습니다. [업데이트·복구 점검](INSTALLER-AUDIT-1.0.0-rc.14.md)을 확인합니다. 상태 유지 실행과 DB 스키마·저장 쿼리는 유지합니다. 실제 Ubuntu/systemd/Docker·WordPress·HUSTOJ 병행 부하는 별도 검수입니다.

이번 요청 범위는 선택한 편집 몰입형 UI와 전환 시 실행 상태 보존입니다. CSS·브라우저 조립 화면·페이지 안내, 릴리스 버전 메타데이터만 갱신했습니다. 65개 파일 동결에서 저장 SQL·실행/채점·Worker·설치 복구 코드는 rc.14와 같은 바이트로 유지합니다. [화면 적용 범위](EDITING-FOCUS-1.0.0-rc.15.md)를 확인합니다.

스키마 5·공개/수업 기록 분리·oj-gpio/3와 GPIO/PWM/서보/I²C 모델, PXT micro:bit 9.1.1/core 13.0.1은 유지합니다. 일반 문제·수업에 대한 통합 목록 제공자 등록은 해제하고 기존 API의 전용 메뉴·페이지·권한을 사용합니다. 코어 채점 DB에 외부 문제를 복사하지 않습니다. 기존 서버에 컴파일 전용 경로를 추가하고 브라우저 상태 유지 실행을 제공합니다. 채점의 시간표·GPIO/서보/I²C 모델은 유지합니다.

[rc.15 동결 목록](feature-freeze-1.0.0-rc.15.json)은 65개 제품 파일과 버전 진입점, 기존 최소 플랫폼 의존성을 기록합니다. rc.1/rc.2/rc.3/rc.4/rc.5/rc.6/rc.7/rc.8/rc.9/rc.10/rc.11/rc.12/rc.13/rc.14 ZIP과 동결 JSON은 보존합니다. 이 요청 이후에는 결함·호환·검증·문서를 보완하고 새 기능은 별도 요청으로 설계합니다.

시험 대상은 Ubuntu 24.04 amd64, PHP 8.3/POSIX, 호스트 직접 설치 WordPress, 로컬 rootful Docker와 기존 HUSTOJ입니다. 현재 자동 설치·호스트 점검의 기본 검증 경로는 활성 `docker.service`입니다. 원격 Docker·rootless Docker·ARM·WordPress 컨테이너·멀티사이트는 이 시험 절차에 포함하지 않습니다.

시뮬레이터·채점 1.0의 승인에는 실제 보드가 필요하지 않습니다. HEX·WebUSB까지 정식 지원 범위에 포함하려면 별도 보드 시험을 완료합니다. RC에서 제공되는 장치 업로드 경로가 물리적으로 검증됐다고 표시하지 않습니다.

정식 전환은 [시험 체크리스트](ACCEPTANCE-CHECKLIST.md)의 필수 항목과 [판정 기록](ACCEPTANCE-REPORT-TEMPLATE.md)에 환경·지원 규모·검수자·근거를 채운 뒤 결정합니다. 모의 테스트 통과나 도구의 종료 코드 0만으로 승인하지 않습니다.
