# 교사 공개 점검·오류 안내·학급 배포

> 현재 rc.3은 공개 문제와 수업별 적용·결과를 분리합니다. 아래 0.5.0 기록의 학급 배포는 기존 제한 수업 배포를 뜻하며 자동 공개·수업 배정 전환은 하지 않습니다. 새 사용법은 [PROBLEM-WORKFLOW.md](PROBLEM-WORKFLOW.md)를 확인합니다.

대상: OJ Microbit 0.5.1. 네 기능의 구현과 브라우저 검증은 0.5.0에서 수행했으며 0.5.1은 오류 상태 코드 안내를 정정했습니다. 실제 서버와 기기 확인은 `RELEASE-PLAN.md`의 P0로 별도 관리합니다.

## 공개 전 점검

1. 과제를 작성하고 공개 상태를 **공개 전 점검 후 학생에게 공개**로 선택한 뒤 **과제 저장**을 누릅니다. 바로 공개되지 않고 작성 화면 위에 점검 패널이 열립니다.
2. **학생용 빈 틀로 시작** 또는 **현재 코드를 의도적으로 배포**를 직접 선택합니다. 기본 선택은 없습니다. 빈 틀은 core 패키지·빈 TypeScript·빈 블록의 새 프로젝트입니다. 기존 자료 파일까지 복사하지 않습니다. 점검 중 원래 작성 코드와 편집기는 유지합니다.
3. 공개 내용 점검을 실행하면 서버가 핀·시간·예시와 학급 관리 권한을 검증합니다. 배포 대상, 공개/비공개 예시, 검사 수와 시간 조건을 확인합니다. 만점 표시는 검사 구성의 요약이며 실제 실행 점수가 아닙니다.
4. **학생에게 보일 내용 미리보기**에서 공개 설명·예시·배포 코드를 확인합니다. 원하면 학생 시작 프로젝트를 별도 MakeCode에서 확인합니다. 비공개 조건은 이 학생 미리보기에 포함하지 않습니다. 미저장 과제의 이 화면은 내용 확인용이며 센서 실행·채점은 공개 후 실습 화면에서 사용합니다.
5. 확인 체크 후 **확인하고 공개**합니다. 서버는 점검한 과제 전체의 지문과 최종 저장 내용을 비교합니다. 코드·학급·비공개 조건·시간 등 내용이 바뀌면 재점검해야 합니다. 기존 공개 과제 수정도 같은 절차를 거칩니다. 초안은 공개 확인 없이 저장할 수 있습니다.

빈 틀로 공개하면 저장된 시작 프로젝트가 학생용 빈 틀로 바뀝니다. 교사 참조 코드를 계속 보관하려면 공개 전 별도 프로젝트로 내보냅니다. 점검을 취소하거나 입력 오류가 나면 현재 작성 내용은 유지합니다.

## 쉬운 입력 오류

서버의 허용된 필드 경로를 **예시 1 → 출력 동작 순서 → 두 번째 동작 → 유지 시간**처럼 표시하고 관련 입력으로 이동합니다. 닫힌 상세 시간표는 필요할 때 펼칩니다. 입력에 `aria-invalid`를 적용하며 카드·코드를 지우고 처음부터 다시 쓰게 하지 않습니다.

프로젝트 원문·알 수 없는 오류 문구는 그대로 노출하지 않습니다. 입력 오류와 함께 표시되는 **문의 번호**는 지원용 요청 ID이며 비밀키가 아닙니다. 교사는 문의 번호·발생 시각·화면에서 한 작업을 전달하면 운영자가 안전한 로그와 대조할 수 있습니다.

## 운영 오류 분류

| 상황 | 처리 |
|---|---|
| 잘못된 입력 | HTTP 400, 가능한 경우 필드 위치·안전한 수정 안내 |
| 로그인·권한 문제 | HTTP 401/403, 타인 또는 대상 학급 밖 자료 차단 |
| 저장 충돌 | HTTP 409, 최신 자료를 덮어쓰지 않음 |
| 동시 실행·횟수·실행기 혼잡 | HTTP 429, 제한된 재시도 대기 시간과 버튼 잠금. 자동 재요청 없음 |
| 실행기 연결 실패·준비 안 됨 | HTTP 503, 원인별 안정된 오류 코드와 지원용 문의 번호 |
| 실행기 인증 설정·버전·격리·응답 이상 | HTTP 502, 설정/응답 원인별 오류 코드와 지원용 문의 번호 |
| 시스템 실행 시간 초과 | HTTP 504, 실패한 실행을 점수로 저장하지 않음 |
| 학생 코드 컴파일·런타임 실패 | 시스템 장애와 구분한 정상 채점 결과. 오류 결과를 기록하고 다음 정상 제출을 계속 허용 |

PHP와 실행기는 각각 신뢰된 요청 ID를 만들고 필요한 경우 안전한 상위/하위 요청 ID로 연결합니다. 로그에는 코드·상태·소요 시간·종료 코드 같은 메타데이터만 남깁니다. 토큰·소스·비공개 입력·원시 상위 오류는 기록하지 않습니다. 장애 후 이전에 표시한 결과는 보존하지만 실패 안내를 표시하며 새 점수로 취급하지 않습니다.

## 학급별 배포

**배포 대상 → 공개 범위**에서 사이트 전체 또는 **선택한 학급만**을 고릅니다. 기존 과제는 사이트 전체 범위를 유지합니다. 학급은 현재 교사가 관리 가능한 활성 학급에서 최대 50개를 선택합니다. 목록은 기본 20개·상한 50개의 커서 페이지로 이동하고 페이지를 넘겨도 선택을 유지합니다.

학급 과제는 선택 학급 중 하나의 활성 구성원에게만 허용합니다. 목록·직접 과제 주소·프로젝트 읽기/저장·센서 실험·자동 채점·이력 상세에서 같은 범위를 검사합니다. 실행 중에도 학급 탈퇴·비활성화·공개 회수 여부를 다시 확인해 허용되지 않은 결과를 기록하지 않습니다. 교사는 본인 과제를 관리하고 관리자는 관리 권한 범위에서 점검할 수 있습니다.

과제 소유 교사의 기존 조회·회수·이력 보존 권한은 유지합니다. 학급 관리 권한을 잃으면 새 배포·공개 점검·해당 학급을 대상으로 한 저장은 차단합니다. 과거에 직접 작성한 과제의 보관 이력 열람까지 자동 박탈하는 정책은 추가하지 않습니다.

OJ Platform의 공개 Context API만 사용하며 다른 모듈의 테이블을 직접 조회하지 않습니다. 학급 기능이 없거나 확인에 실패해도 사이트 전체 과제는 계속 사용할 수 있습니다. 학급 과제는 전체 공개로 바꾸지 않고 차단하며 안내를 표시합니다. 학생당 활성 학급은 한 번의 상한 100개 조회로 확인합니다. 다음 페이지가 남거나 응답이 불완전하면 일부만 임의 허용하지 않고 학급 확인 불가로 처리합니다.

학급의 활성 상태·참여 관계는 플랫폼 계약을 따릅니다. 현재 공개 API는 학급 달력의 시작/종료일을 제공하지 않으므로 **달력 날짜에 따른 자동 차단은 연동하지 않습니다**. 수업 종료 시 플랫폼에서 학급을 비활성화하거나 구성원 관계를 종료합니다. 이 기능과 과제 마감 기능은 구분합니다.

탈퇴 후 일반 실습·이력 API 접근은 차단되지만 WordPress 개인정보 도구의 본인 보관 자료 내보내기·삭제 권리는 유지합니다. 비공개 채점 조건은 개인정보 내보내기에서도 가립니다.

## DB와 업데이트

스키마 3은 과제의 `audience_mode`와 전용 `exercise_classes` 관계·인덱스를 추가합니다. 기존 과제·프로젝트·채점 원문과 요약 컬럼을 보존합니다. 기존 테이블의 엔진을 자동 변환하지 않으며, 과제와 학급 관계의 원자 저장을 위해 필요한 InnoDB가 아니면 준비 상태를 실패로 표시합니다.

학급 목록도 큰 JSON을 읽지 않습니다. 사이트 범위와 학급별 인덱스에서 기본 21개·최대 51개씩의 후보 키를 하나의 제한된 SQL로 합치고 최종 페이지의 요약만 가져옵니다. 100개 학급과 사이트 범위를 합쳐도 후보는 최대 5,151개 키로 제한하며 최종 요약은 최대 51개입니다. 학급 관계도 해당 페이지 ID에 대해 한 번의 작은 조회로 가져옵니다. 과제별 권한 조회 반복·전체 개수 집계·깊은 OFFSET은 사용하지 않습니다. 실제 MySQL 실행계획과 수업 부하는 현장 승인 대상입니다.

개인정보 삭제는 시도·프로젝트를 각각 최대 100건, 교사 과제는 최대 2개 부모 키와 최대 100개 학급 관계씩 나누어 처리합니다. 삭제 중 실패하면 해당 부모와 영속 재시도 작업을 보존합니다. 플러그인 기본 삭제는 자료를 보존하며 **삭제 시 데이터 제거**를 켰을 때 관계 테이블도 함께 제거합니다.

실행 중인 채점의 사용자 잠금을 잡지 못하면 개인정보 삭제를 완료로 보고하지 않고 다음 배치로 미룹니다. 과제 부모 잠금·학급 관계·부모 삭제는 한 트랜잭션으로 처리합니다. 플러그인 자료 제거의 DDL 실패는 즉시 중단하고 삭제 설정과 진단 표식을 보존합니다. DDL 전체를 되돌리는 보장은 없으므로 남은 테이블과 DB 권한을 확인한 뒤 재시도합니다.

업데이트 전 DB를 백업하고 점검 시간에 새 ZIP과 실행기를 함께 갱신합니다. 큰 테이블의 인덱스 추가와 기존 자료 검증이 끝나고 사이트 건강이 준비됨을 확인한 뒤 학생 접근을 엽니다. 운영 서버의 DB 엔진·DDL 잠금·실제 학급 계약은 시험 서버에서 확인해야 합니다.
