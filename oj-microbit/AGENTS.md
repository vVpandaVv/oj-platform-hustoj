# 마이크로비트 DB 성능 작업 규칙

루트 `AGENT.md`와 `_release-kit/README.md`를 먼저 따릅니다. 사용자가 요청한 DB 속도 저하 방지를 이후 변경에도 적용합니다.

- 학생·교사 목록은 기본 20개, 최대 50개로 제한하고 `id < beforeId` 커서로 조회합니다. 페이지 이동 때 `COUNT(*)`나 깊은 `OFFSET`을 추가하지 않습니다.
- 목록에서는 소스·블록·`data_json`·`project_json`·`result_json`·trace를 읽거나 해석하지 않습니다. 요약 컬럼을 사용하고, 상세는 소유권/권한을 확인한 단건 조회로 가져옵니다.
- 필터의 동등 조건과 정렬/범위 키 순서를 복합 인덱스와 맞춥니다. 인덱스 추가는 쓰기 비용도 검토하며 무조건 모든 컬럼에 추가하지 않습니다.
- 반복문 안의 행별 DB 조회는 대화형 목록에 사용하지 않습니다. 유지보수에서 필요한 행별 처리에는 작은 배치 상한을 두고, 큰 JSON은 한 번에 하나씩 처리합니다.
- 만료 정리·개인정보 삭제는 인덱스로 제한된 키 목록을 고른 뒤, 소유자·기간 조건을 재확인하여 해당 키만 삭제합니다. 한 요청에서 전체 이력을 삭제하거나 전체 JSON을 일괄 보정하지 않습니다.
- 스키마 변경 시 기존 자료·CAS 저장 충돌·구버전 기록을 보존합니다. 큰 테이블의 인덱스/컬럼 추가는 운영 유지보수 창에서 실행할 설치 절차를 문서화합니다.
- WordPress 개인정보 내보내기의 page 계약은 예외입니다. 페이지 결정은 인덱스의 작은 키만 사용하고 큰 원문은 페이지당 제한된 단건으로 읽습니다. 이 예외를 대화형 목록으로 확대하지 않습니다.
- 쿼리/스키마 변경에는 실행되는 SQL을 이용한 데이터량·조회 수·페이징 경계 회귀 검사를 추가합니다. 정식 출시 전 실제 MySQL/MariaDB에서 `EXPLAIN`과 부하 측정을 남깁니다. SQLite 계획이나 SQL 모양만으로 운영 성능을 보증하지 않습니다.
