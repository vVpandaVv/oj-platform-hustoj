# 교사 작업 흐름 점검 및 1.0.0-rc.2 안내

이 문서는 rc.2 시점의 기록입니다. 표의 남은 소프트웨어 보완은 [rc.3 사용 안내](workflow-rc3.md)에 구현 결과와 변경된 절차를 정리했습니다. 현재 설치·사용에는 rc.3 문서를 따르세요.

## 변경된 작업 경로

**과제·양식 설정 → 학생 제출·평가 → 필요한 학생의 재제출 설정** 순서로 진행합니다. 상단 바로가기는 계정 권한에 맞춰 표시합니다.

### 과제와 포트폴리오 양식 만들기

1. OJ Console → ML 실습 과제에서 수업·제목·안내를 입력합니다.
2. 실습 유형, 제출 횟수·기한, 파일·데이터 제한을 설정합니다.
3. **포트폴리오 양식 → 이 과제에 교사 양식 제공**을 켭니다.
4. **기본 8문항으로 시작**하거나 **문항 추가**로 제목과 작성 안내를 입력합니다.
5. **초안 만들기/수정 저장** 후 다시 수정 화면을 열어 양식을 확인하고 **게시**합니다.

양식은 최대 30문항, UTF-8 Markdown 32KiB입니다. 제목은 120자, 문항 제목은 200자까지입니다. HTML·중복 명시 문항 ID·제어문자는 거부합니다. 과제 복제 시 양식도 유지됩니다. 게시 후 과제 유형·검사 정책·양식은 고정되므로 다른 양식이 필요하면 복제해 새 과제로 게시하세요. 제목·설명·마감·최대 횟수의 기존 안전 수정은 그대로입니다.

학생은 실습 페이지의 **교사 양식 내려받기 (.md)**를 누른 뒤, 프로젝트 **포트폴리오 → 양식 가져오기 → 파일**에서 선택합니다. 파일 선택 즉시 새 문항이 추가되며, 동일 ID 문항과 기존 답변은 덮어쓰지 않습니다. 별도 적용 확인 모달은 없습니다. 기존 동일 ID의 제목·안내도 자동 갱신되지 않으므로 양식은 게시 전에 확정하고 학생이 먼저 가져오도록 안내하세요. ID가 없는 외부 문항의 제목을 바꾸면 다른 문항으로 인식될 수 있습니다.

양식은 안내 자료입니다. 학생이 문항을 수정·삭제할 수 있고, 자동 적용·필수 답변 검사·양식 일치 강제·자동 채점은 제공하지 않습니다. 학생이 제출해야 교사가 작성한 답변을 볼 수 있습니다. 교사 양식의 다운로드는 프로젝트 제출을 수동 업로드로 되돌리는 것이 아닙니다. 프로젝트는 기존 **OJ에 제출하기**로 바로 제출합니다.

### 제출 내용 확인과 평가

- **제출 보기·평가**: 파일 검사를 통과한 제출의 포트폴리오·설정·실험 기록을 실행 없이 확인합니다.
- **상태·해결 방법**: 파일 반려·검사 대기 이유와 다음 행동을 확인합니다. 읽지 못한 값은 알고리즘 없음/무결성 실패로 단정하지 않습니다.
- **재제출 설정**: 학생별 총 횟수·개인 마감·변경 사유를 별도 영역에서 저장합니다. 권한 없음·과제 종료·100회 소진 시 이유를 표시합니다.
- **제출 이력**: 학생의 과거 시도를 확인합니다.
- **평가 저장**은 비공개 초안, **저장 후 학생에게 공개**는 학생에게 점수·피드백을 전달합니다. 저장 실패 시 입력을 유지합니다. 버전 충돌이면 입력을 복사한 후 최신 상태를 확인하세요.
- 상단 집계는 현재 필터·현재 페이지의 학생 수이며 과제 전체 통계가 아닙니다.

결과 요약은 REPORT가 필요합니다. 내용·원본·평가는 REVIEW 또는 MANAGE와 현재 수업의 평가 권한을 함께 검사합니다. 학생별 허용은 MANAGE가 필요합니다. 플러그인은 이 화면에서 OJ 역할이나 권한을 임의로 부여하지 않습니다.

## 첨부 화면의 MLPX_NOT_ZIP 점검

화면에 보인 파일은 ZIP 열기에 실패한 상태이므로 안전 바로보기를 제공하지 않는 것이 맞습니다. 학생 원본과 서버 로그를 확인하지 않아 실제 원인은 확정하지 않았습니다. 0.12.1과 같은 fflate 스트리밍 ZIP을 PHP 8.3/libzip에서 열어 검사할 수 있음을 확인했으며, CHECKCONS 검증은 유지합니다.

이전 검사기는 ZIP 열기의 모든 실패를 동일한 NOT_ZIP으로 반려했습니다. 검사기 4는 명확한 형식·손상 오류만 반려하고, I/O·메모리·미확인 오류는 서버 검사 대기로 분리합니다. 학생 파일·모델을 실행하지 않고 오류 원문·서버 실경로도 노출하지 않습니다.

**이미 needs_resubmit인 제출은 업데이트로 자동 재검사되지 않습니다.** 새 제출부터 개선된 분류가 적용됩니다. 기존 제출의 재검토는 원본과 서버 증거를 확인하는 별도 운영 절차가 필요하며 안전 검사를 꺼서 열면 안 됩니다.

## 전체 점검 결과와 남은 보완

| 영역 | rc.2에서 처리 | 남은 보완 |
|---|---|---|
| 결과 화면 | 상태 카드, 다음 작업, 별도 설정·이력, 기술정보 접기 | 실제 교사/학생 파일럿 및 장시간 작업 검증 |
| 포트폴리오 | 과제별 문항 편집·저장·다운로드·학생 안내 | 원클릭 가져오기 브리지, 템플릿 라이브러리, 선택적 필수문항 검사 |
| 평가 | 안전 열람과 점수·피드백 작업 구분, 저장 실패 입력 보존 | 항목별 루브릭 편집·배점·학생 공개·채점 연동 |
| 과제 제한 | 기존 횟수·마감·크기·행·특성 설정을 단계별 배치 | 알고리즘 선택 UI, 지정 데이터셋 배포·해시 검증 설정 UI |
| 운영 설정 | WordPress/OJ 권한별 직접 이동과 불가능 이유 | 학교의 보존 정책·권한 묶음·배포 승인 |
| 제출 오류 | 서버 오류와 형식 반려 분리 | 기존 반려의 감사 가능한 운영자 재검토 절차 |

특히 기존 `rubric` 저장 필드는 완성된 루브릭 기능이 아닙니다. `allowedAlgorithms`, 지정 데이터셋 해시 정책도 서버에 존재하지만 별도 교사용 입력 UI는 이번 변경에 포함하지 않았습니다. 위 항목은 완료된 기능으로 안내하지 않습니다.

## 설치와 검증 범위

DB와 비공개 제출물을 함께 백업한 뒤 ZIP 전체를 교체하세요. 버전은 **1.0.0-rc.2**, DB 스키마는 **3**입니다. 이미 rc.1에서 스키마 3으로 업데이트했다면 추가 DB 변경은 없습니다. WordPress 도구 → ML 실습 운영에서 버전·스키마·OJ 연결을 확인하고 기존 실습 탭을 닫은 뒤 새 탭에서 확인하세요. 학생이 작업 중이면 먼저 제출·보존하게 합니다.

로컬 회귀 및 브라우저 API fixture 검증과 운영 서버 실제 인수시험은 다릅니다. 학교 OJ 로그인·역할별 권한, PHP-FPM/Nginx, 공용 PC 파일 선택/포커스/사용자 전환, 동시 접속, 백업 복원은 여전히 현장 확인 대상입니다. rc.2는 정식 1.0.0 안정판 또는 WordPress.org 공개 배포를 의미하지 않습니다.
