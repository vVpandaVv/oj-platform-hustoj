# 운영 점검

2026-09-11 패키징 시점 안내: 합의한 기관용 기술 운영 인수를 통과했으며 정식 1.0.0은 RC6 실행 코드·번들을 유지합니다. 승인 기준 시험 서버 OJ dev.107 / ML RC6에서 G1 삭제·다중 탭 종료·재로그인 후 미노출과 서버 자료 보존, OJ 개인정보 URL 상속 연결을 확인했습니다. 실제 1.0.0 설치 결과와 최신 서버 상태는 배포 폴더의 외부 검증 기록을 따릅니다. 이 문서는 일반 운영 점검표이며 아래 전체 항목을 현재 승인 조건으로 다시 요구하지 않습니다. 서버 관리·로그·백업·복원은 사용자 직접 수행 영역으로 인계했으며 에이전트의 검증 PASS가 아닙니다. 정확한 범위는 [기술 승인 기록](release-1.0.md)을 따릅니다.

## 설치 전

- OJ Platform과 Addon API 버전 범위 확인
- HTTPS 적용 및 WordPress REST cookie 인증 확인
- PHP `zip` 확장 설치
- `upload_max_filesize`, `post_max_size`, 프록시/웹 서버 body 제한을 과제 최대 파일 크기 이상으로 설정
- 웹 문서 루트 밖의 비공개 저장 디렉터리 생성과 쓰기 권한 확인
- PHP 요청 시간과 메모리 제한을 예상 MLPX 크기에 맞춰 검토
- 공용 PC는 반드시 HTTPS로 제공하고 Web Crypto, IndexedDB, BroadcastChannel, Web Locks와 쿠키 정책을 실제 학생 계정으로 확인
- 개인정보 안내는 유효한 `oj_ml_playgrounds_privacy_url` 필터 → ML 별도 주소 → 정상 OJ 연결의 `home_url('/privacy')` → ML 기본 기술 안내 순으로 적용합니다. ML 설정을 비워두면 OJ의 공개 개인정보 경로를 이어받고, 플랫폼이 없거나 연결되지 않으면 기본 기술 안내를 제공합니다. 필터의 기존 HTTP(S) 호환은 유지하지만 화면에서 직접 저장하는 주소는 HTTPS만 허용합니다.
- 설정 화면의 실제 적용 URL·출처와 OJ 개인정보 문서의 공개 여부를 확인합니다. ML은 문서 내용·게시 상태·보존 정책을 복제하지 않으며, 기관명, 담당자, 보유기간, 위탁·백업 정책은 기관에서 확정합니다. ML 기본 기술 안내를 기관의 최종 개인정보 처리방침으로 사용하지 않습니다.
- 동일 브라우저 프로필에서 학생 A/B 전환, 세션 만료, bfcache 복원, 다른 탭에 의한 IndexedDB 삭제 차단 시나리오 시험

공용 PC 보호는 애플리케이션 계층의 우발적 교차 노출 방지입니다. 악성 확장 프로그램, 관리자 권한, 개발자 도구, 디스크 포렌식까지 포함하는 강한 격리가 필요하면 학생별 OS/브라우저 프로필 또는 수업 종료 시 자동 초기화되는 계정을 함께 사용합니다.

실제 배포 절차와 A/B 계정 전환·BFCache·다중 탭 삭제 인수 테스트는 [공용 PC 배포 체크리스트](public-pc-deployment.md)를 따릅니다.

## 수업 운영

- 저사양 기기는 큰 이미지 데이터셋과 많은 알고리즘 동시 학습을 피합니다.
- 브라우저 탭 종료·절전·모바일 메모리 회수로 학습이 중단될 수 있음을 학생에게 안내합니다.
- 기본 제출 경로는 임베디드 툴바의 **OJ에 제출하기**입니다. 현재 메모리 프로젝트가 다운로드 없이 바로 전송되며, 접힌 수동 `.mlpx` 업로드는 직접 제출 장애 때만 사용합니다.
- 실습 종료 전에 시도 번호·접수 시각·SHA-256 영수증으로 OJ 제출 완료를 확인한 뒤 “이 기기의 내 실습 데이터 삭제”를 누르게 합니다. 1.0.0은 RC6와 같이 페이지 내 확인창에서 **로컬 데이터 삭제**를 명시적으로 누른 뒤 현재 계정을 다시 확인합니다. 취소·Esc는 삭제하지 않습니다.
- 로컬 삭제는 서버 제출물과 사용자가 별도로 내보낸 다운로드 폴더의 `.mlpx`를 지우지 않으므로, 내보낸 파일이 있으면 학생이 직접 삭제하게 합니다.
- CSV·이미지 등 원본 파일, 클립보드 기록과 브라우저/OS 동기화 사본도 플러그인이 지우지 않으므로 기관 정책에 따라 별도로 정리합니다.
- 삭제 실패·완료 응답 시간 초과 안내가 나오면 같은 사이트의 다른 실습 탭을 모두 닫고 해당 페이지를 직접 새로고침해 결과를 확인합니다. 1.0.0은 결과를 자동 새로고침으로 지우지 않습니다. 시간 초과 뒤 native DB 요청이 늦게 끝날 수 있으므로 성공이나 미삭제 어느 쪽으로도 단정하지 않습니다.
- 45초 silent 검증 중에는 포커스가 다른 곳에 있어도 현재 화면을 유지합니다. hidden 복귀의 strict 검증이 실패하거나 계정 불일치로 terminal 잠금이 되면 자동 새로고침을 기다리지 말고 로그인 상태를 바로잡은 뒤 사용자가 명시적으로 실습 페이지를 새로고침합니다.
- 제출 완료 화면의 시도 번호, 접수 시각, SHA-256 영수증을 확인하게 합니다.
- `system_pending` 또는 `quarantined` 제출은 학생 오류로 단정하지 않습니다. 서버의 PHP ZIP 확장, 비공개 저장소 파일 존재 여부·권한·SHA-256 무결성, 디스크와 로그를 먼저 점검하고 원인을 해결한 뒤 교사 콘솔의 **재검사** 버튼으로 다시 검사합니다. 저장 파일이 없거나 해시가 기록과 다르면 재검사는 오류로 fail-closed되며 학생에게 재제출 책임을 전가하지 않습니다.
- `draft` 과제는 게시 전에 수정하거나 삭제할 수 있습니다.
- `published` 과제는 제목, 설명, 마감 시각과 최대 시도 횟수만 유효성 검사를 거쳐 수정합니다. 최대 시도 횟수는 유지하거나 늘릴 수만 있고, 과제 유형·제출 정책·명단·Context snapshot은 게시 후 고정됩니다.
- 단순한 OJ Context revision 변경은 기존 기록 접근을 자동 차단하지 않습니다. 과제 게시 명단은 스냅샷으로 보존하고 참여·교사 권한은 현재 OJ 권한으로 재확인합니다. 비활성 수업은 신규 참여가 차단되며 교사는 현재 관리 권한으로 과거 기록을 봅니다. OJ에서 수업 자체를 삭제하면 교사 접근을 복구할 수 없으므로 수업은 삭제보다 비활성화를 사용하고, 불가피한 경우 운영자 CLI로 당사자 기록을 내보내세요.
- 보관은 삭제가 아닙니다. 보관한 과제는 학생 목록에서 숨기되 시도, 제출 원본, 검사·평가와 교사 결과를 보존합니다.
- 마감된 미제출 과제는 학생 목록에서 숨기고, 제출 이력이 있는 과제는 접힌 **과거 제출 결과**로 제공합니다.
- 실행 불가능한 버튼은 대기 커서를 표시하지 않습니다. 실제 네트워크 요청이나 저장 작업 중인 버튼에만 진행 상태가 표시되는지 확인합니다.
- 교사는 학생 행의 **최신 제출 내용 및 평가 보기**에서 허용 목록 요약을 확인합니다. REPORT 전용 계정은 요약만 볼 수 있습니다. REVIEW/MANAGE 계정은 **제출 내용 안전 바로보기**에서 답안·설정·기록된 지표를 확인하고, 필요한 경우 정상 검사 상태의 원본 attachment도 받을 수 있습니다.
- 안전 바로보기가 409/503으로 실패하면 제출 상태, PHP `ZipArchive`, 비공개 파일 존재 여부·regular file 여부, DB 바이트 수·SHA-256과 PHP 임시 디렉터리의 공간·쓰기 권한을 확인합니다. 바로보기 실패 시 원본을 자동 실행하는 우회 동작은 없습니다.
- 안전 바로보기는 원본 전체를 한 번 읽어 검증된 임시 사본을 만든 뒤 네 개의 메타데이터 JSON과 참조된 CSV를 읽습니다. CSV 통계는 전체 8 MiB·1,000,000셀·6개 파일·3초, 파일당 50,000행·128열로 제한하고 모델/전처리는 실행하지 않습니다. 실제 최대 MLPX와 동시 교사 열람 수로 PHP-FPM 실행 시간, 임시 디스크 용량과 메모리 사용량을 시험합니다. 통계 제한 시 원본 제출·수동 평가는 유지되지만 필수 근거가 부족한 AI 점수는 반영할 수 없습니다.
- 원본 다운로드가 409/503으로 실패하면 상태, 비공개 파일 존재 여부·regular file 여부, DB 바이트 수와 SHA-256을 확인합니다. 저장 경로나 storage key를 로그·화면에 복사하지 말고, 크기·해시가 다르면 fail-closed 상태를 유지합니다.
- 큰 원본 다운로드는 PHP가 1 MiB chunk로 전송하지만 전송 전 한 번 전체 해시를 읽습니다. 실제 최대 MLPX로 PHP-FPM 실행 시간, Nginx `fastcgi_read_timeout`, 프록시 buffering과 동시 다운로드 영향을 시험합니다.

## 백업·복구

데이터베이스 8개 테이블과 비공개 artifact 디렉터리를 같은 복구 지점으로 백업해야 합니다. DB 행만 복원하거나 파일만 복원하면 영수증의 SHA-256과 저장 레코드가 일치하지 않을 수 있습니다.

## 복구·정리 명령

WordPress 루트에서 실행합니다. 먼저 테스트 사이트와 백업에서 절차를 검증하세요.

```bash
wp oj-ml doctor
wp oj-ml recover
wp oj-ml reconcile
wp oj-ml retention
wp oj-ml audit --after=0
wp oj-ml export-user --user=123 --assignment=45
wp oj-ml manifest
```

- doctor: 상태 확인. 정상 조건을 충족하지 않으면 종료 코드 1입니다. WP-CLI의 PHP 설정과 PHP-FPM 설정은 다를 수 있으므로 웹 상태 화면도 확인합니다.
- recover: 대기 제출을 최대 100개 재시도합니다. 화면 버튼은 최대 10개입니다. 원본을 재업로드하지 않습니다.
- WP-Cron은 5분 간격으로 최대 10개를 확인하고 시도별 최대 5회 실패 후 운영자 확인 대상으로 남깁니다. 방문자가 없는 사이트에서는 시스템 cron 또는 기관 스케줄러로 WordPress cron을 실행해야 합니다. 이번 설치가 서버 cron을 자동 등록하지는 않습니다.
- reconcile: DB와 원본의 누락·손상·고아 파일을 조사합니다. 파일 정리는 `wp oj-ml reconcile --fix --yes`로 명시 실행하며 24시간이 지난 검증된 고아/부분 파일만 제거합니다. DB 실패로 접수 여부가 불확실했던 파일을 성급히 삭제하지 마세요.
- retention: 항상 dry-run부터 확인합니다. 삭제 유예를 해제하고 기간을 설정한 뒤 `wp oj-ml retention --execute --yes`를 실행하면 종료/보관 과제 원본을 최대 100개 삭제합니다. 점수·메타데이터는 보존합니다. hasMore가 true이면 별도 배치를 실행합니다.
- export-user: 지정 학생·과제의 이력/공개 평가와 원본을 비공개 exports ZIP으로 생성합니다. 공개 URL은 만들지 않습니다. 인증된 당사자에게 전달하고 사본은 직접 정리합니다.
- manifest: DB·원본 백업을 대조할 크기/해시 목록을 비공개 exports 폴더에 생성합니다. 완전한 DB 백업을 대신하지 않습니다.

WordPress 도구의 개인정보 내보내기·삭제 도구에도 ML 항목이 등록됩니다. 삭제는 기본 거부이며 기관 설정과 확인된 요청이 필요합니다. 교사 작성 기록은 보존 사실을 알립니다. WordPress 사용자 계정, 타 플러그인과 백업은 별도 관리 대상입니다.

백업은 점검 모드를 켜고 실행 중 요청과 CLI 변경이 끝난 후 진행합니다. 절차는 [업그레이드 안내](upgrade-1.0.md)를 따릅니다.

## 관찰성

모든 REST 응답은 correlation ID를 사용합니다. 예기치 않은 예외는 `oj_ml_playgrounds_rest_exception` action으로 전달되므로 운영 로거와 연결할 수 있습니다. 제출·게시·검토·공개 같은 주요 변경은 `oj_ml_events`에 별도 기록됩니다.
