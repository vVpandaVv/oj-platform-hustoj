# 공용 PC 배포 체크리스트

2026-09-11 패키징 시점 안내: 합의한 기관용 기술 운영 승인 범위의 G1 실제 삭제·다중 탭 종료·재로그인 후 미노출과 서버 자료 보존 검사를 통과했습니다. **1.0.0은 검증된 RC6 실행 코드·번들을 유지하는 정식 승격본**입니다. 승인 기준 시험 서버는 OJ dev.107 / ML RC6 / 스키마 4였으며 실제 1.0.0 설치 결과와 최신 서버 상태는 배포 폴더의 외부 검증 기록을 따릅니다. 서버 관리·로그·백업·복원은 운영자 직접 수행으로 인계했고 검증 PASS로 대신 표시하지 않습니다. [기술 승인 범위](release-1.0.md)를 따르며 아래 일반 권장 시험 전체를 이번 승인 선행 조건으로 다시 요구하지 않습니다.

## 1.0.0 삭제 동작과 무반응 확인

1. **이 기기의 내 실습 데이터 삭제**를 누르면 페이지 안의 확인창이 열린다. 기본 초점은 **취소**이며 취소·Esc로 닫으면 삭제하지 않는다.
2. **로컬 데이터 삭제**를 명시적으로 선택하면 현재 OJ 계정을 새로 확인하고 삭제를 시작한다. 이 확인 중에는 다른 계정으로 바꾸거나 페이지를 이동하지 않는다.
3. 성공은 **로컬 데이터 삭제 완료**로 남는다. 자동 새로고침하지 않으며 다운로드 폴더 파일은 따로 지워야 한다. 서버 제출물·평가는 삭제 대상이 아니다.
4. 실패·응답 시간 초과는 성공이 아니다. 브라우저 삭제 요청은 뒤늦게 끝날 수 있으므로 “삭제되지 않음”으로 단정하지 않는다. 다른 ML 실습 탭을 닫고 이 페이지를 직접 새로고침한 뒤 결과를 확인하고 필요한 경우 다시 시도한다.
5. 확인창이 없거나 곧바로 새로고침된다면 RC5 이하 자산이 남았는지 확인한다. 1.0.0 전체 ZIP·관련 캐시·기존 탭 재열기를 확인하며 브라우저 저장소를 개발자 도구로 강제 삭제해 인수 시험을 대신하지 않는다.

이 문서는 `oj-ml-playgrounds` **1.0.0 / DB 스키마 4 / ML Playgrounds 0.12.1+OJ 패치**를 학교 컴퓨터실처럼 여러 학생이 같은 브라우저 프로필을 순서대로 사용하는 환경에 배포할 때의 일반 점검표입니다. 내장 앱은 RC6에서 검증한 삭제 패치 번들을 유지하므로 RC5 이하 자산과 혼합하지 않습니다. 플러그인의 보호 기능은 정상 UI에서 이전 학생의 자료가 다음 학생에게 우발적으로 노출되는 일을 줄입니다. 관리자 권한, 악성 확장 프로그램, 개발자 도구, 디스크 포렌식까지 막는 OS 보안 경계는 아닙니다.

RC6의 실제 서버 인수 증거와 1.0.0 패키지 검증은 구분합니다. 기존 RC4·RC5·RC6 ZIP은 동결 역사본이며 다시 포장하지 않습니다. 1.0.0 설치에는 정식 ZIP의 `.sha256`과 외부 검증 기록을 사용합니다. 36명·8GB RAM·Chrome 동시 부하는 미검증입니다.

## 이전 검증 기록

다음은 RC4·RC5의 과거 검증이며 RC6 실제 삭제 통과를 뜻하지 않습니다. 최신 상태는 위 머리말과 출시 기록을 따릅니다.

- rc.4 발행 시 Chrome/Edge 브라우저 UI 회귀 576개가 통과했지만 REST·인증·실습 iframe 데이터는 합성 fixture였습니다. 이 수치를 실제 공용 PC 인수 시험 통과로 간주하지 않습니다.
- 9월 9일 초대 접근 장애는 9월 10일 오전 dev.102 확인 후 시험 계정의 수락으로 해소했습니다. 저녁 실제 사이트의 ML rc.4에서는 학습·직접 제출·재제출·교사 안전 보기·평가 공개·학생 확인과 타 학생 결과 차단을 확인했습니다. 파일 선택 후 프로젝트 복귀와 순차 계정 전환의 로컬 목록 격리도 확인했습니다. 저녁 시험 전 과정에서 OJ 플랫폼 빌드를 고정 확인하지는 못했습니다.
- 9월 10일 20:23 KST 서버 표시는 dev.103/ML rc.4이고 사용자가 업데이트 종료를 확인했습니다. dev.103 고정 ZIP은 확보했지만 서버 설치 바이트 전수 대조는 미수행이며 후속 계약·회귀 결과는 rc.5 외부 검증 기록에 구분합니다. ML rc.5는 아직 설치하지 않았습니다.
- 실제 배포 PC의 BFCache, 다중 탭 삭제, 장시간 학습과 Chrome/Edge 전체 공용 PC 시험은 미완료입니다. 정식 규모는 36명·8GB RAM·Chrome으로 확인했지만 그 동시 부하 시험은 아직 수행하지 않았습니다. 아래 인수 테스트는 실제 배포 PC와 승인된 시험 수업에서 별도로 기록해야 합니다.

## 다른 배포 환경에 적용할 일반 조건

- 운영자의 복구 준비 후 1.0.0 ZIP 전체 교체 → PHP-FPM/OPcache와 관련 캐시 갱신 → 기존 실습 탭 모두 닫고 재열기 → 스키마 4 확인 → 회귀 시험 순서로 진행합니다. 이미 스키마 4이면 추가 DB 변경은 없습니다. [업데이트 안내](upgrade-1.0.md)를 따르세요.
- 새로운 환경에서는 삭제 확인·취소·다중 탭·재로그인 후 미노출과 서버 제출 보존을 확인합니다. RC5부터 제공한 영수증 시각과 서버 사용 횟수 재조회도 유지되는지 재확인합니다. 새 **실습 시작**으로 서버 시도가 생성되면 제출 전에도 사용 횟수가 증가합니다. 기존 시도 이어하기나 동일 영수증 재전달은 추가 차감하지 않으며, 추가 허용·환급 등에 따라 시도 번호와 사용 횟수는 항상 같지 않을 수 있습니다. 1.0.0도 이 기존 정책을 바꾸지 않습니다.
- WordPress, OJ 화면, REST API와 내장 playground를 모두 HTTPS로 제공합니다. HTTP에서는 Web Crypto 기반 vault를 지원하지 않습니다.
- 학생마다 별도 WordPress/OJ 계정을 사용하고, 인증 쿠키에 `Secure`, `HttpOnly`, 적절한 `SameSite` 정책을 적용합니다.
- Chrome 또는 Edge의 현재 지원 버전에서 Web Crypto, IndexedDB, BroadcastChannel과 Web Locks 사용 가능 여부를 실제 학생 계정으로 확인합니다. 네 API 중 하나라도 없으면 공용 PC 저장소는 fail-closed됩니다.
- OJ Console의 ML 실습 설정에서 개인정보 URL을 비워두면 정상 연결된 OJ Platform의 `home_url('/privacy')`를 이어받습니다. 별도 기관 주소가 필요한 경우에만 HTTPS 주소를 저장하거나 `oj_ml_playgrounds_privacy_url` 필터로 연결합니다. 설정 화면의 실제 적용 URL·출처와 OJ 문서의 공개 여부를 확인합니다. ML은 문서 내용·게시 상태·보존 정책을 복제하지 않으며, 기관명, 담당자, 보유기간, 위탁·백업 및 삭제 절차가 없는 기본 기술 고지를 최종 방침으로 사용하지 않습니다.
- 비공개 MLPX 저장 경로가 웹 문서 루트 밖에 있고 PHP가 쓸 수 있는지 확인합니다. PHP `zip` 확장과 업로드 크기 제한도 과제 정책에 맞춥니다.
- WordPress 인증 SALT를 서버 이전 때 임의로 바꾸지 않습니다. `auth` 또는 `secure_auth` SALT가 바뀌면 기존 브라우저 vault의 scope나 키가 달라져 로컬 프로젝트를 다시 열 수 없습니다. 보안 사고로 SALT를 회전해야 하면 먼저 제출·내보내기 가능 여부를 판단하고, 회전 후 공용 PC의 해당 사이트 데이터를 초기화합니다.
- 이미지 실습을 쓴다면 `storage.googleapis.com`의 MobileNetV2 다운로드와 기관 네트워크 정책을 확인합니다. 예시 데이터셋을 허용할 때에는 개인정보 고지에 적힌 외부 연결도 검토합니다.

별도 기관 URL을 필터로 연결하는 선택 사항:

```php
add_filter(
    'oj_ml_playgrounds_privacy_url',
    static fn (): string => 'https://school.example/privacy'
);
```

적용 순서는 유효한 필터 값 → 유효한 ML 별도 주소 → 정상 OJ 연결의 `/privacy` → ML 기본 기술 안내입니다. 잘못된 주소는 다음 순위로 넘어가며, 플랫폼이 없거나 연결되지 않고 별도 주소·필터도 없으면 번들 기본 기술 안내를 제공합니다. 기관 필터의 기존 `http`/`https` 호환은 유지하지만 운영 시에는 HTTPS를 사용하고, 설정 화면에 직접 저장하는 주소는 HTTPS만 허용합니다. OJ에서 실제 개인정보 문서를 게시했는지는 별도로 확인해야 합니다.

## PC와 브라우저 정책

- 학생에게 관리자 권한을 주지 않고, 승인되지 않은 확장 프로그램·동기화·비밀번호 저장을 정책으로 차단합니다.
- 가능하면 학생별 브라우저/OS 프로필을 사용합니다. 단일 공용 프로필이라면 수업 종료 때 프로필을 자동 초기화하는 관리 도구를 함께 사용합니다.
- 브라우저 시작 시 이전 세션 자동 복원을 끄고, 수업 종료 후 모든 OJ 탭과 사용자가 별도로 파일을 내보낸 경우의 다운로드 폴더를 정리합니다.
- 브라우저/OS 클립보드 기록과 계정 동기화를 끄거나 수업 종료 시 정리합니다. 플러그인은 OJ origin 밖의 다운로드·클립보드·동기화 사본을 지울 수 없습니다.
- 학습은 학생 PC에서 실행됩니다. 저사양 PC에서는 이미지 데이터셋 크기와 동시 실습 탭 수를 제한합니다. 암호화·내보내기 과정에는 원본과 암호문이 잠시 함께 메모리에 존재할 수 있으므로 실제 수업용 데이터로 RAM 사용량을 측정합니다.
- 프록시나 CDN이 `/wp-json/oj-ml/`의 인증 응답을 캐시하지 않는지 확인합니다. 플러그인은 `Cache-Control: private, no-store`와 `Vary: Cookie`를 보냅니다.

## 다른 환경·후속 변경의 권장 인수 테스트

아래 전체 목록은 일반 검수용입니다. 현재 사이트의 합의한 기술 승인 범위에 다시 추가하는 선행 조건이 아니며, 실제 수행하지 않은 항목은 미검증으로 남깁니다.

1. 학생 A가 식별하기 쉬운 이름의 프로젝트를 저장하고 새로고침했을 때 자기 프로젝트만 복원되는지 확인합니다.
2. A가 다른 페이지로 이동해 이전 실습 화면을 BFCache에 넣은 뒤 로그아웃하고 학생 B로 로그인합니다. 뒤로가기로 복원하면 이전 iframe을 재사용하지 않고 strict 로그인 검증을 수행하며, A의 프로젝트명이나 화면이 한 프레임도 나타나지 않는지 확인합니다.
3. 같은 scope로 실습 탭을 두 개 연 뒤 한 탭에서 “이 기기의 내 실습 데이터 삭제”를 실행합니다. 다른 탭도 저장 권한이 폐기되고, 성공 메시지 뒤 늦은 자동저장으로 DB가 다시 생성되지 않는지 확인합니다.
4. 다른 탭 때문에 삭제가 끝나지 않은 경우 성공으로 표시되지 않고 재시도 안내가 나오는지 확인합니다.
5. A가 삭제하지 않고 정상 로그아웃한 뒤 B로 로그인합니다. B의 프로젝트 목록이 비어 있고 A의 암호화 DB를 정상 UI에서 열 수 없는지 확인합니다. 다시 A로 로그인하면 A의 자료만 복원되어야 합니다.
6. 내장 playground의 `index.html`을 주소창에서 직접 열었을 때 앱이 저장소를 열지 않고 OJ 호스트 필요 오류로 중단되는지 확인합니다.
7. **실습 시작 → 새 프로젝트 → 만들기**를 실행해 프로젝트 홈이 계속 표시되고 빈 화면으로 바뀌지 않는지 확인합니다. 45초 주기 검증 응답을 지연시키고 다른 창이나 iframe에 포커스를 둬도 같은 화면이 계속 표시되어야 합니다.
8. 문서를 숨겼다가 다시 표시하면 보호막 뒤에서 strict 검증이 수행되고, 같은 계정이면 동일 프로젝트가 다시 표시되는지 확인합니다.
9. 데이터 추가와 프로젝트 가져오기의 **파일 선택**을 눌러 운영체제 파일 선택 창에서 선택과 취소를 각각 시험합니다. 선택 창 동안에는 불투명 보호 안내가 표시되고, 돌아온 뒤 계정 재검증이 끝나면 같은 프로젝트가 복원되며 선택 이벤트가 한 번만 처리되어야 합니다.
10. 임베디드 툴바의 **OJ에 제출하기**를 한 번 눌러 현재 프로젝트가 다운로드 없이 제출되고, 학생별 시도와 SHA-256 영수증, 검사 결과와 교사 평가 화면이 올바른 소유자에게만 보이는지 확인합니다.
11. 교사 결과 화면에서 최신 제출 요약이 표시되는지 확인합니다. REPORT 전용 계정에는 안전 바로보기·원본 버튼·평가 초안이 없어야 합니다. REVIEW/MANAGE 교사는 자기 수업의 정상 제출에서만 **제출 내용 안전 바로보기**를 열어 답안·설정·기록된 지표를 확인할 수 있어야 하며 모델·데이터·첨부파일은 실행되지 않아야 합니다.
12. REVIEW/MANAGE 교사가 자기 수업의 정상 제출만 attachment로 내려받는지 확인합니다. 다른 수업 교사·학생 계정·만료 nonce·변조된 파일은 안전 바로보기와 원본 다운로드 모두 거부되어야 합니다. 이 서버 제출 사본은 학생 공용 PC의 로컬 vault와 별개입니다.
13. 기본으로 접힌 **바로 제출이 안 될 때 파일로 제출**을 펼쳐 fallback 업로드도 별도로 시험합니다. 이 경로가 기본 제출 절차처럼 먼저 노출되어서는 안 됩니다.
14. `storage-revoked`를 유도했을 때 terminal 안내를 유지하고 자동 새로고침이나 상태 문구 교대가 반복되지 않는지 확인합니다.
15. 로컬 삭제 후에도 이미 서버에 제출한 결과는 유지되고, 사용자가 별도로 내보낸 다운로드 폴더의 `.mlpx`는 자동 삭제되지 않는지 확인합니다.
16. 교사 계정에서 `draft` 과제를 수정한 뒤 삭제할 수 있는지 확인합니다. `published` 과제는 제목·설명·마감 시각·최대 시도 횟수만 수정되고, 최대 시도 횟수 감소와 과제 유형·제출 정책 변경은 거부되어야 합니다.
17. 과제를 보관했을 때 학생 목록에서는 사라지지만 기존 제출 원본, 검사·평가와 교사 결과는 그대로 열리는지 확인합니다.
18. 마감된 미제출 과제는 학생 목록에서 사라지고, 제출 이력이 있는 마감 과제는 기본으로 접힌 **과거 제출 결과**에서 펼쳐 볼 수 있는지 확인합니다.
19. 권한·상태상 실행할 수 없는 버튼 위에서 대기 커서나 로딩 표시가 지속되지 않고, 실제 요청 처리 중인 버튼에만 진행 상태가 나타나는지 확인합니다.

작업표시줄이나 Alt+Tab으로 별도 파일 탐색기 창을 연 뒤 외부에서 드래그하면 `hidden → visible` strict 검증과 겹쳐 drop이 차단될 수 있습니다. 포커스 손실만으로 프로젝트를 숨기지는 않지만, 안정적인 파일 입력을 위해 실습 안의 **파일 선택** 버튼으로 운영체제 파일 선택 창을 여는 방식을 사용하십시오.

## 학생 종료 절차

1. 필요한 결과가 OJ 서버에 제출되었는지 시도 번호와 영수증으로 확인합니다.
2. 실습 화면에서 “이 기기의 내 실습 데이터 삭제”를 누르고 성공 메시지를 확인합니다.
3. 별도로 파일을 내보낸 경우 다운로드 폴더에 남은 `.mlpx`, CSV, 이미지 파일과 클립보드 기록을 직접 삭제합니다.
4. OJ에서 로그아웃하고 모든 OJ 탭과 브라우저 창을 닫습니다.

삭제 실패를 성공으로 간주하지 않습니다. 모든 실습 탭을 닫고 다시 시도해도 실패하면 브라우저 설정에서 해당 OJ origin의 사이트 데이터를 지운 뒤, 운영자가 제출물 보존 여부와 브라우저 정책을 점검합니다.

## 잔여 보안 경계

현재 iframe과 WordPress 부모는 제출·로그인 연동을 위해 같은 origin을 사용합니다. 따라서 같은 origin에서 실행되는 악성 관리자 코드, 브라우저 확장 프로그램 또는 개발자 도구를 상대로 키를 비밀로 유지하는 구조는 아닙니다. 민감정보나 실제 개인정보 데이터셋을 다루는 수업은 별도 origin, 학생별 격리 프로필 또는 수업마다 초기화되는 가상 데스크톱을 추가 경계로 사용합니다.
