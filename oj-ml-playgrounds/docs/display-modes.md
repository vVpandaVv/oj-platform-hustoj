# 화면 모드 사용 안내 — 1.0.0-rc.4

학생이 작업 공간을 넓게 쓰고, 교사가 제출 내용과 평가를 한 화면에서 확인하는 기능입니다. 화면 크기만 바꾸며 학습 위치·제출 정책·권한·공용 PC 보호는 바꾸지 않습니다. 학습은 계속 학생 브라우저에서 실행됩니다.

rc.4는 출시 후보입니다. 이 문서는 사용 방법과 현장 확인 기준이며 실제 학교 서버·공용 PC 시험 완료를 뜻하지 않습니다. 설치·업데이트는 [INSTALL.md](../INSTALL.md), 양식·루브릭·CSV·반려 재검토는 [rc.3 사용 안내](workflow-rc3.md)를 함께 보세요.

## 1. 학생: 작업 화면 넓히기

1. 과제 화면에서 설명과 양식을 확인한 뒤 **실습 시작**을 누릅니다.
2. 화면 도구 모음에서 필요한 모드를 선택합니다.
3. 작업 공간의 **OJ에 제출하기**를 눌러 현재 프로젝트를 바로 제출합니다.
4. **제출 확인**에서 접수 결과·시도 번호·영수증을 확인합니다.

| 버튼 | 동작 |
|---|---|
| 넓게 보기 | OJ 화면의 가로 여백을 줄입니다. ML 화면에만 적용되며 다른 OJ 페이지의 기본 너비는 바꾸지 않습니다. |
| 집중 모드 | 브라우저 안에서 실습을 화면 가득 표시합니다. 브라우저 자체 전체화면 권한은 필요하지 않습니다. |
| 전체화면 | 집중 모드에 들어간 뒤 브라우저 전체화면을 요청합니다. 브라우저가 거부하거나 지원하지 않아도 집중 모드로 계속 작업할 수 있습니다. |
| 과제·양식 안내 / 안내 접기 | 접힌 과제 설명·양식·실습 안내를 열거나 다시 접습니다. 집중 모드에서는 별도 패널로 표시합니다. |
| 제출 확인 | 접수 상태를 확인하는 영역을 엽니다. 집중 모드에서는 별도 패널로, 일반 화면에서는 해당 영역으로 이동합니다. 이 버튼 자체가 제출을 실행하지는 않습니다. |
| 원래 화면 | 넓게 보기·집중 모드를 종료하고 기본 화면 배치로 돌아갑니다. |

집중 모드·전체화면·안내·제출 확인 버튼은 실습이 시작된 뒤 사용할 수 있습니다. 화면 모드를 전환해도 기존 프로젝트 iframe을 새로 만들거나 실습을 다시 시작하지 않습니다.

### Esc와 브라우저 전체화면

- 집중 모드에서는 **Esc** 또는 **원래 화면**으로 기본 배치에 돌아갈 수 있습니다.
- 브라우저 자체 전체화면에서 Esc를 누르면 브라우저가 키를 먼저 처리하여 전체화면만 해제할 수 있습니다. 이 경우 **집중 모드는 그대로 유지**됩니다. 필요하면 **원래 화면** 또는 다시 Esc를 사용하세요.
- 파일 선택 창이나 Alt+Tab으로 브라우저 전체화면이 해제되어도 집중 배치와 같은 작업 프레임을 유지합니다. 공용 PC 세션 재확인이 필요한 동안에는 기존 보호막이 우선 표시됩니다.

브라우저 전체화면을 허용하기 위해 학교 보안 정책을 완화할 필요는 없습니다. 전체화면이 불가능하면 **집중 모드**를 사용하세요.

## 2. 제출과 공용 PC 보호

화면을 넓혀도 공용 PC 보호 상태와 **이 기기의 내 실습 데이터 삭제** 버튼은 과제 안내와 함께 접히지 않습니다. 계정·세션 검증이나 보호 잠금 상태에서는 허용되지 않는 동작이 비활성화될 수 있습니다. 확장 모드는 보호막이나 세션 검증을 우회하지 않습니다.

- 제출은 작업 공간의 **OJ에 제출하기**로 실행합니다. 파일을 다운로드해 별도로 업로드할 필요는 없습니다.
- **제출 확인**은 접수 상태 확인용입니다. 접수 영수증을 확인하기 전에는 성공으로 간주하지 마세요.
- **바로 제출이 안 될 때 파일로 제출**은 직접 제출 문제를 해결하기 위한 보조 경로입니다.
- 화면을 원래대로 돌리거나 전체화면을 끝내는 동작은 프로젝트 저장·제출·로그아웃·로컬 삭제가 아닙니다.

수업 종료 시 서버 접수 확인 → 로컬 삭제 및 성공 확인 → 별도로 내보낸 파일 직접 정리 → OJ 로그아웃 → 모든 실습 탭과 브라우저 닫기 순서를 유지합니다. 로컬 삭제는 이미 제출한 서버 사본이나 다운로드 폴더 파일을 삭제하지 않습니다.

## 3. 교사: 크게 채점하기

1. **ML 실습 › 제출·평가**에서 과제를 고르고 학생의 제출 내용·평가 영역을 펼칩니다.
2. **크게 채점하기**를 누르면 해당 학생의 검토 영역이 확장됩니다.
3. 안전 바로보기와 루브릭·점수·피드백을 확인합니다. 넓은 화면에서는 **내용 영역 너비** 슬라이더로 제출 내용 쪽 비율을 조절할 수 있습니다.
4. 기존 평가 저장·공개 버튼으로 평가를 저장하거나 학생에게 공개합니다.
5. **채점 화면 닫기** 또는 Esc로 결과 화면에 돌아갑니다.

확대 화면 상단에는 대상 학생을 구분할 수 있는 제목과 처리·오류 안내가 유지됩니다. 화면 확대·축소는 기존 폼과 입력값을 유지하지만, **저장 대신 동작하는 기능은 아닙니다**. 저장 성공 안내를 확인하기 전에 페이지를 떠나지 마세요. 화면이 좁으면 내용과 평가가 세로로 배치되므로 슬라이더의 가로 비율 변화가 나타나지 않을 수 있습니다.

안전 바로보기는 기존과 동일하게 허용된 제출 문서만 표시합니다. 모델·코드·데이터셋·첨부파일을 실행하거나 지표를 재계산하지 않습니다. 화면 확대로 조회·평가·공개 권한이 추가되지 않습니다.

## 4. 운영자: 시작 화면 기본값 설정

**OJ 콘솔 → 교사 메뉴 › ML 실습 › 설정**에서 아래 항목을 변경하고 저장합니다. 사이트 관리자와 'ML 실습 설정' 권한을 받은 교사가 바꿀 수 있으며 별도의 WordPress 설정 폼은 만들지 않습니다.

| 설정 | 기본값 | 적용 결과 |
|---|---|---|
| 실습 시작 시 집중 모드로 넓게 열기 | 꺼짐 | 켜면 학생의 실습 시작 후 집중 모드로 엽니다. 브라우저 전체화면은 학생이 직접 버튼을 눌러야 합니다. |
| 실습 시작 후 과제·양식 안내 기본 접기 | 켜짐 | 시작 후 안내를 접어 작업 공간을 확보합니다. 학생이 언제든 도구 모음에서 다시 펼칠 수 있습니다. |

변경은 **다음에 여는 페이지부터 적용**됩니다. 이미 열린 실습을 새로고침하거나 강제로 화면 전환하지 않습니다. 학생이 페이지를 다시 열어야 한다면 먼저 작업을 저장·제출하여 보존하세요.

## 5. 업데이트 조건

- WordPress 플러그인 버전: **1.0.0-rc.4**
- DB 스키마: **4**. rc.3에서 스키마 4 설치를 마쳤다면 추가 DB 변경이 없습니다.
- rc.1/rc.2의 스키마 3 또는 이전 설치는 백업 후 **OJ 콘솔 교사 메뉴 › ML 실습 › 설정 → DB 업데이트 및 검증**으로 스키마 4 업데이트가 필요합니다.
- 내장 앱은 rc.3의 OJ 패치를 포함한 **ML Playgrounds 0.12.1** 번들을 그대로 사용합니다.
- DB·비공개 저장소 전체 백업 후 ZIP 전체를 교체하고 관련 캐시를 비웁니다. 기존 실습 탭은 작업을 보존한 뒤 닫고 다시 여세요.
- 화면 확장을 위해 서버에 uv나 새 PHP 확장을 추가할 필요는 없습니다. 제출 검사에 필요한 기존 PHP ZIP·비공개 저장소·HTTPS 요구 사항은 유지합니다.

## 6. 운영 전 현장 확인

실제 학교 서버의 학생·교사 계정과 배포할 Chrome/Edge에서 다음 항목을 확인하고 브라우저 버전·시험일을 기록하세요. 이 목록은 자동 시험 결과를 대신하지 않습니다.

- 넓게 보기 종료 후 원래 OJ 너비가 복구되고 다른 OJ 페이지에 영향이 없는지
- 집중 모드와 전체화면 허용·거부, Esc 단계별 복귀, 원래 화면 버튼이 동작하는지
- 파일 선택·취소와 다른 창에서 복귀한 후 검증 성공 시 같은 프로젝트가 나타나는지
- 안내·제출 확인 패널을 열고 닫아도 작업이 유지되고 공용 PC 보호 상태·삭제 버튼에 접근할 수 있는지
- 전체화면·집중 모드에서도 **OJ에 제출하기**가 동작하고 접수 영수증을 확인할 수 있는지
- 확대 채점에서 대상 학생 이름과 오류 안내가 보이며 너비 조절·축소 후 미저장 입력이 유지되는지
- 평가 저장·공개 결과가 학생 본인에게만 기존 권한 규칙대로 표시되는지
- 키보드 Tab·Shift+Tab·Esc 및 작은 화면·브라우저 확대 사용 시 닫기·저장 버튼에 접근할 수 있는지
- 화면 확장 중 계정 전환·세션 검증 실패·다중 탭 로컬 삭제가 기존 보호 규칙대로 잠기는지
- 두 운영 설정의 기본값과 변경 후 새 페이지 적용이 맞는지

전체 공용 PC 인수 기준은 [공용 PC 배포 체크리스트](public-pc-deployment.md)를 따르세요.
