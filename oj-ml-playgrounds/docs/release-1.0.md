### RC6 삭제 보완의 검증 기준

- 사용자 확인 전에는 삭제 요청·저장소 폐기·DB 삭제가 없어야 한다. 취소·Esc·페이지 숨김·세션 변경은 삭제를 승인하지 않는다.
- 확인 뒤 새 로그인 검증이 명확히 성공한 경우에만 삭제한다. 계정별 범위와 origin/source/frame nonce 검증은 유지한다.
- 삭제 응답은 bootstrap에서 한 번만 처리한다. 정상 응답을 iframe 제거 뒤 다시 검사해 연결 오류로 덮어쓰지 않는다.
- 배타 잠금을 먼저 예약한 뒤 기존 탭의 저장 권한을 폐기한다. 삭제 중 새로 열린 탭이 앞서 공유 잠금을 얻지 못하게 한다. IndexedDB의 `blocked`는 취소가 아니므로 실제 요청이 끝나기 전에 잠금을 해제하지 않는다.
- 성공·실패·확인 불가를 지속 표시한다. 시간이 초과됐다고 실제 삭제가 취소되었다고 단정하지 않으며 자동 재시도·자동 새로고침하지 않는다.
- 합성 로컬 검사 통과와 실제 judge 서버 삭제 성공은 분리해 기록한다. 위 G1은 RC6 설치 후 실제로 확인했으며, 별도 시험하지 않은 오류·대용량·브라우저 조합까지 현장 통과로 표시하지 않는다.

## rc.5의 미배포 표시 수정

실제 시험에서 영수증과 결과 화면의 시각이 9시간 다르고, 새 시도·제출 직후 과제 안내에 사용 횟수가 남아 있는 표시 문제를 확인했습니다. rc.5 로컬 소스는 영수증을 UTC ISO 8601로 반환하고, 시도 생성/직접 제출/파일 제출 성공 뒤 서버의 사용 횟수를 재조회해 안내만 갱신하도록 수정했습니다. iframe을 다시 만들거나 학습 작업을 초기화하지 않습니다. 두 신규 회귀 테스트를 추가했으며, 이 수정은 위 SHA의 동결 rc.4 ZIP이나 서버에는 포함되지 않습니다. 새 후보 패키징·서버 재시험 전까지 해결 완료로 승인하지 않습니다.

새 **실습 시작**으로 서버 시도가 생성되면 제출 전에도 사용 횟수가 증가합니다. 기존 시도 이어하기나 동일 영수증 재전달은 추가 차감하지 않으며, 추가 허용·환급 등에 따라 시도 번호와 사용 횟수는 항상 같지 않을 수 있습니다. rc.5는 이 기존 정책을 변경하지 않고 서버 조회로 표시합니다.

설치는 백업 → rc.5 ZIP 전체 교체 → PHP-FPM/OPcache와 관련 캐시 갱신 → 스키마 4 확인(이미 4이면 DB 변경 없음) → 영수증 시각·시도 생성/직접/파일 제출 후 사용 횟수·기존 제출/평가 회귀 시험 순서입니다. 최종 1.0.0 승인은 이 후보 설치만으로 완료되지 않습니다.
