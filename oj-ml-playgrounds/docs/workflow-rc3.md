# 1.0.0-rc.3 사용·설치 안내

플러그인 **1.0.0-rc.3**, DB 스키마 **4**, 검사기 **5**, 내장 앱 **0.12.1 + OJ 패치**입니다. rc.2 점검표에 남았던 소프트웨어 기능을 구현했습니다. 학교의 실제 로그인·공용 PC·동시 접속·백업 복원 승인까지 대신 완료한 배포본은 아닙니다.

## 반드시 먼저 업데이트할 항목

1. 학생 작업을 제출하거나 보존하고 수업 외 시간에 점검 모드를 켭니다. 실행 중인 요청·cron·정리 작업 종료를 확인합니다.
2. WordPress DB 전체, 비공개 저장소 **전체**, 설정·인증 SALT·이전 플러그인을 같은 시점으로 백업합니다.
3. ZIP 전체를 교체합니다. 설치 폴더는 `oj-ml-playgrounds/` 하나이며 구버전 JS와 PHP를 섞지 않습니다.
4. **WordPress 도구 → ML 실습 운영 → DB 업데이트 및 검증**을 실행합니다. rc.1/rc.2의 스키마 3에서도 반드시 필요합니다. `wp oj-ml migrate`도 가능합니다.
5. 버전 rc.3 / 스키마 4 / OJ 연결을 확인하고 캐시·OPcache를 갱신합니다. 기존 실습 탭은 작업 보존 후 닫고 다시 엽니다.

스키마 4는 평가에 `details_json` 컬럼을 추가해 루브릭·점수 스냅샷을 버전별 보관합니다. 기존 제출·총점·피드백은 유지합니다. WordPress options 테이블도 InnoDB여야 개인 양식과 감사 로그를 함께 저장할 수 있습니다. 자동 엔진 변환은 하지 않습니다. 상세 서버 설정은 [INSTALL.md](../INSTALL.md), 복원은 [업그레이드 안내](upgrade-1.0.md)를 따르세요.

운영 서버에는 기존 PHP ZIP·HTTPS·비공개 저장소가 필요하며, 새 기능 때문에 `uv`나 Node.js를 설치하지 않습니다. 학생 PC도 브라우저만 사용합니다.

## 교사: 과제와 양식·평가 기준 준비

**OJ Console → ML 실습 과제**에서 수업, 안내, 기한·횟수·크기 제한을 먼저 설정합니다. 이후 아래 항목을 필요에 따라 설정하고 초안을 저장·다시 확인한 뒤 게시하세요.

### 포트폴리오 양식과 필수 답변

- 교사 양식을 켜고 기본 8문항 또는 직접 추가한 문항에 제목·작성 안내를 씁니다.
- 각 문항의 **제출 시 필수 답변**을 선택하면 해당 문항만 검사합니다. 공통 최소 길이는 1~1000자이며 공백·제어/비표시 문자를 제외합니다.
- 필수 문항이 삭제됐거나 답변이 없거나 짧으면 제출은 접수·보존되고 검사에서 재제출 필요로 분류합니다. 문항 ID와 답변 연결을 검사하며 학생이 주장하는 완료 표시를 믿지 않습니다.
- 정답·문장의 질·진위·표절은 자동 판단하지 않습니다. 첨부파일만 넣은 답변은 텍스트 길이를 충족하지 않습니다.
- **내 양식 보관함**에 현재 양식을 저장하고 다른 과제 편집기로 복사할 수 있습니다. 교사 계정당 20개, 양식당 30문항·32KiB입니다. 필수 설정도 복사됩니다.
- 보관함 삭제는 그 개인 사본만 지우며 이미 과제에 저장한 양식과 학생 답변은 바꾸지 않습니다.

게시 후 양식·필수 답변·루브릭·데이터 정책은 고정됩니다. 다른 기준이 필요하면 과제를 복제해 새 초안을 만드세요. 기존 게시 과제에 새 필수 검사를 자동으로 강제하지 않습니다.

### 항목별 루브릭

평가 항목 추가 또는 기본 100점 루브릭을 선택하고 항목 이름·설명·배점을 입력합니다. 최대 25개, 항목당 0.01~10,000점, 소수 둘째 자리까지입니다. 학생은 실습 전에 평가 기준을 볼 수 있습니다.

제출 결과에서 각 항목의 점수와 피드백을 작성합니다. 서버가 저장된 과제 배점으로 점수를 검증·합산합니다. 일부 항목만 점수를 입력하면 저장을 거절하며, 모든 점수를 비워 두면 피드백만 저장할 수 있습니다. 항목이 없는 과제는 기존 총점·만점 평가를 계속 사용합니다. 버전 없는 구형 임의 루브릭은 자동 변환하지 않고 그대로 보존합니다.

**평가 저장**은 비공개 초안, **저장 후 학생에게 공개**는 학생에게 항목별 점수·피드백과 전체 평가를 공개합니다. 이후 새 초안을 저장해도 학생에게는 마지막 공개 버전이 유지됩니다. 충돌·저장 실패 시 입력을 지우지 않습니다.

### 허용 알고리즘

체크박스로 허용할 알고리즘을 선택합니다. 아무것도 선택하지 않으면 제한하지 않습니다. 선택한 경우 제출에 포함된 모든 실행 기록을 검사하므로 이전의 허용되지 않은 알고리즘 실험 기록도 반려 사유가 될 수 있습니다. 학습 실행 여부·횟수·최소 성능을 보장하는 자동 채점 기능은 아닙니다.

### 지정 CSV 배포와 해시 확인

**교사 CSV 배포 + 동일 데이터 검사**를 선택하고 CSV를 업로드한 뒤 자료를 골라 과제를 저장합니다. 서버가 정규화된 CSV의 SHA-256을 계산하므로 교사가 해시를 복사할 필요가 없습니다. 학생은 현재 배정·권한이 확인되는 과제에서만 내려받을 수 있습니다. 공개 uploads URL을 만들지 않습니다.

입력 제한은 다음과 같습니다.

- UTF-8 쉼표 CSV, 헤더 포함 2~20,000행, 2~100열, 전체 20만 셀, 최대 5MiB
- 첫 줄은 빈 값·중복 없는 열 이름, 모든 데이터 행의 열 수가 동일해야 함
- 셀당 64KiB, 탭·세미콜론·파이프 및 제어문자는 거절: 앱의 구분자 자동 판별로 데이터가 달라지는 것을 방지
- Excel 수식으로 해석될 수 있는 `=`, `+`, `@`, `-` 시작 셀은 거절. 부호 있는 일반 숫자·지수 표기는 허용. `-apple` 같은 텍스트도 반려되며 값을 임의로 수정하지 않음
- 표준 따옴표·쉼표·따옴표 내부 줄바꿈 지원. 빈 행은 앱과 같이 제거

저장본은 **UTF-8 BOM + LF + RFC4180 따옴표 + 마지막 추가 줄바꿈 없음**입니다. 이 BOM은 배포 소스 코드가 아니라 학생용 CSV 형식의 일부입니다. 학생이 내려받은 파일을 그대로 가져오면 MLPX의 `dataset/data.csv`와 해시가 일치합니다. 서버는 학생의 hashes.json 주장만이 아니라 실제 파일 바이트를 확인합니다. 데이터 수정·다른 파일 사용은 반려되며 모델 실행은 하지 않습니다.

**기존 SHA-256 직접 지정 (고급)**은 구형 정책을 유지하거나 정본 CSV 해시를 직접 지정할 때 사용합니다. 이 모드 자체는 파일을 배포하지 않습니다. **자유 데이터**로 바꾸면 초안에서 자료 연결과 해시 제한을 함께 제거합니다.

교사당 활성 자료 20개·보존 파일 합계 50MiB, 사이트 전체 200개·200MiB 상한입니다. 제출물의 기본 10GiB 설정과 **별도**입니다. 자료 숨기기는 새 선택 목록에서만 제외하며 기존 과제·원본·사용 용량은 보존합니다. 숨긴 자료의 삭제·보존 기간 확정은 기관 운영 절차로 처리하며, 임의로 파일만 지우면 과제 다운로드·검증을 깨뜨릴 수 있습니다. 업로드 시 기록되지 않은 잔여 파일의 물리적 용량도 보수적으로 계산합니다.

## 학생: 내려받기 없이 양식 적용

1. 실습을 시작하고 프로젝트를 새로 만들거나 엽니다.
2. 실습 페이지에서 적용 대상 프로젝트 이름을 확인한 뒤 **현재 프로젝트에 양식 적용**을 누릅니다.
3. 없는 문항만 추가하고 저장한 후 완료를 안내합니다. 같은 ID 문항·답변·첨부는 덮어쓰지 않습니다. 같은 ID의 제목·설명이 달라지면 충돌을 안내하며 변경하지 않습니다.
4. 적용 중 프로젝트·계정·세션이 바뀌면 이전 요청의 완료를 현재 프로젝트에 적용하지 않습니다. 네트워크/저장 응답이 불확실하면 포트폴리오부터 확인하세요.
5. 지정 데이터가 있으면 **수업 CSV 내려받기** 후 앱 데이터 화면에서 가져옵니다. 첫 줄은 열 이름입니다. 이 기능은 데이터를 자동으로 프로젝트에 덮어쓰지 않습니다.
6. 필수 답변과 실험을 마친 뒤 기존 **OJ에 제출하기**로 바로 제출합니다. 별도 MLPX 다운로드·재업로드는 필요하지 않습니다.

양식 `.md` 다운로드와 앱의 파일 가져오기는 대체 경로로 유지합니다. 공용 PC 종료 시 로컬 실습 데이터뿐 아니라 내려받은 `.mlpx`, `.csv`, 양식 `.md`도 직접 삭제하고 로그아웃하세요. 이미 서버에 제출한 원본과 평가를 지우는 동작은 아닙니다.

## 교사: 기존 반려 결과 재검토

**학생 제출·평가 → 제출 열기 → 기존 반려 제출 재검토 요청**에서 사유를 적고 요청합니다. ML 관리 권한과 현재 수업 평가 권한이 모두 필요합니다. 원본이 남아 있는 `needs_resubmit`만 대상입니다.

같은 파일을 `system_pending` 대기열에 넣고 기존 worker가 현재 검사기로 다시 검사합니다. 접수 시각·원본 해시·시도 번호·과거 검사·평가 기록은 보존합니다. 같은 요청 ID 재전송은 중복 등록하지 않으며 다른 교사가 이미 새 검사로 바꿨다면 충돌을 안내합니다. 요청과 대기열 변경은 감사 기록과 함께 원자적으로 저장합니다.

재검토는 검사 우회·자동 통과가 아닙니다. 여전히 형식이 잘못되었거나 지정 정책을 어기면 다시 반려됩니다. 학생에게 새 파일이 필요한 경우에는 별도 **학생별 재제출 설정**에서 횟수·개인 마감을 허용하세요. 업데이트만으로 모든 과거 반려를 자동 변경하지 않습니다.

## 백업·개인정보·현장 승인

- `wp oj-ml manifest`는 제출 원본과 지정 CSV의 바이트·해시를 확인합니다. 전체 DB에는 개인 양식/자료 메타데이터가 있는 WordPress options도 포함해야 합니다.
- 비공개 저장소의 `artifacts/`만 복사하지 말고 `teaching-assets/`를 포함한 전체를 백업하세요. 기존 `reconcile`/보존기간 자동 정리는 제출 원본 대상이며 CSV 숨김 파일을 자동 삭제하지 않습니다.
- 개인정보 내보내기는 교사의 개인 양식과 지정 자료 메타데이터를 포함합니다. 허용된 개인정보 삭제에서 개인 양식은 삭제하지만, 수업 CSV와 기관 과제·평가 작성 기록의 보존 여부를 명시합니다. 원본 CSV 사본·실제 파기는 기관 운영자 절차로 처리합니다.
- 현장 승인: 역할별 접근, 학생 A→B 계정 전환, 파일 선택/포커스 복귀, 장시간 학습, 실제 수업 규모 동시 제출, Nginx/PHP-FPM 업로드 한도, 백업 복원, 보존 정책·승인 책임자를 확인해야 합니다.

개발 검증은 로컬 실제 WordPress/PHP/MariaDB와 합성 REST/iframe 브라우저 검사입니다. 이를 학교 운영 서버의 실제 OJ 인증·부하 시험 결과로 해석하지 않습니다. 기관 인수시험을 통과하기 전에는 정식 1.0.0 안정판으로 표시하지 않습니다.

## 개발 검증 재현

`scripts/verify.ps1`에 `-Php`, `-Node`, `-ExtensionDirectory`, `-UpstreamFrontend`를 전달합니다. UpstreamFrontend는 패치를 적용한 0.12.1의 frontend이며 npm 의존성이 준비돼 있어야 합니다. 지정 CSV 검사에서는 앱의 실제 CSV parser/serializer를 읽어 왕복 바이트를 대조합니다. 브라우저 smoke 두 개와 실제 WordPress DB 통합 시험은 별도로 실행합니다. 시험 DB는 운영 DB를 사용하지 않습니다.
