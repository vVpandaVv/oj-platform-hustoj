# OJ ML Playgrounds

저장소 소유권 확인은 DB·접두사·설치 URL·플러그인/스키마 버전에 묶어 최대 5분간 재사용하며, 실패 시에는 접근을 차단하고 30초 뒤 다시 확인합니다. DB 업데이트·삭제는 실제 소유권을 직접 확인합니다. 반복 메타데이터 조회를 줄이는 변경이며 다른 애드온에 의존하지 않습니다.

현재 버전은 **1.4.2**입니다. 채점 후 현재 등급·점수·판단 기준을 확인하고 **점수 조정**으로 다른 등급을 선택합니다. 교사·학생 데이터 설명과 서버에서 집계한 CSV 통계를 실습 평가에 연결합니다. 항목별 필수 근거가 부족하면 **교사 확인 필요**로 표시하고 AI 점수의 반영을 막습니다. 원본 행·범주 값은 외부 AI에 보내지 않습니다. 평가항목은 1~25개로 추가·삭제하며 교사 과제 목록은 **과제 / 보관** 탭으로 나눕니다. 기존 제출·수동 평가 기록은 변경하지 않습니다. **OJ Platform은 필수, OJ AI Dashboard는 선택**입니다.

`ml-playgrounds`를 OJ Platform 2.x의 과제·명단·권한 체계와 연결하는 WordPress add-on입니다. 모델 학습은 학생 브라우저에서 실행되고, 서버는 과제·학생별 시도·제출 영수증·MLPX 검사 결과·교사 평가를 보관합니다.

## 현재 버전과 기존 기능

삭제 확인·취소와 진행 결과를 명확히 표시하고, 완료 응답 중복 처리와 다중 탭 저장소 잠금 순서를 보완했습니다. 삭제 전 현재 로그인 검증은 유지하며 성공·실패 메시지를 자동 새로고침으로 지우지 않습니다. 별도 개인정보 URL이 없으면 OJ Platform의 안내를 이어받습니다. 영수증 시각·서버 횟수 재조회도 유지하며 시도 차감 정책은 변경하지 않습니다.

DB 스키마는 **4**입니다. 이미 스키마 4인 설치는 추가 DB 변경이 없으며 내장 앱은 **ML Playgrounds 0.12.1+OJ 패치**입니다. 1.4.2은 1.2.4의 내장 앱 번들·상단 경고 확인창·메모리 보완·학습 전 안내·과제 정책 검사를 그대로 사용합니다. 빌드 기록은 [UPSTREAM.md](UPSTREAM.md)를 확인하세요.

2026-09-11의 1.0.0 기술 승인은 OJ dev.107 / ML RC6에서 확인한 공용 PC 삭제·다중 탭 저장 중단·재로그인 후 미노출·서버 원본과 공개 평가 보존에 대한 과거 기록입니다. 1.2.0의 신규 기능과 실제 서버의 AI 연결 검증까지 자동 포함하지 않습니다. 서버 관리·로그·백업·복원은 운영자 직접 수행 영역이며, 기관용 기술 승인은 WordPress.org 심사·공개 게시나 모든 환경의 보증을 뜻하지 않습니다. [출시 기록과 승인 범위](docs/release-1.0.md)를 확인하세요.

rc.4에서 추가한 학생 실습의 넓게 보기·집중 모드·전체화면과 교사의 크게 채점하기도 유지합니다. 과제·양식 안내와 제출 확인은 필요할 때 펼쳐 보고, 화면을 넓혀도 공용 PC 보호 상태와 로컬 데이터 삭제 버튼을 유지합니다. [화면 모드와 운영 설정 안내](docs/display-modes.md)를 확인하세요.

rc.3에서 추가한 원클릭 양식 적용·개인 양식 보관함·필수 문항, 항목별 루브릭, 알고리즘 설정, 비공개 CSV 배포와 기존 반려 재검토도 유지합니다. 해당 기능은 [양식·평가·자료 사용 안내](docs/workflow-rc3.md)를 참고하세요.

기존 제공 기능: 학생별 시도·마감 연장, 전체 제출 이력, 과제 복제·재개, 이름/계정 검색·상태 필터·CSV, 운영 한도·점검 모드, 독립 상태 화면, 검사 복구, 보존·개인정보 도구와 무결성 점검입니다. 기본 파일 한도는 25 MiB, 총 저장 한도는 10 GiB이며 설정 화면에서 변경합니다.

## 실행 구조

1. 교사는 OJ 그룹을 선택해 과제 초안을 만듭니다. 기존 수업 과제의 조회·편집·제출·평가는 유지하며 복제할 때는 새 그룹을 선택합니다.
2. 플러그인은 OJ Addon API에서 권한과 명단 revision을 확인하고 학생 명단을 스냅샷합니다.
3. 학생은 OJ 공개 화면 안의 ML Playgrounds iframe에서 데이터를 준비하고 모델을 학습합니다.
4. 학습 계산은 Web Worker, ML.js 또는 TensorFlow.js를 이용해 학생 컴퓨터에서 수행됩니다.
5. 학생이 임베디드 툴바의 **OJ에 제출하기**를 누르면 현재 메모리 프로젝트가 `.mlpx`로 직렬화되어 WordPress REST API로 바로 전송됩니다. 파일을 먼저 다운로드할 필요는 없습니다.
6. 서버는 비공개 경로에 원본을 저장하고 ZIP 안전성, 필수 문서, 내부 해시, 정책 위반을 검사합니다.
7. 교사는 학생별 미제출/접수/검사/평가 상태를 확인하고 점수와 피드백을 공개합니다.

브라우저 프로젝트는 제출 전까지 서버에 자동 동기화되지 않습니다. OJ 내장 번들은 공용 PC에서 현재 사이트·OJ 사용자별 불투명 scope로 IndexedDB를 분리하고, 프로젝트 문서·데이터셋·모델·임베딩·첨부파일을 AES-GCM으로 암호화합니다. 부모 화면의 접힌 수동 제출 영역은 직접 제출에 문제가 있을 때 이미 내보낸 `.mlpx`를 선택하는 fallback입니다.

## 평가 기준과 선택적 AI 분석

과제 작성의 **평가 기준**에서 항목 이름·평가 방법과 항목당 2~10개 등급의 이름·점수·구체적인 기준을 정합니다. 예를 들어 한 항목을 충분히 충족 25점, 대체로 충족 20점, 일부 충족 10점, 미충족 0점으로 정의할 수 있습니다. 점수는 서로 달라야 하며 항목 배점은 등급의 최댓값으로 자동 계산합니다. 새 과제는 4항목·100점으로 시작하며 기본안과 실험 중심 예시를 불러올 수 있습니다. 학생 안내, 교사 등급 선택과 AI 초안은 같은 기준표를 사용하고 공개 결과에는 선택 등급·점수·판단 기준이 남습니다.

기존 총점·v1 자유 점수 방식과 과거 평가는 자동 변환하지 않습니다. 기존 초안의 **등급별 루브릭으로 전환**을 눌러 기준을 확인·저장하세요. 게시된 과제는 기준이 고정되므로 복제하여 새 그룹 과제를 만드세요. 총점 방식은 수동 평가로 사용하며 AI에는 항목별 기준이 필요합니다.

**제출·평가**에서 수동 채점을 바로 사용할 수 있으며 **AI 평가 보조 (선택)**를 직접 펼칠 때만 AI 연결 상태를 조회합니다. AI 미설치·오류가 수동 평가 입력을 지우지 않습니다. 교사의 전송 동의 후 요청하며 초안을 검토·수정하고 공개하는 책임은 교사에게 있습니다.

채점 항목에는 현재 선택 등급·점수·판단 기준이 표시됩니다. **점수 조정**을 눌러 등급별 점수와 기준을 비교하고 카드를 선택하세요. 합계는 즉시 바뀌지만 서버 반영은 **평가 저장**(비공개) 또는 **저장 후 학생에게 공개**로 완료합니다. 공개된 평가를 비공개로 수정하면 다시 공개하기 전까지 학생에게 이전 공개 평가가 유지됩니다. 이미 저장된 평가는 당시 루브릭 스냅샷을 사용합니다.

등급별 루브릭은 기존 AI 계약의 교사 기준에 전체 등급표를 포함하므로 AI Dashboard를 추가 수정하지 않아도 전달됩니다. AI가 허용되지 않은 점수를 제안하면 ML이 **자료 확인 필요**로 표시하고 반영을 차단합니다. 가까운 등급으로 반올림하지 않으며 교사가 정의된 등급으로 직접 채점해야 합니다. 기준표가 너무 길면 일부를 잘라 보내지 않고 AI 요청을 차단합니다. 모델이 항상 올바른 등급 판단을 한다는 보증은 아니므로 근거를 검토하세요.

AI에는 포트폴리오 답변과 교사 양식뿐 아니라 과제 기준, 프로젝트 유형·버전·현재 설정, **실험 당시** 특성·타깃·전처리·분할·알고리즘·하이퍼파라미터, 실행별 상태·기록된 지표·경고·모델 메타데이터를 보냅니다. 과거에 기록되지 않은 설정을 현재 설정으로 추정하지 않습니다. 원본 데이터·이미지·모델 바이너리·첨부 내용·원시 실행 로그·계정 식별자는 제외하며 자유 입력의 개인정보는 교사가 확인해야 합니다. 요약 생략이나 크기 한도가 있으면 일부 근거만 보내지 않고 AI 요청을 막습니다. 실행·지표 재계산은 하지 않습니다. 정확한 포함·제외 항목과 한도는 설치 안내서의 **AI 평가 연결**을 확인하세요.

1.4.0의 데이터 통계는 별도 상태를 갖습니다. 제출 원본의 UTF-8 CSV를 서버에서만 읽고, 현재·실험 당시 데이터별 행/열 수·자료형·결측 수/비율·고유값 수 및 보호 가능한 평균/모집단 표준편차·익명 빈도를 전달합니다. 표본 행·최솟값/최댓값·범주 값·파일 경로는 포함하지 않습니다. 통계가 부분 집계·지원 불가·보호 생략 상태이면 이를 명시하며, 해당 근거가 필요한 항목은 교사 확인으로 남깁니다. 원본 값은 소수집단·상수·높은 고유성 보호로 숨겨질 수 있으며 전체 통계가 데이터의 출처·변수 의미·결측 원인·누수 여부를 검증하는 것은 아닙니다.

과제의 **데이터 설명**에 공통 맥락을 입력하고 필요한 경우 **학생 설명 항목 추가**로 포트폴리오 문항을 제공합니다. 각 루브릭의 **평가 근거**에서 설명·통계·비교 실험 요구를 고릅니다. 요구가 없던 기존 항목은 AI에 한해 설명·통계를 기본 요구하며 보고서 전용 항목은 명시적으로 해제할 수 있습니다. 게시 과제의 정책·루브릭은 기존처럼 잠기므로 복제한 초안에서 변경합니다. 과거 제출도 원본 CSV가 포함되어 있으면 재제출 없이 조회 시 집계하지만 누락된 데이터나 과거 설정을 만들어 채우지 않습니다.

## 과제 수명주기와 학생 목록

- `draft` 과제는 게시 전에 수정하거나 삭제할 수 있습니다.
- `published` 과제는 제목, 설명, 마감 시각과 최대 시도 횟수만 유효성 검사를 거쳐 수정할 수 있습니다. 최대 시도 횟수는 유지하거나 늘릴 수만 있고 줄일 수 없으며, 과제 유형과 제출 정책은 게시 후 고정됩니다.
- 과제를 보관하면 학생의 과제 목록에서는 숨겨지지만 과제, 시도, 제출 원본, 검사·평가와 교사 결과는 삭제되지 않습니다.
- 마감된 과제 중 제출 이력이 없는 과제는 학생 목록에서 숨깁니다. 제출 이력이 있는 과제는 접힌 **과거 제출 결과**에 남겨 학생이 필요할 때 펼쳐 확인할 수 있습니다.
- 실행할 수 없는 버튼은 대기 중으로 오해할 수 있는 로딩 커서를 표시하지 않습니다. 실제 요청 처리 중인 동작에만 진행 상태를 표시합니다.

## 공용 PC 보호 흐름

1. 학생이 실습 페이지를 열면 부모 화면이 `GET /oj-ml/v1/session/storage-context`에서 현재 로그인 사용자의 scope, 세션 지문과 암호화 키를 받습니다. 응답은 `private, no-store`이며 `Vary: Cookie`를 사용합니다.
2. iframe은 128-bit `frameNonce`를 포함한 bridge v2 handshake를 끝내기 전에는 Vue 앱을 mount하거나 IndexedDB를 열지 않습니다. 플러그인의 정적 `index.html`을 직접 열면 fail-closed됩니다.
3. 소유자를 알 수 없는 기존 전역 `ml-playgrounds` DB는 현재 학생에게 자동 귀속하지 않고 mount 전에 삭제합니다.
4. iframe은 사용자 scope별 Web Lock 공유 lease를 유지합니다. 삭제할 때는 같은 scope의 모든 탭에 저장 권한 폐기를 알리고, 진행 중 저장과 DB 연결이 끝난 뒤 배타 lease 안에서 DB를 삭제합니다.
5. 45초 주기 검사는 iframe을 숨기거나 포커스를 요구하지 않는 silent background verify입니다. 정상 응답이 늦어지거나 다른 곳에 포커스가 있어도 현재 작업 화면을 유지합니다. 문서가 숨김 상태에서 다시 표시될 때에만 먼저 보호막을 적용한 strict verify를 수행합니다. 사용자·세션 불일치나 검증 오류가 확인되면 iframe과 키를 폐기해 잠그며, `storage-revoked`를 포함한 terminal 상태에서 자동 새로고침을 반복하지 않습니다. BFCache에서 복원된 이전 iframe도 재사용하지 않습니다.
6. 앱의 파일 선택 창이 열린 동안에는 iframe을 제거하지 않고 불투명 보호막으로 가립니다. 선택·취소 이벤트는 현재 OJ 저장소 context를 다시 확인할 때까지 보류하며, 성공한 경우에만 파일 이벤트를 한 번 재전달합니다. 화면 숨김, 시간 초과, 계정 불일치와 검증 오류는 계속 fail-closed됩니다.
7. “이 기기의 내 실습 데이터 삭제”는 현재 계정의 암호화 DB와 scope별 화면 설정을 지웁니다. 이미 서버에 제출한 사본과 사용자가 별도로 내보낸 다운로드 폴더의 `.mlpx` 파일은 지우지 않습니다.

이 보호는 정상 UI에서 다음 학생에게 이전 학생 자료가 우발적으로 노출되는 것을 막습니다. 브라우저 강제 종료, 악성 확장 프로그램, 관리자 권한 또는 개발자 도구까지 완전히 격리하는 OS 보안 경계는 아닙니다. 민감한 자료를 다루는 수업은 학생별 OS/브라우저 프로필이나 수업 종료 시 자동 초기화되는 계정을 함께 사용하십시오.

공용 PC 배포 전에는 다음을 반드시 완료해야 합니다.

- HTTPS 적용. OJ 암호화 vault는 Web Crypto를 사용하므로 HTTP 배포를 지원하지 않습니다.
- 최신 Chrome/Edge에서 Web Crypto, IndexedDB, BroadcastChannel, Web Locks 지원 여부를 확인합니다. 필수 동시성 API가 없으면 공용 PC 저장소는 fail-closed됩니다.
- 개인정보 안내 URL은 유효한 `oj_ml_playgrounds_privacy_url` 필터 → ML 별도 주소 → 정상 연결된 OJ Platform의 `home_url('/privacy')` → ML 기본 기술 안내 순으로 선택합니다. ML 설정을 비워두면 OJ 문서를 이어받고, 플랫폼이 없거나 연결되지 않으면 기본 기술 안내를 제공합니다. 필터의 기존 HTTP(S) 호환은 유지하되 화면에 직접 저장하는 주소는 HTTPS만 허용합니다. 문서 내용·게시 상태·보존 정책은 ML에 복제되지 않으므로 OJ 문서의 실제 공개 여부와 기관명·담당자·보유기간·위탁업체를 확인합니다.
- 브라우저의 사이트 데이터 영속성 정책과 수업 종료 초기화 정책을 시험합니다.
- 같은 Chrome/Edge 프로필에서 학생 A 저장 → B 로그인 → B 목록 0건 → A 재로그인 → A 자료 복원 시나리오를 실제 배포 환경에서 확인합니다.

전체 운영·인수 기준은 [공용 PC 배포 체크리스트](docs/public-pc-deployment.md)를 따르십시오.

## 표 데이터 정책의 의미

서버는 `settings.data.dataset.path`가 가리키는 정본 CSV를 ZIP 스트림에서 직접 읽습니다. CSV는 UTF-8 BOM·쉼표 구분 형식을 요구하며, 제한 크기의 quote-aware 스트리밍 파서가 따옴표 안 줄바꿈까지 한 레코드로 계산합니다. 파서는 디코딩 전에 원시 레코드가 16 MiB를 넘는지 먼저 차단합니다. 빈 레코드, 레코드별 열 수 불일치, 잘못된 UTF-8, 지나치게 큰 단일 레코드는 거부합니다.

- `maxRows`는 `hasHeader: true`일 때 첫 레코드를 제외한 **실제 데이터 행 수**에 적용됩니다.
- `maxFeatures`는 현재 `settings.data.features`와 각 `runs.experiments[*].settings.data.features`의 **선택된 원본 특성 수**에 각각 적용됩니다.
- `maxFeatures`는 타깃 열, CSV 전체 열 수, 범주형 one-hot 변환 뒤의 파생 차원 수를 뜻하지 않습니다.
- 선택 특성은 실제 CSV 열 이름과 일치해야 하며 중복될 수 없습니다. 빈 머리글과 중복 머리글은 내장 앱과 같은 `(A)`, `이름 (B)` 규칙으로 이름을 확정한 뒤 대조합니다.

검사 결과의 `facts.tabular`에는 다음 독립 계산값이 기록됩니다.

- `records`: 헤더를 포함한 CSV 레코드 수
- `rows`: 헤더를 제외한 정책 대상 데이터 행 수
- `columns`: 실제 CSV 열 수
- `currentFeatureCount`, `experimentFeatureCounts`, `maxSelectedFeatureCount`: 현재/실험별 선택 원본 특성 수

서버 안전 상한은 CSV 200,000 레코드, 5,000열, 원시 CSV 단일 레코드 16 MiB, 선택 원본 특성 2,000개입니다. 현재 내장 `ml-playgrounds` 브라우저 앱은 가져오기 단계에서 더 낮은 100,000 레코드·1,000열 상한을 적용합니다. 또한 `hashes.json`은 `hashes.json` 자신을 제외한 모든 파일 엔트리를 정확히 한 번 포함해야 하지만, 학생이 파일과 해시를 함께 다시 만들 수 있으므로 전자서명이나 학업적 진위 증명으로 취급하지 않습니다.

## 설치

설치·업데이트의 현재 기준은 릴리스 킷이 배포 묶음의 `install-guides/`에 생성한 **OJ ML Playgrounds 설치 안내서**입니다. 저장소에서는 `_release-kit/guides/oj-ml-playgrounds.md`가 원본이고 `_releases/latest/install-guides/`가 생성물입니다. ZIP과 함께 해당 안내서를 전달하세요. [INSTALL.md](INSTALL.md)와 [1.0 업그레이드 절차](docs/upgrade-1.0.md)는 과거 1.0.0 참고 문서이며 현재 버전의 설치 안내를 대신하지 않습니다.

업데이트는 **운영자의 DB·비공개 저장소·기존 플러그인 백업 → 현재 배포 ZIP 전체 교체 → PHP-FPM/OPcache와 관련 캐시 갱신 → 스키마 4 확인 → 학생·교사 회귀 시험** 순서입니다. 서버 관리·로그·백업·복원은 운영자 직접 수행으로 인계했으며 관리 경로나 백업 위치를 다시 요구하지 않습니다. ZIP 교체만으로 DB가 자동 변경되지 않습니다. **이미 스키마 4인 설치는 추가 DB 변경이 없습니다.** 스키마가 4보다 낮으면 **OJ 콘솔 교사 메뉴 › ML 실습 › 설정 → DB 업데이트 및 검증** 또는 `wp oj-ml migrate`가 필요합니다.

부모 화면과 내장 앱을 함께 교체해야 합니다. 일부 파일만 덮어쓰거나 예전 번들이 동일하다고 가정하지 말고 현재 배포 ZIP 전체를 사용하세요. 기존 실습 탭은 작업을 보존한 후 모두 닫고 캐시 갱신 뒤 새로 여세요. 업스트림 0.12.1과 스키마 4는 유지되지만 내장 앱의 정책 검사 동작은 변경되었습니다. 금지 모델 선택 불가, 허용 모델 학습·직접 제출, 과거 금지 실험 기록의 제출 전 안내를 설치 후 확인하세요.

설치 후 합성 시험 자료로 **삭제 확인창 취소 → 명시적 삭제 → 성공·실패 안내 유지 → 다른 탭 저장 차단 → 새로고침·재로그인 후 미노출 → 서버 제출·평가와 타 계정 자료 보존**을 확인하세요. 실제 삭제 완료 응답 전에는 성공을 표시해서는 안 되며 시간 초과를 삭제 완료로 간주하지 않습니다. ML의 별도 개인정보 URL이 비어 있을 때 OJ `/privacy` 상속도 확인하되 URL 연결과 실제 문서 게시를 구분합니다. 이 기관의 RC6 삭제·취소·두 탭 종료·재로그인 및 서버 사본 보존 시험은 2026-09-11 통과했고, 다른 환경의 시험까지 대신하지는 않습니다.

영수증·결과 화면의 같은 접수 시각과 서버 사용 횟수 표시도 설치 뒤 유지되는지 확인하세요. 새 **실습 시작**으로 서버 시도가 생성되면 제출 전에도 사용 횟수가 증가합니다. 기존 시도 이어하기나 같은 영수증 재전달은 추가 차감하지 않으며, 추가 허용·환급 등에 따라 시도 번호와 사용 횟수는 항상 같지 않을 수 있습니다. 1.2.0은 이 기존 시도 차감 정책을 변경하지 않습니다.

Nginx + PHP-FPM 8.3 서버 설정과 비공개 저장소 준비는 배포 묶음의 서버 준비 안내서, 현재 기능 설정은 OJ ML Playgrounds 설치 안내서를 따르십시오.

1. `oj-ml-playgrounds` 디렉터리를 WordPress `wp-content/plugins/`에 배치합니다.
2. OJ Platform을 먼저 활성화한 뒤 **OJ ML Playgrounds**를 활성화합니다.
3. OJ Platform 역할/권한 화면에서 학습자와 교사 역할에 필요한 add-on capability를 부여합니다.
4. 운영 서버에서 비공개 제출 저장 경로와 PHP ZIP 확장을 확인합니다.

플러그인은 역할을 임의로 수정하지 않습니다. 선언하는 capability는 다음과 같습니다.

- `oj_ml_playgrounds_use`
- `oj_ml_playgrounds_submit`
- `oj_ml_playgrounds_manage`
- `oj_ml_playgrounds_review`
- `oj_ml_playgrounds_report`
- `oj_ml_playgrounds_settings`

권장 역할별 capability 묶음은 다음과 같습니다.

- 학습자: `USE` + `SUBMIT`
- 결과 열람·평가 교사: `REPORT` + `REVIEW` (과제 작성·게시까지 담당하면 `MANAGE`도 추가)
- 설정 담당 교사: `SETTINGS` (이름 'ML 실습 설정', 교사 역할에 부여 가능. 사이트 관리자는 부여 없이 설정 화면을 엽니다)

결과 페이지는 `REPORT` gate를 사용하고 평가 mutation은 `REVIEW` 또는 `MANAGE`를 사용합니다. 따라서 평가 담당자에게는 `REVIEW`만이 아니라 `REPORT`도 함께 부여해야 합니다.

학생별 행의 **최신 제출 내용 및 평가 보기**를 펼치면 서버 사전검사에서 허용 목록으로 추린 프로젝트명, 과제·데이터 유형, 실행 수·알고리즘, 데이터 행·열·특성 수와 무결성 상태가 표시됩니다. `projectId`, 데이터셋 내부 경로, 엔트리별 해시와 finding 매개변수는 REST/화면에 내보내지 않습니다.

`REVIEW` 또는 `MANAGE` 권한과 해당 수업 Context의 `evaluate` 승인을 모두 통과한 교사는 같은 화면의 **제출 내용 안전 바로보기**에서 포트폴리오 답안, 설정·알고리즘과 MLPX에 기록된 평가 지표를 확인할 수 있습니다. 서버는 저장된 파일의 바이트 수와 SHA-256을 먼저 확인하고, 비공개 임시 사본에서 `manifest.json`, `settings.json`, `runs.json`, `portfolio/document.json`만 읽어 허용 목록 DTO로 투영합니다. 모델·전처리기·데이터셋·이미지·첨부파일은 읽거나 실행하지 않으며 지표도 재계산하지 않습니다.

`REPORT` 전용 계정은 안전한 요약과 점수 상태만 볼 수 있습니다. `REVIEW` 또는 `MANAGE` 교사는 필요할 때 `accepted`, `under_review`, `graded` 상태의 최신 원본 `.mlpx`도 POST nonce로 내려받을 수 있습니다. 원본은 inline 실행하지 않고 attachment로만 전달합니다. 결과 표는 **최신 접수 제출**을 우선 표시하고 **전체 제출 이력**에서 과거 시도도 확인할 수 있습니다. 학생에게는 본인의 공개 평가만 보이며 교사 초안은 숨겨집니다.

실제 WordPress capability 이름은 OJ Platform의 공개 capability mapper가 결정합니다.

## 비공개 저장소

기본 저장 위치는 WordPress 설치 디렉터리의 상위에 있는 `oj-ml-playgrounds-private`입니다. 운영 환경에서는 웹 서버 문서 루트 밖의 전용 디렉터리를 명시하는 편이 안전합니다.

```php
define('OJ_ML_PLAYGROUNDS_PRIVATE_DIR', '/srv/private/oj-ml-playgrounds');
```

웹 서버/PHP 사용자가 이 디렉터리를 만들고 쓸 수 있어야 합니다. 업로드 파일은 UUID와 무작위 파일명으로 저장되며 공개 정적 URL을 만들지 않습니다. 원본 다운로드는 REVIEW/MANAGE 권한, 수업 Context, POST nonce와 파일 무결성을 매 요청 다시 확인하는 PHP attachment 응답으로만 제공합니다.

## 데이터 소유권

플러그인은 플랫폼 테이블을 직접 조회하거나 수정하지 않습니다. OJ Context 및 명단은 공개 Addon API로만 읽고, 아래 add-on 소유 테이블에 snapshot과 결과를 저장합니다.

- `oj_ml_assignments`
- `oj_ml_assignment_targets`
- `oj_ml_assignment_learners`
- `oj_ml_attempts`
- `oj_ml_artifacts`
- `oj_ml_evaluations`
- `oj_ml_reviews`
- `oj_ml_events`

비활성화나 일반 삭제만으로 제출 기록은 지우지 않습니다. `OJ_ML_PLAYGROUNDS_DELETE_DATA` 보호 상수를 명시적으로 `true`로 설정한 뒤 제거하면 `uninstall.php`는 위 8개 add-on 테이블과 버전·설정·개인 양식·CSV 자료 메타데이터 옵션을 영구 삭제합니다. 웹 루트 밖 비공개 저장소의 `.mlpx`와 `teaching-assets/` CSV 원본은 그대로 남으므로, 실행 전에 함께 백업하고 운영자의 보존 기간·감사·파기 정책에 따라 별도로 보존하거나 삭제해야 합니다.
