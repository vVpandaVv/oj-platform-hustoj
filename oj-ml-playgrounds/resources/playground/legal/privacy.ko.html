개인정보 및 저장 안내

OJ ML Playgrounds 통합 배포 안내 v1.0 · 시행일 2026년 8월 31일

운영기관 확인이 필요합니다. 이 문서는 플러그인의 기술적 처리 내용을 설명하는 기본 고지입니다. 실제 개인정보처리자는 이 WordPress/OJ 사이트를 운영하는 학교·기관이며, 운영기관은 기관명, 담당자, 법적 근거, 보유기간, 위탁업체와 권리 행사 절차를 자체 방침에 맞게 확정해야 합니다.

프로젝트와 학습은 기본적으로 이 컴퓨터의 브라우저에서 실행·저장됩니다. OJ 제출 버튼 또는 파일 제출을 실행할 때에는 프로젝트 파일과 평가 관련 정보가 운영기관 서버로 전송·보관됩니다.

제1조 (처리하는 정보, 목적 및 저장 위치)

위치처리 항목목적
브라우저프로젝트 문서와 이름, 가져온 데이터셋·이미지, 학습 모델, 임베딩, 포트폴리오 첨부파일, 선택적으로 프로젝트에 입력한 학번·이름실습 실행, 자동저장, 복구, 내보내기
WordPress/OJ 서버로그인 계정 식별자, 수업·명단 context snapshot, 과제·시도·진행 상태, 제출한 MLPX 원본, SHA-256 해시, 형식 검사 결과와 finding, 점수·피드백·검토자, 감사·접속·오류 상관관계 기록제출 접수, 소유권 확인, 무결성 검사, 평가, 결과 제공, 감사와 장애 대응

학습 계산 자체는 학생 기기에서 이루어집니다. 플러그인은 프로젝트를 자동으로 서버에 업로드하지 않으며, 직접 OJ 제출 또는 사용자가 파일을 선택해 제출할 때 프로젝트가 전송됩니다. 일반적인 로그인·과제 조회·시도 생성 요청은 서비스 이용 과정에서 서버와 통신합니다.

제2조 (처리 근거와 제3자 제공)

교육과정 운영, 계약, 동의, 법령상 의무 등 실제 처리 근거와 제3자 제공 여부는 운영기관이 정합니다. 이 플러그인은 제출물을 광고 목적으로 판매하거나 독립적으로 제3자에게 제공하지 않습니다. 교사·검토자에게 결과를 공개하는 범위도 OJ 권한 설정과 기관 정책을 따릅니다.

제3조 (처리 위탁과 외부 서비스)

WordPress 호스팅, 데이터베이스, 백업, 보안 모니터링 사업자가 있다면 운영기관은 위탁 현황과 보관 장소를 별도로 공개해야 합니다. 이미지 실습을 선택하면 MobileNet 모델을 Google Storage에서 내려받고, 예시 데이터셋을 선택하면 luminousky.com에 연결될 수 있습니다. 학생이 가져온 사진이나 데이터셋을 이 외부 서비스에 업로드하지는 않지만 IP 주소, 브라우저 정보, 요청 시각 같은 접속 기록은 각 서비스에 남을 수 있습니다.

제4조 (보유기간과 파기)

  • 로컬 자료: 현재 OJ 계정 전용 IndexedDB에 남아 있으며 사용자가 삭제 버튼을 누르거나 해당 사이트 데이터를 지울 때까지 보관될 수 있습니다.
  • 서버 제출물·평가·감사 기록: 운영기관이 정한 학사·기록관리·분쟁 대응 기간 동안 보관한 뒤 삭제 또는 익명화해야 합니다.
  • 백업: 운영기관의 백업 순환 주기가 끝날 때 파기됩니다.

“이 기기의 내 실습 데이터 삭제”는 현재 계정의 로컬 암호화 저장소만 삭제합니다. 이미 서버에 제출한 사본과 다운로드 폴더의 .mlpx 파일은 삭제하지 않으므로 각각 운영기관에 요청하거나 사용자가 직접 삭제해야 합니다.

제5조 (이용자의 권리와 행사 방법)

이용자 또는 법정대리인은 관련 법령과 기관 정책에 따라 서버 기록의 열람·정정·삭제·처리정지 또는 이의 제기를 요청할 수 있습니다. 계정과 제출 결과는 운영기관 담당 창구로 요청하고, 브라우저 자료는 실습 화면의 삭제 버튼으로 지울 수 있습니다. 요청 처리 방식과 예외는 운영기관의 공식 개인정보 처리방침이 우선합니다.

제6조 (안전성 확보 조치와 한계)

  • 브라우저 저장소를 사이트·OJ 사용자별 불투명 scope로 분리하고 프로젝트, 데이터셋, 모델과 첨부파일을 AES-GCM으로 암호화합니다.
  • 암호화 키는 인증된 REST 응답으로 현재 로그인 사용자에게만 제공하며 URL, HTML 속성, IndexedDB에 저장하지 않습니다.
  • 로그인 세션을 화면 복원·포커스 시점과 주기적으로 다시 확인하고, 변경 또는 확인 실패 시 이전 iframe을 잠그고 제거합니다.
  • 서버는 역할 기반 권한, 제출 소유권 검사, 해시와 감사 기록을 사용합니다. 운영기관은 HTTPS, 업데이트, 백업 암호화와 관리자 계정 보호를 책임집니다.

한계: 브라우저 강제 종료, 악성 확장 프로그램, 관리자 권한 또는 개발자 도구를 이용한 공격까지 완전히 막는 경계는 아닙니다. 민감한 수업은 학생별 OS/브라우저 프로필이나 수업 종료 시 자동 초기화되는 계정을 함께 사용해야 합니다.

제7조 (쿠키, 로컬 저장소 및 자동 수집)

WordPress/OJ는 로그인 유지와 요청 위조 방지를 위해 인증 쿠키와 nonce를 사용합니다. 플러그인은 자체 광고·행동 분석 도구를 추가하지 않습니다. 서버와 호스팅 계층은 보안·장애 대응을 위해 IP 주소, 사용자 에이전트, 요청 시각, 경로와 상관관계 ID를 기록할 수 있으며 실제 항목과 기간은 운영기관이 고지해야 합니다.

제8조 (만 14세 미만 아동 및 학생 보호)

학생의 연령, 보호자 동의 또는 학교의 교육 목적 처리 근거에 관한 절차는 운영기관이 적용 법령과 학칙에 따라 마련합니다. 학생은 교사가 요구하지 않은 실명·학번·민감정보를 프로젝트나 데이터셋에 넣지 않아야 하며, 운영기관은 최소수집 원칙과 보호자 안내 절차를 적용해야 합니다.

제9조 (개인정보 보호책임자와 문의처)

구분운영기관이 게시할 내용
개인정보처리자[학교·기관명, 주소]
보호책임자/담당부서[성명 또는 직책, 부서]
연락처[전화, 이메일, 요청 접수 URL]
보유기간[제출물, 평가, 감사로그, 백업별 기간]

자가 설치 환경에서는 해당 학교·기관이 개인정보처리자입니다. 원본 ML Playgrounds 프로젝트의 저자나 배포 저장소는 운영기관 서버에 저장된 학생 기록의 개인정보처리자가 아닙니다. 관리자는 oj_ml_playgrounds_privacy_url 필터로 기관의 공개 방침 URL을 연결할 수 있습니다.

제10조 (권익침해 구제 방법)

먼저 운영기관 담당자에게 문의하십시오. 한국에서 추가 상담 또는 피해 구제가 필요한 경우 개인정보분쟁조정위원회(1833-6972), 개인정보침해신고센터(118), 대검찰청(1301), 경찰청(182)에 문의할 수 있습니다. 관할과 절차는 이용자 및 운영기관 소재지에 따라 달라질 수 있습니다.

제11조 (방침의 변경 및 우선순위)

저장 항목, 전송 시점, 외부 서비스 또는 보유정책이 바뀌면 운영기관은 적용 전에 방침과 시행일을 갱신해야 합니다. 이 기본 고지와 운영기관의 공식 개인정보 처리방침이 다르면 운영기관이 적법하게 게시한 공식 방침이 우선하며, 기술 동작과 다른 문구는 배포 전에 수정해야 합니다.
