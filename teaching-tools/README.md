## 1.2.8: 전역 수업 발견과 DB 조회 부하 감소

- 다른 OJ 화면의 수업 신호 발견과 배정 활동 발견은 자체 `/discovery` 응답 하나를 공유한다. 새 배정이 있으면 5초 간격을 유지하고, 빈 목록이 이어지면 5→10→20→30초로 간격을 늘린다. 숨겨진 화면에서는 요청하지 않고 화면으로 돌아오면 즉시 확인한다. 수업 신호의 기존 탭 대표 연결과 WebSocket은 유지한다. 비활성 상태에서 처음 시작한 수업은 최대 약 30초 뒤 발견할 수 있다.
- 최초 자동 참가와 활동 자동 열기를 유지하면서 같은 화면에서 모든 배정 활동에 매분 보내던 재참가 요청을 없앴다. 실제 참여 중인 화면과 수업 신호의 heartbeat는 계속 갱신한다. 서버는 발견·참가·조회마다 로그인 사용자와 참가 권한을 확인한다.
- 한 HTTP 요청 안에서 guard와 controller가 읽는 세션·진행 권한·참가자 정보를 재사용한다. 계정별 권한을 분리하고 참가자 삭제·수업 종료·권한 변경·저장 시 관련 읽기 값을 무효화한다. 요청 간 권한 캐시는 만들지 않는다. 정상 스키마가 설치된 일반 요청에서는 테이블 존재를 매번 조회하지 않으며, 버전 업그레이드와 관리자 화면의 누락 테이블 복구는 유지한다.
- 실제 repository/controller를 사용하는 DB 대역 검사에서 수업 신호 조회는 9회에서 3회, 기존 학생의 참가는 10회에서 4회로 줄었다(WordPress·플랫폼 공통 쿼리 제외). 공통 발견 클라이언트·권한 격리·변경 후 무효화·기존 참가와 판서 회귀를 검사한다. 운영 DB 응답 시간을 측정한 결과는 아니다.
- 플러그인 ZIP을 교체하고 교사·학생 화면을 새로고침한다. 실시간 서버 모듈과 설치 명령, 다른 애드온 의존성은 변경하지 않는다.

## 1.2.7: 동일 교사 계정의 참여 화면 충돌 수정과 PDF 배경 공유 선택

- 학생 참여 화면은 로그인 사용자가 수업 소유자·공동 교사여도 `viewer` 티켓을 명시적으로 요청한다. 서버는 기존 수업 접근 권한을 확인한 뒤 읽기 전용으로 내린다. 일반 학생·관찰자는 게시 역할을 요청할 수 없다. 역할을 생략한 기존 교사 클라이언트는 기존 방식으로 호환된다. 같은 교사 계정으로 교사/학생 화면을 열었을 때 두 연결이 교대로 기존 게시자를 끊던 문제를 수정했다. 판서·학생 미니 판서·수업 신호 참여 화면에 함께 적용된다.
- 교사는 시작 전 **학생 PDF 배경**과 수업 중 도구 모음에서 **기존 자료 열람 권한 유지 / 이 수업 참가자에게 배경 공유**를 선택한다. 기본값은 기존 권한 유지다. 접근 거부를 회색 화면으로 숨기지 않고 학생에게 사유와 다시 불러오기를 표시하며, 필기 레이어는 유지한다.
- 수업 배경 공유는 교사의 브라우저가 허용된 PDF 쪽을 2000×1200 이미지로 렌더링해 보호된 수업 이미지로 올린다. 현재와 다음 쪽을 차례로 준비하고, 학생은 해당 쪽의 이미지와 원래 PDF 영역을 기준으로 확대·이동한다. 원본 PDF의 자료 권한은 변경하지 않는다. 교사는 원본을 계속 사용한다. 공유를 끄거나 수업이 종료되면 배경 이미지 경로 접근을 거부한다. 이미 본 화면·캡처를 회수하는 기능은 아니다.
- 배경은 PHP OpenSSL AES-256-GCM으로 인증 암호화해 `.bin` 파일로 저장하므로 정적 웹 경로로 파일을 읽어도 배경 이미지가 노출되지 않는다. 복호화는 로그인·활성 수업·교사/참가자·공유 설정 확인 뒤에만 수행한다. 수업당 배경 500개와 일반 삽입 이미지 30개의 한도를 분리했다. 종료·정리·삭제에서 같은 저장소를 정리한다. WordPress 이미지 편집기와 PHP OpenSSL이 필요하며 미지원이면 실패를 표시하고 공개 파일로 우회하지 않는다.
- 실제 로컬 Edge/Chrome + 실제 PHP 티켓 발급으로 동일 계정의 연결 교체가 수정 전 7회에서 수정 후 0회가 되고 임시 필기를 받는 것을 확인했다. 권한 없는 원본 PDF는 계속 거부하면서 수업 배경만 표시하는 브라우저 검사와 서버 암호화·변조·다른 수업·공유 철회·종료·업로드 권한 검사를 추가했다. 운영 사이트의 네트워크 지연 수치를 보장하는 결과는 아니다.
- 티칭툴 모듈 1.2.3과 공통 서버 1.0.1은 변경하지 않는다. 플러그인 ZIP 교체 후 두 화면을 새로고침한다.

## 1.2.6: iPad 판서 화면과 실시간 필기 지연 개선

- iPad/iPhone에서는 전체화면 버튼이 Safari 네이티브 전체화면 대신 브라우저 창 안의 최대화를 사용한다. 데스크톱 모드 iPad도 감지한다. 네이티브 전체화면 종료 제스처와 필기의 충돌을 피하는 방식이며 Safari 주소창까지 숨기는 기능은 아니다. 같은 버튼 또는 Escape로 해제하고 학생의 나가기 버튼도 유지한다.
- 공유 렌더러가 확정된 필기를 비트맵으로 보관하고, 필기 중에는 새로 추가된 선분만 그린다. 지우개는 필기 레이어만 지우며 취소·도형 교체·페이지·되돌리기·밀도 변경 시 기준 화면을 복원한다. 교사도 선 완성 시 새 요소만 기준 비트맵에 추가한다. 학생 화면의 메시지는 프레임 단위로 묶고, 임시 필기마다 전체 필기 JSON 비교와 PDF 표시·이웃 페이지 준비를 반복하지 않는다. PDF와 필기의 확대 해상도는 유지한다.
- 실시간 좌표를 서버 허용치인 512개 이하로 나눠 보내며 전송에 성공한 좌표까지만 전송 위치를 갱신한다. 대량 coalesced 입력도 남은 좌표를 다음 전송에서 이어 보낸다. 연결이 끊겼을 때 임시 필기 조각은 큐에 쌓지 않고 재연결 스냅샷으로 복구한다. 실제 크기가 바뀌지 않은 확대 화면 재측정은 진행 중인 필기를 끊지 않는다.
- 검증: 실제 공통 허브와 PDF를 사용한 1,537개 좌표 묶음의 펜업 전 전송, 필기·지우개·도형·복원·고해상도 갱신, iPad 데스크톱 식별 조건의 네이티브 API 미호출·터치 최대화, 기존 PDF/참가/나가기/확대·축소 흐름을 검사한다. Chrome 자동화이며 실제 iPad Safari/Apple Pencil 및 운영 네트워크의 지연을 측정한 것은 아니다.
- 실시간 서버 모듈은 1.2.3 그대로 사용한다. 이번 변경은 플러그인 ZIP 갱신과 교사·학생 페이지 새로고침으로 적용하며 서버 재설치·설정 변경은 필요하지 않다.

## 1.2.5: 자료 맞춤·확대와 판서 입력 안정화

- 학생 판서 보기에 화면 맞춤·너비 맞춤·칠판 전체와 25~400% 확대/축소를 추가했다. 화면 맞춤은 PDF의 실제 페이지 영역을 기준으로 좌우 빈 칠판 여백을 줄인다. 너비 맞춤은 자료 상단부터 보여 주며, 칠판 전체로 PDF 밖의 필기도 볼 수 있다. 확대 후 마우스 드래그·터치 스크롤로 이동하고 Ctrl/Command+휠로 확대한다. 보기 설정은 교사 좌표·공유 상태를 바꾸지 않는다.
- `whiteboard-viewer.js`가 학생 화면의 보기 변환만 담당한다. 창 크기·전체화면·회전에 맞춰 다시 계산하고, 확대 중심을 유지한다. PDF와 필기 백킹을 기기 배율·확대 수준에 따라 최대 3000×1800으로 다시 렌더링한다. PDF 비트맵은 해상도별 키를 쓰며 전체 캐시는 기존처럼 6개로 제한한다.
- 교사 판서는 기본 드래그·선택·그리기 중 휠 스크롤을 차단하고 한 포인터만 추적한다. 입력 도중 좌표계를 고정하고 레이아웃이 바뀌면 마지막 정상 지점에서 마친다. 취소·캡처 손실·창 포커스 해제는 마지막 정상 좌표로 완료하며, 화면 밖 좌표는 칠판 범위로 제한한다. 합쳐진 포인터 샘플을 수집하고 화면 그리기는 프레임 단위로 묶는다.
- 브라우저/OS 자체의 Escape·시스템 전체화면 종료는 막지 않는다. 정상 판서에서 발생하는 스크롤·선택·드래그 충돌을 막는 변경이다. 실시간 서버 모듈은 1.2.3 그대로 사용하며 ZIP만 갱신한다.

## 1.2.4: 학생 나가기와 전체화면

- 모든 학생 참여 활동 상단에 **수업에서 나가기**와 전체화면 버튼을 제공한다. 나가기는 해당 학생 화면의 WebSocket·조회·수업 신호 heartbeat·진행 중 요청을 정리하고 코드 입력으로 돌아가며 교사의 수업이나 제출 기록을 삭제하지 않는다. 오래된 비동기 응답으로 다시 참여 화면이 열리지 않도록 한다.
- 나간 코드는 학생별로 브라우저에 최대 100개·24시간 기록해 같은 수업 자동 참가/강제 이동을 막는다. 배정 목록이나 코드로 직접 다시 참여하면 해제된다. 수업 신호의 기존 연결 해제 기록도 함께 정리한다. URL의 코드도 제거하고, 저장소가 막혀도 현재 화면의 나가기는 동작한다.
- 학생도 전체화면에서 수업을 보고 나갈 수 있다. 브라우저 전체화면이 지원되지 않거나 거부되면 창 안의 화면 확대로 전환하며 버튼·Escape로 해제한다. 판서/PDF 배경 비율을 유지하며 모바일과 화면 회전을 지원한다.
- 실시간 서버 모듈은 변경하지 않아 1.2.3을 그대로 사용한다. 이 업데이트에는 서버 명령 재실행이 필요하지 않다.

## 1.2.3: 서버 버전 확인과 판서 공유 복구

- 설정 상단에 플러그인, 서버 티칭툴 모듈, 공통 허브 버전을 함께 표시한다. 서명 인증된 서버 응답을 동봉 코드와 비교해 업데이트 필요·일치·상위 버전·확인 불가를 구분한다. 인터넷 최신 릴리스 조회가 아니며 연결 실패를 정상/최신으로 취급하지 않는다. 이전 모듈은 기존 설정 유지 명령으로 갱신한다.
- 설치 ZIP의 `common-server/package.json`에서 공통 허브 동봉 버전을 읽는다. 개발 폴더의 `_shared` 경로뿐 아니라 실제 압축 파일을 대상으로도 버전 정보를 검사한다. 검수 중 생성된 1.2.2의 동봉 경로 문제는 1.2.3에서 수정했다.
- 학생 판서는 WebSocket 연결 중에도 5초 간격으로 REST 저장본을 확인한다. 신선한 실시간 필기를 보호하고 revision으로 오래된 저장본·재접속 스냅샷이 최신 판서를 덮지 않도록 한다. 끊기면 600ms 조회로 전환한다. 임시 펜 미리보기 취소 시 잔상이 남는 렌더 서명도 수정했다.
- 티켓·소켓 인증 대기를 8초, 판서 REST 요청을 10초로 제한한다. 새 모듈은 애플리케이션 ping/pong을 지원해 열린 채 응답하지 않는 소켓도 재연결한다. 이전 모듈에는 heartbeat를 요구하지 않아 백업 방식과 호환된다. 교사·학생에게 연결 상태를 표시하고 저장 실패는 숨기지 않고 간격을 늘려 재시도한다.
- 브라우저의 전체화면 API가 없거나 권한으로 거부되면 창 안의 화면 확대를 제공한다. 버튼·Escape로 해제하며 칠판 닫기 시 원래 레이아웃을 복구한다. 전체화면에서 펜·도형 미리보기·PDF 배경의 위치와 비율을 맞췄다. 늦게 로딩된 교사·학생 스크립트도 초기화한다.
- 일반 데이터용 노드 수 제한 때문에 필기 좌표 저장이 실패하던 문제를 판서 전용 한도로 수정했다. 512KiB 총용량·페이지·깊이 등 나머지 제한과 다른 도구의 한도는 유지한다.
- 검증: 실제 공통 허브·티칭툴 어댑터와 Chrome에서 코드 수동 참가, 드래그 중 미리보기·완성 판서, 늦은 참가, 중계만 멈춘 연결, 저장 오류 복구, REST 전환, 모바일 픽셀, 전체화면 허용·거부, 버전 안내를 검사한다. 운영 서버 배포·실제 nginx/systemd 점검은 별도다.

## 1.2.1: 설정 유지 서버 업데이트와 참여 안내 접기

- 플러그인 ZIP을 먼저 갱신한 뒤 설정 화면의 **기존 설정 유지 업데이트** 명령을 SSH에서 실행한다. 기존 설치 명령 끝에 `--update`를 붙이는 방식이며 설정 코드·비밀키를 다시 입력하지 않는다. 최초 설치나 의도적으로 주소·키를 바꿀 때는 기존 설치·복구를 사용한다.
- 공통 서버 1.0.1은 저장된 설정을 읽어 모듈 코드만 갱신하고, 주소·인증키·포트·운영 환경값·다른 모듈과 미전송 데이터를 유지한다. nginx 파일과 systemd 유닛·자동 시작 설정은 변경하지 않는다. 기존 스테이징·백업·인증 검사와 오류 복구 절차를 재사용한다. 실행 중 수업·경기는 공통 서비스 재시작으로 중단되므로 비사용 시간에 진행한다.
- 판서의 참여 코드·링크·QR 영역을 기본으로 펼쳐진 접기/펼치기 영역으로 바꿨다. 접으면 한 줄만 남고 코드와 QR이 함께 숨겨져 판서 공간을 확보한다. 전체화면에서도 같은 상태로 사용할 수 있고 키보드로도 조작한다.
- 검증: 공통 서버의 업데이트·레거시 이전·다른 모듈 보존·실제 WebSocket 통신 검사, Bash 구문 검사, 설정 화면 명령·비밀키 미노출 검사, 코드·QR 접기와 기존 판서 브라우저 회귀 검사. Linux의 실제 systemd/nginx 운영 배포는 별도다.

## 1.2.0: 활동 화면 자동 열기와 PDF 전체 가져오기

- 모든 학급·그룹 자동 연결 도구와 수업 신호에 **활동 시작 시 학생 화면 자동 열기** 옵션을 추가했다. 기본은 꺼짐이며, 켜면 로그인한 학생의 활성 OJ 화면에서 약 5초 안에 현재 탭을 활동 참여 화면으로 전환한다. 참여 화면에 있던 학생도 새 활동으로 전환한다. 팝업이나 외부 사이트 제어를 사용하지 않는다.
- 서버가 검증한 그룹 세션만 자동 열기를 지시한다. 학생별로 열린 코드를 브라우저에 기록해 뒤로 이동·새로고침·다른 탭에서 같은 수업을 반복해서 열지 않는다. 가장 최근 자동 열기 활동을 기준으로 하며 이전 활동으로 끌어오지 않는다. 기록은 유효기간 24시간·최대 100개로 제한하고 저장소가 막히면 화면을 강제 이동하지 않는다.
- PDF 범위 기본값은 **전체 페이지**다. 시작 화면에서 자료를 고르고 칠판을 열면 모든 쪽이 판서 페이지로 준비된다. 수업 중에도 현재 페이지 뒤에 문서 전체를 삽입하며, 한 쪽만 추가하거나 현재 배경만 바꾸는 기존 선택도 유지한다. 빈 초기 칠판은 자료로 대체하고 기존 판서·되돌리기 기록은 보존한다.
- 한 칠판은 최대 500페이지이며 초과 문서를 조용히 자르지 않는다. 서버 저장과 실시간 미리보기의 페이지 한도를 함께 조정했다. 이미지 캐시는 6쪽으로 제한하고 이웃 쪽을 미리 렌더링한다. 기존 실시간 서버는 설치·복구 명령으로 갱신해야 101쪽 이후 펜 미리보기도 지원한다.
- 검증: `php tests/session-admission.php`, `php tests/whiteboard-policy.php`, `node tests/activity-navigation.cjs`, `node tests/browser-activities.cjs`, `npm test`(realtime-server).

## 1.1.2 수정

- 시작 전 PDF 선택 창을 숨겨진 칠판 밖에 두고, 전체화면에서는 칠판 안으로 옮겨 표시한다.
- PDF.js 모듈의 파일 내용은 유지하고 확장자를 `.js`로 제공해 MJS MIME 설정이 없는 서버를 지원한다. 모듈 실패 후 다시 불러오기와 30초 로딩 제한을 추가하고, 실제 권한 거부·파일 오류·모듈 오류를 구분한다.
- 다른 OJ 화면에서도 서버가 배정한 활동에 코드 없이 자동 참가하고 1분마다 연결 상태를 갱신한다. 현재 화면은 유지하며 활동 링크로 참여 화면을 열 수 있다. 늦게 삽입된 스크립트도 초기화한다.
- 참가 시 명단의 표시 이름·관리용 이름을 보존하고, 도구 상태 동기화에서 검증된 그룹 정보를 지우거나 클라이언트가 덮어쓰지 못하게 한다.
- 브라우저 회귀 검사는 실제 Learning Materials 보호 스트림에 WordPress 대역 인증을 연결해 실행한다. 시작 전/전체화면 PDF, 모듈 장애 후 재시도, 권한 거부, 페이지 교체·판서·PNG·모바일, 전역 활동 자동 참가·수업 신호를 검사한다. 운영 사이트에 배포한 결과를 뜻하지는 않는다.

## 구조

- 콘솔 허브 `/oj-console/addons/teaching-tools` — 도구 카드 그리드, 준비된 도구만 클릭 가능.
- 도구별 호스트 화면 `/oj-console/addons/teaching-tools/{tool}` — 교사가 실행/제어.
- 공용 참여 진입점 `/oj-addons/teaching-tools/join` — 학생이 참여 코드로 입장(로그인 필수).
- 공통 세션 인프라(`src/Sessions`, `src/Rest/Controllers/Sessions_Controller.php`): 6자리 참여 코드 발급, REST 폴링으로 호스트-참여자 상태 동기화, `Session_Code_Guard`로 코드 추측 시도를 사용자당 5분/10회로 제한. 판서·학생 미니 판서·수업 신호는 `realtime-server/`의 공용 WebSocket 허브를 우선 사용하고, 연결할 수 없을 때 REST 폴링으로 자동 전환한다.
- 자리배치(`src/Addon/Seating`, `resources/js/seating-engine.js`): seat-arranger_v2의 제약 조건 배치 알고리즘(앞자리/거리 제약/짝 배치)을 순수 함수로 포팅. `onReady()`로 받은 `AddonRuntimeContextV1`을 `Runtime_Bridge`가 보관하고, `Roster_Controller`가 학급/그룹 명단(Addon API Context·Roster 게이트웨이)을 조회해 실명 명단을 채워준다. 명단을 학급에서 가져왔을 때만 "동시 참여(내 자리 찾기)" 모드를 열어준다 — 직접 입력한 명단은 실제 로그인 사용자와 매칭할 방법이 없기 때문.
- 사다리타기(`src/Addon/Ladder`, `resources/js/ladder-engine.js`): 각 행이 서로소 열 교환(disjoint transposition)이 되도록 가로줄을 배치해, 합성 결과가 항상 전체 열에 대한 순열(bijection)이 됨을 구조적으로 보장 — 2000회 랜덤 트라이얼로 검증. 학생이 실제로 선택하기 전까지는 `mapping`/`rungs`를 절대 내려주지 않는다(`Sessions_Controller::present()`가 참여자 응답에서 제거) — 교사 화면이 프로젝터에 띄워져 있어도 학생이 미리 결과를 유추할 수 없다. 줄 선점은 `Tool_Session_Repository::atomic_update_by_code()`(`SELECT ... FOR UPDATE` 행 잠금)로 동시 클릭 경쟁을 막는다.
- 판서(`src/Addon/Whiteboard`, `resources/js/host-whiteboard.js`, `resources/js/whiteboard-render.js`): 요소를 비트맵이 아니라 좌표 벡터(0~1000×0~600 정규화 좌표계)로 동기화해, 호스트·학생 화면의 실제 픽셀 크기가 달라도 동일하게 그려지고 폴링 payload도 작게 유지한다. 펜/지우개/직선/사각형/원/화살표/텍스트/이미지 요소를 여러 페이지에 걸쳐 담고, 페이지별로 되돌리기/다시하기 스택을 따로 관리한다. Learning Materials가 활성화돼 있으면 접근 가능한 PDF의 보호 URL을 배경으로 참조하며 원본 파일을 복제하지 않는다. 브라우저 PDF 뷰어 위에 투명 판서층을 겹치는 방식이라 PDF 배경은 PNG 저장 결과에 포함되지 않는다.
- 학생 미니 판서(`src/Addon/Quickboard`, `src/Rest/Controllers/Quickboard_Controller.php`): 학생마다 독립적인 펜·지우개 캔버스를 제공한다. 제출 데이터는 해당 세션의 참가자 레코드에만 두고 다른 학생에게는 보내지 않는다. 교사는 썸네일 갤러리와 크게 보기로 확인하며, WebSocket에는 그림 전체가 아니라 저장 완료 알림만 보내고 실제 데이터는 권한이 확인된 REST로 다시 읽는다.
- 빠른 응답(`src/Addon/Quiz`, `src/Rest/Controllers/Quiz_Controller.php`): 기존 객관식에 척도, 한줄 응답, 워드클라우드, 익명 질문을 추가했다. 학생은 자기 응답과 교사가 공개한 집계만 받고, 익명 질문은 교사 응답에서도 사용자 ID를 제거한다. 질문 공개/숨김과 결과 공개는 행 잠금 기반 원자 갱신으로 새 응답을 덮어쓰지 않는다.
- 조 짜기(`src/Addon/Grouping`, `resources/js/grouping-engine.js`): 무작위 배정 또는 "실력 균형 배정"(제출 기록 기반 스네이크 드래프트 — 스포츠 드래프트처럼 픽 순서를 0,1,...,N-1,N-1,...,1,0으로 뒤집어가며 뽑아 조별 실력 합을 비슷하게 맞춤). 동점자는 매번 무작위로 순서를 섞어 항상 같은 순서로 뽑히지 않게 한다.
- 문제 풀이 타임어택(`src/Addon/Timeattack`, `src/Rest/Controllers/Judge_Controller.php`): 문제를 정하고 시간을 재면서, 챌린지 시작 시각(`session.created_at`) 이후의 정답 제출만 인정해 누가 풀었는지 교사 화면에 실시간으로 보여준다.
- 수업 신호(`src/Addon/Classroom`, `src/Rest/Controllers/Classroom_Controller.php`, `src/Addon/Classroom/Global_Classroom_Bridge.php`): 학생이 준비·이해·어려움·재설명·도움·완료 중 현재 상태 하나를 보내면 교사 화면이 접속 현황과 함께 집계한다. 학생은 6자리 코드로 참여하거나, 교사가 지정한 학급·그룹 명단에 따라 코드 없이 자동 참여한다. 참여 뒤에는 같은 로그인 브라우저의 OJ Platform 및 다른 애드온 화면에도 접이식 신호 바가 이어져 참여 페이지를 계속 열어 둘 필요가 없다. 다른 플러그인의 학생 진입 화면은 프리셋으로 불러오되 URL만 전달해 콘텐츠·제출·점수 저장은 각 플러그인이 계속 소유한다. WebSocket은 신호와 접속/이탈을 즉시 전달하고, 참가자 테이블의 `data`에는 마지막 확인 시각과 자기 신호만 세션 범위로 저장해 REST 폴백과 재접속을 지원한다.
- 수업 운영 보드(`src/Addon/Operations`): 수업 순서, 활동 모드, 신호등, 타이머와 선택형 소음 신호를 한 화면에 둔다. 순서표와 표시 설정은 교사 브라우저 `localStorage`에만 저장한다. 마이크 스트림은 소음 신호를 켠 동안 현재 브라우저에서만 분석하고 녹음하거나 서버로 전송하지 않는다.
- **플랫폼 공식 연동 계약**: 다른 플러그인이나 채점 DB를 직접 읽지 않는다. 학급·그룹 명단, 공개 문제, 명단 범위의 정답 제출, 다른 애드온의 활동 검색은 OJ Platform 2.3의 `AddonIntegrationGatewayV1` 한 통로로만 요청한다. 플랫폼은 현재 사용자와 수업 명단을 다시 검증하고 필요한 최소 필드만 반환한다. 조 짜기 실력 배정과 타임어택도 이 계약을 사용하며, 계약을 사용할 수 없으면 오류를 표시하고 임의의 DB 우회 경로를 열지 않는다.

## 0.1.2 → 0.1.3: 두 가지 추가 버그

## 0.1.3 → 0.1.4: 명단 불러오기 404의 실제 원인

두 번 고쳤는데도 계속 같은 오류가 나서, 브라우저 Network 탭에서 실패한 요청의 **실제 URL**을 받아 확인했다: `.../contexts/group/group:8/roster?revision=...`. `group:8`처럼 `:`이 든 id 자체는 정규식이 이미 허용하고 있었는데도 매치가 안 됐다.

원인은 문자 클래스 안에 있던 **탈출 안 된 `@` 하나**였다. WordPress의 `WP_REST_Server::dispatch()`는 등록된 모든 라우트 정규식을 `preg_match('@^' . $route . '$@i', ...)`로, 즉 **`@`를 구분자로** 감싸서 매칭한다. 그런데 내 정규식 `[A-Za-z0-9_.:@-]` 안의 `@`가 바로 이 구분자로 읽혀서 패턴이 그 자리에서 잘려버렸고, PHP 경고 하나 없이 그냥 "매치 실패"로 조용히 끝나 — id에 `:`, `.`, 어떤 문자가 들었든 상관없이 이 라우트는 절대 매치될 수 없는 상태였다. WordPress의 실제 `preg_match()` 호출을 그대로 재현해서 확인했다: `@` 탈출 전엔 실패, `\@`로 탈출하니 `group:8`을 포함해 정상 매치.

`[A-Za-z0-9][A-Za-z0-9_.:\@-]{0,159}`로 고쳤다.

- **도구 다양화**: 펜/지우개 외에 직선·사각형·원·화살표·텍스트를 추가했다. 도형은 드래그 중 별도의 미리보기 캔버스(`.htt-whiteboard-canvas-preview`, `pointer-events: none`으로 겹쳐 놓음)에 그리다가 손을 떼는 순간 실제 요소로 확정해 메인 캔버스에 커밋한다 — 매 프레임 전체를 다시 그리지 않아도 되게 하기 위함. 텍스트는 별도 리치 에디터 없이 `window.prompt()`로 입력받는다. 페이지를 여러 장 만들 수 있고, 페이지마다 되돌리기/다시하기 스택이 독립적이다. 호스트·학생 렌더링이 갈라지지 않도록 그리기 로직을 `resources/js/whiteboard-render.js` 공용 모듈로 뽑아 양쪽이 같은 코드로 그린다.

## 0.4.0: 타이머 종료 알림음 선택

시각적 표시만으로는 교사가 화면을 보고 있지 않으면 놓치기 쉽다는 후속 요청으로, 종료 시 소리도 선택해서 낼 수 있게 했다.

- **소리는 외부 음원 파일 없이 Web Audio API로 즉석 합성**한다(`resources/js/timer-sound.js`, `window.HttTimerSound.play(key)`). 오실레이터로 만든 짧은 톤 패턴 4가지 — 차임벨(`chime`), 종소리(`bell`), 알람(`alarm`), 딩동(`ding`) — 와 무음(`none`)을 제공한다. mp3/wav 파일을 내려받아 배포하는 대신 코드로 생성하므로 라이선스 문제도 없고 플러그인 용량도 늘지 않는다.
- 타이머 시작 화면에 "종료 알림음" 선택창과 "미리듣기" 버튼을 추가했다(`Timer_Host_Page_Handler.php`). 미리듣기 클릭 자체가 사용자 제스처라서, 브라우저의 오디오 자동재생 제한과도 무관하게 그 뒤 카운트다운이 끝났을 때도 소리가 확실히 난다.
- 선택한 소리 키(`sound`)는 세션 상태(`state.sound`)에 실려 함께 동기화되므로, 동시 참여 모드에서는 학생 화면(`join.js`)에서도 카운트다운이 0이 되는 순간 같은 소리가 재생된다 — 다만 매 폴링마다 다시 울리지 않도록 종료 상태로 "처음 전환되는 순간"에만 한 번 재생하도록 플래그로 막아둔다.

## 0.6.1: 플러그인 삭제 시 데이터 정리

v1.0 준비 상태를 점검하면서 나온 가장 명확한 결함 — 지금까지는 플러그인을 완전히 삭제해도 만든 테이블과 옵션이 DB에 영원히 남았다. `teaching_tools_deactivate()`는 세션 정리 크론만 해제할 뿐, "비활성화"와 "삭제"를 구분해서 처리하는 로직이 없었다.

- **왜 별도 옵션(토글) 없이 항상 지우는가**: 이 플러그인엔 설정 화면 자체가 없고, "삭제"는 이미 WordPress에서 명확히 되돌릴 수 없는 동작으로 취급된다(비활성화와 별개 버튼). 저장된 자리배치를 삭제 후에도 남기고 싶다는 요구가 나오면, 그때 "삭제 시 데이터 보존" 옵션을 추가하는 게 더 맞다고 판단해 지금은 단순하게 뒀다.
- **`uninstall.php`는 메인 플러그인 파일 없이 독립 실행된다는 제약**: WordPress는 삭제 시 `teaching-tools.php`(따라서 오토로더와 `TEACHING_TOOLS_*` 상수들)를 로드하지 않고 이 파일만 단독으로 읽는다. 그래서 `Installer::sessions_table()`이나 `Whiteboard_Image_Repository::SUBDIR`을 재사용하지 못하고, 테이블·폴더 이름을 이 파일 안에 직접 다시 적었다 — 두 군데를 유지보수해야 하는 대가가 있지만, WordPress 코어의 uninstall 실행 방식이 강제하는 제약이라 피할 수 없다.

## 0.7.0: 타임어택 문제별 풀이 현황 표 + 순위

여러 문제를 낼 수 있게 된(0.5.0) 뒤로도 교사 화면에는 "3/5문제, 완료"처럼 숫자만 보였지 정확히 어떤 문제를 풀었는지는 보이지 않았다.

- **문제별 풀이 표**: `Judge_Controller::timeattack_status()`가 학생별로 이미 계산해 두고 있던 문제ID별 제출 시각(`$solved_by_problem`)에서 키만 뽑아 `solvedProblemIds` 배열로 응답에 추가했다(새 쿼리 없음, 기존 계산 재사용). `host-timeattack.js`의 `renderStatusList()`를 카드 목록에서 표로 다시 짜서, 세로는 학생, 가로는 문제 번호 열로 두고 푼 문제 칸에 ✅를 표시한다. 문제가 많아 표가 넓어지면 페이지 전체가 밀리는 대신 `.htt-timeattack-list`가 가로 스크롤된다.
- **전체 완료자 순위**: 서버가 이미 "전부 완료 → 완료 시각" 순으로 정렬해 두던 목록에 순위 번호(`rank`)를 매겨 응답에 실었다 — 다 못 푼 학생에게는 `rank`가 `null`이라 순위가 매겨지지 않는다. 1~3위는 🥇🥈🥉로, 4위부터는 숫자로 표시한다.
- 참여자(학생) 화면(`join.js`)은 그대로 뒀다 — 다른 학생이 뭘 풀었는지 보여주지 않는 원래 설계("공개 순위로 인한 위축 방지")를 유지하기 위해, 이 표와 순위는 교사 화면에만 나온다.

## 0.7.1: 사용법 모달 닫기 버튼 무반응의 진짜 원인 수정

0.5.0에서 "스크롤로 밀려나서 그렇다"고 고쳤는데도 사용자가 "여전히 안 먹힌다"고 다시 알려왔다 — 그 수정은 실제로 유효한 개선이었지만 진짜 원인이 아니었다.

**진짜 원인**: `console.css`의 `.htt-modal-overlay { display: flex; ... }`가 브라우저 기본 스타일시트(user-agent stylesheet)의 `[hidden] { display: none; }` 규칙을 항상 이긴다. CSS 캐스케이드는 origin(작성자 규칙이 브라우저 기본 규칙보다 항상 우선) → 명시도 → 소스 순서로 정해지는데, "작성자 규칙이 이긴다"는 판정은 명시도 비교 없이 그 즉시 확정된다. 즉 `.htt-modal-overlay`라는 클래스 선택자 하나만으로도(명시도가 얼마나 낮든) 브라우저의 `[hidden]` 규칙을 항상 눌러버린다. 그 결과 `usage-modal.js`가 `overlay.hidden = true`를 실행해도(닫기 버튼 클릭 시) 실제로는 `display: flex`가 계속 적용돼 모달이 화면에서 전혀 사라지지 않았다 — 열 때는 `hidden=false`로 가는 방향이라 문제가 없었으니 "열기는 되는데 닫기만 안 된다"는 증상과 정확히 일치한다.

**수정**: `.htt-modal-overlay[hidden] { display: none; }`을 추가했다. 이 규칙도 작성자(author) 출처라 이제 같은 티어에서 명시도로 승부하게 되는데, `[hidden]` 속성 선택자가 붙어 `.htt-modal-overlay`보다 명시도가 높아 확실히 이긴다. 코드베이스 전체를 검색해 `hidden` 속성을 토글하면서 동시에 같은 클래스에 `display`를 선언한 다른 요소가 있는지 확인했고, `.htt-modal-overlay`가 유일한 사례였다.

## 0.8.0: 자리배치 — 앞자리 동적 확장 + 짝 배치를 실제 책상 단위로

앞자리를 희망하는 인원이 앞자리 좌석 수보다 많고, 그 학생들을 짝지어 앉히려 하면 "빈자리는 있는데 배치하지 못했다"는 알람이 떴다. 원인은 세 가지가 겹쳐 있었다.

- **앞자리 구역이 항상 2행으로 고정돼 있었다**: `seating-engine.js`의 `FRONT_ROW_COUNT = 2`가 인원수와 무관한 상수였다. 이제 `arrange()`가 `Math.ceil(앞자리 희망 인원 / 열 수) + 1`행으로 동적 계산한다 — 6명이 6열에 다 들어가는 경우에도 뒷줄까지 여유롭게 1행을 더 얹는다. 인원수가 딱 맞아떨어져도 여유 행이 있어야 짝(책상 2자리)이 들어갈 빈 "덩어리"가 남는다는 게 핵심이다.
- **짝 배치가 아무 인접 칸이나 붙였다**: `chooseBuddySeats`/`evaluateAssignment`가 상하좌우 아무 방향이나 "붙어 있으면" 인정하는 `isOrthogonalNeighbor`를 썼다. 실제 교실은 책상이 좌우로 2개씩 묶여 있는데(1·2번, 3·4번, 5·6번 자리), 이 로직은 통로 건너 옆줄(2번-3번)이나 앞뒤 자리도 "짝"으로 인정해버렸다. 각 행에서 `Math.floor(열 / 2)`가 같은 두 자리만 짝으로 인정하는 `isDeskMate()`로 바꿨다 — 열이 홀수면 마지막 자리는 자동으로 짝 없는 단독 책상이 된다.
- **앞자리 + 짝인 학생이 아예 배치에서 누락됐다**: 원래 순서는 "앞자리 희망자를 한 명씩 개별 배치 → 그중 아직 안 앉은 사람만 짝 배치 시도"였다. 앞자리를 원하는 짝 학생은 개별 배치 단계에서 이미 혼자 자리를 잡아버려 짝 배치 단계에 도달할 때는 이미 "배치 완료"로 빠져 있었다 — 짝 배치 시도 자체가 조용히 건너뛰어졌다. 짝 중 한 명이라도 앞자리를 원하면 "짝 배치를 먼저" 시도하도록 순서를 바꿔, 반드시 같은 책상(앞자리 구역 안)에 나란히 앉게 했다.
- 덤으로, 앞자리 좌석이 정말 부족해 개별 배치조차 실패하면 그 학생을 통째로 누락시키던 버그도 고쳤다 — 이제는 앞자리를 못 받아도 다른 빈자리에는 앉혀서 "배치 실패" 대신 "앞자리 요청 미충족" 경고로 바뀐다.

## 0.8.2: 자리배치 — 앞자리+떨어뜨리기 동시 설정 시 "붙은 자리로 확정"해버리던 문제

앞자리 우선과 떨어뜨리기 조건을 같은 학생들에게 걸었더니 1행1열·2행1열처럼 바로 앞뒤로(같은 열, 다른 행) 붙어서 배치되는 경우를 발견했다는 리포트를 받았다.

코드를 정밀 추적한 결과, `chooseFrontPairSeats()`(앞자리 안에서 두 학생을 배치할 자리를 고르는 함수)가 진짜 원인이었다. 이 함수는 앞자리 구역 안의 모든 좌석 쌍 조합을 점수화해서 "가장 덜 나쁜" 조합을 고르는데, **점수가 가장 좋은 조합이 여전히 "붙어 있음/너무 가까움" 위반이어도 개의치 않고 그걸 그대로 확정**해 버렸다. 즉 이 함수 안에서는 "이 시도에서는 도저히 만족스러운 자리가 없다"는 결과가 존재하지 않았다 — 항상 무언가를 반환했다. 반면 짝 지어 앉히기(`chooseBuddySeats`)는 이미 "만족하는 조합이 없으면 포기하고 다음 기회로 넘긴다(`null` 반환)"는 방식이었는데, 떨어뜨리기 전용 함수만 이 안전장치가 빠져 있었다.

**수정**: `chooseFrontPairSeats()`가 후보 중 1위가 여전히 위반(붙어 있거나 너무 가까움)이면 그 자리에서 확정하지 않고 `null`을 반환하도록 바꿨다. 그러면 그 두 학생은 이번 시도에서는 배치되지 않은 채로 남아 있다가, 바로 다음 단계(개별 앞자리 배치, 이미 앉은 학생과의 거리를 고려해서 자리를 고름)에서 다시 기회를 얻고, 그래도 안 되면 전체 배치 재시도(최대 3500회) 중 다른 순서·다른 셔플에서 또 시도된다. 요약하면 "이번엔 어쩔 수 없이 붙여 앉힌다"를 "이번엔 포기하고 다른 방법을 또 찾아본다"로 바꾼 것이다.

**검증**: 이 리포트의 정확한 재현 조건(학생 수·행렬 크기·떨어뜨리기 간격 등)을 알 수 없어서, 다양한 시나리오로 300회씩 반복 시뮬레이션했다 — 좁은 교실(3~4열), 앞자리 경쟁이 심한 경우, 짝 지어 앉히기와 떨어뜨리기가 동시에 앞자리를 다투는 경우, 자리 일부를 제외 처리한 경우 등. 수정 전 코드로도 대부분 위반 없이 배치됐고(즉 재현 자체가 쉽지 않았다), 딱 하나 — 열이 3칸뿐인 아주 좁은 교실에 대각선 옵션까지 켠 경우만 수정 전후 동일하게 100% 위반이 나왔는데, 이건 버그가 아니라 **기하학적으로 불가능한 조건**이었다(2행×3열 안에서는 어떤 두 자리를 골라도 최소 간격 요건을 만족할 수 없음). 따라서 이번 수정이 실제로 사용자가 겪은 정확한 상황을 재현/해결했는지는 확인하지 못했다 — 코드 감사로 찾은 명백한 결함이라 고치긴 했지만, 정확한 재현 조건(행/열 수, 앞자리·떨어뜨리기 인원, 간격 값)을 알려주면 그 조건으로 다시 검증할 수 있다.

## 0.9.0: D-010 통합 화면 (플랫폼 공용 부품으로 이전)

OJ Platform 2.1의 통합 디자인(D-010, Addon API 1.3)에 맞춰 화면 껍데기만 바꿨다. **세션·REST·저장 형식·권한 키와 모든 `data-field`/`data-action` 속성은 그대로**다.

- **메뉴**: 콘솔 메뉴를 `learning_support`의 "학습지원도구"(순서 95)에서 `classes`(수업 그룹)의 **"교실 도구"**(순서 70)로 옮겼다. 허브와 8개 도구 화면을 로컬 내비 구획(전체 도구, 타이머, 자리배치, 뽑기, 사다리타기, 판서, 퀴즈·투표, 조 짜기, 타임어택)으로 등록해, 도구 화면에서도 사이드바의 "교실 도구"가 강조된다. 플랫폼 2.0.x에는 구획 인터페이스가 없으므로 `instanceof AddonConsoleLocalNavBuilderV1`로 확인한 뒤에만 등록한다. 학생 메뉴 "수업 참여"는 그대로 `classes`에 있다. 권한 표시 이름도 "교실 도구 진행/참여"로 맞췄다(키는 그대로).
- **허브**: 이모지 배너와 카드를 `ojp-page-header` + 앱 타일 격자로 바꿨다. 타일은 둥근 색 사각형 안의 선 아이콘(인라인 SVG) + 도구 이름 + 한 줄 설명이다. 타일 색은 `console.css`에 한 번 정의한 7가지(`htt-tone--*`)이고 모두 `--ojp-color-*` 상태 토큰에서 온다. "열기 →" 문구는 없애고, 준비 중인 도구는 `ojp-status-badge`로 표시한다.
- **도구 화면**: 머리말을 `Ui::tool_header()`(`ojp-page-header`, 머리 글자 "교실 도구")로 통일하고, 아이콘 타일과 "❓ 사용법" 알약 버튼을 `ojp-button--plain` "사용법" 버튼으로 바꿨다. 버튼은 `ojp-button`(시작·실행은 `--primary --large`, 보조는 `--plain`, 삭제·닫기는 `--danger`, 참여 링크 복사는 `--tinted --small`), 상태 표시는 `ojp-status-badge`로 바꿨다. 버튼·선택지·안내 문구 속 이모지는 모두 글자로, 진행 방식 카드와 판서 도구 막대의 아이콘은 Lucide 모양 인라인 SVG(`src/Addon/Ui.php`)로 바꿨다. 번호 단계와 진행 방식 카드는 구조를 그대로 두고 토큰으로 다시 칠했다. 도구 화면은 `page(..., 'wide')`를 쓴다.
- **사용법 시트**: `usage-modal.js`가 플랫폼 시트(`ojp-sheet-scrim`/`ojp-sheet`) 모양으로 열리고, 긴 안내는 본문만 스크롤된다. 열 때 "닫기"로 초점을 옮기고 닫으면 원래 버튼으로 돌려준다.
- **알림·확인**: `window.alert`(타이머 시작 실패, 학생 사다리 선택·투표 실패)는 `OJP.toast(..., 'danger')`로, 자리배치의 저장된 배치 삭제 `window.confirm`은 `OJP.confirm({destructive: true})`로 바꿨다. `OJP`가 없는 플랫폼에서는 원래 `alert`/`confirm`으로 동작한다. 참여 링크를 복사하면 "참여 링크를 복사했습니다" 토스트가 뜬다(복사 실패 시 `window.prompt` 폴백은 그대로).
- **색 토큰과 다크 모드**: `:root`에 있던 `--htt-*` 정의를 지우고 `[data-htt-host]`/`[data-htt-join]` 컨테이너에서 `--ojp-*` 토큰으로 매핑했다(예: `--htt-primary: var(--ojp-color-primary, #087d78)`). 도구 CSS에 남아 있던 고유 색(정답 초록, 완료 행 배경 등)도 토큰으로 바꿨다. 그 결과 허브와 타이머·자리배치·뽑기·사다리타기·퀴즈·조 짜기·타임어택 화면은 플랫폼 다크 모드를 켰다. **판서 화면과 학생 참여 화면은 밝은 화면으로 남겼다** — 판서 캔버스는 펜 색과 지우개 합성이 흰 바탕을 전제해 일부러 흰색(`#fff`)으로 고정돼 있고, 참여 화면도 같은 캔버스를 보여 주기 때문이다.
- **참여 화면**: 머리말을 `ojp-page-header`(머리 글자 "수업")로, 참여 버튼을 `ojp-button--primary`로, 오류를 `ojp-notice--danger`로 바꿨다. 참여 화면에도 `console.css`를 먼저 불러 토큰 매핑을 한 곳에서만 정의한다. 휴대폰 폭에서 여백과 시계 글자 크기를 줄이고, 버튼 높이를 44px 이상으로 둔다.
- 입력 칸(`input`/`select`/`textarea`)은 한 줄에 선택 상자와 버튼이 같이 놓이는 배치가 많아 `ojp-input`(폭 100%)으로 바꾸지 않고, 컨테이너 범위 규칙을 토큰으로 다시 칠하는 데 그쳤다.

## 0.9.2: 학생 판서 화면 확대 + 실시간 동기화 개선

- **학생 화면 확대**: 참여 페이지의 플랫폼 레이아웃을 `wide`로 바꾸되, 다른 참여 도구와 코드 입력 화면은 기존 480px 폭을 유지한다. 판서 세션에 들어온 경우에만 컨테이너를 최대 1200px까지 넓히고, 휴대전화에서는 카드 여백과 장식을 줄여 캔버스가 화면 폭을 최대한 쓰게 했다.
- **진행 중인 획 동기화**: 이전에는 펜을 뗀 뒤에야 완성된 획을 저장했고 교사 전송·학생 조회가 각각 1.5초 간격이라 최악의 경우 3초 이상 늦었다. 이제 그리는 중인 펜·지우개 획과 도형도 포함해 최대 300ms 간격으로 전송하고, 학생 판서 화면은 600ms 간격으로 상태를 확인한다. 요청이 느릴 때는 다음 요청을 겹쳐 보내지 않아 오래된 응답이 최신 그림을 덮지 않도록 했다.
- **불필요한 다시 그리기 방지**: 받은 판서 요소가 이전과 같으면 학생 캔버스를 다시 지우고 그리지 않아 화면 떨림과 렌더링 비용을 줄였다.

## 0.9.3: WebSocket 실시간 판서 + 한 줄 서버 설치

- **진행 중인 획을 즉시 전송**: 교사 브라우저가 약 32ms 간격으로 현재 획·도형 미리보기만 WebSocket으로 보낸다. 손을 떼거나 되돌리기·페이지 전환을 하면 완성 상태를 보내 학생 화면이 바로 확정된다.
- **REST 자동 대체**: WebSocket 연결 중에도 완성 상태는 WordPress DB에 저장한다. 서버 미설치·재시작·네트워크 끊김이 나면 학생 화면은 즉시 0.9.2의 REST 폴링으로 돌아가고, 연결이 복구되면 다시 WebSocket을 사용한다.
- **공용 실시간 허브**: `realtime-server/`는 티켓의 앱·채널·방 네임스페이스를 분리하므로 향후 퀴즈나 다른 플러그인도 같은 Node 프로세스를 공유할 수 있다. 현재는 판서 채널만 연결했다.
- **한 번 실행 설치·업데이트**: 교실 도구 설정 화면은 고정 설치 명령과 별도 설정 코드를 제공한다. 명령을 실행한 뒤 숨김 입력에 설정 코드를 붙여 넣으므로 비밀값이 셸 기록에 남지 않는다. `install.sh`가 Node.js 24 확인, `/opt/oj-realtime-hub` 배치, npm 의존성, systemd, nginx 프록시, 상태 확인을 처리한다. nginx 설정은 먼저 백업하고 `nginx -t`가 실패하면 원본으로 복구한다.
- **역할별 단기 티켓**: WordPress가 2분 유효 기간의 HMAC 티켓을 발급한다. 세션 소유자만 전송할 수 있고, 실제로 참여한 학생은 읽기 전용 연결만 받는다.

## 0.10.0: 독립 설치 가능한 공통 실시간 서버

- 각 플러그인 ZIP에 동일한 `common-server/` 런타임을 포함한다. 티칭툴만 설치해도 동작하며 아레나를 먼저 설치할 필요가 없다. 반대 순서도 같다. OJ Platform 공통 기반은 그대로 사용한다.
- 설정 화면의 새 `ojhub1.` 명령이 공통 서버가 없으면 설치하고, 있으면 다른 모듈·비밀키·데이터를 보존하며 티칭툴 모듈만 추가·갱신한다.
- 한 `oj-realtime-hub` 서비스·3210 포트에서 티칭툴 `/classroom-live`와 아레나 `/arena`를 앱·채널·방으로 분리한다. 인증키와 프로토콜 처리도 앱별이다.
- 상태 확인은 앱 등록·서명 인증·방 수·접속 수를 표시한다. 실제 WebSocket 입장은 수업 참여로 확인한다.
- 공통 서버 갱신은 모든 실시간 연결을 재시작하므로 수업·경기가 없는 시간에 한다. WordPress 플러그인을 삭제해도 다른 모듈이 사용하는 서버는 삭제하지 않는다.
- 로컬 자동 검증에 티칭툴·아레나 단독 운영, 양방향 설치 순서, 재설치 보존, 실제 WebSocket 통합 테스트를 추가했다. 운영 서버 설치는 별도 확인이 필요하다.

## 0.11.0: 수업 신호 + 참여 상태 + 활동 보내기

- **학생 신호**: 참여 학생은 준비됨, 이해함, 조금 어려움, 다시 설명, 도움 필요, 완료 중 하나를 선택한다. 같은 신호를 다시 누르면 취소된다. 교사는 신호별 인원과 학생별 현재 상태를 보고 확인한 신호를 개별 또는 전체 해제할 수 있다.
- **실시간 참여 상태**: 공통 WebSocket 허브가 티켓의 사용자 식별자를 기준으로 접속·이탈을 교사에게 알린다. 여러 탭으로 접속한 학생은 마지막 탭이 닫힐 때만 이탈로 처리한다. WebSocket을 사용할 수 없을 때는 10초 heartbeat와 30초 온라인 판정으로 같은 화면을 유지한다. 이 값은 공식 출석 기록이 아니라 현재 세션의 연결 상태다.
- **활동 보내기**: 교사가 활동 이름, HTTP(S) 주소, 짧은 안내를 보내면 학생 화면에 활동 열기 버튼이 나타난다. Learning Materials, ReadContents, AI Dashboard, Edu Games, Code Arena, Code Lab, ML Playgrounds가 활성화돼 있으면 각각의 학생 진입 화면을 빠르게 채우는 프리셋을 제공한다. 티칭툴은 URL만 전달하고 대상 플러그인의 데이터나 결과를 복제하지 않는다.
- **개인정보 경계**: 교사만 전체 참가자 목록을 조회한다. 학생에게는 전체 명단이나 다른 학생의 신호를 보내지 않고 자기 신호만 반환한다. 참여 상태와 신호는 기존 4시간 수업 세션에 붙으며 별도 출석부나 영구 평가 기록을 만들지 않는다.
- **양방향 실시간 프로토콜**: 읽기 전용이던 참여자 연결에 제한된 `participant-event` 경로를 추가했다. 서버가 티켓의 사용자 ID를 덧붙여 교사에게만 전달하므로 브라우저가 다른 사용자 ID를 가장할 수 없고, 참여자는 여전히 스냅샷이나 교사 이벤트를 변경할 수 없다.

## 0.12.0: 빠른 응답 + 학생 미니 판서 + 운영 보드 + PDF 배경

- **빠른 응답**: 기존 객관식 퀴즈 화면에서 척도, 한줄 응답, 워드클라우드, 익명 질문을 선택한다. 객관식·척도·서술 결과는 교사가 공개하기 전까지 학생에게 집계를 보내지 않는다. 익명 질문은 최대 3개를 받고 교사가 공개·숨김·대기 상태로 조정하며, 교사 화면에도 작성자 식별자를 보내지 않는다.
- **학생 미니 판서**: 학생의 1000×600 정규화 벡터 판서를 세션 참가자 데이터에 저장한다. 교사는 제출 수, 썸네일, 크게 보기, 개인·전체 지우기를 사용한다. 이름 숨김을 켜면 갤러리에 응답 번호만 표시한다. 그림 데이터는 학생끼리 공유되지 않고 영구 평가 기록도 만들지 않는다.
- **수업 운영 보드**: 순서표, 활동 모드, 신호등, 타이머, 소음 신호를 프로젝터용 한 화면에 배치했다. 순서표와 설정은 현재 브라우저에만 자동 저장한다. 소음 신호는 사용자가 버튼을 눌러 허용한 동안에만 Web Audio로 크기를 계산하고 오디오를 저장·전송하지 않는다.
- **학습자료 PDF 배경**: Learning Materials가 함께 활성화돼 있으면 교사가 볼 수 있는 PDF를 판서 시작 화면에서 고른다. Teaching Tools는 기존 보호 스트리밍 URL만 참조하고 파일을 복사하지 않는다. 각 판서 페이지는 PDF 쪽 번호를 함께 저장해 학생 화면에도 같은 배경을 요청한다. 학생에게 해당 자료 열람 권한이 없으면 Learning Materials가 계속 접근을 차단한다. 브라우저 내장 PDF 뷰어 방식이라 배경은 PNG 내려받기에 합성되지 않는다.
- **실시간 채널**: `quickboard` 채널을 추가했다. 참여자는 검증된 `board-updated` 리비전 알림만 교사에게 보낼 수 있고, 스냅샷·교사 이벤트 전송 권한은 없다. 실시간 서버가 없거나 끊기면 교사 갤러리는 3초 REST 조회로 계속 갱신된다.

## 0.12.1: 사이트 전역 수업 신호

- **학생 전역 신호 바**: 학생이 수업 신호 코드로 한 번 참여하면 같은 로그인 브라우저의 문제, 학습자료, 읽기자료, 게임, 코드·ML 실습 등 OJ Platform 화면 오른쪽 아래에 접이식 신호 바가 나타난다. 학생은 현재 활동을 열고 여섯 가지 신호를 보내거나 연결을 직접 해제할 수 있으므로 참여 화면을 계속 띄울 필요가 없다.
- **교사 전역 요약 바**: 교사가 수업 신호를 시작한 뒤 다른 화면으로 이동해도 접속 인원, 도움·재설명·어려움 신호와 학생별 확인 버튼을 볼 수 있다. 전체 명단 관리와 활동 보내기는 기존 수업 신호 화면 링크로 돌아간다.
- **연결 복원과 폴백**: 브라우저 `localStorage`에는 참여 코드, 현재 사용자 ID, 역할, 마지막으로 확인한 활동 시각만 저장한다. 페이지를 열 때 서버에서 소유자·참여자 권한과 활성 세션을 다시 검증하며, 종료·만료·권한 변경 시 기록을 자동 삭제한다. 학생은 WebSocket을 우선 사용하고 실패하면 REST heartbeat·조회로 전환하며, 교사 전역 바는 기존 호스트 연결을 빼앗지 않도록 REST 조회만 사용한다.
- **플랫폼 응답 주입 범위**: OJ Platform의 완성된 HTML 응답에만 전역 자산을 추가한다. 관리자, REST, AJAX, 크론, 비로그인 응답과 일반 비플랫폼 HTML은 변경하지 않으며, 수업 신호 전체 화면과 공용 참여 화면에서는 중복 바를 만들지 않는다.

## 0.12.2: 학급·그룹 자동 참여

- **두 가지 참여 방식**: 수업 시작 전에 기존 `참여 코드`와 `학급·그룹 자동 참여` 중 하나를 고른다. 자동 참여에서는 플랫폼이 현재 교사에게 허용한 학급·그룹 목록만 표시하고 한 대상을 선택한다. 코드 방식은 기존 동작을 그대로 유지한다.
- **서버 검증과 명단 스냅샷**: 브라우저가 학생 ID 목록을 보내지 않는다. 서버가 Addon API Context·Roster 게이트웨이로 교사의 접근 권한과 명단 리비전을 다시 검증한 뒤, 수업 시작 시점의 학생을 참가자로 미리 등록한다. 지정 명단 밖 학생은 코드를 알아도 해당 수업에 들어갈 수 없다. 시작 뒤의 전입·탈퇴는 다음 수업을 시작할 때 반영된다.
- **자동 발견**: 지정 학생의 로그인된 OJ 화면은 활성 수업 조회를 15초 간격으로 수행하고 새 수업을 찾으면 전역 신호 바를 연다. 공용 수업 참여 화면에서도 같은 수업을 자동으로 연다. 교사 화면에는 전체 대상 수와 실제 접속 수를 구분해 표시한다.
- **연결 해제와 세션 정리**: 학생이 전역 바에서 연결을 해제하면 같은 수업 코드를 브라우저에 기록해 자동 재접속하지 않는다. 참여 페이지에서 코드를 직접 입력하면 다시 연결할 수 있고, 새 수업 코드는 자동으로 발견한다. 교사가 새 수업 신호를 시작하면 같은 계정의 이전 수업 신호는 종료한다.

## 1.0.0: 정식 통합 릴리스

- **단일 연동 계약**: 학급·그룹 명단, 공개 문제, 명단 범위의 정답 제출, 학습 활동 검색을 OJ Platform 2.3 / Addon API 1.4의 `AddonIntegrationGatewayV1`로만 수행한다. 직접 HUSTOJ DB 접근과 Learning Materials 런타임 의존성을 삭제했고, 계약을 사용할 수 없으면 우회하지 않는다.

- **수업 중 안전장치**: 빠른 응답에 접수 열기/닫기, 금지어, 서술·워드클라우드·질문 중재를 추가했다. 판서 이미지는 MIME·크기·해상도·개수를 검증하고 재인코딩한 뒤 권한을 확인하는 보호 경로로만 제공한다.
- **결과물과 표시**: 자리배치에 한 명씩 공개, 전체 공개, PNG 저장, 인쇄를 추가했다. 참여 링크는 복사와 로컬 QR 생성을 모두 제공한다.
- **개인정보 관리**: 세션 만료·보관 기간, WordPress 내보내기·삭제 도구, 계정 삭제 연동을 추가했다. 플러그인은 저장 항목만 플랫폼 재고에 등록하며, 처리방침 문구는 OJ Platform 통합 문서에서 관리자가 작성한다.

## 1.0.1: 저장 자리배치 이름 전환과 조건 식별

- **저장 배치 이름 전환**: 새로 저장하는 좌석의 학생 객체에 `id`, 표시 이름, 관리용 이름과 익명 번호를 함께 보존한다. 저장 배치를 불러온 뒤 결과 화면에서 이름 종류를 바꾸면 자리표, 학생 참여 상태, PNG와 인쇄 출력이 같은 표시로 즉시 갱신된다. 기존 배치는 당시 이름으로 계속 열리며, 같은 명단을 먼저 불러오면 `id`로 최신 이름을 다시 연결할 수 있다.
- **선택 조건 입력**: 앞자리, 떨어뜨리기, 짝 조건에서 현재 표시 이름만 강제하지 않고 표시 이름·관리용 이름·`#학생ID`를 모두 해석한다. 동명이인은 구분 번호가 붙은 화면 이름이나 `#학생ID`를 요구하고, 찾을 수 없거나 모호한 입력은 조용히 무시하지 않고 배치 전에 경고한다.

## 1.1.0: 수업 자동 연결과 PDF 페이지 선택

- 코드 제한은 사용자별 고정 5분 창 안의 서로 다른 실패 코드만 집계한다. 만료 수업의 자동 요청이 반복돼도 같은 코드는 한 번만 계산하며, 등록 학생·교사와 정상 공개 코드 참여는 누적 제한 때문에 차단하지 않는다. 기존 제한 키는 읽지 않는다.
- 수업 신호 외의 모든 동시 참여 도구에도 학급·그룹 자동 등록을 적용한다. 공통 학생 연결 선택기를 사용하고, 서버가 플랫폼 명단 계약으로 교사 권한과 리비전을 검증한다. 학생별 배정 활동 조회는 자기 참가 기록만 반환하며, 그룹 밖 계정의 코드 참여를 거부한다.
- 학생 참여 화면은 5초 간격으로 활동을 발견해 코드 없이 열고 여러 활동 사이를 전환한다. 다른 OJ 화면에도 배정 활동 링크를 표시한다. 만료된 연결은 정리하고 다른 활동을 다시 찾는다.
- 판서 중에 PDF 자료를 다시 불러와 페이지 미리보기로 선택하고, 새 페이지로 삽입하거나 현재 배경을 교체할 수 있다. 기존 판서와 페이지 이동은 유지한다. Mozilla PDF.js 6.4.299와 CMap·표준 글꼴·WASM 및 각 라이선스를 로컬에 포함했다. 학생도 자신의 학습자료 권한으로 같은 페이지를 렌더링하고 PNG 저장에 배경을 합성한다.
- PHP 회귀 검사는 `php tests/session-admission.php`, 실제 브라우저 검사는 Playwright가 있는 환경에서 `node tests/browser-activities.cjs`로 실행한다. 브라우저 검사는 그룹 대상 전송, 자동 참여, PDF 페이지·자료 교체, 판서 보존, 활동 전환 및 모바일 캔버스 픽셀을 검사한다.
