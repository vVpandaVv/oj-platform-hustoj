# 설치·지원과 문제 신고

OJ Code Lab은 OJ Platform 2.x 사이트 안에서 사용하는 애드온이다. 학급 소속, 교사 열람, 사용 권한과 개인정보 요청은 해당 사이트 운영자에게 문의한다. 코드 오류와 수정본에 대한 문의는 이 ZIP을 받은 배포 경로의 배포자에게 전달한다. 별도 유상 지원이나 응답 기한 보증은 포함하지 않는다. 재배포자는 자신의 다운로드 안내에 연락 경로와 변경 사항을 함께 제공할 수 있다.

## 오류를 신고할 때

플러그인·OJ Platform·WordPress·PHP 버전, 브라우저/OS, 오류 발생 시각과 재현 순서, 화면의 오류 코드를 전달한다. 학생 이름·노트북 원문·비밀키·cookie·nonce·wp-config.php 또는 전체 debug.log를 공개 게시판에 올리지 않는다. 최소 재현 코드는 개인정보를 제거해 제공한다.

저장 실패 시 먼저 ‘내 노트북 내려받기’로 현재 편집을 보관한다. 409는 다른 탭의 저장 또는 구형 노트북 형식 요청이므로 보관 후 ‘최신 노트북 불러오기’를 사용한다. 413은 서버가 허용하는 저장 크기를 넘은 경우다. 큰 출력·그래프를 줄이거나 운영자에게 서버 한도를 확인한다. 428은 revision이 없는 요청이므로 편집을 보관하고 새로고침한다.

## 설치와 업데이트

WordPress 6.6 이상, PHP 8.1 이상, OJ Platform >=2.0.0-dev.30 <3.0.0 및 Addon API >=1.0.0 <2.0.0이 필요하다. OJ Platform을 먼저 활성화하고 ZIP을 설치한다. 멀티사이트는 사이트별 활성화만 지원한다. 브라우저에서 WebAssembly·Worker·CDN 연결이 필요하며 input()에는 HTTPS와 COOP/COEP에 따른 SharedArrayBuffer 사용 환경이 필요하다.

운영자는 업데이트 전 플러그인 ZIP·DB·WordPress 설정과 salt를 같은 시점으로 백업한다. 혼합 노트북을 이해하지 못하는 RC5 이하나 스키마 2 이전 버전으로 롤백할 때에는 해당 시점의 DB·옵션도 함께 복원한다. 1.0.0에서 1.1.0으로 업데이트해도 DB 스키마 2와 노트북 형식 2는 바뀌지 않는다. 업데이트 후 기존 탭을 새로고침하고 학생 실행·저장·재접속, 교사 요약·상세, 사용하는 형식의 데이터 가져오기를 확인한다. WordPress ‘도구 → 사이트 건강’에서 스키마·암호화·정리 예약과 저장 한도를 점검한다.

제출 테마와 같은 Ace 편집기에는 OJ Platform dev.104 이상이 필요하다. 현재 계정의 제출 설정을 선택적인 공개 Addon Editor API로 읽으며 다른 플러그인의 DB에 직접 접근하지 않는다. API나 Ace 자산이 없는 플랫폼에서는 기본 textarea로 입력·저장을 유지한다. 플랫폼 자체는 별도 라이선스로 제공되며 이 배포판에 포함되지 않는다. 1.1.0에서 플랫폼 코드는 수정하지 않는다.

## 데이터 가져오기 문제

CSV·JSONL·NDJSON 또는 일반 ZIP을 업로드하거나 직접 내려받는 URL로 등록한다. JSONL·NDJSON은 `pd.read_json(..., lines=True)`, CSV는 `pd.read_csv(...)`로 읽고 미리보기 코드를 자동 실행하여 표를 출력한다. JSONL은 각 줄에 객체나 배열 하나를 쓰고 여러 줄로 들여쓴 일반 JSON은 JSONL로 변환한다. 빈 줄은 건너뛰며 정규화 후 한 줄 최대 1MiB, JSON 파서 깊이 한도 64와 파일 전체 상한을 적용한다. 오류의 줄 번호로 위치를 확인하고 신고할 때 해당 줄의 개인정보를 제거한다. UTF-8 또는 손실 없이 변환 가능한 CP949만 받으며 CP949 변환에는 iconv 또는 mbstring이 필요하다.

ZIP 오류가 나면 WordPress ‘도구 → 사이트 건강’의 ZIP 읽기 상태를 확인한다. 서버에 PHP zip 확장의 `ZipArchive`가 없으면 운영자가 확장을 설치하거나 압축을 풀어 CSV·JSONL·NDJSON을 업로드한다. 서버 임시 파일 쓰기 권한도 필요하다. 선택한 Kaggle 파일명과 정확히 일치하는 내부 파일을 우선 사용하고, 일치하지 않으면 지원 파일이 하나일 때만 자동 선택한다. 여러 파일이면 Kaggle 목록에서 원하는 원본 파일을 고르거나 압축을 풀어 필요한 파일 하나를 올린다. ZIP 내부 파일 선택 화면은 따로 제공하지 않는다.

ZIP 내부 파일명은 UTF-8이어야 한다. 중첩 압축·ZIP64·분할·암호화 ZIP과 Store·Deflate 이외 압축은 지원하지 않는다. 디렉터리를 포함해 1,000개 항목, 항목당 압축률 200배, 전체 압축 해제 크기는 실제 파일 상한의 8배와 128MiB 중 작은 값을 적용한다. ZIP 원본과 선택한 압축 해제 파일, UTF-8 정규화 결과도 각각 실제 파일 상한 안에 있어야 한다. 서버·DB·업로드 한도는 [README](../README.md)의 데이터 제한을 확인한다.

‘런타임 재시작’ 뒤 파일을 찾지 못하면 추천 자료나 파일 목록에서 다시 불러온다. 재시작은 변수와 Worker 안의 파일을 지우며 저장된 셀과 기존 출력은 유지한다. 서버 원격 캐시는 내용·실제 파일명·형식을 함께 보관하는 v2 키를 사용한다. 기존 원문 캐시는 업데이트 때 강제 삭제하지 않고 기본 24시간 만료 및 정리 정책을 따른다. 파일 내용이 1MiB와 적용 파일 상한의 1/4 중 작은 값보다 크면 메모리 보호를 위해 캐시하지 않으며 가져오기는 정상 진행한다.

## 검증 범위와 운영 인수

정확한 엔진·OS·PHP·WordPress 버전과 검사 결과는 ZIP 옆 공개 검증 보고서에 기록한다. 데스크톱 Chromium·Firefox와 자동화 WebKit을 구분하고 실제 Apple Safari·iOS·Android 실기 검증을 수행한 것으로 표시하지 않는다. 지원 플랫폼이 다른 경우 설치자가 실행·입력·저장·재접속을 확인한다.

Kaggle은 선택 연동이다. 키가 없어도 코드 실습과 번들 CSV·교사 업로드 자료를 사용할 수 있다. 정식 배포 검증에는 계약·인증정보 보호·오류 처리가 포함되며, 실계정 권한과 보호 자료·사용량 제한은 해당 계정으로 설치자가 확인한다. 공개 데이터 URL, 방화벽, 프록시, CDN 허용, 백업·복원과 사이트 부하는 각 설치 환경의 운영 인수 항목이다.

본판은 직접 배포 ZIP이다. WordPress.org 디렉터리 등록을 위해서는 외부 실행 코드 로딩 등 해당 디렉터리 지침을 별도로 충족하고 심사를 받아야 한다.

## 확장자와 실제 형식이 다른 파일

1.1.1부터 지원 데이터가 없는 ZIP 안에 Word 문서 구조가 있으면 DOCX 형식임을 안내한다. `.jsonl`이나 `.csv`로 이름만 바꾼 Word 문서는 데이터 파일이 아니다. 실제 UTF-8 JSONL·CSV 원본을 제공자에게 받아 사용한다. 플러그인은 Word 문서를 자동 변환하지 않는다. 정상 CSV·JSONL이 포함된 일반 ZIP의 기존 선택 규칙은 유지한다.
