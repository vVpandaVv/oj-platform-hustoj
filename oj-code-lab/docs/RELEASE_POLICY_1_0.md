# 1.0.0 직접 배포판의 승인 범위

이 문서는 Code Lab 단독 ZIP의 정식 직접 배포 기준이다. 2026-09-10 사용자가 라이선스를 포함한 공개 정식 배포판 제작을 지시하여 RC6의 라이선스 보류를 대체했다. 라이선스 선택은 이 제작 지시에 따라 GPL-2.0-or-later와 프로젝트 전용 공개 API 연동 추가 허락으로 정리한다. 다른 저작권자의 자료나 플랫폼 라이선스는 변경하지 않는다.

## 배포물과 설치 사이트의 구분

이전 RC 게이트는 코드 품질, 공개 재배포 권리, 특정 운영 사이트의 인수 작업과 WordPress.org 등록 가능성을 한 상태에 모았다. 1.0.0은 직접 배포 ZIP이라는 대상에 맞춰 배포 승인과 사이트별 운영 인수를 구분한다. 이전 게이트와 미완료 기록은 `history/rc6-release-gates.json`에 보존한다. 미실행 검사를 통과로 바꾸거나 과거 결과의 버전을 새 버전으로 바꾸지 않는다.

배포 게이트 R1–R7은 아래 항목에 대해 1.0.0 입력·소스·ZIP의 관계를 입증하는 실제 검증 증거가 있어야 통과한다. 최종 ZIP의 실행 코드가 검증 입력과 바이트로 같은지 확인한다. GPL 원문·추가 허락·출처와 선언이 일치하지 않으면 패키지 빌드도 실패해야 한다.

| 게이트 | 1.0.0 직접 배포 기준 |
|---|---|
| R1 | Ace·Python Worker·실행 중단·입력·혼합 셀의 선언된 브라우저 검증 |
| R2 | 노트북 저장·CAS 충돌·개인정보·학생/교사 권한·읽기 실패 보호 |
| R3 | DB 패킷·본문·출력·캐시·호출 한도와 요약 조회의 제한 동작 |
| R4 | 선언된 PHP/WordPress 조합의 설치·업데이트·삭제 및 플랫폼 계약 |
| R5 | 선택 외부 연동의 요청 계약·파일 형식·비밀키 보호·오류 처리 |

| R7 | 재현 가능한 ZIP·소스 해시·RC6 업그레이드와 백업 복원·공개 지원 문서 |

## 검증으로 주장하지 않는 사항

- 특정 Kaggle 계정의 보호 자료 접근, 계정별 한도·키 만료는 해당 계정으로 설치자가 확인한다. 계약/안전성 검증과 실계정 인수를 구분한다.
- 서버의 최신 전체 백업, TLS·리버스 프록시·CDN 허용, 장애 복구 책임, 실사용 트래픽 부하는 각 설치 환경의 인수 항목이다. 로컬 DB 백업/복원 검사가 운영 서버 백업 존재를 증명하지 않는다.
- 자동화 WebKit 검사는 실제 macOS/iOS Safari 검사가 아니다. 검증 보고서에 엔진과 OS를 기록하고 실기 검증 범위를 넓혀 쓰지 않는다. 모바일 기기와 접근성 보조기기 역시 개별 확인이 필요하다.
- OJ Platform은 별도 제공되는 필수 의존성이다. 이 ZIP에 플랫폼 파일을 포함하거나 플랫폼 라이선스를 변경하지 않는다.
- WordPress.org 디렉터리 등록·심사 통과를 뜻하지 않는다. CDN 실행 코드 로딩과 플랫폼 의존성 등 디렉터리 규정은 별도 작업이다.

정식 ZIP은 위의 범위와 제한을 공개 README·SUPPORT 및 ZIP 옆 검증 보고서에 함께 제공한다. 아직 검증 중인 입력 ZIP은 `_notes`의 qualification 전용 위치에 두고 공개 산출물로 표시하지 않는다.
