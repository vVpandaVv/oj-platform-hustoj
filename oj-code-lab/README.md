# OJ Code Lab

OJ Platform 2.x의 학생용 Python 실습실과 교사용 노트북 열람 애드온이다.

현재 버전은 **1.4.0**이다. 코드 셀 단계별 디버거(한 줄 실행·중단점·변수 표), 제출 페이지 테마를 공유하는 Ace Python 편집기와 마크다운 텍스트 셀, CSV·JSONL·NDJSON·ZIP 데이터 가져오기를 제공한다. 자체 코드는 **GPL-2.0-or-later**로 제공한다. [라이선스 원문](LICENSE.txt), [개인정보·외부 연결](docs/PRIVACY.md), [설치·지원](docs/SUPPORT.md), [데이터 고지](docs/PUBLIC_DATASETS.md)를 함께 확인한다.

이 배포판은 OJ Platform을 별도로 설치한 사이트를 위한 **Code Lab 단독 직접 배포 ZIP**이다. 플랫폼 파일과 라이선스는 포함하지 않는다. WordPress.org 디렉터리 등록판은 아니며, CDN Python 런타임 및 별도 플랫폼 의존성에 대한 디렉터리 심사는 별도 절차다.

[플랫폼 연동 추가 허락](PLATFORM-LINKING-EXCEPTION.txt)은 Code Lab 자체 코드와 OJ Platform의 공개 Addon API v1 연동에 한정한다. Code Lab의 소스 제공·고지 의무는 유지하며 플랫폼·WordPress·Ace·데이터의 권리와 라이선스를 변경하지 않는다. 이 프로젝트 전용 허락은 SPDX의 표준 예외로 표시하지 않는다.

## 기능과 권한

- 학생별 노트북 1개에 코드·텍스트 셀, 출력, 입력값, 오류, PNG 그래프를 저장한다.
- OJ Platform dev.104 이상에서 제출 페이지의 계정별 테마·글자 크기를 적용한 Ace Python 편집기를 사용한다. 이전 플랫폼이나 자산 로드 실패 시 기본 편집기로 계속 입력할 수 있다.
- Python은 Pyodide 0.26.4 Web Worker에서 실행한다. 실행 중단·재시작, 실행 큐, 60초 초기화 제한을 제공한다.
- numpy/pandas/matplotlib/seaborn은 필요할 때 로드한다. Worker의 그래프는 Agg 백엔드에서 PNG로 변환한다.
- 교사는 담당 학급·모둠 학생 노트북을 읽기 전용으로 확인한다. 명단은 50명씩 요약 조회한다.
- Kaggle, 데이터 파일 URL, 교사 업로드에서 CSV·JSONL·NDJSON 또는 ZIP 안의 데이터 파일 하나를 가져온다. 읽기·미리보기 코드를 새 셀에 추가하고 자동 실행하여 표를 출력한다. 교사 검색 결과의 ‘파일 선택’으로 대상을 고르거나 ‘첫 지원 파일 추가’로 목록의 첫 지원 파일을 추천 자료에 등록한다.
- 재배포 조건이 확인된 기본 샘플을 추천 데이터로 제공한다. 새 ZIP에는 팔머펭귄 CSV만 포함하며 기존 사이트의 추천 자료는 유지한다.

| 화면 | 권한 | 경로 |
| --- | --- | --- |
| 내 노트북 | `oj_code_lab_use` | `/oj-addons/oj-code-lab/lab` |
| 교사 열람 | `oj_code_lab_review` | `/oj-console/addons/oj-code-lab` |
| 추천 데이터 관리 | `oj_code_lab_manage_datasets` | `/oj-console/addons/oj-code-lab/datasets` |
| 코드 실습실 설정(Kaggle) | `oj_code_lab_settings` | `/oj-console/addons/oj-code-lab/settings` |

권한은 OJ Platform Addon API로 할당한다. 설정 화면은 교사 메뉴 › 코드 실습실 › 설정(로컬 내비 마지막 구획)이며, 사이트 관리자 또는 ‘코드 실습실 설정’(`oj_code_lab_settings`, 교사용) 권한을 받은 교사가 쓴다. 교사에게는 `/oj-console/roles`에서 직접 부여하며 자동으로 주지 않는다. 설정 읽기·저장·삭제 REST(`/oj-code-lab/v1/settings/kaggle`)는 `is_super_admin()` 또는 이 권한의 WordPress 키(`oj_addon_oj_code_lab_settings`)를 확인하고, 추천 데이터 관리와 교사의 Kaggle 검색은 `oj_code_lab_manage_datasets` 또는 사이트 관리자에게 열린다. 플랫폼 2.0.x(로컬 내비 없음)에서는 학습 활동 아래 ‘코드 실습실 추천 데이터’와 ‘코드 실습실 설정’ 메뉴로 따로 보인다. 교사 요청마다 Context Gateway의 `report` 권한과 학생 소속을 다시 검사한다. 추천 목록은 사이트 공용이고, 학생 노트북 저장 대상은 로그인 사용자로 결정된다.

## 설치 요구 사항

1. WordPress 6.6 이상, PHP 8.1 이상, OJ Platform `>=2.0.0-dev.30 <3.0.0`, Addon API `>=1.0.0 <2.0.0`을 준비한다. 정확한 버전 조합과 검사 결과는 ZIP 옆 공개 검증 보고서를 확인한다. 운영 서버 인수 검증은 별도로 필요하다.
2. OJ Platform을 먼저 활성화하고 ZIP을 설치한다. 최상위 폴더는 `oj-code-lab`이다. 네트워크 전체 활성화는 차단하며 사이트별 활성화를 사용한다.
3. MySQL/MariaDB의 JSON 함수와 advisory lock, 충분한 packet·메모리 제한이 필요하다. 네 테이블 생성과 스키마 2 마이그레이션 실패는 기록되고 다음 요청에서 재시도한다.
4. 브라우저에서 jsDelivr의 Pyodide 및 패키지 다운로드가 가능해야 한다. Kaggle 키 저장에는 OpenSSL AES-256-GCM, CP949 변환에는 iconv 또는 mbstring이 필요하다. ZIP 가져오기에는 PHP zip 확장의 `ZipArchive`와 서버 임시 파일 쓰기 권한이 필요하다. ZIP 확장이 없어도 압축하지 않은 CSV·JSONL·NDJSON은 사용할 수 있다.
5. HTTPS와 실습실의 COOP/COEP 헤더를 확인한다. `input()`과 단계별 디버거는 `SharedArrayBuffer`가 가능한 환경에서 제공된다. 이를 지원하지 않아도 Worker에서 일반 코드는 실행되며, 입력 사용 시 원인을 안내한다.
6. WordPress **도구 → 사이트 건강**에서 스키마·암호화·캐시 정리 예약 상태를 확인한다. WP-Cron이 실제로 실행되도록 서버 환경을 구성한다.

## 실행과 저장

첫 셀 앞·셀 사이·마지막의 `+ 코드` 또는 `+ 텍스트`를 누르면 그 위치에 빈 셀이 생기고 바로 입력할 수 있다. 텍스트 셀에는 설명과 메모를 마크다운으로 기록하며 서식을 미리 볼 수 있다. HTML 태그는 문자로 표시한다. 기존 코드·출력·입력 대기는 유지하며 새 순서는 저장 후 다시 열어도 유지된다. 상단의 셀 추가 버튼은 마지막에 셀을 추가한다. 전체 실행은 코드 셀만 실행하며 코드 셀의 Ctrl+Enter(또는 Command+Enter)로 개별 실행한다.

실행은 순서대로 처리한다. ‘실행 중단’은 Worker와 대기 작업을 종료하고 다음 실행에서 새 인터프리터를 만든다. ‘런타임 재시작’도 Worker를 새로 만들기 때문에 변수와 가져온 파일은 사라진다. 셀의 코드와 이미 표시된 출력은 유지된다. 데이터 파일은 추천 자료나 파일 목록에서 다시 불러와야 한다. 초기화 실패 시 메인 스레드 Python으로 전환하지 않는다.

코드 셀의 ‘🐞 디버그’는 셀을 한 줄씩 실행한다. 각 줄을 실행하기 직전에 멈추고 편집기에 그 줄을 표시하며, 패널에 지역·전역 변수의 이름·종류·값을 보여 준다. 직전 단계와 값이 달라진 변수는 강조한다. ‘다음 줄’(F10)은 함수 호출을 한 번에 실행하고, ‘함수 안으로’(F11)는 이 셀에서 정의한 함수 안으로 들어가며, ‘함수 밖으로’(Shift+F11)는 현재 함수를 끝까지 실행한다. ‘계속 실행’은 다음 중단점까지, 중단점이 없으면 끝까지 실행한다. 다른 셀에서 정의한 함수와 라이브러리 내부로는 들어가지 않는다.

Ace 편집기의 줄 번호를 누르거나 F9를 누르면 그 줄에 중단점을 놓거나 뺀다. 중단점이 있으면 디버그는 첫 줄이 아니라 첫 중단점에서 멈추며, 디버깅 중에도 중단점을 바꿀 수 있다. 중단점은 줄을 추가·삭제해도 같은 코드 줄을 따라가고, 저장하지 않으므로 새로고침하면 사라진다. 기본 편집기(textarea)에서는 중단점을 쓸 수 없다.

Pyodide 0.26.4에 포함된 패키지(numpy, pandas, matplotlib, scipy, scikit-learn, sympy, networkx 등)는 `import`만 하면 처음 실행할 때 자동으로 내려받는다. 그 밖의 PyPI 패키지를 셀에서 설치하는 기능(`micropip`)은 지원하지 않는다. 셀은 최상위 `await`를 허용하지 않는다.

멈춘 단계는 최대 500개까지 기록한다. ‘이전 단계’·‘다음 단계’로 지나온 줄과 그때의 변수를 다시 보며 실행은 마지막 단계에서 계속한다. 실행이 끝나면 패널이 단계 기록으로 남고 마지막 변수 값 또는 오류가 난 줄과 그때의 변수를 추가로 보여 준다. 정상 종료와 오류 종료 뒤에도 ‘디버깅 중단’ 버튼이 남으며, 누르면 단계 기록과 줄 강조를 닫는다. 이때 실행 결과·변수와 다른 셀의 실행·입력 대기는 유지한다. 해당 셀을 고치거나 다시 실행해도 기록이 닫힌다. 디버깅 중에는 셀을 편집할 수 없고 `input()`은 평소처럼 동작한다. 값은 길이를 줄여 표시하며 모듈과 `__`로 시작하는 이름은 숨긴다. 아직 디버깅 중일 때 ‘디버깅 중단’을 누르면 ‘실행 중단’과 같이 실행을 멈추고 런타임과 변수를 초기화한다. 출력은 일반 실행과 같이 저장한다.

30초 자동 저장과 저장 버튼을 제공한다. 최대 300셀을 받으며 정규화한 JSON의 기본 상한은 16,000,000바이트다. DB 패킷 한도가 작으면 SQL 인코딩 여유를 확보하도록 실제 상한을 낮춘다. 셀당 텍스트 출력은 1MB, 그래프는 최대 20개·원본 PNG 합계 6MB로 제한한다. 저장 실패와 초기 읽기 실패를 명확히 안내한다.

GET은 `formatVersion: 2`와 `revision`을 반환한다. PUT은 `formatVersion: 2`와 읽었던 `revision`을 함께 보내야 한다. 셀은 `{id, type: "code"|"text", code, outputs}`이며 텍스트 본문도 호환성을 위해 `code` 필드에 담고 출력은 비운다. 기존 종류 없는 셀은 코드로 읽는다. 형식 버전이 없는 구형 탭의 저장은 **409**, 올바른 형식에서 revision 없는 요청은 **428**, 오래된 revision은 **409**를 반환한다. 충돌 시 자동 저장을 멈춘다. ‘내 노트북 내려받기’로 현재 편집을 보관하고 ‘최신 노트북 불러오기’로 복구한다. 내려받은 JSON 자동 병합·재가져오기는 제공하지 않는다.

## 마크다운 텍스트 셀

셀 사이의 **+ 텍스트**를 누르면 마크다운 입력과 실시간 미리보기가 나란히 열린다. 작은 화면에서는 위아래로 배치한다. 도구 막대로 제목·굵게·기울임·취소선·인라인 코드·코드 블록·링크·이미지·인용·번호 목록·글머리 목록·구분선·표를 넣는다. `Ctrl/Cmd+B`, `Ctrl/Cmd+I`, `Ctrl/Cmd+K`도 사용할 수 있다.

**닫기** 또는 `Ctrl/Cmd+Enter`로 편집을 닫으면 서식이 적용된 내용만 보인다. **편집**을 누르거나 내용을 두 번 클릭하면 다시 수정한다. 기존 메모의 원문과 줄바꿈을 유지하고, 저장·자동 저장·JSON 다운로드에는 HTML 대신 입력한 마크다운을 그대로 담는다. 교사의 읽기 전용 노트북에도 같은 서식을 표시한다. 노트북 형식은 2로 유지하므로 이전 버전에서는 마크다운 원문을 텍스트로 볼 수 있다.

마크다운 파서는 설치 ZIP에 포함되어 별도 CDN 연결 없이 동작한다. HTML 태그는 문자로 표시하고 스크립트 URL은 링크나 이미지로 만들지 않는다. 이미지 URL을 넣으면 학생·교사의 브라우저가 해당 이미지 서버에 접속한다. 10만 자를 넘는 긴 셀이나 파서 로딩 실패 시에는 원문으로 표시하며 내용을 자르지 않는다. 수식 렌더링과 HTML 삽입은 지원 범위에 포함하지 않는다.

## 데이터와 비밀키

원격/업로드 데이터는 CSV·JSONL·NDJSON 및 이 파일을 담은 일반 ZIP을 받는다. 텍스트는 손실 없는 UTF-8 또는 CP949만 허용하고 BOM 제거·UTF-8 변환 후에도 파일 크기를 검사한다. HTML, PDF, 바이너리와 잘못된 인코딩은 거부한다. 원격 수신은 상한+1바이트로 잘림을 탐지한다. URL에는 WordPress 안전 HTTP API를 사용한다. Kaggle 리다이렉트는 최대 3회 HTTPS만 허용하고 다른 origin으로 이동하면 Authorization을 제거한다.

CSV는 `pd.read_csv(filePath)`, JSONL·NDJSON은 `pd.read_json(filePath, lines=True)`로 읽고 미리보기 코드를 자동 실행하여 표를 출력한다. JSONL은 빈 줄을 제외한 각 줄에 JSON 객체 또는 배열 하나가 있어야 한다. UTF-8 정규화 후 한 줄 최대 1MiB, JSON 파서 깊이 한도 64와 기존 파일 전체 상한을 적용한다. 오류에는 줄 번호를 표시하며 해당 줄의 원문을 노출하지 않는다.

ZIP 응답에서는 선택한 Kaggle 파일명과 내부 경로가 정확히 일치하는 지원 파일을 우선 사용한다. 일치하는 파일이 없으면 지원 파일이 하나인 경우에만 자동 선택한다. 여러 개이면 Kaggle 목록에서 원하는 원본 파일을 선택하거나 압축을 풀어 필요한 파일 하나를 업로드한다. 별도의 ZIP 내부 파일 선택 화면은 제공하지 않는다. 내부 파일은 UTF-8 이름을 사용해야 하며 경로·중복 이름·손상 여부를 검사한다. 중첩 압축, ZIP64, 분할·암호화 ZIP과 Store(무압축 저장)·Deflate 이외 압축 방식은 지원하지 않는다. 압축 해제에는 서버의 `ZipArchive`를 사용하며 외부 압축 라이브러리를 번들하지 않는다.

Kaggle 파일 목록은 다음 페이지를 이어 읽으며 전체20초·최대10페이지·1,000파일 한도를 적용한다. 한도나 오류가 발생하면 불완전한 목록을 성공으로 반환하지 않는다. 단일 파일 요청이 ZIP으로 돌아와도 위 선택·크기 검사를 적용한다.

원격 캐시는 정규화한 내용과 실제 내부 파일명, `csv` 또는 `jsonl` 형식을 함께 보관하여 다시 불러와도 같은 읽기 방식을 사용한다. 1.1.0은 `dataset-file-v2:` 키를 사용한다. 기존 원문 캐시는 업데이트 시 삭제하지 않고 기존 만료·정리 정책을 따른다. 파일 내용이 1MiB와 적용 파일 상한의 1/4 중 작은 값보다 크면 메모리 보호를 위해 캐시하지 않으며 가져오기는 정상 진행한다.

Kaggle 설정은 하나의 비자동로드 옵션에 원자적으로 저장한다. API 키는 AES-256-GCM으로 암호화하며 기존 CBC 키는 호환해서 읽고 다음 저장에서 전환한다. 같은 계정의 빈 키 입력은 기존 키를 유지하지만 계정 변경에는 새 키가 필요하다. 설정 화면에서 키를 삭제할 수 있다. WordPress salt가 바뀌면 기존 키를 복호화할 수 없어 재입력이 필요하다.

학생 응답에는 Kaggle 키와 추천 원본 URL을 보내지 않는다. 서비스키가 포함된 원본 URL은 관리 화면과 DB에는 보관되므로 공유하지 않는다. 설정 변경은 마지막 이벤트 코드·UTC 시각만 기록하고 `oj_code_lab_audit` 훅 및 사용 가능한 공용 감사 로거에 연결한다. 전체 플랫폼 감사 로그 수집은 운영 환경에서 확인한다.

| 기본 제한 | 값 / 필터 |
| --- | --- |
| 데이터 파일 1개 | 기본 16,000,000바이트 / `oj_code_lab_max_dataset_bytes`; ZIP 원본·선택한 압축 해제 파일·정규화 결과에 적용 |
| JSONL 한 줄 / 깊이 | 최대 1MiB / JSON 파서 깊이 한도 64 |
| ZIP 항목 수 / 압축률 | 디렉터리 포함 최대 1,000개 / 각 항목 압축 해제 크기 최대 압축 크기의 200배 |
| ZIP 전체 압축 해제 크기 | 실제 파일 상한 × 8과 128MiB 중 작은 값 |
| 캐시 총량 | 128,000,000바이트 / `oj_code_lab_cache_max_bytes` |
| 업로드·샘플 총량 | 256,000,000바이트 / `oj_code_lab_uploads_max_bytes` |
| 데이터 요청 | 사용자당 분당 30회 / `oj_code_lab_requests_per_minute` |
| 사이트 데이터 요청 | 분당 300회 / `oj_code_lab_site_requests_per_minute` |
| 캐시 수명 | UTC 기준 24시간, 매시간 WP-Cron 정리 |

용량과 요청 한도는 DB 잠금 안에서 확인한다. 캐시 한도 초과 시 캐시 적재를 생략하고 파일을 반환한다. 업로드 한도와 호출 제한은 오류를 반환한다. 웹 서버, `post_max_size`, `upload_max_filesize`, PHP 메모리, DB `max_allowed_packet`에도 JSON/SQL 인코딩 여유가 필요하다. DB 패킷이 16MiB이면 노트북 JSON과 데이터 파일의 실제 상한은 각각 8,355,840바이트다. 상한을 확인할 수 없으면 새 저장은 503으로 중단하고 기존 자료를 보존한다.

## 보관·개인정보·삭제

자체 테이블은 `oj_code_lab_notebooks`, `oj_code_lab_datasets`, `oj_code_lab_dataset_cache`, `oj_code_lab_uploads` 네 개이며 사이트 prefix를 사용한다. 노트북에는 코드 외에 입력값·출력도 보관된다. WordPress 개인정보 내보내기·지우기와 사용자 삭제에 연결했다. 공유 자료는 유지하고 삭제 사용자와의 작성자 연결을 해제한다.

비활성화와 일반 플러그인 삭제는 데이터를 보존하고 예약 작업을 해제한다. `OJ_CODE_LAB_DELETE_DATA=true` 상태에서 WordPress의 플러그인 삭제를 실행하면 해당 사이트의 네 테이블과 플러그인 설정을 삭제한다. 멀티사이트에서 다른 사이트 데이터까지 순회 삭제하지 않는다.

업데이트 전에는 기존 ZIP, 테이블·옵션·WordPress salt를 백업하고 학생 편집을 중지한다. **DB 스키마 2와 노트북 형식 2**를 사용하며 1.0.0에서 1.1.0으로 업데이트할 때 바뀌지 않는다. 이번 릴리즈는 OJ Platform 코드를 수정하지 않으며 기존 공개 Editor API와 Ace 자산을 그대로 사용한다. 업데이트 뒤 기존 탭은 새로고침한다. RC5 이하로 롤백할 때는 같은 시점의 DB·옵션 백업을 함께 복원한다.

## 검증과 빌드

`oj-code-lab` 폴더에서 실행한다.

```powershell
python scripts/verify.py --php D:/php/php.exe
python scripts/build_release.py --output-dir ../_releases/oj-code-lab/1.1.0
```

ZIP, SHA-256, 파일별 manifest, 로컬 검증 보고서를 만든다. tests/scripts/비밀키/임시 DB/사이트별 운영 기록과 재배포 미확인 CSV는 ZIP에 포함하지 않는다. 기존 출력물이 있으면 덮어쓰지 않는다. 정식 버전 빌드는 7개 게이트의 완료 증빙·버전 일치·LICENSE.txt·readme.txt·헤더의 라이선스 선언이 있어야 허용된다.

릴리즈 검증 보고서는 ZIP과 함께 배포한다. 배포물의 실행·저장·권한·복원 검증과 개별 사이트의 운영 인수는 구분한다. Kaggle 실계정·보호 자료 접근, 서버 백업·방화벽·CDN 연결, 실제 Apple Safari와 모바일 기기는 설치자가 해당 환경에서 확인한다. 자동화 WebKit 검사는 Apple Safari 실기 검사를 대신하지 않는다. 검증하지 않은 환경까지 지원 완료로 표시하지 않는다.
